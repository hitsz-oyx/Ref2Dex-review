# ObjectInteractionCmv2 V1.0 架构

- 状态：`frozen snapshot`
- 指导依据：[指导/V1.0.md](../指导/V1.0.md)
- modification_version：`V1.0`
- 适用范围：新建独立 Task；本版本先冻结结构与 rigid-object smoke 合同，不接入 articulated 全量数据或正式训练。

## 1. 研究边界

模型把局部 hand-object interaction、全局 object structure 和 predicted effect 分开：

```text
local hand-object interaction
        -> grounded contact features/tokens
        -> rigid-part representation
        -> articulation graph (V1.0 为单 rigid part)
        -> root/joint effect
        -> FK point flow
```

局部交互证据只来自物体点周围 2 cm 内的手点；结构表征仍读取完整物体几何。V1.0 中每个样本只有一个 rigid link，`num_links=1`、`link_id=0`、`num_joints=0`，因此 effect 退化为物体相对 `SE(3)` 运动。剪刀等多 link 对象只在接口中预留，不进入本版本数据或训练。

## 2. 输入合同

### 2.1 当前状态

- `obj_points`: `[B, N, 3]`，运行时 `N=1024`；点来自 object pool 的确定性采样。
- `obj_normals`: `[B, N, 3]`，与点逐行对应。
- 当前 hand geometry、hand normals、`hand_flow` 和有效掩码；源手可为 MANO 或 Inspire，但内部使用统一 hand stream 接口。
- 离线 KNN：每个物体点最多 32 个 hand 邻居；只接受欧氏距离 `< 0.02 m` 的边；无有效邻居的物体点 `contact_feature=0`。

所有点、法向、flow 和物体位姿继续使用现有 OI-Cm 的单位与坐标声明。不得把 future geometry、`obj_flow_gt` 或未来 hand 状态输入当前几何分支。

### 2.2 结构元数据

V1.0 必须能读取或生成以下字段，即使 rigid smoke 中部分字段为固定值：

```text
obj_link_id       [N]       # V1.0 全为 0，仅用于分组，不作为语义 embedding
num_links         scalar    # V1.0 = 1
joint_parent      [J]
joint_child       [J]
joint_type        [J]
joint_axis        [J,3]
joint_origin      [J,3]
joint_limits      [J,2]
joint_q           [J]
```

link 编号只参与 pooling/grouping；语义来自几何和关节结构，不能学习固定 link-ID embedding。V1.0 `J=0`，后续 articulated 版本必须显式校验 parent/child、轴、原点、单位和跨帧 correspondence。

## 3. 编码与表示

1. **Object geometry encoder** 对全部物体点产生 `g_i`。
2. **Local interaction encoder** 对每条有效 hand-object 边使用相对位置、距离、法向、法向夹角、hand flow 的 normal/tangent 分量等特征，产生 `c_i`。
3. **Direct part pooling** 分别聚合完整几何 `G_l` 和 active contact `I_l`，避免小接触区域被长物体稀释。
4. **Grounded contact tokens** 只压缩 active contact features。每个 token 必须携带可回投的 anchor position、anchor normal、所属 link mask 和 attention mass；token 数量为配置项并带 mask，不把固定 slot index 当作跨手型语义。
5. **Hybrid fusion** 将 direct part representation 与同 link 的 token cross-attention 结果相加/融合；token 是可迁移的 interaction interface，但不是 effect predictor 的唯一信息瓶颈。
6. **Articulation graph** 在 V1.0 保留 graph API；单节点无 joint message passing。后续多 link 版本以 joint type/axis/origin/q 为 edge features。

推荐的局部 contact feature 宽度为 128，具体 hidden width、token 数和层数属于实现参数，必须进入配置与 manifest，不改变上述外部合同。

## 4. Effect 与 point-flow 输出

effect head 输出：

```text
delta_xi_root = [tx, ty, tz, rx, ry, rz]
p_effect
optional log_sigma_root
```

`delta_xi_root` 表示现有 object frame 中的相对刚体变换，不使用 COM 作为定义。V1.0 无 joint output；接口保留 `delta_q[0:J]`。

由结构化 effect 通过 FK 得到：

```text
obj_flow_structured: [B,1024,3]
obj_flow_pred = obj_flow_structured + obj_flow_residual
```

residual head 可配置开启，并以零范数正则约束；其作用是暴露 cache/metadata 或未建模几何问题，不能替代结构化路径。最终监督仍兼容现有 point-flow 指标。

## 5. Loss 与证据边界

V1.0 保留 point-flow SmoothL1 主损失，并可加入 root transform、effect/no-effect、contact hand-flow auxiliary 和 residual penalty。各项权重必须在配置中声明并记录尺度来源。

刚体 FK 重建、forward/backward、checkpoint save/load、manifest 和 shape/mask 检查属于工程 smoke 证据；它们不能证明跨手型迁移、articulation 效果或真实数据收益。科研结论必须由后续独立 experiment 记录。

## 6. 不变量与兼容边界

- 不修改旧 `ObjectInteractionCm` 的代码、配置、cache、split、checkpoint、输出或运行进程。
- V1.0 不改变旧 OI-Cm 的坐标系、单位、GT point-flow 语义和评估定义；新 Task 使用独立 cache/config/output 入口。
- train/val/test split 若复用既有索引，必须显式引用并保持 sequence/episode/object-disjoint；不得静默重划分。
- 新 checkpoint 不承诺旧 OI-Cm checkpoint 直接加载；若未来提供 adapter，必须单独记录兼容合同。
- 任何缺失/越界 KNN、错误坐标声明、非 finite 几何、结构元数据不一致或未来信息泄漏都必须 fail-fast。
