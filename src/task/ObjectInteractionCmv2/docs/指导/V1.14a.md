这里：

* **N = object points 数量**
* **H = hand points 数量**

在你们现在这个 benchmark 里：

$$
N=1024
$$

因为每个物体最终采样 1024 个 surface points。

而：

$$
H=4096
$$

是 benchmark 里设定的手表面点数量。对于不同数据源实际 H 可能不同，例如 Inspire 原始高分辨率手点可以更多；V1.13 compact cache 就是在避免训练时反复读取这些完整手点。

所以 endpoint KNN 本质是在做：

$$
N\times H
$$

即每个物体点去手点里找邻居。

K=8 candidates 时，现在 benchmark flatten 后相当于：

$$
8\times1024\times4096
$$

组距离；而 start 和 end 各算一次，所以大约：

$$
2\times8\times1024\times4096
\approx67\text{ million}
$$

个点对距离。

其中：

* \(N=1024\)：物体表面 query 点；
* \(H=4096\)：手表面候选点；
* \(K=8\)：actor 产生的 8 个候选动作；
* 最后的 **32** 是每个 object point 保留的 hand neighbors 数，即 `top-32`。

可以把形状理解成：

```text
object points:        [B, N, 3]       N=1024

hand points:          [B, H, 3]       H=4096

candidate hand end:   [B, K, H, 3]    K=8

最终邻居:
edge indices:         [B, K, N, 32]
```

而刚才我说 start KNN 可以共享，就是因为 K=8 时：

$$
h_t[B,H,3]
$$

完全相同；只有：

$$
h_{t+1}^{(k)}
$$

随 candidate \(k\) 变化。因此 start 部分理论上应该是 `[B,N,H]` 算一次，而不是 `[B,K,N,H]` 算八次。
