对。这里应该把两个问题拆开：

1. **物体表面的 grounded tokens 怎么保留**
2. **如何从一个整体预测，改成逐 part 预测**

而且你明确不要 residual 的话，我认为架构可以非常干净。

先说当前实现：你们现在其实有两套没完全接上的结构。

当前 `V1.3 rigid` 是：

```text
object points
   │
   ├─ geometry encoder ───────────────→ global geometry feature
   │
hand interaction
   ↓
per-point contact feature
   │
   ├─ attention pool ────────────────→ interaction feature
   │
   └─ CompetitiveContactTokens
            ↓
       K=16 surface tokens
       + anchor
       + normal
       + mass
            ↓
       token encoder
            ↓
direct feature --cross-attention--> tokens
            ↓
        一个 fused feature [B,D]
            ↓
        root_head
            ↓
          Δξ [B,6]
```

所以现在之所以只能预测整个物体，是因为 **attention 之后把信息压成了一个 `[B,D]` feature**，然后只有一个 `root_head`。

而 `articulated.py` 又走了另一条路：它没有使用这 16 个 grounded surface tokens，而是直接根据 `obj_link_id` 对 point feature 做 `_segment_mean()`，得到 `[B,L,D]` 的 link nodes，再进入 joint graph。

我认为这两条应该重新合并。

# 我建议的新架构

核心形式就是：

> **surface token 保留；part 也变成 token/query；最后一直保留 `[B,L,D]`，不要再 pool 成 `[B,D]`。**

整体：

```text
                         object surface
                              │
                    geometry feature g_i
                              │
hand start/end ─ KNN ─→ interaction feature c_i
                              │
                ┌─────────────┴──────────────┐
                │                            │
                ▼                            ▼
        surface tokenization            part grouping
          K=16 tokens                 by obj_part_id
                │                            │
                ▼                            ▼
       S = [B,K,D]                    P = [B,L,D]
                │                            │
                └──────────┬─────────────────┘
                           ▼
                part → surface cross-attn
                           │
                           ▼
                     P' = [B,L,D]
                           │
                     part self-attn
                           │
                           ▼
                    P'' = [B,L,D]
                           │
                  shared SE(3) head
                           │
                           ▼
                  Δξ_part = [B,L,6]
                           │
              gather with obj_part_id
                           │
                           ▼
                     point flow
```

这里**没有 residual，也没有 root + joint。**

就是每个 part 直接预测自己的 `SE(3)`。

## 1. ID 不应该直接拼到 feature 后面

这里我觉得要改一下你说的“把 ID 拼在物体特征后面”。

当前 `articulated.py` 实际上没有这么做，这是正确的：

```python
geometry = _segment_mean(
    geo,
    batch["obj_link_id"],
    link_valid,
)
```

`obj_link_id` 只是告诉我们：

```text
point 0 ─┐
point 1 ─┤ part A
point 7 ─┘

point 2 ─┐
point 3 ─┤ part B
point 8 ─┘
```

而不是：

```text
feature_i = [geometry_i, part_id_i]
```

后者我不建议。

因为假设：

```text
part A = 0
part B = 1
```

交换成：

```text
part A = 1
part B = 0
```

物理问题根本没变。

但如果把：

```text
0 / 1
```

作为 feature 输入，网络看到的输入就变了。

所以 **part ID 应该是 routing/grouping information，不是语义 feature。**

# 2. Part feature 怎么产生？

对于每个 part \(l\)，从属于它的 points 聚合：

$$
G_l =
\operatorname{Pool}
\{g_i \mid part(i)=l\}
$$

以及 interaction：

$$
C_l =
\operatorname{Pool}
\{c_i \mid part(i)=l\}
$$

得到：

```text
G_part [B,L,D]
C_part [B,L,D]
```

然后：

```text
part_query_l =
MLP(
    geometry_l
    +
    interaction_l
)
```

或者 concat：

```text
P_l = MLP([G_l, C_l, active_fraction_l])
```

这和现在 `articulated.py` 已经做的非常接近：

```python
geometry = _segment_mean(...)
interaction = _segment_mean(...)
active_fraction = _segment_mean(...)

nodes = link_encoder([
    geometry,
    interaction,
    active_fraction
])
```

所以这一块基本可以直接保留。

---

# 3. 那 16 个 surface token 怎么办？

**也保留。**

因为 part pooling 和 surface token 不是重复信息。

Part pooling 回答的是：

> 这个刚性部件整体长什么样、整体受到了多少交互？

而 grounded surface tokens 回答的是：

> 具体是物体表面的哪里被手作用、作用方向和空间分布是什么？

例如打开笔记本：

```text
screen part
┌─────────────────────┐
│                     │
│              手 → X │
│                     │
└─────────────────────┘
```

如果只做：

```text
screen 所有 contact feature → mean
```

很容易丢掉：

> 接触是在屏幕边缘，还是靠近转轴的位置。

而你们现在：

```text
token_anchor
token_normal
token_mass
```

恰好保留了这种 spatial grounding。

所以它应该留下。

# 4. 真正应该改变的是 cross-attention 的 query

现在 V1.3：

```python
attended, _ = self.cross_attention(
    direct[:, None],
    spatial_tokens,
    spatial_tokens,
)
```

注意这里 query 是：

```text
direct[:,None]
shape = [B,1,D]
```

所以最后必然只有：

```text
[B,1,D]
```

也就是一个 object feature。

要逐 part 预测，只需要把 query 从一个变成 L 个：

```text
part_query
shape = [B,L,D]
```

然后：

```python
part_attended, _ = cross_attention(
    query=part_query,
    key=surface_tokens,
    value=surface_tokens,
)
```

得到：

```text
[B,L,D]
```

于是：

```text
part 0 query
   ↓
关注与 part 0 motion 有关的 surface tokens

part 1 query
   ↓
关注与 part 1 motion 有关的 surface tokens
```

这就是逐 part 的关键。

# 5. 但 surface token 怎么知道自己属于哪个 part？

这是这里最值得设计好的地方。

我不建议给 token 再硬塞：

```text
part_id embedding
```

因为同样有编号问题。

实际上你们 `CompetitiveContactTokens` 已经有 assignment weight：

$$
w_{ik}
$$

意思是：

> object point \(i\) 有多少质量被分给 surface token \(k\)。

而我们又知道每个 point 的：

$$
part(i)
$$

所以可以免费得到：

$$
M_{lk}
=
\sum_{i:part(i)=l} w_{ik}
$$

也就是：

> **token k 有多少质量来自 part l。**

例如：

```text
          token0 token1 token2 token3
part A     0.95   0.80   0.05   0.00
part B     0.05   0.20   0.95   1.00
```

这比人工给 token 一个 ID 更自然。

于是 part A 的 query 对 surface token 做 attention 时，可以用：

```text
M_Ak
```

作为 attention bias / routing mask。

### 这样：

```text
obj_part_id
      ↓
只参与 routing
      ↓
point → part
point → surface token
      ↓
自动得到
part ↔ surface-token correspondence
```

**完全不需要 learned ID embedding。**

---

# 6. 然后为什么还需要 part self-attention？

因为有些 part 没有被手直接碰。

比如：

```text
laptop

part 0 = base
part 1 = screen

手只接触 screen
```

screen 的 surface tokens 有很强 interaction。

base：

```text
interaction ≈ 0
```

但 base 的运动并不一定是 0，因为整个 laptop 也可能被移动。

所以：

```text
part0 feature
part1 feature
```

之间还是需要通信。

但这里没必要知道：

```text
parent
child
revolute joint
```

直接：

```text
Part Self-Attention
```

即可：

```text
          ┌── part A ──┐
          │     ↕      │
          │   attn     │
          │     ↕      │
          └── part B ──┘
```

也就是 Set Transformer 式的：

```python
parts = self.part_self_attention(
    parts,
    parts,
    parts,
    key_padding_mask=~part_valid_mask,
)
```

这样模型可以自己学习：

> part A 的 interaction 会如何影响 part B。

没有显式动力学 graph。

# 7. 最后怎么逐 part 预测？

这里其实最简单。

**不要再 pool。**

当前 articulated：

```python
node_pool = mean(nodes)
delta_xi = root_head(node_pool)
```

把这一步删掉。

直接：

```python
delta_xi_part = self.part_motion_head(parts)
```

如果：

```text
parts.shape = [B,L,128]
```

共享的：

```python
Linear(128, 6)
```

直接得到：

```text
delta_xi_part.shape = [B,L,6]
```

也就是：

```text
part 0 → [tx,ty,tz, rx,ry,rz]
part 1 → [tx,ty,tz, rx,ry,rz]
part 2 → [tx,ty,tz, rx,ry,rz]
```

这里用的是**同一个 head**：

```text
shared part head
```

不是：

```text
head_0
head_1
head_2
```

因此交换 part 编号只会交换输出的位置，不改变物理意义。

# 8. Flow 怎么出来？

对于 object point \(i\)：

```text
part_id[i] = l
```

直接取：

```text
Δξ_i = Δξ_part[l]
```

然后：

$$
p_i^{next}
=
SE3(\Delta\xi_l)p_i
$$

所以：

$$
flow_i
=
p_i^{next}-p_i
$$

代码概念上：

```python
point_delta_xi = gather(delta_xi_part, obj_part_id)

future_points = transform_points_by_part(
    obj_points,
    point_delta_xi,
)

obj_flow_pred = future_points - obj_points
```

**没有 residual。**

也没有：

```text
root transform
+
joint transform
+
FK
```

就是：

```text
每个 rigid part
→ 一个直接 SE(3)
```

object:

    normals [B,N,3]

## 最重要的三点

第一，**保留你们现在的 surface token**。它们非常重要，因为 Cm 最需要的恰恰是“作用发生在物体表面的哪里”。

第二，**part ID 不进入 feature embedding，只负责 grouping/routing**。

第三，attention 以后不要：

```text
[B,L,D]
→ pool
→ [B,D]
→ 一个 SE3
```

而是始终保留：

```text
[B,L,D]
→ shared part head
→ [B,L,6]
```

这样就天然获得逐 part prediction。

而且它有一个很好的退化性质：

```text
GRAB:
L=1
[B,1,D]
→ [B,1,6]
```

自动就是现有 rigid prediction。

ARCTIC：

```text
L=2
→ 两个直接 SE(3)
```

OakInk2：

```text
L=1,2,3,...
→ 对应数量的 SE(3)
```

因此如果我们决定“不再使用显式 joint graph”，我会认为 **`V1.3 surface-token architecture + part queries + part self-attention + shared per-part SE3 head`** 才是最自然的下一版，而不是从现在的 `articulated.py` graph 上继续修修补补。
