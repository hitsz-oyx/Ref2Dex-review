## 1. 目标与语义替换

V1.12 将 V1.3 的 grounded surface-token 路径与 V1.5 的逐部件 grouping 路径合并，形成统一的
`endpoint interaction -> surface tokens + part queries -> per-part SE(3) -> point flow` 模型。

本版明确替换以下 V1.11 训练语义：

- 不再使用手点运动线段到物体点的 `swept_topk`；
- 不再使用 `root SE(3) + joint delta + analytic FK`；
- OakInk2 不再每个 transition 只抽一个刚性部件，而是输入同一实例的整体多部件点云；
- GRAB、ARCTIC、OakInk2 均由同一个共享 part head 为每个有效刚性部件直接预测一个 SE(3)；
- 不使用 residual flow、part-ID embedding 或显式 joint graph。

GRAB 以 `L=1` 自然退化为单刚体；ARCTIC 以 `L=2` 直接预测两个部件 SE(3)，不再输出
`delta_q`；OakInk2 使用 `L=1..3` 的真实组件集合。正式训练从随机初始化开始，不加载或宣称兼容
V1.11 checkpoint。

## 2. 数据、坐标和整体点云

### 2.1 数据范围

保持 V1.11 的五组来源不变：GRAB/MANO、ARCTIC/MANO、OakInk2/MANO、GRAB/Inspire、
OakInk2/Inspire。保持既有 recording holdout、split、stride `{1,2,3}`、手点身份、时间连续性门禁、
米/秒/弧度单位和同一 transition 内的起止点对应。V1.12 实现及有界 smoke 不自动批准新的正式训练运行。

### 2.2 公共参考坐标系

每个样本的整体物体点、法线、手点、手流、部件 GT 和输出均表达在当前帧已有的参考物体坐标系中：

- GRAB 使用当前物体 pose；
- ARCTIC 使用当前 root pose；
- OakInk2 沿用 cache 的当前 `obj_pose_world` 参考 pose。

OakInk2 的该 pose 只作为公共坐标系，不再被解释为整个多部件对象的刚体运动标签。每个 OakInk2
部件的 pose GT 仍来自官方组件逐帧 SE(3)；禁止用未来点云 SVD 拟合伪 GT。

### 2.3 4096 到 1024 的逐部件分层采样

每个 transition 从整体 4096 点池抽取总计 1024 点，而不是每个部件各抽 1024 点：

1. 根据稳定 `obj_point_id` / `obj_part_id` 统计每个有效部件在 4096 点池中的占比；
2. 每个有效部件先分配最多可用且不少于 64 点的 quota；若该部件池不足 64，则取其全部；
3. 剩余名额按原池占比和最大余数法确定性分配，且不放回采样；
4. 使用 source path、起始 source-frame ID、split 和固定 seed 生成稳定抽样；
5. 起始帧和末帧严格复用同一组 object point ID。

采样后 part ID 可压缩为 batch 内连续索引，但只用于 grouping、routing 和 gather；不得进入 learned
embedding。对 part 编号做任意置换时，输出必须只发生相同置换。

## 3. 端点 KNN 合同

对每个起始物体点 `o_t[i]` 和具有稳定身份的手点流 `h_t[j] -> h_e[j]=h_t[j]+flow[j]`：

1. 以固定的 `o_t[i]` 为 query，对 `h_t` 取欧氏距离 top-32；
2. 仍以同一个 `o_t[i]` 为 query，对 `h_e` 取欧氏距离 top-32；
3. 对两组手点 ID 作稳定并集，候选最多 64 个；
4. 对每个候选计算 `d_endpoint(i,j) = min(||o_t[i]-h_t[j]||, ||o_t[i]-h_e[j]||)`；
5. 按 `d_endpoint` 升序、手点 ID 升序作稳定重排，最终只保留最近 32 个；
6. `d_endpoint < 0.02 m` 且 hand-valid 的边才有效。

因此模型每个物体点的邻居上限仍为 32，不读取未来物体位置选择邻居，也不计算线段投影距离。
保留起点/终点相对位置与距离、起始手法线、手流、法向/切向流、`delta_time_s` 和速度特征；原
swept-distance 槽由 `d_endpoint` 替换。相同距离时必须由较小手点 ID 胜出，CPU 参考与 GPU 实现
需逐索引一致。

## 4. 模型架构

### 4.1 点级几何与交互

- 宽度保持 `D=128`。
- V1.3 geometry encoder 对完整 1024 点编码 `g_i [B,N,D]`，保留当前中心化、RMS scale 和
  `log(scale/0.02m)` 物理尺度表达。
- endpoint-KNN local interaction encoder 产生 `c_i [B,N,D]` 和逐点 `has_interaction`。

### 4.2 Grounded surface tokens

沿用 V1.3 的 `CompetitiveContactTokens`，全对象共产生 `K=16` 个 token，并保留：

```text
surface_tokens [B,K,D]
token_anchor   [B,K,3]
token_normal   [B,K,3]
token_mass     [B,K]
token_mask     [B,K]
assignment     [B,N,K]
```

assignment 必须作为内部 routing 证据暴露给 part-surface 融合；无 active object point 时 token、
anchor、mass 和 mask 均为零。

### 4.3 Part queries

对每个有效 part 分别聚合其 geometry、interaction 和 active fraction：

```text
G_part = segment_mean(g_i)
C_part = segment_mean(c_i over active points)
P      = part_encoder([G_part, C_part, active_fraction])  # [B,L,D]
```

`obj_part_id` 只作为 segment selector，不拼接进 point/part feature，也不建立 learned ID embedding。

### 4.4 固定 soft routing prior

令 `w_ik` 为 point `i` 分配给 surface token `k` 的竞争权重。对 part `l` 和 token `k`：

```text
part_mass_lk      = sum_{i:part(i)=l} w_ik
rho_lk            = part_mass_lk / (token_mass_k + eps)
attention_bias_lk = log(rho_lk + eps)
```

其中 `eps=1e-8`，bias 系数固定为 1，不设可学习温度。`log(rho+eps)` 作为每个 head 共用的 additive
cross-attention prior；token mask 仍屏蔽空 token。

若某个 part 的 `sum_k(part_mass_lk) <= eps`，该 part 的 surface cross-attention 输出必须严格置零，
不能因 `eps` 获得伪 interaction；随后它只能通过 part self-attention 接收其他部件的信息。

### 4.5 Part-to-surface、part-to-part 与输出

1. `P [B,L,D]` 作为 query，对 16 个 spatial surface tokens 做一次 4-head cross-attention；
2. 将 query 与 routed surface 输出拼接，经共享 fusion MLP 得到 part features；
3. 对有效 part 做一次 4-head self-attention，padding part 通过 `part_valid_mask` 屏蔽；
4. 使用同一个共享 `Linear(D,6)` 为每个有效 part 输出
   `delta_xi_part [B,L,6] = [translation, axis_angle]`；
5. 按 `obj_part_id` gather 对应 SE(3)，直接变换每个物体点并得到 `obj_flow_pred`。

cross-attention、self-attention 和共享 head 均不得依赖 part 的编号。模型不输出或训练
`delta_xi_root`、`delta_q`、joint nodes、residual flow 或 `p_effect`。

## 5. GT、loss、指标与 checkpoint

### 5.1 逐部件直接 GT

每个有效 part 的当前/未来真实 pose 转换到 §2.2 的当前公共参考坐标系，得到：

```text
delta_translation_part_gt [B,L,3]
delta_rotation_part_gt    [B,L,3,3]
part_valid_mask           [B,L]
```

解析变换必须在相同点身份上逐点 replay `obj_flow_gt`，误差阈值沿用既有 0.2 mm 门禁；失败时
fail-fast，不静默退化成点云拟合。最终 flow GT 仍是相同 1024 点在未来帧与当前帧公共坐标中的差。

### 5.2 Loss

- translation：每个有效 part 的 SmoothL1，平移除以 `0.02 m`；先在 sample 内对有效 part 等权，
  再对 batch 等权；
- rotation：预测 rotation 与 GT 的 SO(3) geodesic angle；先在 sample 内对有效 part 等权，再对
  batch 等权；
- flow：`obj_flow_pred / 0.02m` 与 `obj_flow_gt / 0.02m` 的普通逐点 SmoothL1，先对全部有效点平均，
  不做 part reweight，避免小或 noisy part 被过度放大。

总损失固定为 `L_total = L_translation + L_rotation + L_flow`，三项权重均为 1。validation 以
`L_total` 选择 best，同时分别报告 translation、rotation、原始米制 point-flow EPE、样本数、
transition 数和各 part-count 分组计数。新指标不得与 V1.11 的 root/joint structured loss 直接横向比较。

### 5.3 Checkpoint

V1.12 使用新的 architecture/schema 标识并从随机初始化开始。V1.11 `v1_5_articulated_fk` 和 V1.3
rigid checkpoint 均不得 strict load，也不进行部分 warm start；optimizer、step、epoch 和 best
状态全部从零开始。

## 6. Cache 与实施边界

本轮接受现有 cache 已保存完整 4096 物体池和高分辨率手点流的事实，不重写、不迁移、不删除旧
cache。endpoint KNN 首版从现有 mmap 数组读取起止手点并精确在线计算；因此本计划不声称已经解决
NAS 随机读取或总 I/O working-set 问题。

本轮不创建 endpoint 派生 cache。若实现验证后需要物化紧凑 cache，必须另行确认 schema、stride、
抽样身份、存储预算和构建运行；产物只能进入独立
`data/processed_data/oicmv2_endpoint_knn/<schema>/<run_id>/`，不得覆盖现有 cache。

实现限制在 `src/task/ObjectInteractionCmv2/`：

- 新增独立 V1.12 model/dataset 路径，保留 V1.11 runner、模型和配置可复现；
- 按需复用 `model.py` 的稳定纯函数，不修改 `src/base/`；
- 新配置使用独立 schema/文件名，不能让旧 runner 静默接受；
- Task-local 测试放在 `src/task/ObjectInteractionCmv2/tests/`；
- 当前 V1.11 正式训练的 source snapshot、进程、输出和 checkpoint 不受工作树修改影响。

## 7. 验证门禁

### 7.1 纯函数与合成测试

- endpoint top-32 + top-32 并集、按最小端点距离重排、最终 top-32、2 cm mask 和稳定 tie-break；
- 末端邻居只依赖 `o_t`、`h_t`、`hand_flow`，改变未来物体 GT 不得改变任何输入边；
- 4096→1024 quota 总和、每部件至少 64 点、无放回、确定性和起止点 ID 一致；
- per-part SE(3) replay、近零/近 pi SO(3) geodesic 的 finite forward/backward；
- `rho` 归一、`log(rho+eps)` prior、空 token、无 interaction part 严格零 surface 输出；
- part 编号置换等变性、point 顺序置换等变性、padding mask；
- GRAB `L=1`、ARCTIC `L=2`、OakInk2 `L=1/2/3` 的有限前向和反向；
- 参数、输出和 loss 中不存在 residual、joint/FK、`p_effect` 或 part-ID embedding。

### 7.2 真实数据检查

- GRAB、ARCTIC、OakInk2 × MANO/Inspire 各抽真实 transition，与全量计算参考逐索引比较 KNN；
- 全量核对每域 pose/point-flow replay、part ID 范围、跨帧 identity、split 和时间连续性；
- OakInk2 MANO/Inspire 对应 segment 的 component identity、采样 quota 和 GT 必须一致；
- 分别测量 mmap 等待、H2D 和 GPU 计算时间；吞吐只作工程证据，不作为科学效果。

### 7.3 工程门禁

- CPU 合成 forward/backward；
- 单 GPU 真实 batch 的有限 forward/backward 和 checkpoint round-trip；
- Task 定向 pytest、`git diff --check`、`python tools/verify.py --changed`；
- 有界 smoke 只证明接线正确，不得作为模型有效性结论。

## 8. 风险、停止条件与回滚

主要风险：

- 直接逐部件 SE(3) 不施加真实关节约束，ARCTIC/OakInk2 可能预测物理不一致的相对运动；
- 全局 16 个 surface tokens 可能忽略小部件，soft prior 也不能保证 token 不 collapse；
- 每部件至少 64 点改变原整体随机抽样分布；
- 普通逐点 flow loss 仍会由大部件主导；
- 随机初始化与新 loss 使 V1.11 曲线和 checkpoint 不具可比解释；
- 在线 endpoint KNN 仍需读取完整手流，未必改善 NAS I/O。

若出现未来物体信息进入邻居选择、部件 pose 无法 replay 点流、part permutation 改变非对应输出、
无 interaction part 获得非零 surface 输出、非 finite 梯度或旧 checkpoint 被误加载，则停止实施并
回到计划协商。

回滚只需切回 V1.11 runner/config。V1.12 使用独立模型、配置、测试及未来运行目录；不得停止或删除
V1.11 服务、cache、adapter、checkpoint 或输出。
