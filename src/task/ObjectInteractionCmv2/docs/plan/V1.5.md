## 范围

新增 Task-local articulated loader/model/runner contract 和定向测试：从已有 ARCTIC geometry 读取
part ID、current q、root pose；构造 root-frame targets、link/joint masks；完成 root + revolute FK、
link-wise pooling、两轮 joint graph、root/joint heads 与结构化 loss。新增的 V1.5 runner 仅用于小型 smoke，
不自动复用 V1.4 checkpoint。

## 保持不变

`model.py` 中 V1.0--V1.4 的 rigid 实现、`multi_domain.py` 的 V1.4 loader、所有已有配置、原始数据、
cache、split、queue、output、checkpoint 和 `src/base/` 均不改动。ARCTIC joint axis/origin 作为 V1.5
source metadata 显式声明；不能按 object 名称隐式猜测，也不写回现有 cache manifest。

## 接口与不变量

- batch：`obj_link_id[B,N]`、`link_valid_mask[B,L]`、`joint_parent/child[B,J]`、
  `joint_axis_root/origin_root[B,J,3]`、`joint_q_t[B,J]`、`joint_valid_mask[B,J]`；GRAB 的 joint mask 全 false。
- target：`delta_xi_root_gt[B,6]`、`delta_q_gt[B,J]`、`obj_flow_gt[B,N,3]`；forward 不得读取 future root/q/points。
- first-stage ARCTIC joint 为 producer-verified `axis=(0,0,-1), origin=(0,0,0)` 的 revolute transform；metadata 必须显式传入并经 unit/finite/
  parent-child/mask 校验。
- FK 按 current q 到 predicted q 的相对 link transform 再复合 predicted root transform；rigid reduction
  逐点一致。
