## 1. 目标

V1.12 正式 run 的数据集加载约为 `17 min 01 s`，进入训练后前 200 step 平均约
`4.09 s/step`。V1.13 的目标是停止在训练时反复从 NAS 读取完整 4096 物体池和完整高分辨率手流，
并移除每个 batch 的全手流 endpoint KNN 搜索。

V1.13 只改变数据表示和读取路径。模型参数、1024 点采样、endpoint top-32 union-rerank、坐标与单位、
逐部件 GT、loss、五组 split、stride、随机种子、batch、validation 和 checkpoint 含义均保持 V1.12 不变。

## 2. 方案

### 2.1 独立紧凑 cache

新增不可变 schema `object_interaction_cmv2_compact_endpoint_v1`。producer 对每个实际 transition 执行
一次 V1.12 参考路径，并保存训练真正需要的内容：

- transition 身份、split、group、stride、起止 source-frame ID 与确定性 1024 点 ID；
- 1024 点的坐标、法线、part ID、point-flow GT、逐部件 SE(3) GT 与 `delta_time_s`；
- endpoint union-rerank 后的 32 个邻居；按 transition 去重手点，保存 float32 的起点、法线、flow，
  再用 `[1024,32]` 局部索引恢复边，避免复制完整手流或重复邻居；
- edge valid mask 及审计所需的原始 hand-point ID。

cache 使用固定大小 shard 加索引，禁止“一条样本一个小文件”。规范位置为
`data/processed_data/oicmv2_endpoint_knn/object_interaction_cmv2_compact_endpoint_v1/<build_run_id>/`；
只提交 producer、schema 和测试，不提交 cache。manifest 必须记录 producer commit、源 manifest/hash、
split、坐标/单位、dtype、记录数、字节数、分组计数和验证结果。旧 cache 不覆盖、不迁移、不删除。

### 2.2 训练读取

- dataset 启动时只读紧凑索引，不再为 train 和 15 个 validation 视图重复扫描全部序列 mmap；
- rank 独立懒加载 shard，使用有界句柄缓存、顺序预取和 pinned-memory 搬运；
- 模型跳过全手流 KNN，只把已选择邻居送入与 V1.12 相同的 edge encoder；在线 V1.12 路径保留为
  parity/reference 后端；
- sampler 的数据集长度、行顺序和 RNG 消耗必须与 V1.12 一致，因此相同 seed 产生相同 transition 序列。

NAS 上的紧凑 cache 是唯一权威副本。若 NAS 仍限制吞吐，可在运行前把 immutable shards 校验后镜像到
用户确认的本地 NVMe scratch；本地副本可删除，路径与 hash 必须写入 run manifest，不得放进仓库或 outputs。

## 3. 实施与门禁

1. 先给 V1.12 在线路径增加只读计时：dataset construction、sample read/transform、KNN、H2D、model；
2. 五组各选一个 sequence 构建 pilot，统计去重邻居数、压缩比和预计全量容量；若预计紧凑 cache 大于
   对应源训练 working set 的 `1.25x`，停止全量构建并只实施索引复用/懒加载；
3. 实现 producer、shard reader、reference/compact 双后端及 Task-local 测试；
4. 对五组和 stride 1/2/3 做抽样 parity：transition/点/hand ID 与 mask 完全一致，float32 输入、GT、
   forward 和 loss 在 `atol=1e-6, rtol=1e-6` 内一致；全量 manifest 校验 `bad_count=0`；
5. 在 GPU0+2、B64×2 上分别做冷启动和热缓存 benchmark。相对 V1.12 记录，验收目标为 dataset
   construction `<=3 min`、训练 step 中位数 `<=2.5 s`，且无非有限值、OOM 或 FD 泄漏；
6. `git diff --check`、Task 定向 pytest 和 `python tools/verify.py --changed` 全部通过后，才向用户申请
   全量 cache 构建及新的正式训练授权。

pilot、cache build、benchmark 和正式训练使用不同 run_id；工程吞吐只作性能证据，不作模型效果结论。

## 4. 风险、停止条件与回滚

主要风险是派生 cache 体积过大、producer 与在线路径漂移、shard 随机读取仍受 NAS 限制，以及预取增加
主存压力。出现任一 parity 失败、source hash 不符、split/行序变化、容量超门限、内存不可控或性能未达标时，
停止扩大构建，不启动正式训练。

回滚只需把配置切回 V1.12 reference backend；模型和 checkpoint 不需转换。删除派生 cache 或本地镜像属于
独立破坏性操作，必须另获用户授权。
