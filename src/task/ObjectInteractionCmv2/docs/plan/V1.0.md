## 1. 目标

建立独立的 `ObjectInteractionCmv2` Task，验证“局部交互 + 全局结构 + 结构化 effect/FK”在当前 rigid-object 数据上的可运行合同，并为后续 articulated object 与跨手型 token transfer 留出稳定接口。

## 2. 保护边界

保留旧 `ObjectInteractionCm` 的全部代码、未提交改动、数据/cache、split、checkpoint、输出和运行进程。新 Task 使用独立配置、cache/index、运行目录和 checkpoint；本版本不接入 ARCTIC/剪刀全量训练、不迁移数据、不改共享 `src/base`。

## 4. 实施阶段

1. **合同落地**：把 V1.0 架构中的输入 shape、2 cm/32-NN、坐标/单位、link metadata、mask 和 point-flow 输出写成 Dataset/Model contract。
2. **rigid baseline**：实现单 link pooling、grounded contact token、hybrid fusion、root `SE(3)` effect head 和 FK flow reconstruction；`num_links=1, J=0`。
3. **最小验证**：使用小型、独立且可追溯的 rigid 数据做 CPU/GPU smoke，覆盖空接触、有效接触、forward/backward、FK flow、checkpoint round-trip 和 manifest。
4. **对照诊断**：在同一输入/预算下比较结构化 head、token-only head 与 hybrid head 的工程指标和 point-flow 指标；只记录结果，不预先宣称科研收益。
5. **后续边界**：articulation graph、多 link cache、ARCTIC/剪刀和正式训练另建 `V1.0.k` 操作记录；若改变 schema/GT/split/坐标或 checkpoint 解释，必须重新审批 L2/L3。

## 7. V1.0 冻结参数

- rigid smoke 首先使用独立 synthetic contract，固定 `seed=42`、至少 16 个样本和可重复的空接触/有效接触覆盖；通过后才接入现有真实 rigid cache 的只读副本。
- grounded token 最大数量为 `K=16`（带 active mask），token/part hidden width 为 `128`；这些是 V1.0 配置默认值，不赋予 slot index 语义。
- residual flow head 默认开启，用零范数正则；若对照显示其长期承担主要流量，停止并记录为结构路径未充分建模，不静默调大 residual 容量。
- 对照实验从独立随机初始化开始，在相同输入、split、seed、训练步数和评估指标下比较 token-only、structured 和 hybrid；不加载旧 OI-Cm checkpoint。
- loss 权重先按训练集各项的 finite scale 校准并写入配置/manifest；不改变 GT、坐标系、单位和 point-flow 指标定义。

上述默认值只冻结 V1.0 的工程实现与验证边界；articulation、多 link cache、ARCTIC/剪刀和正式训练仍须另建 `V1.0.k` 操作记录。
