## 1. 改变与保护项

改变：新增 V1.14a-native lean geometry schema，只保存训练实际读取的物体点/法向/位姿、时间与帧 ID、固定
左右各 2048 手点/法向和 2 cm candidate mask；不落盘 decoder 手流、离线 KNN、5 cm mask 或手监督辅助数组。
仅从本地 Stage4 GRAB 生成 MANO 与 Inspire 两组 cache，并从随机初始化执行已批准的一轮本地双组训练。

保持：沿用 `stage4/splits/full_grab_v1` 的 1335 条序列与 `1068/134/133` split、30 Hz、stride 1/2/3、
左右顺序、对象 4096→1024 采样、KNN32、2 cm、GT、坐标、米制单位、loss、两组 1:1 权重和 V1.14a 模型不变。
当前本地 Stage4 为 400616 帧，与历史 NAS cache 的 406264 帧不是同一输入身份，本运行不得解释为历史 run 的精确复现。

## 2. 实施、门禁与运行

1. 新增独立 lean producer/reader 合同和本地配置；数据写入 `data/processed_data/ObjectInteractionCmv2/v114c/`，
   运行写入既有 Task output 根，均不提交 Git，也不访问 NAS。
2. Inspire 先按冻结 seed=2024 生成每手 10135 点并计算既有全分辨率 2 cm mask，再按 V1.14a seed=42
   固定索引只保存每手 2048 点；MANO 的 4096 点不再二次改变。
3. pilot 必须通过数组/schema、左右顺序、固定索引 hash、reference→lean 数值 parity、split 身份、finite、
   active mask 和 loader/model smoke；同时记录实际字节数与读取/step benchmark，不预先承诺加速倍数。
4. full build 必须由已提交的干净代码产生，manifest 固定 commit、split SHA、输入路径、帧数、失败数和输出身份；
   `bad_count=0` 且 MANO/Inspire IDs 与 split 完全一致后，才生成双组 split 并启动 GPU0、batch16、seed42、1 epoch 训练。
5. 验证执行定向 pytest、`python tools/verify.py --changed`（若过渡期入口不可用则如实记录实际检查）与
   `git diff --check`；工程 smoke/吞吐只证明接线和性能，不构成科研效果结论。

## 3. 风险与回滚

主要风险是 Inspire 预选索引或 candidate mask 改变 transition 集、cache 生成超时、磁盘不足和本地 Stage4
身份差异。任一 parity/split/空间门禁失败即停止扩大运行；生成前要求保留至少 500 GiB 空闲，估算输出不超过
180 GiB。回滚只需停用 V1.14c config/schema 并保留失败 manifest；旧 cache、checkpoint、split 和代码入口不覆盖、不删除。
