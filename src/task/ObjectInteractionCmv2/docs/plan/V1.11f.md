## 范围

1. 保留当前 GPU2 上的 GRAB Inspire 续跑和已有输出；其 launcher 在 GRAB 成功后不再自动启动 ARCTIC，避免与并行服务双写。
2. 在空闲 GPU1 上以独立 user systemd service 启动 ARCTIC Inspire，使用独立 run ID、NAS 日志、状态和 TMPDIR；输出根仍为唯一的
   `/mnt/ugreen_nas/storage/Ref2Dex_storage/processed_data/oicm_v1_4_5_highres_full/arctic_inspire_20260920T055000Z`。
3. 两个 producer 使用相同的 source index、schema、点数、KNN32、坐标、单位和 split；只改变设备和启动并发，不改变研究语义。

## 保护与风险

- 不覆盖已完成 GRAB geometry、OakInk2 cache、输入、旧 queue、旧 manifest 或 checkpoint；不启动 OakInk2 job。
- 两个服务使用不同 output root、run directory 和 GPU；共享 NAS source 只读，可能增加 NAS/CPU 竞争。
- 本地系统盘仍仅约 `1.5 GiB` 可用；两个服务的临时文件、stdout/stderr 和状态均写 NAS，不自动清理本机内容。
- 任一服务失败只停止其自身，不自动重试；ARCTIC 失败不改变 GRAB 的已完成数据。

## 验证、终止与回滚

- 启动前确认 GPU1 空闲、ARCTIC output root 不存在、无第二个 ARCTIC producer；启动后核对两个 cgroup、manifest、日志和 GPU 映射。
- GRAB launcher 正常完成后只标记 GRAB 完成；ARCTIC service 独立记录自己的 exit code / signal 和 producer manifest。
- 停止 `ref2dex-cmv2-inspire-v111e.service` 或 `ref2dex-cmv2-arctic-v111f.service` 可单独终止对应任务；保留全部 cache、partial、日志和 manifest。
- 回滚调度为停止 ARCTIC service，并恢复 GRAB launcher 的顺序 ARCTIC 分支前必须另行确认；不删除任何数据。
