## 2. Cache 与 hand variant 合同

每个 sequence 的 geometry 至少包含：

```text
frame_time.npy                 [T]
source_frame_id.npy            [T]
obj_points_pool_world.npy      [T,4096,3]
obj_normals_pool_world.npy     [T,4096,3]
obj_pose_world.npy             [T,4,4]
hand_points_world.npy          [T,3076,3]       # decoder compatibility only
hand_normals_world.npy         [T,3076,3]
knn_hand_points_world.npy      [T,H,3]          # training input
knn_hand_normals_world.npy     [T,H,3]
obj_knn_indices.npy            [T,4096,32]      # uint16, high-res stream IDs
```

`hand_variant` 必须出现在 source index entry 或 geometry manifest，并且只能是：

| hand_variant | 每侧 KNN 点数 | 双手 H | 允许的来源 |
| --- | ---: | ---: | --- |
| `mano` | 2048 | 4096 | GRAB、ARCTIC、OakInk2 MANO |
| `inspire_f1` | 10135 | 20270 | Inspire geometric |

旧 decoder stream 固定为左右各 1538、双手 3076，仅用于兼容和审计；loader 拒绝将它作为高分辨率
训练输入。`obj_knn_indices` 的最大索引必须小于当前 variant 的 H。每个 geometry manifest 仍需声明
`knn_k=32`、2 cm 半径、30 Hz、`bilateral_merged_left_then_right` 和对应 `knn_points_per_side`。

## 3. Loader、batch 与模型

- source spec 必须显式写出 `{name, hand_variant, index, manifest}`；共享 GRAB/ARCTIC MANO index
  通过 `dataset` 过滤，不能把 ARCTIC 或错误 Inspire 条目混入 GRAB。
- 每个 sequence 按自己的 H 读取 `knn_hand_points_world`；当前和 future frame 都变换到当前
  `object_pose_t`，GT 仍为直接 SE(3) 相对位姿和物体点流。
- batch collate 只将 H padding 到该 batch 最大值，补零项的 `hand_valid_mask=false`；swept top-32、
  hand flow 和所有 hand feature/loss 都必须使用该 mask。
- MANO/Inspire 可出现在同一 batch；三域均衡按 domain label 计算，不按 variant 或原始行数改变
  `grab/arctic/oakink2 = 1/3`。

## 4. OakInk2 回填

使用现有 selection index 的 1849 个 selected segment。旧导出中 1656 个完成目录和 193 个 partial
目录全部只读保留；新回填输出使用新的独立 root。失败 segment 的 object static points/normals
来自已有 Stage3 文件，selected frame 的 object pose 直接来自同一 annotation 的 `obj_transf`，不
删除帧、不插值 pose、不将 3076 点旧 pilot 接入训练。

回填必须为每个正式 variant 写出一致的 MANO 4096 或 Inspire 20270 KNN 流、对应 normals、KNN32
indices 和 2 cm mask；index/manifest 同时记录 `hand_variant`、源资产、选择 index、帧覆盖和错误清单。
任何 segment 失败都使 run 终态为 `FAILED`，不生成可供训练使用的正式 index。

## 5. Smoke 与后续闸门

- smoke 使用三域各至少一条 train sequence，batch 2，最多 2 optimizer steps，固定 seed；检查 loader、
  variant shape、变长 padding、sampler、model forward/backward、finite loss、直接 pose GT 重建和 manifest。
- smoke 通过只表示 `SUPPORTED` 的工程接线证据，不表示跨域性能；任何 shape/finite/index 失败为
  `INVALID_IMPLEMENTATION`。
- 全量训练另开 V1.4.x 运行计划，明确 GPU、batch、epoch/step、初始 checkpoint、停止和 val/test 指标后再启动。

## 7. V1.4.3 并行恢复补充（final）

用户于 2026-09-17 明确批准在已启动的单 writer 高分辨率 OakInk2 回填上尝试批量并行。该修订不改变
selection、2 cm/KNN32、坐标、MANO/Inspire 点数、split 或 cache schema。

1. 先停止当前单 writer；保留 current output root 的 complete sequence 和任何 `.partial` 目录，不删除、
   覆盖或移动已有产物。
2. 恢复入口必须逐段验证 current output root 内的 complete geometry：`inspire_f1`、20270 KNN 点、10135
   每侧点、KNN32 index 上界、shape 和 finite。通过者直接复用；`.partial` 只记录为待处理，不作为输入。
3. 第一阶段只提高单个 GPU2 KNN32/writer 的 frame batch，并保持 retarget、写入与 sequence 所有权串行；
   不让多个进程争用同一 CUDA 设备或写同一 sequence。仅在小规模恢复 smoke 的逐帧耗时表明 CPU retarget
   仍是主要瓶颈时，才另行协商并实现有界 CPU 预取队列。
4. 先对少量未完成段运行独立的恢复 smoke，验证新 writer 复用完成段、不覆盖旧数据、输出合同和失败清单；
   smoke 通过后才从相同 output root 恢复余下段。
5. 新恢复运行使用独立 `run_id`/manifest，明确链接被暂停的基线 run 和复用段数。正式 `index.json`/
   `cache_manifest.json` 只在所有 1849 段通过后生成。

回滚为停止新恢复 run；已验证完成段和旧 baseline 均保留。若 batch/worker 改变任何数据语义、KNN 参数、
坐标或点数，必须暂停并重新协商。

## 8. V1.4.4 双域 MANO 续训与全 variant cache 队列（final）

用户于 2026-09-17 明确修订目标为每个 `grab`、`arctic`、`oakink2` 数据域均具备 `mano` 和
`inspire_f1` 两个高分辨率 hand variant；并批准立即以现有 GRAB/ARCTIC MANO cache 开始约 8 小时的
双域训练，以及使用 GPU0。该补充不改变刚体模型、2 cm、KNN32、坐标、原始已有 split 的 GRAB 部分或
MANO/Inspire 点数合同。

1. 建立可恢复的后台 cache supervisor：保留正在运行的 OakInk2 Inspire 回填；其余 GRAB/ARCTIC
   Inspire-20270 与 OakInk2 MANO-4096 任务使用互不覆盖的输出根和独立 run manifest，按 GPU 资源
   串行启动。旧 GRAB/ARCTIC Inspire 3076 点、KNN8 cache 仅作审计，绝不接入本轮训练。
2. 为立即训练生成独立的 GRAB+ARCTIC MANO source index：GRAB 沿用既有 train/val/test；ARCTIC 以
   trajectory/sequence id 的稳定 hash（seed=42）作 90% train、10% val，不跨 trajectory 共享。原始
   MANO cache/index 不修改。仅 V1.4.4 双域 runner 可由该派生 index 覆盖 ARCTIC geometry manifest 的
   原始 `train` 标签；其他 loader 仍严格拒绝 split mismatch。
3. 新建双域单 GPU0 训练入口和配置。以
   `cmv2_v134_grab_ddp4_20260917T070638Z/latest.pt` 仅初始化模型权重，重建 optimizer、sampler 和
   数据顺序；不得加载旧 optimizer/RNG 或覆盖旧 output。训练按 GRAB/ARCTIC `1/2:1/2` source-balanced
   replacement 采样，batch=160，最多 16 epoch，`max_duration_s=28800`，以先达到者停止。
4. 每个完整 epoch 在 GRAB 原 val 与新增 ARCTIC trajectory val 上固定 stride=2 评估，取两个域 loss 的
   等权平均为 `selection_metric`；仅改善时原子更新新 run 的 `best.pt`，并按间隔/终态原子更新
   `latest.pt`。时间上限中途停止时仍保留上一个 `best.pt` 和最后 `latest.pt`。
5. 先以临时小型 synthetic cache 对配置、ARCTIC split、初始化、padding、双域概率、best/latest 原子写入
   做定向测试；GPU0 正式 run 使用独立输出目录。GPU0 已有非本任务进程，若可用内存不足、OOM 或影响
   该进程，立即停止新训练而不停止 GPU2 cache 回填。

回滚为终止新的训练或 queue job；不删除 cache、baseline checkpoint、`best.pt` 或 `latest.pt`。本节的
训练结果只说明工程/优化状态，跨域效果仍需单独 held-out 结论。

## 9. V1.4.5 缺失高分辨率 producer 与持续 queue（final）

用户于 2026-09-17 在 producer 审计发现缺口后明确批准实现。新增 producer 只写入新的 Cmv2 output
root：GRAB/ARCTIC Inspire 使用 Stage4 双侧 MANO 几何、同一 retarget 资产生成每侧 10135 点，OakInk2
MANO 使用官方 annotation MANO 和固定每侧 2048 点 surface correspondence。三者均必须生成 decoder
3076 compatibility stream、正确的高分辨率 `knn_hand_points_world`、KNN32、2 cm mask、独立 manifest
和失败清单；不得修改或升级旧 3076/KNN8 cache。

1. 每个 producer 先在一个明确 sequence/segment 上 smoke，逐项验证 H、index 上界、finite、坐标、30 Hz
   和原子 `.partial` 行为；smoke 失败不入 queue。
2. 对通过 smoke 的 producer 创建独立 full run command、output root 和 success manifest；queue 等当前
   OakInk2 Inspire run 的 `COMPLETED` 后，在 GPU2 串行执行 GRAB Inspire、ARCTIC Inspire、OakInk2 MANO。
3. queue 只接受 `COMPLETED` run manifest 作为前序成功条件；任一 job 失败即停，保留已完成 cache，不启动
   后续任务。GPU0 双域训练和其他用户 GPU 进程不属于 queue 控制范围。

回滚为停止 queue 或当前 job；所有新 cache root、manifest 和日志保留，旧 cache/训练/checkpoint 不覆盖。
