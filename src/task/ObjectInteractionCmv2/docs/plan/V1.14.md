- 关联指导：[指导/V1.14](../指导/V1.14.md)
- 基线：V1.12 架构、V1.13 compact endpoint cache 与提交 `5265797`
- branch：`ai/ObjectInteractionCmv2/v1.13-io-acceleration`（复用现有分支，避免在尚未正式训练的 V1.13 数据路径上另开并行工作树）
- 等级：`L2`（网络宽度、推理接口及 checkpoint 解释变化）
- approval：`user-approved`
- approval_basis：用户确认以新讨论架构为主、允许随机初始化验证接口，并于 2026-09-21 明确许可按本计划继续实施。

## 1. 目标与边界

V1.14 在保留 V1.13 compact 输入合同的前提下，把稠密的逐边交互计算从 128D 降至 32D，并让多个
candidate 真正共享静态物体编码。目标是降低未来 Cm planner 对 `K=8` candidate 的 Cmv2 延迟，而不是
继续微调 endpoint KNN。

本版不兼容 V1.12/V1.13 checkpoint，模型从随机初始化开始；接口和工程验证均使用随机权重，不以旧权重
数值 parity 为门禁。实现完成不自动批准 cache full build、benchmark、smoke 或正式训练。

## 2. 改变与保持项

改变：

- local interaction width 从 128 改为可配置的 `interaction_dim`，主方案固定为 32；
- edge MLP 为 `24 -> interaction_dim -> interaction_dim`，query 为 `128 -> interaction_dim`，key/value
  为 `interaction_dim -> interaction_dim`；
- point contact、surface-token interaction 聚合与 part interaction 聚合保持低维，仅在 16 个 token 和
  part 层升回 128D；
- 新增静态 `encode_object()` 与 candidate 轴 `forward_candidates()`；
- 使用新的 architecture/config/checkpoint schema，旧 checkpoint 必须显式拒绝。

保持：

- 整体对象 1024 点、endpoint union-rerank top-32、2 cm mask、16 个 surface tokens；
- 128D geometry、token/part reasoning、soft routing、part self-attention 和共享逐部件 SE(3) head；
- part ID 只用于 grouping/routing；
- 坐标、单位、五组数据、split、stride、GT、loss、指标及 4096→1024 分层采样；
- V1.13 compact cache schema、记录顺序和 raw 24D edge feature 的重建语义；
- `src/base/`、旧模型、旧 cache、旧 checkpoint 和旧运行产物不修改。

第一轮不实现 fused logit/value edge head，也不改变邻居数、token 数或 endpoint KNN 定义。

## 3. 架构与接口合同

### 3.1 窄 interaction、宽 reasoning

```text
raw edge [24]
  -> edge MLP [32]
  -> Q/K/V attention [32]
  -> point contact [32]
     ├─ part interaction pool [32]
     └─ 16 surface-token pools [32]

[part geometry 128, interaction 32, active fraction 1] -> part feature [128]
[token contact 32, anchor 3, normal 3, mass 1]          -> token feature [128]
part/token reasoning                                    -> per-part SE(3)
```

`interaction_dim={128,64,32}` 只用于受控对照；V1.14 主配置使用 32。128 对照必须走同一份新接口，避免把
接口重构收益误算成降维收益。

### 3.2 Candidate 共享

`encode_object(object_batch)` 每个 state 只计算一次 geometry point feature、geometry part pool 和静态
metadata，返回不含 candidate 信息的 object context。

`forward_candidates(object_context, candidate_batch)` 接受 object 轴 `[B,...]` 和 candidate 轴
`[B,K,...]`，只在 candidate 轴计算 edge/contact、token assignment、surface routing、part fusion 与输出。
禁止通过 `repeat_interleave` 把完整 object geometry 复制为 `[B*K,1024,128]` 后重新编码。

token assignment、contact token、part interaction 和 routing prior 都依赖 candidate，不能错误缓存为静态状态。
训练入口可保留 `forward(batch)` 作为 `K=1` 包装；V1.13 compact 单 transition dataset 不改成 candidate cache。
在线接口优先接收已选择的 endpoint edge，同时把 endpoint 构建时间作为独立端到端计时项。

## 4. 实施顺序

1. 新增独立 V1.14 model/config/checkpoint 标识，保留 V1.12 模型可复现；
2. 将 interaction、token 与 part 输入维度参数化，先实现保守的低维 Q/K/V；
3. 拆分静态 object context 与 dynamic candidate forward，并提供 `K=1` 训练包装；
4. 接入 V1.13 compact 和 reference 两种输入路径，确认二者重建同一 raw edge；
5. 增加 Task-local 合成测试、随机初始化 GPU smoke 与 checkpoint round-trip；
6. 实现通过且 plan 定稿后，再为本地短程训练和性能 benchmark 单独固定 run manifest。

## 5. 验证门禁

### 5.1 接口与语义

- 随机初始化下，GRAB `L=1`、ARCTIC `L=2`、OakInk2 `L=1..3` 的 forward/backward 均 finite；
- `forward(batch)` 与 `forward_candidates(..., K=1)` 输出一致；逐个运行 K 个 candidate 与一次 candidate-axis
  运行在浮点容差内一致；
- candidate 重排只产生相同的输出重排，修改一个 candidate 不影响其他 candidate；
- object context 不含 hand/candidate tensor，geometry encoder 每个 state 只执行一次；
- point/part permutation 等变性、padding、空 interaction、token mask 和 routing 语义保持；
- reference 与 compact 输入的 raw edge、mask、forward 和 loss 在 `atol=1e-6, rtol=1e-6` 内一致；
- 新 checkpoint 可 round-trip，旧 architecture/checkpoint schema 被明确拒绝；
- Task 定向 pytest、`git diff --check` 与 `python tools/verify.py --changed` 通过。

以上仅证明实现和接口有效，不证明模型训练效果。

### 5.2 性能对照

在同一提交、GPU、dtype、chunk、输入和同步计时协议下，对 `interaction_dim={128,64,32}` 分别预热后重复测量，
报告 median、p90、峰值显存及模块分解。主场景为 `B=1, K=8, N=1024, E=32`；另报告 `K=1` 和当前
训练 batch。至少分开记录：

1. 已提供 compact/preselected edge 的纯模型时间；
2. endpoint edge 构建时间；
3. 包含两者的端到端时间。

32D 相对同接口 128D 的建议验收线为：edge/contact median 至少加速 3 倍、纯模型 candidate forward
至少加速 2 倍、包含 endpoint 构建的端到端至少加速 1.5 倍，且峰值显存不高于基线。未达线时只说明该
实现未满足性能目标，不以理论 FLOPs 代替实测。

### 5.3 短程训练门禁

正式训练前，以相同数据、初始化 seed、batch、step 数和 validation 口径比较 128/64/32 三档。核心
validation loss、translation、rotation 和 point-flow EPE 中，32D 相对同接口 128D 的退化不得超过 5%；
若 32D 未通过而 64D 通过，则只把 64D 作为候选，不宣称 32D 可用。短程 pilot 只能用于筛选，不能作为
最终科学效果结论。

## 6. 风险、停止条件与回滚

主要风险是 32D interaction 表达不足、candidate 维度造成意外张量复制、静态/动态边界错误、compact 与
reference 路径漂移，以及 kernel launch 或内存带宽使理论 FLOPs 未转化为延迟收益。

出现旧 checkpoint 被静默加载、candidate 泄漏进 object context、共享/逐 candidate 输出不一致、cache
输入 parity 失败、非 finite 梯度或性能门禁明显失败时停止扩大验证。精度超过 5% 退化时不得开始正式训练，
先在同一边界内评估 64D 或回到计划讨论。

代码回滚为切回 V1.13 runner/config/model；V1.13 compact cache 无需转换或删除。任何已生成的 benchmark、
checkpoint 或训练输出均保留为独立 run，不覆盖旧产物。

## 7. 实施授权

本计划已获准实施模型、配置、checkpoint 合同和定向测试。实现完成后的本地训练仍需单独固定训练预算、
GPU、seed、输入 cache、validation 与停止条件；当前计划不授权启动该运行。
