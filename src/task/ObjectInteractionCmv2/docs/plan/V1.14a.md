# ObjectInteractionCmv2 V1.14a：共享起点 KNN 与统一 2048 手点

- work_version：`V1.14`

- 等级：`L2`（手点输入、endpoint 邻域候选集合、cache/checkpoint 解释与 planner 接口变化）
- approval：`approved`

## 1. 目标与结论边界

V1.14a 解决 V1.14 benchmark 中占主导的 endpoint 构建：K 个 candidate 共享完全相同的起始手点，
所以 start top-32 每个 state 只计算一次；end top-32 仍按 candidate 分别计算。所有 MANO/Inspire 输入统一为
每只手 2048 点，即固定左手 2048 点、右手 2048 点，双手合计 `H=4096`。

本计划只允许实现、真实输入审计、随机初始化接口验证和性能 benchmark；不自动批准短程或正式训练。

## 2. 2048 手点合同

- 原始 4096 点 MANO 和 20270 点 Inspire cache 保持只读，不迁移、不覆盖、不删除；
- 每种 hand variant、每一侧使用固定 seed 从稳定点 ID 中无放回选择 2048 个索引；同一 variant 的所有
  sequence、frame、current/future 和 candidate 复用完全相同的索引；
- 左右手仍按 `left_then_right` 合并，输出索引为左 2048 后接右 2048；点、法线和 flow 使用同一索引；
- loader 输出必须精确为 `hand_points/hand_normals/hand_flow [4096,3]` 和全真的
  `hand_valid_mask [4096]`；batch 不再因 MANO/Inspire 混合而 pad 到 20270；
- manifest/config 记录 `hand_sampling_contract=bilateral_fixed_random_2048_per_side_v1`、源点数、固定 seed
  和左右索引 SHA256；禁止按 frame 或 transition 重新抽样。

这会改变 endpoint 候选集合，因而不是 V1.13 compact cache 的数值等价读取。旧 compact cache 保留但 V1.14a
必须拒绝其训练身份；若物化 compact 输入，使用新 schema `object_interaction_cmv2_compact_endpoint_v2`，并从
精确 4096 点 reference path 生成。本轮不授权 full cache build。

## 3. 共享 start KNN

新增 candidate endpoint 接口：

```text
object_points    [B,N,3]
hand_start       [B,H,3]
hand_normals     [B,H,3]
hand_valid       [B,H]
candidate_flow   [B,K,H,3]

shared start top32     [B,N,32]       # 只计算一次
candidate end top32    [B,K,N,32]
union + stable rerank  [B,K,N,32]
```

最终排序仍按 `min(start_distance,end_distance)` 升序、原 4096 点流中的稳定 ID 升序 tie-break；2 cm mask、raw 24D
edge feature 和 top-32 语义不变。共享实现必须与“将相同 start 手流复制 K 份后逐 candidate 调用 reference
函数”的索引、距离、mask、forward 和 loss 在既定浮点容差内一致。

`encode_object()` 保持 V1.14 静态物体共享；`forward_candidates()` 的 reference 输入改为共享
`hand_points/hand_normals/hand_valid_mask [B,H,...]` 加 `hand_flow [B,K,H,3]`。compact edge 输入仍为
`[B,K,N,32,...]`。训练 `forward(batch)` 继续作为 `K=1` 包装。

## 4. 改变与保护项

改变：

- reference loader 在坐标变换和 endpoint KNN 前固定选取每侧 2048、双手 4096 点；
- candidate endpoint start top-32 从 K 次降为一次；
- model/config/checkpoint identity 更新为 V1.14a，旧 V1.14 随机模型和旧 compact schema 显式拒绝；
- benchmark 固定报告 `H=4096`，并拆分重复 start、共享 start 和完整 model 时间。

保持：

- 1024 object points、endpoint 最终 top-32、2 cm radius、32D interaction、16 tokens、128D part reasoning；
- part routing/self-attention、逐部件 SE(3)、GT、loss、坐标、单位、split、stride 和五组来源；
- 起点/终点使用同一 hand point identity，不读取未来物体 GT；
- 原始高分辨率 cache、V1.13 compact cache、旧 checkpoint 和旧 benchmark 输出均只读保留；
- `src/base/` 不修改。

## 5. 实施顺序

1. 实现固定双侧 2048+2048 索引函数及身份摘要，接入 GRAB/ARCTIC/OakInk2 reference adapters；
2. 实现 shared-start candidate endpoint union-rerank，并保留逐 candidate reference oracle；
3. 更新 V1.14a 模型接口、随机初始化配置和 checkpoint/schema 拒绝门禁；
4. 更新 compact producer/reader 的 v2 身份，但只做小样本内存 round-trip，不构建 full cache；
5. 完成五组真实 transition 的 4096 输入、邻域覆盖和 shared-start parity 审计；
6. 提交固定实现后，运行 `H=4096` 的 duplicated-start 与 shared-start 性能 benchmark；
7. 仅在接口、覆盖与性能门禁通过后，再另行协商本地短程训练。

## 6. 验证与成功标准

### 6.1 确定性与接口

- MANO 4096→4096、Inspire 20270→4096 均严格左右各 2048、无重复、跨 frame/sequence 稳定；
- current/future 点、法线和 flow 身份严格一致，混合 batch 的 hand 轴恒为 4096；
- shared-start 与 duplicated-start oracle 的 edge ID/mask 完全一致，距离与模型输出在
  `atol=1e-6, rtol=1e-6` 内一致；
- K=1 wrapper、candidate permutation、point/part permutation、reference/compact-v2 parity 和 finite
  forward/backward 通过；旧 V1.13 compact 与 V1.14 checkpoint 必须明确拒绝。

### 6.2 真实输入覆盖

五组各抽固定 transition，对 full-source 与 4096-source endpoint 记录：2 cm active object-point recall、
最近 endpoint 距离增量、最终 edge 的来源侧别与 finger/point 覆盖（metadata 可用时）。建议门槛为 active recall
`>=99%`、最近距离增量 p95 `<=1 mm`；任一组未通过则停止训练，不以速度收益覆盖输入退化。

### 6.3 性能

固定 GPU、FP32、`B=1,K=8,N=1024,H=4096,E=32` 和 tuned chunk，分别测：

1. H=4096、start 仍复制 K 份的 oracle；
2. H=4096、共享 start 的新实现；
3. shared endpoint + V1.14a model。

门槛为 shared endpoint 相对 duplicated-start 至少 `1.5x`，相对既有 H=4096 tuned endpoint
`32.93 ms` 至少 `1.5x`，且 endpoint+encode+candidate 中位数 `<=28 ms`。这不把手点分辨率缩减计入收益；
显存、median、p90 均需记录。

## 7. 风险、停止条件与回滚

主要风险是 Inspire 的固定 4096 子集降低指尖/接触覆盖、不同来源点拓扑并不适合固定随机子集、共享 start 实现破坏稳定
tie-break、compact v1/v2 被混用，以及 tuned chunk 在训练 batch 下 OOM。

出现索引身份漂移、任一来源非 4096、current/future 不同点、shared/oracle parity 失败、真实覆盖未达标、
非 finite 值或性能门槛失败时停止扩大运行，不启动训练。

代码回滚为继续使用提交 `aad77c1` 的 V1.14 模型与原 reference/compact 路径。数据回滚无需删除任何源 cache；
新 compact-v2 pilot 若存在也作为独立目录保留，删除仍需单独授权。

## 8. 批准解释

用户已明确“统一 2048 点”是**每只手 2048、双手合计 4096**。MANO 的现有每侧 2048 点保持原样；
Inspire 每侧从 10135 个稳定点 ID 中固定无放回选取 2048 点。§6 门槛已按 `H=4096`、仅共享 start KNN
的性能问题校正，并随本计划一并获准实施。
