可以分成两个结论：

[
\boxed{\text{PoseToken 的模型架构已经可以定版并进入规模化预训练}}
]

但

[
\boxed{\text{当前 Dataset 实现还不适合直接上 10万/100万级样本}}
]

因为现在会在 Dataset 初始化时把所有 MANO surface 和 target surface 全部预生成并常驻 RAM。

所以我建议：**不要再改 PoseToken 主架构了；先把数据管线改成 on-the-fly（训练时按 batch 生成 MANO surface），顺手做一次 GRAB/ARCTIC OOD smoke test，然后就可以正式大规模预训练。**

---

# 一、现在 PoseToken 到底在表示什么

现在定义非常清楚：

[
\boxed{
S_t=E_P(H_t^{root})
}
]

它只表示：

> **当前手的静态构型。**

不负责：

* 动作；
* point flow；
* temporal；
* root motion；
* object；
* contact。

和我们刚刚重新定义的 ActionToken 是平行关系：

```text
                    Hand state H_t
                    /            \
                   /              \
                  ↓                ↓
             PoseToken         point flow
              state               ↓
                              ActionToken
                                motion
```

---

# 二、PoseToken 当前输入

输入是 root-local MANO surface：

[
\boxed{
H_t^{root}
\in\mathbb R^{B\times1538\times3}
}
]

1538 个点是固定 MANO face centers。

另外有 canonical neutral hand：

[
H^{cano}
\in\mathbb R^{B\times1538\times3}
]

以及固定 canonical atlas：

[
I\in\mathbb R^{B\times64\times32}.
]

也就是：

```text
hand_points_root      [B,1538,3]
hand_cano_points      [B,1538,3]
patch_knn_idx         [B,64,32]
```

64 个 patch、每个 32 个稳定 surface point。

---

# 三、先切成 64 个局部 patch

当前 surface：

[
H
\rightarrow
H^{patch}
]

得到：

[
\boxed{
H^{patch}
\in
[B,64,32,3]
}
]

canonical：

[
H^{cano}
\rightarrow
H^{cano,patch}
]

也是：

[
[B,64,32,3].
]

然后分别计算 patch center：

[
c_j=\frac1{32}\sum_p h_{j,p}
]

[
c_j^{cano}=\frac1{32}\sum_p h_{j,p}^{cano}.
]

---

# 四、每个 surface point 的输入特征是 12D

现在每个 patch point 构造：

[
x_{j,p}
=

[
h_{j,p},
h_{j,p}-c_j,
h^{cano}*{j,p},
h^{cano}*{j,p}-c_j^{cano}
].
]

所以：

[
3+3+3+3=12.
]

最终：

[
\boxed{
X\in[B,64,32,12]
}
]

这四项分别告诉模型：

1. 当前点位置；
2. 当前 patch 内相对位置；
3. canonical 点位置；
4. canonical patch 内相对位置。

因此 PoseToken 实际学的是：

[
\boxed{\text{当前 surface 相对 canonical surface 的 deformation}}
]

而不是绝对世界坐标。

---

# 五、Point MLP

当前：

```python
Linear(12,128)
GELU
Linear(128,256)
GELU
Linear(256,384)
```

所以：

[
[B,64,32,12]
]

变成：

[
[B,64,32,384].
]

然后对 patch 内 32 点 max pooling：

[
\boxed{
[B,64,384]
}
]

---

# 六、加入 Patch Identity

当前还有：

[
e_j^{patch}\in\mathbb R^{384}
]

是 learnable patch atlas embedding。

所以：

[
\boxed{
P_{t,j}
=

\max_p E(x_{j,p})
+
e_j^{patch}
}
]

得到：

[
\boxed{
P_t\in[B,64,384].
}
]

这就是正式的 **local PoseTokens**。

这个设计之前非常关键：没有 patch identity 时，controlled overfit 的 local reconstruction 一度只有约 77%；加入稳定 atlas identity 后提升到 87.2%。

---

# 七、Global PoseToken

除了 64 个 local tokens，还保留一个全局姿态 token。

先定义 learnable query：

[
q_g\in\mathbb R^{1\times384}.
]

然后：

[
z'_t
====

Attention(
Q=q_g,
K=P_t,
V=P_t
).
]

输入：

[
P_t:[B,64,384]
]

query：

[
[B,1,384].
]

得到：

[
[B,1,384].
]

再：

[
384\rightarrow128
]

最终：

[
\boxed{
z_t\in[B,128].
}
]

也就是：

```text
Local PoseToken:
[B,64,384]

Global PoseToken:
[B,128]
```

当前代码就是 `MultiheadAttention(384, 6 heads)` 加 `Linear(384,128)`。

---

# 八、所以 Encoder 主干其实很简单

完整 tensor flow：

```text
Current root-local hand
[B,1538,3]

Canonical hand
[B,1538,3]
        │
        │ fixed 64×32 atlas
        ▼

Current patches
[B,64,32,3]

Canonical patches
[B,64,32,3]
        │
        ▼

[current xyz
 current local xyz
 canonical xyz
 canonical local xyz]
        │
        ▼

[B,64,32,12]
        │
        │ Point MLP
        │ 12→128→256→384
        ▼

[B,64,32,384]
        │
        │ max pool 32 points
        ▼

[B,64,384]
        │
        │ + patch identity
        ▼

Local PoseTokens
P_t
[B,64,384]
        │
        │ learnable global query
        │ 6-head attention
        ▼

[B,384]
        │
        │ Linear
        ▼

Global PoseToken
z_t
[B,128]
```

我认为这部分现在**没有继续加 Transformer 或复杂 backbone 的必要**。

---

# 九、预训练时有两个 decoder

Encoder 后面临时接两个 reconstruction head。

## Local decoder

每个：

[
P_{t,j}\in\mathbb R^{384}
]

经过：

```text
384 → 384 → 96
```

然后：

[
96=32\times3
]

得到：

[
\boxed{
\hat D^{local}
\in[B,64,32,3].
}
]

它预测：

> 当前姿态对应的 beta=0 normalized surface 相对 canonical surface 的局部 deformation。

---

## Global decoder

[
z_t\in[B,128]
]

经过：

```text
128 → 384 → 1538×3
```

得到：

[
\boxed{
\hat D^{global}
\in[B,1538,3].
}
]

所以 global token 必须能够表达整只手的 pose。

---

# 十、现在真正监督的 Target

这里 V2 有一个非常关键的设计。

输入可以是：

[
MANO(\theta,\beta)
]

但 target 固定为：

[
\boxed{
MANO(\theta,\beta=0)
}
]

也就是说：

```text
input:
same pose θ
random morphology β

              ↓ PoseEncoder

target:
same pose θ
canonical morphology β=0
```

因此模型被要求：

[
\boxed{
\text{保留 pose，尽量去掉 morphology}
}
]

这就是当前 V2 morphology normalization。

---

# 十一、Loss

两个 loss。

### Local dense reconstruction

[
D^{GT}_{local}
==============

100
(
H^{target,patch}
----------------

H^{cano,patch}
)
]

单位 cm。

然后：

[
\boxed{
L_{local}
=========

MSE(
\hat D^{local},
D^{GT}_{local}
)
}
]

---

### Global reconstruction

[
D^{GT}_{global}
===============

100
(
H^{target}
----------

H^{cano}
).
]

然后：

[
\boxed{
L_{global}
==========

MSE(
\hat D^{global},
D^{GT}_{global}
)
}
]

---

最终：

[
\boxed{
L_{Pose}
========

\lambda_lL_{local}
+
\lambda_gL_{global}
}
]

目前：

[
\lambda_l=\lambda_g=1.
]

所以就是：

[
\boxed{
L=L_{local}+L_{global}.
}
]

没有：

* contrastive loss；
* beta regression；
* consistency loss；
* classification loss；
* Action loss。

之前试过 morphology consistency loss，但收益很小且伤害 global reconstruction，所以已经撤回。

当前 `SyntheticManoPoseDataset` 会在 `__init__`：

```text
        ↓

        ↓
```

明确有：


```text

1M
```

# 十六、正式大规模版本应该怎么改

Dataset 不再存：

[
[B,1538,3]
]

surface。

只存/生成：

[
\boxed{
\theta\in\mathbb R^{24},
\qquad
\beta\in\mathbb R^{10}
}
]

甚至连它们都不用全部存，根据：

```text
sample_id + seed
```

确定性生成即可。

训练：

```text
sample ids
   ↓
θ, β
   ↓
batch MANO forward
   ├─────────────┐
   ↓             ↓
MANO(θ,β)     MANO(θ,0)
   ↓             ↓
 input         target
 surface       surface
      \         /
       PoseToken
```

这样大规模训练的数据几乎是无限的。

# 十七、我建议的大规模预训练流程

不是重新从随机初始化直接训练 V2。

仍然沿用当前已经验证过的：

```text
Stage 1
V1 fixed morphology
β = 0
        ↓
学习 pose representation

Stage 2
V2 morphology normalization
random β input
β = 0 target
        ↓
得到最终 PoseEncoder
```

因为仓库已经明确验证：

> V2 从随机初始化容易 global collapse；从 V1 初始化是正确路线。

所以大规模也应该如此。

---

## 我会把规模设置成

第一阶段不必一上百万。

```text
V1:
100k–200k unique poses

V2:
200k–500k pose × morphology samples

val:
5k–10k

test:
5k–10k
```

先看 scaling curve。

如果继续稳定下降，再扩到：

[
1M+
]

没有必要一开始就硬上百万。
