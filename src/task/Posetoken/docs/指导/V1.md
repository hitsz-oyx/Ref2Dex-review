# PoseToken V1：静态手部姿态表示预训练最小实现

## 0. 任务目标

本阶段只解决一个问题：

> 给定某一时刻的手部三维表面，学习一个稳定、可反解码的静态 PoseToken 表示。

定义：

[
H_t^{world}\in\mathbb R^{N\times3}
]

经过当前手根坐标系变换：

[
H_t^{root}
=

(T_t^{root})^{-1}H_t^{world}
]

然后：

[
H_t^{root}
\rightarrow
E_{\text{pose}}
\rightarrow
\left(
P_t,z_t
\right)
]

其中：

[
P_t\in\mathbb R^{64\times384}
]

是 64 个局部 surface PoseToken，

[
z_t\in\mathbb R^{384}
]

是单个 global PoseToken，用于表达整个手的静态 configuration，例如：

* 两指捏合；
* 五指张开；
* 握拳；
* 三指 grasp；
* 不同程度的 finger flexion。

本阶段不训练动态 ActionToken。

---

# 1. 本阶段明确不做什么

V1 必须严格控制范围。

不要加入：

* Object point cloud；
* WorldToken；
* Uni3D；
* DenseToken；
* Contact；
* 动态 point flow；
* 相邻帧 pair；
* root motion prediction；
* InteractionToken；
* (C_m)；
* object SE(3)；
* Flow Matching；
* gesture 分类标签；
* contrastive learning；
* multi-embodiment alignment。

只训练：

```text
single static hand surface
        ↓
Pose Encoder
        ↓
Local PoseTokens + Global PoseToken
        ↓
surface reconstruction
```

先证明：

[
\boxed{
\text{PoseToken 能可靠编码静态手部 configuration}
}
]

---

# 2. Root SE(3) 的处理原则

这是本实现最重要的不变量。

PoseToken **不应该编码手在世界中的位置和方向**。

因此：

[
H_t^{root}
=

(T_t^{root})^{-1}H_t^{world}.
]

当前项目已经有：

```python
transform_points(points, pose_frame_to_world)
```

可以直接把 world point 变换到 root frame。

PoseEncoder 只允许看到：

```text
hand_points_root
hand_cano_points
patch index
```

绝对禁止输入：

```text
hand_root_pose_world
root translation
root rotation
object pose
world xyz
```

`hand_root_pose_world` 只在 Dataset 内用于坐标变换。

因此应满足严格不变性：

[
E_{\text{pose}}(H^{world},T)
=

E_{\text{pose}}(GH^{world},GT)
]

其中 (G\in SE(3)) 是任意全局刚体变换。

换句话说：

```text
同一个手型

平移 2 m
旋转 90°
换到另一个世界原点

PoseToken 都应该完全相同。
```

root motion 将在以后 Dynamic Action 阶段独立成为：

[
A_t^{root}
]

而不是进入 PoseToken。

# 6. Patch 必须在 canonical surface 上定义

这是 V1 和当前 V12 PosePairEncoder 很重要的区别。

当前不要：

```text
current posed surface
      ↓
FPS
```

因为手弯曲以后 Euclidean geometry 会变化。

我们应该：

[
\boxed{
\text{canonical surface}
\rightarrow
FPS/KNN
\rightarrow
固定 patch atlas
}
]

也就是用：

```python
hand_cano_points
```

计算：

```text
64 FPS centers
每个 center KNN 32 points
```

得到：

[
I^{patch}\in\mathbb N^{64\times32}.
]

之后无论当前是什么姿态：

```text
open hand
pinch
fist
grasp
```

都复用同一个：

```text
patch_knn_idx
```

因此：

[
P_{t,j}
]

始终表示同一个 canonical surface region。

---

# 7. hand_cano_points 的正确定位

注意：

```python
hand_cano_points
```

来自默认 MANO canonical hand。

真实 GRAB sequence 使用 subject-specific MANO `v_template`。

所以：

[
H_t^{root}-H^{cano}
]

包含：

```text
subject morphology
+
articulation
```

不能把它解释为纯 articulation。

因此 V1：

### 可以

把 `hand_cano_points` 当作：

[
\boxed{\text{surface atlas / positional encoding}}
]

### 不可以

声称：

[
H_t^{root}-H^{cano}
]

已经完全消除了 subject morphology。

真正去除 morphology 的 neutral deformation 放到 V2 做。

# 8. PoseEncoder 输入设计

对于 patch (j) 的第 (p) 个点：

当前 root-frame point：

[
x_{jp}.
]

当前 patch center：

[
c_j
===

\frac1{32}\sum_px_{jp}.
]

canonical point：

[
u_{jp}.
]

canonical patch center：

[
\bar u_j.
]

每个 point 构造：

[
f_{jp}
======

[
x_{jp},
x_{jp}-c_j,
u_{jp},
u_{jp}-\bar u_j
].
]

总维度：

[
3+3+3+3=12.
]

四部分含义分别是：

```text
x_root
    当前点相对 wrist 在哪里

x_root - patch_center
    当前局部表面是什么形状

x_canonical
    这个点在 canonical hand 上是谁

x_canonical - canonical_patch_center
    canonical patch 内部的位置
```

这样同时包含：

[
\boxed{
\text{current pose geometry}
+
\text{stable surface identity}
}
]

# 9. Local PoseToken Encoder

最小实现：

```python
self.point_mlp = nn.Sequential(
    nn.Linear(12, 128),
    nn.GELU(),
    nn.Linear(128, 256),
    nn.GELU(),
    nn.Linear(256, 384),
)
```

输入：

```text
[B, 64, 32, 12]
```

然后：

```python
pose_tokens = self.point_mlp(features).amax(dim=2)
```

得到：

[
\boxed{
P\in\mathbb R^{B\times64\times384}.
}
]

V1 不需要 Transformer。

先把局部表示学通。

# 10. Global PoseToken

用户需要一个变量表达：

> 整只手当前是什么手型。

不要简单把某一个 patch 当 global token。

使用一个 learnable query：

```python
self.global_query = nn.Parameter(
    torch.randn(1, 1, 384) * 0.02
)

self.global_attn = nn.MultiheadAttention(
    384,
    num_heads=6,
    batch_first=True,
)
```

计算：

```python
query = self.global_query.expand(batch_size, -1, -1)

global_pose, _ = self.global_attn(
    query=query,
    key=pose_tokens,
    value=pose_tokens,
)

global_pose = global_pose[:, 0]
```

得到：

[
\boxed{
z_t\in\mathbb R^{384}.
}
]

这里的 (z_t) 就是以后：

```text
open palm
pinch
fist
wrap
```

对应的全局连续 latent。

不要人为给这些动作分类标签。

# 11. Decoder 设计

必须同时监督：

1. local PoseToken；
2. global PoseToken。

否则 global token 可能只是无意义的 pooling。

---

## 11.1 Local dense surface decoder

每个：

[
P_j\in\mathbb R^{384}
]

直接预测该 patch 32 个点的 deformation：

[
\hat D_j\in\mathbb R^{32\times3}.
]

Decoder：

```python
self.local_decoder = nn.Sequential(
    nn.Linear(384, 384),
    nn.GELU(),
    nn.Linear(384, 32 * 3),
)
```

target：

[
D_{jp}
======

x_{jp}-u_{jp}.
]

注意这里预测的是：

```text
current root-frame surface
-
canonical surface
```

而不是 absolute xyz。

这样网络不用浪费容量重复记固定 canonical geometry。

---

# 12. Global PoseToken decoder

从：

[
z_t
]

预测 64 个 patch center deformation：

[
\hat d_j^{center}.
]

定义：

[
d_j^{center}
=

c_j-\bar u_j.
]

Decoder：

```python
self.global_decoder = nn.Sequential(
    nn.Linear(384, 384),
    nn.GELU(),
    nn.Linear(384, 64 * 3),
)
```

reshape：

```python
[B, 64, 3]
```

这样强迫：

[
z_t
]

知道整只手各区域的位置关系。

比如：

```text
pinch
```

必须能够同时表示：

```text
thumb 靠近
index 靠近
其他 fingers configuration
```

而不是只知道一个局部 patch。

# 15. Zero baseline

所有指标必须有 zero baseline。

因为目标是 deformation：

[

]

zero predictor：

[

]

[

# 18. Dataset split

PoseToken 的泛化目标与 InteractionDynamics 不一样。

InteractionDynamics 主要做 sequence-disjoint。

PoseToken 应该优先：

[
\boxed{\text{subject-disjoint split}}
]

因为如果：

```text
subject s1 的其他 sequence
```

同时出现在 train/test，模型可能只是记住 subject morphology。

建议：

```text
train subjects
val subjects
test subjects
```

完全隔离。

如果当前工具不方便做 subject split，第一版可以：

1. controlled overfit；
2. sequence-disjoint smoke test；

但正式 PoseToken pretraining 必须补 subject-disjoint evaluation。

# 41. 最终 V1 定义

完成后，PoseToken 的正式接口定为：

[
\boxed{
E_{\text{pose}}
:
H_t^{root}
\rightarrow
\left{
P_{t,1:64},
z_t
\right}
}
]

其中：

[
P_t\in\mathbb R^{64\times384}
]

保存局部 surface configuration，

[
z_t\in\mathbb R^{384}
]

保存整只手 global configuration。

root 位姿不属于 PoseToken：

[
\boxed{
T_t^{root}\notin S_t.
}
]

以后动态动作定义：

[
\boxed{
A_t^{art}
=

E_{\text{dyn}}(S_t,S_{t+1})
}
]

而 root action 独立定义：

[
\boxed{
A_t^{root}
=

E_{\text{root}}
\left(
(T_t^{root})^{-1}T_{t+1}^{root}
\right).
}
]

这样整个 Action representation 的职责从一开始就是清晰的。
对。**如果当前目标只是预训练 Static PoseToken，那么我同意：完全没必要先依赖 GRAB 数据集。直接用 MANO 在线随机生成静态手型，反而更干净。**

因为这一阶段我们真正要学的是：

[
\boxed{
H^{root}\rightarrow S_{\text{pose}}
}
]

即“一个手的静态几何构型怎么编码”，并不需要 object、contact、trajectory 或真实任务分布。

而 MANO 本身就是一个参数化生成器：

[
H = \operatorname{MANO}(\theta,\beta)
]

其中：

* (\theta)：hand pose，控制手指关节姿态；
* (\beta)：shape，控制手掌宽度、手指长度等个体形态。

因此甚至可以把 PoseToken V1 做成**完全 synthetic、online generation（在线生成：训练时现场随机采样）**。

整个任务会简单很多。

# 1. Root 问题甚至可以在生成阶段彻底消失

因为我们自己生成数据，所以直接固定：

[
\text{global_orient}=0
]

[
\text{transl}=0.
]

那么 MANO 输出天然就在 canonical/root frame：

[
\boxed{
H^{root}=\operatorname{MANO}(\theta,\beta, R=I,t=0)
}
]

根本不需要 world→root transform。

这样 PoseToken 的定义从数据层面就是：

[
\boxed{\text{与 root SE(3) 无关}}
]

而不是靠网络学出来。

为了做 sanity check，可以偶尔人为随机一个：

[
G\in SE(3)
]

把手变换出去，再 inverse transform 回来，验证 PoseToken 不变即可。

# 2. 这样我们甚至可以非常系统地控制两个变量

我觉得这里应该把 MANO 的参数明确拆成：

[
\boxed{
\theta = \text{pose}
}
]

和：

[
\boxed{
\beta = \text{morphology}
}
]

这正好对应我们一直担心的问题。

### 第一版最干净的实验

直接固定：

[
\boxed{\beta=0}
]

只随机：

[
\theta.
]

于是训练集只有：

[
\boxed{\text{articulation variation}}
]

没有 subject morphology。

这样 PoseToken 学到什么非常容易解释：

> 它只是在编码手型，而不是在识别是谁的手。

我强烈建议 **V1 就这么做**。

# 3. 然后 V2 再随机 (\beta)

等 V1 证明：

[
\theta
\rightarrow H
\rightarrow S
\rightarrow\hat H
]

可以学通之后，再加入：

[
\beta\sim p(\beta).
]

这时可以明确测试两个目标：

### 方案 A：PoseToken 保留 morphology

让：

[

完整重建：

[
H(\theta,\beta).
]

那么 (S) 同时含：

[
\theta+\beta.
]

---

### 方案 B：PoseToken 消除 morphology

我更倾向最终做这个。

输入：

[
H(\theta,\beta)
]

但 target 统一成：

[
\boxed{
H(\theta,\beta=0)
}
]

也就是：

> 无论这个人的手长什么样，都把它编码成“平均 MANO 手做同样姿势”的 geometry。

于是：

[
E(H(\theta,\beta_1))
\approx
E(H(\theta,\beta_2)).
]

这实际上会非常漂亮。

你根本不需要 subject-specific neutral hand。

MANO 生成器直接给我们 supervision：

[
\boxed{
(\theta,\beta)
\rightarrow
\text{normalize morphology}
\rightarrow
(\theta,0)
}
]

# 4. 这比我刚才说的 neutral deformation 更干净

之前基于 GRAB，我们需要想办法得到：

[

]

现在完全不需要。

例如：

[

[

=

那么 PoseEncoder：

[

[

loss：

[
\boxed{

=

直接强迫 latent 忽略：

[

]

这比事后做：

[

理论上和工程上都更清楚。

# 5. 但“随机 MANO 参数”不能直接随便 uniform

这里需要注意。

如果直接：

```python
hand_pose = torch.rand(...) * 20 - 10
```

会生成大量：

* 手指穿模；
* 极端扭转；
* 解剖上不合理；
* 完全不会出现在真实运动里的姿态。

这样虽然 autoencoder 也能学，但最后 latent 空间会花很多容量覆盖垃圾 configuration。

因此我建议：

[
\boxed{
\text{不要 uniform random MANO pose}
}
]

而用 **bounded stochastic sampling（有界随机采样）**。

你当前项目的 MANO 是：

```python
use_pca=True
num_pca_comps=24
flat_hand_mean=True
```

所以 pose 可以直接在 24D PCA 空间采样。

# 6. 最小版 pose sampling

第一版可以直接：

[
\epsilon_i\sim\mathcal N(0,1)
]

然后：

[
\theta_i=s_i\epsilon_i
]

其中低阶 PCA 分量允许变化更大，高阶逐渐缩小。

例如概念上：

```python
scale = [
    1.5, 1.5, 1.2, 1.2,
    1.0, 1.0, 1.0, 1.0,
    0.8, 0.8, 0.8, 0.8,
    0.6, ...
]
```

再 clamp：

```python
pose = pose.clamp(-limit, limit)
```

具体尺度最好先生成几百只手可视化，再定范围。

不要一开始追求复杂 prior。

# 7. 我甚至建议做 mixture sampling

因为单纯 Gaussian 会严重集中在：

[
\theta\approx0
]

也就是接近张开手。

但我们特别希望学：

* pinch；
* fist；
* wrap；
* finger opposition；
* 单指屈曲。

所以可以使用：

[
\boxed{
p(\theta)
=

0.5p_{\rm local}
+
0.3p_{\rm wide}
+
0.2p_{\rm sparse}
}
]

例如：

### local

小幅随机：

[
\theta\sim\mathcal N(0,\sigma_{small}^2)
]

学习精细姿态。

### wide

更大范围：

[
\theta\sim\mathcal N(0,\sigma_{large}^2)
]

增加整体覆盖。

### sparse

随机只激活少数 PCA dimensions：

```text
24 dims
↓
random choose 2~6 dims
↓
others = 0
```

让 latent 看到比较干净的独立 deformation mode（形变模式）。

这个特别适合 representation pretraining。

# 8. 不过还有一个更重要的问题：PCA 随机不保证出现“pinch”

你刚才举的：

> 两指捏起 / 五指张开

其实是很有语义的 configuration。

随机 PCA 肯定可以产生大量姿态，但未必高效覆盖：

[
\boxed{\text{功能性手型 manifold}}
]

例如 pinch 需要：

[
\text{thumb tip}
\approx
\text{index tip}
]

这是多个关节协同产生的。

因此我建议 PoseToken pretraining 分两类 synthetic sample：

```text
Random MANO Pose
+
Procedural Gesture Pose
```

第二类不需要真实数据集。

可以直接按照几何条件优化 MANO 参数。

# 9. 比如自动生成 pinch

随机初始化 (\theta)，然后优化：

[
L_{\rm pinch}
=

|
p_{\rm thumb-tip}(\theta)
-------------------------

p_{\rm index-tip}(\theta)
|^2
]

同时加：

[
L_{\rm prior}=|\theta|^2
]

防止姿态太离谱。

求：

[
\theta^*
=

\arg\min_\theta
L_{\rm pinch}
+
\lambda L_{\rm prior}.
]

这样就能自动生成大量不同强度、不同形态的 pinch。

finger extension
thumb opposition
spread
partial grasp

比如 fist 可以让 fingertips 靠近 palm：

[

=

spread 可以最大化 fingertip pair distance。

这些都可以自动优化 MANO pose parameter。

但这属于 V1.5，**最开始甚至不用做**。
