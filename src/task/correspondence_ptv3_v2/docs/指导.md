## 结论

**判断“扰动后能否恢复正确接触关系”，最关键的指标是：**

```text
val_perturbed/pseudo_recovery_brier
```

它直接比较：

```text
扰动几何产生的错误接触结果
        ↓
模型修正后的结果
        ↓
距离 clean GT 还有多远
```

定义为：

$$
R_{\text{Brier}}
================

\frac{E_{\text{pseudo}}-E_{\text{model}}}
{E_{\text{pseudo}}}
$$

其中：

* $E_{\text{pseudo}}$：直接相信扰动物体位置时，与真实接触关系的误差；
* $E_{\text{model}}$：模型预测与真实接触关系的误差。

数值解释：

|   数值 | 含义              |
| ---: | --------------- |
|  $1$ | 完全恢复到 clean GT  |
|  $0$ | 模型没有比直接相信错误几何更好 |
| $<0$ | 模型修正后反而更差       |
|   越大 | 恢复效果越好          |

这个指标只在接触 target 因扰动发生明显变化的边上统计，因此比普通的 QFL、BCE 或整体 MAE 更直接地反映“恢复能力”。

---

## 建议重点关注的指标顺序

### 第一优先级：真正的恢复能力

| 优先级 | 指标                                                   | 主要作用              |
| --: | ---------------------------------------------------- | ----------------- |
|   1 | `val_perturbed/pseudo_recovery_brier`                | 总体恢复效果，**最关键**    |
|   2 | `val_perturbed/pseudo_missed_contact_recovery_brier` | 能否找回被扰动破坏的真实接触    |
|   3 | `val_perturbed/pseudo_fake_contact_recovery_brier`   | 能否消除扰动产生的虚假接触     |
|   4 | `val_perturbed/pseudo_recovery_projection`           | 模型是否沿正确方向修正       |
|   5 | `val_perturbed/pseudo_changed_edge_fraction`         | 本次验证中有多少边真正受到扰动影响 |

代码明确将 changed edge 分成两类：

```text
fake contact:
扰动后看起来接触，clean GT 实际不接触

missed contact:
clean GT 实际接触，扰动后看起来不接触
```

并分别计算两类 recovery。

### 最重要的判定方式

不要只看总体 Brier。建议同时要求：

```text
pseudo_recovery_brier > 0

pseudo_fake_contact_recovery_brier > 0

pseudo_missed_contact_recovery_brier > 0
```

因为总体恢复可能掩盖单边问题。例如：

```text
fake recovery   = 0.70
missed recovery = -0.20
overall recovery = 0.35
```

整体看起来是正数，但模型其实只擅长删除接触，不擅长找回真实接触。

对你的手物交互任务，**`missed_contact_recovery_brier` 通常尤其重要**：真实接触被漏掉后，后续的对应关系、动作效果建模和接触区域提取都会缺少关键监督。不过不能以牺牲 fake-contact recovery 为代价，否则模型会在大量错误区域制造虚假对应。

---

## `projection` 怎么看

```text
val_perturbed/pseudo_recovery_projection
```

它衡量模型从扰动 target 朝 clean target 修正了多少：

$$
R_{\text{proj}}
===============

\frac{
\sum (p-\tilde y)(y-\tilde y)
}{
\sum (y-\tilde y)^2
}
$$

直观理解：

| Projection | 含义                   |
| ---------: | -------------------- |
|        $0$ | 完全没有朝正确方向移动          |
|      $0.5$ | 大约完成了一半修正            |
|        $1$ | 沿修正方向到达 clean target |
|       $>1$ | 可能修正过头               |
|       $<0$ | 朝错误方向修正              |

但是它**不能代替 Brier recovery**。

例如模型沿正确方向走得很远，但产生严重过冲，projection 仍可能较大，而 Brier 会因为最终误差较大而下降。因此：

```text
Brier recovery：判断最终恢复得好不好
Projection：判断模型是否知道该往哪个方向改
```

我的建议是：

```text
主指标看 Brier
辅助诊断看 Projection
```

---

## 第二优先级：接触预测本身是否健康

恢复指标不错以后，还要检查模型是不是通过“全部预测成很低概率”来获得表面上的改善。

### 真实接触区域

重点看：

```text
val_perturbed/cross_edge_random_nonzero_mae
val_perturbed/random_edge_y_050_075_mae
val_perturbed/random_edge_y_075_100_mae
```

其中：

* `nonzero_mae`：所有真实接触边上的误差；
* `y_050_075_mae`：较强接触；
* `y_075_100_mae`：最强接触。

对于恢复效果，**强接触 bin 的 MAE 比总体 MAE更重要**。因为 random128 中零接触边数量很多，总体 MAE 很容易被大量简单负样本稀释。仓库已经按 target strength 分桶统计这些指标。

### 虚假接触和困难负样本

重点看：

```text
val_perturbed/cross_edge_random_zero_pred_p95
val_perturbed/cross_edge_random_zero_pred_p99
val_perturbed/contact_aux_hard_neg_pred_mean
val_perturbed/contact_aux_hard_neg_pred_p95
```

解释：

* `zero_pred_p99`：真实不接触的边中，预测概率最高的那部分有多离谱；
* `hard_neg_pred_p95`：距离接触阈值只有 2～3 cm 的困难负样本，模型是否错误判成接触。

其中 `p99` 比 `zero_pred_mean` 更值得关注。平均值很低，不代表没有少量非常严重的虚假热点。

## 第三优先级：Dense Hand Heatmap

如果你的 `corresponsedense2v2` 指的是加入 dense hand-contact head 的实验，还应看：

```text
val_perturbed/hand_contact_nonzero_mae
val_perturbed/hand_contact_nonzero_pred_mean
val_perturbed/hand_contact_mae
```

其中最重要的是：

```text
hand_contact_nonzero_mae
```

不要优先看总体 `hand_contact_mae`，因为手部大部分区域通常不接触物体，总体 MAE 也容易被大量零 target 主导。

但需要明确：

> Dense hand heatmap 是辅助目标，不是核心 object-hand cross-edge 恢复指标。

它预测的是“每个手点是否接近完整物体表面”，而不是指定 object point 与 hand point 之间的对应关系。因此，除非你后续直接使用 hand heatmap，否则其重要性低于 `pseudo_recovery_brier` 和 random cross-edge 指标。仓库的默认总损失中，dense hand BCE 权重也只有 `0.005`。

## 当前 checkpoint 选择存在的问题

当前配置选择 `best.pt` 使用的是：

```yaml
metric_for_best: val_clean/cross_edge_random_qfl
lower_is_better: true
```

也就是说，当前的 `best.pt` 是：

> clean 输入下 random128 QFL 最低的 checkpoint。

它**不一定是扰动恢复效果最好的 checkpoint**。

因此建议至少保留两种模型：

```text
best_clean.pt
    按 val_clean/cross_edge_random_qfl 最低选择

best_recovery.pt
    按 val_perturbed/pseudo_recovery_brier 最高选择
```

最后选择时，用 clean 性能作为约束：

```text
优先最大化 pseudo_recovery_brier
但不能让 clean random QFL、强接触 MAE 明显恶化
```

否则模型可能很擅长处理扰动，却降低了正常几何输入下的接触精度。

## 你实际看 W&B 时，可以只固定这 10 条曲线

```text
val_perturbed/pseudo_recovery_brier
val_perturbed/pseudo_recovery_projection

val_perturbed/pseudo_fake_contact_recovery_brier
val_perturbed/pseudo_missed_contact_recovery_brier
val_perturbed/pseudo_changed_edge_fraction

val_clean/cross_edge_random_qfl
val_perturbed/cross_edge_random_nonzero_mae

val_perturbed/random_edge_y_075_100_mae
val_perturbed/cross_edge_random_zero_pred_p99
val_perturbed/contact_aux_hard_neg_pred_p95
```

判断顺序为：

```text
1. 总体 recovery Brier 是否持续为正并上升
2. fake 和 missed recovery 是否都为正
3. 强接触 MAE 是否下降
4. zero p99 和 hard-negative p95 是否受控
5. clean QFL 是否没有明显退化
```

## 最终恢复效果的核心标准

可以压缩成一句话：

> **最关键看 `val_perturbed/pseudo_recovery_brier`；再用 fake/missed 两类 recovery 检查是否偏科，用强接触 MAE 和 zero-p99 防止模型通过保守地压低所有接触概率获得虚假的恢复改善。**

最后还应使用可视化验证：开启物体扰动后，对同一 object point 比较 `CurrentPseudo → Eval → RefGT`，真正好的恢复应当让红色接触热点回到正确手指区域，而不是简单地把所有区域颜色变暗。仓库的可视化脚本已经支持这三个视图之间的切换。
