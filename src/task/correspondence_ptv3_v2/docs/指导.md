## 结论

整体数据链路方向基本正确：

```text
Raw MANO 参数
→ Stage 2
→ Stage 3
→ GPU MANO forward
→ 手部扰动
→ 扰动后筛选物体点
→ PTv3
```

并且已经删除新 Stage 3 中的 `obj_candidate_mask_5cm`，保留完整 4096 点池与 clean `hand_to_obj_min_dist`，这部分符合之前讨论的方案。

但当前分支存在几个明显问题，**暂时不建议直接启动 50 epoch 正式训练**。

# 阻断级问题

## 1. MANO 重建和 Hand PCA 扰动大概率根本没有执行

Runner 中 `_should_reconstruct_mano()` 明确要求：

```python
has_mano = batch.get("has_mano")
if has_mano is None:
    return False
```

只有 `has_mano=True` 才会调用：

```python
self._reconstruct_hand_from_mano(...)
```

但 Dataset 返回了：

```text
mano_global_orient
mano_transl
mano_pose
mano_betas
mano_v_template
mano_use_pca
...
```

却没有返回 `has_mano`。因此 Runner 会直接认为当前 batch 没有 MANO 参数，不执行 MANO forward，也不会加入 PCA 噪声。

也就是说，即便配置写了：

```yaml
use_mano_reconstruction: true
apply_hand_perturb: true
```

实际训练仍然很可能使用旧的 `hand_points`。

### 修复

Dataset 应明确返回：

```python
has_mano = all(
    key in data
    for key in (
        "mano_global_orient",
        "mano_transl",
        "mano_pose",
        "mano_betas",
        "mano_use_pca",
        "mano_num_pca_comps",
        "mano_flat_hand_mean",
        "hand_root_pose",
    )
)

result["has_mano"] = torch.tensor(has_mano, dtype=torch.bool)
```

更稳妥的是在 Dataset 初始化时要求整个数据根目录使用同一 schema，避免旧版和新版 `.npz` 混合。

---

## 2. 修复上一个问题后，`val_clean` 也会被加入手部扰动

`make_dataloaders()` 给 clean 验证集设置了：

```python
"apply_hand_perturb": False
```

但 Dataset 没有把这个开关放进返回的 batch。

Runner 的逻辑是：

```python
batch_apply = batch.get("apply_hand_perturb")

batch_apply_hand = True
if torch.is_tensor(batch_apply):
    batch_apply_hand = bool(batch_apply.bool().all().item())

apply_hand_perturb = (
    cfg.meta.apply_hand_perturb
    and batch_apply_hand
)
```

因为 batch 里没有该字段，`batch_apply_hand` 默认是 `True`。如果正式配置中：

```yaml
meta:
  apply_hand_perturb: true
```

那么：

```text
val_clean
val_perturbed
```

都会加入手部扰动。

### 修复

Dataset 返回：

```python
result["apply_hand_perturb"] = torch.tensor(
    self.apply_hand_perturb,
    dtype=torch.bool,
)
```

这样才能保证：

```text
train：按配置扰动
val_clean：不扰动
val_perturbed：扰动
```

## 3. ARCTIC 左手使用了右手的 `v_template`

ARCTIC 中只构造了一份：

```python
default_v_template = self.mano_r.v_template
```

随后右手和左手都使用：

```python
"mano_v_template": default_v_template
```

因此左手训练时会用左手 MANO layer 加载右手模板。

这会破坏左手的 MANO 重建一致性。

### 修复

```python
right_v_template = (
    self.mano_r.v_template.detach().cpu().numpy().astype(np.float32)
)

left_v_template = (
    self.mano_l.v_template.detach().cpu().numpy().astype(np.float32)
)

right_mano["mano_v_template"] = right_v_template
left_mano["mano_v_template"] = left_v_template
```

## 4. Hand PCA 噪声没有稳定随机种子

当前直接使用：

```python
noise = torch.randn_like(hand_pose) * hand_pca_std
hand_pose = hand_pose + noise
```

没有使用：

* `seq_id`
* `side`
* `raw_frame_id`
* `epoch`
* 独立的 `hand-perturb` namespace

生成稳定种子。

结果是：

1. 相同验证集每次评估的手部扰动不同；
2. 恢复指标无法严格比较；
3. 改变 batch size 或 DataLoader 顺序会改变噪声；
4. 多卡各 rank 的噪声依赖全局 RNG 状态；
5. checkpoint 恢复后数据增强序列可能不连续。

### 修复

Dataset 应产生独立种子：

```python
hand_seed = stable_frame_seed(
    base_seed=self.base_seed,
    seq_id=seq_id,
    side=side,
    raw_frame_id=raw_frame_id,
    epoch=epoch,
    namespace="hand-perturbation",
)

result["hand_seed"] = torch.tensor(
    hand_seed & ((1 << 63) - 1),
    dtype=torch.long,
)
```

Runner 再按每个样本生成噪声：

```python
noise = torch.empty_like(hand_pose)

for i, seed in enumerate(batch["hand_seed"].tolist()):
    generator = torch.Generator(device=hand_pose.device)
    generator.manual_seed(int(seed))

    noise[i] = torch.randn(
        hand_pose.shape[1:],
        device=hand_pose.device,
        dtype=hand_pose.dtype,
        generator=generator,
    )

hand_pose = hand_pose + noise * hand_pose_std
```

# 重要方法问题

## 5. `hand_pca_std` 同时作用于 PCA24 和 axis-angle45

当前逻辑对两种表示统一执行：

```python
noise = torch.randn_like(hand_pose) * hand_pca_std
```

但两种参数含义完全不同：

```text
GRAB：
24 维 PCA 系数

ARCTIC：
45 维关节 axis-angle
```

当前正式配置设为：

```yaml
hand_pca_std: 0.5
```

同时 Runner 注释明确表示 axis-angle 也使用相同标准差。

问题是：

* PCA 各维本身尺度可能不同；
* axis-angle 的单位是弧度；
* 两者不能使用同一个数值解释；
* ARCTIC 可能产生非常激烈甚至不合理的关节变化。

### 建议拆开

```yaml
hand_perturb_prob: 0.8

hand_pca_noise_scale: 0.10
hand_pca_noise_clip: 3.0

hand_axis_angle_std_rad: 0.05
hand_axis_angle_clip_rad: 0.15
```

GRAB 推荐按照训练集统计的每维标准差加入噪声：

```python
noise = torch.randn_like(pca)
noise = noise * pca_train_std * hand_pca_noise_scale
```

而不是所有 PCA 维度统一加 `0.5`。

## 6. 当前 256 个手代理点不是 FPS

当前代码使用：

```python
proxy_idx = torch.linspace(
    0,
    num_hand - 1,
    steps=proxy_count,
).round().long().unique()
```

这只是按 face index 等间隔取点。MANO 的面编号顺序不保证空间上均匀，因此不能保证手掌、指尖、指缝和手背都被合理覆盖。

Stage 3 元数据中也写的是：

```text
hand_proxy_method = fixed_stride_faces
```

而不是之前讨论的 FPS。

### 建议

离线在 canonical MANO 面中心上做一次 FPS：

```text
right_hand_proxy_face_idx: [256]
left_hand_proxy_face_idx:  [256]
```

由于左右手拓扑通常一致，也可以验证后共享索引。

运行时只需：

```python
hand_proxy = hand_input[:, proxy_face_idx]
```

不需要每个 batch 重新执行 FPS。

## 7. `4096×256` 的 `cdist` 没有分块

当前直接生成：

```python
obj_min_dist = torch.cdist(
    full_input_obj,
    hand_proxy,
).amin(dim=-1)
```

距离张量是：

```text
[B, 4096, 256]
```

随后又逐样本：

```python
for b in range(batch_size):
    near_idx = torch.topk(...).indices.cpu()
```

这会产生两个性能问题：

1. 一次性距离矩阵造成显存峰值；
2. 每个样本单独 `.cpu()`，会触发频繁的 GPU→CPU 同步。

正式配置 batch size 是 16，暂时未必 OOM，但仍可能成为明显的数据准备瓶颈。

### 建议

先分块计算最短距离：

```python
obj_min_dist = torch.empty(
    batch_size,
    pool_size,
    device=device,
)

for start in range(0, pool_size, 512):
    end = min(start + 512, pool_size)

    dist = torch.cdist(
        full_input_obj[:, start:end],
        hand_proxy,
    )

    obj_min_dist[:, start:end] = dist.amin(dim=-1)
```

然后一次性执行 batched top-k：

```python
near_idx = torch.topk(
    obj_min_dist,
    k=near_pool,
    dim=1,
    largest=False,
).indices
```

不要在循环中重复执行 `topk(...).cpu()`。

## 8. 新 schema 没有被严格校验

Stage 3 已经升级到：

```text
schema_version = 2.1.0
```

但 Dataset 的 `REQUIRED_FIELDS` 仍只要求旧的点云字段，不要求：

```text
schema_name
schema_version
hand_root_pose
mano_pose
mano_transl
mano_betas
...
```

而且只要存在：

```python
"mano_pose" in data and "mano_global_orient" in data
```

就会继续无条件访问：

```text
mano_transl
mano_betas
```

部分字段缺失时会在 `__getitem__()` 中间才报错。

Runner 在缺少 `hand_root_pose_world` 时还会退化为：

```python
hand_root_points = face_centers
```

这对于 `coordinate_frame="hand_root"` 的数据是危险的：世界坐标手点可能被直接拼入 hand-root 坐标的物体点中。

### 建议

如果：

```yaml

```

则初始化时强制要求：

```text
schema_version >= 2.1.0
hand_root_pose
mano_global_orient
mano_transl
mano_pose
mano_betas
mano_use_pca
mano_num_pca_comps
mano_flat_hand_mean
```

缺少任何字段都直接终止，而不是静默回退。

```yaml
  runtime_resample_object: true
```

并检查：

```text
selected object indices 随扰动变化
val_clean input hand_points 等于 gt hand_points
```

## 10. MANO 重建测试实际上没有验证严格一致性

测试文件顶部声明的目标是：

```text
mean error < 1e-5
max error < 1e-4
normal cosine similarity ≈ 1
```

但实际 on-disk 测试：

* 没有把重建世界坐标点变换到 Stage 3 的 hand-root 坐标；
* 直接比较 world 点和 hand-root 点；
* 最终只要求 `mean_err < 1.0 m`；
* 没有比较法向；
* 缺少环境变量时整个测试跳过。

这个测试几乎无法捕获厘米级的 MANO 重建错误，也捕获不了左手模板错误。

### 正确测试

应执行：

```text
MANO params
→ MANO world vertices
→ face centers/normals
→ 使用 hand_root_pose 转到 hand_root
→ 与 Stage 3 hand_points/hand_normals 比较
```

严格要求：

```text
mean position error < 1e-5 m
max position error < 1e-4 m
mean normal cosine > 0.999
```

还需要增加真正的 Runner 集成测试，确认 `_reconstruct_hand_from_mano()` 被调用。

1. 增加 `has_mano`，确认 MANO forward 真正执行。
