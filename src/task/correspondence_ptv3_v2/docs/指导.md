# 1. Stage 3 不再保存 5 cm mask

建议删除：

```text
obj_candidate_mask_5cm
```

Stage 3 不再提前决定哪些物体点靠近干净手，只保存完整物体表面表示。

但是建议继续保留：

```text
hand_to_obj_min_dist
```

它与 `obj_candidate_mask_5cm` 的性质不同：

* `obj_candidate_mask_5cm` 控制输入点采样，会造成 clean 信息泄露；
* `hand_to_obj_min_dist` 只用于生成干净的手部接触 GT，不进入模型，也不控制输入。

当前 dense hand-contact 分支就是使用它生成监督。删除后，要么在线重新计算完整 clean `4096×1538` 距离，要么取消手部接触辅助损失。因此暂时保留更合理。

新的 Stage 3 不应该保存：

```text
clean hand 决定的物体候选区域
```

但可以保存：

```text
clean contact GT
```

两者并不冲突。

# 2. 使用 256 个扰动后手点筛选物体区域

这个方案合理，而且我建议不要再严格依赖“5 cm 内必须够 512 点”。

## 256 个手点怎么选

不要每次随机选 256 个手点。建议预先从 MANO 的 1538 个面中心中，通过 FPS 选固定的 256 个 face ID。

FPS 是 **Farthest Point Sampling，最远点采样**，意思是逐步选择距离已有采样点最远的点，使 256 个点尽量均匀覆盖整个手表面。

因为 MANO 拓扑固定，可以全数据集共用：

```text
hand_proxy_face_idx: [256]
```

这个数组甚至不需要写进每个 `.npz`，可以作为代码资产或根目录元数据保存。

运行时：

```python
perturbed_hand_points = mano_forward(...)
hand_proxy_points = perturbed_hand_points[:, hand_proxy_face_idx]
```

然后计算：

```python
proxy_dist = torch.cdist(
    perturbed_obj_pool,     # [B, 4096, 3]
    hand_proxy_points,      # [B, 256, 3]
)

obj_min_dist = proxy_dist.amin(dim=-1)  # [B, 4096]
```

计算规模为：

[
4096\times256\approx105\text{ 万点对/样本}
]

比完整的：

[
4096\times1538\approx630\text{ 万点对/样本}
]

小约 6 倍。

## 不建议硬性要求 5 cm

更推荐按距离排序：

```python
near_pool_idx = obj_min_dist.topk(
    k=1024,
    largest=False,
).indices
```

然后从最近的 1024 个物体点里随机选择 512：

```python
selected_idx = random_sample_without_replacement(
    near_pool_idx,
    num_samples=512,
)
```

这样有几个优点：

* 永远不会出现 5 cm 内不足 512 点；
* 不需要为 256 点近似重新调整一个准确半径；
* 保留 epoch 间采样变化；
* 完全只依赖扰动后的输入几何；
* 不访问 clean 候选区域。

为了保留一些全局物体上下文，也可以采用：

```text
384 点：从距离手最近的 1024 点中采样
128 点：从完整物体剩余点中均匀采样
```

我更推荐这个 `384 + 128` 方案。否则 512 点可能全部聚集在接触附近，模型看不到足够的物体整体形状。

# 3. Hand PCA 扰动必须增加新字段

是的。当前 Stage 3 只有最终的手部点和法向，无法从它们恢复原始 MANO PCA 参数。

以 GRAB 为例，原始数据中已经有：

```text
global_orient: [T, 3]
hand_pose:     [T, 24]   # PCA 系数
transl:        [T, 3]
betas:         [10]
```

当前 GRAB adapter 使用：

```python
MANO(
    use_pca=True,
    num_pca_comps=24,
    flat_hand_mean=True,
)
```

并且会注入每个受试者对应的 `v_template`。

因此对于 GRAB，至少需要保存：

```text
mano_hand_pose        [T, 24]
mano_betas            [10] 或 [T, 10]
mano_v_template       [778, 3]
mano_side             scalar
mano_pose_repr        "pca"
mano_num_pca_comps    24
mano_flat_hand_mean   true
```

为了完整复现原始 MANO forward，还建议保存：

```text
mano_global_orient    [T, 3]
mano_transl           [T, 3]
hand_root_pose_world  [T, 4, 4]
```

虽然其中存在一定冗余，但每帧只多几十个浮点数，数据量很小，第一版不值得为了节省这些数据而增加复现风险。

## 不同数据集不能默认使用同一种 MANO 表示

这是当前设计里必须注意的问题。

GRAB 当前是：

```text
24 维 PCA
use_pca=True
flat_hand_mean=True
受试者专属 v_template
```

ARCTIC 当前是：

```text
45 维关节 axis-angle
use_pca=False
flat_hand_mean=False
标准 MANO + shape betas
```

ARCTIC 代码明确说明，如果错误地将 `flat_hand_mean=False` 改成 `True`，指尖位置可能出现厘米级误差；其当前 pose 是 15 个关节的 45 维 axis-angle，而不是 PCA。

所以不要把字段直接命名成：

```text
mano_hand_pose_pca
```

更稳妥的是：

```text
mano_pose
mano_pose_repr
mano_use_pca
mano_num_pca_comps
mano_flat_hand_mean
```

例如 GRAB：

```text
mano_pose_repr = "pca"
mano_pose.shape = [T, 24]
```

ARCTIC：

```text
mano_pose_repr = "axis_angle"
mano_pose.shape = [T, 45]
```

如果现阶段只训练 GRAB，可以先只支持 PCA24，但 schema 仍建议保留这些描述字段。

# 4. 参考 Stage 4 保存坐标变换：哪些情况等价

## Stage 4 当前实际做法

Stage 4 的 shared 文件保存：

```text
obj_points_world
obj_normals_world
```

手侧文件保存：

```text
hand_root_pose_world
hand_points_world
hand_normals_world
obj_candidate_mask_5cm
```

也就是说，它保存的是完整世界坐标几何，而不是只保存变换。

Dataset 在运行时读取世界系点云，然后通过：

```python
x_hand = R_hand.T @ (x_world - t_hand)
```

转换到当前 `hand_root_t` 坐标系。

因此：

```text
world points + hand_root_pose_world
```

与：

```text
预先转换好的 hand_root points
```

在数学上是等价的，只有微小浮点误差。

这种 Stage 4 思路可以参考。

---

## 只保存物体 canonical 点和物体变换

对于 GRAB 的刚体物体，可以做到完全等价：

```text
obj_points_canonical     [4096, 3]
obj_normals_canonical    [4096, 3]
obj_root_pose_world      [T, 4, 4]
```

运行时：

```python
obj_points_world = R_obj @ obj_points_canonical + t_obj
obj_normals_world = R_obj @ obj_normals_canonical
```

GRAB 当前本来就是对固定 canonical 采样点执行逐帧刚体变换。

这种设计有明显优势：

* 不需要每帧重复保存 4096 个物体点；
* 点 ID 天然跨帧一致；
* 物体扰动可以直接修改 `obj_root_pose`；
* 法向也可以精确恢复；
* 存储量显著下降。

### 但对 ARCTIC 不完全等价

ARCTIC 有铰接物体，例如：

```text
laptop
scissors
microwave
box
waffleiron
```

除了整体刚体位姿，还有逐帧铰接角。代码中的 object 参数包括：

```text
articulation angle
global rotation
global translation
```

并且 canonical 物体采样点还需要知道属于哪个部件。

因此 ARCTIC 至少需要：

```text
obj_points_canonical      [4096, 3]
obj_normals_canonical     [4096, 3]
obj_part_id               [4096]
obj_root_pose_world       [T, 4, 4]
obj_articulation          [T, 1]
```

仅保存一个 `obj_root_pose_world` 不够。

---

## 只保存 hand_root 变换不能恢复手部

这一点不等价。

`hand_root_pose_world` 只能描述：

```text
整只手的全局旋转和平移
```

不能描述：

```text
每根手指的弯曲
拇指外展
手掌姿态变化
关节之间的相对运动
```

因此：

```text
canonical hand + hand_root_pose
```

只能生成一只姿态固定、整体移动的手，不能恢复原始 MANO 动作。

要恢复完整手部，必须是：

```text
MANO 模型资产
+ shape / v_template
+ articulated pose
+ root transform
```

# 5. MANO 参数能否完全等价地恢复现有手点

理论上可以，但“完全等价”有几个前提。

## 必须固定 MANO 配置

下面任何一项不一致，都可能导致输出不同：

```text
MANO_LEFT / MANO_RIGHT 模型文件
use_pca
num_pca_comps
flat_hand_mean
betas
v_template
左右手 side
长度单位
PCA basis
MANO/smplx 版本
```

尤其 GRAB 当前使用受试者专属 `v_template`。如果只保存 PCA 和 betas，却不保存或无法定位这个 `v_template`，重建的会是平均手型，而不是原始受试者手型。当前代码专门注入该模板，就是为了避免这种不一致。

建议在元数据中额外保存：

```text
mano_model_identifier
mano_model_sha256
mano_config_version
length_unit = "meter"
```

不需要把 MANO 官方模型文件复制进数据集，但要记录所用资产的哈希，防止训练环境悄悄更换了模型文件。

## 建议保留 `hand_root_pose_world`

即使理论上可以从：

```text
global_orient
transl
MANO joints
```

重新计算手根位姿，我仍建议直接保存：

```text
hand_root_pose_world
```

因为当前手根原点使用的是 MANO forward 后的 wrist joint，而不是简单把 `transl` 当成 wrist 坐标。

它可以作为整个数据管线的权威坐标定义：

```text
所有手物几何最终都表达在 hand_root_pose_world 对应的局部坐标系
```

# 推荐的运行时流程

```text
读取 canonical object + object state
             ↓
恢复当前帧完整 4096 物体点
             ↓
读取 MANO 参数
             ↓
生成 clean hand
             ↓
对 PCA 加噪，生成 perturbed hand
             ↓
对 object pose 加扰动，生成 perturbed object
             ↓
取 perturbed hand 的固定 256 个代理点
             ↓
计算 4096 × 256 距离
             ↓
384 个近手点 + 128 个全局点
             ↓
input 使用 perturbed geometry
GT 使用同一 selected_idx 对应的 clean geometry
```

MANO 和采样应放在 GPU 上的 `Runner.prepare_batch()`，不要放进 DataLoader worker。Stage 4 当前使用 NumPy 做简单坐标变换没有问题，但 MANO forward 和 `cdist` 应由主训练进程的 GPU 完成。

# 最终判断

你的五点方案可以整理成：

1. 删除 `obj_candidate_mask_5cm`，保留完整物体表示。
2. 使用扰动后手部的固定 256 个代理点进行近似查询。
3. 不再死守 5 cm，改用最近点池采样。
4. 物体尽量保存 canonical 几何与运动参数。
5. 手部保存 MANO 参数与必要资产描述。
6. `hand_root_pose_world` 作为统一坐标系定义。
7. 暂时保留 `hand_to_obj_min_dist` 作为 clean GT 缓存。

其中唯一不能成立的是：

```text
只保存 hand_root 坐标变换即可恢复完整手部
```

正确关系是：

```text
手部完整恢复
=
MANO pose
+ betas/v_template
+ MANO 配置
+ hand_root/world 变换
```

第一版改造后应做一次重建一致性测试：

```text
旧 Stage 3 hand_points
vs
新字段 MANO 重建 hand_points

mean error < 1e-6～1e-5 m
max error < 1e-5～1e-4 m
normal cosine similarity 接近 1
```

只有通过这个测试，才能认为新的参数化存储与当前点云存储在你的实现中等价。
