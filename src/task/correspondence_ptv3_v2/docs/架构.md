# correspondence_ptv3_v2：当前实现架构

本文只描述仓库中正在运行的 correspondence_ptv3_v2 代码路径。它不是旧版设计提案：
不存在 object-contact head、10-bin contact 分类、hand 扰动训练或 runtime logit 邻域这几条旧路径。

## 1. 任务与核心约定

任务从手根坐标系中的手物点云，预测 object-to-hand 接触概率。模型输入含有带噪的物体位姿，监督始终来自 clean 手物几何；目标是学习在物体位姿有误差时恢复 clean 接触关系，而不是复现扰动后几何直接导出的伪接触。

当前默认量级如下。

| 项目 | 默认值 | 含义 |
| --- | ---: | --- |
| object point pool | 4096 | Stage 3 每帧完整物体表面点池 |
| sampled object points | 512 | 每个运行时样本实际送入模型的物点数 |
| hand points | 1538 | MANO face-center 点 |
| random edge width | 128 | 每个有效物点均匀抽取的主监督边数 |
| contact-aux width | 80 | 4 组各 16 条正边加 16 条 hard negative |
| contact radius | 0.02 m | 连续接触 target 的截断半径 |
| object candidate threshold | 0.05 m | 从 4096 点池进入采样候选集的阈值 |
| coordinate frame | hand_root | 默认 Stage 3 和模型输入坐标系 |

连续接触 target 对任意 object-hand 边定义为：

    y(d) = clamp(1 - d / r, 0, 1),  r = contact_radius

因此 d 大于等于 2 cm 时 target 为 0，距离越近 target 越接近 1。它不是二分类标签。

## 2. 数据链路

    raw dataset
      -> dataset-specific Stage 2 preparation
      -> Stage 2 single-sequence single-hand pkl
      -> process/common/stage3_corr.py
      -> Stage 3 single-sequence single-hand npz
      -> CorrStaticDatasetV2
      -> PTv3 + three supervision streams

### 2.1 Stage 2

Stage 2 是不同数据集的适配层。当前 GRAB 使用 init_only MANO 重建，不执行 contact 或 repulsion 优化。它至少提供 world 坐标下的每帧物体表面点、手面中心点、法向、物体位姿和 hand-root pose。

物体表面点在 Stage 2 固定采样；同一刚体物体在各帧只改变坐标和法向，point id 保持稳定。当前常用池大小为 4096。手点数为 1538。

### 2.2 Stage 3

Stage 3 将 Stage 2 的点变换到指定的规范坐标系，并计算与训练无关但可复用的 clean 几何统计。默认 coordinate_frame 为 hand_root：

    x_hand_root = R_hand_root^T (x_world - t_hand_root)

左手不再在生成时镜像到右手约定；左右手保持原始 MANO/数据集约定。训练时会验证每个 npz 的 coordinate_frame 与配置一致；不一致会报错，而不会静默混用 object frame 和 hand-root frame。

Stage 3 v2 是仅供本任务消费的最小 schema：

| 字段 | 形状 | 作用 |
| --- | --- | --- |
| obj_points / obj_normals | T x 4096 x 3 | clean 物体点池 |
| hand_points / hand_normals | T x 1538 x 3 | clean 手点 |
| seq_id / side | scalar | 稳定采样种子的序列与左右手 identity |
| raw_frame_id | T | 稳定采样种子的一部分 |
| hand_to_obj_min_dist | T x 1538 | hand 到完整 4096 object pool 的最短距离 |
| coordinate_frame | scalar | 数据坐标系声明 |
| hand_root_pose | T x 4 x 4 | world <- hand_root，用于 MANO 重建回到训练坐标系 |
| dataset_id | scalar | grab / arctic / contactpose，供混合 batch 与噪声 profile 分派 |
| mano_global_orient / mano_transl | T x 3 | MANO 全局参数；不参与局部手形噪声 |
| mano_pose | T x D | GRAB PCA24、ARCTIC axis-angle45 或 ContactPose PCA15 |
| mano_betas / mano_v_template | T x 10 或 10；778 x 3 | shape 与 subject template |
| mano_use_pca / mano_num_pca_comps / mano_flat_hand_mean | scalar | 完整 MANO 表示描述，训练按此分组重建 |
| obj_repr | scalar | 可选：rigid_canonical / articulated_canonical |
| obj_points_canonical / obj_normals_canonical | 4096 x 3 | 可选：canonical object 表面点，用于后续从参数恢复物体 pool |
| obj_root_pose_world | T x 4 x 4 | 可选：world <- object root 刚体状态 |
| obj_part_id | 4096 | 可选：ARCTIC 铰接物体部件 ID |
| obj_articulation | T x K | 可选：ARCTIC 铰接角等状态 |

hand_to_obj_min_dist 必须基于完整 4096 点池计算，而不是运行时抽到的 512 点。它使 dense hand heatmap 目标不随 epoch 采样改变。

为减少磁盘占用，v2 不落盘 obj-to-hand 距离、clean object-to-hand KNN、canonical hand、finger/region id 或旧任务 provenance。运行时启用手部 MANO 重建/扰动时要求上表中的 MANO 字段；关闭手部扰动时，`schema_version` 只作为数据标识，不作为能力门槛，旧 Stage 3 几何可以继续读取。不同数据集仍必须统一 `coordinate_frame`。带 MANO 的数据其 pose 会 pad 到 45 维用于 collate，runner 再按 `dataset_id` 和 MANO 描述分组、切回有效维数并选择几何标定 profile。当前 runner 仍以 per-frame obj_points 为权威训练输入。

## 3. 运行时采样与物体扰动

### 3.1 确定性 epoch 采样

每个样本以 base seed、sequence id、左右手、raw frame id、epoch 和 namespace 共同生成稳定种子。

1. Stage 3 只提供完整 4096 object pool，不再提供 clean-hand 5 cm mask。
2. Dataset 先把同一个 object perturbation 作用到完整 4096 pool，并把 full_input/full_gt pool 交给 runner。
3. Runner 使用当前输入 hand 的固定 256 个 proxy face 计算 4096 x 256 距离。带 MANO 的路径使用 canonical MANO FPS proxy；OakInk 这类 clean-geometry 路径可从存储的 1538 hand points 载入版本化 FPS index，因此无需 MANO forward 或 MANO 模型文件也能保留 runtime resampling。
4. 从最近 1024 个 object 点中随机取 384 个，再从剩余全局点中取 128 个，组成 512 点输入。
5. 训练集随 epoch 改变采样；验证集固定使用 epoch 0，所以跨 epoch 可比。
6. random128 主监督边也以独立 namespace 重新确定性采样。

训练的顺序以 sequence 为局部块打散，避免每个 worker 在相邻 iteration 中频繁切换 npz；空 val split 时 train/val 按原始 sequence 分组，左右手不会分到两侧。

### 3.2 输入几何与 clean GT

当前扰动包含 object pose perturbation，并可通过 MANO forward 对 hand pose/PCA 系数加噪：

    clean GT:      (O, H)
    model input:   (O_tilde, H_tilde)

其中 O_tilde 是对完整 4096 object pool 施加同一个刚体变换后的结果，H_tilde 来自 MANO 重建后的可选 hand perturbation。GT points 始终保留 clean O 和 H，并使用同一 runtime selected_idx 对齐。

默认配置为：

| 参数 | 默认值 |
| --- | ---: |
| apply_obj_perturb | true |
| obj_perturb_prob | 1.0 |
| obj_rot_std_deg | 10.0 |
| obj_trans_std | 0.01 m |
| val_obj_perturb_prob | 1.0 |
| use_mano_reconstruction | true |
| apply_hand_perturb | false（训练配置可打开） |
| hand_pca_std | 0.5 |
| hand_proxy_face_count | 256 |
| runtime_near_pool_points | 1024 |
| runtime_near_obj_points | 384 |

`use_mano_reconstruction=false` 与 `runtime_resample_object=true` 可以同时使用，但必须显式提供 `stored_hand_proxy_indices_path`。该索引直接选择 batch 中的存储 hand points，runner 不实例化 MANO，也不依赖 MANO `.pkl`。

OakInk 当前导出是 wrist-centered camera frame：手和物在同一 camera frame 内减去 wrist，所以接触距离与 GT 语义正确；它没有再应用真实 hand-root rotation，因此不同 camera view 仍保留不同的整体旋转。这对 OakInk-only 的局部接触监督不构成 schema 错误，但与严格 MANO hand-root 的 GRAB/ContactPose 混训时属于方向分布差异。

具体实现从各向同性随机轴和零均值高斯角度构造旋转，并对平移三个分量各采样零均值高斯。法向只旋转并重新归一化。没有 global scene augmentation，因为 hand-root 规范化已移除了全局 SE(3) 自由度。

运行时 batch 的核心字段为：

    points, normals              # input: [B, 512 + 1538, ...]，物体可能已扰动
    gt_points, gt_normals        # clean target geometry
    point_valid_mask             # [B, 2050]
    runtime_obj_valid_mask       # [B, 512]
    runtime_obj_selected_idx     # [B, 512]，在完整 object pool 中的索引
    random_edge_idx              # [B, 512, 128]，所选手点索引
    random_edge_valid_mask       # [B, 512, 128]
    hand_min_dist                # [B, 1538]，clean hand 到完整 object pool
    full_input_obj_points        # v2.1: [B, 4096, 3]，runtime sampling pool
    full_gt_obj_points           # v2.1: [B, 4096, 3]，同 selected_idx 的 clean GT 来源
    contact_seed                 # contact-aux 边采样种子

### 3.3 验证集

训练代码建立两套固定采样验证 loader：

| loader | input | GT |
| --- | --- | --- |
| val_clean | clean O, clean H | clean O, clean H |
| val_perturbed | perturbed O_tilde, optionally perturbed H_tilde | clean O, clean H |

val_clean 会显式关闭 object/hand perturbation；val_perturbed 使用训练配置中的 hand perturbation 和 val_obj_perturb_prob。val_perturbed 是检验抗扰动和 pseudo-contact recovery 的有效环境；val_clean 没有由扰动带来的可恢复误差。

## 4. 模型

### 4.1 11D runtime point feature

所有点特征都从实际输入 geometry 计算，即使用 O_tilde 和 H，而不是 clean GT。

对任一点 p、法向 n 和对侧点云，特征为：

    [p_xyz, one_hot(object_or_hand), n_xyz,
     distance_to_opposite_nearest,
     dot(direction_to_nearest, n),
     dot(direction_to_opposite_centroid, n)]

维度为 3 + 2 + 3 + 3 = 11。

物点以全部 hand 点为对侧点云；手点以有效的 512 个 object 点为对侧点云。无效 padding 不参与最近点和 centroid 计算。

### 4.2 Unified PTv3 backbone

object 与 hand token 在同一个 PointTransformerV3 backbone 中编码，不存在双 stem、canonical head 或额外 cross-attention 分支。

    coord = concat(O_tilde, H)                       # [B, 2050, 3]
    feat  = concat(object_11d_feature, hand_11d_feature)
    tokens = PTv3(feat, coord, point_valid_mask)
    z_obj  = tokens[:, :512]
    z_hand = tokens[:, 512:]

PTv3 的默认 grid size 为 0.003；实际层深、通道和 attention 配置由 config.py 中的 ptv3_* 字段控制。

### 4.3 Heads

当前模型只有下列预测 heads。

1. 一个 shared cross-edge head。对每条 object i 到 hand j 的边，拼接 z_obj[i] 和 z_hand[j]，经过两层 GELU MLP 与单标量线性 head，最后 sigmoid。
2. 一个可选 dense hand-contact head。其输入是每个 z_hand[j]，输出该手点对完整 clean object 的接触概率。loss_hand_contact_weight 大于 0 时创建；当前默认大于 0。

random128 与 contact-aux 不是两个独立模型分支：它们复用同一个 edge MLP 与线性 head，只是采样边的分布和损失权重不同。

模型输出为：

    pred_cross_random_logits / prob        # [B, 512, 128]
    pred_cross_contact_aux_logits / prob   # [B, 512, 80]
    pred_hand_contact_logits / prob        # [B, 1538]，默认启用

旧的 pred_obj_contact、bin logits、runtime context/logit KNN 输入均不是当前 live code。

## 5. 三条监督流与总损失

### 5.1 Random128 主流

每个有效物点从全部 1538 手点中均匀、无放回抽取 128 条边。边 target 在 clean GT 几何上重算：

    y_ij = contact_target_from_distance(||O_i - H_j||, 0.02)

每条边使用 Quality Focal Loss：

    QFL(logit, y) = |sigmoid(logit) - y|^beta * BCEWithLogits(logit, y)

默认 beta 为 2。先对同一物点的有效边平均，再对有效物点平均，因此每个有效物点权重相等。

这条流保持对手点的无偏均匀抽样，是 best checkpoint 的选择流。

### 5.2 Contact-aux 辅助流

对每个有效物点，代码在 clean GT 端按 target strength 分层抽边：

| 块 | target 或距离条件 | 默认最多条数 |
| --- | --- | ---: |
| weak | 0 小于 y 小于等于 0.25 | 16 |
| medium | 0.25 小于 y 小于等于 0.50 | 16 |
| strong | 0.50 小于 y 小于等于 0.75 | 16 |
| very strong | 0.75 小于 y 小于等于 1.00 | 16 |
| hard negative | 0.02 m 小于等于 d 小于 0.03 m | 16 |

某个 bin 没有足够候选时只留下 invalid slot，不会由其他 bin 补位。因此该流是有意偏置的局部强化监督，不能与 random128 指标混在一起解释。

它同样使用 per-object QFL，但权重较小。

### 5.3 Dense hand heatmap 流

对每个手点 j，target 来自 Stage 3 已保存的 full-pool 最短距离：

    y_hand[j] = contact_target_from_distance(hand_to_obj_min_dist[j], 0.02)

这不是 selected object point 的 cross-edge 分数，也不依赖运行时 512 点采样。它用逐手点 BCEWithLogits 的全局均值训练一个 object-conditioned dense hand prior。

### 5.4 默认总损失

    L = 1.0 * L_random_qfl
      + 0.05 * L_contact_aux_qfl
      + 0.005 * L_hand_bce

dense hand loss 的项数远多于 sampled edge loss，因此其系数刻意很小。将 loss_hand_contact_weight 设为 0 会同时关闭该 head 和该监督流；此时 HandHeatmap Eval 可视化不可用。

## 6. 指标与 checkpoint 选择

### 6.1 选择指标

默认 best checkpoint 指标是：

    val_clean/cross_edge_random_qfl

它来自无偏的 random128 流，且 lower_is_better 为 true。contact-aux 因为抽样分布被人为改变，不用来选择 best。QFL 仍只是一个训练拟合指标，不能单独代表类别严重不均衡下的实际恢复能力。

### 6.2 常规诊断

当前日志按 stream 分开记录。

| 前缀 | 用途 |
| --- | --- |
| cross_edge_random_* | 主 random128 流的 QFL、BCE、MAE、nonzero / zero 预测分布、strength-bin MAE 和 zero baseline |
| contact_aux_* | 分层辅助流的 QFL、BCE、MAE、hard-negative 分布、覆盖率和分桶统计 |
| hand_contact_* | dense heatmap 的 BCE、总体 MAE、nonzero target MAE 与预测均值 |
| pseudo_* | 仅用于扰动恢复分析的指标 |

每 20 个训练 step 计算一次昂贵诊断；所有验证 batch 都计算。观察 cross_edge_random_nonzero_*、zero_pred_p95/p99、各 target-strength bin 的 MAE 与 hand_contact_nonzero_mae 时，应同时查看相应的样本 count 或 coverage。

### 6.3 Pseudo-contact recovery

在诊断时，代码基于 input 中的 O_tilde 与 H 构造 random128 的伪 target y_tilde；clean target y 来自 clean O 与 H；模型预测为 p。

只在发生显著变化的边上计算，默认阈值 delta 为 0.05：

    changed = |y - y_tilde| > delta
    E_pseudo = sum((y_tilde - y)^2)
    E_model  = sum((p - y)^2)
    pseudo_recovery_brier = (E_pseudo - E_model) / E_pseudo
    pseudo_recovery_projection =
        sum((p - y_tilde) * (y - y_tilde)) / E_pseudo

解释：

| 值 | Brier recovery 含义 |
| ---: | --- |
| 1 | 完全恢复到 clean target |
| 0 | 不优于直接信任扰动几何 |
| 小于 0 | 比伪接触 baseline 更差 |

代码还分别记录扰动制造的假接触和扰动破坏的真实接触：

    pseudo_fake_contact_recovery_brier / projection
    pseudo_missed_contact_recovery_brier / projection
    pseudo_changed_edge_fraction

这些指标应主要在 val_perturbed 下阅读。若没有 changed edge，MetricStat 会标为无效；不要把无效值当成 0。当前实现尚未记录 pseudo recovery Excess-BCE，文档中的该建议不应当作已实现功能。

## 7. 训练和续训

默认 baseline.yaml 的训练超参数为 AdamW、lr 1e-4、weight decay 1e-4、batch size 8、val batch size 24、100 epoch、cosine scheduler 与 3% warmup、gradient clip 1.0，且 amp 关闭。实际实验应以输出目录内保存的 config.json 为准。

常规训练：

    PYTHONPATH=. python -m src.task.correspondence_ptv3_v2.train \
      --config src/task/correspondence_ptv3_v2/configs/baseline.yaml \
      --data <stage3_root> \
      --output-dir outputs/train/<run_name>

常规评估会从 checkpoint 读取保存的配置：

    PYTHONPATH=. python -m src.task.correspondence_ptv3_v2.eval \
      --checkpoint outputs/train/<run_name>/checkpoints/best.pt

框架支持 cosine、linear、step、null 和 cosine_restart。max_steps 始终是绝对停止步数。使用 cosine_restart 开新续训阶段时，必须同时设置：

    train.scheduler=cosine_restart
    train.finetune_steps=<本阶段新增步数>
    train.min_lr=<阶段末学习率>
    train.warmup_steps=0
    train.warmup_ratio=0
    train.max_steps=<checkpoint step + finetune_steps>

兼容的 cosine_restart checkpoint 会继续既有阶段；从其他 scheduler checkpoint 开新 phase 时保留 optimizer moment、重置该阶段的 cosine 学习率进度。

## 8. 交互可视化

可视化脚本以与训练相同的 Stage 3 dataset 采样逻辑重建单帧，并能对当前 512 个物点手工施加额外 object SE(3) 扰动：

    PYTHONPATH=. python -m src.task.correspondence_ptv3_v2.visualize \
      --config src/task/correspondence_ptv3_v2/configs/baseline.yaml \
      --input <single_stage3_sequence.npz> \
      --device cuda

不传 `--checkpoint` 时进入 GT-only 模式，此时不加载预测模型，CrossEdge/HandHeatmap 均使用数据集 GT，仍可查看手工 object 扰动。对于带 MANO 字段的 v2.1 数据，后端会在 CPU 上复用训练端的 MANO 重建与噪声实现：根据每帧 `mano_use_pca` 自动选择 PCA 或 axis-angle 分支，强度 `1.0x` 对应 YAML 配置，variant 只改变稳定 hand noise seed，不改变帧、epoch 或 object 采样。可视化的 Enable 是显式 gate，因此启用后固定应用噪声；YAML `hand_perturb_prob` 仅作为训练配置展示。传入 checkpoint 后才显示 Eval，MANO hand 手工控制仅在 GT-only 模式开放。`--input` 省略时按 `data.val_path`、`data.train_path` 顺序从 YAML 取路径。

可使用 --check-only 验证 checkpoint、数据和两个可视化输出形状，而不创建 Open3D 窗口。

### 8.1 两个独立主模式

| 模式 | GT | Eval | 颜色 |
| --- | --- | --- | --- |
| CrossEdge | 选中 object point 到每个 hand point 的 clean 距离 target | shared cross-edge head 对该物点与全部手点的 dense 推理 | 深灰到红色 |
| HandHeatmap | hand_to_obj_min_dist 导出的 dense clean hand target | 仅 pred_hand_contact_prob | 深蓝到紫色 |

HandHeatmap 不使用 CrossEdge 输出。它要求 checkpoint 带有 dense hand-contact head。

在手工扰动模式下，F 可以切换参考 clean GT 与当前伪 target。对于 HandHeatmap，CurrentPseudo 是从当前输入的有效 512 个物点重新计算的近似 target；由于训练 GT 来自完整 4096 点池，两者不应混称为同一个 GT。

### 8.2 键位

| 按键 | 功能 |
| --- | --- |
| A / D 或左右键 | 上一帧 / 下一帧 |
| [ / ] | 切换确定性 sampling epoch |
| H | CrossEdge / HandHeatmap |
| G | 当前主模式下的 GT / Eval |
| , / . | 切换 CrossEdge 中选中的 object point |
| P | 开关手工 object 扰动 |
| M | 开关 GT-only MANO hand 扰动 |
| F | 扰动时切换 RefGT / CurrentPseudo 着色 |
| 0 | 清零并关闭手工扰动 |
| J / L, I / K, U / O | object 沿 X、Y、Z 平移 |
| Z / X, C / V, B / N | object 绕 X、Y、Z 旋转 |
| R | 重置相机 |
