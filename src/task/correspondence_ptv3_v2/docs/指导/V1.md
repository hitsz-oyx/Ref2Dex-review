# V1：ARCTIC 外部评估优先

## 1. 目的

在启动 GRAB / ContactPose / OakInk 三数据集混合训练之前，先用未参与这两条训练的 ARCTIC 数据，比较现有纯 GRAB 与 GRAB+ContactPose checkpoint。

本阶段要回答两个问题：

1. 当前纯 GRAB 在 ARCTIC 上的优势是否只来自旧的 `box_*` 偏置子集；
2. mixed checkpoint 是否只是训练预算不足，还是在 ARCTIC 域上确实发生了稳定退化。

本阶段不训练 ARCTIC，不修改模型、loss 或 evaluator，不把 ARCTIC 作为训练数据。

## 5. 结果统计

主指标方向必须保持一致：

| 指标 | 方向 | 用途 |
| --- | --- | --- |
| `cross_edge_random_qfl` | 越低越好 | 主 correspondence 拟合 |
| `cross_edge_random_mae` | 越低越好 | 辅助拟合诊断 |
| `contact_aux_qfl` | 越低越好 | dense contact 辅助头 |
| `pseudo_recovery_brier` | 越高越好 | 总体 perturb recovery |
| `pseudo_recovery_projection` | 越高越好 | 几何 recovery |
| `pseudo_fake_contact_recovery_*` | 越高越好 | 假接触恢复 |
| `pseudo_missed_contact_recovery_*` | 越高越好 | 漏接触恢复 |

至少报告两种汇总：

1. 全量或子集的 frame-weighted micro average；
2. 按 object category 的 macro average。

如果额外按 subject 分层，必须同时报告每个 subject 的样本帧数。不能把不同帧数的 JSON 指标直接做未加权平均来代替 micro average，也不能只报告 `box` 类结果。

如果需要逐类别数字，按类别建立临时软链接目录，复用同一 evaluator 分别运行；每个类别使用相同的 checkpoint、batch、seed 和扰动协议。

## 6. 判定规则

### 6.1 可以进入下一步混训的条件

- 全量或覆盖全部类别的分层结果已生成；
- 两个 checkpoint 的协议和帧数通过核对；
- 结果中明确区分 micro 与 category-macro；
- 至少保存两个 checkpoint 的 JSON、命令、文件清单和运行日志；
- 不再把旧 `box_*` 子集作为唯一 ARCTIC 证据。

### 6.2 对 mixed checkpoint 的解释

- 如果 mixed 在多数类别和 macro 指标上仍低于纯 GRAB，才可把它记为“当前训练协议下的 ARCTIC 退化”；
- 如果 mixed 只在 box 类下降，而在其他类别持平或提升，说明旧子集偏置造成了误判；
- 如果 mixed 在全量 ARCTIC 上仍持续改善但未超过纯 GRAB，先延长 mixed 训练或补足 GRAB sample exposure，不能判定 ContactPose 无效；
- 如果 pure 和 mixed 的排序随 subject/category 大幅变化，优先报告域间 trade-off，不选择单一全局 best。

## 7. 下一步决策门

在本 V1 评估完成前，不启动三数据集混合训练。

评估后若仍需要训练，下一版必须使用：

- 相同 global batch 和 optimizer budget；
- domain-balanced sampler；
- 独立的 GRAB / ContactPose / OakInk validation loader；
- 固定的 domain mixture 权重；
- ARCTIC 继续保持完全 held-out。

本 V1 不定义三域最终权重，也不把当前 mixed checkpoint 作为收敛模型。
