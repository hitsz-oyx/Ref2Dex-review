# V1 架构

> 本文档是 `docs/指导/V1.md` 的架构分支。聚焦"模型是什么、怎么拼成 forward"。数据/训练流程相关见 `docs/Pipeline/V1.md`。完整设计与论证以指导文档为准。

## 一、项目命名

- 任务名：**InteractionDynamics**（代码层不再使用 Cm 作为主名）
- 代码目录：`src/task/InteractionDynamics/`
- 数据缓存目录：`data/processed_data/interaction_dynamics_v1/data/grab`
- 旧 Cm 完整保留于 `src/task/Cm/`，不破坏性修改
- 内部核心表征统一命名为 `interaction_tokens`（论文符号可继续使用 C<sub>m</sub>，但代码层不用 Cm）

## 二、V1 要解决的核心问题

InteractionDynamics V1 只解决下面这条完整链路：

```
当前手物状态  H_t + O_t
        +
未来 8 步人手动作  H_t → H_{t+1} → ... → H_{t+8}
        ↓
Interaction Encoder
        ↓
interaction_tokens
        ↓
Effect Decoder
        ↓
物体未来 8 步运动  O_t → O_{t+1} → ... → O_{t+8}
```

数学定义：

```
World_t        = (H_t, O_t)
ActionChunk_t  = {ΔH_1, ΔH_2, ..., ΔH_8},   ΔH_k = H_{t+k} - H_t
interaction_tokens = Encoder(H_t, O_t, ΔH_1:8)
ΔO_k            = O_{t+k} - O_t
ΔÔ_1:8         = EffectDecoder(interaction_tokens, O_t)
```

训练目标：预测**整段**物体点运动，而不是只预测一个 endpoint。

## 三、V1 明确不做的事情

- 不训练机器人动作 Decoder。
- 不建立 Human-Robot 配对训练集。
- 不训练 Allegro、LEAP、Shadow 等机器人数据。
- 不使用 Slot Attention。
- 不使用 Hard-Concrete gate / L0 sparsity。
- 不使用随机 temporal stride。
- 不使用 scalar delta_time_s 作为模型条件。
- 不做 384 local + 128 global effect query 混合采样。
- 不加入 action reconstruction loss。
- 不加入 contrastive human-robot alignment loss。
- 不直接优化机器人关节轨迹。

V1 最终做到 MANO self-inverse optimization：

```
GRAB MANO action  →  interaction_tokens
              →  反向优化另一条 MANO trajectory
              →  验证是否能够恢复原始动作
```

只有这个实验成功以后才进入机器人阶段。

## 四、五个最重要的硬约束

第一：World 只看 current H<sub>t</sub> / O<sub>t</sub>，永远不看 future object。

第二：Action 输入不是 endpoint ΔH，而是完整 8-step hand trajectory。

第三：动作局部信息 hand-centric，interaction 几何使用 object-relative representation。

第四：interaction_tokens 按 object patches 索引，而不是 arbitrary slots 或 hand patch index。

第五：第一轮只训练 Human action → Object effect，并用 MANO self-inverse 验证；不提前加入机器人 paired supervision。

## 五、为什么不在旧 Cm 上继续修改

旧 Cm 核心是 DenseToken → 当前 hand geometry + 单个 endpoint hand_flow → Slot Attention → sparse Cm slots → object flow；delta_time_s 只是可选时间条件，核心仍是 endpoint flow。

新的 InteractionDynamics 已在三个方面发生结构性变化：

1. 从 endpoint motion 变成 action chunk。
2. 从 Slot bottleneck 变成 Uni3D patch tokens + action/world attention。
3. 从自由 Slot token 变成 object-patch-indexed interaction tokens。

因此不在 `src/task/Cm/src/model.py` 上继续叠代码。新建独立目录更安全。

## 六、三套坐标系：Hybrid 帧方案

V1 在同一个 sample 中同时使用三套不同用途的表示。所有 transform 都以 current 帧 t 的 pose 为基准，禁止使用未来帧的 pose。

### 6.1 World Expert：current object frame

定义 T<sub>WO</sub>(t) 表示 object frame → world frame，求逆得 T<sub>OW</sub>(t)。

```
O_t^O = T_OW(t) · O_t^W
H_t^O = T_OW(t) · H_t^W
N_O^O = R_OW(t) · N_O^W    # 法线只旋转不平移
N_H^O = R_OW(t) · N_H^W
```

World Expert 只接收当前帧 t，绝对不能接收 H<sub>t+1:t+8</sub> 或 O<sub>t+1:t+8</sub>——这是防止 future leakage 的第一条硬约束。

### 6.2 Action Expert：current hand frame

定义 T<sub>WH</sub>(t)，求逆得 T<sub>HW</sub>(t)。整个未来 hand chunk 都投影到当前 t 的 hand frame。

```
H_0^H = T_HW(t) · H_t^W
H_k^H = T_HW(t) · H_{t+k}^W       # 始终用 T_HW(t)，不是未来 hand root frame
D_H(k) = H_k^H - H_0^H             # 累计位移
```

最终 `hand_disp_chunk` shape 为 [8, 1538, 3]。如果未来分别用各帧 hand root frame，wrist/global motion 会被坐标变化抵消掉——禁止。

### 6.3 Object Effect GT：current object frame

```
O_0^O = T_OW(t) · O_t^W
O_k^O = T_OW(t) · O_{t+k}^W
D_O(k) = O_k^O - O_0^O
```

如果未来每一帧分别变到自己的 object frame，刚体运动会全部被抵消——禁止。

## 七、World Expert：Uni3D-S patch encoder + World Transformer

### 7.1 输入点规模

- Hand：1538 points → 64 patch centers（deterministic FPS）→ 每中心 KNN 32 points
- Object：4096 points → 64 patch centers（deterministic FPS）→ 每中心 KNN 32 points

固定 `num_hand_patches = num_obj_patches = 64`，`patch_size = 32`。FPS 必须 deterministic，禁止 random start，确保 object point ordering + obj_point_id 固定后同一 object 的 patch index 有稳定对应关系——这一点对未来 Human → Robot 对齐非常重要。

World Expert 输入**使用全部 4096 object points**，不是 5cm → 512，因为它需要看到完整物体几何。

### 7.2 Patch 构成

每个 patch j：

```
local_feature_j = PointNet(relative_xyz, normal)
patch_token_j = local_feature_j
              + center_position_embedding
              + mean_normal_embedding
              + entity_embedding
```

`entity_embedding` 固定两种：HAND / OBJECT。

### 7.3 Normal 改造（原 RGB 通道）

原 Uni3D patch encoder 局部输入是 relative xyz + RGB 共 6 维。V1 改为 relative xyz + normal，仍然 6 维。第一层 pretrained Conv 权重处理方式固定如下：

- xyz 对应的前 3 个输入通道：加载 pretrained 权重
- 原 RGB 对应的后 3 个输入通道：全部初始化为 0

不是把 RGB pretrained weight 直接解释成 normal weight。训练开始时 normal 分支对输出基本无影响，随着训练进行 normal 权重自行学习。

### 7.4 World Transformer 组织方式

不是分别跑两个完全独立的 Transformer。流程固定为：

```
1538 hand   → hand patchify   → 64 hand patch embeddings
4096 object → object patchify → 64 object patch embeddings
拼接：128 patch tokens
加入 Uni3D CLS token
[CLS, 64 hand, 64 object]
→ pretrained Uni3D-S EVA Transformer
丢弃 CLS
```

输出：

- `world_hand_tokens`：[64, 384]
- `world_obj_tokens`：[64, 384]
- `world_tokens`：[128, 384]

World Transformer 内部已经可以建模 hand ↔ object 当前几何关系。

### 7.5 DenseToken 注入 World hand patches

World hand FPS/KNN 得到 `hand_knn_idx`：[64, 32]，直接用同一批 index 从 `z_hand` 和 `hand_contact` 取值。

```
dense_patch_j    = mean(z_hand[knn_idx])
contact_patch_j  = mean(hand_contact[knn_idx])
dense_residual_j = Linear([dense_patch_j, contact_patch_j]) → 384
world_hand_patch_j = uni3d_hand_patch_j
                   + sigmoid(world_dense_gate) · dense_residual_j
```

`world_dense_gate` 初始化 -4，初始 sigmoid(-4) ≈ 0.018，DenseToken 不会一开始破坏 Uni3D pretrained representation。

## 八、Action Expert

### 8.1 硬约束：必须复用 World hand patch

World hand patchification 得到的 `hand_fps_idx` 和 `hand_knn_idx` 必须原样交给 Action Expert。Action Expert 绝对不能重新做 FPS 或 KNN。因此 World hand patch j 和 Action hand patch j 对应完全相同的 32 个 hand surface point IDs。

### 8.2 点级输入

对于 hand patch j、future step k：

```
relative_xyz_hand   (3 维)   来自 current hand frame
normal_hand         (3 维)   来自 current hand frame
cumulative_disp ΔH_k (3 维)  也是 current hand frame
```

合计 9 维，全部在 current hand frame 下。

### 8.3 Spatial encoder

对每一时间步 k：

```
[32 points, 9 dims] → shared PointNet: 9 → 128 → 256 → 384
→ max pool over 32 points
→ action_patch_step_feature shape [8, 64, 384]
```

### 8.4 Temporal encoder

对每一个 hand patch j，取它 8 个时间步 [e<sub>j1</sub>, e<sub>j2</sub>, ..., e<sub>j8</sub>]，加入 learned temporal positional embedding `time_embed[0...7]`，再经过 2-layer Transformer Encoder（d_model=384, nhead=6, dim_feedforward=1536, num_layers=2）。最后对 8 个时间 token 做 mean pooling。

最终 `action_tokens` shape [64, 384]。

### 8.5 空间定位信息

Action Expert 的运动主体是 hand-centric，但它必须知道当前这块手表面在物体的什么位置。最终 action token：

```
action_token = temporal_motion_feature
             + hand_local_position_embedding          # current hand frame 下 patch center
             + object_relative_position_embedding    # current object frame 下同一 patch center
             + DenseToken residual
```

Hybrid representation 的核心：

- 动作局部结构以手为中心
- interaction 几何关系以物体为参考

### 8.6 DenseToken 注入 Action token

继续复用同一个 `hand_knn_idx`，对 `z_hand` 和 `hand_contact` pooling。使用独立的 `action_dense_gate` 初始化同样 -4。

`world_dense_gate` 和 `action_dense_gate` 是两个独立 scalar parameter。

## 九、Action-World Fusion

```
Q = action_tokens
K = world_tokens
V = world_tokens
```

2 层 Cross-Attention Block。每层：LayerNorm → MultiHeadAttention(6 heads) → Residual → LayerNorm → FFN(384 → 1536 → 384) → Residual。

输出 `action_context_tokens`：[64, 384]。语义："这块手表面在当前完整 hand-object world 中，这段动作意味着什么。"

## 十、Object Canonicalization：最关键的新设计

### 10.1 不再以 hand patch 为索引

如果最终 representation 仍是 64 个 hand patch tokens，那么 Human finger patch 17 与 Robot finger patch 17 没有天然对应关系。

V1 固定以 object patches 作为 canonical query：

```
Q = world_obj_tokens
K = action_context_tokens
V = action_context_tokens
```

执行一个 Object Canonicalization Cross-Attention。最终 `interaction_tokens`：[64, 384]。第 j 个 token 的意义是"当前 object patch j 周围受到的 action-conditioned interaction 是什么"。

### 10.2 显式禁止 object residual

必须**不**写成：

```
interaction_token = world_obj_token + CrossAttention(...)
```

否则 interaction_tokens 中可能被大量静态 object geometry 主导。V1 固定：

```
interaction_token = LayerNorm(
    CrossAttention(
        Q = world_obj_token,
        K = action_context_token,
        V = action_context_token
    )
)
```

object token 只用来决定"我要查询哪一个物体区域的 interaction"，它本身不作为大的 residual 加进最终 interaction representation。这样以后 `interaction_tokens_human` 与 `interaction_tokens_robot` 比较时，距离主要反映 interaction，而不是同一个 object 本身。

### 10.3 Token 数量固定

`num_interaction_tokens = 64 = num_obj_patches`。不做 gate，不做动态 token 数量，不做 Top-K，不做 sparsity。每一个 object patch 始终产生一个 interaction token。

## 十一、Effect Decoder

### 11.1 Query

Effect Decoder 仍使用当前 5cm 采样出的 512 object points，每个 query：

```
[xyz (3), normal (3), z_obj (D_dense)]
→ MLP → 384
```

得到 `effect_query_base`：[512, 384]。

### 11.2 显式 8 个时间点

V1 不直接 `384 → 24` 一次输出 8×3，而是显式构造 temporal queries：

```
query_i,k = effect_query_base_i + effect_time_embedding_k，k = 1...8
```

总共 8 × 512 = 4096 个 effect query。

### 11.3 Cross-Attention with spatial bias

```
Q = effect query
K = interaction_tokens
V = interaction_tokens
```

EffectDecoder 内部对 cross-attention 加显式 spatial bias，使每个 effect query 物理上更靠近的 object patch 拿到更高权重：

```
distance_sq = cdist(effect_query_xyz, obj_patch_centers)^2
spatial_bias = -distance_sq / (2 · sigma^2)，sigma = effect_spatial_sigma_m
```

这是 routing-only 空间偏置，不改变 interaction value 也不给 flow head 加旁路，仅用于"告诉 512 个 query 应该对应哪个 object patch"。

### 11.4 输出

```
pred_obj_disp_chunk shape: [B, 8, 512, 3]
单位对外统一：meter
```

### 11.5 禁止绕过 interaction bottleneck

DenseToken z_obj 和 current object geometry 可以进入 query generation，但最终 flow head 不直接拿完整 z_obj feature 做 residual prediction。最终 flow head 输入固定：

```
[effect_context, current object xyz, time embedding] → MLP → 3D displacement
```

这样预测必须依赖 `interaction_tokens`，而不能形成 `z_obj → object flow` 的旁路。

## 十二、Forward 完整数据流（五阶段）

第一部分（World）：

```
当前完整 object 4096 + 当前完整 hand 1538
→ object frame
→ Uni3D patchify
→ 64 object + 64 hand
→ Uni3D World Transformer
→ world tokens
```

第二部分（Action）：

```
当前 hand geometry + 8-step hand displacement chunk
→ hand frame
→ reuse hand patch indices
→ spatial PointNet
→ temporal Transformer
→ 64 action tokens
```

第三部分（Action-World fusion）：

```
64 action tokens (Q) × 128 world tokens (K/V)
→ 64 action_context_tokens
```

第四部分（Object canonicalization）：

```
64 object world tokens (Q) × 64 action_context_tokens (K/V)
→ 64 object-indexed interaction_tokens
```

第五部分（Effect decoding）：

```
512 current object effect queries × 8 time embeddings
× 64 interaction_tokens (with spatial bias)
→ 8 × 512 predicted object displacement
```

整个因果链固定为：

```
Human Hand Action Chunk
→ Interaction
→ Object Effect Chunk
```

## 十三、训练与诊断

### 13.1 Motion 数值尺度

V1 不做数据集 RMS calibration。固定一个简单且物理意义明确的内部 motion scale：

```
motion_scale = 100      # meter → centimeter
```

- Action Encoder 内部：`hand_disp_internal = hand_disp_meter × 100`
- Effect GT loss：`obj_disp_gt_internal = obj_disp_gt_meter × 100`
- decoder 内部预测 centimeter
- 对外输出：`pred_obj_disp_meter = pred_obj_disp_internal / 100`
- Geometry xyz 仍保持 meter，不把 object/hand geometry 乘 100

### 13.2 Loss

V1 只有一个训练主损失：Object Effect Chunk Loss。

```
L_effect = mean(||pred_obj_disp_internal - gt_obj_disp_internal||²)
```

对所有有效 `batch × 8 time steps × valid 512 query points` 计算 MSE。无效的 effect point 由 `effect_obj_valid_mask` 完全排除。8 个时间步权重全部相同，不对后期帧额外加权。

```
L_total = L_effect
```

没有第二个辅助 loss。

**为什么 V1 暂时只有 effect loss**：单靠 object-effect supervision 验证 interaction 是否保留 action mechanism。

- 如果 MANO inverse 成功 → 不需要人为增加 action reconstruction constraint
- 如果 object flow 准，但 MANO inverse 明显失败 → 说明 interaction representation 被压缩成 effect-only representation，V2 才加 action-preservation loss

不要在 V1 就提前把问题复杂化。

### 13.3 训练参数固定

`grab_v1.yaml` 第一版固定：

```
seed = 42
chunk_len = 8
temporal_stride = 1
effective_fps = 30
num_hand_points = 1538
num_obj_world_points = 4096
num_effect_points = 512
num_hand_patches = 64
num_obj_patches = 64
patch_size = 32
model_dim = 384
action_temporal_layers = 2
action_world_layers = 2
attention_heads = 6
motion_scale = 100
batch_size = 8
num_workers = 8
epochs = 30
gradient_clip_norm = 1.0
mixed_precision = bfloat16
```

### 13.4 Optimizer

使用 AdamW，两组学习率：

- 新模块学习率 `1e-4`：normal input weights、normal embedding、entity embedding、DenseToken adapters、Action Encoder、Cross-Attention blocks、Canonicalizer、Effect Decoder
- Uni3D pretrained Transformer 学习率 `1e-5`
- `weight_decay = 0.05`

DenseToken 完全 frozen，不进入 optimizer。V1 使用 constant learning rate，不增加 scheduler。

### 13.5 Uni3D checkpoint 加载检查

必须打印三类参数：成功加载 pretrained 参数、因 normal 改造而重新初始化的参数、新建参数。

不得直接 `strict=False` 然后不检查 missing keys。训练启动日志中必须明确输出：

```
loaded pretrained parameter count
new parameter count
missing keys
unexpected keys
```

unexpected keys 如果不是明确处理的 CLS/head 等结构差异，直接报错。

Uni3D-S checkpoint 固定放 `pretrained/uni3d/model-s.pt`，V1 只使用 S，不从 Uni3D-B/L 开始。

### 13.6 验证指标

- **Object ADE**：全部 8 个未来时间步、全部有效 object points 的平均欧氏距离误差，单位 mm
- **Object FDE**：只取第 8 帧的 object point error，单位 mm
- **Per-step EPE**：分别报告 step 1, 2, ..., 8 的平均 object point error

### 13.7 Representation Collapse 诊断

不加入 loss，只记录。每 batch 统计：

- interaction token feature variance
- interaction token pairwise cosine similarity
- interaction token L2 norm
- object-to-action attention entropy

如果出现 64 个 interaction tokens 几乎完全一样、或 cosine similarity 接近 1，记录为 collapse 风险，但 V1 不立即加 regularization。

### 13.8 extract.py 输出

`extract.py` 不再输出 Cm slots/gates。每个 extraction sample 保存：

- `schema_name`, `seq_id`, `side`
- `raw_frame_id`, `future_raw_frame_ids`
- `effect_obj_idx`
- `world_hand_patch_centers_object`, `world_obj_patch_centers_object`
- `hand_patch_center_hand`, `hand_patch_center_object`
- `action_tokens`, `action_context_tokens`, `interaction_tokens`
- `pred_obj_disp_chunk`, `gt_obj_disp_chunk`
- `effect_obj_points`, `effect_obj_valid_mask`
- `action_to_world_attention`, `object_to_action_attention`, `effect_to_interaction_attention`

主要用于后续检查 representation 是否 collapse，以及可视化每个 interaction token 负责哪块 object。

## 十五、DenseToken 代码暂时怎么处理

V1 不重构旧 DenseToken 文件。直接从 `src.task.Cm.src.dense_token` 导入 `FrozenDenseTokenEncoder`——这是唯一允许的新任务依赖旧 Cm 目录的地方。该类本身只是已有 correspondence checkpoint 的 frozen adapter，没有 Slot/Cm 逻辑，明确只编码 current O<sub>t</sub>/H<sub>t</sub>，本身不存在 future leakage。

等新 pipeline 完全稳定后，再把它移动到 `src/task/common/`。现在不为目录洁癖增加一次额外重构。
