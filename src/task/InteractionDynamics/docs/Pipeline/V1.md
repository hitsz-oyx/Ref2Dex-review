# V1 Pipeline

> 本文档是 `docs/指导/V1.md` 的流程分支。聚焦"数据怎么流、怎么训练、怎么验证"。模型结构相关见 `docs/架构/V1.md`。完整设计与论证以指导文档为准。

## 一、数据缓存

### 1.1 缓存的定位

不要把每一个 chunk 单独保存成文件。仍然使用完整 sequence cache，原因是完整 sequence 可以在运行时生成任意合法的 chunk，不需要离线枚举大量 `t → t+8` pair 文件。

新缓存目录示例：

```
data/processed_data/interaction_dynamics_v1/data/grab/
s1/
  bowl_pass_1/
    shared.npz
    left.npz
    right.npz
  mug_lift_1/
    shared.npz
    left.npz
    right.npz
s2/
  ...
```

文件仍使用 NPZ。V1 不改 HDF5。同时默认使用 `np.savez`，不使用 `np.savez_compressed`——现在仍处于快速修改 schema 和训练读取阶段，优先减少 CPU 解压开销和工程复杂度。

### 1.2 来源：GRABRawAdapter

`build_interaction_dynamics_cache.py` 不依赖旧 Stage4 输出。它直接复用 `process/GRAB/raw.py` 中的 `GRABRawAdapter`。这样新旧数据完全隔离，但底层 MANO 重建、object mesh sampling 等逻辑仍然一致。

`GRABRawAdapter` 已能产生 `obj_points_world`、`obj_normals_world`、`obj_point_id`、`obj_root_pose` 以及 `hand_points_world`、`hand_normals_world`、`hand_root_pose`。其中 `obj_root_pose` 旧 Cm Stage4 没存，新 cache 直接写入。

### 1.5 时间采样参数固定

- `source FPS = 120 Hz`
- `ds_rate = 4`
- `effective FPS = 30 Hz`
- `chunk_len = 8`
- `temporal_stride = 1`

一个训练样本包含 `t, t+1, t+2, t+3, t+4, t+5, t+6, t+7, t+8` 一共 9 个状态。其中 t 是 current world，后面 8 个状态组成 future chunk，总时间跨度 `8/30 ≈ 0.2667 s`。

V1 不随机 temporal_stride。代码里保留 `temporal_stride` 字段，但 `grab_v1.yaml` 固定为 1。

### 1.6 缓存脚本职责边界

`build_interaction_dynamics_cache.py` 只负责 raw GRAB → complete sequence NPZ cache。**不得**做：

- chunk sampling
- 计算 Uni3D feature
- 保存 DenseToken
- 保存 interaction tokens

## 二、数据集构建

### 2.1 合法 Chunk 的定义

对于 sequence 长度 T，current frame t 必须满足：

```
t + chunk_len × temporal_stride < T
```

V1 即 `t + 8 < T`。Dataset 初始化时**预先建立全部合法**的 `(hand_path, current_frame)` 索引。训练 DataLoader 使用 `shuffle=True`。Dataset 枚举所有合法 t，DataLoader 随机打乱 chunk 训练顺序——更可复现。

### 2.2 单手数据筛选 / Manifest

V1 只训练 dominant hand，不把左右手同时作为 action source。如果左右手同时对物体施力却只输入其中一只手，会产生严重的因果标签噪声。

`build_interaction_dynamics_manifest.py` 复用现有 dominant-hand filter 逻辑——旧 filter 已基于 5cm 接触区域、hand flow、object flow、左右手 coupling error 判断 unilateral、bilateral dominant、bilateral cooperation、ambiguous。

V1 只生成 `stride = 8` 一种 manifest row（因为 `K=8, temporal_stride=1` 的 endpoint 正好是 t+8）。最终 manifest 每个样本固定 `hand_path`、`current_frame`、`dominant_side`、`stride=8`。Dataset 只接受 `decision=keep` 的样本。旧的 multi-stride dominant manifest 不直接作为 V1 训练输入。

### 2.3 Dataset 内部三套表示

给定 `current = t`，frames 为 `[t, t+1, ..., t+8]`，先读取完整 world-frame 数据，然后构造三套不同用途的表示：

A. World Expert 用 object-relative representation
B. Action Expert 用 current hand-root representation
C. DenseToken 使用旧 checkpoint 原本的 hand-root representation

这就是 Hybrid frame 方案。

- World Expert 只接收当前帧 t。`WorldExpert input = H_t^O + O_t^O`——防止 future leakage 的第一条硬约束
- Action Expert 整个未来 hand chunk 都投影到当前 t 的 hand frame，始终用 `T_HW(t)` 而不是未来 hand root frame
- Object Effect GT 也固定在 current object frame t，否则刚体运动会全部被抵消

### 2.4 World 4096 / Effect 512

World Expert 输入 `obj_world_points` shape `[4096, 3]`，**不是** 5cm → 512。因为 World Expert 需要看到完整物体几何：整体尺度、整体方向、接触区域位于物体什么位置、手和整体物体的相对关系。

```
4096 object points → Uni3D patchification → 64 object tokens
```

Effect supervision 从当前帧 `obj_candidate_mask_5cm[t]` 的 candidate object points 中**稳定采样 512 点**：

- `effect_obj_idx`：[512]
- `effect_obj_points` / `effect_obj_normals`
- `effect_obj_disp_gt`：[8, 512, 3]

V1 不采用 384 local + 128 global。先完全使用 512 local points，等 V1 训练稳定以后再单独做 global query ablation。

| `world_obj_points_object` | `[4096, 3]` | World Expert 当前完整物体 |

| `hand_disp_chunk` | `[8, 1538, 3]` | Action 累计位移 |
| `dense_obj_points_hand` | `[512, 3]` | DenseToken 5cm object（hand 帧） |
| `dense_obj_normals_hand` | `[512, 3]` | DenseToken 5cm object 法线 |

### 2.6 DenseToken 在 V1 中的 contract

不能简单让 DenseToken 直接吃 4096 object points。`FrozenDenseTokenEncoder` 的 checkpoint contract 明确要求：

- 512 object points
- 1538 hand points
- 只读取当前 `(O_t, H_t)`，本身不存在 future leakage

V1 完全保留这个 contract。DenseToken 输入当前 512 个 5cm effect object points + 当前完整 1538 hand points，坐标继续使用 current hand-root frame。

输出：

- `z_obj`：[512, D_dense]
- `z_hand`：[1538, D_dense]
- `hand_contact`：[1538]

DenseToken 全程 frozen，checkpoint 不进入 optimizer。

### 2.7 DenseToken 具体注入位置

- `z_hand` 用于：World hand patch **以及** Action hand patch
- `z_obj` 不尝试扩散到完整 4096 object world points（只对应 512 points）。`z_obj` 只用于 Effect Decoder 的 512 object query

`z_obj → object flow` 的旁路在 Effect Decoder 内部被显式禁止（详见 `docs/架构/V1.md` 第十一节）。

### 2.8 Dataset 文件职责

`src/task/InteractionDynamics/dataset.py` 负责：

- 完整 sequence 读取
- 合法 t 索引
- manifest 过滤
- 5cm 512 effect sampling
- world → object frame
- world → current hand frame
- 8-step hand chunk
- 8-step object GT chunk

**不负责任何神经网络**。

## 三、训练流程

### 3.1 Train/Val/Test Split

必须按 sequence group 划分。`left/right` 和同一 sequence 的不同 current frames 绝对不能跨 split。

固定：

- 80% train
- 10% val
- 10% test
- `seed = 42`

同一个 subject/sequence 只能属于一个 split。**不能 frame-level random split**。

### 3.2 Future Leakage 硬约束

模型 forward 函数禁止接收：

- `future_hand_points`
- `future_obj_points`

唯一允许的 future-derived tensor 是 `hand_disp_chunk`（已观测 human action）以及 runner loss 使用的 `effect_obj_disp_gt`。

- World Expert 只能收到 current tensors
- Effect GT 只能进入 loss

必须有 `test_interaction_dynamics_no_leakage.py` 检查 forward 参数中不存在 `obj_future` / `future_obj_points` / `obj_disp_gt` 等 target tensor。

### 3.3 20 步实施顺序

严格按照下面顺序做，不并行展开：

1. 新建 InteractionDynamics 目录和 config。
2. 新建 `build_interaction_dynamics_cache.py`。
3. 验证一条 GRAB sequence 的新 shared/left/right NPZ。
4. 新建 `dataset.py`。
5. 验证单个 chunk 的所有坐标和 shape。
6. 增加 dominant manifest wrapper，只使用 stride=8。
7. 实现 Uni3D-S world encoder。
8. 单独测试 4096 object + 1538 hand → 64 + 64 tokens。
9. 接入 DenseToken，仅检查 z_hand/z_obj shape。
10. 实现 Action Encoder。
11. 检查 hand patch KNN index 完全复用。
12. 实现 Action-World fusion。
13. 实现 object canonicalization。
14. 实现 Effect Decoder。
15. 用一个 batch 做 forward/backward。
16. 做 1 条 sequence overfit。
17. 做小数据集 overfit。
18. 再开始完整 GRAB training。
19. 完成 extract/diagnostics。
20. 最后实现 `inverse_mano.py`。

### 3.4 一条 Sequence Overfit

正式训练以前必须选一条 dominant-hand sequence，只使用大约 32 到 128 个 chunk，训练到 training object ADE 明显下降。需要检查 predicted object trajectory 是否跟随 GT。

如果一条 sequence 都无法 overfit，**禁止直接跑 full GRAB**。优先检查：

- frame transform
- chunk construction
- motion scale
- future correspondence
- Effect Decoder
- attention bottleneck

### 3.5 必通过的 Dataset 测试

`test_interaction_dynamics_frames.py` 必须验证：

- world → object → world 可逆
- world → hand → world 可逆
- normal 只旋转不平移
- 当前 object 在 current object frame 与 canonical sampled object geometry 一致
- 未来 object 使用 current object frame 后确实保留 object motion

`test_interaction_dynamics_chunk.py` 必须验证：

- `hand_disp_chunk[0]` 等于 `H_{t+1} - H_t`
- `hand_disp_chunk[7]` 等于 `H_{t+8} - H_t`
- `obj_disp_chunk_gt` 同理

`test_interaction_dynamics_dataset.py` 必须验证：

- chunk 不越界
- manifest side 正确
- 同一 sequence 不跨 split
- effect index 对 8 帧始终保持相同 object point ID

### 3.6 必通过的 Model 测试

`test_interaction_dynamics_model.py` 检查：

- World input：`[B, 1538, 3]`, `[B, 4096, 3]`
- World output：hand tokens `[B, 64, 384]`，object tokens `[B, 64, 384]`
- Action input：`[B, 8, 1538, 3]`
- Action output：`[B, 64, 384]`
- Interaction：`[B, 64, 384]`
- Effect output：`[B, 8, 512, 3]`

一次 `loss.backward()` 必须保证：

- Action Encoder 有梯度
- Interaction fusion 有梯度
- Effect Decoder 有梯度
- Uni3D 有梯度
- DenseToken 无梯度

### 3.7 最终 V1 Pipeline 全景

```
Raw GRAB
  → MANO reconstruction
  → stable object surface sampling
  → complete world-frame sequence cache
  → dominant-hand manifest，horizon=8
  → Dataset 取 current t 和未来 8 帧

Current World 分支：
  H_t + O_t
  → current object frame
  → full 1538 hand + 4096 object
  → deterministic FPS/KNN
  → 64 hand patches + 64 object patches
  → Uni3D-S
  → 128 World Tokens

Action 分支：
  H_t → H_{t+1} ... H_{t+8}
  → current hand frame
  → cumulative hand displacement chunk
  → reuse 64 hand patches
  → Spatial PointNet
  → Temporal Transformer
  → 64 Action Tokens

Action Tokens query World Tokens
  → 64 Contextualized Action Tokens

64 Object World Tokens query Action Tokens
  → 64 Object-indexed Interaction Tokens

当前 5cm 区域采样 512 object points
  → 8 个 temporal effect queries
  → query Interaction Tokens（带 spatial routing bias）
  → predicted object displacement chunk
  → [8, 512, 3]

与 GT object displacement chunk 做 MSE

→ GRAB 全量训练
→ interaction extraction
→ MANO self-inverse optimization
→ 判断 representation 是否可以作为未来 cross-embodiment inverse optimization space
```

## 四、MANO 逆优化

### 4.1 训练完成后的第一项测试不是机器人

representation model 训练完成后，先运行 `inverse_mano.py` 做 **MANO self-inverse test**。目的不是测机器人泛化，而是回答：interaction space 是否真的可以用来反求动作。

### 4.2 MANO Target Interaction

从 GRAB test chunk H<sub>t</sub>, H<sub>t+1:t+8</sub>, O<sub>t</sub> 直接编码 GT action chunk：

```
Z_target = InteractionEncoder(H_t, O_t, GT hand_disp_chunk)
```

`Z_target` 即 `interaction_tokens_target`，shape `[64, 384]`。

### 4.3 MANO Candidate Trajectory

V1 不直接随机优化 point flow，使用真实 MANO 参数空间。固定当前 `betas`，固定 MANO subject v_template。

未来 8 帧每一帧优化：

- `global_orient`（3）
- `transl`（3）
- `hand_pose PCA`（24）

每帧 30 个优化变量，共 `8 × 30 = 240` 个变量。当前 t 的 MANO 参数固定不优化。

### 4.4 MANO Candidate 初始化

未来 8 帧全部初始化为 current MANO state——一开始假设未来手完全不动。然后给 hand_pose PCA 添加标准差 0.01 的小高斯扰动。**不从 GT future pose 初始化**——否则测试没有意义。

### 4.5 MANO Inverse Forward

每次 optimization iteration：

```
candidate MANO parameters
  → differentiable MANO forward
  → 8 future hand meshes
  → 1538 fixed face-center points
  → 转到 current hand/object frames
  → candidate hand_disp_chunk
  → frozen InteractionDynamics encoder
  → candidate interaction_tokens
```

然后计算：

```
L_interaction = mean(||Z_candidate - Z_target||²)
```

因为 `interaction_tokens` 是 object-patch-indexed，所以这里允许直接按 token index 做 MSE——这正是 object canonicalization 的价值。

### 4.6 MANO Inverse Regularization

为避免剧烈抖动的 MANO trajectory，固定加入两个 regularizer：

```
L_smooth_pose  = mean(||q_k - q_{k-1}||²)
L_smooth_trans = mean(||t_k - t_{k-1}||²)

L_inverse = L_interaction
          + 0.01 × L_smooth_pose
          + 0.01 × L_smooth_trans
```

V1 暂时不加 collision/contact loss。

### 4.7 MANO Inverse Optimizer

使用 Adam，learning rate `1e-2`，iterations `500`。每一个测试 chunk 独立优化。

- 不做 learned decoder
- 不需要 human-robot paired data

### 4.8 MANO Inverse 成功指标

虽然 optimization 本身不看 GT hand future，但评估时拥有 GRAB GT，因此计算：

- **Hand Surface ADE**：预测 candidate MANO 1538 points 与 GT future MANO points，8 帧平均误差，单位 mm
- **Hand Surface FDE**：第 8 帧 surface error，单位 mm
- **Interaction Distance**：`Z_candidate` 与 `Z_target` 的 MSE
- **Predicted Effect Distance**：分别把 `Z_candidate`、`Z_target` 送入 frozen Effect Decoder，比较两者 predicted object effect chunk

如果 interaction distance 很低、object effect 很接近，但 hand surface 完全不同——说明 interaction representation 存在多解。这不是立刻判定失败，需要检查它是否属于真正的 interaction-equivalent action。

### 4.9 什么时候才进入 Robot

只有以下三件事**都**成立以后才开始 Robot FK：

1. Object flow chunk prediction 明显优于 zero-flow baseline。
2. interaction tokens 没有严重 collapse。
3. MANO self-inverse 能从 current-state initialization 明显向 GT interaction 收敛。

满足后才进入：

```
MANO
  → interaction target
  → robot FK trajectory
  → interaction matching
```

Robot 不属于 InteractionDynamics V1 的首轮实现。

### 4.10 为什么 V1 不建 Human-Robot Paired Dataset

新方法的目标之一就是避免 `Cm/interaction → learned robot joint decoder` 这种必须依赖大量 paired data 的方式。V1 先验证：

```
shared interaction space
+
kinematic inverse optimization
```

是否成立。如果一开始就加入 human-robot paired supervision，就无法判断 representation 自身是否具备跨 embodiment 可优化性。因此 V1 明确没有 paired training dataset。

### 4.11 脚本职责

`src/task/InteractionDynamics/inverse_mano.py` 只负责 MANO self-inverse optimization，**不放进训练 runner**。这是 Pipeline 中独立于 train / extract 之外的一个独立流程。
