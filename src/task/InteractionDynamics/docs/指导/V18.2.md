# 3. 第一部分先做全量解析一致性，不跑 MANO

这个非常重要，而且便宜。

我们真实定义：

[
r_i=\sum_j w_{ij}(h_j-o_i)
]

[
d_i=\sum_jw_{ij}|h_j-o_i|.
]

根据三角不等式一定有：

[
\boxed{
|r_i|\le d_i
}
]

所以对 GT 和 generated (Y) 全量计算：

[
e_{rd}
======

\max(0,|r|-d).
]

输出：

```text
violation_rate
mean_violation_cm
p95_violation_cm
max_violation_cm
```

分别报告：

```text
GT
Generated

formation
transition
maintenance
```

如果 GT 几乎：

[
e_{rd}=0
]

但 generated 大量：

[
|r|>d,
]

那已经不用怪 inverse：

[
\boxed{r,d\text{ 自己就在打架。}}
]

# 4. 再检查 (u) 和空间轨迹的一致性

当前 future 每个 step 的排列就是：

[
[u_t,r_{t+1},d_{t+1}]
]

因为 `pack_state_future()` 就是这么构造的。

计算：

[
\Delta r_t=r_{t+1}-r_t
]

以及：

[
e_{ur}
======

|u_t-\Delta r_t|.
]

注意：

[
u_t\neq \Delta r_t
]

严格来说不要求相等，因为 (r_{t+1}) 的 soft correspondence 权重会变化。

所以**不要自己定绝对阈值**。

只比较：

[
e_{ur}^{GT}
]

和：

[
e_{ur}^{Gen}.
]

例如输出：

```text
mean
median
p90
p95
```

如果：

[
e_{ur}^{Gen}\gg e_{ur}^{GT},
]

就说明 diffusion 在独立预测 (u) 与 (r) 时破坏了真实数据里的 temporal consistency（时序一致性）。

# 5. MANO inverse 做三个 loss 消融

现有脚本：

```python
loss = (predict() - target).square().mean()
```

把全部：

[
r+d+u
]

混在一起优化。

V18.2 增加：

```python
--target-mode r
--target-mode rd
--target-mode rdu
```

由于每个 step 是：

```text
[u_x,u_y,u_z,r_x,r_y,r_z,d]
```

可以这么拆：

```python
def reshape_y(value):
    # [M, 7H] -> [M, H, 7]
    return value.reshape(value.shape[0], 8, 7)

def target_loss(pred, target, mode):
    pred = reshape_y(pred)
    target = reshape_y(target)

    if mode == "r":
        diff = pred[..., 3:6] - target[..., 3:6]

    elif mode == "rd":
        diff = torch.cat([
            pred[..., 3:6] - target[..., 3:6],
            pred[..., 6:7] - target[..., 6:7],
        ], dim=-1)

    elif mode == "rdu":
        diff = pred - target

    return diff.square().mean()
```

但无论用什么模式优化，最终都统一额外报告：

[
RMSE_r,\quad RMSE_d,\quad RMSE_u.
]

这样能明确知道：

### 情况 A

[
r\text{-only}=0.15cm
]

[
rd=0.18cm
]

[
rdu=0.75cm
]

那几乎可以确定：

[
\boxed{u\text{ 是主要冲突源}}
]

### 情况 B

[
r=0.15,\quad rd=0.70
]

则：

[
\boxed{d\text{ 与 }r\text{ 不一致}}
]

### 情况 C

连：

[
r\text{-only}
]

都很差：

[
\boxed{\text{空间 interaction field 本身就不容易由一只真实手实现}}
]

这时才该继续怀疑 correspondence / part identity / anchor-level joint consistency。

# 6. 初始化要做三种

这是区分 basin 和 off-manifold 的核心。

## A. `current_repeat`

就是现在 V18.1 的：

[
H_t,H_t,\ldots,H_t.
]

代码已经这样初始化：

```python
pose = pose0.expand(8, -1).clone()
orient = orient0.expand(8, -1).clone()
transl = transl0.expand(8, -1).clone()
```

这是最接近真实部署情况的。

---

## B. `gt_future`

直接拿这一 sample 的真实未来：

```python
pose[1:9]
orient[1:9]
transl[1:9]
```

作为优化初值。

注意：

> 这只是 **oracle diagnosis（上帝视角诊断）**，部署时当然没有 GT future。

它回答：

[
\boxed{
\text{如果从一个已经很合理的 hand trajectory 开始，
generated }Y\text{ 能不能被拟合？}
}
]

如果：

```text
current_repeat → 0.8 cm
gt_future      → 0.2 cm
```

那说明：

[
\boxed{\text{主要是 optimization basin}}
]

而不是 generated (Y) 完全非法。

---

## C. `multi_start`

从 current repeat 出发构造多个扰动初始化，例如：

```text
K = 4
```

每个 start 对：

* finger pose；
* root orientation；
* translation；

做小扰动。

建议所有 noise scale 做 CLI 参数，不要写死：

```text
--multistart 4
--pose-noise-rad 0.15
--orient-noise-rad 0.10
--trans-noise-m 0.02
```

最后：

[
\boxed{
E_{multi}
=========

\min_{k=1...K}E_k
}
]

这能检查：

> generated (Y) 是否对应一个和 GT demonstration 不同、但仍然真实可实现的 grasp mode。

# 7. 真正需要比较的是下面这张矩阵

每个 test sample 都跑：

| Target        | Init           | Loss         |
| ------------- | -------------- | ------------ |
| GT (Y)        | current repeat | r / rd / rdu |
| Generated (Y) | current repeat | r / rd / rdu |
| Generated (Y) | GT future      | r / rd / rdu |
| Generated (Y) | multi-start    | r / rd / rdu |

最关键的是前两行和后两行之间的变化。

不需要：

```text
GT Y + GT future
```

全量跑，因为这理论上接近 identity，只随机抽几十个做 parity check 就够了。

# 11. realizability threshold 不要拍脑袋定

不要直接说：

[
RMSE<0.2cm
]

就算 realizable。

用 **val full split 的 GT inverse** 定阈值。

例如：

[
\boxed{
\epsilon_{\rm real}
===================

P_{95}
\left(
RMSE^{GT,current}_{final}
\right)
}
]

也就是：

> 95% 的真实 (Y) 在当前优化器下能达到什么误差。

然后 test 上：

### directly realizable

[
E_{gen,current}\le\epsilon_{real}
]

### basin-rescued

[
E_{gen,current}>\epsilon_{real}
]

但：

[
\min(E_{gen,GTinit},E_{gen,multistart})
\le\epsilon_{real}
]

### persistent gap

所有初始化：

[
E>\epsilon_{real}.
]

于是我们最后会得到非常清楚的三个比例：

```text
directly realizable:   xx%
basin rescued:         xx%
persistent gap:        xx%
```

这比“平均 0.771 cm”有解释力得多。

# 13. 结果出来以后怎么决定下一步

这个决策树很重要。

### 如果 GT-init / multistart 大量救回来

例如：

```text
current repeat     30% realizable
GT init            75%
multi-start         70%
```

说明：

[
\boxed{\text{Y 大体没问题，inverse optimizer / initialization 才是瓶颈}}
]

下一步做：

* coarse hand initialization；
* sequential warm start；
* root propagation；
* better IK / optimizer；

不改 Diffusion。

---

### 如果 `r` 很好，`rd` 很差

说明：

[
\boxed{d\text{ 是冗余且不一致的生成变量}}
]

下一版考虑：

[
\text{只生成 }r
]

或者：

[
r\rightarrow d
]

解析/辅助预测，而不是独立 diffusion。

---

### 如果 `rd` 很好，`rdu` 很差

这是我目前最怀疑的一类：

[
\boxed{u\text{ 与 spatial trajectory 不一致}}
]

那就考虑：

[
\boxed{
\text{Diffusion 只生成 }r,d
}
]

然后 (u) 从合法 trajectory 再计算，而不是单独生成。

---

### 如果连 `r-only + GT init + multistart` 都差

这时候才真正说明：

[
\boxed{\text{generated spatial }Y\text{ 本身 off-manifold}}
]

下一步才考虑：

* MANO/robot projection；
* train-time realizability loss；
* hand-part semantics；
* ContactGen 式 part correspondence；
* latent/manifold generation。
