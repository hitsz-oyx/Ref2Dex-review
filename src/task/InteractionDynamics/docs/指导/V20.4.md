# 3. 不只测 v_H，全 channel combination 都扫一次

我建议这里比刚才再严谨一点。

因为我们虽然从 aggregate metric 看出 Y 的 r/d 更好，但不代表组合后 stable 一定如此。

直接穷举：

```text
r source: Y / H
d source: Y / H
v source: Y / H
```

共：

[
2^3=8
]

组。

例如：

```text
YYY
YYH
YHY
YHH
HYY
HYH
HHY
HHH
```

其中：

```text

HHH = Direct-H
YYY = Free-Y
```

p 始终使用：

[
p_Y.
]

这个实验计算成本几乎为零，但信息量很大。

最终直接输出：

| Fusion | r RMSE | d RMSE | v RMSE | F1 | Stable | Formation |
| ------ | -----: | -----: | -----: | -: | -----: | --------: |
| YYY    |        |        |        |    |        |           |
| YYH    |        |        |        |    |        |           |
| YHY    |        |        |        |    |        |           |
| ...    |        |        |        |    |        |           |
| HHH    |        |        |        |    |        |           |

如果 `YYH` 最好，那很好。

但如果比如：

[
YHH
]

stable 明显更强，那么说明 H 的 (d,v) 必须配套。

# 4. 做连续 interpolation

对 (v)：

[

========

]

测试：

[

我建议稍微比之前密一点。

\rightarrow

\end{cases}

如果存在：

[

优于两个端点，那就证明**真正的 fusion 有价值**，而不是纯 branch selection。

# 5. complementarity diagnostic

这个也是 Phase 0 必须做。

逐 sample 计算：

[
e_Y^{(s)},\qquad e_H^{(s)}.
]

分别对：

[
r,d,v.
]

输出：

### Win rate

例如：

[
P(e_H^v<e_Y^v)
]

是多少。

如果 Direct-H 的 aggregate (v) 更好，但实际上只是少数样本特别好，这会影响 gate 设计。

---

### Error correlation

计算：

[
\rho_r,\rho_d,\rho_v
]

其中：

[
\rho_v
======

corr(e_Y^v,e_H^v).
]

如果：

[
\rho_v\approx1
]

说明两个模型错在相同地方，融合提升空间不大。

如果比较低，融合更有意义。

---

### Oracle upper bound

逐 sample/channel 取更好的那个：

[
e_{\rm oracle}^{(s)}
====================

\min(e_Y^{(s)},e_H^{(s)}).
]

这里只用于诊断。

它告诉我们：

[
\boxed{
\text{如果有一个完美 selector，最多能提升多少}
}
]

如果 oracle 都只比 Free-Y 好 2%，就没必要设计复杂 fusion。

# 第一版 Gate 只融合 v

不要一开始碰：

定义：

其中：

* (i)：object anchor；
* (k)：future timestep。

然后：

[

(1-g)v_Y+gv_H
}
]

最终：

[
\boxed{

=========

[r_Y,d_Y,v_{final},p_Y]
}

# Gate 输入

第一版不要读取 backbone hidden feature。

只读两个模型的**预测结果以及简单 disagreement 特征**：

[
x_{ik}
======

[
d_Y,
d_H,
|d_Y-d_H|,
|r_Y-r_H|,
|v_Y-v_H|,
|v_Y|,
|v_H|,
t_k
].
]

所以大约 8 维。

其中：

[
t_k=k/H
]

告诉 gate 当前处于预测 horizon 的哪个位置。

---

# 为什么不输入 F？

因为现在我们想证明：

> 两种预测自身是否具有互补信息。

如果把：

[
F_Y,F_H
]

都给进去，gate 很容易直接重新学一遍 dynamics。

那就不是 fusion 了。

---

# Gate 网络

足够小：

```python
class VelocityFusionGate(nn.Module):
    def __init__(self, in_dim=8, hidden=32):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(in_dim, hidden),
            nn.GELU(),
            nn.Linear(hidden, hidden),
            nn.GELU(),
            nn.Linear(hidden, 1),
        )

    def forward(self, x):
        return torch.sigmoid(self.net(x))
```

参数量基本可以忽略。

# Gate loss

第一版：

[
\boxed{

============

\left|
\frac{v_{\rm final}-v^{GT}}
{\sigma_v}
\right|^2
}

# 一个我建议加入的小正则

不是为了防止 gate collapse，而是防止它非常高频地在 anchor/time 上抖动。

[

|g_{k+1}-g_k|^2.
]

例如：

[
\lambda_g=10^{-3}.

不过第一轮甚至可以：

[
\lambda_g=0.
]

先观察 gate 自己会不会乱跳。

# V20.4-B Architecture

Free-Y branch 保留：

[
F_i\in R^D.
]

Direct-H branch 在 output head 前保留：

[
G_k\in R^D.
]

即：

```text
Free Y:
spatial tokens F_i
      ↓
 Y_free

Direct H:
future tokens G_k
      ↓
    H
```

然后：

[
(F_i,G_k)
\rightarrow
\delta Y_{ik}.
]

推荐第一版仍只预测：

[
\delta v.
]

---

# Adapter

可以很简单：

[
x_{ik}=[F_i,G_k].
]

得到：

[
[B,N,H,2D].
]

然后：

```python
adapter = nn.Sequential(
    nn.Linear(2 * D, D),
    nn.GELU(),
    nn.Linear(D, 3),
)
```

最后一层 zero-init。

所以初始化：

[
\boxed{
v_{final}=v_Y
}
]

然后：

[
v_{final}=v_Y+\delta v.
]

---

# 为什么这种方式比强 consistency 更合理

因为我们并不希望：

[
Y_{free}\approx Y_H
]

所有 channel 都一样。

实验已经说明它们各有所长。

真正想要的是：

[
\boxed{
H\text{ 的 global temporal structure}
\rightarrow
\text{修正 Free-Y 某些不一致部分}
}
]

这是一种 correction，不是复制。

# 暂时绝对不要做的东西

V20.4 第一轮不要：

* shared backbone；
* Y/H 同时从随机初始化训练；
* full `Y_free ↔ Y_H` consistency；
* H-GT loss；
* stable surrogate loss；
* direct-H 反向影响 Y encoder；
* Y branch 反向影响 H branch；
* PoseToken/Z；
* stochastic H。

这些都是以后可能做的东西，但现在会破坏因果归因。
