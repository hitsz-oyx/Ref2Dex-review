# V16 Minimal：解析 Interaction Field 与 MANO Self-Inverse

## 0. 当前阶段目标

暂停继续设计 learned interaction token (C)。

当前首先回答一个更基础的问题：

> **是否存在一种比直接 Action imitation 更抽象、但仍保留足够交互信息的解析表示 (Y)，能够通过 MANO forward + gradient optimization 恢复合理的手部运动？**

第一阶段完全不训练新的 neural network。

流程：

[
\boxed{
\text{GT MANO trajectory}
\rightarrow
Y^{GT}
}
]

然后从错误的 MANO trajectory 初始化：

[
\boxed{
q_{0:T}
\overset{MANO}{\longrightarrow}
H_{0:T}
\overset{\mathcal I}{\longrightarrow}
Y(q)
}
]

通过：

[
\boxed{
q^*
===

\arg\min_q
D(Y(q),Y^{GT})
}
]

恢复 trajectory。

这里：

* (q)：MANO pose + wrist root pose；
* (H)：MANO surface；
* (\mathcal I)：完全解析、可微的 interaction field builder；
* (Y)：物理可解释的 interaction representation；
* 不存在 learned (C)。

---

# 1. 为什么现在先不做 learned C

此前我们把几个不同问题混到了一起：

[
A=\text{动作表征}
]

[
C=\text{interaction latent}
]

[
Y=\text{真实 interaction GT}.
]

实际上应该先明确：

[
\boxed{
Y=\text{什么交互是正确的}
}
]

再考虑：

[
\boxed{
C=\text{如何学习和压缩 }Y
}
]

如果 (Y) 本身无法支持 MANO/FK optimization，

那么继续训练：

[
A+W\rightarrow C
]

没有意义。

---

# 2. 当前项目的核心思想

项目最终不是简单做：

[
\boxed{
\text{Human Action}
\rightarrow
\text{Robot Action}
}
]

否则直接匹配 ActionToken 已经足够。

真正目标是学习：

[
\boxed{
\text{Object Shape}
+
\text{Desired Effect}
\rightarrow
\text{Useful Interaction}
}
]

即：

> 对这种几何形状的物体，如果希望产生某种效果，执行体应该怎样与物体发生交互。

因此希望最终允许：

[
A_H\neq A_R
]

但：

[
\boxed{
Y_H\approx Y_R
}
]

并产生：

[
E_H\approx E_R.
]

---

# 3. ActionToken 与 Y 的关系

ActionToken：

[
\boxed{
A_t=E_A(\Delta H_t)
}
]

负责：

> 执行体具体怎么运动。

ActionToken 应保留较高的 motion fidelity。

而：

[
\boxed{
Y_t=\mathcal I(H_t,H_{t+1},O_t,O_{t+1})
}
]

负责：

> 这些运动放在当前物体附近意味着什么。

因此：

[
\boxed{
A=\text{motion}
}
]

[
\boxed{
Y=\text{interaction}
}
]

如果未来发现：

[
D(A_R,A_H)
]

和：

[
D(Y_R,Y_H)
]

效果完全相同，那么 learned interaction representation 的研究价值需要重新评估。

---

# 4. Y 的设计原则

第一版 (Y) 必须同时满足：

1. **解析**

GT 不由 neural network 产生。

2. **可微**

从 MANO parameters 到 (Y) 必须可以反向传播。

3. **动态**

不能只描述最终 contact。

4. **Object-centric**

统一定义在物体坐标系中。

5. **不依赖 human↔robot patch correspondence**

Human 和 Robot 不需要拥有相同的 surface topology。

6. **信息足够**

第一阶段宁可多保留信息，不要一开始过度压缩。

---

# 5. Object Anchors

在 object canonical frame 中固定采样：

[
\boxed{
X_O=
{x_m}_{m=1}^{M}
}
]

第一版：

[
\boxed{
M=128
}
]

推荐直接从 object surface point cloud 上做 deterministic FPS。

同一个 object 的 anchors 永远固定：

[
x_1,\dots,x_M.
]

这里的 index 只是在同一个 object 内方便存储。

真正的 identity 来自：

[
\boxed{
x_m\in\mathbb R^3
}
]

而不是：

[
\text{token index }m.
]

# 6. 所有几何统一到 Object Frame

GT hand：

[
H_t^W.
]

Object root：

[
T_{O,t}^W.
]

转换：

[
\boxed{
H_t^O
=====

(T_{O,t}^W)^{-1}
H_t^W
}
]

得到：

[
H_t^O=
{h_{t,i}}_{i=1}^{N}.
]

后面所有 interaction target 都在该坐标系计算。

这样如果：

```text
hand + object
一起平移/旋转
```

但二者相对关系不变，

则：

[
Y
]

基本保持不变。

Global object motion 单独记为 effect：

[
E.
]

---

# 7. 不使用 Hard Nearest Neighbor

不要：

[
i^*
===

\arg\min_i
|h_i-x_m|.
]

Hard argmin 会造成 correspondence 离散跳变。

使用 soft nearest surface。

对于每个：

[
x_m
]

以及 MANO surface point：

[
h_{t,i},
]

定义：

[
d_{tmi}^2
=========

|h_{t,i}-x_m|_2^2.
]

Soft weight：

[
\boxed{
w_{tmi}
=======

\frac{
\exp(-d_{tmi}^2/\tau^2)
}{
\sum_k
\exp(-d_{tmk}^2/\tau^2)
}
}
]

第一版：

[
\boxed{
\tau=0.015m
}
]

即 1.5 cm。

后面仅作为 ablation 测：

```text
1 cm
1.5 cm
2 cm
```

第一版不要调参。

---

# 8. Y 的第一个部分：Relative Geometry

对于 object anchor (x_m)：

[
\boxed{
r_{t,m}
=======

\sum_i
w_{tmi}
(h_{t,i}-x_m)
}
]

其中：

[
r_{t,m}\in\mathbb R^3.
]

它描述：

> 当前 object location 附近的 hand surface 在哪里。

它同时包含：

### 距离

[
d_{t,m}
=======

|r_{t,m}|
]

以及：

### 方向

[
\hat r_{t,m}
============

\frac{r_{t,m}}
{|r_{t,m}|}.
]

因此不需要单独增加 scalar SDF。

---

# 9. Y 的第二个部分：Relative Motion

利用同一时刻 (t) 的 soft weights：

[
w_{tmi}
]

跟踪附近 hand surface 的下一步运动：

[
\boxed{
u_{t,m}
=======

\sum_i
w_{tmi}
\left(
h_{t+1,i}-h_{t,i}
\right)
}
]

其中：

[
u_{t,m}\in\mathbb R^3.
]

它描述：

> 当前 object location 周围的 hand surface 接下来如何运动。

注意：

不要使用：

[
r_{t+1,m}-r_{t,m}
]

作为唯一 motion target。

因为最近的 hand surface 区域可能发生切换。

使用 (w_t) 跟踪当前邻域可以保留更明确的 local motion。

[
\boxed{
Y_{t,m}
=======

[

u_{t,m}
]
}
]

因此：

[
\boxed{
Y
\in

当前：

[

\qquad

即：

```text

```

其物理意义：

```text
Y[..., 0:3] = hand relative geometry
Y[..., 3:6] = nearby hand relative motion
```

# 11. 暂时不要加入 Contact Label

Contact 可以由：

[
r
]

解析得到：

[
\boxed{
c_{t,m}
=======

\exp
\left(
-\frac{
|r_{t,m}|^2
}{
2\sigma_c^2
}
\right)
}
]

因此 contact 是：

[
c=g(Y)
]

不是新的独立信息。

第一阶段不要重新加入：

```text
binary contact
64×64 contact matrix
hand patch identity
```

避免重新制造稀疏监督和 correspondence 问题。

# 12. 暂时不要加入 SDF

SDF 本身并非错误。

但：

[
SDF(x)
]

主要是静态几何距离。

当前已经通过：

[
r_{t,m}
]

保留：

* 距离；
* 方向；

通过：

[
u_{t,m}
]

保留：

* 动态。

因此第一版无需单独加入 SDF。

之后可以把：

[
|r|
]

与真实 mesh SDF 做对照实验。

# 23. 一个非常重要的解释原则

如果：

[
Y=[r,u]
]

不能恢复完全相同的 MANO pose，

不能立即判定 Y 失败。

例如：

```text
GT:
无名指稍微弯曲

Prediction:
无名指稍微伸直
```

但这个 finger 离 object 很远。

如果：

[
Y_{pred}\approx Y_{GT}
]

且：

[
contact_{pred}\approx contact_{GT},
]

这种差异可能正是我们未来希望的：

[
\boxed{
\text{丢掉与 interaction 无关的动作细节}
}
]

因此：

[
\boxed{
MANO reconstruction
}
]

只是信息保真诊断，

不是最终目标。

# 33. 当前项目的一句话思想

[
\boxed{
\text{Action 描述“执行体怎么动”，
Interaction 描述“这些运动如何作用于物体”。}
}
]

最终真正希望模型学到的是：

[
\boxed{
\text{对于这种形状的物体，
为了产生这种效果，
什么样的 interaction 是有效的。}
}
]

因此现在先验证 (Y)，不要急着训练 (C)。
