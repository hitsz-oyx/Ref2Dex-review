# 我建议的 V12 架构

整体变成：

```text
Hand surface at t
      ↓
Static Pose Encoder
      ↓
Pose representation S_t
      │
      ├── global hand-shape code z_t
      └── local surface pose tokens P_t

Hand surface at t+1
      ↓
Static Pose Encoder
      ↓
S_t+1 = {z_t+1, P_t+1}

S_t , S_t+1
      ↓
Motion / Action Encoder
      ↓
A_t
      ↓
Action reconstruction
      ↓
Δ wrist SE(3)
+
local articulated surface flow
```

然后 8 个相邻 transition：

[
A_{t\to t+1},
A_{t+1\to t+2},
\dots,
A_{t+7\to t+8}
]

再经过 temporal Transformer：

[
\boxed{
A\in\mathbb R^{8\times64\times D}
}
]

最终才进入：

[
W+A\rightarrow C_m.
]

我认为这比当前“从 (t) 直接编码整个 cumulative 8-step displacement”要干净很多。

# 1. 第一层：Static Hand Pose Encoder

你说的：

> “我想用一个变量来表征手型，例如两指捏起或者五指张开。”

这个想法是对的。

但是这个变量应该表示：

[
\boxed{\text{articulation / hand pose}}
]

而不是：

* 手在世界坐标哪里；
* 手朝什么方向；
* 这个人的手比较大还是比较小。

因此第一步一定要 canonicalize（规范化：把手变换到自己的固定局部坐标系）。

现在有：

[
H_t^{world}.
]

用 wrist/root pose：

[
T_t^H
]

变成：

[
\tilde H_t =

(T_t^H)^{-1}H_t.
]

这样：

```text
手平移 20 cm      → static code 不变
手整体旋转 90°    → static code 不变
两指 pinch        → static code 改变
五指张开          → static code 改变
```

这才是真正的：

[
\boxed{z_t^{pose}}
]

---

# 2. 最好连“人的手大小”也去掉

这是一个容易忽略的问题。

GRAB 不同 subject 的 MANO betas 不一样，所以：

[
\tilde H_t
]

里面同时包含：

[
\text{hand identity}
+
\text{hand articulation}.
]

而我们其实只想让：

[
z_t
]

表达：

> 当前是什么手型。

而不是：

> 这是 subject 7 的手。

因为 MANO 有稳定 vertex correspondence，所以这里有一个很好用的做法。

对每个 subject 生成 neutral hand：

[
H_{\mathrm{neutral}}^{(s)}.
]

然后编码：

[
\boxed{
D_t = \tilde H_t -

H_{\mathrm{neutral}}^{(s)}
}
]

这个 deformation field（形变场：当前手型相对该人的中立手型发生了什么变形）基本就把：

* 手掌宽度；
* 手指长度；
* subject morphology

消掉了。

于是：

[
D_t
\rightarrow
E_{\text{pose}}
\rightarrow
z_t.
]

我非常推荐这么做。

---

# 3. Static code 不要只有一个 global token

如果只有：

[
z_t\in\mathbb R^{128}
]

它当然可以学：

```text
pinch
open palm
fist
three-finger grasp
```

但是可能把细节压掉。

所以我会同时保留：

[
P_t\in\mathbb R^{64\times D}.
]

也就是：

```text
1538 surface points
        ↓
same 64 stable surface patches
        ↓
64 pose patch tokens
        ↓
        ├── mean/attention pool → z_t [128]
        │
        └── retain P_t [64,D]
```

因此：

[
\boxed{
S_t=(z_t,P_t)
}
]

其中：

### (z_t)

回答：

> 整只手现在是什么 configuration？

### (P_{t,j})

回答：

> 第 (j) 个 hand surface region 当前是什么局部 configuration？

这样既有你想要的“手型变量”，又不会牺牲细节。

# 4. static encoder 应该怎么监督？

这里我不建议给它人工分类：

```text
pinch = class 1
open = class 2
fist = class 3
```

因为那会把动作空间人为离散化，而且很多真实 grasp 根本无法清楚分类。

更好的方法是：

[
\boxed{\text{static hand surface reconstruction}}
]

也就是：

[
S_t
\rightarrow
\hat D_t.
]

由于 MANO vertex correspondence 已知，直接：

[
L_{\text{pose}} =

\frac1N
\sum_i
|
\hat D_{t,i}-D_{t,i}
|^2.
]

甚至不用 Chamfer。

这样如果：

```text
two-finger pinch
```

和：

```text
open palm
```

对应 surface geometry 明显不同，那么：

[
z_{\text{pinch}}\neq z_{\text{open}}
]

自然会被学出来。

# 5. 然后才是你的“前后两帧拼起来”

这里我很赞同。

例如：

[
S_t=(z_t,P_t)
]

[
S_{t+1}=(z_{t+1},P_{t+1}).
]

那么每个 patch 的 action token：

[
A_{t,j} =

F_A(
P_{t,j},
P_{t+1,j},
z_t,
z_{t+1},
\Delta T_t^H
).
]

其中：

[
\Delta T_t^H =

(T_t^H)^{-1}T_{t+1}^H
]

是 wrist/root 的刚体运动。

结构可以很简单：

```text
P_t,j --------┐
P_t+1,j ------┤
P_t+1,j-P_t,j ┤
              ├── MLP / Transformer → A_t,j
z_t ----------┤
z_t+1 --------┤
Δ wrist SE3 --┘
```

于是：

[
\boxed{
A_{t,j}
}
]

真正代表：

> 从这个 static configuration 到下一个 static configuration，当前 surface region 做了什么动作。

这个定义我认为非常自然。

# 6. 为什么我更推荐相邻帧，而不是现在的 cumulative displacement

当前代码其实是：

[
H_t
\rightarrow
\Delta H_{t\to t+1},
\dots,
\Delta H_{t\to t+8}.
]

也就是每一步都相对：

[
H_t.
]

这很容易让 global wrist motion 占主导：

```text
整只手上移 5 cm
```

所有 point 都有差不多的 displacement。

而改成 adjacent：

[
H_k\rightarrow H_{k+1}
]

以后每个 action token 就是真正的 incremental action（增量动作）。

8 帧变成：

[
\boxed{
A_1,A_2,\dots,A_8
}
]

对应：

[
t\to t+1,;
t+1\to t+2,\dots
]

这和 object SE(3) 现在已经使用 incremental pose 的逻辑也是一致的。

# 7. ActionToken 的监督：我建议反解码点流，但要拆成两部分

这里回答你最核心的问题：

> 要不要反解码动作点流？

### 要。

但我**不建议只反解码 raw point flow**。

因为：

[
\Delta H =

\text{wrist rigid motion}
+
\text{finger articulation}.
]

如果直接 MSE：

[
A\rightarrow\Delta H
]

很容易再次出现：

> 模型先把 global translation 学得很好，loss 就很低，finger motion 反而不重要。

所以拆成：

[
\boxed{
A_t
\rightarrow
\begin{cases}
\Delta T_t^{wrist}\
\delta H_t^{articulation}
\end{cases}
}
]

## 8. 第一条：wrist action

监督：

[
\Delta T_t^H.

分成：

[
\Delta p_t\in\mathbb R^3
]

和：

[
\Delta R_t\in SO(3).
]

loss：

[
L_{\text{root}} =

L_{\text{translation}}
+
\lambda_RL_{\text{rotation}}.
]

这告诉 ActionToken：

> 整只手怎么移动。

# 9. 第二条：local articulated point flow

先把前后两帧都放进各自 wrist frame：

[
\tilde H_t,
\tilde H_{t+1}.
]

然后：

[
\boxed{
\delta H_t = \tilde H_{t+1} -

\tilde H_t
}
]

这时候 wrist 平移旋转已经被剥掉了。

剩下的就是：

* finger closing；
* finger opening；
* thumb opposition；
* palm/finger articulation。

然后：

[
A_t\rightarrow
\hat{\delta H}_t.
]

loss：

[
\boxed{
L_{\text{art}} =

\frac1N
\sum_i
|\hat{\delta h}_{t,i} -

\delta h_{t,i}
|^2
}
]

这才是我认为真正关键的 action supervision。

# 11. 为什么我暂时不建议 Flow Matching

FastWAM 用 Flow Matching 是因为它最终要解决的是：

[
p(a_{1:T}\mid observation)
]

动作**生成分布**，一个 observation 可能对应多种正确 action。

而我们现在首先要解决的是：

[
\boxed{
\text{给定一个真实动作，怎么把它编码得足够完整？}
}
]

这是 representation learning 问题。

现在有确定 GT：

[
H_t,H_{t+1}.
]

最小实验直接：

[
\text{encode}\rightarrow\text{decode}\rightarrow MSE
]

就够了。

如果这个阶段都不能保留 finger articulation，再上 Flow Matching 只会让调试复杂很多。

# 14. 我会怎么实际推进

我不建议一次把整个 V12 写得特别复杂。我会按三个最小实验推进：

1. **V12-A：先用现有 ActionToken 做 global/local action reconstruction。** 当前仓库已经有 `action_reconstruction` head 和 `patch_motion_target`，但目前只是 patch mean cumulative flow，并且 loss 被关掉。先改成 wrist motion + wrist-frame local patch flow，确认 ActionToken 能被明显拉出 local information。
2. **V12-B：加入 Static Pose Encoder。** 每帧先得到 (S_t=(z_t,P_t))，做 static surface reconstruction；检查 (z_t) 是否能自然区分 open / pinch / fist，同时对 global SE(3) 不敏感。
3. **V12-C：改为 pairwise incremental ActionToken。** 用 ((S_t,S_{t+1})\rightarrow A_t)，再让 8 个 incremental ActionToken 进入现有 World+(A)(\rightarrow C_m) 路径。

我认为真正应该作为最终架构的是 **V12-C**；但 V12-A 很值得先做，因为它几乎不改网络，就可以回答一个非常重要的问题：

[
\boxed{
\text{只给当前 ActionToken 加正确的 local action supervision，够不够？}
}
]

如果够，我们甚至不需要立刻引入复杂 Static Pose Encoder；如果不够，再上你提出的“静态手型编码 → 相邻帧动作编码”就有充分实验依据。

而从表示设计本身来说，我最支持的是：

[
\boxed{
\underbrace{z_t}*{\text{global hand shape}}
+
\underbrace{P_t}*{\text{local surface pose}}
\rightarrow
\underbrace{A_{t\to t+1}}_{\text{incremental action}}
}
]

而不是简单：

[
H_t,H_{t+1}\rightarrow一个 global\ ActionToken.
]

这会更适合你现在真正想保留的灵巧手细节。

actiontoken流其实也可以直接训练，不需要依赖物体，在mano里面改pca参数其实就对应一组单独姿态了
