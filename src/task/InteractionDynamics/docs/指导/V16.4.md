# V16.4：Object-Effect Conditional Interaction Field Diffusion

## 0. 本阶段思想变化

V16.3 的主要路线是：

[
Y
\rightarrow
C
\rightarrow
\hat Y
]

即首先研究如何将高维 analytic interaction field (Y) 压缩成 compact latent (C)。

V16.4 调整优先级：

[
\boxed{
\text{压缩不是当前最前置的问题。}
}
]

当前更重要的问题是：

> 已经定义好的 analytic (Y)，能否作为监督信号，让模型从 Object Geometry (O) 和 Desired Effect (E) 中学习“这个物体应该如何被交互”？

因此 V16.4 暂停：

* (Y\rightarrow C\rightarrow\hat Y) compression；
* K=8 latent slot 调优；
* PCA compression；
* C-space metric；
* C-space inverse。

优先打通：

[
\boxed{
p_\theta(Y\mid O,E)
}
]

最终验证：

[
\boxed{
O+E
\rightarrow
Y^*
\rightarrow
MANO/Embodiment\ Optimization
}
]

# 1. 当前核心问题

当前 Y-Teacher V1 已经定义为：

[
Y=
{
r_{0:T},
d_{0:T},
u_{0:T-1}
}.
]

其中：

[
r\in\mathbb R^{9\times M\times3},
]

[
d\in\mathbb R^{9\times M},
]

[
u\in\mathbb R^{8\times M\times3},
]

当前：

[
M=128.
]

Y 表示的是：

> 在物体表面不同位置附近，手在整个交互过程中在哪里、有多近、如何运动。

它是一次具体 demonstration 的高保真 interaction descriptor，而不是 knowledge 本身。

当前真正希望学习的是：

[
\boxed{
\text{这种物体 }O
+
\text{希望产生这种效果 }E
\Rightarrow
\text{哪些 interaction }Y\text{ 是有效的？}
}
]

因此真正的 knowledge model 应建模：

[
\boxed{
p(Y\mid O,E).
}
]

---

# 2. 为什么不能直接做确定性 O+E→Y

对于同一个：

[
O=\text{cup}
]

和：

[
E=\text{lift},
]

可能存在多个有效 interaction：

[
Y_1=\text{抓杯柄},
]

[
Y_2=\text{抓杯身},
]

[
Y_3=\text{托住底部}.
]

因此：

[
\boxed{
(O,E)\not\rightarrow Y_{\rm unique}.
}
]

真实关系是：

[
\boxed{
p(Y\mid O,E).
}
]

如果使用普通 MSE regression：

[
\hat Y=f(O,E),
]

不同 interaction modes 可能被平均，从而得到不存在的中间交互模式。

因此 V16.4 第一版直接使用 conditional diffusion。

Diffusion 在这里指：

> 给真实 interaction (Y) 加噪，然后训练网络在给定物体 (O) 和目标效果 (E) 的条件下逐步恢复 (Y)。

---

# 3. Y 不依赖 Object Anchor Index

当前 Y 虽然用：

[
M=128
]

个 object anchors 离散保存，但必须明确：

[
\boxed{
\text{anchor index 本身没有语义。}
}
]

正确表示不是：

[
[Y_1,\ldots,Y_M],
]

而是：

[
\boxed{
\mathcal Y
=

{
(x_m,Y(x_m))
}_{m=1}^{M}.
}
]

其中：

[
x_m\in\mathbb R^3
]

是该 anchor 在 object frame 中的真实位置。

不同物体：

[
x_{17}^{A}
]

与：

[
x_{17}^{B}
]

不需要对应。

模型不能学习：

[
\text{anchor #17}\rightarrow interaction.
]

模型应该学习：

[
\boxed{
\text{geometry at }x
+
\text{global object geometry}
+
\text{desired effect}
\rightarrow
\text{interaction at }x.
}
]

# 4. V16.4 对 Y 的组织方式

为了第一版 architecture 简单，不再将：

[
(t,m)
]

分别看作大量 token。

对于每个 object anchor (x_m)，直接将完整 interaction trajectory 拼成：

[
\boxed{
y_m
===

[
r_{0:8,m},
d_{0:8,m},
u_{0:7,m}
].
}
]

维度：

[
9\times3
+
9
+
8\times3
=

60.

]

因此：

[
\boxed{
Y\in\mathbb R^{M\times60}
}
]

当前：

[
\boxed{
Y\in\mathbb R^{128\times60}.
}
]

每一个 token 表示：

> 一个 object surface location 在整个 interaction trajectory 中经历了什么。

即：

```text
object anchor x_m
        ↓
[r0 ... r8]
[d0 ... d8]
[u0 ... u7]
        ↓
interaction trajectory y_m
```

V16.4 暂时保留当前固定 8-step horizon，不解决 temporal progress normalization。

## 5.3 Effect E

V16.4 第一版不使用语言 label。

直接从真实 object trajectory 构造 Desired Effect。

推荐第一版使用完整 8-step object motion：

[
\boxed{
E=
{
\Delta T^O_0,
\ldots,
\Delta T^O_7
}.
}
]

其中：

[
\Delta T^O_t
=

(T^O_t)^{-1}T^O_{t+1}.
]

每一步提取：

[

[

\Delta\omega_t
]

所以：

[
\boxed{
E\in\mathbb R^{8\times6}.
}

第一阶段主动给模型较强的 effect supervision。

当前目标不是研究：

[
Language\rightarrow Effect,
]

而是研究：

[
\boxed{
Object+Effect\rightarrow Interaction
}
]

本身是否成立。

# 7. Object Encoder

Object Encoder 负责回答：

> 这个 query point 位于怎样的局部几何中，同时整个物体是什么形状？

输入：

[
O[N,6]
======

[x,y,z,n_x,n_y,n_z].
]

输出：

[
Z_O
===

{
z_i
}_{i=1}^{N},
\qquad
z_i\in\mathbb R^D.
]

对于 128 个 anchors：

[
x_m,
]

获得对应 local feature：

[
\boxed{
z_m=z_O(x_m).
}
]

同时通过 global pooling：

[
\boxed{
z_G=\operatorname{Pool}(Z_O).
}
]

因此模型同时具有：

[
z_m
===

\text{local geometry},
]

以及：

[
z_G
===

\text{global object shape}.
]

第一版优先复用项目已有 point-cloud encoder，不重新设计大规模预训练。

[

[

]

参与 diffusion。

[

[

[

# 11. Diffusion Transformer

第一版使用标准 Transformer block。

每一层：

```text
Interaction Tokens [M,D]
        ↓
Self Attention
        ↓
Cross Attention ← [Global Object, Effect Tokens]
        ↓
FFN
```

Self Attention 负责：

[
\boxed{
\text{不同 object locations 之间的 interaction consistency}
}
]

例如：

> 一个位置建立 contact 后，其他位置应该形成怎样的互补 interaction。

Cross Attention 负责：

[
\boxed{
\text{interaction query 从整体物体与 desired effect 获取条件信息。}
}
]

# 13. 严禁 Anchor Index Embedding

V16.4 不允许：

```python
nn.Embedding(128, dim)
```

表示 object anchor identity。

原因：

[
\boxed{
\text{不同物体的 anchor index 没有 correspondence。}
}
]

唯一允许提供的空间身份是：

[
\boxed{
x_m
}
]

和：

[
\boxed{
z_m=z_O(x_m).
}
]

模型必须满足 permutation equivariance：

如果同时 permutation：

[
(X,Y,Z)
]

则输出只应发生相同 permutation。

训练时建议随机打乱：

[
(x_m,z_m,y_m)
]

顺序作为最低成本 sanity check。
