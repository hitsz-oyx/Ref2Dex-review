### V5 的好消息

你之前担心 raw hand/object flow 几乎全是 global motion，这个问题相对运动确实解决了不少。

V5 统计得到，法向/切向相对运动 (v_n,v_t) 的跨 edge 局部能量占比：

[
\begin{array}{c|cc}
& v_n & v_t\
\hline
val &33.11%&22.16%\
test&41.58%&37.49%
\end{array}
]

而之前 raw hand/object patch flow 只有大约 1%–3%。这说明

[
\boxed{\Delta H-\Delta O}
]

确实比单独的 (\Delta H) 或 (\Delta O) 更接近我们想要的 local mechanism（局部作用机制）。

这部分我认为可以保留，不需要退回 object-flow supervision。

## 但 V5 真正训练还没成功

现在每个 hand patch：

1. 找**当前帧最近的 object patch**；
2. 拼接：

   * `action_context`
   * 最近 object token
   * hand-object 相对位置
   * object normal
   * distance
3. 得到一个 `relative_interaction_token`；
4. 预测 8 步：

[
[v_n,v_t]\in\mathbb R^4.
]

代码已经完全绕开了之前 collapse 的 object canonicalizer 来构造这个 edge token。

所以 V5 token 本身也确实**没有 collapse**：

[
\text{val cosine}=0.871
]

[
\text{test cosine}=0.840.
]

但预测结果：

### 全部最近邻 edge

[
RMSE_{val}=1.389\text{ cm}
]

zero baseline：

[
1.370\text{ cm}.
]

测试：

[
1.178>1.110\text{ cm}.
]

### 只监督当前 5 cm 内 edge

[
RMSE_{val}=0.999\text{ cm}
]

zero：

[
0.968\text{ cm}
]

测试：

[
0.874>0.841\text{ cm}.
]

也就是说：

[
\boxed{\text{目前仍然没有打败“全部预测为 0”。}}
]

这和前面的 collapse 问题已经不同了：**现在 representation 是有局部差异的，但 target prediction 本身泛化不起来。**

# 我看代码后认为目前最值得注意的是三个问题

### 1. correspondence（对应关系）被固定在当前帧

现在：

[
j(i)=\arg\min_j|h_i(t)-o_j(t)|
]

只在 (t) 时刻算一次。

之后 8 个未来 step 一直使用同一个 object patch (j(i))。`relative_motion_target()` 就是按这个固定 `nearest` 抽出 object motion。

所以如果手指发生：

```text
object patch A
     ↓
   滑动
     ↓
object patch B
```

你的 target 仍然计算：

[
h_i(t+k)-o_A(t+k)
]

而不是：

[
h_i(t+k)-o_B(t+k).
]

对于“抓稳后整体搬运”问题不大。

但是我们现在恰恰想学：

* sliding；
* contact establishment；
* re-contact；
* release；

这类 mechanism。

所以我现在最怀疑：

[
\boxed{\text{fixed current nearest-neighbor correspondence}}
]

本身就把一部分 interaction target 定义错了。

仓库日志目前也已经把这个列为首要嫌疑之一。

---

## 2. 5 cm mask 也是只看当前帧

当前 loss：

```python
edge_mask = edge_distance_m * 100.0 < radius_cm
```

然后：

```python
mask = edge_mask[:, None, :, None]
```

也就是说这个 mask 对整个 8-step chunk 都不变。

这产生一个很重要的问题。

假设当前：

[
d(t)=6\text{ cm}
]

但手正在接近物体：

[
6\rightarrow4\rightarrow2\rightarrow0.5\text{ cm}.
]

这其实是一个非常有价值的：

[
\boxed{\text{contact establishment}}
]

样本。

但因为：

[
d(t)>5\text{ cm}
]

整个 edge 的未来 8 帧都不会被 relative loss 监督。

反过来：

[
d(t)=3\text{ cm}
]

但下一步已经离开到 10 cm，它仍然整个 chunk 都被监督。

所以现在的“5 cm near-field edge”实际上是：

[
\boxed{\text{current-near edge}}
]

不是：

[
\boxed{\text{interaction-active edge over the chunk}}.
]

这个我认为非常值得优先改。

---

## 3. 当前用 cumulative trajectory，而不是 step-wise relative motion

现在 target 是：

[
\Delta H_{t\rightarrow t+k}
---------------------------

\Delta O_{t\rightarrow t+k}.
]

也就是累计到当前：

```text
step1: t → t+1
step2: t → t+2
...
step8: t → t+8
```

而不是：

[
\Delta H_{k-1\rightarrow k}
---------------------------

\Delta O_{k-1\rightarrow k}.
]

这意味着后面的 target 很容易有：

* 重尾；
* 累积误差；
* 不同 trajectory duration/magnitude；
* 一个异常 motion 影响后面所有 step。

仓库目前也明确把“逐步增量、重尾程度、correspondence 稳定性”列为下一步诊断，而不是继续调 loss weight。

我同意这个顺序。

# 当前还有一个非常有用的发现

contact classification 暂时确实不应该加。

2 cm threshold 下：

[
contact\ occupancy:
]

val：

[
9.45%
]

test：

[
17.86%
]

而真正：

[
far\rightarrow contact
]

或者：

[
contact\rightarrow far
]

只占：

[
0.98%,\quad1.26%.
]

所以如果现在直接上 contact transition classification：

```text
stay far    绝大多数
stay contact 少数
establish    极少
release      极少
```

模型很容易直接预测“不变化”。

所以仓库目前决定不加 contact classification 是合理的。

# 现在 V5 的训练配置也比较干净

目前 `grab_v5_small20.yaml`：

```yaml
action_loss_weight: 0.0
patch_effect_loss_weight: 0.0
relative_loss_weight: 1.0
relative_edge_radius_cm: 5.0
```

也就是说没有把 V3 的旧 patch loss 搅进来；这次是在比较干净地测试 relative supervision。

Effect consistency 仍然存在，因为总 loss 里始终还有：

[
L_{\text{effect}}
]

但 relative branch 是独立的新机制表征，并且当前还没有接入 Effect Decoder。

这也符合研究顺序：先证明 mechanism target 自己能学，再谈 world effect。

# 我现在对仓库状态的判断

经历 V1→V5 后，问题已经定位得比较清楚：

```text
V1
object flow
→ collapse / global shortcut

V3
加 direct patch supervision
→ 旁路监督无效

V4
强制 local decoder routing
→ 仍无效

target diagnostics
→ 发现 raw motion 97–99% 是 global

V5
改为 hand-object relative motion
→ local signal 提升到 20–40%
→ edge token 不再 collapse
→ 但预测仍打不过 zero baseline
```

所以现在最大的进展其实是：

[
\boxed{\text{representation collapse 已经不再是 V5 的首要问题。}}
]

当前真正要解决的是：

[
\boxed{
\text{怎么定义一个稳定且可预测的 hand-object interaction correspondence。}
}
]

我现在不会继续改 backbone、Uni3D、attention，也不会调 `relative_loss_weight`。

优先级应该是：

[
\boxed{
\text{逐步增量 target}
\rightarrow
\text{动态/逐帧 correspondence}
\rightarrow
\text{interaction-active mask}
}
]

其中我尤其建议先做一个**纯数据诊断**：统计当前 hand patch 的 nearest object patch 在未来 8 帧里有多少比例发生变化，以及变化几次。如果 correspondence 大量变化，那么 V5 当前这个固定 nearest-object edge 的定义基本就找到主要问题了。

还有一点，我们现在严格筛选单手动作，我怀疑过于严格导致筛掉了很多实际交互的数据，导致学的泛化性不好，关注泛化性的时候可以试试全量数据。
