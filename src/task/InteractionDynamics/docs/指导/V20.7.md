# 一、GT contact map 到底是什么

对于物体表面点：

[
o_i\in\mathbb R^3
]

对应 outward normal（向外表面法线）：

[
n_i\in\mathbb R^3
]

以及 GT MANO 手表面点：

[
h_j\in\mathbb R^3,
]

GenDex 不直接用普通：

[
\min_j|h_j-o_i|
]

而是使用 **aligned distance（带法线方向的对齐距离）**。这是为了避免薄壳物体两面同时被错误认为接触。官方论文和项目页都明确强调这一点。([谷歌网站][1])

但是这里有一个实现细节：

**论文公式和公开代码的 `Sqrt...` 实现有一些缩放/平方根差异。**

为了做 B，我建议不要自己按照论文重新实现，而是：

[
\boxed{\text{严格复现官方 }CMapAdam.compute_energy_align_dist()}
]

因为最后 Allegro optimizer 也是用这套代码算当前 contact map。

公开代码实际上计算：

[
\Delta_{ij}=h_j-o_i
]

[
d_{ij}=|\Delta_{ij}|
]

然后：

[
a_{ij}
======

\frac{\Delta_{ij}^{T}n_i}
{d_{ij}+\epsilon}.
]

这里 (a) 可以理解为：

> 这个 hand point 是否位于 object surface normal 指向的正确一侧。

如果：

[
a_{ij}\approx1
]

说明 hand point 正好位于法线方向。

然后代码定义：

[
\tilde d_{ij}
=============

d_{ij}
\exp\left(2(1-a_{ij})\right).
]

再：

[
d_i^{contact}
=============

\sqrt{
\min_j\tilde d_{ij}
}.
]

最后变成 contact value：

[
\boxed{
C_i
===

1-2\left(
\sigma(10d_i^{contact})-0.5
\right)
}
]

其中：

[
C_i\in(0,1].
]

越接近：

[
C_i\rightarrow1
]

越远：

[
C_i\rightarrow0.
]

这就是我们要从 **GT MANO** 算出来的东西。

# 六、真正生成 GT 的函数就这么短

我建议直接新建：

```text
src/task/InteractionDynamics/research/gendex_baseline/
    contact_map.py
```

核心：

```python
import torch


def build_gendex_contact_value(
    object_points: torch.Tensor,   # [N, 3], meter
    object_normals: torch.Tensor,  # [N, 3]
    hand_points: torch.Tensor,     # [M, 3], meter
) -> torch.Tensor:
    delta = (
        hand_points[None, :, :]
        - object_points[:, None, :]
    )  # [N, M, 3]

    dist = torch.linalg.norm(
        delta,
        dim=-1,
    )  # [N, M]

    align = (
        delta
        * object_normals[:, None, :]
    ).sum(-1)

    align = align / (dist + 1e-5)

    aligned_dist = (
        dist
        * torch.exp(2.0 * (1.0 - align))
    )

    contact_dist = torch.sqrt(
        aligned_dist.min(dim=1).values
    )

    contact_value = (
        1.0
        - 2.0
        * (
            torch.sigmoid(10.0 * contact_dist)
            - 0.5
        )
    )

    return contact_value
```

这就是把官方 `compute_energy_align_dist()` 里：

```text
robot surface
    ↓
current contact map
```

那部分拿出来，

把 robot surface 换成：

```text
GT MANO surface
```

即可。其计算结构与官方 optimizer 一致。

然后：

```python
def build_gendex_gt_map(
    object_points,
    object_normals,
    mano_surface,
):
    contact_value = build_gendex_contact_value(
        object_points,
        object_normals,
        mano_surface,
    )

    return torch.cat(
        [
            object_points,
            object_normals,
            contact_value[:, None],
        ],
        dim=-1,
    )
```

输出：

```python
[2048, 7]
```

# 十、需要注意 object origin

GenDex `CMapAdam.reset()` 的初始化有一个明显假设：

它通过：

```python
object_radius = max(norm(object_point_cloud))
```

再把随机 hand 摆到 object 周围。

因此它默认物体大致：

[
\boxed{\text{centered around origin}}
]

我们 GRAB canonical object 虽然在 object local frame，但未必严格零均值。

因此给 GenDex 前，我建议统一做：

[
c_O
===

\frac1N
\sum_i o_i.
]

然后：

[
o_i'
====

o_i-c_O
]

[
h_j'
====

h_j-c_O.
]

normal 不变：

[
n_i'=n_i.
]

生成：

[
C^{GT}(O',H').
]

这样不会改变 hand-object relative geometry。

最后优化得到 Allegro translation：

[
t_R'
]

viewer 放回原 canonical frame：

[
t_R=t_R'+c_O.
]

这个小处理很重要。

# 十四、这里千万不要做的一件事

**不要使用 CVAE 的 `sharp_lift`。**

官方在 `inf_cvae.py` 里对网络预测 contact map 做：

```python
contact_map[contact_map > 0.4] += 0.5
contact_map = clamp(..., 1)
```

是因为论文认为**生成出来的 CVAE map 比 GT map 更模糊**，所以推理阶段人为 sharpen。 ([alphaXiv][2])

我们的：

[
C_H^{GT}
]

已经是从真实 MANO geometry 直接算的。

所以：

[
\boxed{\text{不要 sharp_lift}}
]

否则就不是 GT map 了。
