我看了最新提交 `ebb1cd43`：**“实现 V18 稳定抓取交互扩散并验证全量泛化”**。整体上，这次改动基本按我们刚才讨论的方向落地了，而且结果比 V17 有意义得多。

## 先说目前 V18 到底做成了什么

模型现在确实变成了：

[
\boxed{
R_{t:t+8}\sim p_\theta(R\mid Y_t,O)
}
]

没有 Goal、active、time-to-effect、ActionToken、PoseToken、Effect、CFG，也没有 MANO inverse。数据直接从 stable-grasp 成功 demonstration 中截取。

而且这次是真的扫了比较完整的 GRAB：

* 1335 个 demonstrations
* 2670 个左右手文件
* 检测到 1857 个 stable-grasp hand events
* 覆盖 1320 / 1335 demonstrations
* train / val / test：1487 / 185 / 185 events
* 对应 16357 / 2035 / 2035 个训练 sample。

stable grasp detector 现在定义为：

[
N_{\rm contact}\ge4
]

以及

[
u_{\rm RMS}<0.3\ {\rm cm/frame}
]

连续 6 帧，同时之后 30 帧物体平移超过 1 cm 或旋转超过 (5^\circ)。随机检查的 20 个 onset 基本落在“接触增加 + 相对运动下降”的位置。

所以数据链这一部分我认为**方向正确**。

# 但是我现在不会马上接物体轨迹，有 4 个问题需要先处理

## 1. 最大的问题：stable-success 指标现在可以作弊

这个问题已经被实验自己暴露出来了。

如果按 validation stable success 选 checkpoint，会选 **epoch 1**。

它的 test：

[
single=92.7%
]

[
any-of-8=94.7%.
]

formation subset 甚至：

[
80.8/86.2%.
]

看起来远胜 epoch29。

但是它的 terminal contact：

[
\boxed{42.4\text{ anchors}}
]

而 epoch29 只有：

[
11.1.
]

同时 epoch1 RMSE 达：

[
1.949\text{ cm}.
]

也就是说 epoch1 找到了一个非常明显的漏洞：

> **既然 contact anchors ≥ 4 就算成功，那我疯狂制造接触就行。**

仓库自己的结论也是如此。

所以：

[
N_c\ge4
]

可以做 detector threshold，

**绝对不能直接作为生成模型的主要 reward/selection metric。**

---

# 2. 更隐蔽的问题：我们的 Dataset 和 stable-success evaluation 其实没有完全对齐

现在每个事件采：

[
t_g-8,\ldots,t_g-1
]

再加：

[
t_g,t_g+2,t_g+4.
]

但是 (t_g) 的定义是什么？

> 从 (t_g) 开始，连续 6 帧满足 stable。

因此，如果 sample 从：

[
t=t_g-8
]

开始，而 horizon：

[
H=8,
]

那么它的最后一帧刚刚到：

[
t_g.
]

也就是说：

```text
t_g - 8
    ↓
8-step prediction
    ↓
t_g   ← stable 才刚刚开始
t_g+1
t_g+2
...
t_g+5 ← 才完整满足 6-frame stable
```

所以这个 sample **理论上根本不应该在 H=8 内完成完整 stable grasp**。

这也很可能是为什么 formation subset 的 GT stable success 自己都只有：

[
62.5%.
]

如果这是一个正确的“未来必须达到 stable grasp”指标，那么 GT 应该接近 100%。

因此现在同时混着两个问题：

### A. Grasp-progress prediction

> 从 (t_g-8) 开始，预测接下来真实的 interaction evolution。

和：

### B. Stable-grasp reaching

> 在 H 步以内一定进入稳定抓取。

它们不是同一个任务。

我倾向于**保留 A 作为训练任务**，不要为了让 metric 好看去删数据。

但 evaluation 要分开。

---

# 3. 我比较担心左右手数据存在“伪 functional grasp”

这个问题仓库当前没有充分讨论。

现在是：

* 1320 个 demonstration 检出 event；
* 1857 个 hand event；
* left = 619；
* right = 1238。

这意味着相当一部分 demonstration **两只手都被认为形成了 stable grasp**。

这不一定错，GRAB 里确实可以有双手参与。

但 detector 中的：

> “之后 object 确实移动”

是 **object-level 条件**，不是 hand-specific causal condition。

例如：

```text
左手：轻轻扶着杯子
右手：真正抓住并抬起
           ↓
       object moves
```

那么左手也可能满足：

[
N_c\ge4,\qquad u\approx0
]

并且之后：

[
object\ moves.
]

于是左手也会被标成：

> functional stable grasp。

但如果我们以后把这个左手 (Y_g) 单独 inverse 到机器人：

> 它未必是一个单手就能完成任务的 grasp。

所以如果最终目标是**单手机器人 stable grasp**，我建议马上加一个 audit：

[
\boxed{\text{single-hand event vs bilateral event}}
]

最简单甚至先不用复杂 causal analysis。

在 (t_g) 附近检查另外一只手：

[
N_{\rm other}<4
]

则标：

```text
single-hand clean
```

否则标：

```text
bilateral
```

然后分别报告 V18 结果。

**先不要立刻删除 bilateral。**

看看两组模型表现差多少再决定。

# 我建议 V18.1 现在只做很小的修改

**不要改模型。**

模型：

[
p(R|Y_t,O)
]

我认为目前没发现需要改的理由。

只改 evaluation 和 training protocol。

### 第一件事：训练延长到约 10k optimizer steps

```text
30 epochs → 160 epochs
```

保存每 5 epoch checkpoint。

---

### 第二件事：把 test 分成三个 subset

不要再只报 overall：

```text
Formation:
    current contact < 4

Transition:
    current contact >= 4
    frame < t_g

Maintenance:
    frame >= t_g
```

这样我们马上知道模型到底是在：

* 建立 interaction；
* 收紧 interaction；
* 保持 interaction；

哪一步强、哪一步弱。

---

### 第三件事：不要用 binary stable success 选模型

我建议第一版甚至不要急着造一个加权 score。

先采用 **Pareto selection（帕累托选择）**：

中文就是：

> 一个 checkpoint 必须在多个指标之间都合理，而不是为了一个指标把另一个指标搞崩。

至少同时看：

[
\text{trajectory RMSE}
]

[
\text{stable success}
]

[
\text{terminal contact count}
]

并把 GT contact distribution 一起报告：

```text
GT terminal contact:
mean / median / p10 / p90

Prediction:
mean / median / p10 / p90
```

只要出现：

[
42.4
]

这种离 GT 很远的过接触，就直接拒绝 checkpoint。

# 然后我认为下一步必须做一次 Y-realizability

这是比“继续提高 stable success”更重要的问题。

现在我们证明的是：

[
\boxed{
\text{Diffusion 能生成一个看起来像 stable grasp 的 }Y
}
]

但还没证明：

[
\boxed{
\exists H:
\Phi(H,O)=Y_{\rm generated}
}
]

也就是说：

> **这个生成出来的 (Y) 到底有没有一只真实的手可以实现？**

因为网络直接生成：

[
r,d,u
]

这些量并不是任意独立组合都合法。

真实 (Y) 来自：

[
Y=\Phi(H,O),
]

所以它应该落在一个受手几何约束的 manifold（流形，简单说就是“所有真实手能够产生的合法 (Y) 集合”）上。

Diffusion 完全有可能生成：

```text
contact 很好
u 很小
stable metric 通过
```

但实际上：

> 没有任何 MANO hand pose 能同时满足这 128 个 anchor 的关系。

因此我认为 V18.1 训练完后，下一个 Gate 应该不是 object tracking，而是：

[
\boxed{
Y_{\rm generated}
\xrightarrow{\text{MANO inverse}}
H^*
}
]

然后看：

[
D_Y(\Phi(H^*,O),Y_{\rm generated})
]

是否足够小。

这不是重新让 MANO 进入学习主链。

它只是一个：

> **生成 (Y) 的物理/几何合法性检查。**

如果：

```text
GT Y      → inverse 很容易
Generated Y → inverse 也很容易
```

那我们才能真正说：

> V18 学到了可以落到实际手上的 stable-grasp knowledge。

# 所以我现在对这次更改的判断

我不会说 V18 已经“解决了抓取”。

但相比 V17，它第一次给出了一个我认为**科学问题基本对齐**的结果：

[
\boxed{
\text{无 Goal、无 Action、只从当前 }Y
\text{ 出发，模型能从未接触状态生成向 stable grasp 演化的 }Y.
}
]

特别是 formation：

[
Persistence=0%
]

而：

[
Diffusion=33.9%,
\qquad
AnyOf8=70.1%
]

这个结果是值得继续走的。

但下一步我不会做 V19，也不会改 architecture。我会让 Codex 做一个很窄的 **V18.1**：

> **保持 V18 模型和数据表示不变；训练延长到约 10k optimizer steps；把 formation / transition / maintenance 分开评估；加入 GT 对照的 terminal-contact calibration，禁止用 stable-success 单指标选 checkpoint；审计 single-hand/bilateral event；最终对最佳若干 checkpoint 的生成 (Y) 做 MANO inverse realizability 验证。**

这几个实验跑完，我们就能判断当前这个 (Y)-Diffusion 是“指标上会造 contact”，还是已经真正开始成为可用于后续物体轨迹 tracking 的 interaction knowledge。
