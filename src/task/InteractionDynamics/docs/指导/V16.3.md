[

Y={r_{0:T},d_{0:T},u_{0:T-1}}

[
r:[9,128,3],\qquad
d:[9,128],\qquad
u:[8,128,3].

terminal (r_8) 已经补上；同时增加了

[
d_{t,m}

\left|\sum_iw_i r_i\right|

# 3. Phase B 也已经开始实现

现在新增了一个真正的：

[
\boxed{
Y\rightarrow C\rightarrow\hat Y
}
]

`InteractionAutoencoder`。

结构与你我讨论的基本一致：

[
C\in\mathbb R^{K\times128},
]

默认：

[
K=8.
]

Encoder 输入的不是 patch index，而是：

[
[x_m,r,d,t,type]
]

以及

[
[x_m,u,t,type].
]

然后用 8 个 learned latent queries 做 cross-attention 压缩：

[
Y\rightarrow C_{8\times128}.
]

Decoder 再通过：

[
(x_m,t,type)+C
]

恢复：

[
\hat r,\hat d,\hat u.
]

因此**空间路由来自 object coordinate (x_m)，而不是 token #17 这种 index correspondence**。这个设计方向是对的。

而且测试里已经确认了一个我们以后非常需要的性质：

```python
model.requires_grad_(False)
...
loss.backward()
assert r.grad is not None
```

也就是：

[
\boxed{
\text{冻结 C 网络参数后，输入 Y 仍然可以获得梯度。}
}
]

以后：

[
q\rightarrow FK\rightarrow Y(q)\rightarrow C
]

做优化需要的正是这个性质。

# 4. 不过目前压缩实验实际上失败了

这个需要明确。

### PCA baseline

1280 train / 256 unseen-sequence：

|   维度 |   r RMSE |   d RMSE |   u RMSE | Contact F1 |
| ---: | -------: | -------: | -------: | ---------: |
|  256 | 1.547 cm | 1.632 cm | 0.251 cm |      0.007 |
|  512 | 1.473 cm | 1.579 cm | 0.240 cm |      0.005 |
| 1024 | 1.346 cm | 1.494 cm | 0.262 cm |      0.021 |

很差。

但 PCA 这里本身存在一个公平性问题：不同 object 的 FPS anchor #17 根本不是同一个物理位置，flatten PCA 却强行把它们当同一维。因此这个 PCA 更像一个“错误地忽略空间坐标”的 baseline，而不是特别强的压缩方法。

### K=8 learned C

512 chunks / 20 epochs：

[
r/d/u=
3.002/3.044/0.909\text{ cm}
]

[
F1=0.003.
]

比 PCA 还差。

随后专门做 32-chunk controlled overfit，把学习率提高到 (10^{-3})，训练 4000 steps：

[
r=0.617\text{ cm}
]

[
d=0.337\text{ cm}
]

[
u=0.092\text{ cm}
]

但：

[
F1=0.212.
]

所以目前：

[
\boxed{
\text{K=8 compact C 尚未成立。}
}
]

research log 的决策也是正确的：**不跑 K=16/4，不做 reconstructed-Y inverse，不进入 latent metric，先把 K=8 controlled overfit 做通。**

# 5. 但是我检查代码后发现一个比 autoencoder capacity 更优先的问题

这个我建议马上修。

目前 MANO inverse 的 Y 是这样产生的：

[
H_t^{obj}
=========

(T_{O,t}^{world})^{-1}H_t^{world},
]

即**每一帧都使用该时刻自己的 object pose**。所以如果 hand 和 object 一起运动：

[
Y
]

保持相对不变。

但是 autoencoder/PCA 数据是这样构造的：

```python
hand0 = sample["world_hand_points_object"]
displacement = sample["action_hand_disp_chunk_object"]

hand = torch.cat([
    hand0[None],
    hand0[None] + displacement
], 0)
```

而 Dataset 里的 `action_hand_disp_chunk_object` 实际定义是：

```python
obj_pose = obj_root_pose_world[current]

hand_future_object = transform_points(
    hand_points_world[future],
    obj_pose,
)

action_hand_disp_chunk_object = (
    hand_future_object - world_hand
)
```

也就是说，**未来所有 hand frame 都被变换到“当前时刻 object frame”**，而不是分别变换到：

[
T_{O,t+1},T_{O,t+2},...
]

自己的 object frame。

因此现在实际上存在：

[
\boxed{
Y_{\text{inverse}}
\neq
Y_{\text{compression dataset}}
}
]

特别是 object 本身发生明显运动时。

这是当前我认为**最高优先级的问题**。

因为我们刚刚宣布冻结：

[
\boxed{\text{Y-Teacher V1}}
]

就必须保证所有地方使用的 teacher 是完全同一个定义。

# 6. 所以 compression 先不要继续改 Transformer

我建议先新增 Dataset 字段，例如：

```text
action_hand_points_object_sequence
```

真正计算：

```python
hand_object_sequence = np.stack([
    transform_points(
        hand_points_world[frame],
        obj_root_pose_world[frame],
    )
    for frame in [current, *future]
])
```

得到：

[
[9,1538,3].
]

然后：

```python
Y = build_interaction_y(
    hand_object_sequence,
    anchors,
)
```

**inverse、PCA、autoencoder 三边必须调用同一个 builder，输入语义也必须完全相同。**

甚至最好写一个 parity test（等价性测试）：

同一个 raw chunk：

```text
inverse raw MANO path → Y1
Dataset path          → Y2
```

必须：

[
\boxed{
\max|Y_1-Y_2|<10^{-5}
}
]

或者至少浮点误差级。

在这个通过以前，我不会解释当前 compression 数值。

# 7. 还有第二个数据采样问题

`sequence_disjoint_indices()` 虽然保证 train/eval sequence 不重叠，但它现在是：

```python
train = [
    i
    for name in names[:boundary]
    for i in groups[name]
][:max_train]
```

这意味着：

> shuffle 的第一个 sequence 如果 chunk 很多，就可能吃掉大量甚至大部分 `max_train=1280`。

所以它是：

[
\text{sequence-disjoint}
]

但不一定：

[
\text{sequence-balanced}.
]

你之前 InteractionDynamics 已经踩过这种“前几个序列占满 max_samples”的坑。

建议直接复用之前的：

[
\boxed{\text{每序列均匀限额 + 时间均匀采样}}
]

例如：

```text
train:
max 32 chunks / sequence

val:
max 16 chunks / sequence
```

再构成总的 512 / 128。

否则 autoencoder 泛化指标会被 sequence composition 强烈影响。

# 9. 我对这次仓库更改的总体判断

我认为这次方向总体是正确的，而且有一个重要进展：

[
\boxed{
\text{Phase A 可以认为基本完成。}
}
]

现在公平 baseline 已经说明：

[
\text{same morphology: Action > Y}
]

而：

[
\text{cross morphology: Y > Action}
]

这正是我们想看到的性质。

但是：

[
\boxed{
\text{Phase B 现在还不能判断 C 设计失败。}
}
]

因为当前至少有一个明显的 **Y 数据定义不一致**，以及一个 sequence sampling 问题。

---

## 我建议接下来严格做这 5 件事

1. **统一 Y Teacher 数据链**：compression 也必须使用每帧自身 object pose，增加 raw-vs-dataset Y parity test。
2. **改 sequence-balanced sampling**，不要让某几个 sequence 吃掉 512/128 samples。
3. 在修正的数据上重新跑 **1-sample → 4-sample → 32-sample K=8 overfit**。1 个 sample 都不能接近零误差，就检查 decoder/attention；1 个可以、32 个不行，才是 latent capacity/optimization 问题。
4. 只有 32-chunk overfit 足够好以后，再重新跑 512-chunk unseen-sequence。
5. 暂时仍然**不要做 K sweep、C-space inverse、metric learning**。

换句话说，现在仓库的研究状态应该写成：

[
\boxed{
\text{Y-Teacher V1：通过并冻结}
}
]

[
\boxed{
\text{Compact C：已开始，但尚未通过最小 overfit gate}
}
]

而当前最优先不是“给 C 加更复杂结构”，而是先确保：

[
\boxed{
\text{我们压缩的确实是刚刚验证成功的那个同一个 }Y.
}
]

这一步我认为比继续调 autoencoder 更重要。
