# 2. 现在最应该拆开的其实是两种信息

之前一直试图让一个 latent 同时完成：

[
\text{手怎么作用}
+
\text{物体怎么运动}
]

但仓库的数据已经明确告诉我们，这两个东西统计结构完全不同。

### 物体运动

GRAB object 是刚体：

[
O_{t+k}=R_kO_t+t_k
]

所以它真正的自由度就是：

[
\boxed{SE(3)}
]

也就是三维刚体位姿——3 维平移 + 3 维旋转。

之前 object patch target 的：

[
96.7%-99.0%
]

能量都是所有 patch 共享的 global motion。

因此物体未来运动就应该：

[
\boxed{
\text{直接预测 SE(3)，不要再让 64 个 interaction token 分别预测刚体 point flow。}
}
]

---

### Interaction mechanism

而 hand-object relative motion 的局部能量却达到：

[
v_n:33%-42%
]

[
v_t:22%-37%.
]

说明真正具有局部辨识力的是：

[
\boxed{\text{手相对于物体表面的动作分布}}
]

而不是物体本身怎么动。

所以这两个分支应该彻底拆开。

# 5. Action Encoder 有一个地方我会明确改：不要再 mean pool 时间

当前代码最后是：

```python
temporal = self.temporal(...)
action = temporal.mean(1)
```

所以原本：

[
[8,64,384]
]

最后被压成：

[
[64,384].
]

这对于“搬运”可能没问题。

但对于：

```text
approach
→ contact
→ slide
→ release
```

非常不自然。

我们刚刚已经发现真正重要的 mechanism 是**随时间变化的局部关系**。

所以新 Action Expert 应该直接保留：

[
\boxed{
A\in\mathbb R^{B\times8\times64\times384}
}
]

也就是：

> 每一个 hand patch，每一个时间步都有自己的 action token。

这其实也更接近 Fast-WAM 的设计思想：**不要过早把 action chunk 时间维压掉。**

# 6. 不再使用 hard nearest edge

V5 当前：

[
j(i)=\arg\min_j d(h_i,o_j)
]

有两个问题。

第一，V6 已经证明超过一半 edge 会换 nearest。

第二，而且对我们后面最重要的：

[
\boxed{\arg\min}
]

不可微。

以后 robot inverse optimization：

[
q^{robot}
\rightarrow FK
\rightarrow hand\ surface
\rightarrow C_m
]

需要：

[
\frac{\partial C_m}{\partial q}
]

才能优化机器人关节。

hard nearest 一旦边界跳了：

```text
patch 13
→ patch 14
```

梯度非常不连续。

所以从最终 robot optimization 目标来看，**hard nearest 本来就不应该成为最终表示。**

# 7. 改成 soft interaction field

对每个 object patch：

[
o_j
]

每个 hand patch：

[
h_{k,i}
]

定义连续权重：

[
w_{kij} =

\exp
\left(
-\frac{|h_{k,i}-o_j|^2}{2\sigma^2}
\right)
]

例如：

[
\sigma=3\sim5\text{ cm}.
]

然后归一化：

[
\tilde w_{kij} =

\frac{w_{kij}}
{\sum_iw_{kij}+\epsilon}.
]

这叫 soft routing（软路由：不是只选一个最近点，而是附近的多个手部区域按距离连续贡献）。

# 8. 每条 edge 不再预测未来，而是描述“已知动作”

这是和 V5 最大的思想变化。

我们输入本来就已经知道：

[
\Delta H_{1:8}.
]

所以我们其实没必要让：

[
EdgeToken
\rightarrow
\widehat{v_n,v_t}
]

然后再跟一个近零 target 较劲。

直接构造：

[
e_{kij} =

[
A_{k,i},
r_{kij},
d_{kij},
n_j,
n_i,
\Delta h_{k,i}
]
]

其中：

[
r_{kij}=h_{k,i}-o_j.
]

还可以把动作投影到 object normal：

[
a^n_{kij} =

\Delta h_{k,i}\cdot n_j
]

以及 tangent：

[
a^t_{kij} =

## \Delta h_{k,i}

a^n_{kij}n_j.
]

这些量**全部来自模型输入本身**。

不需要 future object GT。

[


删掉作为主训练结构。

换成：

[
C_{1:8,1:64}

加上：

[
W_O

[
g_k

Pool(C_{k,:},W_O).

然后：

[
g_k
\rightarrow
\xi_k\in\mathbb R^6.

这里：

[

叫 twist，中文就是：

> **6 维刚体运动增量：3 维平移 + 3 维旋转增量。**

最好预测 step-wise：

[
T_{k-1}^{-1}T_k

# 12. Point-flow 不需要学，直接从 SE(3) 算

假设预测：

[
\hat T_k=(\hat R_k,\hat t_k)
]

那么任意 object point：

[
o_i
]

未来：

[
\hat o_{i,k}
============

\hat R_ko_i+\hat t_k.
]

所以：

[
\hat{\Delta o}_{i,k}
====================

(\hat R_k-I)o_i+\hat t_k.
]

这样 512-point ADE 仍然能算。

但它变成**evaluation metric**，而不是一个给网络制造 shortcut 的 decoder。

这比现在直接 MLP 回归 512 point flow 更符合数据物理结构。

# 13. Loss 也应该简化

第一版我甚至建议只用两个主要项。

### Global dynamics

[
L_{SE3} =

L_{translation}
+
\lambda_RL_{rotation}.
]

约束：

> 当前 interaction 最终使物体怎么运动。

---

### Local action-field preservation

不要再预测未来 (v_n/v_t)。

可以让 learned token reconstruct 一个**直接可计算的 local action descriptor**：

例如：

[
F_{k,j} =

[
\rho_{k,j},
\bar a^n_{k,j},
\bar a^t_{k,j}
]
]

其中：

[
\rho_{k,j}=\sum_iw_{kij}
]

表示附近有多少手部作用；

然后：

[
L_{field}
=========

|\hat F-F|^2.
]

甚至第一版更激进一点：

[
\boxed{\text{直接把 }F\text{ 本身作为 interaction representation 的一部分}}
]

这样 representation 根本不可能为了 SE(3) loss 又 collapse 成一个 global vector。

## 16. 另外一个很重要的工程决定

目前 `FrozenDenseToken` 可以继续作为 human branch 的辅助 prior。

但我不建议让最终：

[
C_m
]

强依赖 DenseToken。

因为以后 robot FK branch 未必有与 human DenseToken 完全等价的输入分布。

最终共享 interaction representation 最好主要依赖：

* surface xyz；
* normal；
* action trajectory；
* object geometry；
* relative geometry。

这些 human 和 robot 都有。

DenseToken 可以：

[
\text{training-time prior}
]

或者小 gate residual。

不要成为 representation 的必要输入。
