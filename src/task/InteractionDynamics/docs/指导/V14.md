# InteractionDynamics V14：预训练 Pose/ActionToken 回接交互动力学最小实现

## 0. 前提

执行本阶段前，认为以下两个模块已经完成独立预训练并导出 encoder checkpoint：

[
E_P:\ H_t^{root}\rightarrow(P_t,z_t)
]

其中：

[
P_t\in\mathbb R^{64\times384},\qquad
z_t\in\mathbb R^{128}
]

以及：

[

\rightarrow
A^{art}_{1:8}
]

其中：

[
A^{art}\in\mathbb R^{B\times8\times64\times384}.
]

本轮不再修改 PoseToken / ActionToken 的表示学习目标。

本轮只回答：

> 已经学好的详细动作表示，在读取当前 WorldToken 后，是否能够直接形成可预测物体动力学的交互表示？

# 51. 最终正式定义

Static Pose：

[
\boxed{
S_t
===

E_P(H_t^{root})
}
]

Dynamic articulation：

[
\boxed{
A_t^{art}
=

E_A(S_t,S_{t+1})
}
]

Root motion：

[
\boxed{
A_t^{root}
=

E_R(\Delta T_t^{root})
}
]

Raw Action：

[
\boxed{
A_t^{raw}
=

[
A_t^{root};
A_t^{art}
]
}
]

World：

[
\boxed{
W
=

E_W(H_t,O_t)
}
]

Interaction representation：

[
\boxed{
C_{m,t}
=

CrossAttn(
Q=A_t^{raw},
KV=W
)
}
]

严格说实现中 query 会额外加入当前 object-frame position embedding，但原始动作表示保持不变。

最后：

[
\boxed{
E_t
===

EffectQuery(C_{m,t})
}
]

[
\boxed{
E_t
\rightarrow
\Delta T_t^{obj}
}
]

这就是 V14 的完整最小实现。

# 52. 执行顺序

严格按照：

```text
1. 补 canonical action atlas 到 InteractionDynamics Dataset
2. 加载 Frozen PoseEncoder
3. 加载 Frozen ActionEncoder
4. 构造独立 RootToken
5. 拼成 A_raw
6. 逐 timestep A Q → W KV
7. 定义输出为 Cm
8. EffectQuery → object SE3
9. 32-chunk controlled overfit
10. Action intervention
11. small20
12. 通过后再考虑解冻 DynamicActionEncoder
```

在第 9、10 步通过前：

[
\boxed{
不要加 Slot，不要回到 I，不要进入多 embodiment。
}
]

这份方案还有一个关键点：当前 `InteractionDynamicsRunner` 会无条件计算旧 action/patch/relative/field 分支，因此 V14 最好加一个独立 `_step_v14()` 早返回，而不是为了兼容旧 Runner 给新模型伪造大量无意义输出。 这样改动最少，也最不容易破坏已有 V1–V13 实验。
