对。看了 Fast-WAM 的论文和官方训练代码后，可以比较确定地说：

[
\boxed{\text{Fast-WAM 没有专门设计 anti-collapse loss（防坍缩损失）}}
]

没有类似我们可能想到的：

[
L_{\text{variance}},\quad
L_{\text{diversity}},\quad
L_{\text{contrastive}}
]

也没有显式要求不同 token 之间 cosine similarity 变小。

它主要靠**训练任务本身的直接监督结构**避免 token 坍缩。这一点跟我们现在的 InteractionDynamics 差别非常大。

---

## 1. Fast-WAM 实际有两个直接监督

论文写得很明确：

[
\boxed{
L=L_{\text{act}}+\lambda L_{\text{vid}}
}
]

其中：

[
L_{\text{act}}
==============

L_{\text{FM}}(a_{1:H})
]

是动作 chunk 的 flow matching loss；

[
L_{\text{vid}}
==============

L_{\text{FM}}(z_{1:T})
]

是未来视频 latent 的 flow matching loss。这里 flow matching（流匹配）就是给加噪后的动作/视频 latent，直接预测对应的速度场。([arXiv][1])

官方代码也正是这么实现的：

```python
loss_total =
    loss_lambda_video * loss_video
    + loss_lambda_action * loss_action
```

而不是加一个额外的 diversity/collapse loss。

所以它确实有“别的监督”，而且这个别的监督非常关键：

[
\boxed{\text{Action supervision + Future Video supervision}}
]

---

# 2. 更关键的是：它的 action token 本身有逐 token GT

这和我们差异非常大。

假设 Fast-WAM action horizon：

[
H=32
]

那么它有：

[
a_1,a_2,\ldots,a_{32}
]

每一个动作位置都会被加噪：

[
a_t^{noise}
]

然后要求对应 token 输出自己的 flow-matching target。

官方代码先：

```python
noise_action = torch.randn_like(action)
noisy_action = scheduler.add_noise(...)
target_action = scheduler.training_target(...)
```

然后模型输出：

```python
pred_action
```

最后：

```python
action_loss_token =
    F.mse_loss(
        pred_action,
        target_action,
        reduction="none"
    ).mean(dim=2)
```

得到：

[
[B,T]
]

也就是**每一个时间 token 都有自己的直接误差**。

这非常重要。

如果：

[
a_1\neq a_2\neq a_3
]

但所有 action hidden token collapse 成：

[
h_1=h_2=h_3
]

那么最终基本不可能同时预测：

[
v_1,v_2,v_3
]

三个不同 target。

所以 loss 本身就给了很强的：

[
\boxed{\text{token differentiation pressure}}
]

也就是“不同 token 必须承担不同预测任务”的压力。

---

# 3. Video token 更是如此

未来视频也不是：

> 把所有视频 latent 压成一个 representation，再拿一个下游 loss 监督。

而是未来视频 latent 本身直接进行 flow matching：

[
z_{t,i}
\rightarrow
\hat v_{t,i}
]

其中既有：

* temporal dimension；
* spatial dimension。

论文直接定义：

[
L_{\text{vid}}
==============

\mathbb E
\left[
|f_\theta(z_t,t,o,l)-(\epsilon-z)|_2^2
\right].
]

([arXiv][1])

官方代码也是对整个：

```text
[B, C, T, H, W]
```

的视频预测逐位置计算 MSE，只在最后做 reduction。

所以如果一个场景里：

```text
左边杯子
右边机械臂
上面桌面
下面背景
```

对应的视频 latent 全部：

[
z_1=z_2=\cdots
]

那根本无法预测不同空间位置的未来 latent velocity。

所以视频建模本身就在强迫：

[
\boxed{
z_{t,x,y}
\text{ 保留 spatially-specific information}
}
]

即保留“这个时间、这个空间位置特有的信息”。

---

# 4. 这正是我们目前最大的区别

我们现在是：

[
(H,O,\Delta H_{1:8})
\rightarrow
{C_1,\ldots,C_{64}}
\rightarrow
\Delta O_{1:8}
]

但是：

[
C_1,\ldots,C_{64}
]

本身**完全没有直接 GT**。

只有最终：

[
\Delta O
]

有监督。

所以实际上允许这样一个 shortcut（捷径）：

[
C_1=C_2=\cdots=C_{64}=\bar C
]

只要 decoder 能够：

[
(\bar C,O_i)
\rightarrow
\Delta O_i
]

loss 就照样可以很低。

这也就是我们之前真实观察到的：

[
\boxed{\text{mean token replacement 几乎不改变预测}}
]

的原因。

---

# 5. Fast-WAM 没有这个自由度

粗略对应一下：

### Fast-WAM

```text
Action token 1 ──→ GT action velocity 1
Action token 2 ──→ GT action velocity 2
Action token 3 ──→ GT action velocity 3
...

Video token (t,x,y)
       ↓
GT video latent velocity (t,x,y)
```

每个位置都有任务。

而我们：

```text
Interaction token 1 ─┐
Interaction token 2 ─┤
Interaction token 3 ─┤
...                   ├→ decoder → object flow
Interaction token 64 ┘
```

只监督最后结果。

因此：

[
\boxed{
\text{我们的 interaction tokens 是 under-constrained latent}
}
]

under-constrained latent 就是：

> 中间表征受到的约束不够，很多不同甚至退化的 latent 都可以产生相同最终答案。

---

# 6. Fast-WAM 还有第二层防护：token 本身有位置身份

ActionDiT 并不是 permutation-invariant（置换不变，即交换 token 顺序还完全一样）。

Action token 有：

[
1,2,\ldots,H
]

明确的时序位置。

官方 ActionDiT 给 action sequence 使用 RoPE：

```python
freqs = self.freqs[:seq_len]
```

RoPE（Rotary Position Embedding，旋转位置编码）会让不同 action timestep 具有不同的位置身份。

所以：

[
a_1,\ a_2,\ a_3
]

既：

* 输入不同；
* 位置不同；
* GT 不同。

这三个条件一起抑制 collapse。

---

# 7. 第三层是 pretrained video backbone

Fast-WAM 不是从头学习 world representation。

它直接建立在 pretrained Wan2.2-5B video DiT 上，并使用 pretrained VAE 和 text encoder。论文明确把 Wan2.2-5B 作为 world modeling backbone。([arXiv][1])

而 action expert 的 backbone 官方训练流程也不是完全随机初始化，README 要求先从 Wan2.2 DiT 插值得到 ActionDiT backbone，再开始 Fast-WAM 训练。([GitHub][2])

所以初始状态下 video representation 本来就已经有很强的：

* spatial structure；
* temporal structure；
* semantic structure。

模型不是从：

[
z_1=z_2=\cdots=0
]

这种状态开始找 representation。

不过这只是辅助因素，**真正关键还是直接的 dense supervision（密集监督）**。

---

# 8. Attention mask 也有作用，但它不是 anti-collapse 机制

Fast-WAM 训练时：

* video → video；
* action → action；
* action → current first-frame video；
* action **不能看 future video**。

官方代码：

```text
video → video                    ✓
action → action                  ✓
action → first-frame video       ✓
action → future video            ✗
```

论文也明确强调这个 mask 防止未来信息泄漏。([arXiv][1])

它解决的是：

[
\boxed{\text{future leakage / shortcut}}
]

而不是：

[
\boxed{\text{representation collapse}}
]

这两个不要混在一起。

---

# 9. 这对我们非常有启发

我们之前说：

[
L=L_{\text{effect}}
]

先看看能不能学出来。

现在实验已经告诉我们：

> **只用 effect supervision 确实容易让 intermediate interaction representation 找捷径。**

而 Fast-WAM 的真正对应并不是：

[
C_m\rightarrow object\ flow
]

这一条。

Fast-WAM 更像：

[
\boxed{
\begin{aligned}
\text{Action branch} &\rightarrow \text{Action GT}\
\text{World branch} &\rightarrow \text{Future World GT}
\end{aligned}
}
]

然后两者通过 shared attention 交互。

所以如果我们想更严格地模仿 Fast-WAM，其实应该是：

[
A_{context}
]

不能只靠：

[
C\rightarrow\Delta O
]

间接监督。

应该再有一个：

[
\boxed{
A_{context}\rightarrow\Delta H_{1:8}
}
]

直接 action reconstruction / action flow supervision（动作重建监督）。

---

# 10. 我现在比较看好这个改法

保留现有主任务：

[
C_m + O
\rightarrow
\Delta O
]

即：

[
L_{\text{effect}}
]

同时在 canonicalization **之前**，对：

[
A_{context}
===========

{a_1,\ldots,a_{64}}
]

增加一个 hand action reconstruction head。

因为这 64 个 token 本身是 hand-patch indexed：

[
a_j
\leftrightarrow
hand\ patch_j
]

对应关系非常明确。

于是要求：

[
a_j
\rightarrow
\Delta H_j^{1:8}
]

即：

[
\boxed{
L_{\text{action}}
=================

\sum_{j=1}^{64}
|
D_A(a_j)
--------

\Delta H_j^{GT}
|^2
}
]

这样如果：

[
a_1=a_2=\cdots=a_{64}
]

但是食指、拇指、掌心的运动不同，就不可能把这个 loss 做低。

这和 Fast-WAM 的：

[
L_{\text{act}}
]

在思想上几乎完全对应。

---

# 11. 然后 interaction token 仍然由 object query 产生

完整结构就变成：

```text
                   Current World
                    H_t + O_t
                        ↓
                    World Expert
                        ↓
                   World Tokens
                        │
                        │
Hand Action Chunk      │
ΔH_1:8                 │
    ↓                   │
Action Expert           │
    ↓                   │
Action Context Tokens ←─┘
    │
    ├────────────→ Action Reconstruction
    │                     ↓
    │                 ΔH_1:8 GT
    │
    ▼
Object Patch Queries
    ↓
Interaction Tokens
    ↓
Effect Decoder
    ↓
ΔO_1:8 GT
```

训练：

[
\boxed{
L
=

L_{\text{effect}}
+
\lambda_{\text{action}}L_{\text{action}}
}
]

这就比现在单纯：

[
L=L_{\text{effect}}
]

更接近 Fast-WAM 的：

[
L=L_{\text{act}}+\lambda L_{\text{vid}}.
]

---

# 12. 但有一个细节：不要直接重建 1538×8 个 hand points

没必要。

因为我们最终需要的是 patch-level interaction。

可以把每个 hand patch 的 GT motion pooling 成：

[
\bar{\Delta h}_{j,k}
====================

\frac1{|P_j|}
\sum_{i\in P_j}
\Delta h_{i,k}
]

得到：

[
[64,8,3]
]

然后 action token (a_j) decode：

[
a_j
\rightarrow
[8,3]
]

这样 supervision 非常轻：

[
64\times8\times3
]

就足够明确告诉每个 token：

> 你必须记住自己这个 patch 怎么运动。

第一版甚至不用预测局部 deformation，只预测 patch center trajectory 就行。

## 所以回答你的问题

Fast-WAM **没有专门防坍缩的正则项**。

它之所以不像我们现在这么容易 collapse，最核心原因是：

[
\boxed{
\text{每个 action token 有直接 action flow target，}
\quad
\text{每个 video latent 有直接 future-video flow target。}
}
]

再加上：

[
\boxed{
\text{时空位置编码 + pretrained video backbone}
}
]

所以 token 如果全部变成一样，本身就会显著增加训练 loss。论文的训练目标就是：

[
\boxed{
L_{\text{Fast-WAM}}
===================

L_{\text{action FM}}
+
\lambda L_{\text{video FM}}
}
]

并没有额外的 diversity/variance/contrastive anti-collapse loss。([arXiv][1])

而我们现在是：

[
\boxed{
L_{\text{ours}}=L_{\text{object effect}}
}
]

所以 intermediate action/interaction latent 的自由度大得多。

**因此我现在会把“给 hand-indexed `action_context_tokens` 加一个 patch-motion reconstruction supervision”列为非常合理的下一步，而不是先加什么 cosine diversity loss。** 因为前者是在增加物理语义约束，后者只是人为要求 token 不一样。

[1]: https://arxiv.org/abs/2603.16666 "Fast-WAM: Do World Action Models Need Test-time Future Imagination?"
[2]: https://github.com/yuantianyuan01/FastWAM/blob/main/README_zh.md?utm_source=chatgpt.com "FastWAM/README_zh.md at main · yuantianyuan01/FastWAM · GitHub"
目前我建议：**World Tokens 暂时不要单独加监督。** 但要给最终的 object-indexed `interaction_tokens` 增加更直接的局部监督。原因是我们现在真正出问题的位置不在 World branch。

现在诊断里：

[
\text{world object token variance}\approx0.399,\qquad
\text{cosine}\approx0.713
]

World Tokens 本身其实有很好的空间差异；真正开始趋同的是 `action_context`，随后在 object canonicalization 处进一步坍缩。也就是说目前没有证据表明：

[
W_1\approx W_2\approx\cdots
]

相反，World branch 目前是比较健康的。

所以如果现在给 World Token 再加 reconstruction loss，容易把精力放错地方。

---

我们可以把 Fast-WAM 和我们重新严格对应一下。

Fast-WAM：

[
\text{Current/Future Video}
\rightarrow
\text{Video Expert}
\rightarrow
\hat v_{\text{video}}
]

视频分支确实有直接的 video flow-matching supervision；动作分支也有 action flow-matching supervision。

但我们这里的 World Token：

[
W=E_W(H_t,O_t)
]

表示的是**当前世界状态**，它不是我们真正想学的最终 dynamics representation。

我们最终真正关心的是：

[
\boxed{
C_j=\text{object patch }j\text{ 上的 interaction}
}
]

所以如果要借鉴 Fast-WAM，我认为正确的不是：

[
W_j\rightarrow O_t
]

去重建当前物体。

而应该是：

[
\boxed{
C_j\rightarrow \Delta O_{j,1:8}
}
]

也就是给每一个 object-indexed interaction token 一个直接的局部 future-effect target。

---

## 我现在建议形成三层监督

第一层：Action supervision。

我们上一条刚讨论的：

[
A_j\rightarrow \Delta H_{j,1:8}
]

这里 (A_j) 是 hand-patch-indexed action context token。

具体 GT 可以直接用 hand patch 中 32 个点的平均位移：

[
\bar{\Delta H}_{j,k}
====================

\frac1{32}
\sum_{i\in P_j}
\Delta h_{i,k}
]

于是：

[
L_{\text{action}}
=================

\frac1{64\times8}
\sum_{j,k}
\left|
\hat{\Delta H}_{j,k}
--------------------

\bar{\Delta H}_{j,k}
\right|^2
]

它约束：

> 第 (j) 个 hand action token 必须知道自己的手部区域怎么运动。

---

第二层：Interaction / object-patch supervision。

这一步我现在觉得尤其重要。

我们已经有 object FPS center：

[
o_j,\qquad j=1,\ldots,64
]

而 object point IDs 在整个 sequence 中是稳定的。

所以可以直接得到这个 object patch 的 GT future displacement：

[
\bar{\Delta O}_{j,k}
====================

\frac1{|P_j^O|}
\sum_{i\in P_j^O}
\Delta o_{i,k}
]

然后让：

[
\boxed{
C_j\rightarrow
[\bar{\Delta O}*{j,1},
...,
\bar{\Delta O}*{j,8}]
}
]

于是：

[
L_{\text{patch-effect}}
=======================

\frac1{64\times8}
\sum_{j,k}
\left|
D_C(C_j)*k-\bar{\Delta O}*{j,k}
\right|^2
]

这一项对我们现在的坍缩问题会非常直接。

因为如果：

[
C_1=C_2=\cdots=C_{64}
]

但是一个旋转物体上不同位置的点位移不同：

[
\Delta O_1\neq\Delta O_2
]

那么这个 loss 就不可能低。

---

### 举个最简单的旋转例子

假设物体绕 z 轴转：

```text
          ↑ ΔO_left

     ●-----------●
   left          right

                    ↓ ΔO_right
```

左右两个 object patch 的 displacement 完全不同。

所以：

[
C_{\text{left}}
]

和：

[
C_{\text{right}}
]

必须保留不同信息。

这比我们现在只是：

```text
64 interaction tokens
        ↓
512 queries cross-attention
        ↓
object point flow
```

要强很多。

因为目前 decoder 可以自己利用：

[
O_i
]

的位置算：

[
\Delta O_i
]

于是 interaction 只需要提供一个 global rigid transform，就会出现 shortcut。

但加：

[
C_j\rightarrow\Delta O_j
]

以后，object-indexed token 自己就必须承担局部预测责任。

---

第三层才是现在已有的 dense effect supervision：

[
C_{1:64}
+
512\ object\ queries
\rightarrow
\Delta O_{1:8}^{512}
]

保留：

[
L_{\text{effect}}
]

因为最终我们还是希望 point-level prediction 精确。

---

# 所以最终我更看好的 loss 是

[
\boxed{
L
=

L_{\text{effect}}
+
\lambda_A L_{\text{action}}
+
\lambda_C L_{\text{patch-effect}}
}
]

第一版先简单：

[
\lambda_A=1
]

[
\lambda_C=1
]

主 effect loss：

[
\lambda_{\text{effect}}=1
]

不要现在花精力调十几个权重。

这三项分别对应：

```text
Hand patch action token
        ↓
“我这块手怎么动”
        ↓
L_action


Object interaction token
        ↓
“我这块物体怎么动”
        ↓
L_patch-effect


Full interaction representation
        ↓
512 object point trajectories
        ↓
L_effect
```

## 那 World Token 到底承担什么？

World Token：

[
W_H,W_O
]

我更愿意把它看成**condition/context（条件和上下文）**，而不是必须自己成为预测目标的 representation。

它负责告诉 Action：

> 手现在在哪里、物体是什么形状、手与物体如何排列。

然后：

[
A
\overset{W}{\longrightarrow}
A_{\text{context}}
]

再：

[
W_O
\overset{A_{\text{context}}}{\longrightarrow}
C
]

所以 World 的主要职责是提供几何 context。

而且它还有 Uni3D pretrained prior，所以没有必要第一时间再强迫：

[
W\rightarrow\text{reconstruct current point cloud}
]

这种任务。

---

# 为什么我不推荐 current-world reconstruction

比如加：

[
W_O\rightarrow O_t
]

看起来能保护 World Token。

但它有个明显的问题：

我们的目标是 interaction dynamics：

[
\text{Hand Action}
\rightarrow
\text{Object Effect}
]

而 current object reconstruction 主要逼网络记：

* 杯子形状；
* 盒子形状；
* 几何表面；

未必帮助：

* 谁在接触；
* 哪里受力；
* 怎么运动。

甚至可能让 object geometry 在 latent 中占比过大。

最后：

[
C_j
]

更像 object appearance/geometry token，而不是 interaction token。

所以暂时不要。

---

# 如果以后 World branch 真出问题，再加什么？

如果后面发现：

[
W_O
]

跨 sequence 也开始 collapse，或者 fine-tune Uni3D 后 pretrained geometry 被破坏，那么我不会优先加 point reconstruction，而是考虑一个轻量的 geometry preservation target。

例如 frozen pretrained Uni3D teacher：

[
W_O^{teacher}
]

当前 trainable Uni3D：

[
W_O^{student}
]

加：

[
L_{\text{world-distill}}
========================

|W_O^{student}-W_O^{teacher}|^2
]

这叫 distillation（蒸馏：用冻结的原模型输出约束新模型别偏得太远）。

但目前也没必要。

---

## 因此我会把下一版结构定成

```text
                         Current World
                           H_t + O_t
                               ↓
                            Uni3D
                               ↓
                         World Tokens
                               │
                     ┌─────────┴─────────┐
                     │                   │
                     ▼                   │
Hand Action Chunk → Action Context       │
                     │                   │
                     ├──→ ΔH patch GT    │
                     │     L_action      │
                     │                   │
                     ▼                   │
              Object Canonicalization ←──┘
                     ↓
              Interaction Tokens C_j
                     │
              ┌──────┴─────────┐
              │                │
              ▼                ▼
        ΔO patch GT       512 point queries
     L_patch-effect             ↓
                           ΔO point GT
                            L_effect
```

我认为这比给 World Token 加 reconstruction loss更准确地吸收了 Fast-WAM 的思想：

[
\boxed{
\text{关键中间 token 都有与其语义对应的直接预测任务。}
}
]

所以我的结论很明确：

[
\boxed{\text{现在不额外监督 World Tokens。}}
]

先加：

[
\boxed{L_{\text{action}}}
]

以及我现在认为很值得一起加的：

[
\boxed{L_{\text{patch-effect}}}
]

尤其后者是直接针对我们当前 **object-indexed interaction token 坍缩** 的，比 variance/cosine regularization 更有物理意义。
