## 1. H 就定义成这个

当前 MANO 已经使用：

* `hand_pose`: 24 PCA coefficients；
* `global_orient`: 3；
* `transl`: 3；
* `betas` 固定。

仓库现有 `inverse_mano.py` 就是这套参数化。

但不要直接预测 world-frame 的 `global_orient/transl`。用 object-centric wrist state：

[
H_t=
\left[
p^O_t,;
R^O_t,;
\theta_t
\right]
]

当前 condition 用：

[
p^O_t\in\mathbb R^3,\qquad
R^O_t\in SO(3),\qquad
\theta_t\in\mathbb R^{24}.
]

旋转 condition 可以编码成 6D，所以：

[
H_t^{cond}\in\mathbb R^{3+6+24}=33.
]

真正预测的 target 不用 absolute (H)，而是：

[
\boxed{
\Delta H_{t\rightarrow t+k}
===========================

[
\Delta p_k^O,
\Delta\omega_k^O,
\Delta\theta_k
]
}
]

其中：

[
\Delta p_k^O=p_{t+k}^O-p_t^O
]

[
\Delta R_k^O=R_{t+k}^O(R_t^O)^{-1}
]

把 (\Delta R) 转为 3D rotation vector：

[
\Delta\omega_k^O=\log(\Delta R_k^O)\in\mathbb R^3
]

以及：

[
\Delta\theta_k=\theta_{t+k}-\theta_t.
]

因此每个未来 timestep：

[
\boxed{3+3+24=30D}
]

8 步就是：

[
\boxed{\Delta H\in\mathbb R^{8\times30}}
]

而不是当前自由生成的：

[
Y\in\mathbb R^{128\times8\times7}.
]

---

# 2. 为什么 object frame 很重要

V18 已经把手和物体都放到了动态 object-centric reference frame，通过刚体 SVD 从每帧 object points 恢复 frame。

所以 (H) 也沿用同一个 frame。

这样模型学的是：

> 手相对于物体怎么移动。

而不是：

> 杯子在世界坐标 ((1.2,0.4,0.8)) 时 MANO translation 是多少。

也避免重新引入绝对 world pose 的泛化问题。

# 5. 第一版模型不要 Diffusion

新建：

```text
mano_hand_transition.py
```

结构可以最大程度复用 V18。

当前 V18 已经有：

```python
state encoder
anchor encoder
object patch encoder
AdaLN blocks
```

只是最后对每个 object anchor 输出：

[
7H=56D.
]

我们改成：

```text
current Y + object geometry
          ↓
anchor tokens
          ↓
Transformer/AdaLN blocks
          ↓
global pool
          +
current H embedding
          ↓
MLP
          ↓
[8, 30] ΔH
```

概念上：

```python
tokens = (
    state_encoder(state)
    + anchor_encoder(anchors)
    + object_encoder(patches).amax(2)
)

condition = current_h_encoder(current_h)

for block in blocks:
    tokens = block(tokens, condition)

global_token = tokens.mean(dim=1)

pred_delta_h = head(
    torch.cat([global_token, condition], dim=-1)
).reshape(B, 8, 30)
```

就够了。

**不要 ActionToken。**

# 6. 第一轮训练 loss 只用 H

先不要训练时 MANO forward。

原因是我们现在只想验证：

[
(Y_t,O,H_t)
\rightarrow
\Delta H
]

到底可不可以学。

对 train split 的 `future_delta_h` 做 train-only normalization：

[
\tilde{\Delta H}
================

\frac{\Delta H-\mu_H}{\sigma_H}.
]

然后：

[
\boxed{
L_H=
|\hat{\Delta H}*{norm}-\Delta H*{norm}^{GT}|^2
}
]

这样 translation / rotation / MANO PCA 三种尺度不用手工配权重。

第一版不要：

```text
Y loss
contact loss
smooth loss
cone loss
ActionToken loss
MANO inverse loss
```

全部不加。

否则一旦失败没办法定位。

---

# 7. 预测出来以后再 MANO forward

Inference：

[
\hat{\Delta H}
]

还原：

[
\hat p_k^O=p_t^O+\Delta\hat p_k^O
]

[
\hat R_k^O=
\exp(\Delta\hat\omega_k^O)R_t^O
]

[
\hat\theta_k=
\theta_t+\Delta\hat\theta_k.
]

得到：

[
\hat H_{t+1:t+8}.
]

然后：

[
\boxed{
\hat H
\xrightarrow{\text{MANO forward}}
\hat P_{\rm hand}
\xrightarrow{\Phi}
\hat Y
}
]

这里完全没有 optimization。

# 8. 这一版最重要的评价指标不是 H-MSE

真正比较：

### H-space

报告：

[
RMSE_{\Delta p}
]

[
RMSE_{\Delta R}
]

[
RMSE_{\Delta\theta}
]

这里只用于诊断。

### Y-space

重点报告与 V18 完全一致的：

[
RMSE_r,\quad RMSE_d,\quad RMSE_u
]

以及：

* stable success；
* terminal contact distribution；
* contact F1；
* formation / transition / maintenance。

### Realizability

这里就不需要 MANO inverse：

[
\boxed{
\hat Y=\Phi(\hat H,O)
}
]

天然来自 MANO。

所以必然：

[
|r|\le d.
]

更重要的是它还天然满足：

[
\boxed{
\text{128 anchors 来自同一只 MANO hand}
}
]

这才是 V18.3 的 cone constraint 无法解决的部分。

# 9. 实验只分两个 Gate

## Gate 1：controlled32 overfit

先拿现有 32 samples。

目标不是论文数字，只检查：

[
\Delta H\text{ 能否被拟合}
]

以及：

[
\hat H\rightarrow\hat Y
]

是否能逼近 GT interaction。

如果 32 samples 都拟合不好：

> H parameterization / normalization / network 有 bug。

不要 full train。

---

## Gate 2：完整 V18 full-data

controlled32 通过后直接同样：

[
16357/2035/2035
]

训练。

与 **epoch40 V18** 正面对比：

| 指标                  | V18 free-Y |              MANO-H |
| ------------------- | ---------: | ------------------: |
| overall Y RMSE      |            |                     |
| formation Y RMSE    |            |                     |
| stable success      |            |                     |
| contact F1          |            |                     |
| contact calibration |            |                     |
| (r/d) violation     |       ~30% |              **0%** |
| MANO realizable     |          差 | **by construction** |

最重要的问题就是：

[
\boxed{
\text{用 realizability 换来的代价到底是多少？}
}
]

例如如果：

```text
V18 Y RMSE   0.97 cm
H model      1.05 cm
```

但 H model：

* 100% MANO-realizable；
* contact 接近；
* formation 保留；

那我会认为 H 方案非常值得继续。

反之如果：

```text
H model Y RMSE 3 cm
formation 基本没了
```

说明直接 MANO regression 太强地退化成 conditional mean，下一步才需要：

[
\boxed{\text{H-space Diffusion}}
]

来恢复 multimodality（多模态，即同一当前状态对应多个合理抓法）。

---

# 10. 这一步先不要做 H-space Diffusion 的原因

因为 deterministic regression 本身就能回答三个非常基础的问题：

1. (H) 数据链是否正确？
2. (H\rightarrow Y) 是否能保留 interaction？
3. full-data 下 (H) 是否至少具有可学习性？

如果这三个都没过：

[
\text{Diffusion}
]

没有意义。

如果 deterministic 结果出现典型平均化：

[
\text{RMSE 尚可，但 formation/contact 模糊}
]

那正好说明：

[
p(H_{future}|Y_t,O,H_t)
]

确实需要 Diffusion。

- grasp_interaction_diffusion.py
- interaction_field.py
- inverse_mano.py
- research/log.md
- V18/V18.1/V18.2/V18.3

不要修改旧 V18/V18.1/V18.2/V18.3 实现和 cache。
新建独立 V18.4。

第一版禁止：
- ActionToken
- diffusion
- learned latent
- cone penalty
- MANO inverse optimization
- 训练时复杂 Y/contact auxiliary loss

只做 deterministic MANO-H residual regression。

H 定义：
当前 condition：
H_t = [object-frame wrist translation(3),
       object-frame wrist rotation 6D(6),
       MANO PCA hand_pose(24)]
共 33D。

future target 每步：
ΔH_k = [
  object-frame wrist translation residual Δp(3),
  relative rotation log Δω(3),
  MANO PCA pose residual Δtheta(24)
]
共 30D，H=8，因此 target [8,30]。

object frame 必须与 V18 sequence_interaction 使用的动态刚体 object frame 完全一致，
不要重新定义另一套坐标系。

Gate 0：
先验证 GT MANO H -> MANO surface -> build_interaction_y

模型：
复用 V18 的 state/object/anchor encoder 和 transformer 风格，

anchor tokens 编码后 global pool，
current H 做 global condition，
最终 MLP 输出 [B,8,30]。
不要增加 ActionToken。

训练：
future_delta_h 用 train-only mean/std 标准化，
仅优化 normalized H residual MSE。
不要第一轮加入 Y/contact/smoothness auxiliary。

Gate 1：
controlled32 overfit。

第一版 deterministic H regression 如果出现明显 multimodal averaging，

只做保证数值可信所需的 sanity checks。
更新 research/log.md：
