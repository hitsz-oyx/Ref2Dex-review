我建议把这一版定义成 **V20.3：Direct-H Parallel Baseline**。它不是马上做复杂双分支联合训练，而是先把关键科学问题单独验证清楚：

[
\boxed{
\text{V20.2 泛化失败，到底因为 }H\text{ 难预测，还是因为 }Y\rightarrow H\text{ 这个 inverse mapping 太难？}
}
]

这里 inverse mapping 指“反问题”：从 interaction field 反推出具体手构型。

---

# 1. V20.3 的核心结构

现有 V20：

[
X=(Y_t,O)
\rightarrow
\hat Y_{1:H}
]

保持完全不动。

新增一个**独立的 Direct-H predictor**：

[
\boxed{
X_H=(Y_t,O,H_t)
\rightarrow
\Delta H_{1:H}
\rightarrow
MANO
\rightarrow
Y_H
}
]

注意它**不读取 predicted future Y**。

即：

```text
                         ┌──────── FieldDynamics ───────→ Y_pred
                         │
current Y + object ──────┤
                         │
                         └──────── Direct-H ────────────→ ΔH
                               ↑                         │
                           current H                    MANO
                                                         │
                                                         ▼
                                                        Y_H
```

这时候：

* `Y_pred`：高带宽 free interaction prediction；
* `H`：直接从当前状态预测出来的可实现手；
* 不存在：
  [
  Y_{\rm pred}\rightarrow H
  ]
  这一步。

---

# 2. 第一阶段不要让两条路发生任何交互

这点非常重要。

V20.3 第一版应该是一个**纯 baseline experiment**：

### Branch A

现有：

[
X\rightarrow Y.
]

### Branch B

新建：

[
X,H_t\rightarrow H\rightarrow Y_H.
]

两边：

* 不共享训练 loss；
* 不做 consistency；
* 不互相蒸馏；
* 不联合更新；
* 不共享 hidden features。

这样实验结果才能回答问题。

否则如果两边一开始就联合，我们又不知道 improvement 到底来自哪里。

[

# 4. Direct-H architecture

新增：

```text
direct_h_dynamics_v20_3.py
```

我建议继续采用 spatial token + temporal queries，不用一个 global mean vector。

先构造当前 spatial tokens：

[
S_i=
E_Y(Y_{t,i})
+
E_A(o_i)
+
E_O(P_i).
]

形状：

[
S\in\mathbb R^{B\times N\times D}.
]

然后：

[
e_H=E_H(H_t).
]

使用 8 个未来时间 query：

[
q_1,\dots,q_8.
]

每一个：

[
q_k'=q_k+e_H
]

对同一组当前 spatial tokens 做 cross-attention：

[
G_k=
\operatorname{CrossAttn}
(q_k',S,S).
]

于是：

[
G\in\mathbb R^{B\times8\times D}.
]

最后 temporal Transformer：

[
G_{1:8}
\rightarrow
\tilde G_{1:8}
\rightarrow
z_H
\in\mathbb R^{B\times8\times30}.
]

---

# 5. 为什么这一版仍然不用 global bottleneck

虽然：

[
G_k\in R^D
]

最终每个时间点是一个全局表示，但注意它只负责：

[
H_k.
]

而不是：

[
Y_{1:N,k}.
]

所以这个压缩是合理的：

> H 本身就是一只手的全局参数。

我们真正反对的是：

[
[N,D]
\rightarrow H
\rightarrow
[N,8]
]

成为 **Y 的唯一数据路径**。

现在不是这样。

# 6. 具体模型可以直接这么写

```python
class DirectHDynamicsV20_3(nn.Module):
    def __init__(
        self,
        horizon=8,
        y_dim=8,
        dim=192,
        heads=4,
        temporal_layers=2,
    ):
        super().__init__()

        self.horizon = horizon

        self.y_encoder = nn.Sequential(
            nn.Linear(y_dim, dim),
            nn.GELU(),
            nn.Linear(dim, dim),
        )

        self.anchor_encoder = nn.Sequential(
            nn.Linear(3, dim),
            nn.GELU(),
            nn.Linear(dim, dim),
        )

        self.object_encoder = nn.Sequential(
            nn.Linear(6, dim),
            nn.GELU(),
            nn.Linear(dim, dim),
        )

        self.h_encoder = nn.Sequential(
            nn.Linear(33, dim),
            nn.GELU(),
            nn.Linear(dim, dim),
        )

        self.queries = nn.Parameter(
            torch.randn(1, horizon, dim) * 0.02
        )

        self.cross_attn = nn.MultiheadAttention(
            dim,
            heads,
            batch_first=True,
        )

        layer = nn.TransformerEncoderLayer(
            d_model=dim,
            nhead=heads,
            dim_feedforward=4 * dim,
            batch_first=True,
            norm_first=True,
            activation="gelu",
        )

        self.temporal = nn.TransformerEncoder(
            layer,
            temporal_layers,
            nn.LayerNorm(dim),
        )

        self.output = nn.Linear(dim, 30)

        nn.init.zeros_(self.output.weight)
        nn.init.zeros_(self.output.bias)

    def forward(
        self,
        current_y,
        anchors_cm,
        object_patches,
        current_h,
    ):
        spatial = (
            self.y_encoder(current_y)
            + self.anchor_encoder(anchors_cm)
            + self.object_encoder(object_patches).amax(2)
        )

        query = (
            self.queries.expand(len(current_y), -1, -1)
            + self.h_encoder(current_h)[:, None]
        )

        future, _ = self.cross_attn(
            query,
            spatial,
            spatial,
            need_weights=False,
        )

        future = self.temporal(future)

        return self.output(future)
```

这和 V20.2 realizer capacity 可以保持非常接近，方便公平比较。

# 15. 结果如何解释会非常清楚

### 情况 A

如果：

[
E_Y<E_{directH}\ll E_{Y\rightarrow H}
]

那么基本支持我们的猜测：

[
\boxed{
H\text{ 本身不是主要问题，主要问题是 }Y\rightarrow H\text{ inverse mapping}
}
]

这时应该放弃后置 realizer。

---

### 情况 B

如果：

[
E_Y\ll E_{directH}\approx E_{Y\rightarrow H},
]

说明真正的问题是：

[
\boxed{
H\text{ deterministic generation 本身泛化困难}
}
]

可能需要：

* stochastic H；
* flow/diffusion；
* 更强 temporal context。

---

### 情况 C

如果：

[
E_{directH}\approx E_Y,
]

那会很有意思。

说明我们之前担心的：

[
30D\ H
]

瓶颈可能并没有实际造成太大损失。

那么最简单的 solution 反而可能就是：

[
X\rightarrow H\rightarrow Y.
]

这时没必要为了“理论上的高带宽”强行保留复杂结构。
