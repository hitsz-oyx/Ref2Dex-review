[

## 1. 数据和 4 卡训练本身做得没什么问题

这次发现旧 manifest 有 25 个 dominant-hand 文件，但实际上只来自 20 个 demonstration。Codex 没有按 hand 文件直接切分，而是按 `path.parent` 把同一个 demonstration 的左右手放在同一个 split，最终：

[
16/2/2
]

个 demonstration 对应 train/val/test。

合法 chunk：

[
7909/1471/1159.
]

所以没有明显的 sequence leakage（序列泄漏：同一演示同时出现在训练和测试）。

而且确实保留了完整 frame：

```python
self.samples.extend(
    (path, frame)
    for frame in range(len(poses) - max(8, horizon))
)
```

没有重新只筛 contact、dynamic 或近场。

这点符合我们 V17 的设计。

# 2. Batch size 压测也做了，而且空间其实非常富余

单卡 BF16：

* batch 8～768 都能跑；
* batch 1024 才 OOM；
* batch 512 reserved memory ≈ 12.53 GB；
* batch 768 ≈ 18.73 GB；
* 吞吐到这里已经接近饱和。

随后真实 4 卡短训练比较了：

* global batch 128；
* global batch 256；
* LR (1e-4/2e-4)。

最后选：

[
\boxed{
B_{\rm gpu}=64
}
]

4 卡：

[
\boxed{
B_{\rm global}=256
}
]

以及：

[
LR=2\times10^{-4}.
]

所以虽然显存还能塞更大 batch，但 **256 是根据短优化结果选出来的，不是因为显存只能到这里**。

我觉得这个选择合理。

现在没必要再尝试：

[
B=512,\ 1024,\ 2048
]

来救 V17。

# 7. 我现在认为 Active 的语义在 full-data 下可能出了问题

我们以前在 `cup_lift` 单序列中定义：

> 从开始持续 approach 就算 active。

这个思想本身没错。

但现在：

[
96%\text{ frames active}
]

说明自动算法实际上可能把：

```text
几乎整个 demonstration
```

都包进了 active interval。

于是：

[
a_t
]

从：

> “当前是否应该参与这个物体”

退化成：

> “这整段录像反正最终会操作这个物体。”

那它就几乎没用了。

甚至可能形成错误 shortcut：

[
a=1
\Rightarrow
\text{模型倾向输出更大的 residual}.
]

所以把 active 设 0 后，模型变得更接近：

[
R=0
]

反而靠近 persistence，于是测试误差下降。

# 8. 这里还有一个非常值得注意的数字：Residual 是重尾的

Train residual RMS：

[
\text{median}=0.287\text{ cm}
]

但是：

[
\text{mean}=1.396\text{ cm}
]

[
p90=5.729\text{ cm}.
]

这差距很大：

[
0.287
\quad vs\quad
1.396.
]

说明 residual distribution（残差分布）有明显 heavy tail。

**Heavy tail，中文就是少量样本变化特别大，把均值拉得很高。**

而我们现在训练用普通 MSE：

[
L=|\hat R-R|^2.
]

平方误差对大 residual 极其敏感。

比如：

[
0.3^2=0.09
]

但：

[
6^2=36.
]

一个 6 cm residual 的 loss 权重相当于大量普通 frame。

所以即使我们没有做“dynamic balancing”，**MSE 本身已经在隐式强烈强调大动态样本。**

这可能导致模型形成：

[
\boxed{\text{系统性过预测 interaction change}}
]

然后 persistence 反而泛化更好。

这和：

[
active=0
]

之后性能改善是相互吻合的。

# 11. 这让我开始重新审视我们现在的 Goal

目前：

[
G=
[active,\text{next meaningful object }\Delta T].
]

在单个 `cup_lift` 里面非常合理。

但 full dataset 可能存在：

```text
当前 object 未来都要 +z

Demonstration A:
从左侧伸手抓

Demonstration B:
从右侧伸手抓

Demonstration C:
抓杯把

Demonstration D:
从杯身抓
```

它们可能拥有相似：

[
S,O,\Delta T
]

但下一步：

[
R
]

差很多。

对于 Diffusion，这本来可以建模多模态。

可是 deterministic 也被一起训练，而且 validation 直接输 persistence，说明 conditional mapping 本身已经非常困难。

# 12. 还有时间语义问题

现在 `extract_goal()` 是找：

[
k^*=\text{未来最近 meaningful object motion}
]

但不编码：

[
\boxed{k^*-t}
]

也就是：

> **距离真正要让物体运动，还有多久？**

这是我目前非常怀疑的一点。

例如两个完全相同的：

[
G=\text{向上 lift}
]

可能分别是：

```text
A:
20 帧后物体开始 lift

B:
200 帧后物体才开始 lift
```

当前 Goal 对网络来说：

[
G_A\approx G_B.
]

但 hand 下一步应该完全不一样：

A：

> 已经接近，要准备形成抓取。

B：

> 可能还在很远的位置慢慢 approach。

所以：

[
\boxed{
\text{next meaningful }\Delta T
}
]

告诉了：

> **以后要干什么**

但可能没有告诉：

> **现在离那个事情还有多远。**

单序列 controlled experiment 中时间进程可以从 (S_t) 被“记住”。

跨 sequence 后，这个 shortcut 消失，于是问题暴露出来。

---

# 13. 所以我现在最想做的不是再训练一遍

我会先做三个非常小的 V17.1 diagnostic。

不改模型。

第一，统计：

[
\boxed{
\tau_t=k^*(t)-t
}
]

也就是 **time-to-effect（距离目标物体真正开始运动还有多少帧）**。

看：

[
(S,O,G)
]

相似时：

[
\tau
]

是不是变化很大。

---

第二，把 Test 按：

```text
time_to_effect:
0–10 frames
10–30
30–100
>100
```

分别计算：

[
r/d.
]

如果：

[
\tau>100
]

的误差明显最大，那么基本就抓到问题了。

---

第三，先不要加到模型。

做一个 deterministic regression：

[
\boxed{
R=f(S,O,G,\tau)
}
]

只加一个标量：

[
\tau
]

或者归一化：

[
\log(1+\tau).
]

如果它在 sequence-disjoint val 上明显超过：

[
f(S,O,G)
]

那我们就获得非常清晰的证据：

[
\boxed{\text{Goal 缺的是“什么时候发生”，而不是“发生什么”。}}
]

## 当前我对 V17 的判断

工程部分其实做得很好：

[
\boxed{\text{4卡 DDP 没问题}}
]

[
\boxed{\text{batch=256 没明显问题}}
]

[
\boxed{\text{full-frame 数据链没明显问题}}
]

[
\boxed{\text{sequence split 没泄漏}}
]

真正研究问题已经暴露出来：

[
\boxed{
\text{单序列中成立的 }(S,O,G)\rightarrow R
\text{ 并没有跨 demonstration 成立。}
}
]

其中我现在优先怀疑两个点：

[
\boxed{\text{① active 几乎恒为 1，已经失去控制意义}}
]

和

[
\boxed{\text{② Goal 只有“下一步想让物体怎么动”，没有“多久以后要动”。}}
]

其次才是：

[
\boxed{\text{③ residual heavy-tail + MSE 导致模型偏向大变化}}
]

我建议下一步不要碰 Diffusion，也不要删 approach 数据，先围绕这三个假设做最小诊断。
