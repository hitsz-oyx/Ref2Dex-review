InteractionDynamics V1 全流程设计文档

一、项目命名与总体目标

新任务统一命名为：

InteractionDynamics

代码主目录：

src/task/InteractionDynamics

新数据缓存目录：

data/processed_data/interaction_dynamics_v1/data/grab

新任务不再使用 Cm 作为文件夹名、类名或主要变量名前缀。

原来的 Cm 继续完整保留：

src/task/Cm

它作为旧实验基线，不进行破坏性修改。

新模型内部原来称为 Cm 的核心表征统一改名为：

interaction_tokens

论文层面以后仍然可以讨论是否继续使用 C_m 这个数学符号，但代码层面 V1 不再使用 Cm，避免新旧架构混淆。

二、V1 要解决的核心问题

InteractionDynamics V1 只解决下面这条完整链路：

当前手物状态
H_t + O_t

加上

未来一小段人手动作
H_t → H_t+1 → ... → H_t+8

经过 InteractionDynamics Encoder 后得到：

interaction_tokens

再由 interaction_tokens 预测：

O_t → O_t+1 → ... → O_t+8

也就是：

Current World + Hand Action Chunk
→ Interaction Representation
→ Object Effect Chunk

具体定义为：

World_t = (H_t, O_t)

ActionChunk_t = {ΔH_1, ΔH_2, ..., ΔH_8}

其中：

ΔH_k = H_t+k - H_t

最终：

interaction_tokens = Encoder(H_t, O_t, ΔH_1:8)

物体监督：

ΔO_k = O_t+k - O_t

EffectDecoder(interaction_tokens, O_t)
→ {ΔÔ_1, ..., ΔÔ_8}

训练目标是：

预测整段物体点运动，而不是只预测一个 endpoint。

三、V1 明确不做的事情

为了保证第一版能够尽快跑通，以下内容明确不进入 V1：

不训练机器人动作 Decoder。

不建立 Human-Robot 配对训练集。

不训练 Allegro、LEAP、Shadow 等机器人数据。

不使用 Slot Attention。

不使用 Hard-Concrete gate。

不使用 L0 sparsity loss。

不使用随机 temporal stride。

不使用 scalar delta_time_s 作为模型条件。

不做 384 local + 128 global 的 effect query 混合采样。

不加入额外 action reconstruction loss。

不加入 contrastive human-robot alignment loss。

不直接优化机器人关节轨迹。

V1 最终做到 MANO self-inverse optimization，也就是：

GRAB MANO action
→ interaction_tokens
→ 反向优化另一条 MANO trajectory
→ 验证是否能够恢复原始动作。

只有这个实验成功以后才进入机器人阶段。

四、为什么不在旧 Cm 上继续修改

旧 Cm 的核心模型目前是：

DenseToken

* 当前 hand geometry
* 单个 endpoint hand_flow
  → Slot Attention
  → sparse Cm slots
  → object flow

而 delta_time_s 只是可选的时间条件，核心仍然是 endpoint flow。

新的 InteractionDynamics 已经在三个方面发生结构性变化：

第一，从 endpoint motion 变成 action chunk。

第二，从 Slot bottleneck 变成 Uni3D patch tokens + action/world attention。

第三，从自由 Slot token 变成 object-patch-indexed interaction tokens。

因此不要在 src/task/Cm/src/model.py 上继续叠代码。

新建独立目录更安全，也方便后面做旧 Cm vs InteractionDynamics 的直接对比。

九、时间采样参数固定

V1 固定：

source FPS = 120 Hz

ds_rate = 4

因此：

effective FPS = 30 Hz

chunk_len = 8

temporal_stride = 1

因此一个训练样本包含：

t
t+1
t+2
t+3
t+4
t+5
t+6
t+7
t+8

一共有 9 个状态。

其中：

t 是 current world。

后面 8 个状态组成 future chunk。

总时间跨度：

8 / 30 = 0.2667 s

V1 不随机 temporal_stride。

代码里保留 temporal_stride 这个配置字段，但 grab_v1.yaml 固定为：

temporal_stride: 1

训练阶段不进行随机选择。

十、合法 chunk 的定义

对于一个 sequence 长度 T：

current frame t 必须满足：

t + chunk_len × temporal_stride < T

V1 即：

t + 8 < T

Dataset 初始化时预先建立全部合法的：

(hand_path, current_frame)

索引。

训练 DataLoader 使用 shuffle=True。

因此不是 **getitem** 内部随机产生 t，而是：

Dataset 枚举所有合法 t，
DataLoader 随机打乱这些 chunk 的训练顺序。

这样更可复现。

十一、单手数据筛选

V1 仍然只训练 dominant hand。

不把左右手同时作为 action source。

原因是当前模型设计的是：

一个 hand action chunk
→ 一个 object effect chunk。

如果左右手同时对物体施力，却只输入其中一只手，会产生严重的因果标签噪声。

新建：

process/GRAB/build_interaction_dynamics_manifest.py

这个脚本不重新设计 dominant-hand algorithm，而是复用现在已有 dominant-hand filter 的逻辑。

旧 filter 已经会基于：

当前 5 cm 接触区域，
hand flow，
object flow，
左右手 coupling error

判断 unilateral、bilateral dominant、bilateral cooperation 和 ambiguous 情况。

V1 只生成：

stride = 8

这一种 manifest row。

原因是当前 chunk：

K = 8
temporal_stride = 1

其 endpoint 正好是：

t+8。

最终 manifest 中每个样本固定：

hand_path
current_frame
dominant_side
stride = 8

Dataset 只接受这份 manifest 中 decision=keep 的样本。

旧的 multi-stride dominant manifest 不直接作为 V1 训练输入。

十二、一个 Dataset sample 的完整构造

给定：

current = t

frames 为：

[t, t+1, ..., t+8]

先读取完整 world-frame 数据。

然后构造三套不同用途的表示：

A. World Expert 用 object-relative representation。

B. Action Expert 用 current hand-root representation。

C. DenseToken 使用旧 checkpoint 原本的 hand-root representation。

这就是我们前面确定的 Hybrid frame 方案。

十三、World Expert 的坐标系

定义当前 object pose：

T_WO(t)

表示 object frame → world frame。

求逆：

T_OW(t) = inverse(T_WO(t))

当前 object points：

O_t^O = T_OW(t) O_t^W

当前 hand points：

H_t^O = T_OW(t) H_t^W

object normal：

N_O^O = R_OW(t) N_O^W

hand normal：

N_H^O = R_OW(t) N_H^W

World Expert 只接收：

当前帧 t。

绝对不能接收：

H_t+1:t+8

或：

O_t+1:t+8。

因此：

WorldExpert input =
H_t^O + O_t^O

这是整个模型防止 future leakage 的第一条硬约束。

十四、Action Expert 的坐标系

定义当前 hand root：

T_WH(t)

求逆：

T_HW(t)

整个未来 hand chunk 都投影到当前 t 的 hand frame。

当前手：

H_0^H = T_HW(t) H_t^W

第 k 帧：

H_k^H = T_HW(t) H_t+k^W

注意：

这里始终使用当前时刻 t 的 T_HW(t)。

绝对不能分别使用未来 hand root frame。

否则 wrist/global motion 会被坐标变化抵消掉。

定义累计 displacement：

D_H(k) = H_k^H - H_0^H

k = 1...8

最终：

hand_disp_chunk
shape：

[8, 1538, 3]

同时 Dataset 可以计算 incremental flow：

F_H(k) = H_k^H - H_k-1^H

但 V1 模型不使用 incremental flow。

V1 只返回 cumulative：

hand_disp_chunk。

十五、Object effect GT 的坐标系

物体 future trajectory 也全部固定表达在 current object frame t。

当前：

O_0^O = T_OW(t) O_t^W

未来：

O_k^O = T_OW(t) O_t+k^W

注意这里同样始终使用：

T_OW(t)

而不是未来 object frame。

然后：

D_O(k) = O_k^O - O_0^O

这才是真实的 object effect。

如果未来每一帧分别变到自己的 object frame，那么刚体运动会全部被抵消，这是禁止的。

十六、World object 输入使用全部 4096 点

World Expert 输入：

obj_world_points
shape：
[4096, 3]

不是当前的 5cm → 512。

因为 World Expert 需要看到完整物体几何，包括：

整体尺度，
整体方向，
接触区域位于物体什么位置，
手和整体物体之间的相对关系。

因此：

4096 object points
→ Uni3D patchification
→ 64 object tokens。

十九、DenseToken 在 V1 中怎么使用

这里不能简单让 DenseToken 直接吃 4096 object points。

当前 FrozenDenseTokenEncoder 的 checkpoint contract 明确要求：

512 object points
1538 hand points

并且它只读取当前：

(O_t, H_t)

不读取 hand_flow，也不读取 future object，因此本身不存在 future leakage。

所以 V1 完全保留这个 contract。

DenseToken 输入：

当前 512 个 5cm effect object points
+
当前完整 1538 hand points

并且坐标继续使用它原来熟悉的：

current hand-root frame。

输出：

z_obj
shape：
[512, D_dense]

z_hand
shape：
[1538, D_dense]

hand_contact
shape：
[1538]

DenseToken 全程 frozen。

DenseToken checkpoint 不进入 optimizer。

二十、DenseToken 具体注入位置

z_hand 用于：

World hand patch

以及：

Action hand patch。

z_obj 不尝试扩散到完整 4096 object world points。

因为它只对应被选出的 512 points。

z_obj 只用于：

Effect Decoder 的 512 object query。

这样不会通过 nearest-neighbor 之类的人为方式伪造 4096 个 DenseToken。

二十一、Uni3D 版本固定

World backbone 固定：

Uni3D-S

latent dimension：

D = 384

checkpoint：

pretrained/uni3d/model-s.pt

不从 Uni3D-B 或 Uni3D-L 开始。

V1 只使用 S。

二十二、Uni3D patch 设置固定

Hand：

1538 points
→ deterministic FPS
→ 64 patch centers
→ 每个 center KNN 32 points

Object：

4096 points
→ deterministic FPS
→ 64 patch centers
→ 每个 center KNN 32 points

固定：

num_hand_patches = 64
num_obj_patches = 64
patch_size = 32

FPS 必须 deterministic。

禁止 random start。

这样 object point ordering + obj_point_id 固定后，同一个 object 的 patch index 具有稳定对应关系。

这一点以后 Human → Robot 对齐非常重要。

二十三、Uni3D 的 normal 输入

原 Uni3D patch encoder 的局部输入原本是：

relative xyz + RGB

共 6 维。

InteractionDynamics 改成：

relative xyz + normal

仍然 6 维。

第一层 pretrained Conv 权重处理方式固定如下：

xyz 对应的前三个输入通道：
加载 pretrained 权重。

原 RGB 对应的后三个输入通道：
全部初始化为 0。

不是把 RGB pretrained weight 直接解释成 normal weight。

训练开始时：

normal 分支对输出基本无影响。

随着训练进行：

normal 权重自行学习。

二十四、Uni3D patch token 构成

对于 patch j：

来自：

然后加：

加：

加：

entity embedding 固定两种：

HAND
OBJECT

因此：

patch_token =
local_feature

* position_embedding
* normal_embedding
* entity_embedding。

二十六、DenseToken 如何进入 World hand patches

二十七、Action Expert 必须复用同一批 hand patch

这是硬约束。

对于每一个 hand patch j：

三十一、Action token 的空间定位信息

Action Expert 的运动主体仍然是 hand-centric。

但是为了让它知道当前这块手表面在物体的什么位置，需要加入两个位置 embedding。

第一个：

hand patch center in current hand frame

第二个：

同一个 hand patch center in current object frame

所以最终 action token：

# action_token

temporal_motion_feature

* hand_local_position_embedding
* object_relative_position_embedding
* DenseToken residual

这里正是 Hybrid representation 的核心：

动作局部结构以手为中心。

interaction 几何关系以物体为参考。

三十二、DenseToken 如何进入 Action token

继续复用同一个：

对 z_hand 和 hand_contact pooling。

使用独立的：

-4。

最终：

action_token =

* sigmoid(action_dense_gate) × dense_residual

world_dense_gate 和 action_dense_gate 是两个独立 scalar parameter。

三十三、Action 和 World 如何融合

首先产生：

每层包含：

Residual

输出：

action_context_tokens
shape：
[64, 384]

它的语义是：

“这块手表面在当前完整 hand-object world 中，这段动作意味着什么。”

三十四、interaction_tokens 不继续以 hand patch 为索引

这里是新架构和旧 Cm 最关键的区别之一。

如果最终 representation 仍然是 64 个 hand patch tokens，那么以后：

Human finger patch 17

和：

Robot finger patch 17

没有天然对应关系。

因此最终 interaction_tokens 固定以：

object patches

作为 canonical query。

也就是：

Q = world_obj_tokens

K = action_context_tokens

V = action_context_tokens

执行一个 Object Canonicalization Cross-Attention。

最终：

interaction_tokens
shape：

[64, 384]

第 j 个 token 的意义是：

“当前 object patch j 周围受到的 action-conditioned interaction 是什么。”

三十五、canonicalization 时不加入 object residual

这里必须特别规定。

不要写成：

interaction_token =
world_obj_token

* CrossAttention(...)

因为这样 interaction_tokens 中可能被大量静态 object geometry 主导。

V1 固定：

interaction_token =
LayerNorm(
CrossAttention(
Q = world_obj_token,
K = action_context_token,
V = action_context_token
)
)

object token 只用来决定：

“我要查询哪一个物体区域的 interaction。”

它本身不作为大的 residual 加进最终 interaction representation。

这样以后：

interaction_tokens_human
与
interaction_tokens_robot

比较时，距离主要反映 interaction，而不是同一个 object 本身。

三十六、interaction token 数量固定

V1：

num_interaction_tokens = 64

等于：

num_obj_patches = 64。

不做 gate。

不做动态 token 数量。

不做 Top-K。

不做 sparsity。

每一个 object patch 始终产生一个 interaction token。

三十七、Effect Decoder 的 query

Effect Decoder 仍然使用当前 5cm 采样出的：

512 object points。

每个 query 当前拥有：

obj point position in current object frame
3

obj normal
3

DenseToken z_obj
D_dense

通过 query encoder：

[xyz, normal, z_obj]
→ MLP
→ 384

得到：

effect_query_base
shape：

[512, 384]

三十八、Effect Decoder 显式预测 8 个时间点

V1 不直接：

384 → 24

一次输出 8×3。

而是显式构造 temporal queries。

对于第 k 个 future step：

query_i,k =
effect_query_base_i

* effect_time_embedding_k

k = 1...8

所以总共：

8 × 512

个 effect query。

每个 query 通过：

CrossAttention(
Q = effect query,
K = interaction_tokens,
V = interaction_tokens
)

得到：

effect_context。

三十九、Effect Decoder 禁止绕过 interaction bottleneck

DenseToken z_obj 和 current object geometry 可以进入：

query generation。

但是最终 flow head 不直接拿完整 z_obj feature 做 residual prediction。

最终 flow head 输入固定：

effect_context
+
current object xyz
+
time embedding

然后：

MLP
→ 3D displacement

这样预测必须依赖：

interaction_tokens

而不能形成：

z_obj → object flow

的旁路。

四十、Effect Decoder 输出

输出：

pred_obj_disp_chunk

shape：

[B, 8, 512, 3]

单位对外统一是：

meter。

四十一、motion 数值尺度

V1 不做数据集 RMS calibration。

为了避免毫米级运动导致数值过小，固定一个简单且物理意义明确的内部 motion scale：

motion_scale = 100

即：

meter → centimeter。

Action Encoder 内部使用：

hand_disp_internal =
hand_disp_meter × 100

Effect GT loss 使用：

obj_disp_gt_internal =
obj_disp_gt_meter × 100

decoder 内部预测 centimeter。

对外输出时：

pred_obj_disp_meter =
pred_obj_disp_internal / 100

Geometry xyz 本身仍然保持 meter。

不把 object/hand geometry 乘 100。

四十二、训练 loss

V1 只有一个训练主损失：

Object Effect Chunk Loss。

定义为所有有效：

batch
× 8 time steps
× valid 512 query points

上的 MSE。

也就是：

L_effect =
mean(
||pred_obj_disp_internal - gt_obj_disp_internal||²
)

无效的 effect point 由：

effect_obj_valid_mask

完全排除。

8 个时间步权重全部相同。

不对后期帧额外加权。

V1 总 loss：

L_total = L_effect

没有第二个辅助 loss。

四十三、为什么 V1 暂时只有 effect loss

这是刻意设计的实验。

我们首先需要回答：

单靠 object-effect supervision，

新的 interaction_tokens 是否已经保留足够的 action mechanism。

如果后面的 MANO inverse experiment 成功：

说明不需要人为增加 action reconstruction constraint。

如果 object flow 很准，但 MANO inverse 明显失败：

才说明 interaction representation 被压缩成了 effect-only representation。

这时 V2 才添加 action-preservation loss。

不要在 V1 就提前把问题复杂化。

五十七、MANO inverse forward

每次 optimization iteration：

candidate MANO parameters
→ differentiable MANO forward
→ 8 future hand meshes
→ 1538 fixed face-center points
→ 转到 current hand/object frames
→ candidate hand_disp_chunk
→ frozen InteractionDynamics encoder
→ candidate interaction_tokens

然后计算：

L_interaction =
mean(
||Z_candidate - Z_target||²
)

因为最终 interaction_tokens 是同一个 object 的 64 个 object-patch-indexed tokens，所以这里允许直接按 token index 做 MSE。

这正是 object canonicalization 的价值。

五十八、MANO inverse regularization

为了避免得到剧烈抖动的 MANO trajectory，固定加入两个 regularizer。

第一项：

pose smoothness

相邻 future frame PCA pose 差：

L_smooth_pose =
mean(
||q_k - q_k-1||²
)

第二项：

translation smoothness

L_smooth_trans =
mean(
||t_k - t_k-1||²
)

总优化目标固定：

L_inverse =
L_interaction

* 0.01 × L_smooth_pose
* 0.01 × L_smooth_trans

V1 暂时不加 collision/contact loss。

使用：

Adam

learning rate：

1e-2

iterations：

500

每一个测试 chunk 独立优化。

不做 learned decoder。

不需要 human-robot paired data。

六十、MANO inverse 成功指标

虽然 optimization 本身不看 GT hand future，但评估时我们拥有 GRAB GT，因此计算：

Hand Surface ADE

预测 candidate MANO 1538 points 与 GT future MANO points，8 帧平均误差。

单位：

mm。

Hand Surface FDE

第 8 帧 surface error。

单位：

mm。

Interaction Distance

Z_candidate 与 Z_target 的 MSE。

Predicted Effect Distance

分别把：

Z_candidate
Z_target

送入 frozen Effect Decoder，

比较两者 predicted object effect chunk。

如果：

interaction distance 很低，
object effect 很接近，
但 hand surface 完全不同，

说明 interaction representation 存在多解。

这不是立刻判定失败，需要检查它是否属于真正的 interaction-equivalent action。
