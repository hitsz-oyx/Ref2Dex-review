你感觉对了。最新 `ad4489fc` 的 Viser 可视化里，**GT 手看起来奇怪主要是一个明确的渲染数据 bug，不是 GT MANO 本身就长这样。**

问题出在这里：

```python
gt_surface = face_centers(
    layer(...).vertices,
    faces,
)
...
gt_frames = self.backend.decode_gt({
    "gt_mesh": (gt_surface.cpu().numpy(), faces)
})
```

`face_centers()` 做的是：

```python
return vertices[:, faces].mean(2)
```

即把每个三角面的三个顶点平均成**一个面中心点**。

所以本来：

```text
MANO vertices ── faces ──> 正常三角网格
```

现在变成了：

```text
MANO vertices
     ↓
face_centers
     ↓
一堆“每个三角面的中心点”
     ↓
却继续套用原来的 MANO faces
     ↓
错误拓扑
```

原来的 `faces` 是用来索引 **MANO 原始 vertices** 的，不是用来索引 face centers 的。于是它会把互不相关的面中心乱连起来。

这也是你看到“手点上为什么有很多连线”的直接原因。

当前 GT 显示代码还专门设置了：

```python
wireframe=True
```

所以那些线就是 **Viser 绘制的错误三角网格边**，不是：

* (Y) 的连线；
* 手部运动轨迹；
* 骨架；
* contact correspondence。

而且不只是 GT，**Prediction 现在其实也有同样的问题**。因为 `decode_mano_y()` 返回的 `surface` 本身也是通过 `face_centers()` 得到的：

```python
future_surface = face_centers(
    layer(...).vertices,
    faces,
)
```

然后 viewer 又拿：

```python
(predicted_surface_world, faces)
```

当真正的 mesh 去画。

所以当前画面严格来说不能用来判断：

> predicted MANO 手型到底好不好。

---

## 应该怎么改

这里要把两个用途彻底分开：

```text
MANO vertices
   │
   ├──→ Viewer           用真正 vertices + faces
   │
   └──→ face_centers     用于计算 Y
```

也就是：

### GT

不要：

```python
gt_surface = face_centers(layer(...).vertices, faces)
```

而是直接：

```python
gt_output = layer(
    global_orient=item["global_orient"].to(device),
    hand_pose=item["hand_pose"].to(device),
    betas=item["betas"].to(device),
    transl=item["transl"].to(device),
)

gt_vertices_world = gt_output.vertices
```

然后：

```python
gt_mesh = (
    gt_vertices_world.cpu().numpy(),
    faces,
)
```

这样才是正常 MANO mesh。

---

### Prediction

也一样。

现在 `decode_mano_y()` 内部其实先有：

```python
layer(...).vertices
```

只是立刻被：

```python
face_centers(...)
```

压成 interaction surface 了。

不要改变训练用的 `decode_mano_y()` 行为，最稳妥的是**额外写一个 viewer-only decoder**：

```python
decode_mano_vertices(...)
```

使用完全相同的：

```text
ΔH
↓
world_rotation
world_translation
future_pose
↓
MANO forward
```

但是最后直接返回：

```python
output.vertices
```

而不是：

```python
face_centers(output.vertices)
```

这样：

```text
训练 / Y evaluation:
MANO vertices → face centers → Y

可视化:
MANO vertices + MANO faces → mesh
```

两条链互不干扰。

---

## GT 还建议不要默认 wireframe

修完拓扑后我也建议把：

```python
wireframe=True
```

去掉。

第一版简单用：

```text
Prediction：蓝色实心
GT：绿色半透明实心
Object：灰色实心
```

例如：

```python
gt_handle = server.scene.add_mesh_simple(
    "/world/hand/gt",
    gt.vertices,
    gt.faces,
    color=(80, 220, 120),
    opacity=0.35,
    wireframe=False,
)
```

这样一眼就能看出来：

* GT 手是不是正常；
* Prediction 手是不是正常；
* 两者相对物体的抓取位置是否合理。

不需要那些三角边干扰。

## 给 Codex 可以直接这么说

```text
检查最新 viewer_v2，可视化存在明确 mesh topology bug。

当前 prediction_v18_5.py 把 MANO vertices 经过 face_centers() 后得到的
surface points 当作 mesh vertices，同时仍使用原 MANO layer.faces。
这是错误的：layer.faces 索引的是原 MANO vertices，不是 face centers。
因此 GT 和 prediction 的 mesh 都可能出现错误连线/畸形。

修复原则：

1. 不修改训练和 Y 构造逻辑。
   face_centers 仍然只用于 interaction Y。

2. viewer 必须使用真正 MANO vertices：
   MANO output.vertices + layer.faces。

3. GT：
   直接从
   layer(global_orient, hand_pose, betas, transl).vertices
   获取 9 帧 GT world vertices。
   不再调用 face_centers。

4. Prediction：
   新增 viewer-only helper，例如 decode_mano_vertices()。
   严格复用 decode_mano_y 中相同的
   delta_h -> object-frame H -> world_rotation/world_translation/future_pose
   恢复逻辑，
   但 MANO forward 后直接保留 output.vertices，
   不调用 face_centers。

5. prediction 和 GT 最终都输出：
   vertices [T,V,3]
   faces [F,3]

6. viewer.py：
   Prediction 使用实心 mesh；
   GT 使用半透明实心 mesh；
   去掉 GT 默认 wireframe=True。

7. 加 sanity check：
   assert faces.max() < vertices.shape[1]
   分别检查 GT 和 prediction。

不要改变 V18.6 checkpoint、模型、Y loss 或 interaction_field。
只修 viewer 的 rendering geometry。
```

所以现在**先别根据当前画面判断 MANO 预测质量**。先把这个 bug 修掉，再看 GT；正常情况下 GT MANO 应该是一只非常规整的手。如果修完之后 GT 仍然姿态很怪，那才继续查 `v_template / side / raw_frame_ids / world transform`。
