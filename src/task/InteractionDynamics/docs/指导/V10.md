这里要分开看。**“压成全局”本身不一定坏，但如果把局部手指动作也一起抹掉，对我们现在想做的 RL prior 就是坏的。**

更准确地说，我们希望的是：

[
\boxed{\text{去掉冗余，而不是丢掉可区分的 action 信息}}
]

### 目前还不能说 Action Token 已经坍缩

你刚做的 V9 证明的是：

[
\boxed{\text{object-indexed interaction field 不需要空间差异}}
]

因为所有 object field positions 都相同，性能仍几乎不变。

但 `ActionEncoder` 里面其实还保留着 64 个 hand-patch action token。当前代码是：

[
[8,64,D]
\rightarrow \text{temporal encoder}
\rightarrow [64,D]
]

然后经过 world conditioning，再重新加回 temporal token 构成 `action_temporal`。所以 V9 仍可能在利用**不同手指 patch 的局部运动**，只是没有必要把它投影成 64 个不同 object-field token。

因此现在还不能说：

[
A_{1}=A_{2}=\cdots=A_{64}.
]

这个需要单独测。

---

## 现在有没有“Action Token → 原始动作点流”的监督？

**代码里有，但 V7 当前训练实际上关闭了。**

模型里明确有：

```python
self.action_reconstruction = nn.Linear(
    meta.model_dim,
    meta.chunk_len * 3
)
```

并且：

```python
pred_hand_patch_disp_internal = self.action_reconstruction(
    action_context
)
```

也就是：

[
\boxed{
A_i
\rightarrow
\widehat{\Delta H}_{1:8,i}
}
]

每个 action token 预测对应 hand patch 的 8 步平均点流。

Runner 也有对应 GT：

[
\Delta H^{patch}_{k,i}
======================

\operatorname{mean}*{p\in patch_i}
\Delta h*{k,p}.
]

所以这个 auxiliary task（辅助任务）是完整存在的。

**但是 V7 配置里：**

```yaml
action_loss_weight: 0.0
```

也就是说当前 V7，按你描述 V9 如果沿用同样设置，也是：

[
\boxed{\text{没有 action reconstruction supervision}}
]



它现在只靠：

[
L_{SE3}
]

训练。

---

# 这其实让我觉得现在有一个很明确的问题

如果我们最终只优化：

[
C/A \rightarrow SE(3)_O
]

那么模型**完全有动力主动丢掉 finger articulation（手指局部关节运动）**。

因为 GRAB 当前的数据告诉它：

[
\text{global hand motion}
]

已经足够把 SE(3) 猜得很好。

所以对于 SE(3) prediction：

[
\boxed{\text{Action collapse 是一种合理的最优解}}
]

但对于我们想要的：

[
\boxed{\text{cross-body RL prior}}
]

它就未必是好事。

因为以后你可能需要区分：

```text
两指夹住 + 向上
```

和

```text
整只手整体向上，但手指没形成类似动作
```

如果 Action representation 已经只剩：

[
\bar{\Delta H}
]

这两个动作很可能变得非常接近。

---

# 但我也不建议直接把现有 `action_loss_weight=1` 打开就结束

因为现有 action reconstruction 也有一个问题：

它监督的是：

[
\Delta H_{k,i}
]

本身。

而 hand flow 也可以分解为：

[
\Delta H_{k,i}
==============

\underbrace{\bar{\Delta H}*k}*{global}
+
\underbrace{\delta H_{k,i}}_{local}.
]

其中：

[
\bar{\Delta H}_k
================

\frac1{64}\sum_i\Delta H_{k,i}.
]

如果 global motion 很大，raw action reconstruction MSE 也可能主要奖励：

[
\hat{\Delta H}_{k,i}\approx\bar{\Delta H}_k.
]

也就是又出现：

> 64 个 token 都预测差不多的 global hand motion。

这和之前 object patch supervision 的问题高度类似。

---

# 所以如果现在要保护 Action representation，我更建议监督 local residual

显式定义：

[
\boxed{
\delta H_{k,i}
==============

## \Delta H_{k,i}

\bar{\Delta H}_k
}
]

然后让 action token 解码：

[
A_i
\rightarrow
\widehat{\delta H}_{1:8,i}.
]

同时 global motion 单独预测：

[
A_{global}
\rightarrow
\bar{\Delta H}_{1:8}.
]

变成两个非常明确的 head：

```text
Action Tokens
      │
      ├── global head
      │      ↓
      │   mean hand flow
      │
      └── local head
             ↓
       per-patch residual flow
```

对应：

[
L_A
===

\lambda_gL_{global}
+
\lambda_lL_{local}.
]

这样才真正防止：

[
A_1=A_2=\cdots=A_{64}.
]

---

# 而且这个监督和我们现在的项目目标很契合

因为它不是要求模型学完美 interaction physics。

它只要求：

[
\boxed{C/A\text{ 不要把原始 human action 信息全扔掉}}
]

这对于 RL prior 足够合理。

Effect branch 告诉它：

[
\text{哪些 action 信息与 object effect 有关}
]

Action reconstruction 告诉它：

[
\text{不要把 source action 压缩得只剩 object SE(3)}
]

Cross-body supervision 再告诉它：

[
\text{不同 morphology 中功能相似的信息应该靠近}.
]

这三个约束正好形成：

[
\boxed{
L
=

L_{\text{effect}}
+
\lambda_A L_{\text{action-info}}
+
\lambda_C L_{\text{cross-body}}
}
]

我觉得这比继续强行设计 local object field 更合理。

---

## 我会先做诊断，不急着重新训练

在当前 V9 checkpoint 上直接测三个量：

[
\operatorname{Var}_i(A_i)
]

以及 action-token pairwise cosine。

更重要的是做三个 linear probe（线性探针：冻结 encoder，只训练一个很小的线性层看 latent 里是否还存在某类信息）：

1. (A\rightarrow\Delta H)：完整 patch flow；
2. (A\rightarrow\bar{\Delta H})：global flow；
3. **(A\rightarrow\delta H)：local residual flow。**

第三个最重要。

如果结果是：

[
global\ probe\ 很好
]

但：

[
local\ residual\ probe\approx zero
]

那我们就可以明确说：

[
\boxed{\text{Action representation 真的发生了有害的 global collapse。}}
]

如果 local residual 仍然很好，那反而说明 V9 只是**后面的 interaction field 不需要空间展开**，Action Encoder 自己还保留了丰富动作信息，这其实是很理想的结果。

所以我现在不会先判断“全局化一定好或坏”，而会把验收标准定成一句话：

[
\boxed{
\text{允许 effect pathway 全局化，但不允许 bottleneck 丢失 local action residual。}
}
]

而当前仓库**确实已有 action reconstruction head，但 V7 配置的 `action_loss_weight=0`，所以它目前没有参与训练**。
