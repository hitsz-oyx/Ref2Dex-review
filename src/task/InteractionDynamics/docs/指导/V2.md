是的，我把最新仓库重新看了一遍。现在的 10 序列实验**说明多序列效果明显弱于单序列，但我暂时不会把它定性成“模型已经证明泛化不行”**。当前实验里有几个很强的混杂因素，而且其中两个我认为必须先修。

最新提交是 `97b0e1c`，仓库记录的 10 序列结果是：训练 ADE 35.53 → 19.54 mm；验证集 42.94 → 32.07 mm；测试集 30.98 → 25.19 mm。也就是说未见序列确实只比 zero-flow 好约 19%–31%，远没有单序列 overfit 的 6.71 mm 那么漂亮。

但我看下来，当前最该注意的是下面这几个问题。

### 1. 首先是“训练都没训好”，还不能先怪泛化

单序列实验：

[
32\ chunks,\quad 400\ steps
]

batch size 8，相当于：

[
400/(32/8)=100\ epochs
]

而现在 small10 是 8 条训练 sequence × 每条最多 128：

[
1024\ chunks
]

只训练：

[
5\ epochs=640\ steps
]

配置里确实就是 `epochs: 5`。

所以实际比较是：

[
\text{单序列：每个 sample 看约 100 次}
]

vs.

[
\text{多序列：每个 sample 看约 5 次}
]

这不是同一训练强度。

更关键的是多序列最终连 **train ADE 都还有 19.54 mm**。如果 train 已经做到 5–8 mm，val 还是 25–30 mm，我会明确说是 generalization gap（泛化差距）。

但现在是：

[
Train=19.54,\qquad Test=25.19
]

差距其实只有约 5.6 mm。

所以当前更像：

[
\boxed{\text{underfitting / optimization not converged}}
]

即“训练本身还没有充分收敛”，而不是纯粹的“模型记住训练集但泛化不了”。

因此第一件事非常简单：**small10 不改模型，直接训练 20–30 epochs，看 train/val 曲线。**

如果最后：

[
Train\rightarrow 8mm,\quad Val/Test\approx25mm
]

才真正证明泛化问题。

# 2. 当前 `max_samples_per_sequence=128` 的实现有一个明显采样偏差

这个我认为应该直接修。

现在代码先：

```python
self._samples.sort(key=lambda item: (str(item[0]), item[1]))
```

然后每条 sequence：

```python
if count < 128:
    limited.append(sample)
```

也就是说它不是：

> 从一条 sequence 的所有有效 chunk 里均匀取 128 个。

而实际上是：

[
\boxed{\text{直接拿时间上最前面的 128 个有效 chunk}}
]

假设一条动作：

```text
approach
   ↓
pre-contact
   ↓
grasp
   ↓
lift
   ↓
manipulate
   ↓
release
```

你可能只拿到了：

```text
approach + grasp 前半段
```

而后面的动作阶段根本没进入训练。

更麻烦的是这个限制通过 `common` 同样传到了 train / val / test。

所以现在所谓：

> 每条 sequence 128 chunks

其实不是一个好的 temporal coverage（时间覆盖）。

我建议固定改成：

[
\boxed{\text{uniform temporal sampling}}
]

例如如果一条 sequence 有 600 个合法 chunk：

```text
0 -------------------------------- 599
|    |    |    |    |    |    |
128 个近似均匀位置
```

而不是：

```text
0 ------- 127
```

这个改动比现在继续动网络结构优先级高很多。

# 4. 我现在最担心的结构问题还是 canonicalization

现在是：

[
Q=W_O
]

[
K,V=A_{context}
]

然后：

[
C=\operatorname{CrossAttn}(W_O,A)
]

问题是它**没有显式告诉 attention 哪个 hand patch 靠近哪个 object patch**。

模型必须自己从：

* object token；
* action token；
* position embeddings；

学出：

[
object\ patch_j
\leftrightarrow
hand\ patch_i
]

这种空间 correspondence（空间对应关系）。

effect loss 又没有强迫它这么做。

所以最简单的解就是：

[
c_j\approx\frac1{64}\sum_i a_i
]

这正好和你现在看到的高 entropy 对上。

测试：

[
H(attention)=4.0819
]

离：

[
H_{uniform}=4.1589
]

已经非常近。

# 5. 更关键的是：以前我们已经证明 Effect Decoder 很容易只用 global mean

之前做过：

[
C={c_1,\ldots,c_{64}}
]

然后把所有 token 替换成：

[
\bar c
======

\frac1{64}\sum_jc_j
]

预测变化只有：

[
0.0048mm
]

这实际上是一个非常强的证据：

[
\boxed{\text{decoder 当时几乎完全不需要 object-indexed interaction}}
]

`action_local_gain=10` 解决了 interaction token collapse，但我没有看到仓库里**在 gain=10 之后重新做一次 mean-token intervention**。

这应该成为下一项实验。

拿现在 small10 best checkpoint，在 val/test 分别测：

### Normal

[
C={c_j}
]

### Mean replacement

[
C_j=\bar c,\quad\forall j
]

### Permutation

随机打乱：

[
C_{\pi(j)}
]

### Cross-sample swap

换成另一条 sample 的：

[
C^B
]

如果现在：

```text
normal ADE       25.2 mm
mean-token ADE   25.5 mm
shuffle ADE      25.4 mm
```

那就可以直接确认：

[
\boxed{\text{object-indexed representation 还没真正建立}}
]

这比继续看 cosine 更直接。

# 6. 还有一个我刚刚从 Uni3D 官方代码对出来的问题：输入尺度不匹配

这个我认为很值得做一个 sanity check（可信度检查）。

官方 Uni3D 数据在送进网络之前会：

[
p_i
\leftarrow
p_i-\bar p
]

然后：

[
p_i
\leftarrow
\frac{p_i}
{\max_j|p_j|}
]

也就是把点云归一化到大致单位球：

[
\boxed{|p|\sim O(1)}
]

官方代码明确这么做。

但是我们现在的 Uni3D 输入是：

[
\boxed{\text{真实 meter}}
]

例如：

[
0.03,\ 0.08,\ 0.15
]

这种量级。

当前 `Uni3DWorldEncoder` 的 position MLP 和 pretrained local xyz Conv 都直接吃这些 meter 坐标。也就是说 pretrained Uni3D 原本看到的：

[
xyz\sim [-1,1]
]

现在变成：

[
xyz\sim[-0.1,0.1]
]

甚至局部 patch：

[
\Delta xyz\sim0.005
]

左右。

这意味着：

[
\boxed{\text{pretrained coordinate distribution 明显发生 shift}}
]

单序列 overfit 不怕这个——网络可以硬适应。

**多序列泛化才更容易暴露这个问题。**

我现在会把它列为第二阶段非常值得测的 ablation。

# 7. 但不要直接把整个系统都归一化

因为我们还需要真实 metric geometry：

[
5cm
]

[
\Delta H
]

[
contact distance
]

这些都应该保持米制。

我建议只让 Uni3D backbone 使用 normalized view：

```text
metric current scene
H_t + O_t
        │
        ├────→ metric representation
        │     给 Action/object-relative geometry
        │
        └────→ normalized copy
              给 pretrained Uni3D
```

例如：

[
X=[H;O]
]

共同计算：

[
c=\operatorname{mean}(X)
]

[
s=\max_i|x_i-c|
]

然后：

[
X^{uni3d}
=========

\frac{X-c}{s}
]

注意一定是 **hand + object 共用同一个 transform**。

绝对不能：

```text
hand 单独 normalize
object 单独 normalize
```

否则 hand-object 相对位置直接没了。

然后把：

[
s
]

保留下来，metric action branch 继续知道真实尺寸。

# 8. 还有一个理论层面的 shortcut 要警惕

我们现在 supervision 是 rigid object point flow。

GRAB 的刚体 object 实际上：

[
\Delta O_{1:8}
]

本质只有每一步：

[
SE(3)
]

六个自由度。

也就是说 512 个点：

[
512\times3
]

看起来 supervision 很丰富，但实际上自由度非常低：

[
\boxed{6}
]

因此网络特别容易学成：

```text
整个 hand action
      ↓
global interaction vector
      ↓
object SE(3) motion
      ↓
结合 object xyz
      ↓
512 point flow
```

而不是：

```text
哪个手指
作用在哪个 object patch
      ↓
局部 interaction
      ↓
object effect
```

这和之前：

> mean interaction tokens 几乎不影响 prediction

完全一致。

所以如果多序列之后仍然发现 mean-token replacement 没影响，那么根本问题可能不是“数据不够”，而是：

[
\boxed{
L_{object-flow}
\text{ 本身不足以迫使 }C_m\text{ 学到局部 action mechanism}
}
]

这时候就该进入我们之前说的 V2：

[
L=
L_{effect}
+
\lambda L_{action-preserve}
]

或者加入局部 contact/coupling supervision。

但**现在还不到马上加这个的时候**。

# 我建议接下来严格按这个顺序做

1. **不改模型。**
   把 small10 从 5 epochs 跑到 20–30 epochs，直到 train ADE 明显 plateau。现在 5 epochs 太少。配置当前确实只有 5 epochs。

2. **修 128 chunk sampling。**
   每个 sequence 从全部合法 chunk 中按时间均匀取 128，不再取前 128。当前实现明确是排序后从前往后截取。

3. **扩大到至少 12/4/4。**
   先别 full GRAB。val/test 各 4 sequence 才有资格判断 sequence generalization。

4. **重新做 post-gain token intervention。**
   对 `action_local_gain=10` 当前模型测：
   `normal / mean-token / shuffled-token / cross-sample-token`。

5. 如果训练已经收敛但 val/test 仍差，做一个非常小的 **Uni3D normalized-input ablation**，因为官方预训练明确使用 normalized point cloud，而我们现在是 meter raw input。

6. 如果 normalized Uni3D 仍然不解决，并且 mean-token intervention 证明 decoder 仍不使用 token-level information，再改 canonicalization / supervision。

---

所以现在我的判断是：

[
\boxed{
\text{确实有泛化隐患，但当前 small10 还不足以证明“架构泛化失败”。}
}
]

目前最明显的三个问题按优先级是：

[
\boxed{
\text{训练不足}

>

\text{每序列取前 128 帧的采样偏差}

>

\text{canonical attention 仍过于接近全局平均}
}
]

而 **Uni3D meter 输入与官方单位球预训练分布不一致**，是我这次重新浏览官方仓库后认为非常值得马上加一个对照实验的第四点。这个问题单序列很可能看不出来，多序列恰好最容易暴露。
