你的这个定位更合理：**viewer 不应该暴露 (r,u) 这种内部表示，而应该展示一个通用任务：**

[
\boxed{
\text{给定物体运动/目标}
\rightarrow
\text{输出手应该怎么过去、怎么抓}
}
]

第一版只接 MANO，后面 Inspire Hand、Allegro、Shadow Hand 都走同一个 visualization interface。Viser 很适合这个需求：它本身就是 Python 端维护 scene + GUI，支持 mesh、slider、checkbox 等交互，而且浏览器访问方便。([Viser Studio][1])

不过有一点需要先明确：**当前 V18.5 并不是“给定任意 object trajectory 条件，预测 hand trajectory”**。目前它主要还是从当前 hand-object state 预测局部 grasp-formation。viewer 可以现在就把接口设计成 `object trajectory -> hand trajectory`，但当前版本的 object trajectory 应标成 `Reference / Dataset trajectory`，不要假装它已经是模型 condition。

## 最小 viewer 我建议只显示这些

3D 场景：

```text
Object
├── current object
└── future object trajectory

Hand
├── current hand
├── predicted hand
└── GT hand      # 可选，仅研究阶段
```

GUI：

```text
Hand Model:  [MANO ▼]

Sample:      [  123  ]
Frame:       [0 -------- 8]

[Play] [Pause]

[x] Object trajectory
[x] Predicted hand
[x] GT hand
[ ] Ghost trajectory
```

指标只放三个通用的：

```text
Grasp success:     YES / NO
Collision:         YES / NO
Penetration depth: 2.1 mm
```

如果暂时还没有真正 physics grasp evaluator，`Grasp success` 可以先叫：

```text
Grasp proxy
```

避免把几何 proxy 当成物理抓取成功。

我甚至**不建议第一版显示 hand pose RMSE**。因为以后：

[
MANO \neq Inspire
]

joint space 根本无法横向比较，而且多解 grasp 下 GT pose 本来也不唯一。

# 1. 最重要的抽象：Hand Backend

不要把 viewer 写死成 MANO。

第一版就定义：

```python
from dataclasses import dataclass
from typing import Protocol
import numpy as np


@dataclass
class HandFrame:
    vertices: np.ndarray   # [V, 3]
    faces: np.ndarray      # [F, 3]


class HandBackend(Protocol):
    name: str

    def decode_prediction(
        self,
        sample,
        prediction,
    ) -> list[HandFrame]:
        ...

    def decode_gt(
        self,
        sample,
    ) -> list[HandFrame] | None:
        ...
```

第一版：

```python
class ManoBackend:
    name = "MANO"
```

以后加：

```python
class InspireBackend:
    name = "Inspire Hand"
```

viewer 本身完全不用知道：

* MANO PCA；
* Inspire joint angles；
* URDF；
* FK。

它只认：

[
\boxed{\text{每一帧给我 vertices + faces}}
]

这样架构会很干净。

# 2. Object trajectory 也统一成通用格式

建议统一成：

```python
@dataclass
class ObjectTrajectory:
    vertices: np.ndarray      # canonical object mesh [V,3]
    faces: np.ndarray         # [F,3]
    poses: np.ndarray         # [T,4,4]
```

这样未来不管输入来自：

* GRAB GT；
* 用户指定 SE(3) trajectory；
* VLA；
* motion planner；

viewer 都不用改。

最终：

```text
ObjectTrajectory
      +
HandTrajectory
      ↓
    Viser
```

# 4. 更新 frame 时只更新 mesh

核心逻辑应该非常简单：

```python
def set_frame(frame: int):
    object_vertices = object_trajectory.world_vertices(frame)

    pred = pred_hand_frames[frame]
    gt = gt_hand_frames[frame] if gt_hand_frames else None

    object_handle.vertices = object_vertices
    pred_handle.vertices = pred.vertices

    if gt is not None:
        gt_handle.vertices = gt.vertices
```

如果当前 Viser 版本 handle 不方便直接换 vertices，就删除再 `add_mesh_simple()`；第一版 9 帧而已，性能完全不是问题。

后面再优化。

# 5. Frame slider

Viser 官方 GUI 原生支持 slider/button/checkbox。([Viser Studio][2])

核心：

```python
frame_slider = server.gui.add_slider(
    "Frame",
    min=0,
    max=8,
    step=1,
    initial_value=0,
)
```

然后：

```python
@frame_slider.on_update
def _(_):
    set_frame(frame_slider.value)
```

这样你就能直接拖：

```text
0 → 1 → 2 → ... → 8
```

看模型到底怎么接近物体。

# 6. Play 也只需要一个小线程

第一版不用做很复杂的播放器。

```python
playing = False

play_btn = server.gui.add_button("Play")
pause_btn = server.gui.add_button("Pause")


@play_btn.on_click
def _(_):
    global playing
    playing = True


@pause_btn.on_click
def _(_):
    global playing
    playing = False
```

主循环：

```python
while True:
    if playing:
        next_frame = (frame_slider.value + 1) % num_frames
        frame_slider.value = next_frame
        set_frame(next_frame)

    time.sleep(0.15)
```

就够了。

# 7. Object trajectory 的呈现

我不建议显示 8 个完整 object mesh ghost，会显得很乱。

第一版只做：

### 当前 frame object mesh

以及 object root trajectory：

```text
○──○──○──○──○──○──○
```

直接把每个：

[
T^W_{O,t}
]

的 translation：

[
p_{O,t}
]

连成一条 line。

如果物体 rotation 也很重要，可以后面加 frame axes。

所以：

```text
[x] Object trajectory
```

控制的是：

* path line；
* 若干小坐标轴。

不是一堆半透明 mesh。

# 9. GT 和 Prediction 怎么呈现

我建议：

* Prediction：实心 mesh；
* GT：wireframe 或半透明 mesh。

不要都画成两个实心 mesh，否则重合之后很难看。

例如：

```python
pred_handle = server.scene.add_mesh_simple(
    "/hand/pred",
    vertices=pred.vertices,
    faces=pred.faces,
    color=(80, 160, 255),
)

gt_handle = server.scene.add_mesh_simple(
    "/hand/gt",
    vertices=gt.vertices,
    faces=gt.faces,
    color=(80, 220, 120),
    opacity=0.35,
)
```

Viser `add_mesh_simple()` 当前支持 `opacity`、`wireframe`、材质等参数。([Viser Studio][3])

# 10. 我建议 viewer 的输入不要直接绑定 checkpoint

这个也很重要。

不要写成：

```text
viser
  ↓
直接 import V18.5 model
  ↓
直接 inference
```

而是分两层：

```text

        ↓
viewer
```

定义：

```python
@dataclass
class VisualizationSample:

    grasp_success: bool | None
    collision: bool | None
```

当前：

```python

```

负责：

```text
checkpoint
+ dataset sample
→ model inference
→ MANO
→ VisualizationSample
```

以后：

```python
InspirePredictionProvider
```

也是返回同样的 `VisualizationSample`。

这就正好符合你以后想扩展的方向。

# 13. 一个重要的当前限制

你最终希望的是：

[
\boxed{
T^*_{O,0:H}
\rightarrow
H^*_{0:H}
}
]

也就是：

> 给定 desired object trajectory，输出如何拿住并操作。

但目前 V18.5 更接近：

[
\boxed{
\text{current hand/object state}
\rightarrow
\text{grasp-formation hand trajectory}
}
]

所以 viewer 第一版可以显示：

```text
Reference Object Trajectory
```

但**不要给 GUI 起名叫 `Desired Object Trajectory`**。

等后面真正把 object trajectory 接入模型 condition 后，再改成：

```text
Input Object Trajectory
```

这样展示逻辑和研究事实不会混淆。

## 给 Codex 的最小实现提示词

```text
为 InteractionDynamics 新建一个独立的 Viser viewer v2。

目的不是展示 r/u/Y 等内部量，而是建立一个通用的
“object trajectory -> hand grasp/manipulation trajectory”
可视化框架。

当前只实现 MANO，未来要能扩展 Inspire Hand / Allegro / robot hand，
所以 viewer 不能依赖 MANO 参数本身。

第一版只做最小功能，不重构训练代码。

目录：
src/task/InteractionDynamics/viewer_v2/
    viewer.py
    backends.py
    prediction_v18_5.py

一、统一数据接口

定义：

HandFrame:
    vertices [V,3]
    faces [F,3]

ObjectTrajectory:
    canonical vertices [V,3]
    faces [F,3]
    poses [T,4,4]

VisualizationSample:
    object_trajectory
    pred_hand: list[HandFrame]
    gt_hand: optional list[HandFrame]
    grasp_success / grasp_proxy
    collision
    max_penetration_mm

定义 HandBackend 接口。
第一版实现 ManoBackend。
viewer.py 只能读取 HandFrame，不允许依赖 MANO PCA/global_orient 等参数。

二、V18.5 provider

prediction_v18_5.py：
- load V18.5 checkpoint
- load MANO-H cache sample
- 使用现有 ManoHandTransition
- 使用现有 MANO structured decoder
- 得到 current + 8 future predicted MANO meshes
- 恢复对应 GT MANO meshes
- 恢复 dataset object trajectory
- 转成 VisualizationSample

注意：
当前 V18.5 并没有以任意 desired object trajectory 作为 condition。
viewer 中将当前 object trajectory 标为 Reference Object Trajectory，
不要称为 model input trajectory。

三、Viser viewer

使用 viser.ViserServer。

3D scene 仅显示：
- object mesh
- predicted hand mesh
- optional GT hand mesh
- object root trajectory line

GUI 仅包含：

Hand Model:
    dropdown，第一版只有 MANO

Sample:
    integer / slider

Frame:
    slider 0~8

Play
Stop

Display:
    Show Prediction
    Show GT
    Show Object Trajectory

Metrics:
    Grasp proxy / success
    Collision
    Max penetration depth

不要显示：
- r/u/d
- Y loss
- ActionToken
- MANO PCA RMSE
- diffusion 内部量
- 其他 InteractionDynamics-specific 指标

Prediction 用实心 mesh。
GT 用半透明或 wireframe mesh。
frame 0 显示 current hand/object；
frame 1~8 显示对应 future。

Play 按钮按固定 FPS 自动更新 frame slider。
拖动 slider 必须立即更新 object、pred hand、GT hand。

四、实现原则

先做单 checkpoint、单 test split、单 sample 可运行。
随后再加 sample selector。
不要第一版做复杂 ghost、视频导出、相机预设、热力图。
不要修改训练代码。

代码要把：
model inference / hand decoding / viewer
三部分严格分开。

启动方式类似：

python -m src.task.InteractionDynamics.viewer_v2.viewer \
    --checkpoint <v18.5_best.pt> \
    --cache <mano_h_cache> \
    --split test \
    --port 8080

启动后打印：
http://localhost:8080
```

Viser 官方当前就是通过 `ViserServer` 提供浏览器端 3D scene 和 GUI，`add_mesh_simple()` 可以直接画 MANO 的 vertex/face mesh，`add_slider()` 等 GUI 控件也都是原生能力，所以不需要再维护之前那套手写 Three.js HTML。([Viser Studio][1])

这个最小版我认为已经足够作为以后整个项目统一的 visualization shell。
