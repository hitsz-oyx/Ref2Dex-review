V18.5 保持 V18.4 的网络、`current_h`、`ΔH[8,30]`、MANO 参数化和数据不变，只把

[
L_H=|\hat H-H^{GT}|^2

[
\boxed{
L_Y=
D_Y\left(
\Phi(\hat H,O),
Y^{GT}
\right)
}
]

也就是：

[
\text{network}\to H\to MANO\to hand\ surface\to Y\to loss.
]

没有加 diffusion、ActionToken、contact loss、stable loss，也没有重新加 H-GT loss。

结果非常明显：

| 模型                   |    Stable | Formation stable | Contact F1 |
| -------------------- | --------: | ---------------: | ---------: |
| V18.4 H-MSE          | **2.34%** |        **1.63%** |      0.585 |

这是同一个“前 512 test”口径。

也就是说只换监督目标：

[
\boxed{1.63%\rightarrow49.4%}

而且：

[
\boxed{r/d\ violation=0}

仍然保持。

所以现在可以相当有信心地说：

[
\boxed{
\text{V18.4 的主要错误之一确实是强迫 }H\text{ 模仿 GT human MANO pose。}
}

而不是“MANO 作为中间空间本身不行”。

## 实现本身我也核了，关键链路目前是对的

`decode_mano_y()` 做的是：

[
\Delta H
\rightarrow H^O_{future}
\rightarrow H^W_{future}
\rightarrow MANO
\rightarrow surface
\rightarrow object/reference\ frame
\rightarrow Y.
]

future 8 帧分别用了对应帧的 `object_rotation/object_translation`，不是错误地一直用当前帧 object pose。

而且它把：

```text
current GT MANO surface
+
8 predicted future MANO surfaces
```

拼成完整 9-frame surface trajectory，再计算：

[
u_t=h_{t+1}-h_t,
]

所以第一步 (u_t) 确实是：

[
H_t^{GT}\rightarrow \hat H_{t+1}
]

产生的，不存在把 current frame 丢掉的问题。

batched Y 也有单元测试跟 frozen Teacher 对齐：

[
\text{batched/chunked Y}
\approx
\text{original Y},
]

误差门限 (2\times10^{-5})，并且梯度能穿过。

实际 MANO parity：

[
\max\ error\approx3.97\times10^{-4}\text{ cm}.
]

所以这部分没发现结构 bug。

# 但是我发现了一个应该先修的地方

这个很重要。

当前 V18.5：

```python
def residual_std(dataset):
    values = torch.cat([...], 0).double()
    return values.std((0, 1))
```

这里 `values` 是：

[
[N\times128,\ 56].
]

然后：

```python
std((0,1))
```

把 **anchor 维和 56 个 Y channel 全部一起求掉了**。

所以最终实际上得到：

[
\boxed{
\sigma_R\in\mathbb R
}
]

一个 scalar。

不是我们原本想要的：

[
\boxed{
\sigma_R\in\mathbb R^{56}.
}
]

而原始 V18 正确实现是：

```python
values.std(0)
```

得到：

[
[56].
]

因此现在 V18.5 实际优化的近似就是：

[
L_Y\propto
|\hat R-R^{GT}|^2
]

一个 **raw Y MSE**，而不是逐 channel normalized Y loss。

这个问题不会否定当前结果——事实上 raw Y loss 已经把 formation 从 1.6% 拉到了 49%。

但它意味着：

[
\boxed{
\text{V18.5 现在甚至还不是我们原计划的最佳 Y-supervision。}
}
]

我会优先修成：

```python
values.std(0)
```

得到：

```text
residual_std [1,1,56]
```

然后只重新跑同一个 2048/512 实验。

这是现在最干净的 V18.5.1。

## 还有一个口径要注意

现在所谓 `stable success` 仍然不是原始 detector 的“连续 6 帧 stable”。

当前 evaluator 实际取未来最后 3 帧：

```python
terminal = values[..., -3:, :]
success = (
    (contact >= 4).all(-1)
    & (u_rms < 0.3)
)
```

所以严格来说，我们现在报告的是：

[
\boxed{\text{terminal 3-frame stable proxy}}
]

也就是“末端三帧稳定代理指标”。

因此后面写论文/记录时不要直接把 57.2% 写成“原始 6-frame stable grasp success”。

但由于 V18.4、V18.5、V18 free-Y 后期评估都使用同一个 evaluator，它们之间还是可以比较的。

# 我对现在路线的判断已经发生变化

之前我会说：

> 先试 H-Diffusion，看看是不是 multimodality。

现在我不会优先做这个了。

因为 V18.5 已经证明监督改成 Y 后：

[

]

这远远大于我们之前期待 Diffusion 单纯解决 conditional mean 能带来的证据。

而且 normalized H：

[
mean|z_H|=0.261
]

最大：

[
5.10
]

但超过 (3\sigma) 的元素只有：

[
0.024%.
]

所以没有出现：

> 网络为了骗 Y-loss，把 MANO 参数跑到极端奇怪区域。

至少从参数统计上暂时看不到这个问题。

因此当前最合理的主链已经越来越清楚：

[
\boxed{
\text{Interaction encoder}
\rightarrow
H
\rightarrow
MANO
\rightarrow
Y
}
]

其中：

[
\boxed{
H=\text{structured generation variable}
}
]

而：

[
\boxed{
Y=\text{task supervision / transferable representation}.
}
]
