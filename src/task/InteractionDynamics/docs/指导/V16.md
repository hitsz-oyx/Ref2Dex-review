# InteractionDynamics V16：Object-Centric Interaction Representation

## 0. V16 的核心目标

V16 不继续强化 V15 的：

[
64_{\text{hand}}
\times
64_{\text{object}}
]

精细 hand-object contact correspondence。

V16 只验证一个更基础的问题：

> **ActionToken 与当前 World 融合后，能否形成一个以物体为索引、能够描述“动作作用在物体哪里”的 Interaction Representation？**

核心表示改为：

[
\boxed{
C_t^{obj}
=========

F(A_t,W_t)
\in
\mathbb R^{64\times384}
}
]

其中 64 个 token 与 **64 个 object patches 一一对应**。

第一阶段仅监督：

[
\boxed{
C^{obj}
\rightarrow
\text{Object Contact Field}
}
]

即预测：

> 未来哪些物体表面区域会与手发生接触。

V16 暂时不要求恢复：

* 哪一个 hand patch 接触哪个 object patch；
* 完整 hand trajectory；
* MANO 参数；
* ActionToken；
* 力；
* grasp taxonomy。

---

# 1. 为什么需要 V16

V15 使用：

[
C^{HO}\in[64,64]
]

作为监督。

也就是要求每一个 hand patch 判断：

> 自己最终会接触哪一个 object patch。

32-chunk V15.1 中，endpoint 时间对齐已经修正，并且 endpoint geometry oracle 可以达到：

[
99.92%
]

zero-baseline improvement，

以及：

[
F1\approx0.995.
]

因此 contact GT 本身没有问题。

但是当前 Cm：

* unweighted contact MSE 只比 zero 好约 6%；
* 正样本加权后 F1 约 0.46；
* articulation shuffle 几乎不影响结果；
* 8-step temporal readout 也没有明显改善。

因此当前瓶颈更可能是：

[
\boxed{
\text{Cm 尚未建立精确的 hand-patch}
\leftrightarrow
\text{object-patch correspondence}
}
]

而不是单纯的：

* GT 错误；
* loss 错误；
* ActionToken 不够好；
* temporal context 不够。

V16 因此主动降低第一阶段监督难度。

---

# 2. Ref2Dex 当前的核心思想

整个项目需要严格区分：

## 2.1 Pose / State

[
\boxed{
S_t=E_P(H_t)
}
]

表示：

> 当前执行体是什么构型。

---

## 2.2 Action / Motion

[
\boxed{
A_t=E_A(\Delta H_t)
}
]

表示：

> 当前执行体具体怎么动。

ActionToken 的目标是 **motion fidelity**：

[
A_t
\rightarrow
\Delta H_t.
]

因此如果任务只是：

> 复现 human demonstration 的具体动作，

最直接的方法就是：

[
A_H
\rightarrow
\Delta H_H
]

或者：

[
D(A_R,A_H).
]

这不需要 C。

---

## 2.3 Interaction

C 存在的真正理由不是重新描述 Action。

而是：

[
\boxed{
C=F(A,W)
}
]

表示：

> **这个动作放在当前世界中产生了什么交互意义。**

我们最终希望允许：

[
A_H\neq A_R
]

但是：

[
\boxed{
C_H\approx C_R.
}
]

例如：

* 人类用拇指和食指夹住杯子；
* 三指机器人使用完全不同的关节运动夹住同一区域；

两者 ActionToken 可以完全不同，但 interaction 应该相似。

因此：

[
\boxed{
A=\text{动作保真}
}
]

而：

[
\boxed{
C=\text{交互等价}
}
]

---

# 3. 一个必须坚持的判断原则

后续设计 C 时始终使用以下判断：

[
\boxed{
\text{如果某个 C 的目标可以直接通过匹配 ActionToken 实现，
那么这个 C 没有存在必要。}
}
]

因此 V16 明确 **不加入**：

[
C\rightarrow A
]

高精度重建监督。

也不加入：

[
C\rightarrow\Delta H
]

完整 point-flow reconstruction。

否则很容易得到：

[
C\approx A
]

使 C 退化成第二个 ActionToken。

---

# 4. V16 的核心改变

V15 是 hand-indexed：

```text
Hand Action Token j
        ↓
     Cm_hand[j]
        ↓
预测 64 个 object patches
        ↓
[64 hand × 64 object]
```

V16 改成 object-indexed：

```text
                    Action Tokens
                         ↓
Object Patch m ─────── query
                         ↓
                     C_obj[m]
                         ↓
                  Contact probability
```

即：

[
\boxed{
C_t^{obj}
=========

CrossAttn(
Q=W_{O,t},
KV=A_t
)
}
]

得到：

[
\boxed{
C_t^{obj}
\in
\mathbb R^{B\times8\times64\times384}.
}
]

这里：

> 第 (m) 个 C token 永远表示 object patch (m) 上发生的 interaction。

---

# 5. 为什么 object-centric 更适合 cross-embodiment

Human：

[
A_H
\rightarrow
C_H^{obj}
]

Robot：

[
A_R
\rightarrow
C_R^{obj}
]

虽然：

[
A_H\neq A_R,
]

但二者面对的是同一个 object space。

因此可以自然比较：

[
\boxed{
D(C_H^{obj},C_R^{obj})
}
]

而不需要建立：

[
64_{\text{human hand}}
\leftrightarrow
64_{\text{robot hand}}
]

这种执行体相关 correspondence。

因此 object-centric representation 更符合最终：

[
\boxed{
\text{cross-embodiment interaction prior}
}
]

的目标。

\in[64,64].

直接沿 hand 维聚合：

[
\boxed{

\max_j
C_{jm}^{HO}
}

得到：

[
\boxed{

\in[64].
}

物理含义：

> object patch (m) 是否被任意 hand surface patch 接触。

第一版直接使用 `max`。

不要：

* 新增 binary contact；
* 新增 hand semantic grouping；
* 调 contact direction；
* 引入力信息。

[

必须与：

[
O_{t+8}

计算接触。

在当前 object frame 中：

[
O_{t+8}

O_t+
\Delta O_{t+8}.

然后：

[

\min_{p\in patch_j}

h_{j,p}^{t+8}-o_m^{t+8}

[

\max_j C_{jm}^{HO}.

[
\sigma_c=0.01,m.

# 9. RootToken 暂时不进入 V16 Contact Path

V15 已经证明：

[
A^{root}
]

非常容易支配 rigid object motion。

但是 V16 第一阶段只问：

> 哪些 object patches 会发生 contact？

为了避免再次形成 global/root shortcut，

第一版 Contact branch 只读取：

[
\boxed{
A^{art}
}
]

不读取 RootToken。

原有 rigid Effect branch 可继续保留 RootToken。

因此：

```text
RootToken ─────────→ Rigid Effect

        ↓
Object-Centric C
        ↓
Object Contact Field
```

使用当前 WorldEncoder 的 object tokens：

[
W_O
\in[B,64,384].
]

对于每个 timestep：

[
A_t^{art}
\in[B,64,384].

增加 hand patch position embedding：

[
\tilde A_{t,j}
==============

A_{t,j}
+
E_H(x_{t,j}).

增加 object patch position embedding：

[
\tilde W_{O,m}
==============

W_{O,m}
+
E_O(o_{t,m}).

然后：

[
\boxed{
C_{t}^{obj}
===========

CrossAttn(
Q=\tilde W_O,
KV=\tilde A_t

}
]

输出：

[
[B,8,64,384].
]

不要继续使用 V15 的：

[
x_{t,j}=x_{0,j}

复制方式。

[
\boxed{
x_{t,j}
=======

x_{0,j}

\Delta x_{t,j}^{object}.
}

```python
hand_patch_0 = gather_points(
```

# 17. 不加入 Action Reconstruction Loss

V16 明确禁止：

[
C\rightarrow A
]

以及：

[
C\rightarrow\Delta H.
]

原因：

ActionToken 已经负责：

[
\boxed{
\text{motion fidelity}
}
]

C 应该负责：

[
\boxed{
\text{interaction abstraction}
}
]

如果两种不同动作：

[
A_1\neq A_2
]

在同一物体上形成类似交互：

[
I_1\approx I_2,
]

我们希望：

[
\boxed{
C_1\approx C_2.
}
]

因此强制精确重建 A 会与 V16 的目标冲突。

# 21. V16 的关键科学验收

## Gate 1：Contact 可拟合

要求：

[
\boxed{
MSE_{model}
<
0.5MSE_{zero}
}
]

即至少：

[

> 50%
> ]

zero-baseline improvement。

Controlled overfit 期望：

[

> 80%.
> ]

同时要求：

[
F1>0.
]

---

## Gate 2：Action 内容确实重要

要求：

[
Error_{art-zero}

>

Error_{normal}.
]

如果 articulation 全部置零仍然几乎不变，

说明模型还是只根据当前 World 猜 contact。

---

## Gate 3：Action 与 sample correspondence 重要

要求：

[
\boxed{
Error_{cross-sample}

>

Error_{normal}
}
]

或者：

[
F1_{cross-sample}
<
F1_{normal}.
]

这证明：

> 不同样本的动作不能随便互换。

---

## Gate 4：Local patch identity

继续观察：

[
articulation_shuffle.
]

但 V16 不要求第一版立刻出现巨大退化。

因为 object-centric attention 理论上可能更多依赖整体局部 motion distribution。

如果：

[
shuffle
]

明显恶化，是强正证据。

如果不恶化，但：

* zero 明显恶化；
* cross-sample 明显恶化；
* contact prediction 很好；

则先保留，再进一步研究局部 correspondence。

# 26. 建议实现形式

伪代码：

```python
action = articulation_action
action = action + self.hand_position(hand_patch_position)

obj = object_tokens + self.object_position(object_patch_position)

B, T, H, D = action.shape
O = obj.shape[1]

query = obj[:, None].expand(-1, T, -1, -1)
query = query.reshape(B * T, O, D)

context = action.reshape(B * T, H, D)

object_cm, attention = self.object_to_action(
    query,
    context,
)

object_cm = object_cm.reshape(B, T, O, D)

pred_object_contact = self.object_contact_head(
    object_cm[:, -1]
).squeeze(-1).sigmoid()
```

不要再额外加别的模块。

# 27. 推荐空间 bias

V16 第一版可以保留一个解析 spatial bias：

[
b_{mj}
======

-\frac{
|o_m-x_j|
}{\sigma}.
]

其中：

[
\sigma=0.05m
]

作为起始值。

Attention：

[
softmax
\left(
\frac{QK^\top}{\sqrt d}
+
b
\right).
]

这不是额外 supervision。

它只是告诉模型：

> 相距几十厘米的 hand/object patches 不应该具有和近邻 patch 相同的 interaction prior。

如果担心同时改变太多，可以先关闭 bias 跑 baseline，再开一个 controlled comparison。

# 29. V16 的失败解释

如果 object-contact 仍然无法 overfit：

[
\boxed{
\text{不要扩大训练。}
}
]

这时优先检查：

1. World object patch indexing；
2. dynamic hand patch position；
3. object-to-action attention；
4. contact target 的 object patch index 是否与 World encoder 一致。

不要第一时间：

* 加 Transformer；
* 加 Action reconstruction；
* 加更多 loss。

---

如果 object-contact 能很好 overfit，但 articulation-zero / cross-sample 几乎不变，则说明：

[
\boxed{
\text{World geometry 本身就可以预测 contact，
Action 仍未被使用。}
}
]

这时下一步应构造：

> 同一个 current World、不同 future Action

的 controlled pairs。

而不是继续增加 decoder capacity。

# 30. V16 最终希望验证的命题

V16 不试图证明：

> C 已经完整表示 grasp skill。

V16 只验证：

[
\boxed{
\text{Action + World}
\rightarrow
\text{Object-Centric Interaction Field}
}
]

是否成立。

更具体：

[
\boxed{
C_m^{obj}
\text{ 能否回答：
“这个动作将作用在物体的哪里？”}
}
]

如果这个最基础的命题都不能成立，

后面的：

* contact direction；
* grasp strategy；
* cross-embodiment matching；
* RL reward；

都没有必要继续。

# 31. 长期目标

最终 Human 和 Robot 可以具有完全不同的：

[
A_H,\qquad A_R.
]

但是如果二者：

* 接触相似的 object regions；
* 产生相似的 relative interaction；
* 达成相似的 object effect；

则希望：

[
\boxed{
C_H^{obj}
\approx
C_R^{obj}.
}
]

然后在下游 RL 中：

[
\boxed{
r_C
===

-D(C_R^{obj},C_H^{obj})
}
]

作为 interaction prior。

这才是 C 相对于直接 ActionToken matching 的真正价值。

---

# 32. V16 一句话定义

[
\boxed{
A=\text{How the embodiment moves}
}
]

[
\boxed{
C^{obj}=\text{Where and how that motion interacts with the object}
}
]

V16 第一版只验证其中的：

[
\boxed{
\text{Where}
}
]

即：

[
\boxed{
A+W
\rightarrow
C^{obj}
\rightarrow
\text{Object Contact Field}.
}
]

只有这个通过以后，再进入：

[
\text{How}
]

也就是 relative normal / tangential interaction。

---

# 33. V16 最重要的设计原则

整个 V16 必须遵守：

[
\boxed{
\text{ActionToken 保存动作差异，
InteractionToken 消除无关的动作差异。}
}
]

因此：

[
A_1\neq A_2
]

并不要求：

[
C_1\neq C_2.
]

只要两种动作在当前物体上产生相同 interaction，

理想情况应当：

[
\boxed{
C_1\approx C_2.
}
]

这也是未来 cross-embodiment transfer 的核心。
