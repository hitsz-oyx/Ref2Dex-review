对，我把最新 `8fa4594b` 这版代码和实验日志都看了。结论比较明确：

[
\boxed{\text{V3 目前没有解决核心问题，而且不像是一个明显的实现 bug。}}
]

更准确地说，**action / patch-effect 两个辅助监督已经正确接进去了，但它们只是两个旁路 head，没有改变主 Effect Decoder 的信息通路，因此主 decoder 仍然可以继续走原来的 global shortcut（全局捷径）**。

### 先看实验结果

small20 原 baseline 在 12/4/4 sequence-disjoint 划分下，train ADE 已经到 14.38 mm，但 val/test 只有：

[
49.05\rightarrow46.93\text{ mm}
]

[
45.82\rightarrow44.80\text{ mm}
]

只提升 4.3% / 2.2%，同时 interaction cosine 已经达到 0.9965 / 0.9987，基本接近 collapse。Uni3D 单位球输入也没有改善。

然后 V3 加：

[
L=L_{\text{effect}}+L_{\text{action}}+L_{\text{patch-effect}}
]

初始三个 loss 分别约：

[
19.02,\quad20.60,\quad19.65
]

说明没有明显的 loss scale 错误，三者量级也是一致的。模型训练一步也正常。可是 5 epoch 后 best val ADE 还是 48.82 mm，而且 interaction cosine 仍接近 1。更关键的是 intervention：

[
\begin{array}{c|cccc}
& normal & mean & shuffle & cross\
\hline
ADE &48.82&48.81&48.82&49.09
\end{array}
]

也就是说把 64 个 interaction token **全部换成平均值，或者彻底打乱顺序，结果几乎一模一样**。

这一项比单纯看 ADE 更有说服力：

[
\boxed{\text{主 decoder 仍然没有使用 object-indexed token identity。}}
]

## 为什么加了直接监督还是没用

现在代码实际上是三条并行支路。

第一条：

[
A_{\text{context}}
\rightarrow Linear
\rightarrow
\hat{\Delta H}_{patch}
]

第二条：

[
C_j
\rightarrow Linear
\rightarrow
\hat{\Delta O}_{patch}
]

第三条才是真正部署时用的：

[
C_{1:64}
\rightarrow EffectDecoder
\rightarrow
\hat{\Delta O}_{512}
]

代码就是单独的：

```python
self.action_reconstruction = nn.Linear(...)
self.patch_effect = nn.Linear(...)
self.effect = EffectDecoder(...)
```

Runner 再把三个 loss 简单相加：

[
L_{\text{effect}}
+L_{\text{action}}
+L_{\text{patch-effect}}.
]

问题在于：

> `patch_effect` 学好了，并不意味着 `EffectDecoder` 必须使用它。

它完全可以出现：

```text
interaction tokens
   │
   ├── patch_effect head
   │        ↓
   │    学局部 patch GT
   │
   └── Effect Decoder
            ↓
       继续走 global shortcut
```

所以这两个 loss 的确会向 interaction token 传梯度，但**没有强迫最终预测路径使用这些局部信息**。

这就是目前 V3 最大的问题。

---

# 更严重的 shortcut 就在 `EffectDecoder` 里面

现在 EffectDecoder 首先用：

```python
base = query([points, normals, z_obj])
```

然后 query 全部 64 个 interaction token：

```python
context = CrossAttention(query, interaction)
```

最后 flow head 又明确拿：

```python
[context, xyz, time]
```

预测点流。

这个结构对于 GRAB 刚体物体来说，存在一个极其自然的解。

刚体运动：

[
o_i'=Ro_i+t
]

因此：

[
\Delta o_i=(R-I)o_i+t.
]

所以 decoder 只需要：

[
\bar C
\rightarrow(R,t)
]

然后利用当前 point 自己的：

[
o_i
]

就可以计算：

[
(R-I)o_i+t.
]

也就是：

```text
64 interaction tokens
         ↓
几乎全部一样
         ↓
一个 global interaction vector
         ↓
       R, t
         +
current object xyz
         ↓
每个 point 不同的 flow
```

这实际上是一个**完全合理、而且比学习 64 个局部 interaction 容易得多的最优解**。

所以：

[
C_1=C_2=\cdots=C_{64}
]

根本不妨碍 object-flow loss 做得不错。

这也解释了为什么：

[
shuffle(C)
]

完全没有影响。

---

## V3 的 `patch_effect` 为什么也没强力阻止 collapse

这里还有第二个原因。

现在 patch-effect GT 是：

```python
patch_motion_target(
    obj_disp_chunk_gt,
    obj_knn_idx
)
```

即每个 object patch 的 KNN 点平均位移。这个实现本身是对的，而且 `obj_disp_chunk_gt` 使用完整 4096 stable-index object points，只在 Runner 里构建监督，没有喂进 model，因此我没有看到 target 构造或 future leakage 的明显问题。

但是 GRAB object 是刚体。

如果某个 chunk 主要是 translation：

[
\Delta O_1
\approx
\Delta O_2
\approx
\cdots
\approx
\Delta O_{64}
]

那你给 64 个 interaction tokens 加直接 patch-flow GT，实际上 64 个 target 本来就很像。

只有 rotation 足够明显的时候：

[
\Delta O_j=(R-I)o_j+t
]

不同 patch target 才明显不同。

因此它对“必须不同”的约束强度没有我们之前直觉上想象得那么大。

---

# Action supervision 也解决不了 object canonicalization

Action loss 本身是合理的：

[
A_j\rightarrow\Delta H_j.
]

而且目前确实用同一个 `hand_knn_idx` 从完整 hand displacement chunk pooling GT。

这可以防止：

[
A_1=A_2=\cdots=A_{64}
]

但我们的问题最终发生在：

[
A_{\text{context}}
\overset{Object\ Query}{\longrightarrow}
C
]

这一层。

即使：

[
A_1,\ldots,A_{64}
]

非常丰富，如果 canonicalizer 最终：

[
C_j
\approx
\frac1{64}\sum_iA_i
]

依旧解决不了。

所以：

[
L_{\text{action}}
]

可以保留，但它不是当前核心药方。

---

# 所以我现在不建议继续调三个 loss 的权重

比如：

[
\lambda_{\text{patch}}=5
]

或者：

[
\lambda_{\text{action}}=0.1
]

我不认为这是正确方向。

因为现在的问题不是：

> patch head 学得不够好。

而是：

> **patch head 和真正的 dense prediction path 是解耦的。**

把旁路 loss 放大 10 倍，只会让旁路更好，不保证主 decoder 开始使用 object-indexed token。

同样，我也不会加：

[
L_{\text{variance}}
]

或者强制 cosine 降低。

之前 `action_local_gain=10` 已经证明：

> token 看起来不 collapse ≠ decoder 真正在用 token identity。

---

# 下一步我认为应该做一个非常明确的 V4：结构耦合

不要再加监督。

直接让：

[
\boxed{\text{patch-effect prediction 成为 dense effect prediction 的一部分}}
]

现在是：

```text
C_j ──→ patch head ──→ patch GT
 │
 └────→ Effect Decoder ──→ dense GT
```

我要改成：

```text
C_j
 ↓
Patch Motion Head
 ↓
ΔO_patch,j
 │
 ├──────────────→ patch GT
 │
 ▼
Dense Effect Decoder
 ↓
ΔO_point
 ↓
dense GT
```

即：

[
\boxed{
C_j
\rightarrow
\Delta O_j^{patch}
\rightarrow
\Delta O_i^{point}
}
]

这样 `patch_effect` 就不再是 auxiliary head（辅助头），而是主预测链中的中间变量。

---

# 最小实现我建议这么做

对 512 个 effect query point：

[
q_i
]

找最近的 Uni3D object patch center：

[
j(i)
====

\arg\min_j
|q_i-c_j^O|.
]

当前 `world` 已经返回：

```python
obj_patch_centers_object
```

所以不需要改 Dataset。

然后：

### Step 1：Interaction token 直接预测 patch trajectory

已有：

[
C_j
]

通过：

```python
patch_effect
```

得到：

[
\hat D_{j,k}^{patch}
\in\mathbb R^3.
]

shape：

[
[B,8,64,3].
]

这部分代码已经存在，可以直接复用。

---

### Step 2：每个 effect point 只拿自己的 patch

不再：

[
q_i
\rightarrow
CrossAttn(C_1,\ldots,C_{64})
]

而变成：

[
q_i
\rightarrow
C_{j(i)}.
]

即：

```text
effect point i
      ↓ nearest patch
object patch j
      ↓
interaction token C_j
```

彻底去掉当前 EffectDecoder 对 64 tokens 的 global cross-attention。

---

### Step 3：dense flow 变成 patch flow + local residual

最终：

[
\boxed{
\hat{\Delta o}_{i,k}
====================

\hat{\Delta o}*{j(i),k}^{patch}
+
r*{i,k}
}
]

其中：

[
r_{i,k}=

MLP(
C_{j(i)},
q_i-c_{j(i)},
n_i,
e_k
).
]

注意这里我会**故意不再给 residual head absolute `xyz`**。

只给：

[
q_i-c_j
]

即 point 相对于所属 patch center 的局部位置。

否则：

[
global\ C + absolute\ xyz
]

这个 SE(3) shortcut 又回来了。

```text
              Action Chunk
                  ↓
            Action Tokens
                  ↓
           World-conditioned
                  ↓
             C1 ... C64
                  │
        ┌─────────┴─────────┐
        │                   │
        ▼                   │
patch motion head           │
        ↓                   │
 64 patch trajectories      │
        │                   │

                 ▼          │

```

这时 dense loss 自己就会反向要求：

[
C_j
]

必须对所属 object region 有用。

# 最关键的验收指标也会非常清晰

这次先不看：

[
cosine=0.7
]

还是：

[
variance=0.2.
]

真正的第一验收指标就是你现有的 `intervention.py`。它已经会做 normal / mean / shuffle / cross-sample，而且实现没问题。

V4 训练后必须满足：

[
\boxed{
ADE_{\text{shuffle}}

>

ADE_{\text{normal}}
}
]

而且不是 0.01 mm 这种数值误差。

我会直接把验收线定为：

[
\boxed{
\frac{ADE_{\text{shuffle}}-ADE_{\text{normal}}}
{ADE_{\text{normal}}}

> 10%
> }
> ]

同时：

[
ADE_{\text{mean}}
]

也应该明显变差。

如果做了强 local routing 后，shuffle 还是完全不掉，那我们才需要重新审视：

> “object-indexed 64 token”这个表示本身到底有没有必要。

## 还有一个更根本的问题值得现在明确

我们的最终目标是：

[
\text{human action mechanism}
\rightarrow C_m
\rightarrow
\text{robot action}.
]

而 GRAB object 是刚体。

从纯 object flow：

[
\Delta O
]

本身，最多稳定识别的是：

[
SE(3)
]

但：

[
\boxed{\text{相同的 }SE(3)\text{ 可以由完全不同的手部机制产生。}}
]

比如杯子向右移动 5 cm：

```text
食指从左推
```

和：

```text
整只手抓住后向右搬
```

都可能产生相似：

[
\Delta O.
]

所以即使我们把 V4 的 object-indexed routing 做成功，**object effect supervision 本身仍不能保证 interaction representation 保存完整“动作机制”**。

这也是为什么：

[
L_{\text{action}}
]

我建议继续保留。

它至少保证：

[
A_{\text{context}}
]

不能彻底退化成纯 object SE(3)。

最终更合理的分工是：

[
\boxed{
\begin{aligned}
L_{\text{action}}
&:\ \text{保留 human mechanism}\
L_{\text{patch-effect}}
&:\ \text{约束 local object consequence}\
L_{\text{dense-effect}}
&:\ \text{保证真实 world effect}
\end{aligned}}
]

但区别是下一版要让后三者**结构串起来**，而不是三个平行 head。

---

所以我对这轮代码的判断是：

**没有明显结果是预期现象。** V3 证明了“仅仅给中间 token 加直接监督”还不够；代码本身没有看到明显 target 错位或 future leakage。真正暴露出来的问题是：

[
\boxed{
\text{监督是局部的，但主 decoder 的计算路径仍然是全局的。}
}
]

下一步我会停止调 loss，直接做一个最小的 **patch-routed Effect Decoder**，把 `patch_effect` 强制接进 dense flow 主路径，然后继续用现成的 `intervention.py` 做验收。这会比继续在当前 V3 上训练 20 epoch 更有信息量。
