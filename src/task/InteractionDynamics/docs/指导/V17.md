# V17：Full-Data Interaction Knowledge Learning

## 0. 阶段目标

V16.5–V16.9 已完成单序列 controlled experiment。

当前确定：

[
S_t=[r_t,d_t]
]

[
G_t=[a_t,\Xi_t]
]

其中：

* (a_t)：active，当前是否需要 hand 参与该 object；
* (\Xi_t)：next meaningful 4-step object (\Delta T)。

未来 residual：

[
\boxed{
R_t
===

## F_t^{GT}

F_t^{persist}
}
]

其中：

[
F_t^{persist}
=============

[0,S_t,0,S_t,\ldots].
]

V17 不再研究单序列能否 overfit。

核心问题变成：

[
\boxed{
\text{能否从完整 demonstration 数据中学习可泛化的}
\quad
p(R_t\mid S_t,Z_O,G_t)
}
]

即：

> 给定当前 hand-object interaction、物体几何和目标 object motion，学习接下来 interaction 应该如何变化。

---

# 1. V17 核心原则

V17 保持：

[
\boxed{
\text{不人为划分 approach / grasp / manipulation / release 模型}
}
]

并且：

[
\boxed{
\text{不刻意进行 dynamic/static 数据平衡}
}
]

完整 demonstration 中合法的时刻原则上全部参与训练。

包括：

```text
远距离 approach
↓
靠近
↓
pre-contact
↓
contact formation
↓
stable grasp
↓
manipulation
↓
transport
↓
release
↓
withdraw
```

原因：

> “如何靠近物体”本身就是 interaction knowledge 的一部分。

模型应该从：

[
S_t,Z_O,G_t
]

自行学习不同阶段对应什么 residual。

---

# 2. 数据只做必要合法性过滤

不按照：

* hand-object distance；
* dynamic/static；
* phase；

筛选训练数据。

只删除无法构造监督的样本，例如：

```text
object pose 缺失

hand points 缺失

object geometry 缺失

未来不足 H 帧

数值 NaN / Inf

无法计算 Y

sequence 完全不存在 meaningful object motion，
导致 Goal 无定义
```

除这些必要情况外：

[
\boxed{\text{保留完整有效时间范围}}
]

---

# 3. Dataset

使用完整 GRAB / 当前 InteractionDynamics 可用数据。

每一个合法 frame (t) 构造：

### State

[
S_t=[r_t,d_t]
\in\mathbb R^{128\times4}
]

### Object

[
Z_O
]

仍使用：

```text
128 FPS anchors
32-NN local object patch
relative xyz + normal
```

### Goal

[
G_t=[a_t,\Xi_t]
\in\mathbb R^{25}
]

### Future

[
F_t^H,\qquad H=4
]

### Residual

[
\boxed{
R_t=F_t^H-F_t^{persist}
}
]

# 4. Active

继续使用 V16.6/V16.7 当前自动提取方法。

active 应覆盖：

```text

manipulation

```

不因为：

[

很大而自动变成 inactive。

如果 demonstration 中 hand 从远处开始持续朝 active object 靠近：

[

]

是合理的。

# 9. Full Dataset Sampling

第一版使用：

[
\boxed{\text{natural sampling}}
]

中文：

> 按数据集中实际存在的合法 frame 分布正常随机采样。

不使用：

```text

50% static

```

> 让模型直接学习真实 demonstration 分布。

如果后面明确观察到：

[

]

的 persistence collapse，再单独讨论 sampler。

V17 第一版不要预先修正一个尚未发生的问题。

# 13. 四卡训练

使用：

[
\boxed{\text{PyTorch DDP}}
]

DDP = Distributed Data Parallel。

中文：

> 每张 GPU 保存一份模型，每张卡处理不同 batch，反向传播后自动同步梯度。

使用：

```bash

  --standalone \
  --nproc_per_node=4 \
  ...
```

而不是单进程：

```python
DataParallel
```

---

# 14. DDP 数据分配

Train Dataset 使用：

```python
DistributedSampler(
    train_dataset,
    num_replicas=world_size,
    rank=rank,
    shuffle=True,
)
```

每个 epoch：

```python
sampler.set_epoch(epoch)
```

保证四张 GPU：

```text
GPU0 → batch A
GPU1 → batch B
GPU2 → batch C
GPU3 → batch D
```

不会四张卡读取完全相同的数据。

# 15. Global Batch Size

定义：

[
\boxed{
B_{\rm global}
==============

B_{\rm gpu}
\times
N_{\rm gpu}
\times
N_{\rm accum}
}
]

其中：

* (B_{\rm gpu})：每张 GPU batch；
* (N_{\rm gpu}=4)；
* (N_{\rm accum})：gradient accumulation steps。

例如：

```text
per_gpu_batch = 16
gpu = 4
grad_accum = 1
```

则：

[
B_{\rm global}=64.
]

# 18. Batch Size 选择规则

不要简单选择：

[
B_{\rm gpu}^{max}.
]

例如：

```text
B=32 → 20 GB
B=48 → 29 GB
B=64 → 39.5 GB / 40 GB
```

即使 64 能跑，也不建议正式训练。

保留：

[
\boxed{10%-15%\text{ 显存余量}}
]

用于：

* validation；
* allocator fluctuation；
* checkpoint；
* 不同 batch shape；
* CUDA kernel workspace。

因此：

[
\boxed{
B_{\rm train}
\approx
0.85\sim0.90
\times
B_{\rm OOM-limit}
}
]

按实际测试选择。

---

# 19. Batch Size 还要看吞吐

显存最大不代表速度最快。

记录：

[
\boxed{
\text{samples/sec}
}
]

例如可能出现：

```text
B=16 → 400 samples/s
B=32 → 620 samples/s
B=48 → 650 samples/s
B=64 → 645 samples/s
```

那么：

[
B=48
]

比 64 更合理。

因此最终 batch 选择依据：

[
\boxed{
\text{高吞吐}
+
\text{10-15% 显存余量}
}
]

而不是单纯“塞到 OOM 前一刻”。

# 22. Learning Rate

不要直接按照：

[
B
]

线性放大 LR。

单序列使用：

[
2\times10^{-4}.
]

V17 第一轮候选：

```text
1e-4
2e-4
4e-4
```

只需要在 batch probe 后，对最终 1-2 个 batch 候选做短测试。

默认优先：

[
\boxed{
lr=2\times10^{-4}
}
]

如果 global batch 很大且 loss 收敛明显变慢，再测试：

[
4\times10^{-4}.
]

不要直接使用：

```text
batch × 16
→ lr × 16
```

# 23. AMP

启用 mixed precision。

即：

[
\boxed{\text{BF16 优先}}
]

如果 GPU 支持：

```python
torch.autocast(
    device_type="cuda",
    dtype=torch.bfloat16
)
```

中文：

> 大部分矩阵运算使用 BF16，减少显存、提高 Tensor Core 吞吐。

但：

* normalization statistics；
* metric accumulation；

使用 FP32。

---

# 24. Gradient Accumulation

如果最佳 global batch 希望是：

[
128
]

但单卡只能：

[
B_{\rm gpu}=16,
]

4 GPU：

[
16\times4=64.
]

可以：

```text
gradient_accumulation = 2
```

得到：

[
B_{\rm effective}=128.
]

但优先：

[
\boxed{\text{真实 batch > gradient accumulation}}
]

如果显存允许，不要为了 accumulation 故意减小单卡 batch。

# 30. Normalization

这是多卡训练必须特别注意的地方。

禁止每张 GPU：

```text
各算自己的 mean/std
```

必须：

[
\boxed{
\mu,\sigma
\text{ 只根据完整 Train split 计算一次}
}
]

包含：

```text
state_mean/std
goal_mean/std
residual_mean/std
```

由 rank 0 计算 / 加载，然后 broadcast 给其余 GPU。

Validation 和 Test：

[
\boxed{
\text{必须使用 Train statistics}
}
]

禁止重新计算。
