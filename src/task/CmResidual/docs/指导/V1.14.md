## 1. DExplore base 已经被替换成我们刚讨论的 direct retargeting base

现在新增了：

```text
CmResidualGrabRetargeted
```

配置明确写的是：

```yaml
basePolicy:
  mode: retargeted_reference
  useOiCmContext: false
```

并且 observation 从原来的 1442-D 降到了 **68-D**。

这一点我认为是正确的。

现在 task 会判断：

```python
self.retargeted_base =
    cfg["basePolicy"]["mode"] == "retargeted_reference"
```

如果是这个模式，就**根本不加载 DExplore checkpoint**：

```python
self.teacher = None if self.retargeted_base else ...
```

并且使用新的 `RetargetedReferenceProvider`。

也就是说现在链路已经从：

$$
\text{reference}
\rightarrow
\text{1442D DExplore obs}
\rightarrow
\pi_{DX}
\rightarrow
a_{base}
$$

变成：

$$
\boxed{
\text{retargeted reference}
\rightarrow
q^{ref}_{t+1}
}
$$

这就是我们刚才讨论的结构。

# 2. 现在 zero residual 真正具有明确含义了

当前代码直接做：

```python
next_idx = idx + 1
target = self.reference.robot_q[next_idx]
self.base_action.copy_(target)
```

也就是说：

$$
a_t^{base}
=
q^{ref}_{t+1}.
$$

然后新的 `compose_reference_residual()` 做：

$$
q^{target}
=
q^{ref}_{t+1}
+
\Delta q^{RL}.
$$

其中 residual authority 仍然限制为：

$$
\Delta x_{\max}=15\text{ mm},
$$

$$
\Delta\theta_{\max}=0.2\text{ rad},
$$

$$
\Delta q_{\text{finger,max}}=0.08\text{ rad}.
$$

并且重新应用 mimic coupling 和 joint limit clamp。

因此现在：

$$
\boxed{
\Delta a=0
\Rightarrow
q^{target}=q^{ref}_{t+1}
}
$$

已经是严格成立的。

这比之前的：

$$
\Delta a=0
\Rightarrow
\text{whatever DExplore predicts}
$$

干净得多。

# 4. 68-D observation 也比原来的 1442-D 更符合我们的问题

现在 retargeted residual PPO 的 observation 是：

```python
[
    native_q,               # 18
    native_dq,              # 18
    target - native,        # 18
    current_object_pose,    # 7
    next_object_pose        # 7
]
```

总共：

$$
18+18+18+7+7=68.
$$

这个设计比 DExplore 的 1442-D 更容易解释：

$$
o_t=
[
q_t,\dot q_t,
q^{ref}_{t+1}-q_t,
T^{obj}_t,
T^{obj,ref}_{t+1}
].
$$

至少现在 residual policy 非常清楚地知道：

> 当前机器人在哪里、下一个 reference hand target 在哪里、当前 object 在哪里、reference object 下一步应该在哪里。

这已经很接近我们真正想训练的 residual controller。

# 6. Cmv2 的 action-conditioned evaluator 也已经实现

另一个很重要的变化是提交 `7d750d61...`。

现在已经有：

```text
cm_v2_action_evaluator.py
```

其设计注释非常明确：

> action realization 放在 learned model 外；
> controller targets → FK → nominal hand surface sweep → Cmv2。

这个基本就是我们之前讨论的：

$$
a_k
\rightarrow
q_{t+1}^{nominal}
\rightarrow

\rightarrow
\Delta H_k

C_m

而且现在 task 里面已经暴露：

> **OI-Cm/Cmv2 作为 candidate action effect evaluator 的基础设施现在已经存在了。**

这比以前单纯把 `cm_tokens` append 到 observation 强很多。

# 7. 但是——现在真正的问题已经转移到 PPO 训练目标上了

这里我要明确反对直接把当前 `CmResidualGrabRetargetedPPO` 当成最终方案跑很久。

因为 **reward 还是旧 reward**：

$$
r
=
20\cdot\text{lift}
-
2\cdot\text{tip-distance}
-
0.01\|\delta a\|^2.
$$

代码现在仍然是：

```python
reward =
    liftRewardScale * lift
    - distanceRewardScale * distance
    - actionPenaltyScale * residual²
```

这是一个很严重的概念不一致。

我们现在已经说：

> base = reference tracking
> residual = correct physical interaction so object follows reference.

那么 residual 的目标应该至少包含：

$$
T^{obj}_t
\rightarrow
T^{obj,ref}_t.
$$

但当前 reward 只问：

> “物体有没有升高？手指离物体近不近？”

它**根本不要求跟踪 reference object trajectory**。

---

## 举个非常具体的例子

reference 希望：

$$
\Delta z_{obj}=3\text{ cm}
$$

并同时向右平移 2 cm。

如果 residual 找到了一个方法：

$$
\Delta z_{obj}=10\text{ cm}
$$

而且完全不向右移动，

当前 reward 很可能反而更喜欢这个行为，因为 lift 更高。

也就是说当前 PPO 的最优解不是：

$$
T^{obj}_t\approx T^{obj,ref}_t,
$$

而更接近：

$$
\max z_{obj}.
$$

这和我们的研究问题已经不一致了。

# 9. 还有一个我们刚才讨论的问题，目前仍然没有解决：phase coverage

现在依然是：

$$
reference\_index=0
$$

开始，然后每一步：

$$
reference\_index\leftarrow reference\_index+1.
$$

也就是说仍然是完整：

```text
approach → contact → grasp → lift
```

从头开始跑。

仓库当前没有实现：

$$
k\sim p(k)
$$

然后：

$$
s_0\approx r_k
$$

的 randomized reference-state initialization / short-window curriculum。

所以你刚才指出的那个 credit assignment 问题仍然存在：

> 如果早期 grasp 学不会，后面的 lift correction 很难获得有效经验。

DExplore 用大规模训练、reference-scoped exploration 和 termination 来解决；我们现在的小 residual PPO 还没有对应机制。

我认为这是当前仓库下一步最值得解决的结构问题之一。

# 我对当前仓库状态的结论

我现在会把它画成：

```text
                     ┌────────────────────────────┐
GRAB retargeting ───>│ q_ref[t+1]                │
                     └─────────────┬──────────────┘
                                   │
                                   ▼
                           deterministic base
                                   │
                         q_ref + residual
                                   │
                      ┌────────────┴───────────┐
                      │                        │
                      ▼                        ▼
                  Isaac Gym              FK → hand sweep
                      │                        │
                      ▼                        ▼
                 actual object              Cmv2
                                               │
                                               ▼
                                      predicted effect
```

左边的 **base path 已经基本正确**。

右边的 **Cmv2 counterfactual path 也已经搭好了**。

现在缺的是中间这一块：

$$
\boxed{
\text{如何让 PPO 真正利用 Cmv2 和 reference effect}
}
$$

目前 PPO 还是：

$$
\delta a
\rightarrow
\text{lift reward}.
$$

我认为最终应该变成更接近：

$$
\delta a
\rightarrow
\hat{\Delta T}_{obj}
$$

与

$$
\Delta T^{ref}_{obj}
$$

比较，同时 simulator 的真实 transition 再提供实际 reward / correction。

## 所以我现在不会推翻仓库的新方向

相反，**最新两次提交把最关键的两个接口都改对了**：

1. `retargeted_reference` 代替 frozen DExplore 作为 nominal base；
2. `action → controller/FK → hand sweep → Cmv2` 已经实现。

但我也**不会直接开始大规模训练**。

当前最重要的顺序我认为是：

1. 先运行并看 `eval_grab_retargeted_base` 的 no-contact tracking 结果；
2. 确认 400/40 或其他 PD gain 下 wrist/finger/tip tracking 足够好；
3. 打开真实 object，做 zero-residual reference baseline；
4. 把 reward 从单纯 `lift + distance` 改成**reference object transition tracking**；
5. 加 randomized reference start / short-horizon curriculum；
6. 然后才把 `evaluate_cmv2_actions()` 真正接到 residual PPO 的决策或 auxiliary objective 里。

现在仓库离我们刚讨论的架构已经近很多了，但**真正的研究关键已经不再是 basepolicy，而是 residual training formulation**。
