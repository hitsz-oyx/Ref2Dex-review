# CmResidual V1.5 用户指导

- status: `user-confirmed`
- source: 用户在确认 V1.4 zero-residual baseline 可抓取后，要求“先做第 2 项工程门禁，再进入小规模 PPO pilot”，
  并明确同意 Agent 将已交接的具体边界整理为本指导。

## 目标

1. 先以固定、确定性的非零 residual 验证 physical target 增量、mimic、限幅、finite 和跨环境隔离；
2. 只有工程门禁通过，才运行 seed 42、64 env、2 PPO updates 的 GPU pilot；
3. pilot 只验证 PPO wiring、梯度/normalizer 数值、checkpoint 保存和独立重载，不据此宣称 residual 有效或训练收敛。

## 已确认边界

- 保持 V1.4 已验证的 frozen DExplore baseline、OI-Cm checkpoint、2005D observation、reward 数值、
  `0.015 m / 0.20 rad / 0.08 rad` residual 权限和 18D action schema。
- 18D action 中 6 个 mimic 输出没有直接 target 权限，pilot 保持这一既有兼容合同；本版本不改为 12D。
- 非零 gate 使用 4 env × 32 control steps：两个零 residual 对照、一个固定 `+0.25`、一个固定 `-0.25`；
  非零 action 覆盖全部 18 维，并分别核对实际有权的 wrist 6D 与独立 finger 6D。
- 首次 gate 后用户确认修订隔离判据：mimic 预期直接读取 runtime contract；跨环境隔离由 indexed reset 前后
  未目标环境的 DOF/root/target/progress 张量不变，以及零环境 applied residual 为零来判断。独立 PhysX 环境在
  接触后的 trajectory 差异只作诊断，不要求逐位相等。
- corrected reference 保持 `training_eligible=false` 且不修改；明确允许本次 gate/pilot 使用 legacy DExplore
  source 构造 observation/reset。该 override 必须 fail-closed、只允许显式的 `diagnostic` 或 `ppo_pilot` 用途，
  并写入 resolved config 与 run manifest。
- pilot 固定 seed 42、64 env、2 updates、horizon 32、minibatch 2048；从随机初始化 residual PPO 开始，
  使用空闲单 GPU。保存终态 checkpoint，并在独立 CPU 构造的相同网络上重复加载、比较固定输入 action。

## 禁止事项与停止条件

- 不修改 reference/manifest eligibility、GT、坐标系、reward、residual 尺度、DExplore/OI-Cm 权重、共享
  `src/base/`、外部 DExplore checkout 或其他 Task。
- 不启动超过 2 updates 的训练，不自动进入长训、超参搜索、并行 seed 或效果对照。
- 非零 gate 发生 non-finite、零对照 applied delta 非零、requested/applied delta 合同错误、mimic 错误、
  indexed reset 跨环境污染或异常退出时，
  标记 `INVALID_IMPLEMENTATION` 并停止。
- PPO 出现 non-finite observation/action/reward/loss/normalizer/model/optimizer、没有终态 checkpoint、独立重载不一致、
  没有完成 episode 或 simulator error 时，标记 `INVALID_IMPLEMENTATION` 并停止。
- 工程 smoke 结论最多为 `SUPPORTED`；residual 增益、抓取成功率改善和科研假设统一为 `INCONCLUSIVE`。
