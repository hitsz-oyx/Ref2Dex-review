我把 `ai/cmresidual/v121-cm-actor` 这条分支目前的 V1.21c 路径梳理了一遍。结论比较明确：**之前的 30 Hz replay bug 已经修对了，多环境 q/dq 不完全一致也不应该继续当成需要“修到 1e-5”的问题；现在真正应该先处理的是 duplicate calibration 本身还有几个协议级实现漏洞。**

### 现在这条线发生了什么

最早的 9-env prefix smoke 确实失败了：同一个 prefix 后，q 最大差大约 `0.0111 rad`、dq 大约 `0.5535 rad/s`，而 object root 只有微米级差异。当时协议要求所有公开状态 `<1e-5`，所以被判成 `INVALID_IMPLEMENTATION`。

之后你们发现了一个真正的实现 bug：

`DExploreTaskPrefixRuntime.step()` 原来一个 native action 只做了一次 `gym.simulate()`，实际上 DExplore 是：

```text
1 native action
→ pre_physics_step
→ 2 × 1/60s PhysX
→ post_physics_step
= 1/30s control step
```

现在 `src/task/CmResidual/v121c_prefix_replay.py` 已经改成调用官方 `_physics_step()`，并且强制：

```python
control_freq_inv == 2
```

这个修改是对的。**这一部分不用再动。**

之后 V1.21c 把 multi-env exact parity 降成 diagnostic，并用：

```text
[0,0,1,2,3,4,5,6,7]
          ↓
PCG64(candidate_seed) 随机分配到 9 个 env
```

candidate 0 的两个副本测 simulator noise。

Gate 0 的结果其实很好：

```text
duplicate object position ≈ 1.60e-6 m
duplicate object rotation ≈ 5.95e-7 rad
duplicate DOF divergence = 0
```

远小于：

```text
5e-4 m
5e-3 rad
```

所以**“多环境略有分叉”这个方向目前不应该再回去折腾 fresh simulator / exact clone。**

## 但现在 calibration 有一个必须先修的 bug

在：

`src/task/CmResidual/tools/v121c_calibration_replay_bootstrap.py`

里面的 `_loss()`：

```python
reference = task.hoi_data[data_ids, progress + 1]

goal_position = reference[:, 106:109]
goal_rotation = reference[:, 109:113]

...
reference_ig = reference[..., reference_ig_start:...]
```

也就是说当前 duplicate calibration 实际使用的是：

```text
object goal = reference[t+1]
IG ref      = reference[t+1]
```

但是你们 V1.21c FINAL plan 明确定义的是：

```text
object goal = T_ref[t+6]
IG target   = IG_ref[t+1]
```

也就是这两个时钟**本来就不一样**。

ranking core 里的定义实际上是对的：

```text
D_obj(T_next, T_goal=t+6)
E_IG(IG_next, IG_ref=t+1)
```

所以目前 calibration 用错了 object goal。

### 为什么这个问题很严重

你们后面要冻结：

```text
epsilon_PhysX
= max(
    5 * p99(abs(delta_S_duplicate)),
    1e-6
  )
```

而 `delta_S_duplicate` 正是这个 `_loss()` 算出来的。

所以如果现在直接跑 64-state calibration：

```text
错误 object goal
→ 错误 duplicate score difference
→ 错误 epsilon_PhysX
→ 所有 PhysX pair 的 tie 判定错误
→ ranking accuracy / top1 improvement 都会被污染
```

这不是简单的 log 问题，而是**会改变最终 Cm ranking scientific gate 的统计结果**。

---

## 推荐的修法：不要在 calibration 里再实现一套 score

当前最大的结构问题就是：

```text
v121c_ranking.py
    有正式 score 定义

v121c_calibration_replay_bootstrap.py
    又自己写了一个 _loss()
```

两套定义已经开始漂移了。

我建议在 `v121c_ranking.py` 增加一个公共的 PhysX scoring primitive，例如：

```python
physics_scores(
    current_pose,
    goal_pose_t6,
    current_ig,
    reference_ig_t1,
    next_pose,
    next_ig,
)
```

和现在的：

```python
cm_scores(...)
```

完全对称。

统一成：

```text
D0   = D_obj(T_t, T_ref[t+6])
D1   = D_obj(T_next, T_ref[t+6])

E0   = E_IG(IG_t, IG_ref[t+1])
E1   = E_IG(IG_next, IG_ref[t+1])

S = (D0-D1) + 0.5*(E0-E1)
```

然后 calibration、512-state ranking、offline evaluator **全部调用同一个函数**。

duplicate calibration 只需要：

```text
delta_S_duplicate
= S(slot_B) - S(slot_A)
```

这样以后就不会再出现一个地方 t+1、另一个地方 t+6 的漂移。

## 所以我建议现在不要直接跑 64-state calibration

当前正确的顺序应该是：

## 关于之前的 multi-env divergence，我的判断

你们现在的处理方向是合理的：

```text
不再声称 9 env 是 exact counterfactual clones
        ↓
随机 candidate-env allocation
        +
duplicate anchor
        +
epsilon_PhysX
        ↓
把 simulator divergence 当成实验噪声
```

这比继续追求 q/dq `<1e-5` 更符合实际。

但有一个原则要坚持：

> `epsilon_PhysX` 必须来自**和正式 ranking 完全相同的 score 定义和 replay protocol**。

现在恰恰差在这里。

如果后面 64-state calibration 得到的 `epsilon_PhysX` 很大，以至于大量 candidate pair 都被判成 tie，也**不要再人为减小 epsilon 或放宽统计规则**。那说明当前 K=8 / σ 邻域里的物理效果差异已经和 simulator noise 同量级，结果应该是 `INCONCLUSIVE`。那时再讨论 candidate scale 或更合适的 action neighborhood。

### 当前状态我会这样定

```text
30 Hz replay contract          ✅ 已解决
multi-env exact parity         ✅ 已正确降级为 diagnostic
randomized duplicate Gate 0    ✅ 已通过

64-state collector             基本可用
duplicate calibration          ⚠️ 先别正式跑
                              ├─ object goal 时钟错误
                              ├─ Python runtime 未固定
                              └─ 24/24/16 未 hard-gate

512-state Cm ranking           ⛔ calibration 修完前不要开始
PPO / Cm actor integration     ⛔ 更不应该现在开始
```

所以目前不需要推翻 V1.21c。**修好 calibration 这三个点，然后继续 64-state noise calibration，是最短的正确路径。**
