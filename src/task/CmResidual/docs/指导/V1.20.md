# CmResidual V1.20 指导：单序列官方 DExplore 复现

## 研究目标

重建上游 `NVlabs/dexplore` 的 Inspire GRAB teacher，只处理 `s1_airplane_lift`，从零初始化训练 153 个 PPO epoch。该运行用于回答上游单序列训练能否在本机按公开转换器与可审计的输入重建合同执行；不将其与本地 fork 数据训练或 CmResidual/Cmv2 结果混同。

## 已确认事实

- 现有 `inspire_geometric`、`inspire_rl_object_dexplore` 与上游转换结果在全部语义字段 `0:391` 存在实质差异。
- 本机 `dexplore_grab` 的 contact 为 30 Hz，而上游转换器按 120 Hz 的 `4*t` 索引读取。此前通过重复每帧 contact 的临时视图只能用于诊断，不能产出官方复现数据。
- 当前 SAPIEN 2.2.2 与上游转换器期望的旧 API 不兼容；headless port、路径重定向或任何修改转换器的做法都不能作为 V1.20 的正式数据路径。

## 范围与不变量

- 固定数据集为原始 GRAB 的 `s1_airplane_lift`，固定 Inspire 手、上游 598-D tensor schema、上游 reward/observation/action/physics、seed 42、从零初始化和 153 PPO epoch。
- 必须从清洁、固定 commit 的上游 DExplore 与其匹配的 InterAct/依赖快照运行未改动的上游转换器；输入 contact 必须原生满足 120 Hz 合同。
- 用户明确授权一个 Task-local reconstruction adapter：它只将既有 30 Hz `body`/`object` 与原始 GRAB 的 native-rate contact 组装为 DExplore 输入，禁止插值、重复、过滤或数值改写 contact。公开仓库缺失该 producer，因此结果必须标为 reconstructed baseline，不能声称与作者未发布 producer 完全等价。
- 先执行数据转换与 1-iteration PPO smoke。只有转换、loader、PPO、checkpoint 和 event 均通过，才启动正式训练。
- 现有本地处理数据、DExplore checkout、V1.17.5 双卡训练、CmResidual/Cmv2 代码、checkpoint 与 outputs 均保持不变。

## 禁止事项

- 不使用 30 Hz contact 重复、headless SAPIEN 兼容 port、资产路径软链接补丁或本地 fork 转换逻辑作为正式重建数据。
- 不覆盖现有 data/cache/output/checkpoint，不从 V1.17.5 或任何本地 fork checkpoint 续训，不把工程 smoke 或训练 reward 表述为抓取成功。
