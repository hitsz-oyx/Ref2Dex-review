
# 当前 Cmv2 最重的地方在哪里

现在输入：

```text
object: 1024 points
hand:   1538 points
K=8 candidates
```

而每个 candidate 都要做 swept interaction。

核心 `swept_topk()` 本质上是在找：

$$
1024\times1538
$$

的手物轨迹邻域。

单 candidate 大约是：

$$
1.57\text{ million}
$$

个 object-hand pair。

K=8：

$$
12.6\text{ million}
$$

pair / state。

然后每个 object point 还保留 `knn_k=32`：

$$
1024\times32\times8
$$

约 26 万条 interaction edges，送进 edge MLP。

这就是之前显存爆掉的根源。V1.18 记录里：

```text
128 env × K=8
→ 首次 Cmv2 interaction graph
→ 额外申请 2.84 GiB
→ OOM
```

后来 V1.19 为了不 OOM 又做了：

```text
env microbatch = 16
object chunk = 32
```

但这样本质上是：

> **用串行换显存。**

所以显存好了，吞吐自然变差。

# 还有一个值得注意的问题

现在：

```python
predict_effect_only(...)
```

实际上并不是真正的“轻量 effect head”。

它内部还是：

```python
output = self.predict(...)
```

而 `predict()` 会跑完整：

```text
geometry encoder
→ swept top-k interaction
→ edge MLP
→ contact feature
→ competitive tokens
→ token encoder
→ cross attention
→ effect head
→ structured object flow
→ Cm token projection
```

最后才只取：

```python
delta_xi_root
token_mask
token_mass
```

所以名字是 `effect_only`，计算图却基本不是 effect-only。

# 我认为应该砍，但不是简单把网络层砍掉

我会把优化分成两级。

## 第一级：不重新训练，先把重复计算消掉

现在 8 个 candidate：

```text
object geometry      完全一样
current hand geometry 完全一样
只有 hand_flow / next hand pose 不一样
```

但当前是把：

```text
[B,K]
```

直接 flatten 成：

```text
[B×K]
```

于是 object：

```text
1024 points
```

被完整复制 K 次。

geometry encoder 也跑 K 次。

这是明显浪费。

应该改成：

```text
shared state encoder:
object points/normals
current hand points/normals
        ↓
只算一次

candidate-dependent:
a0...a7
→ hand flow
→ interaction update
→ effect
```

至少：

$$
\text{object geometry encoding}
$$

不能 ×8。

---

## 第二级：真正做一个 planner fast path（这个先不做）

我更建议把 Cm 拆成：

```text
State encoder
      ↓
compact interaction representation
      │
      ├── action a0 → effect
      ├── action a1 → effect
      ├── ...
      └── action a7 → effect
```

也就是：

$$
z_t=E(s_t)
$$

只算一次。

然后：

$$
\Delta\xi_k=F(z_t,a_k)
$$

而不是：

$$
F(\text{1024 object points},
  \text{1538 hand points},
  \text{1538 flow}_k)
$$

从头算 8 遍。

这才是适合 planner 的 world model 形式。

# 具体最该砍的是 swept point-pair search

我认为最值得重新设计的不是：

```text
128 hidden width → 64
4-head attention → 2-head
```

这些可能只能省一点。

真正的大头是：

$$
1024\times1538\times K
$$

的 swept geometric neighborhood construction。

应该把 candidate scoring 从“dense point interaction”变成：

```text
当前 state:
高精度点云 → contact/surface tokens
                ↓
             16 tokens

candidate:
18-D action / link delta
        ↓
token-action interaction
        ↓
predicted effect
```

也就是说，**点云到 token 的昂贵过程只做一次。**

8 个候选只在：

```text
16 tokens × candidate
```

级别上计算。

复杂度会完全不同。

# 我建议下一步不要马上改网络

先做一个非常小的 latency profile。

分别测 single state：

```text
K=1
K=2
K=4
K=8
```

并拆时间：

```text
1. candidate generation
2. FK
3. hand surface generation
4. swept_topk
5. edge/contact encoder
6. token + attention + effect head
7. scoring
```

用 CUDA Event 测，不用 wall-clock `time.time()`。

这样我们会马上知道类似：

```text
K=8 total       42 ms

其中
FK                1 ms
surface geometry  3 ms
swept_topk       25 ms
edge MLP          9 ms
token/head        2 ms
other             2 ms
```

还是另一种情况。

如果确实是我现在从代码判断的：

> `swept_topk + local interaction` 占绝大多数，

那就不用浪费时间优化 PPO、attention、MLP 小层。

直接重构 interaction representation。
