I checked the newest repository state. The important change is that **CmResidual has advanced to V1.3.2**, and the team correctly stopped before PPO because the zero-residual base-policy gate failed.

### What has been fixed

The three training-critical issues we discussed have essentially been implemented:

* DExplore's contact observation now comes from the Isaac Gym **net contact-force tensor**, rather than hand-link velocity.
* The residual no longer has DExplore-sized authority. It is applied after converting the frozen DExplore action into physical targets, with bounds of **15 mm wrist translation, 0.20 rad wrist rotation, and 0.08 rad independent-finger correction**.
* OI-Cm is frozen, has the correct `32-D × 16 slots` contract, and the task is now its single owner instead of loading redundant copies. The combined policy observation remains \(1442+563=2005\) dimensions.

The physical residual code itself now has the structure we wanted:

$$
a^{DExplore}
\rightarrow
q_{\rm base}^{target}
$$

followed by

$$
q^{target}
=
q_{\rm base}^{target}
+
\delta q_{\rm physical},
$$

with mimic-joint reconstruction and joint-limit clamping afterwards. Zero residual therefore exactly reduces to the frozen base target mapping.

The test suite reportedly reaches **8 passing CmResidual tests**, including configuration/contact/zero-residual contracts.

## The important new result: zero-residual DExplore failed behaviorally

They then did exactly the test I wanted before PPO:

$$
\delta a_t=0
$$

for 4 environments and up to 367 control steps.

Engineering parity worked:

* observations remained finite;
* targets remained finite;
* residual action was exactly zero;
* residual-induced target difference was exactly zero.

But the physical behavior was clearly wrong:

$$
\text{contact occupancy}=0
$$

throughout, and

$$
\text{mean fingertip-object distance}
=
\boxed{1.421636\ {\rm m}}.
$$

There was an apparent maximum lift of about

$$
0.0885\ {\rm m},
$$

but because there was **no contact**, the log explicitly says this cannot be treated as grasp/lift performance. Isaac Gym also hung for more than seven minutes during `destroy_sim`, so the run was terminated. The final classification is `FAILED / INVALID_IMPLEMENTATION`, and **PPO was not started**.

This is actually a useful result.

It tells us we should **not currently blame Cm, PPO, critic design, or residual authority**. The base environment/reference is already wrong before any residual action exists.

# The current blocker is now the reference/base-state contract

The repository has also documented why the reference is suspicious.

The current reference manifest is still explicitly

$$
\texttt{training\_eligible=false}.
$$

One reason is that the source data do not contain a real raw contact flag; the existing 5 cm candidate mask is only geometric proximity and was correctly *not* relabeled as true contact.

More importantly, the earlier D0 audit found significant problems in the original retargeted wrist trajectory. Within the nominal contact interval, some frames still have large local wrist jumps; the old retarget optimizer allowed the six virtual wrist DoFs to compensate for finger errors, producing wrist behavior much more aggressive than the original GRAB wrist. There were also 44 transitions violating at least one URDF joint-velocity limit, 17 of them inside the main reference interval.

A replacement reference was subsequently generated using:

$$
\boxed{\text{one fixed }X_{HB}+\text{only q6 optimization}}
$$

over the 367-frame interval corresponding to source indices \(44\ldots410\). That fixed the wrist-compensation issue considerably, but because a trustworthy raw contact label is unavailable, the artifact remains non-training-eligible.

## What this means scientifically

The architecture we have been discussing has **not yet really been tested**.

The latest V1.3 deliberately preserves:

$$
\text{frozen DExplore}
+
\text{retrospective frozen OI-Cm}
+
\text{563-D Cm context}
$$

and explicitly postpones prospective/action-conditioned Cm, SE(3) effect heads, articulated tokens, online Cm learning and reward modifications.

So the present failure says nothing about:

$$
\text{Does Cm help RL?}
$$

It says:

$$
\boxed{
\text{our frozen DExplore wrapper does not yet reproduce a physically sensible base rollout}.
}
$$

Given a mean fingertip-object separation of **1.42 metres**, this is not a small tracking-quality issue. It strongly suggests a world-frame/reset/reference/asset alignment problem somewhere in the base pipeline.

### My current priority would therefore be

Before changing Cm again, I would trace one single zero-residual environment at \(t=0\) and compare:

$$
T_{\rm wrist}^{sim},
\quad
T_{\rm wrist}^{ref},
\quad
T_{\rm object}^{sim},
\quad
T_{\rm object}^{ref},
$$

and the five fingertips in the same world frame.

Then do the same at the first intended contact frame.

I would specifically verify the fixed \(X_{HB}\), robot root pose, object initial pose, reference-frame offset, and DExplore's native reset semantics. With a 1.42 m tip-object gap, I expect the cause to become obvious from those transforms.

**I agree with the repository's current decision not to launch PPO.** The residual/OI-Cm wiring is now sufficiently close to what we wanted; the urgent problem has moved upstream to making the frozen DExplore/reference base physically valid. Once zero residual produces the expected hand-object encounter, then the Cm/no-Cm RL experiment becomes meaningful.
