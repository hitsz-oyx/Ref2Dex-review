I checked the latest `oyx` state. The most important change is that the repository has now reached **`CmResidual V1.8`**, while **`ObjectInteractionCm` is still officially V1.3.2**.

The V1.8 result is useful because it isolates the residual-RL problem much more cleanly.

### What V1.8 changed

The new safe residual experiment deliberately **turns OI-Cm off** and keeps the DExplore 1442-D observation only. It retains the 18-D residual interface, but changes the stochastic policy initialization to:

$$
\mu_{\delta a}=0
$$

and

$$
\sigma=0.1
$$

with sigma frozen during the stability gate. The config literally uses

$$
\log\sigma=\log(0.1)=-2.302585...
$$

and `learn_sigma: false`.

So this directly tests the diagnosis we made after V1.7:

> Residual RL should start in the neighborhood of the competent DExplore policy rather than immediately injecting order-one random corrections.

The V1.8 plan explicitly says this is a **no-Cm experiment** and must not be used to judge OI-Cm. It also intentionally retains the 18-D action space, current reward, physical residual bounds, mimic mapping, and clamp behavior.

---

## And the result is much better

The controlled sequence was:

$$
B0
\rightarrow
T10
\rightarrow
E10
\rightarrow
T20
\rightarrow
E20.
$$

The deterministic evaluations are:

| Stage             | mean per-env max lift | contact occupancy |
| ----------------- | --------------------: | ----------------: |
| B0, zero residual |            0.085096 m |          0.193631 |
| E10               |            0.085426 m |          0.225536 |
| E20               |            0.082827 m |          0.325996 |

Relative to B0:

$$
E10:
\quad
\text{lift}=1.0039,
\quad
\text{contact}=1.1648
$$

and

$$
E20:
\quad
\text{lift}=0.9733,
\quad
\text{contact}=1.6836.
$$

Both pass the predefined 80% preservation gate. During stochastic training, residual RMS is only about 0.105 at epoch 10 and 0.107 at epoch 20 instead of the ~0.7–0.85 seen in V1.7.

This is a very important result.

It strongly supports our earlier diagnosis:

$$
\boxed{
\text{V1.7 collapse was mainly an exploration/initialization problem}
}
$$

rather than evidence that

$$
\boxed{
\text{residual RL itself is fundamentally incompatible with DExplore}.
}
$$

The repo is correctly careful: this only establishes **short-term preservation stability**, not that residual PPO improves grasping. E20 lift is actually about 2.7% below B0, while contact occupancy rises substantially.

So I would describe V1.8 as:

> **We now know how to train a residual without immediately destroying the base policy.**

That is exactly the prerequisite we needed.

# What changed in the network implementation

`CmBuilder` now supports an explicit `learn_sigma` flag. When `fixed_sigma=True` and `learn_sigma=False`, the sigma parameter has gradients disabled.

This is a small code change but scientifically important because the exploration scale is now truly controlled.

Also, V1.8 keeps **18-D**, rather than switching to our proposed 12-D reduced space. The plan explicitly preserves the mimic/null directions and the existing physical residual mapper.

Given the result, I agree with that choice for now. The 18-D redundancy was clearly **not the primary failure**.

---

# Where I think the project stands now

We have essentially solved one layer:

$$
\boxed{
\text{DExplore base + small residual PPO can remain stable.}
}
$$

The next scientific question is finally the one we actually care about:

$$
\boxed{
\text{Does OI-Cm improve residual learning?}
}
$$

And now we can test it without the huge confound from V1.7.

I would **not** immediately switch the full 563-D Cm context back into both actor and critic.

I would do this incrementally.

### Experiment A — already completed

$$
\pi_{\rm res}(o_{1442}),
\qquad
V(o_{1442})
$$

No Cm.

This is V1.8.

### Experiment B — Cm in critic only

Keep the actor **identical**:

$$
\pi_{\rm res}(o_{1442}).
$$

But let the critic see:

$$
\boxed{
V_\phi(o_{1442},C_m)
}
$$

or eventually:

$$
V_\phi
(
o_{1442},
C_m,
\hat e,
e^\star-\hat e
).
$$

This is the cleanest test of the proposition we've been discussing:

> Does physical interaction representation improve value estimation / advantage estimation while leaving exploration unchanged?

If B learns faster or preserves behavior better than V1.8, Cm has demonstrated actual RL utility.

### Experiment C — Cm into actor as well

Only after B.

Then:

$$
\pi_{\rm res}
(
o,
C_m,
e^\star-\hat e
)
\rightarrow\delta a.
$$

That tests whether Cm can actively guide corrections.

This staged design is much more interpretable than immediately returning to the old 2005-D actor+critic input.

# One thing has **not** changed yet

The committed branch does **not** yet contain the OI-Cm redesign we were just discussing:

* stride = 1 as the new formal OI-Cm training contract;
* swept candidate hand motion;
* soft 2–3 cm interaction halo;
* action-advected next-frame proximity;
* grounded part/contact tokens.

The official version pointer remains:

$$
\texttt{ObjectInteractionCm = V1.3.2}.
$$

The V1.8 commit also explicitly says there were unrelated `ObjectInteractionCm` user modifications in the working tree that were **excluded from the commit**.

So if you've already modified OI-Cm locally after our stride-1 discussion, those modifications are not visible in the GitHub branch I can inspect yet.

## My assessment after these changes

The project is in a substantially better position than a few hours ago.

Before V1.8 we didn't know whether:

$$
\text{residual RL}
$$

could even coexist with DExplore without destroying it.

Now we have evidence that it can.

Therefore I would **stop changing residual PPO for the moment**. The `μ=0, σ=0.1` safe setup should become the controlled baseline.

The next two pieces should be developed independently:

$$
\boxed{\textbf{Track 1: OI-Cm V2}}
$$

Implement the stride-1 / swept-soft-contact representation we just discussed.

And:

$$
\boxed{\textbf{Track 2: critic-only Cm ablation}}
$$

Using the current frozen OI-Cm checkpoint first, so we can determine whether even the existing representation adds value to PPO.

Only after those two are understood would I combine

$$
\text{new OI-Cm V2}
+
\text{actor-conditioned residual RL}.
$$

The most important takeaway from the warehouse is therefore:

$$
\boxed{
\text{the residual-control stability problem is now largely isolated;
the research bottleneck moves back to Cm itself.}
}
$$

That is a much cleaner place to be than V1.7.
