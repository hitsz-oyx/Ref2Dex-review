## 1. 研究问题、假设与范围

### 1.1 只回答一个问题

在官方 DExplore policy 实际访问到的 Inspire + PhysX interaction states 上，冻结的 Cmv2
能否把当前 policy mean 附近的 8 个 native actions 按真实 one-step 物理效果排好序，并且
Cm top-1 相对 actor mean 产生真实正改善？

### 1.2 假设与结论上限

- `H_CmRank`：Cm 的 candidate ranking 与 one-step PhysX ranking 的 pairwise accuracy
  至少达到 `0.60`，且 block-bootstrap 95% CI lower bound 大于 `0.50`。
- `H_CmImprove`：Cm top-1 相对 actor mean 的 PhysX improvement 成功率至少 `0.55`，
  且其 block-bootstrap 95% CI lower bound 大于 `0.50`；平均 improvement 的 CI lower
  bound 大于 `0`。
- 通过后结论最多为 `SUPPORTED`：Cm 具备可用于下一阶段蒸馏的 local action-ranking
  evidence。不得据此声称抓取成功、策略收敛、跨序列泛化或 Cm 因果改善 PPO。
- 样本不足、阶段配额不足或统计条件不满足但实现本身有效时为 `INCONCLUSIVE`；公开状态
  parity、duplicate-anchor、finite 或输入合同失败时为 `INVALID_IMPLEMENTATION`；有效
  样本充分但 ranking gate 未通过时为 `REFUTED`。

### 1.3 明确排除

本计划不实现或运行：

- PPO loss、Cm distillation、actor/critic integration；
- P=3 imagined rollout；
- asynchronous teacher worker、replay freshness 或 queue contract；
- confidence/calibration network 或 Cmv2 fine-tune；
- 多物体、多序列泛化结论；
- 任何长训练、checkpoint 续训或把 Cm 直接接入 rollout action。

## 3. Collector 合同：`collection_batch`

### 3.1 目标规模与资源

一个 `collection_batch_id` 的目标是：

```text
N_collected_unique = 512
N_rank_valid       >= 384  # 后续 parity/Cm/PhysX gate 后
max_collection_episodes = 64
```

每个 episode 使用一个固定 seed：`seed = 5909 + episode_id`，`episode_id=0..63`。
默认沿用已验证的官方评估入口（单 collector env、GPU0）；启动前必须检查 GPU0 和
运行时依赖，资源不可用时停止并请求确认，不自动换卡或改变环境规模。

### 3.2 官方 policy state distribution

- 加载并校验官方 checkpoint；不训练、不更新 RunningMeanStd；
- 使用官方 Gaussian policy distribution 采样实际 collector action；关闭 DExplore
  epsilon-greedy override；
- policy 的 `mu`/`sigma` 取已经由 model 产生的 `res_dict["mus"]` 和
  `res_dict["sigmas"]`，保存为 float32；
- action history 同时记录 policy sample 和经过 DExplore action wrapper 后真正传给
  `env.step()` 的 executed action；prefix replay 只重放 executed action；
- Python、NumPy、Torch 和 simulator seed 全部由 episode seed 固定，并写入 manifest；
- 只收集满足 `t <= L-1-H_ref`、observation/state finite、active 且 state_id 未重复的
  state。超过 phase quota 的 state 不替换已选 state，最终按 canonical `state_id` 排序
  做 deterministic selection。

`state_id` 使用 canonical little-endian contiguous float32 bytes 计算：

```text
SHA256(checkpoint_sha256 || seed || episode_id || frame_id ||
       raw_obs_1442_bytes || executed_action_prefix_sha256)
```

同一 `state_id` 不得重复。不同 episode 即使 reference frame 相同，只要 state/action
prefix 不同，可以作为不同 state。

### 3.3 Active 与 phase quota

使用官方 5 个 contact bodies 的 net contact force，阈值为 `||F||_inf > 0.1 N`；使用
tip key bodies `[3,6,9,12,15]` 和 DExplore 256-point object surface。

```text
C_actual = any contact force > 0.1 N
N_actual = min tip/object surface distance <= 0.04 m
C_ref    = any reference hand-object contact in [t,t+6] with label > 0.5
M_ref    = object translation over [t,t+6] >= 0.002 m
           OR rotation geodesic over [t,t+6] >= 0.01 rad
N_ref    = min reference tip/object distance over [t,t+6] <= 0.04 m

Active   = C_actual OR N_actual OR C_ref OR (M_ref AND N_ref)
```

phase 互斥且优先级固定为 `moving > contact > precontact`：

```text
moving     = M_ref
contact    = NOT moving AND (C_actual OR C_ref)
precontact = Active AND NOT moving AND NOT contact
```

全局 quota 固定为：

```text
moving     = 192
contact    = 192
precontact = 128
```

不跨 bucket 补位。64 个 episode 后仍无法填满任一 bucket，停止并报告
`collection insufficient`，不得复制 state 或用其它 phase 填充。

## 4. Candidate 合同

对每个 selected state：`K=8`，candidate 0 是 actor mean baseline。

```text
mu    = res_dict["mus"]       # post-activation model output
sigma = res_dict["sigmas"]    # post-activation model output

a[0]  = clip(mu, -1, 1)
a[k]  = clip(mu + sigma * epsilon[k], -1, 1), k=1..7
epsilon[k] ~ iid Normal(0, I_18)
candidate_std_multiplier = 1
```

candidate RNG 使用独立 CPU `torch.Generator`，避免 GPU scheduling 影响复现。其 seed 为：

```text
candidate_seed = uint64_le(SHA256(collection_batch_id || state_id)[0:8])
```

生成 float32 epsilon 后再传 GPU。每个 candidate 都调用官方 `_action_to_pd_targets`
语义，并传入 `candidate.clone()`；不额外 clamp PD target，不引入 residual 或 reference
residual。

```text
candidate_valid = finite(action) AND finite(PDTarget(action))
cm_valid = candidate_valid
             AND finite(delta_xi_root)
             AND finite(token_mass)
             AND token_mask.any()
             AND token_mass.sum() > 0
```

一个 state 至少需要 `4/8` 个 `cm_valid` candidates 才有资格进入 ranking statistics；
否则记录为 collection state，但不计入 `N_rank_valid`。

## 5. Cmv2 几何与 score

### 5.1 Cmv2 输入

Cmv2 内部输入继续使用 bridge 提供的 1024 object points/normals、1538 hand
points/normals 和 one-step hand flow，`dt=1/30`。这些点只属于 Cmv2 world-model 输入，
不能替代实验 score 的 DExplore canonical IG。

### 5.2 Canonical IG

Cm score 与 PhysX score 都使用完全相同的 DExplore canonical IG：

- key bodies：`[0,3,6,9,12,15]`，顺序与 `_key_body_ids` 一致；
- object surface：DExplore 的 256 点，sampling seed/mesh SHA 固定；
- 每个 key body 取最近 object point displacement `d_i=h_i-p_i*`；
- displacement 转到当前 root heading frame，得到 `g_i`；
- `IG=[g_1,...,g_6] ∈ R^18`。

```text
E_IG(IG, IG_ref) = (1/6) * sum_i ||g_i - g_i_ref||^2 / 0.02^2
```

`IG_t` 与 `IG_ref[t+1]` 比较；candidate/PhysX next IG 也用同一函数计算。

### 5.3 Object progress 与 Cmv2 pose composition

```text
T_goal = T_ref[t+6]
D_obj(T,T_goal) = ||p-p_goal||^2 / 0.02^2
                  + d_R(R,R_goal)^2 / 0.05^2
d_R(R1,R2) = acos(clip((trace(R1^T R2)-1)/2, -1, 1))
```

Cmv2 输出 `xi=[delta_x, omega]` 是 current-object-local effect。V1.21c 使用显式的
右乘 block transform：

```text
DeltaT(xi) = [[Exp_SO3(omega), delta_x], [0, 1]]
T_hat_next = T_current @ DeltaT(xi)
```

不使用完整 SE(3) twist exponential 的 `V(omega) delta_x` translation coupling。

```text
D0          = D_obj(T_t, T_goal)
P_obj[k]    = D0 - D_obj(T_hat_next[k], T_goal)
E0_IG       = E_IG(IG_t, IG_ref[t+1])
E_IG[k]     = E_IG(IG_hat_next[k], IG_ref[t+1])
P_IG[k]     = E0_IG - E_IG[k]
S_Cm[k]     = P_obj[k] + 0.5 * P_IG[k]
```

PhysX 使用同样的 `D_obj`、`E_IG` 和 progress 公式，只把 Cm predicted next state
替换为 PhysX real next state。

## 6. PhysX prefix replay、branch 与 parity

### 6.1 Episode replay artifact

每个 source episode 保存：

```text
episode_id, seed
initial_dof_state
initial_actor_root_state
initial_task_indices
executed_action_history[T,18]
done_history[T]
reference_index, data_id, start_time, progress history
resolved simulator config SHA
```

所有正式 validation 都从该 episode initial state 开始，不从中途公开 tensor 直接 clone。

### 6.2 Branch protocol

对每个 selected state 建立 `K+1=9` 个 validation env，从相同 initial state 逐步 replay
`executed_action_history[0:t]`，到 frame `t`：

- env `0..7` 执行 8 个 candidates；
- env `8` 再执行 candidate 0，作为 identical-action duplicate anchor；
- 每个分支只执行一个 DExplore control step，读取 object pose、object twist、key body
  state 和 canonical IG。

branch 前要求公开状态相同：`q/dq/object/table root state` 的 max absolute error
`<=1e-5`（对应单位），reference/task indices 必须逐项相等；否则该 state 无效。

### 6.3 Clone-noise calibration 与 tie tolerance

从已收集 state 中按 phase 和 state_id deterministic 选择 `24 moving + 24 contact +
16 precontact = 64` 个 calibration states，不计入最终 512 的排名样本数量。

duplicate anchor 的 hard ceiling 固定为：

```text
object position divergence <= 5e-4 m
object rotation divergence <= 5e-3 rad
```

任一 calibration state 超过 ceiling，整个 PhysX protocol 记为
`INVALID_IMPLEMENTATION`，不得继续 ranking。主 batch 中单个 state 超过 ceiling 时，
该 state 的 `physics_clone_valid=false`，不进入 `N_rank_valid`。

由 64 个 calibration states 的 duplicate score divergence 冻结：

```text
epsilon_PhysX = max(5 * p99(abs(delta_S_duplicate)), 1e-6)
```

此值写入 run manifest、metrics 和 replay record。PhysX pair 的绝对 score 差不超过
`epsilon_PhysX` 时视为 simulator tie。

## 7. Ranking metrics 与 gate

### 7.1 Pairwise

每个 state 对所有 `cm_valid AND physics_candidate_valid` 的 candidate pair 计算：

- PhysX tie：`abs(delta_S_PhysX) <= epsilon_PhysX`，从该 state 的 pair denominator 排除；
- PhysX 非 tie 且 Cm tie：`abs(delta_S_Cm) <= 1e-6`，计 `0.5`；
- 方向相同计 `1`，方向相反计 `0`。

先计算 state-level `A_s_pair`，再对有效 state 等权：

```text
A_pair = mean_s(A_s_pair)
```

如果一个 state 没有任何非-tie PhysX pair，则不产生 `A_s_pair`。最终至少要有
`384` 个 pair-valid states，才能计算 gate CI。

### 7.2 Cm top-1

```text
k_star = argmax_{k:cm_valid} S_Cm[k]
```

同分稳定选择最小 candidate index；baseline 是 `k=0`。若 `k_star` 在 PhysX 中 crash、
non-finite 或无效，记录为 top-1 failure，不删除 state。只有：

```text
S_PhysX[k_star] > S_PhysX[0] + epsilon_PhysX
```

才计为 improvement；tie 单独统计，不计 success。baseline candidate 0 无法得到 finite
PhysX score 时，该 state 的 top-1 结果为 failure。

### 7.3 Bootstrap 与最终 gate

使用 10,000 次 episode-block bootstrap，不按 candidate pair 或相邻 frame bootstrap。
有效 episode 少于 8 个时，统计 gate 为 `INCONCLUSIVE`。

最终需要同时满足：

```text
N_rank_valid >= 384
A_pair >= 0.60
block-bootstrap 95% CI lower(A_pair) > 0.50
top1_success_rate >= 0.55
block-bootstrap 95% CI lower(top1_success_rate) > 0.50
mean(top1_improvement) > 0
block-bootstrap 95% CI lower(mean(top1_improvement)) > 0
```

按 moving/contact/precontact 分 phase 报告相同指标，但 phase 结果先作为诊断，不单独
替代 global gate。

## 10. 风险、停止条件与回滚

以下任一情况立即停止并标记对应 run：

- input/checkpoint/asset SHA 不匹配；
- collector 64 episodes 后 phase quota 不足或无法得到 512 unique states；
- observation/action/reference/单位/坐标/schema 不一致；
- Cmv2 token/support、geometry、dt 或 no-grad 合同失败；
- 64-state calibration 超过 duplicate hard ceiling；
- PhysX crash、non-finite、NCCL/OOM 或 branch parity 无法满足；
- 运行输出缺少 manifest、config、metrics/log 或 episode replay artifact。

代码回滚只撤回本计划批准后新增的 Task-local 实现和测试；不删除、不覆盖旧计划、用户
指导、历史 Activity/experiment、数据、cache、checkpoint、vendor 或 outputs。运行产物保留
作为失败或停止证据。
