## 目标

建立独立、可审计的上游 DExplore 单序列重建单元。正式训练接受原生 contact、清洁 source 和未改动转换器；公开仓库缺失 `motion.npz` producer，因此新增的 adapter 只组装已存在的 30 Hz body/object 与原始 contact，结果明确归类为 reconstructed baseline。

## 实施范围

1. 在仓库外创建固定 commit 的清洁上游 DExplore 与 InterAct source snapshot，以及独立 Python 环境；不改写既有 checkout、共享 `graspenv` 或系统包。
2. 新增 `src/task/CmResidual/tools/data/build_dexplore_v120_motion_input.py`：从既有 DExplore-compatible 30 Hz `motion.npz` 读取 body metadata/params，从原始 GRAB 同序列读取 native-rate contact，将两者无插值组装到隔离数据根。复制同一 30 Hz `object.npz`，并将原始 `objects/<name>/mesh.obj` 无修改复制为公开 converter 约定的 `objects/<name>/<name>.obj`；数据 manifest 记录所有输入 SHA256、contact 形状和 reconstruction 分类。坐标诊断证明原 body 与 object/table 不共享 world frame，且 432 帧手/物相对偏差不是常量；因此仅在新的 `dexplore_reconstructed_v120_coordfix/` 候选根，针对每帧 `body.params.transl` 施加由 `inspire_geometric_dexplore` 的 right-hand/object 相对位移经 converter `rotation_x_90` 逆变换得到的平移。该几何控制 tensor 缺少首次 producer 的可审计记录，只用于行为对照；显式校正、两份对照 tensor 哈希、逐帧数值范围和方法必须写入 manifest；不改变 raw contact、object/table、mesh、skeleton、body rotation 或其他 body 参数。
3. 对未改动上游 `convert_grab.py` 做源文件 SHA256 审计，并处理 `s1_airplane_lift`。不允许临时 shim、contact 重复、输入内容重写或 source patch。
4. 新增或扩展 Task-local 启动器，只读取 V1.20 数据根并将 resolved config、source/依赖版本、输入 manifest、seed、命令和输出写入新的 `outputs/Dexplore/<run_id>/run_manifest.json`。
5. 先以官方 `inspire.pth` 在修复候选 tensor 与 `inspire_geometric_dexplore` 控制输入上，以相同固定 seed 运行单环境 Gym rollout；只有输出手/物体/桌面关系与几何控制一致且官方 checkpoint 的物理行为通过检查，才重新运行 4 rank × 2048 env（总 8192）的 1-iteration PPO 容量 smoke。随后从零启动四卡单序列训练。每 rank 保持上游 `horizon_length=64`，local `minibatch_size=4096`；四个 rank 的 DDP gradient average 因此对应 global minibatch `16384`，每个 PPO epoch 为 `(2048×64/4096)×6=192` 次 optimizer step，与上游单进程 `8192×64/16384×6` 相同。V1.20a 的无 Horovod DDP facade 在每次上游 optimizer step 平均梯度。用户已确认目标为实际 5000 PPO epoch：因上游以 `epoch_num > max_epochs` 退出，启动参数必须传 `--max_iterations 4999`，从而只完成 epoch 1..5000。正式结果明确归类为 reconstructed baseline。正式运行固定同一总 env 数，不复用无效运行的 checkpoint。

## 不变量与门禁

- 上游 tracked 源码、转换器、数据字段、598-D schema、单位、contact 采样率、split、reward、observation、action、physics 与 checkpoint 解释均不得静默改变；converter 可生成且只允许登记的 `data_processing/smplx_vert_segmentation.json`，它不构成 source patch。唯一允许的坐标修改是实施范围第 2 项的显式 body world-frame 平移；不得静默修改其他坐标字段。
- 数据门：source clean、依赖版本可复核、原生 contact、转换器未改动、adapter 不改变 contact 数值、输出 `(T,598)` float32 finite、manifest 完整；修复候选必须保留 object-table 关系，并使 right-hand/object 相对位置与 legacy 对照在 1cm 内。任一失败为 `INVALID_IMPLEMENTATION`，不运行 PPO。此门只支持 reconstructed baseline 的输入完整性，不证明作者未发布 producer 的等价性。
- smoke 门：4 rank loader 初始化、1 PPO iteration、finite tensors、exit code 0、非空 checkpoint 和 TensorBoard event，且每卡峰值未越过可用显存。任一失败不启动 153 epoch。
- 长训门：从零、seed42、4×2048 env、实际 5000 epoch、独立 output。OOM、non-finite、traceback、丢失 checkpoint/event、资源冲突或数据合同不成立即停止并记录。

## 验证

- 静态：source clean/commit/哈希、依赖版本、数据 manifest、tensor shape/dtype/finiteness、`py_compile`、启动器 dry-run、定向测试和 `git diff --check`。
- 运行：smoke 与正式运行分别生成独立 config、run manifest、train log、metrics/event 和 checkpoint；活动记录写入 run_id、状态、末 epoch、best metric 与产物链接。
- 科学解释：数据转换与 smoke 只支持工程可运行性；正式训练 reward 仅为优化诊断。抓取与上游结果一致性需要独立评估，默认 `INCONCLUSIVE`。
