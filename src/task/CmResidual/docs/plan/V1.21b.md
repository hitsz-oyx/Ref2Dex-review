## 目标与消歧

用户确认的新主线是：以 V1.20e 已运行的 vendor DExplore reconstructed-baseline
训练合同作为唯一无 Cm 对照；在同一环境、同一训练骨架上接入冻结 Cmv2。这里“与
`EXP-20260919-204049-CMRESIDUAL-V120E-E500-LIFT` 一致”解释为与该实验所加载的
V1.20e **训练来源**一致，而不是把该文件的单环境、432 帧、epoch-500 checkpoint
评估协议误作训练协议。

无 Cm 对照固定为：vendor DExplore `Dexplore_Inspire`、
`dexplore_reconstructed_v120_coordfix_v4/converted_attempt1` 的
`s1_airplane_lift`、598-D 输入、18-D 原生 action、30 Hz/native-contact、V1.20e
reward/termination/physics、seed 42、DDP 4 rank x 2048 env、horizon 64、每 rank
minibatch 4096（global 16384）、6 mini-epochs、从零初始化。其数据仍明确标注为
`reconstructed_baseline`，不声称等同官方原始数据。

Cm-off 的可比运行必须使用随后引入的同一 task-local runner/agent 分支，并满足
`cm_distill_coef=0` 时既不构造 Cmv2、也不改变 policy/critic 输入、动作、reward、
reset、DDP 梯度平均、optimizer step、checkpoint 解释或随机数消费。已有 V1.20e
run 是历史对照和容量证据；新的 Cm-off run 是该不变量的工程验证，不把两者的训练
reward 当作抓取或收敛证据。

## 已发现的 Cm bridge 缺口与候选合同

DExplore 已暴露 GPU 上的 18-DoF、rigid-body、object root 和 256 个物体表面点，
但冻结 Cmv2 的当前接口要求每环境 1024 object points + normals、1538 hand points
+ normals + hand flow，且要求严格 `dt=1/30`。因此不能直接复用 V1.18 的 1442-D
reference adapter，也不能将 256 点重复后宣称几何等价。

候选实现是新增 **Task-local** DExplore-Cm adapter（不修改 tracked vendor
`third_party/DExplore`）：从 DExplore 的真实 object pose、固定 canonical mesh surface
及 hand FK/mesh 中构造 Cmv2 所需几何；以同一 canonical 采样方案确定 1024 点及
法线，显式验证 world/object frame 与 Inspire 18-DoF joint order；Cmv2 只在 rollout
产生 detached teacher action。actor 仍执行原生 DExplore action；critic、环境 reward、
termination、reference tensor 和 Cmv2 参数均不接收梯度或更改。

在实现前必须审计 Cmv2 checkpoint 的 mesh/point ordering 与 DExplore asset 的对应性。
若无法证明几何、坐标、单位、joint mapping 或 `dt` 合同，停止 Cm-on 接入；不得用
插值、复制点或经验坐标修补替代该证明。

## 分阶段实施与门禁

1. **Cm-off parity change + test。** 新建 task-local bootstrap/runner extension，不改
   vendor source；以静态和小型 fake-tensor tests 证明 `coef=0` 不导入/实例化 Cm，且
   action、PPO batch、loss 和 checkpoint key 路径保持 DExplore 合同。定向测试、语法
   检查及 `python tools/verify.py --changed` 通过后，才允许 smoke。
2. **Cm-off DDP engineering smoke。** 先按既有 V1.20a 拓扑 smoke 的资源尺度运行，
   再在资源可用时跑一次 4 x 2048 / local-4096 / global-16384 的一实际 epoch 容量门；
   均从零开始、独立 output/manifest。只有 rank、finite checkpoint、DDP、物理和
   expected optimizer-step 计数均通过，才称无 Cm 训练骨架可运行。
3. **geometry bridge change + test。** 单独实现并测试 1024/1538 几何 bridge；测试须
   覆盖 shape、finite、normal unit length、物/手 frame、18-DoF mapping、`dt=1/30`、
   Cmv2 SHA 和 no-grad/detach。此阶段不训练。
4. **Cm-on smoke。** 与通过的 Cm-off 运行同一 DDP/优化合同，仅令
   `cm_distill_coef` 为待确认的非零值；先小预算工程 smoke，再讨论任何长期训练。

每个 run 使用新的 `outputs/CmResidual/<run_id>/`、完整 manifest 和配置快照；终态写
Activity 与 experiment card。容量门的停止条件为 OOM、NCCL/PhysX/traceback、non-finite、
rank/checkpoint 缺失、step 计数偏离或几何合同失败。停止只保留独立 output，不删除旧
运行或 checkpoint。

## 保护项、风险与回滚

保护 V1.20e 数据身份、598-D input、坐标/单位、原生 action、reward、GT、split、
physics、DDP global batch、optimizer 语义和 checkpoint 解释；保留 vendor source
只读。风险是 Cmv2 与 DExplore 的 asset/mesh、采样密度、frame 或 joint order 无法
证明匹配，以及 4 x 2048 容量不足。回滚为只撤回新增 task-local adapter/runner/tests
和本计划对应提交；所有既有数据、vendor 文件、checkpoint 与 outputs 保留。

## 需要确认

确认本草案后，先执行第 1 阶段的最小 task-local 代码修改；第 2 阶段的 4 x 2048
容量 smoke 仍以机器资源可用为条件。Cm-on 的非零系数在第 3 阶段几何合同通过前不设定。
