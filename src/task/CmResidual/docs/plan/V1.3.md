## 1. 目标与当前证据

本版本只完成指导中列出的三个必要修正和一个 zero-residual gate，不重新设计 Cm、reward 或 PPO：

1. 统一 Cm 维度与真实 checkpoint/reference 配置；
2. 将 DExplore 当前 contact 输入从 hand-link linear velocity 改为 Isaac Gym net contact force；
3. 将 PPO residual 从与 DExplore 等权的 normalized action 改为小尺度 physical target correction；
4. 在任何 PPO 训练前运行冻结 DExplore 的 zero-residual 评估。

## 3. 配置与 checkpoint 合同

### 3.1 两个注册入口统一

`CmResidual.yaml` 是 canonical 入口；`CmResidualOnline.yaml` 仍被 task map 注册到同一实现，因此本版本将其
收敛为 canonical 配置的兼容 alias，而不是继续保留一个必然失败的旧 128-D/cube 合同。两者锁定：

```yaml
env:
  numObservations: 2005
  numActions: 18
  asset:
    objectAssetFileName: airplane.urdf

basePolicy:
  mode: dexplore
  cmFeatureDim: 32
  cmNumSlots: 16
  cmObjectPoints: 1024
  cmHandPoints: 1538

residual:
  translationScaleM: 0.015
  rotationScaleRad: 0.20
  fingerScaleRad: 0.08
```

删除 `CmResidualOnline.yaml` 中已经无实现消费者的 `cmEmaDecay`。`CmResidualDecoderBank.yaml` 是不同历史入口，
本版本不修改。

### 3.2 真实输入与 fail-closed 校验

- 两个 task 配置保留 `DEXPLORE_CHECKPOINT`、`OI_CM_CHECKPOINT`、`CMRESIDUAL_REFERENCE` 环境变量覆盖，
  默认值指向第 1 节已验证的本机真实文件，而不是空字符串或不存在的 `checkpoint/inspire.pth`。
- 配置同时声明三个已核对 SHA256；loader 在构造环境前逐一校验，任何缺失、摘要不符、OI-Cm
  `feature_dim/num_cm_tokens/point count` 不符均 fail closed。
- PPO builder 删除未使用的第二份 OI-Cm loader 和 `network.oi_cm_checkpoint`；Task 是唯一 checkpoint owner。
  V1.2 smoke PPO checkpoint 因包含旧的重复模块状态，不作为 V1.3 初始化 checkpoint；后续 PPO 必须 fresh start。
- 运行 manifest 保存 resolved absolute path、SHA256 和 reference manifest 的 `training_eligible`，但不修改或
  内嵌原 manifest。

## 4. contact 观测修正

- 继续使用当前 5 个 DExplore contact link 顺序；从已刷新并 reshape 为 `[num_envs, num_bodies, 3]` 的
  `self.contact_force` 选择对应 body，而不是从 `rigid_body_state` 的 velocity slice 选择。
- `build_dexplore_observation()` 仍按 DExplore 当前合同以 `amax(abs(force)) > 0.1` 生成 5-D binary contact。
- 明确该张量是每个 rigid body 的 net contact force，不冒充 hand-object pairwise contact；reference contact
  仍使用 V1.2 已批准的 2 cm 几何 target，不改变其语义。
- 增加合成 tensor 测试：速度和 contact force 给出相反信号，断言 observation 只随 contact force 变化；
  继续验证 `+1/+16` 两个 721-D offset 的 shape/finite 合同。

## 5. physical residual 权限

保留 PPO 的 18-D normalized action 接口，但不再在 normalized DExplore action 上相加。实现分两步：

1. 用与原 DExplore Inspire 一致的映射把 `base_action` 转成 physical native targets；zero residual 时输出必须与
   原 V1.2 base-only 映射逐元素一致。
2. 在 physical DOF target 上施加小修正并做最终 joint-limit clamp：
   - wrist translation DOF `0:3`：`0.015 * residual[0:3]` m；
   - wrist rotation DOF `3:6`：`0.20 * residual[3:6]` rad；
   - 六个 independent finger DOF `(6,8,10,12,14,15)`：各自
     `0.08 * residual[index]` rad，然后按既有比例重新展开 mimic DOF。

本版本不引入 wrist IK 或新的 SE(3) pose controller；“physical”指在 DExplore normalized action 已转换后的
URDF wrist/finger DOF target（m/rad）上施加有界修正。其余六个 mimic 对应 residual 分量不获得独立物理权限，
以保持 18-D checkpoint/network 接口和 Inspire coupling 不变。

reward 公式及 action penalty 不变；只增加不参与 reward 的诊断量：normalized residual RMS、translation/rotation/
finger physical RMS、target clamp/saturation ratio，便于判断后续是否需要扩大权限。

## 6. zero-residual gate

新增 Task-local `tools/eval_zero_residual.py`，直接创建 `CmResidual` 环境并在每一步传入严格全零 residual；
不构造 PPO network、不更新参数。首个 gate 固定为 CPU PhysX、seed 42、4 envs、最多 367 control steps，
使用第 1 节的三个真实输入及独立新目录：

```text
outputs/CmResidual/<run_id>/
├── config.json
├── run_manifest.json
├── metrics.jsonl
└── eval.log
```

工程 gate 条件：

- 进程正常退出，无 traceback、non-finite、非法 reset 或 simulator error；
- 每步 residual 精确为零，physical residual RMS 和 residual-induced target delta 精确为零；
- teacher action、2005-D policy observation、physical target、object pose 与 reward 全部 finite；
- 记录实际步数、reset/终止原因、max/mean lift、tip distance、contact occupancy、target saturation ratio；
- unit test 中 zero residual 对 base-only mapping 的误差为零（浮点容差内）。

上述条件只能证明 wrapper wiring 和 zero-residual 退化关系成立，结论最多为工程 `SUPPORTED`；是否“行为合理”
以及 DExplore 是否能完成抓取仍依据 rollout 指标判为 `SUPPORTED` / `REFUTED` / `INCONCLUSIVE`，不由无 traceback
替代。若初始状态、reference 对齐或物理行为异常，gate 标记 `INVALID_IMPLEMENTATION` 并停止，不启动 PPO。

由于当前 reference manifest 为 `training_eligible=false`，即使 zero-residual gate 通过，本计划也不自动启动 PPO。
后续训练必须先由用户决定是补齐 reference eligibility gate，还是明确批准带该限制的独立实验；随后另行冻结
GPU、env 数、seed、预算、评估指标和停止条件。
