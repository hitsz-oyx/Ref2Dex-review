## 1. 冲突、候选解释与目标

### 1.1 已识别冲突

基线 final plan 的实施范围第 5 项以 Horovod 的 `DistributedOptimizer`、`allreduce` 与
`horovodrun` 作为四卡 PPO 同步路径；用户最新要求是不使用 Horovod 包，改在已可运行的
PyTorch 2.4.1 + CUDA 12.1 + `rl_games==1.1.4` 隔离环境中自行实现多卡。

候选解释是：替换的仅是进程启动与梯度/状态通信实现，不是 DExplore 任务、598-D 输入、
PPO 损失、奖励、观测、动作、物理、数据或 checkpoint 合同。基线 plan 因此保留为已执行
历史，V1.20a 在确认后成为其 DDP 实施补充。

### 1.2 目标

在不安装、导入或链接 Horovod 包、不修改上游 DExplore checkout、不修改 `rl_games` 安装目录的
前提下，新增 CmResidual Task-local 的 `torch.distributed`/NCCL 适配层。它必须让外部 DExplore
现有的多卡控制流在 `torchrun` 多进程下完成参数广播、梯度平均、统计量同步、rank-0 写盘和同步退出。

此工作只验证工程通信和 PPO 更新合同；不改变也不论证抓取能力、重建基线效果或与未公开 producer
的等价性。

## 2. 保护边界与不变量

- 保留 V1.20 的单序列 `s1_airplane_lift`、原始 120 Hz contact、598-D schema、坐标/单位、
  split、上游 reward/observation/action/physics、seed、从零初始化与 reconstructed-baseline 解释。
- 保留并只读既有 Horovod 环境、bootstrap、上游 checkout、`rl_games` site-packages、数据、cache、
  checkpoint、outputs 和历史运行；不卸载或覆盖任何包。
- 不把 `torch.distributed` 适配层放入 `src/base/`，不在外部 DExplore 或 `rl_games` 中留下 patch。
- 不以单卡/多卡 rollout 的逐帧 bitwise 相同作为物理成功条件；不同 PhysX subscene 的随机流和并行
  排列可造成轨迹分叉。参数/梯度的受控合成测试才承担数值等价性门。
- 外部 DExplore 的 CLI 仍可能需要传递遗留的 `--horovod` 开关，以打开其既有 `multi_gpu` 分支；
  在 V1.20a 中该开关只表示“选择 Task-local DDP facade”，绝不导入或安装 Horovod。

## 3. 实施范围

### 阶段 1：最小两 rank DDP 接线与 smoke

1. 新增 `src/task/CmResidual/tools/dexplore_ddp_compat.py`，只封装 PyTorch 原生
   `torch.distributed`：
   - 从 `torchrun` 的 `RANK`、`LOCAL_RANK`、`WORLD_SIZE` 初始化/销毁 NCCL process group；
     在 Isaac Gym/Torch 张量创建前设置 rank-local CUDA device。
   - 对模型/优化器 state 做 rank-0 广播；在每次 optimizer step 前对 finite gradient 求和后除以
     world size；提供同步/非同步 step、KL/RunningMeanStd 平均、frame 计数求和、布尔退出广播和
     rank-0 判定。
   - 将这一组调用以进程内 facade 提供给外部 `dexplore/run.py` 与 `rl_games==1.1.4` 既有
     `HorovodWrapper` 消费；facade 只能在 Task-local bootstrap 中注册到 `sys.modules`，不创建
     可安装的 `horovod` 包、不得写入 site-packages。
2. 新增 `src/task/CmResidual/tools/dexplore_ddp_rank_bootstrap.py`：先安装 facade 与
   rank-local Isaac Gym tensor-device hook，再以 `runpy` 运行未修改的外部 `dexplore/run.py`；
   `finally` 中执行 barrier（仍存活时）和 process-group 清理。
3. 新增 `src/task/CmResidual/tools/run_dexplore_v120_ddp.py`：只构造 `torch.distributed.run`
   / `torchrun --standalone` 命令、GPU 可用性检查、明确 `CUDA_VISIBLE_DEVICES`、配置快照和新
   `run_id`，不复用旧输出。启动器不得选择“最新 checkpoint”。
4. 新增 Task-local 定向测试
   `src/task/CmResidual/tests/test_dexplore_v120_ddp_compat.py`：验证没有 Horovod 安装时 facade
   的 API 边界、rank/device 映射、广播、平均梯度、统计量/退出同步和 cleanup。受控的两 rank
   合成 PPO-like update 必须与单进程拼接同一 global batch 的一次 Adam 更新在预先声明的浮点
   容差内一致。
5. 仅在代码审查和定向测试通过后，运行一个新的两 rank、单 iteration 工程 smoke。它使用现有
   V1.20 合法输入与从零初始权重，但减小 env 数仅用于容量/接线测量；不与 153 epoch 结果比较，
   不形成科研结论。

阶段 1 通过条件：两个 rank 均使用不同 logical CUDA device；无 `horovod` 分发包导入；初始化、
rollout、一次更新、统计同步和受控退出均成功；各 rank 更新后模型参数哈希一致；loss/gradient/
parameter/checkpoint finite；只由 rank 0 写出一个可加载 checkpoint 和 TensorBoard event；所有
子进程退出且 process group 清理。任一失败则停止，不进入阶段 2。

### 阶段 2：四 rank 语义保持 smoke

仅在阶段 1 的工程门通过、用户审阅阶段 1 证据并再次同意资源使用后执行：

1. 先对当前可用 GPU 做只读盘点；本计划不预占 GPU，也不默认重用历史的 `0,1,3,7`。由执行前
   可用显存和用户确认决定四张物理卡，并显式写入 run manifest。
2. 以 V1.20 的每 rank 环境数、horizon、PPO hyperparameter、seed、逻辑 minibatch 与梯度累积
   合同为唯一来源，生成解析后的配置快照。若现有 Horovod 运行的“逻辑 minibatch 16384 / 64×256
   microbatch”是每 rank 而不是 global 的语义，必须在启动前从代码和历史 config 证明并写入 manifest；
   不可凭名称猜测。
3. 运行新的四 rank、单 iteration smoke。除通信实现和明确批准的资源映射外，不改变数据或训练
   变量。比较受控更新 fixture、rank 间参数/optimizer-state 一致性、global frame 计数和 rank-0
   checkpoint reload；不以 rollout 逐帧一致性作门禁。

阶段 2 通过条件：四 rank 全部映射正确、NCCL 无 timeout/hang、一次 PPO 更新后 state 一致、
run manifest/config/train log/event/checkpoint 齐全、无 non-finite 或未处理 traceback、显存未超过
执行前声明阈值。该 smoke 只支持 DDP 工程协议，科学结论为 `INCONCLUSIVE`。

## 4. 正式运行边界

本草案**不**授权 153 epoch 或其他长训。四 rank smoke 成功后，Agent 应提交证据和资源快照；
用户明确确认正式预算、GPU、停止条件与输出目录后，才生成独立 run manifest 并从零启动正式运行。
正式运行仍须使用 V1.20 的数据门和 `reconstructed baseline` 标签。

## 5. 验证、记录与回滚

- change 验证：Task-local pytest、`py_compile`、受控两 rank numerical fixture、`git diff --check`；
  过渡期记录实际检查，除非 `tools/verify.py --changed` 已存在且通过，不声称统一 VERIFY PASS。
- run 验证：每个 smoke 使用独立 `run_id` 与输出目录，写入 config snapshot、run manifest、train log、
  metrics/event 和 checkpoint（实际存在者）；终态写入新的 `docs/activities/` Activity。科学证据另写
  `docs/experiments/` card，不能写入历史 `docs/logs/`。
- 回滚：`git revert` 该 DDP 实现提交即可删除 Task-local facade/bootstrap/launcher/test；不会改动
  上游 checkout、site-packages、既有 Horovod 环境、数据或历史 outputs。每个运行使用新目录，
  停止/删除必须另获授权。
