## 0. 修订边界

本草案是已经 `FINAL` 的 V1.21c 计划的后缀补充。它只替代 V1.21c 的以下合同：

- 6.1–6.3 中“创建 task 后用公开 root/DOF tensor 恢复初态，再在 9 个常驻 env 中同步 replay”的 branch backend；
- 8 中与 branch provenance、native-init parity 和 duplicate calibration 有关的 replay 字段；
- 9.3 的真实运行门禁与 10 中相应停止条件；
- 11 中获准实施和运行的边界。

V1.21c 的研究问题、checkpoint、observation、action、reference、candidate、Cmv2、canonical
IG、score、phase quota、统计量、bootstrap、成功阈值和结论上限继续生效。V1.21c 和更早计划作为
历史事实保持不变，不覆盖原文件。

本计划已获确认，允许实施批准的 Task-local L2 变更；每个真实 GPU/PhysX 运行阶段仍需单独
固定资源、预算、run manifest 和停止条件。

## 1. 已知失败与设计判断

### 1.1 已观察事实

V1.21c 的 GPU3、1-state/9-env prefix smoke 从相同公开 tensor 初态出发，9 个 env 执行相同的
一个 hold prefix step 后，跨 env 出现：

```text
max |delta q|  = 0.0111185312 rad
max |delta dq| = 0.5535187721 rad/s
max |delta object position| ~= 1.99e-6 m
required public-state parity <= 1e-5
```

task/reference indices 相同，但 q/dq 不满足门禁；candidate step 未执行。该 run 的协议结论是
`INVALID_IMPLEMENTATION`，Cm 科学结论是 `INCONCLUSIVE`。

### 1.2 待检验假设

当前工作假设是：task/sim 已创建后，仅恢复公开 root/DOF tensor，不足以恢复 PhysX articulation、
solver/contact cache 或其他隐藏状态，因此“tensor 相同”不保证下一步动力学相同。这是待验证的工程
假设，不作为已证实的 PhysX 机制结论。

设计因此改为：不再把中途公开 tensor clone 当作 counterfactual 起点；每个被评估 state 都创建
新的 simulator/task，用 DExplore 原生 episode 初始化合同得到初态，再重放真实 executed-action
prefix。fresh simulator 隔离前一个 state 的隐藏 solver 历史，native init 避免创建后强行恢复初态。

## 2. 保持不变的研究语义

以下内容不得因 branch backend 改造而变化：

- 官方 DExplore checkpoint、frozen Cmv2 checkpoint 及其 path/SHA/解释；
- `s1_airplane_lift` motion/reference source、`H_ref=6` 和 reference clock；
- actor 的 canonical `1442-D` observation 与 RunningMeanStd；
- DExplore native normalized `18-D` action、官方 action mapping、PD target 和 30 Hz control；
- collector 保存并重放真正交给 `env.step()` 的 executed action；
- `K=8` candidate、candidate 0 actor mean、CPU RNG 与 candidate seed；
- Cmv2 `eval()`、no-grad、几何输入、current-object-local pose composition；
- DExplore 256-point canonical IG、score、坐标、单位、GT、phase 和 quota；
- state-level pairwise、episode-block bootstrap、`N_rank_valid>=384` 及 V1.21c 的所有科学 gate；
- vendor、`src/base/`、原始数据、cache、checkpoint 和既有 outputs 只读；不启动 PPO、蒸馏、P=3、异步 worker 或 Cmv2 更新。

不得通过放宽 `1e-5` public-state parity、删除 q/dq 检查或事后选择较宽阈值来使实现通过。

## 3. Native-init fresh-sim backend

### 3.1 Collector artifact 的初态合同

每个 source episode 除 V1.21c 已定义字段外，必须记录足以重建原生初始化的身份：

```text
state_init_mode = "Start"
hybrid_init_prob = 1.0
episode seed
motion/data identity and resolved SHA
initial reference/task indices
initial public state snapshot
executed_action_history[T,18]
done_history[T]
resolved task/simulator config SHA
```

正式 collector episode 必须确实从官方 `StateInit.Start` 路径开始。validation task 使用完全相同的
motion、seed、config 和原生初始化参数；不得先创建任意状态的 task，再用 setter 把它伪装成该 episode
初态。

新 task 原生 reset 后，立即把公开初态与 episode artifact 比较：

```text
q/dq/object/table/actor root state max absolute error <= 1e-5
reference_index/data_id/start_time/progress exact equal
```

单位沿用各字段既有单位。任一项不符，该 episode/state 为 `native_initial_parity=false`，停止当前门禁；
不得使用 tensor setter 修正后继续。

### 3.2 每个 state 的 fresh-sim 生命周期

每个 calibration 或 ranking state 使用一个全新的 9-env simulator/task 实例：

1. 创建固定 `num_envs=9` 的 validation task，并通过 3.1 的官方 native init 得到同一 episode 初态；
2. 检查 9 个 env 之间以及它们相对 episode artifact 的 native-initial parity；
3. 所有 env 逐 control step 重放 `executed_action_history[0:t]`；中途 done、reset 或 task index 漂移立即使该 state 无效；
4. candidate 前检查 9 env 的 `q/dq/object/table root state <=1e-5`，task/reference indices exact equal；
5. 仅在 parity 通过后，env `0..7` 分别执行 candidate `0..7`，env `8` 执行 candidate `0` duplicate；
6. 读取下一步 object pose/twist、key body state、canonical IG 和 score；
7. 写完该 state 的完整记录后销毁 task/simulator，再处理下一个 state。

validation task 进程可以复用，但 simulator/task 不得跨 state 复用。必须记录单调递增的
`sim_instance_id`、create/destroy 结果和累计重建数。销毁失败、GPU memory 持续增长到不可安全完成
预定 probe，或无法证明下一个 state 使用新 simulator 时立即停止。

## 4. 分阶段证伪门禁

### 4.1 Gate 0：静态与单状态接线

先完成纯 CPU/fake tensor 合同测试，再做一次独立 run_id 的 1-state/9-env native-init smoke。
该 smoke 必须通过初态 parity、至少一个非空 prefix 的 candidate 前 parity、candidate 0 duplicate 和
simulator 销毁检查。它只证明接线，不校准噪声，也不产生科学结论。

### 4.2 Gate A：12-state parity probe

collector 满足 V1.21c 的 512-state quota 后，从每个 phase 按 `(frame_id,state_id)` 排序，选择最接近
经验分位数 `0, 1/3, 2/3, 1` 的 4 个不同 state，共：

```text
moving=4, contact=4, precontact=4
```

若无法得到 12 个不同 state，Gate A 为 `INCONCLUSIVE` 并停止。每个 state 必须完成 3.2 全流程，且：

- native-initial parity 全部通过；
- 非空 prefix replay 后 candidate 前 parity 全部通过；
- candidate 0 duplicate finite；
- create/destroy 计数严格一一对应。

任一 state 的公开 parity 失败即为 `INVALID_IMPLEMENTATION`，不得进入 Gate B，不得调整阈值重试。

### 4.3 Gate B：64-state all-duplicate calibration

沿用 V1.21c 的 deterministic calibration 配额：`24 moving + 24 contact + 16 precontact`。每个 state
仍创建 fresh 9-env task，但本门禁让 9 个 env 全部执行 candidate 0，而不是只比较 env 0 与 env 8。

对每个 state 计算全部 36 个 env pair 的：

```text
object position divergence
object rotation divergence
canonical IG divergence
absolute score divergence
```

hard ceiling 保持 V1.21c 固定值，对所有 pair 生效：

```text
object position divergence <= 5e-4 m
object rotation divergence <= 5e-3 rad
```

任一 pair 超过 ceiling、non-finite 或前置 parity 失败，整个协议为 `INVALID_IMPLEMENTATION` 并停止。
只有 64 个 state、576 个 replicate outcome 均有效时，才按每个 state 的最大 pairwise score divergence
组成 64 个值并冻结：

```text
epsilon_PhysX = max(5 * p99(state_max_abs_pairwise_score_divergence), 1e-6)
```

Gate B 的 64 states 可来自已收集的 512 states，但只用于 calibration，不贡献最终 ranking 统计。

### 4.4 Gate C：512-state ranking

Gate A、B 全部通过并冻结 `epsilon_PhysX` 后，才允许执行 V1.21c 的 512-state ranking。每个 state
继续使用 fresh 9-env task；env `0..7` 执行 8 candidates，env `8` 执行 candidate 0 duplicate。

candidate 前 parity 是 hard gate。主 batch 中 duplicate 超过 hard ceiling 时，按 V1.21c 记该 state
`physics_clone_valid=false` 并排除；同时完整记录，不得重跑到通过。科学 metrics、bootstrap、有效样本数、
成功阈值和结论映射完全沿用 V1.21c。

## 5. 有限降级诊断

若 Gate A 因相同 prefix 后 9-env parity 失败，允许的唯一后续动作是一个新的、独立 run_id 的
12-state isolated single-env 诊断：对每个 state/candidate branch 都创建一个全新的 1-env simulator，
从同一 native init 重放 prefix；candidate 0 另建一个 duplicate simulator。该诊断需要
`12 * 9 = 108` 次 simulator 创建，继续使用相同 12 states 和相同 parity/duplicate 阈值。

这个诊断只回答“跨 env 同步是否是分叉来源”，不产生 ranking 科学结论。不得自动把它扩大到
512 states；正式 single-env ranking 预计需要 `512 * 9 = 4608` 次 simulator 创建，资源、预算、
失败恢复和统计合同必须另建后缀计划并由用户确认。

record SHA。旧 replay schema 和旧 outputs 不迁移、不覆盖；reader 必须显式拒绝把旧 tensor-restore

## 8. 风险与停止条件

主要风险是 simulator 重建成本高、销毁后 GPU 资源不能稳定释放，以及原生 seed/init 仍不足以复现
collector 初态。任何以下情况立即停止当前 gate 并保留证据：

- input/checkpoint/motion/config SHA 不匹配；
- native-initial parity 或 candidate 前 public-state parity 失败；
- prefix 中出现意外 done/reset、task/reference index 漂移；
- duplicate hard ceiling、finite 或 score 合同失败；
- simulator 创建/销毁失败，或 GPU memory 呈不可控增长；
- run manifest、record、metrics/log 或依赖 run_id 不完整；
- 资源消耗显著超过已确认预算。

不得通过换 seed、挑 state、重复运行取最好结果、放宽阈值或忽略失败 env 继续。失败的 Gate A/B/C
分别记录 `INVALID_IMPLEMENTATION` 或合同定义的 `INCONCLUSIVE`；Cm 科学结论保持独立。

## 9. 回滚

代码回滚只撤销 V1.21d 定稿后新增的 Task-local backend、schema adapter 和测试；恢复 V1.21c 代码

cache、checkpoint、vendor 和 outputs 不删除、不覆盖。失败 run 作为审计证据保留。
