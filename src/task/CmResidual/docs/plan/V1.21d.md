## 1. 目标与结论边界

目标是在不改变 V1.21c 科学问题、candidate、replay 或 hard ceiling 的前提下，消除 duplicate
calibration 的三类实现漂移：

1. object score 错用 `T_ref[t+1]`，而正式合同要求 `T_ref[t+6]`；IG 仍使用 `IG_ref[t+1]`；
2. calibration bootstrap 继承 launcher 的 `sys.executable`，没有固定已验证的 DExplore runtime；
3. frozen collection validator 没有硬校验 `24 moving / 24 contact / 16 precontact` 及完整 artifact
   identity。

本计划只恢复“corrected 64-state calibration 是否有效”的可判定性。它不产生 Cm ranking、PPO、
抓取、收敛或泛化结论。corrected calibration 通过时只能冻结该协议下的 `epsilon_PhysX`；失败时
结论仍为 `INVALID_IMPLEMENTATION`，Cm 科学结论保持 `INCONCLUSIVE`。

## 2. 保持不变的合同

- 一个 native action 仍严格为 `1 × pre_physics_step + 2 × gym.simulate + 1 ×
  post_physics_step`，即 30 Hz control / 两个 `1/60 s` PhysX substeps；继续调用官方
  `_physics_step()`，并硬校验 `control_freq_inv == 2`。
- 9 env 继续按 `PCG64(candidate_seed)` 对 multiset `[0,0,1,2,3,4,5,6,7]` 做确定性置换；
  candidate 0 的两个随机 slot 是 duplicate anchor。
- 跨 env q/dq/root 数值差异继续完整记录，但 `1e-5` 只作 diagnostic；finite 与 task/reference
  indices 一致仍是 branch 前 hard gate。
- duplicate hard ceiling 保持 object position `<= 5e-4 m`、rotation `<= 5e-3 rad`；不得根据
  运行结果放宽。
- `epsilon_PhysX = max(5 * p99(abs(delta_S_duplicate)), 1e-6)` 保持不变；只有 64/64 state
  通过 hard ceiling 后才可冻结。
- actor observation、598-D reference source、18-D native action、candidate RNG、Cmv2 checkpoint、
  geometry、坐标、单位、GT、split、checkpoint 解释和 V1.21c ranking gate 均不变。
- vendor、`src/base/`、数据、cache、checkpoint、既有 outputs 与用户指导只读；不覆盖或删除旧证据。

## 3. Task-local 实施

### 3.1 收敛 producer-owned PhysX score

在 `src/task/CmResidual/v121c_ranking.py` 建立纯 tensor、producer-facing 的唯一 PhysX score
实现。先提供统一 next-state cost primitive，其输入显式区分：

```text
goal_pose_t6
reference_ig_t1
next_pose
next_ig
```

唯一 next-state cost 为：

```text
C_next = D_obj(T_next, T_ref[t+6]) + 0.5 * E_IG(IG_next, IG_ref[t+1])
```

正式 PhysX score 的 baseline 必须来自 artifact 中所有 candidate 共享的 canonical collected
pre-action state：

```text
C0 = D_obj(T_collected_t, T_ref[t+6])
     + 0.5 * E_IG(IG_collected_t, IG_ref[t+1])
S_PhysX[k] = C0 - C_next[k]
```

`T_collected_t/IG_collected_t` 不得从 9 个 replay env 的 branch-local pre-candidate state 读取或逐 env
重算；replay env 即使在 branch 前已发生数值分叉，也不能改变共享 baseline。producer 必须验证
canonical collected state identity 与 replay target 的 `state_id/reference_index` 一致。

若现有 64-state calibration artifact 没有足够字段可靠恢复 `T_collected_t/IG_collected_t`，duplicate
calibration 不得隐式退回 branch-local current state。它直接复用统一的 `C_next` primitive，并定义：

```text
delta_S_duplicate = S_B - S_A = -(C_next_B - C_next_A)
```

只有在 shared canonical baseline 明确定义时，`C0` 才能在 candidate 差分中代数抵消。

`D_obj`、rotation geodesic、`E_IG`、sigma 与 V1.21c `cm_scores()` 共用现有实现，不复制常量或
另写近似公式。`v121c_calibration_replay_bootstrap.py` 删除私有 `_loss()` 的独立定义；duplicate
calibration 和正式 PhysX replay producer 调用同一 next-state cost/score 实现并写出
`physics_score`。offline evaluator 不重新计算 physics score，只消费 producer 生成的字段，并校验
schema、shape、finite、state/candidate mapping、score-clock metadata 与 producer provenance。

### 3.2 固定 DExplore Python runtime

`run_v121c_duplicate_calibration.py` 使用与 collector 相同的：

```text

```

同时只读校验 executable 存在、可执行，并在 config/manifest 记录原始路径、resolved target 与目标
SHA256。不得回退到 `sys.executable`。Isaac Gym-first import order、`PYTHONPATH`、logical
`cuda:0` 与 physical GPU 映射保持现状。

### 3.3 强化 frozen collection validation

在创建 corrected run output 之前一次性验证：

- source manifest 为 `COMPLETED`，`selected_state_count == 64`；
- NPZ 恰有 64 行、64 个 non-empty unique `state_id`；
- `phase_id` 只允许 `PHASE_MOVING=0`、`PHASE_CONTACT=1`、`PHASE_PRECONTACT=2`，计数严格为
  `24/24/16`；manifest 的字符串 key counts 必须与 NPZ 一致；
- 所有 `collection_batch_id` non-empty 且全体相同，并与 source manifest/config 声明一致；
- `candidate_seed.dtype == uint64`，每行均等于公共 `candidate_seed(batch_id,state_id)`；
- 所有 referenced episode id/seed 合法，对应 `episodes/<episode_id>/episode.npz` 存在且可读；
- selected state 的 episode/seed/frame/progress 与 episode artifact 范围一致；必需字段、shape、dtype
  和 finite 合同全部通过。

validator 返回冻结的 collection identity 与 episode 清单；后续 bootstrap 不重新推断或补写缺失值。

## 5. corrected calibration run

只有本计划定稿、实现提交固定、上述验证通过并另获 GPU3 运行确认后，才进入 `run`：

1. 只读复核 frozen collection manifest/NPZ/episodes、指导与 FINAL plan SHA、代码 commit、DExplore
   runtime、checkpoint/assets/sim config SHA；GPU3 超过容量门限时停止，不换卡。
2. 使用全新 `run_id` 和 `outputs/CmResidual/<run_id>/`；manifest 明确引用旧失败 run、source
   collection、corrected commit、三个修复项、physical GPU3/logical `cuda:0`、30 Hz、seed、phase
   counts、score clock 和 hard ceilings。
3. 依 episode replay 64 个 frozen states；任一 finite/index/artifact/runtime/duplicate hard gate 失败即
   停止，不尝试 512-state ranking。
4. 仅当 64/64 duplicate anchor 均通过，才计算并冻结 `epsilon_PhysX`，写入 config、manifest、
   calibration records、summary 与 metrics。
5. 无论成功或失败，保存独立终态 Activity；本次只校准实现协议，不产生独立 Cm 科学假设结论，
   因此 experiment card 仅在后续正式 ranking 产生科学证据时建立或更新。

本计划不授权 corrected calibration 之后自动启动 512-state collector/ranking。calibration 通过后先交接
`epsilon_PhysX`、tie 比例预估和证据入口，再由用户决定下一阶段。

## 6. 风险、停止条件与回滚

主要风险是：消除已知 confound 后，长 prefix duplicate 仍产生远超 ceiling 的 simulator divergence；
公共 score 修改暴露 calibration 与 ranking 的其它时钟/shape 漂移；或现有 frozen collection 无法通过
新增 provenance hard gate。

以下任一情况停止：输入或 runtime SHA 漂移、collection hard gate 失败、公共 score parity 失败、
GPU3 不可用、PhysX/Isaac Gym error、non-finite、task/reference indices 不一致、任一 duplicate 超过
position/rotation ceiling，或输出证据不完整。不得以缩短 prefix、只选 Gate-0 state、改 seed、删失败
state、减小 `epsilon_PhysX` 或放宽统计规则规避。

回滚只撤回 V1.21d 新增的 Task-local score primitive、runner validation、tests、plan/Activity 提交；不
回退已经确认的 30 Hz `_physics_step()` 修复和 randomized env assignment，不修改或删除 frozen
collection、旧失败 run、数据、cache、checkpoint、vendor、V1.21c FINAL plan 或用户指导。
