## 目标与保护边界

执行已实现的 V1.18 主线中的前置阶段：1442-D `+1/+16` reference-conditioned PPO、18-D residual action，先验证 Cm-on planner 工程路径，再训练无 Cm 的 reference-PPO Phase A。Cmv2 `latest.pt`（SHA256 `371fb3396d8fc4ecea61de25178e58954090e26b2f2856aad925f25cb3b01591`）保持只读、`eval()`、无梯度；数据为 `s1_airplane_lift`，world frame、米/弧度、30 Hz、split、reference clock、action/authority/PD、奖励、termination 和 transition-only buffer schema 不变。

官方 DExplore `inspire.pth`（SHA256 `8f6823db752288f1bddd6d042981d33514e29dac5a68e58726e76215fea6d553`）只证明 V1.20 reconstructed DExplore 环境可执行；它的 598-D DExplore schema 与 V1.18 1442-D actor 不兼容，禁止作为本训练恢复 checkpoint。

不覆盖 V1.20 DExplore 数据/checkpoint/output、官方 checkpoint、已有 V1.18/V1.19 outputs、cache、raw data 或 vendor。每次运行均创建新的 `outputs/CmResidual/<run_id>/`，保存 config、manifest、metrics、log、buffer 和实际 checkpoint；产物不提交。

## 阶段与门禁

### Phase 0：Cm-on 工程 smoke

执行前确认 GPU6 仍空闲；在 GPU6 运行单卡、128 env、64 horizon、seed 42、1 PPO epoch、`cm_distill_coef=0.10`、K=8、`plannerEnvMicrobatch=16`、`interactionObjectChunk=32`。成功条件为：完成一个 PPO epoch、all-active coverage、microbatch 不超过 16 env、reward/loss/action/checkpoint finite、checkpoint reload，以及没有 OOM/NCCL/PhysX error。

若 GPU6 不再空闲、或任一成功条件失败，停止并报告；不得自动换卡、启动 Phase A 或改变模型/数据合同。该 smoke 只能产生工程结论。

### Phase A：reference-PPO warm-up

仅在 Phase 0 通过后，于 GPU6 从零初始化运行 `cm_distill_coef=0` 的 scoped reference PPO：64-step window、128 env、seed 42、10 PPO epochs（81,920 env-steps）。该路径必须完全绕过 Cmv2 planner。记录 tracking、contact、object height/lift、scope termination、residual saturation、metrics 和 checkpoint reload；到预算终点即停止，交由用户审阅。

## 明确排除

Cm planner-to-actor distillation Phase B、128/366 window curriculum、多卡训练、online planner action execution、Cmv2 fine-tune，以及任何“抓起来”的科研结论都不在本计划范围。继续到 B 必须以 Phase-A 的明确 pin checkpoint 和新计划补充冻结预算、对照与指标。
