## 目标与可证伪问题

V1.10 不再修改 V1.9.2 的 critic-only Cm 架构，而是执行其尚未开始的 Gate III，回答一个限定问题：

> 在相同 2005-D 环境路径、相同 1442-D actor 输入、相同随机初始化合同和相同 PPO 协议下，
> critic 额外读取冻结的 563-D OI-Cm 上下文，是否在 seed42 的 10-epoch 探索性实验中表现出可复核的行为差异？

对照保持为：

- A（control）：`pi(o_1442)`，`V(o_1442)`；
- B（critic-Cm）：`pi(o_1442)`，`V(o_1442, C_m563)`。

本轮只能给出单 seed 探索性 effect size。即使 B 优于 A，也不得表述为统计显著、因果成立或 Cm 普遍有效；
即使 B 不优于 A，也不得据此否定多 seed、长程训练或后续 OI-Cm V2。

## 已收口的指导口径

1. V1.10 先执行现有实现的 fresh B0-Cm-path、A/B T10 和 deterministic A/B E10；不自动执行 T20/E20。
2. 指导中“重复 seeds”作为后续正式统计方案，不在本轮启动。当前 runner 锁定 GPU5、64 env、seed42，
   V1.9 也已规定单 seed 结果统一为 `INCONCLUSIVE`。
3. 不继续追求两个独立 GPU PhysX 进程的逐 trajectory bitwise 一致；保留 V1.9.2 已通过的静态
   post-build CPU RNG 和首轮 stochastic action exact parity 作为启动合同。
4. 训练 `losses/c_loss`、`losses/a_loss`、KL、residual RMS、saturation 和 success fraction 只作学习动态诊断；
   现有 runner 未记录 advantage variance 或 explained variance，因此本轮不声称直接验证“advantage 更稳定”。
5. deterministic evaluation 的 episode return 只有在 `completed_episode_count > 0` 时才解释；若没有完成 episode，
   manifest 中的数值占位不得当作真实平均回报比较。

## 分阶段执行协议

### Gate 0：运行前合同

在任何 GPU 正式运行前：

- Task tests、相关 Python `py_compile`、runner/evaluator `--help`、Hydra resolved config 和 `git diff --check` 通过；
- control/critic-Cm 的 observation/actor/critic 维度仍为 `2005/1442/1442` 与 `2005/1442/2005`；
- actor state 无 mismatch，Cm 后缀扰动不改变 actor mean/sigma；post-build CPU RNG equality 为 true，
  首轮 stochastic action max absolute difference 为 0；
- OI-Cm 冻结、输入 SHA、reward、residual scale、固定 sigma 和 eligible reference 合同通过；
- GPU5 无冲突，且没有遗留 CmResidual 训练进程。

任一条件失败均不得启动 B0/T10；记录 `INVALID_IMPLEMENTATION` 或阻塞原因，不通过改 seed、GPU 或参数绕过。

### Gate 1：fresh B0-Cm-path

新建唯一 run_id，以 `variant=control`、无 residual checkpoint、全零 18-D residual 在 2005-D Cm 环境路径上执行
GPU5、64 env、seed42、367 steps deterministic rollout。由于 A/B 零 residual 时共享相同环境、OI-Cm 和 action
路径，该 manifest 作为两侧共同 preservation baseline。

继续条件：

- 367 steps 正常完成，observation/target finite；
- `max_residual_target_delta == 0`；
- `mean_env_max_lift_m > 0` 且 mean contact occupancy `> 0`；
- input SHA、reward、residual scale 与后续 E10 protocol 完全相同。

### Gate 2：A-T10 与 B-T10

先后使用独立 run_id 启动 control T10 和 critic-Cm T10；二者均从零初始化，不从 2-epoch smoke 恢复。
运行顺序固定记录但不解释为 treatment effect。每侧必须严格产生 10 个 epoch events 和独立 epoch-10 checkpoint。

每侧继续条件：

- `run_status=COMPLETED`、last epoch/frame 符合 10 epochs 预算；
- model、optimizer、action、observation、reward、value、gradient 和 checkpoint finite；
- sigma 仍为 0.1 且冻结，checkpoint 独立重载 action diff `<= 1e-6`；
- variant schema、actor parity、输入 SHA 和 PPO 配置未漂移。

任一侧失败即停止科研比较：保留两侧已生成证据，不只凭另一侧形成 Cm utility 结论，也不自动重跑或换参数。

### Gate 3：A-E10 与 B-E10

仅在两侧 T10 都通过后，分别显式加载各自 epoch-10 checkpoint，以与 B0 完全相同的 GPU5、64 env、seed42、
367 steps、terminate-on-success、deterministic mean-action 协议执行评估。禁止 latest 模糊选择或跨 variant checkpoint。

每侧 preservation gate 为：

- `mean_env_max_lift_m / B0 >= 0.8`；
- `mean_contact_occupancy / B0 >= 0.8`。

两项均通过只表示没有明显破坏 base 行为。任一侧低于 0.8 时记录 `REFUTED`（对应 preservation 假设），
停止 V1.10，不启动 T20、多 seed 或额外调参。

## 指标与比较规则

### 主要行为指标

- E10 `mean_env_max_lift_m`；
- E10 mean contact occupancy；
- E10 max/final success 指标；
- completed episode count 与 mean completed episode return（仅在 count > 0 时解释）。

同时报告每侧相对 B0 的 preservation ratio，以及 B 相对 A 的绝对差和相对差。单 seed A/B effect size 一律标记
`INCONCLUSIVE`，不设置事后“胜出阈值”。

### 训练诊断

逐 epoch 对齐报告 `losses/a_loss`、`losses/c_loss`、entropy、KL、learning rate、residual RMS、saturation ratio
和 success fraction；可描述曲线形态和方差，但不得用 critic loss 单项证明 value learning 或 Cm utility。
