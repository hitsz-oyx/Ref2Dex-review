## 1. 目标和结论上限

固定对象仍为 DexYCB `subject-10/20201022_110806/right` 的 72 帧、30 Hz、
`002_master_chef_can`。本修订的第一目标不是启动 residual PPO，而是完成并验证下面的可复核闭环：

```text
residual action
  → 现有 DExplore controller / nominal q target
  → Inspire URDF/FK
  → nominal hand surface sweep
  → frozen ObjectInteractionCmv2 V1.3
  → predicted object SE(3) effect
```

reference object transition 提供期望 effect；在同一仿真状态生成多个可行候选动作，比较 Cmv2
预测 effect 与真实执行 effect，并检查它是否能正确排序候选动作。只有这个 action-conditioned
接口和 MANO→Inspire 迁移证据通过，才起草下一版 residual PPO 计划。

本轮不把 `cm_tokens` 直接拼接到 actor/critic 作为主研究接口，不解冻或用 PPO 梯度训练 Cmv2，
也不把 Cmv2 当作替代 Isaac Gym 真值 reward 的模型。单轨迹、单物体、单 seed 的排序和误差只能
说明该接口在此对象上的工程/行为证据，不能证明泛化、统计显著性或 Cmv2 的因果收益。

## 2. 固定不变量和输入边界

- 基线固定为远端 `origin/oyx` 提交 `e444b1d0cce192dc9a310f0dcfd7bb67eea8f67c` 的独立工作树；不在含用户 `ObjectInteractionCm` 改动的工作树执行 reset、merge 或覆盖。
- DExplore checkpoint、1442-D observation、base action、18-D residual、物理尺度 `0.015 m / 0.20 rad / 0.08 rad`、mimic、关节限制、机器人/物体资产、z-up 米制和现有 reward 保持不变。
- Cmv2 只接受 `architecture_version=v1_3_rigid_only`，模型快照固定为 `hidden_width=128`、`num_tokens=16`、`use_residual=false`、`knn_k=32`、`interaction_radius_m=0.02`、`interaction_mode=swept`、`feature_scale_m=0.02`、`frame_dt=1/30`；checkpoint 路径和 SHA256 在真实 gate 前固定。
- Cmv2 采用 `eval()`、无梯度、冻结参数；不修改其 GRAB/MANO 训练代码。FK/URDF 是确定性动作实现层，不训练 FK，也不把 realized post-contact hand state 冒充 nominal sweep。
- Cmv2 在线输入只来自当前仿真 object/hand geometry 和当前候选 action 通过 controller/FK 生成的 nominal hand sweep。不得读取下一帧 DexYCB hand/object、仿真执行后的 object pose 或监督 GT 生成预测输入。
- 一步时间差固定为 `1/30 s`；大跨度 reference 只用于 desired effect 或评估，不改变 Cmv2 的局部 transition 合同。

## 3. Action-conditioned Cmv2 合同

### 3.1 动作实现

候选动作使用现有 18-D residual 语义。对每个仿真状态，先用 frozen DExplore base action 和
`compose_physical_residual` 得到候选 native q target；随后用锁定 Inspire URDF/FK 生成 nominal
next link poses、1538 个 hand surface points/normals 和
`hand_flow = hand_points_nominal_next - hand_points_current`。该 flow 是 controller/FK 的
nominal prediction，不是接触后真实 hand motion。初始帧 flow 严格为零，所有 pose/flow 在同一
world frame、米和 1/30 s 中表达。

候选动作 batch 维度显式保留 `[B,K,...]`；不得把不同候选的 points、mask 或 effect 混排。候选
超出 q/mimic/速度/加速度约束时，在进入 Cmv2 前标记 invalid 并排除，不靠裁剪掩盖动作实现错误。

### 3.2 Cmv2 输出和 effect 指标

Cmv2 输入为 `obj_points[1024]`、`obj_normals[1024]`、`hand_points[1538]`、`hand_normals[1538]`、
`hand_flow[1538]`、`hand_valid_mask` 和 `delta_time_s=1/30`。输出保留 `delta_xi_root`、
`obj_flow_pred`、`cm_tokens`、anchors、normals、mass、mask；结构化输出是 action evaluator 的
事实接口，640-D latent 编码只可作为诊断字段，不能让 PPO 静默退回旧的 observation concat。

reference desired effect 优先由相邻 object poses 计算：`T_obj,t^{-1} T_obj,t+1`。reference
Cmv2 只作为离线对照，不作为在线候选输入。候选误差至少记录 translation norm、SE(3) rotation
angle、point-flow error 和 finite/empty-token；所有指标都区分 predicted effect 与真实执行 effect。

## 4. 数据和评估边界

- V1.11 的 evaluation-only reference、source、raw 数据和 cache 只读；本修订不复制旧 manifest 后翻转 `training_eligible`，也不先生成新的 PPO training split。
- desired effect 使用该 72 帧 reference 的相邻 object pose；不得随机拆分成 val/test，也不得借用其他 DexYCB sequence。
- 物理评估在固定仿真状态采样 `K=8` 个可行候选 residual（包含 zero residual 和 base 附近的小扰动，采样规则、seed 在 run manifest 冻结），逐个执行一个 control step 后读取真实 object transition。
- 主要证据为 predicted-vs-true SE(3)/flow 误差、候选排序 Spearman/Kendall 相关、top-1 desired-effect 选择率、contact occupancy、tip distance、relative lift 和 residual 饱和。几何近邻不冒充接触力 GT。
- 该实验只回答“在此 Inspire/YCB 状态上，nominal action sweep 经 Cmv2 是否有可用的 counterfactual effect/ranking 信号”；MANO→Inspire 分布迁移若未通过，结论为 `INCONCLUSIVE` 或 `INVALID_IMPLEMENTATION`，不启动 PPO。

## 6. 分阶段门禁

1. **静态合同 Gate**：config/adapter/evaluator `py_compile`、定向 tests、`git diff --check`；验证候选 batch shape、18-D residual parity、FK 输出、Cmv2 strict load/freeze、empty-token finite 和 no-future-leakage。
2. **真实 checkpoint Gate**：用户放入 checkpoint 后固定路径/SHA，严格加载 V1.3；单批 Inspire geometry 推理有限、耗时/显存可记录。失败即止。
3. **nominal sweep parity Gate**：用同一状态和 action 对比 `compose_physical_residual`、URDF/FK、surface sampling 的 hand points/normals/flow；reset 首帧零 flow，候选之间无串扰。
4. **counterfactual physics Gate**：单轨迹中固定状态/seed，K=8 候选逐个执行一个 control step；验证 predicted-vs-true effect 误差和候选排序。运行使用新 `run_id`、空闲 GPU5（仅在资源确认后），不启动 PPO。
5. **PPO 决策 Gate**：只有 Gate 1–4 通过且 MANO→Inspire ranking 证据达到预先记录的最低标准，才与用户另行确认 residual PPO 的 actor/critic 输入、候选 reranking 或 effect feature、训练 reference、GPU 预算和对照设计。V1.12 不自动进入 2/10 epoch PPO。

每次正式评估的 `outputs/CmResidual/<run_id>/` 必须含 config、run_manifest、metrics、eval log、
checkpoint 引用和 effect/ranking 结果；activity 记录秒级 timestamp、`activity_id`、`run_id`、
`run_status`、`base_commit`、候选 K/seed、输入 SHA、终态和链接。工程 smoke 不作为科研效果结论。
