## 目标与可证伪假设

V1.9 在保持 V1.8 安全 residual PPO 不变量的前提下，只检验一个增量问题：critic 使用现有冻结 OI-Cm
上下文，是否相对严格匹配的 no-Cm critic 对照改变短程 residual 学习。实验变量唯一为 critic 可见的输入：

- A（matched control）：actor 与 critic 都只读取 `o_1442`；
- B（critic-only Cm）：actor 只读取 `o_1442`，critic 读取 `concat(o_1442, C_m563)`。

这里的 `C_m563` 固定为当前实现的 `16×32` tokens、`16×3` anchors 和 `3-D` mean predicted object flow；
后 3 维属于现有上下文，不再额外拼接 `e_hat` 或 `e* - e_hat`。本版本不声称直接检验 OI-Cm V2、
actor-conditioned correction 或 Cm 表征的普遍有效性。

## 冻结输入与身份

- OI-Cm checkpoint 固定为
  `outputs/objectinteractioncm/object_interaction_cm_dexplore_rl_v1_3_20260910_020856/checkpoints/best.pt`，
  SHA256 固定为 `3a3d6c0f88565b9e41f257e4f8b87a3ca5731fd356a98f4514091754036a7283`。
- OI-Cm 始终 `eval()`、所有参数 `requires_grad=False`，并仅在 `torch.no_grad()` 中推理；checkpoint、
  schema、点数、slot 数、feature dim 和 scale manifest 均须在启动前校验。Cm 不参与 optimizer、PPO
  gradient 或 checkpoint 更新。
- DExplore checkpoint、eligible v2 reference、legacy-parity source tensor及其既有 SHA 保持 V1.8 不变。
- 不允许“自动选择最新 checkpoint”；任一输入文件身份不一致即停止。

## 严格匹配的 A/B 观察合同

为避免把 OI-Cm 推理开销、环境代码路径或随机初始化差异混入 critic 对照，A/B 都由 Task 构造同一份
`2005 = 1442 + 563` observation，并加载同一个冻结 OI-Cm checkpoint：

1. actor 在 A/B 中都只切取前 1442 维；Cm 后缀不得进入 actor MLP、mean head 或 sigma；
2. A 的 critic 也只切取前 1442 维，B 的 critic 才读取完整 2005 维；
3. 输入 normalizer 可以维护 2005 维逐维统计，但 actor 只消费归一化后的前 1442 维；必须用测试证明
   改变 Cm 后缀不会改变 actor 输出；
4. A/B 使用相同 seed 重新从零初始化 residual policy，不加载 V1.8 或 V1.7 residual checkpoint；
5. reset 同一随机种子后，A/B 的 actor hidden layers、mean head、sigma 逐 tensor 完全相同，且在相同
   `o_1442` 上 deterministic/stochastic actor 输出一致；critic 参数或输入宽度允许不同。初始化 parity
   不满足时禁止启动训练。

A 是 V1.8 no-Cm 网络语义的匹配复跑，不复用 V1.8 E20 数值充当本次唯一对照。A/B 均计算但 A 完全忽略
Cm，使二者除 critic 信息外共享相同环境与 observation 生成路径。

## 实现范围

1. 扩展 `CmBuilder`，显式声明并校验 `actor_input_dim=1442` 与 `critic_input_dim=1442|2005`；仅支持
   `separate=true`，在 `eval_actor`/`eval_critic` 内执行确定性前缀切片，禁止依赖隐式共享 trunk。
2. 新增 V1.9 matched-control 与 critic-only-Cm 训练配置；二者均继承 V1.8 的零 mean、固定
   `sigma=0.1` 和 PPO 超参数，只允许 critic input dim 不同。
3. 新增或扩展 Task-local V1.9 runner，支持显式 `--variant control|critic_cm`，为每个 stage 写入独立
   `outputs/CmResidual/<run_id>/`，记录 variant、输入 SHA、actor/critic schema、初始化 parity、resolved
   config、metrics、日志、checkpoint 校验和终态 manifest。
4. 扩展 deterministic evaluation，使其按 checkpoint 内的 V1.9 schema 构造 2005-D observation，actor
   仍只使用 1442-D 前缀；评估不得把 critic value 或 Cm 后缀送入 action 路径。
5. 增加 Task-local 合同测试，覆盖观察切片、actor 后缀不变性、A/B actor 初始化 parity、critic 输入敏感性、
   OI-Cm 冻结、checkpoint schema、固定 sigma、manifest 和旧 V1.8 1442-D checkpoint 兼容路径。

若实现必须修改 `src/base/`、rl_games 公共 agent、ObjectInteractionCm 模型/数据合同，或无法在 Task-local
builder/runner 内实现上述非对称输入，应暂停并重新协商，不得扩大范围。

## 保持不变的科研与工程边界

- action 维度保持 18；mean 精确零初始化，state-independent `sigma=0.1` 且不可训练。
- physical residual scale 保持 `0.015 m / 0.20 rad / 0.08 rad`；mimic/null direction、action mapper、
  joint-limit clamp 和 saturation 语义不变。
- reward 保持 `20*lift - 2*tip_distance - 0.01*mean(residual^2)`；success threshold、reset、reference
  frame、坐标系、单位和 simulator 参数不变。
- 网络 hidden units、activation、PPO optimizer/hyperparameters、64 env、horizon 32、minibatch 2048、
  seed 42、physical GPU5 和 deterministic 367-step evaluation protocol 保持 V1.8 不变。
- 不修改指导文档、OI-Cm checkpoint/模型、ObjectInteractionCm 工作区、数据/cache/schema、共享 `src/base/`、
  外部 DExplore checkout、旧 checkpoint/output 或其他 Task。

## 分阶段验证与实验协议

### Gate I：静态与 CPU 合同

- Task tests、Python compile、Hydra resolved-config 和 runner `--help` 通过；
- A/B 都解析为 2005-D Task observation、1442-D actor；A critic 为 1442-D，B critic 为 2005-D；
- 对相同 actor prefix 任意扰动 563-D 后缀，A/B actor mean 与 sigma 的最大绝对差均为 0；
- OI-Cm 参数冻结且不在 residual optimizer 中；旧 V1.8 1442-D safe config/reload 测试保持通过。

### Gate II：最小 wiring smoke

在用户单独确认启动后，A/B 各运行相同的短 smoke。两者必须完成相同 update 数，observation、reward、
action、value、gradient、optimizer 与 checkpoint 全部 finite，checkpoint 独立重载 action 差 `<=1e-6`。
smoke 只支持工程 wiring，不作为 Cm 效果证据。

### Gate III：seed42 配对短程实验

正式运行仍需用户单独确认，并采用独立 run_id：

1. **B0-Cm-path**：2005-D 环境路径、全零 residual、GPU5、64 env、seed42、367 steps，重新记录
   `mean_env_max_lift_m` 与 mean contact occupancy；只有协议、输入 SHA 和 zero-target parity 通过才继续。
2. **A-T10 / B-T10**：A/B 从各自经 parity 验证的同 seed 随机初始化训练 10 epochs。
3. **A-E10 / B-E10**：分别加载各自 T10 checkpoint，执行同一 deterministic mean-action protocol。
4. 只有 A、B 在 E10 都达到 B0 的 lift/contact `80%` preservation gate，才允许各自从明确的 T10
   checkpoint 恢复至总 epoch 20。
5. **A-T20 / B-T20 / A-E20 / B-E20**：保持 variant 隔离；禁止跨 variant resume 或共享 optimizer state。

运行顺序、GPU、seed、预算、resolved config 和输入 SHA 写入 manifest。运行顺序本身不得被解释为处理效应；
任一 variant 失败时保留两侧证据，不以另一侧单独结果形成 Cm utility 结论。

## 指标与结论规则

### 工程结论

- 非对称 observation wiring、actor 后缀不变性、冻结 OI-Cm 和 checkpoint reload 全部通过，可标记
  `SUPPORTED`（工程）；
- 任一合同失败标记 `INVALID_IMPLEMENTATION`，不得进入科研比较。

### seed42 探索性比较

- 主要行为指标：E10/E20 的 `mean_env_max_lift_m`、mean contact occupancy、success fraction 和 episode return；
- 训练诊断：逐 epoch `losses/c_loss`、`losses/a_loss`、KL、residual RMS、saturation 和 success fraction；
- `losses/c_loss` 受 on-policy 分布和 value normalization 影响，只作诊断，不单独证明 value estimation 改善；
- preservation gate 只证明没有明显破坏 base，不证明 Cm 有益；
- 单 seed 的 A/B 差异统一标为 `INCONCLUSIVE` 的探索性 effect size，不使用“显著提升”或因果成立表述。

若 seed42 工程合同和双侧 preservation 均通过，再提交一份包含 seed 集合、配对统计、独立 benchmark 和
预注册判据的后续实验方案；重复 seed 不在本计划内自动启动。Experiment C 也不因任一单次指标自动启动。

## 停止条件

- actor 读取 Cm 后缀、A/B actor 初始化不一致，或 critic schema 与 variant 不符；
- OI-Cm checkpoint/SHA/schema 不符，参数可训练，或出现 Cm gradient；
- observation、target、reward、value、gradient、optimizer、action 或 checkpoint 出现 non-finite；
- initial mean 非零、sigma 不等于 `0.1`、sigma 可训练，或 action/reward/residual 不变量漂移；
- subprocess、Isaac Gym/PhysX 异常退出，checkpoint 独立重载不一致；
- E10 任一 variant 的 lift/contact preservation ratio `<0.8`。

停止后写入 `FAILED`/`STOPPED` 及对应 conclusion，不静默换 checkpoint、seed、GPU、阈值、网络输入、reward、
训练预算或追加长训。
