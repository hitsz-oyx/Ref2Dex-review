## 1. 目的与旧证据解释

V1.21e 的 16-state run 保留为当前实现的 `INVALID_IMPLEMENTATION`；其 snapshot Markov parity
科学问题仍为 `INCONCLUSIVE`。该 run 在同一 simulator 内用两个 vectorized env 形成 duplicate，且
restore 路径在 GPU tensor setter 后、下一次 simulate 前执行 refresh，因此不能据此判定 public
snapshot 不足。

本微补充只排除上述两个 confound。它不改变 V1.21e 的研究问题，不授权 16-state 扩大实验、
64-state calibration、512-state ranking、PPO、P=3、Cmv2 更新或长训。

## 2. 修订协议

- 只读复用正式 V1.21e run
  `cmresidual_v121e_snapshot_parity_gpu3_20260920_2130` 已保存的 snapshot/episode artifacts，
  不重新采集、不修改源 NPZ/manifest；按 canonical `state_id` 确定性选择 exactly 6 states：
  `2 moving / 2 contact / 2 precontact`。源 artifact identity 或 phase/episode gate 失败时停止。
- 每个 state 顺序启动四个完全独立的 fresh subprocess/simulator：`A1/A2` 为 initial state +
  recorded prefix + actor-mean action，`B1/B2` 为 direct public snapshot restore + 同一 action。
- 每个 subprocess 只有 `num_envs=1`；四臂使用相同 state seed、相同 snapshot 和相同 actor-mean
  action，不在一个 simulator 内构造 duplicate。
- initial restore 与 snapshot restore 均遵循 GPU pipeline 顺序：reset 已完成后写 q/dq/root tensor
  buffer 和 task bookkeeping，调用 root/dof setter；在 candidate 前不得 refresh、不得从 simulator
  重算 observation 或 IG。下一次读取只发生在正常 `pre_physics_step → simulate × 2 →
  post_physics_step` 之后。
- pre-action current pose、canonical IG、raw observation 与 score baseline 全部来自 collector
  snapshot。producer 记录 snapshot SHA256、setter 输入 q/root SHA256、与 snapshot 的 max-abs
  error（必须为 `0`）、setter 返回状态、task indices/bookkeeping 和 candidate action SHA256。
- GPU pipeline 无法在不插入额外 simulate 的情况下观察 setter 后的 PhysX 内部状态；因此上述记录
  只证明 setter 输入一致，不声称读取了 setter 后内部状态，也不为验证而增加 simulate。
- 同步删除 `v121c_prefix_replay.py::restore_initial()` 中 setter 后、candidate/prefix simulate 前的
  refresh/observation 重算。旧 V1.21d failure 原样保留，并注明受该 restore-order confound 污染；
  不将其重写为通过，也不归因于单一原因。

## 3. 保持不变的合同与 gate

- 官方 checkpoint、runtime、reference、坐标、单位、native 18-D action、30 Hz/two-substep、
  canonical IG 和公共 PhysX score primitive保持不变。
- shared canonical baseline、`t+6` object goal、`t+1` IG target保持不变；offline evaluator 只消费
  producer score。
- object duplicate 与 cross-method hard ceiling仍为 `5e-4 m / 5e-3 rad`；所有 metric floor、
  `5 × duplicate difference` 规则和 finite/provenance/task-index gate保持不变。
- 6 个 state 全部运行并报告，不因首个 parity 失败提前停止；实现/input/runtime/PhysX hard failure
  仍立即停止。不调整 threshold、seed、state 或 phase 来绕过结果。

结果解释保持三分：四臂均可重复且 A/B parity 通过为 `SUPPORTED`；A/B 各自可重复但 cross-method
有效失败为 `REFUTED`；任一 duplicate、输入、setter provenance 或实现 gate 失败为
`INVALID_IMPLEMENTATION`。科学结论仅限 public snapshot one-step parity，不外推 Cm ranking 或策略效果。

## 4. 验证、运行和回滚

定向测试覆盖：四个 `num_envs=1` 独立命令、6-state `2/2/2` selection、setter 后无 refresh/observation、
canonical pre-action baseline、setter 输入 hash/error/status、四臂 identity 与 parity metrics，以及
V1.21c initial restore 的顺序。随后执行 Task pytest、`python3 tools/verify.py --changed` 和
`git diff --check`。

实现验证通过后先提交固定代码，再在 physical GPU3、logical `cuda:0` 以新 `run_id` 顺序运行
24 个单环境 subprocess。输出写入 `outputs/CmResidual/<run_id>/`，记录独立 manifest/config/
metrics/log/summary；终态写 Task Activity 与 experiment card，生成产物不提交。

代码回滚为 revert 本微补充的 Task-local implementation commit；不修改或删除 V1.21e/V1.21d
代码历史、计划、指导、outputs、数据、cache、checkpoint 或 vendor。运行产物无论结论均作为证据保留。
