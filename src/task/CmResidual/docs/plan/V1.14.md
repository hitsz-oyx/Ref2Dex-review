## 目标

保留 GRAB `s1_airplane_lift` 的确定性 retargeted reference base：每个动作仍是
`q_ref[t+1] + residual`，零 residual 必须严格退化为 `q_ref[t+1]`。将 residual 的优化目标从
`lift - tip-distance` 改为物体相对同一 reference 的当前 pose 与一步 transition 跟踪，并用可复现的
reference-state 随机短窗口初始化改善接触/抓取阶段的 credit assignment。

本版先证明新的训练闭环可解释；不把工程接线、单 seed PPO 曲线或 Cmv2 预测当作抓取效果或 Cmv2
utility 的科研结论。

## 固定边界与不变量

- 数据固定为现有、训练准入的 GRAB `reference_tracking_v2/s1_airplane_lift`，其 SHA、367 帧、30 Hz、世界坐标、米/弧度、object pose 和 split 不改；不得重写 reference、GT、cache 或 manifest。
- 保留 Inspire/YCB 资产、PhysX 参数、腕部 `400/40` / 手指 `100/10` drive、18-D residual authority、mimic coupling、joint-limit clamp、`q_ref[t+1]` 时钟和现有 68-D policy observation。旧 DExplore 路径、旧 PPO 配置、旧 checkpoint、既有 outputs 与共享 `src/base/` 不改。
- reference state `T_ref[k]` 只用于 reset、当步/下一步 reference observation 及 reward target；不得把执行后的 simulator state 或 future simulator state 输入 actor。reward 可在环境 transition 后比较实际 `T_obj[t]` 与同 index 的 `T_ref[t]`，但这不是 actor observation。
- Cmv2 保持冻结且不拼接到 PPO observation、不代替 Isaac Gym reward、不控制 phase。本版只保留已有 `evaluate_cmv2_actions()` 接口，待 reference-tracking PPO 有独立基线后再协商其 candidate-selection 或 auxiliary-objective 版本。

## 分阶段范围与停止条件

### A. 真实物体 zero-residual reference 基线（先执行）

扩展 Task-local `eval_grab_retargeted_base.py` 的 `physical` 协议，使每个 step 同时记录实际和 reference
object 的世界 pose、位置误差、旋转测地误差，以及实际/参考一步相对变换的平移与旋转误差。索引固定为
第 `step` 个执行后状态对应 `reference_index=step`；transition 比较 `T_obj[step-1]^{-1}T_obj[step]` 与
`T_ref[step-1]^{-1}T_ref[step]`，不混用 frame 0 或未来状态。

在 GPU5、1 env、seed42、366 steps、真实 object、zero residual、`terminateOnSuccess=false`、`400/40`
下运行一个新 run。该 run 的工程硬门为：reference/SHA 合同、366 行、finite、zero target delta、无异常
reset/进程失败和可解析 manifest/metrics/log；不以 lift 或 success 判为“跟踪成功”。若工程门失败，停止，
不改 reward、不做 PPO。若通过，报告完整 object tracking 曲线及与 `t-1/t/t+1` 的时间对齐诊断；该结果是
后续 reward 可解释性的证据，不预先宣称其必须达到某个抓取阈值。

### B. reference-transition reward 与 reference-window reset（仅在 A 的工程门通过后实现）

新增独立的 V1.14 Task/train 配置和 Task-local runner，不改写 `CmResidualGrabRetargeted` 或 V1.13 runner。

1. 为 retargeted provider 增加按每个 env 的 reference 起点 `k` 读取 `q_ref[k]`、`dq_ref[k]`、
   `object_state_ref[k]` 的受检 reset 接口；Task 在 reset 时将 hand DOF、object root state 和
   `reference_index` 同步设到相同 `k`。采样范围必须保证 `k + window_length <= 366`，并将所选 `k`、
   window length 和 RNG/seed 写入 metrics/manifest。frame-0 full trajectory evaluation 保留 fixed start，
   不能被随机窗口替代。
2. 在 post-transition reward 中维护上一实际 object pose。新增下列只读诊断指标：
   `reference_object_position_error_m`、`reference_object_rotation_error_rad`、
   `reference_object_transition_translation_error_m`、
   `reference_object_transition_rotation_error_rad`。旋转误差用 SO(3) 相对旋转角，transition 用对象局部
   `T[t-1]^-1 @ T[t]`，与 `src/task/CmResidual/cm_v2_action_evaluator.py` 的
   `object_pose_delta_to_xi()` 保持同一坐标语义。
3. 新 reward 只由上述四项 reference tracking error 的负加权和与原 action penalty 构成：
   `-(e_pos/0.02 + e_rot/0.05 + 0.5*e_delta_pos/0.02 + 0.5*e_delta_rot/0.05)
   - 0.01*mean(residual^2)`。`0.02 m/0.05 rad` 是本 reference 一步 object delta 的 p95
   `0.01584 m/0.03360 rad` 的向上取整尺度；不得用训练中观察到的 reward 曲线临时改权重或尺度。
   `lift`、`tip-distance`、contact occupancy 与 success 继续记录为诊断，不能作为此配置的优化项或终止条件。
4. 新配置以 `referenceStart.mode=random_uniform` 和显式 `windowLength` 区分训练；短窗口课程固定为
   `64 -> 128 -> 366` 个 control steps，每一阶段独立 run/checkpoint，均从同一明确的初始化策略开始。
   每个阶段为 GPU5、64 env、seed42，先 2 epochs smoke 后从该 checkpoint 续跑 8 epochs；64-step 阶段
   horizon 为 64，128/366-step 阶段 horizon 为 128，minibatch 均为 2048。因而每 env 分别至少覆盖
   10、10、3 个完整窗口/episode；366-step 阶段不再重演 V1.13.4 的“没有完整 episode”问题。任何 epoch
   的 `residual_saturation_ratio > 0.05`、非有限值、zero-residual parity 失效或 checkpoint reload 失败即停止，
   不自动扩大 epoch 数或 residual authority。

### C. PPO 与评估（仅在 B 的实现/短窗口 smoke 通过后运行）

每个课程阶段先进行小预算 GPU5 smoke，再由同一冻结配置运行预先确定的训练预算；所有阶段用不同
`run_id`，并记录 seed、start-frame 分布、window、完整 episode 数、target saturation、四项 reference
tracking 指标、checkpoint reload 及失败原因。每个阶段之后只用 frame-0、366-step、zero residual 和
deterministic policy rollout 作独立评估；训练 rollouts 不作为完整轨迹效果结论。

若真实物体基线或随机 reset 显示 state 不可复位、index/transition 不一致、追踪误差非有限、target saturation
超预先冻结阈值或 checkpoint 不能重载，立即停止该阶段。Cmv2 接入、多 seed、更多物体/轨迹、reward 权重
搜索和任何大规模 PPO 预算均不属于本草案，需另行计划和用户批准。

## V1.14.3 后的局部可行动作映射修订（最终版）

V1.14.3 诊断显示 native finger DOF 8、14、15 的 nominal reference target 在部分 phase 已位于 joint
boundary；固定 `sigma=0.1` 下其 saturation 分别为 `41.57%/21.65%/11.43%`，其余 15 个维度为零。
因此不缩小全局 translation/rotation/finger scale，也不放宽 `5%` 门禁。

拟在 `compose_reference_residual()` 中把每个动作分量的 configured authority 变为相对于 absolute base
target 的**有符号可行 authority**：正 residual 的上限为 configured authority 与所有受 joint/mimic limit
剩余余量的较小者；负 residual 类似取下余量。mimic source 的可行动作区间同时由 source 与所有耦合 mimic
joint 的 limit 反推，故 target 仍严格满足 coupling。wrist 的无界 DOF 保持现有 configured scale。此映射使
zero action 仍精确得到 `q_ref[t+1]`；靠近边界的 outward action 的 effective authority 可为零，必须作为
`authority_limited` 指标记录，不能伪装成原 scale 下成功执行的 residual。

拟修改 Task-local action mapping、transition task metrics、V1.14 config/runner 与定向测试；不改 reference、
reward 权重、18-D action 维度、joint limits、mimic、checkpoint、PPO 超参数、Cmv2 或共享 `src/base`。先运行
unit/GPU 1-env zero-action 与 boundary smoke；通过后仅重跑既定 64-step GPU5 `2+8` stage。继续条件为 finite、
zero-action parity、target saturation 为零、checkpoint reload 通过；`authority_limited` 仅诊断记录，暂不以
新阈值阻断。若 mapping 不能保持上述不变量，停止，不进入训练。

影响等级 `L2`，GPU run `L3`；回滚仅删除该映射/config/test/runner 增量和对应 activity，保留 V1.14.1–3
证据。status: `final`；approval: `user-approved`（用户审阅本修订后回复“你继续吧”）。

## V1.14.5 action-conditioned Cmv2 与 CmBuffer 修订（最终版）

- status: `final`
- approval: `user-approved`（用户明确确认“可以，然后开始吧”，并确认 buffer 不存点云、OI-Cm 不进入 actor/critic 或更新）。
- change_level: `L2`；后续三卡物理训练与容量探测为 `L3`。

### 目标与固定边界

保留 68-D PPO actor/critic、reference-transition reward、18-D residual、V1.14.4 可行动作映射和冻结 PPO
超参数。启用的不是历史 OI-Cm token context，而是现有冻结的 action-conditioned `Cmv2ActionEvaluator`：它只对
**已执行** residual 的 nominal `q -> PD target -> FK -> hand sweep` 预测 object effect，不将输出反馈到 actor、
critic、reward、candidate selection 或任何优化器。

每个执行 transition 写入 CmBuffer 的最小可重建状态：pre/post native `q/dq`、pre/post object pose、residual、
nominal reference target、实际 PD target/applied delta/authority flag、reference index/window progress、Cmv2
prediction、reference local effect 与 PhysX actual local effect。不得写入 object/hand points、normals、flow 或
Cmv2 token；它们仅可由固定 URDF/mesh、deterministic surface sampling、buffer schema、pinned asset/reference/
Cmv2 SHA 与所存状态离线重建。每个 rank 独立 chunk/shard 和 manifest，禁止多进程写同一文件。

冻结 Cmv2 checkpoint 为 `third_party/IsaacGymEnvs/isaacgymenvs/tasks/cm_residual/latest.pt`，SHA256
`371fb3396d8fc4ecea61de25178e58954090e26b2f2856aad925f25cb3b01591`；只允许 `eval`/inference mode 和
`requires_grad=False`。未来是否微调只能基于 buffer 的 prediction-vs-PhysX error、coverage 与候选排序诊断
另立计划，不能由本次 buffer 自动触发。

### 实现、验证与运行边界

- 新增 Task-local `cm_buffer.py`，写入版本化 compressed shard 和 manifest；flush 采用有限 chunk，记录 rank、
schema、source checkpoint/reference/asset hashes 与采样语义。
- 新增独立 task config/registry/runner 路径，不改写 V1.14.4 no-Cm config 或其已生成 config snapshot；Task 在
pre-physics 记录 prediction 和 pre-state、在 post-physics 记录真实结果。只有实际执行 action 有 PhysX label，
不得把未执行 candidate 伪装成训练样本。
- 单元测试覆盖无点云 schema、chunk round-trip、pre/post local effect 对齐、冻结/68-D contract；GPU5 单 env
zero/nonzero smoke 必须验证 finite、Cmv2 prediction、buffer shard/manifest、zero residual parity 和无 PPO update。
- 三卡分布式或“最大 numenv”训练在此实现门通过后另行确定：必须先有每卡容量/吞吐诊断、固定的总 env-step 或
人工停止记录、rank-to-GPU 映射和每 rank output。不得以无终止条件的无限训练替代这些运行合同。

回滚仅删除本修订新增的 Cmv2 buffer config/adapter/runner/test/records；不删除生成的 buffer shards、旧 outputs、
reference、checkpoint 或用户已有改动。
