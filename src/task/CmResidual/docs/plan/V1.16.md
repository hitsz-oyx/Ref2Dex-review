## 目标

在不改变 V1.15 actor/critic 表示的前提下，令 actor-side nominal-base Cmv2 完全在 GPU 上运行：从当前
PhysX hand link poses 与同一 GPU 上的 `reference.link_pose[t+1]` 直接生成 Cmv2 hand sweep，不再调用
CPU/NumPy `InspireKinematics`。同时把正式训练的 CmBuffer 收敛为 transition-only、以 GPU staging 批量转存，
并提供基于现有 rl_games DDP 的 GPU0/1/2 三 rank launcher 和容量门。

## 保持不变的合同

- raw actor observation 仍为 `[base68, token16×40, predicted6, reference6, error6]=726-D`；网络内仍为
  `68+128+18=214-D`，critic 只读取 base `68-D`。
- `q_base=q_ref[t+1]`、18-D residual、V1.14.4 feasible authority、mimic/joint limit、400/40 wrist PD、
  reference-transition reward、random reference window、reference/SHA、Cmv2 checkpoint/SHA/schema/model weights
  均不变。Cmv2 继续 `eval`、`requires_grad=False`、inference-only，且不进入 reward、critic、optimizer。
- 不增加 MPPI、action chunk、proposal/correction、Cmv2 reward shaping、Cmv2 critic input 或 hard contact gate。
- 旧 V1.14/V1.15 config、buffer shard 与输出保留可复现；V1.16 使用新的 task/train config 和 buffer schema，
  不把 transition-only 解释回写到历史 shard。

## 实现范围

1. **GPU nominal-base Cmv2**：Task 初始化时按 `QUERY_LINKS` 构建并校验 `reference.link_order` 的索引映射。
   在 `compute_observations()` 直接以 current GPU `links` 和 `reference.link_pose[next_idx]` 生成
   current/next hand surfaces 和 `flow=H_ref_next-H_actual`，再用实际 object GPU surface 调 frozen Cmv2。
   此 actor 热路径禁止 `.cpu()`、`.numpy()`、`InspireKinematics` 与 `evaluate_cmv2_actions()`；reference link
   pose 缺失、顺序不匹配、shape/finite 不合法时 fail fast。保留 legacy executed-action evaluator 仅供旧 V1.14.5
   config/离线诊断，V1.16 transition-only 路径不调用它。
2. **transition-only CmBuffer v2**：新 schema 精确只允许指导列出的 16 个 pre/action/reference/post/actual-effect
   字段；禁止 `predicted_delta_xi`、`predicted_effect_score`、`candidate_valid` 及任何 point/normal/flow 字段。
   `pre_physics_step()` 不再为 buffer 调 executed-action Cmv2；post-step 仅计算 actual local effect 并 append。
   V1.14.5 schema/读取兼容保持。
3. **GPU staging 写盘**：buffer append 只 detach/保留 GPU tensors，并检查 batch/schema；到 `flushEvery` 或关闭时，
   按字段在 GPU cat、一次批量 CPU transfer、写一个 compressed NPZ。rank 独立目录仍是
   `cm_buffer/rank_{rank:03d}`；新 config 默认 `flushEvery=8192`，不在逐 transition 同步/转 NumPy。
4. **base-only RMS**：增加专用 Cmv2 actor model wrapper，使 `normalize_input=true` 时仅对 raw observation prefix
   `base68` 运行 rl_games `RunningMeanStd`；token 16×40 原样保留，effect 三组继续由 Task 的
   `0.02m/0.05rad` 显式 normalization/clamp。新的 checkpoint 仅在 V1.16 config 下解释，V1.15 checkpoint
   不尝试加载到新 model wrapper。
5. **DDP launcher/config**：新增 V1.16 task/train config 和 Task-local runner。runner 只接受显式
   `--gpus 0,1,2`、`--envs-per-rank {128,256}`、`--activity-id`、`--modification-version` 与唯一 run id，
   通过 `torchrun --nproc_per_node=3 ... multi_gpu=True` 复用 rl_games NCCL/DDP；每 rank 从 `LOCAL_RANK/RANK`
   使用本地 Isaac Gym、frozen Cmv2 和独立 CmBuffer 目录。rank 0 负责汇总 manifest/checkpoint，runner 在启动前
   检查 GPU 空闲、world size、每-rank env、726/214/68 contract、buffer schema 和输出目录不冲突。
6. **测试与 gates**：新增 CPU tests 覆盖 reference-link mapping、GPU-sweep 输入等价/无 CPU FK 调用的静态合同、
   transition-only field whitelist、GPU staging 合并和 base68-only RMS；GPU5 1-env smoke 验证一 step 仅触发一次
   Cmv2、target saturation/finite、v2 shard。仅在其通过且 GPU0/1/2 空闲后，运行独立 L3 `3×128` capacity probe；
   其显存/throughput/Cmv2 finite/三 rank buffer manifest 都通过才允许另次批准的 `3×256` probe 或正式训练。

## 验证与回滚

- 静态：`py_compile`、Hydra resolved config、Cmv2/Task/model/buffer/runner 定向 tests、`git diff --check`；
  activity link audit 使用仓库 `graspenv` Python。
- GPU5 smoke 只证明 GPU nominal path、single-Cmv2 count、v2 buffer 和 checkpoint wiring；结论最多为工程
  `SUPPORTED`，训练/attention utility/Cmv2 accuracy 均为 `INCONCLUSIVE`。
- 多 GPU capacity run 必须生成独立 `outputs/CmResidual/<run_id>/`、run manifest、每 rank buffer manifest、
  `metrics.jsonl`、train log、checkpoint validation；不把 capacity probe 作为科研效果结论。
- 回滚只删除 V1.16 新 adapter/Task/model/config/runner/test/docs；历史 V1.14/V1.15 code、checkpoint、reference、
  outputs 和用户已有未提交路径均保留。若 reference link pose 不能与 `QUERY_LINKS` 一一对齐、GPU sweep 与
  nominal base 定义不一致、或 DDP/rank output 无法验证，则停止在对应 gate，不启动正式训练。
