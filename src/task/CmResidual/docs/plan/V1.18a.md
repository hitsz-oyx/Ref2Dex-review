## 范围

只测当前 V1.19 streaming planner 的延迟，不改网络、权重或 teacher 数学。用 Phase-A checkpoint、seed 42
在 GPU6 捕获 Phase-B 首个 planner-active pre-action state；固定同一组候选，测试 `K={1,2,4,8}`。

用 CUDA Event 记录 candidate、FK、hand surface、`swept_topk`、edge/contact、token/head、scoring 与
end-to-end；20 次 warm-up、100 次测量，报告 mean/median/p90、峰值显存、分项占比和输入 SHA。诊断入口
默认关闭，必须验证开关前后 K=8 输出 parity。

## 保护、验证与回滚

保持 observation/action/reward、Cmv2 checkpoint/schema、K=8 正式 planner、microbatch/chunk、坐标单位、
PhysX 和旧 outputs 不变。风险是 profiler 扰动 kernel 调度及单 state 代表性有限；结论只用于定位该状态的
延迟热点。执行定向测试、语法检查、`python3 tools/verify.py --changed`、`git diff --check` 和 GPU6 dry-run。

产物写入独立 profiling run；失败不进入网络优化。回滚只 revert V1.18a profiler/runner/test/docs 提交，
不删除输入、checkpoint 或历史运行。
