## 目标

在不改变 Cmv2 checkpoint/state_dict、几何/坐标/单位、K=8 candidate、feasible residual mapping、activation/cost/softmax teacher 定义、PPO executed action、reward、reference、buffer schema 或训练数据的前提下，消除 V1.18 retry4 的两项纯实现资源问题：

1. Cmv2 `LocalInteractionEncoder` 对 KNN 结果的 edge MLP 按 object-query chunk（固定 `32`）执行，避免为 `[B_c,1024,32,128]` 一次性保留约 2 GiB edge activation；
2. planner 保留所有 active env，按固定 `16 env × K=8` microbatch 依次完成 frozen inference，不再以 `maxActiveEnvs` 轮转截断 teacher coverage；
3. `lambda_cm=0` 的 Stage A 不构造 Cmv2 teacher，写入零权重与 detached actor mean，成为真正无 Cm 的 reference-PPO baseline。

本版本只解决峰值显存/调度与 Stage-A bypass；不缓存 object encoding、不改变 precision、不降低 K、不改候选分布或尝试长训。

## 实现范围

1. `src/task/ObjectInteractionCmv2/model.py`
   - 为 `LocalInteractionEncoder` 增加可选的 object-query chunk 参数；先保持现有 `swept_topk` 的 index/distance 选择和 object 顺序，再逐 chunk 构造 edge、attention 与 contact，最后按原顺序拼接。
   - 为 V1.3 forward 提供可选转发入口；默认调用保持原未分块行为和 state_dict 不变，避免影响既有 Cmv2 训练/评估调用。
2. `src/task/CmResidual/cm_v2_adapter.py`
   - 为冻结 V1.3 adapter 新增 planner 专用 `predict_effect_only(...)`，只将 `delta_xi_root`、`token_mask`、`token_mass` 交还调用方；支持显式传递 V1.19 object chunk，仍在 `inference_mode`、`eval`、无参数梯度下运行。
   - 既有 `predict`/`__call__` 输出与调用方式保持兼容。
3. `src/task/CmResidual/v118_planner.py`
   - 将 `max_active_envs` 替换为 `planner_env_microbatch` 与 `interaction_object_chunk`，固定默认 `16/32`；对完整 active ID 序列按原顺序分组，并对每组独立执行与原来相同的 FK、Cmv2、valid、cost 与 teacher 更新。
   - 大型 Cmv2 输出只在每个 microbatch 生命周期内存在；全局只保留原有 fallback/teacher 小张量。无 active 或无有效 candidate 的 fallback 不变。
4. `third_party/IsaacGymEnvs/isaacgymenvs/tasks/cm_residual/task.py` 和 `third_party/IsaacGymEnvs/isaacgymenvs/cfg/task/CmResidualGrabReferenceV118.yaml`
   - 仅为 V1.18 opt-in task 传入 `plannerEnvMicrobatch: 16`、`interactionObjectChunk: 32`；移除 `maxActiveEnvs` 截断配置，不改 V1.16 或其他 task。
5. `third_party/IsaacGymEnvs/isaacgymenvs/learning/v118_agent.py`
   - `cm_distill_coef == 0` 时不调用 task planner，写入 detached `mu` 和全零 weight；大于零时沿用 rollout-time frozen teacher，mini-epoch 不重算 target。
6. `src/task/CmResidual/tests/`
   - 新增/扩展 CPU 可重复单元测试：Cmv2 chunk 与 unchunked 的关键输出近似相等、adapter effect-only 输出合同、all-active microbatch 覆盖/顺序、无效 fallback、Stage-A 没有调用 planner 且写入正确 target/weight、V1.18 config 只含新 memory contract。

## 不变量与风险控制

- Cmv2 state_dict、checkpoint SHA、model config（width=128、KNN=32、FP32）不变；不新增或转换 checkpoint。
- object query 的分块只改变执行次序。允许 FP32 kernel 的极小数值舍入差异；单元测试对数值输出使用明确的浮点容差，而非宣称 bitwise identity。
- active env 按 `active_ids` 升序连续分组；每个 active env 每次 planner 调用恰好得到一次 K=8 candidate 评估。inactive 与无有效 candidate 仍为 `teacher_weight=0`。
- Stage A 的 loss 已由 `lambda_cm=0` 乘零；本次进一步保证 rollout 也无 planner/Cmv2 调用。actor action sampling、buffer fields、PPO loss 与 checkpoint schema保持不变。
- 不修改正在运行的 V1.17 DexPlore 进程、外部 DExplore checkout、`graspenv`/`dexplore_v117` 依赖、V1.16 DDP、用户已有工作区改动或任何 `outputs/`。
