它固定采样 4096 个 canonical surface points，并保存稳定 correspondence；对于 laptop、scissors、box 等 articulated object，根据：

# 不过我现在发现 4 个正式训练前值得修的问题

## 1. `persistent_workers=True` 下 epoch sampling 可能实际上没有更新

这是我认为当前最值得先修的代码问题。

`_MmapSequenceDataset` 现在写的是：

```python
self.epoch = 0

def set_epoch(self, epoch):
    self.epoch = int(epoch)
```

而正式 config：

```yaml
num_workers: 4
persistent_workers: true
```

问题在于 DataLoader persistent worker 中的 Dataset 是独立进程副本。

主进程：

```python
dataset.set_epoch(epoch)
```

修改的只是主进程对象，**不一定传到已经常驻的 worker 副本**。

旧 `Stage4CmDataset` 之前专门用：

```python
mp.Value(...)
```

就是为了处理这个问题。

而 V1.2 又回到了普通整数。

结果可能变成：

```text
worker 永远 epoch=0
       ↓
同一个 sample
每个 epoch 使用相同 stride
相同 sampling bank
```

这会让我们本来设计的 epoch-level sampling augmentation 失效。

### 建议

直接恢复：

```python
self._epoch = mp.Value("q", 0, lock=True)
```

和旧 dataset 一样。

这个应该在正式训练前修。

# 2. mmap cache 目前没有 LRU，上千 sequence 会一直积累打开

现在 `_MmapSequenceDataset`：

```python
self._cache = {}
```

然后：

```python
if key not in self._cache:
    self._cache[key] = {
        "obj": np.load(..., mmap_mode="r"),
        ...
    }
```

也就是说一个 worker 随着 shuffle 遍历数据，会不断打开：

```text
GRAB sequences
+
ARCTIC sequences
×
left/right
×
多个 .npy
```

但没有 eviction。

现在是：

[
1636\ sequence
]

理论上每 worker 最后可能持有几千个 mmap/file handle。

Scene V1.1 当时反而做得更好，有：

```text
_OPEN_SEQUENCE_LIMIT = 8
OrderedDict LRU
```

### 建议

Object V2 也恢复这个结构：

```python
_OPEN_SEQUENCE_LIMIT = 8~16
OrderedDict
```

只缓存最近访问 sequence/side。

OS page cache 负责真正的文件页复用。

这个同样应该正式训练前修。

# 4. Full-data 有了，但正式 train-only calibration / split 还没有完全收口

当前 E1 的 662,557 samples 和 RMS 是**全数据诊断统计**。

实验记录自己也明确写了：

> 当前统计不是严格 train-only calibration。下一步是固定 split、train-only calibration。

当前 loader 确实已经做到：

```text
GRAB 内部 sequence split
ARCTIC 内部 sequence split
然后组合
```

不会 frame leakage。

但是目前 split 是：

```python
rng.shuffle(sequence)
10% val
10% test
```

而不是保存下来的正式 split JSON，也不是 ARCTIC 官方 split。

所以我建议现在直接生成固定：

```text
splits/object_v2_seed42/
├── grab_train.txt
├── grab_val.txt
├── grab_test.txt
├── arctic_train.txt
├── arctic_val.txt
└── arctic_test.txt
```

一旦生成，就不要以后随着 cache 内容变化重新 shuffle。

然后**只在 train split**上统计：

[
RMS_{\text{train}}
]

写入 config：

```yaml
flow_target_rms_m: ...
object_flow_target_scale: 1 / RMS_train
require_flow_calibration: true
```

当前 V1.2 config 还是：

```yaml
require_flow_calibration: false
```

所以它目前还是 smoke/研究配置，不应该直接当正式长训 config。
