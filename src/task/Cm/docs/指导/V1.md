可以。基于我们刚才已经确定的约束，我建议直接做一版 **Cm Scene Cache V1**，一次把数据语义和三级 cache 都改完，但**不改 Cm 主干、不改 loss、不改变 512 点输入规模**。

核心目标：

[
\boxed{
(P_t,H_t,\Delta H_t,\Delta t)
\rightarrow C_m
\rightarrow \hat{\Delta P}_t
}
]

这里 (P_t) 不再特指 manipulated object，而是：

[
\boxed{
P_t=\text{当前手附近的 local scene points}
}
]

GRAB 当前可用环境资产主要是 table，但代码层统一叫 `environment`，绝不写死 table。

# 1. 最终数据语义

以前：

```text
4096 object points
        ↓
hand 5cm candidate
        ↓
random 512
        ↓
Cm
```

新版：

```text
4096 manipulated-object points
            +
N_env environment points
            ↓
       scene point pool
            ↓
距离当前手 <= 5cm
            ↓
      candidate indices
            ↓
sampling bank 中取 512
            ↓
           Cm
```

模型不知道：

```text
这个点是 object
这个点是 table
```

所有点：

[
\boxed{\text{完全一视同仁}}
]

进入模型。

GT flow 也统一：

[
F_i^{GT}
========

## P_{t+s,i}^{hand_t}

P_{t,i}^{hand_t}.
]

所以 manipulated object 点自然有运动，固定环境点自然：

[
F_i^{GT}=0.
]

**不增加任何额外 static/environment loss。**

# 7. 点必须有稳定 correspondence

这一点非常重要。

Object 现在本来就是固定 canonical surface sample，通过每帧 rigid pose 得到：

[
O_t.
]

Environment 也必须一样：

```text
canonical env point #37
 ↓
frame t pose
 ↓
E_t[37]

同一个 canonical point #37
 ↓
frame t+s pose
 ↓
E_{t+s}[37]
```

这样 scene pool index 才稳定：

```text
0 ... 4095
    object

4096 ... 8191
    environment
```

于是一个 `selected_idx` 同时可以访问：

```python
scene_current[selected_idx]
scene_future[selected_idx]
```

从而得到正确 flow。

---

# 8. Environment 固定时不要重复存 T 份

如果 GRAB table 的 world pose 对整个 sequence 恒定，则不应该存：

```text
[T,4096,3]
```

而存：

```text
env_points_world.npy
[4096,3]

env_normals_world.npy
[4096,3]
```

Dataset 自动 broadcast。

为了兼容未来动态 environment，也可以 metadata 写：

```json
{
  "environment_storage": "static_world"
}
```

另外支持：

```text
static_local + pose
dynamic_world
```

但 GRAB 第一版优先 `static_world`。

# 9. Candidate cache 改成 ragged index

现在 Stage4 保存：

```python
obj_candidate_mask_5cm
[T,4096]
```

新版不再保存 bool mask。

直接计算：

[
\mathcal C_t
============

\left{
i:
d(P_{t,i},H_t)\le0.05
\right}.
]

存：

```text
candidate_offsets.npy
[T+1]

candidate_indices.npy
[sum(candidate_count)]
```

例如：

```text
frame 0:
[3, 9, 100, 4150]

frame 1:
[5, 8, 12]
```

变成：

```python
offsets = [0, 4, 7]

indices = [
    3, 9, 100, 4150,
    5, 8, 12
]
```

取 frame：

```python
s = offsets[t]
e = offsets[t + 1]

candidate = indices[s:e]
```

比：

```text
8192 bool
→ nonzero
→ sampling
```

更直接。

# 10. Candidate 计算保持“当前手 5 cm”逻辑

这一点不变：

[
d(scene\ point, hand)<5\text{ cm}.
]

不做：

```text
× environment 强制配额
× object 强制配额
× object/env balance
```

因此某一帧如果：

```text
hand 离 table > 5cm
```

那么最终 512 点可能全部来自 object。

没问题。

这完全遵循现有 Cm candidate 逻辑。

# 11. Sampling Bank

这是第二层 cache。

当前训练：

```python
object_seed = stable_frame_seed(
    ...,
    epoch=self.epoch
)
```

所以每 epoch 会重新抽 512 点。

新版提前给每个：

[
(sequence,side,current)
]

生成：

[
B=4
]

套 512-point sampling。

存：

```text
sampling_bank/left_indices.npy
[T,4,512]

sampling_bank/right_indices.npy
[T,4,512]
```

类型：

```python
uint16
```

因为：

[
8192<65535.
]

每个 frame 仅：

[
4\times512\times2
=================

4096\text{ bytes}.
]

很小。

---

# 12. Bank 选择仍然随 epoch 改变

训练时：

[
b=
hash(
sequence,
side,
frame,
epoch
)\bmod4.
]

例如：

```text
epoch 0 → bank 3
epoch 1 → bank 0
epoch 2 → bank 2
epoch 3 → bank 1
```

因此不是固定 512 点。

保留一定 sampling augmentation（采样增强），只是随机空间变成提前生成的 4 套。

Validation/Test 固定 bank，例如：

```text
bank = 0
```

保证完全 deterministic。

---

# 13. Stride 不要 cache 死

当前 Cm 的时间跨度是运行时：

[
s\in[1,10].
]

这个继续保留。

Sampling bank 只决定：

```text
current frame 的 512 个点
```

未来端：

```python
future = current + stride
```

依然在线选择。

所以：

```text
same current + bank
     │
     ├── stride 1
     ├── stride 4
     ├── stride 7
     └── stride 10
```

都可以用。

---

# 14. DenseToken Bank

这是最大的训练加速项。

现在每个 batch Frozen DenseToken 都会重新执行：

[
(512\ scene+1538\ hand)
\rightarrow PTv3.
]

虽然 no-grad、冻结，但计算依然真实发生。

新版对：

[
(sequence,side,current,bank)
]

提前计算：

```text
z_scene
z_hand
dense_hand_contact
```

---

# 15. Dense cache 必须同时 cache z_hand

不要认为：

> hand 没变，所以 z_hand 一帧只需要存一次。

不对。

Frozen DenseToken 是联合输入：

```python
points = torch.cat([
    obj_points,
    hand_points
], dim=1)
```

PTv3 中 hand token 可能受到 scene 点选择变化影响。

所以：

```text
bank 0:
512 scene A + same hand
       ↓
z_hand_A

bank 1:
512 scene B + same hand
       ↓
z_hand_B
```

应该分别缓存。

因此 cache key 是：

[
\boxed{
sequence+side+current+bank
}
]

而不是只对 scene token 分 bank。

---

# 16. Dense bank 不需要 stride

Frozen DenseToken 完全不知道：

```text
hand_flow
future
stride
delta_time
```

当前代码明确只输入当前：

[
(O_t,H_t).
]

因此：

[
z_{scene},z_{hand},contact
]

只与：

```text
current
sampling bank
```

相关。

不需要：

```text
stride × bank
```

这会节约很多 cache。

---

# 17. Dense Bank 存 FP16

比如：

```text
z_scene.npy
[T,B,512,D] float16

z_hand.npy
[T,B,1538,D] float16

hand_contact.npy
[T,B,1538] float16
```

Dataset 读取后：

```python
torch.from_numpy(...).float()
```

或 AMP 下直接保留 fp16。

由于 DenseToken 已冻结，这种 feature cache 使用 FP16 一般是合理的，但必须做 parity test，不能直接假设误差可忽略。

`CmFlowModel.forward()` 改成：

```python
if "cached_z_obj" in batch:
```

后面：

```text

```

全部不动。

因此可以随时：

```yaml

  use_dense_cache: true
```

关闭以后恢复在线 Frozen PTv3，用于验证 cache parity。

```text
        ↓
```

```text
        ↓
C_m
        ↓

        ↓

```

大的 Frozen PTv3 已完全移出 training loop。

当前 Cm 模型结构不变，因此：

```text

        ↓
load trainable weights
        ↓
新的 Scene dataset
        ↓
新的 calibration
        ↓
```

我建议：

```text

```

初始：


# 26. 必须做的 parity tests

这次 cache 改动很多，所以我建议先把验证写死。

### Test A：object-only regression

关闭 environment：

```text
scene = old object pool
```

新版 Dataset 与旧 Dataset 相同 seed/frame/stride 时：

```text
selected points
GT flow
hand flow
```

必须一致。

---

### Test B：ragged candidate parity

旧：

```python
np.nonzero(mask)[0]
```

新：

```python
candidate_indices[
    offsets[t]:offsets[t+1]
]
```

必须逐元素完全一致。

---

### Test C：Sampling Bank

同一：

```text
sequence
side
frame
bank
```

多次加载：

```text
selected_idx
```

100% 一致。

不同 bank 应有足够 overlap diversity。

---

### Test D：DenseToken FP32 online vs cache FP16

同一样本：

```text
online PTv3
vs
cached feature
```

比较：

[
|z^{online}-z^{cached}|.
]

还要比较最终：

[
EPE_{online}
\quad vs\quad
EPE_{cached}.
]

要求差异极小，例如：

```text
mean EPE difference < 0.01 mm
```

阈值最终根据实测定。

---

### Test E：Loss parity

environment disabled + FP32 dense cache：

[
L_{old}\approx L_{new}
]

要求 numerical parity（数值一致性）到浮点误差范围。

```text
                         Cm Slot Attention
                              │
                              ▼
                             C_m
                              │
                              ▼
                       Scene Flow Decoder
                              │
                              ▼
                          ΔP_pred
                              │
                              ▼
                     原来的 SmoothL1
```

这一版的原则非常明确：

[
\boxed{
\text{数据语义升级，cache 全面升级，但 Cm 和 loss 尽可能不动}
}
]

这样后面如果性能变化明显，我们可以把原因主要归因到 **“object-only → local scene”**，而不是同时掺入新的模型结构或新的监督目标。
