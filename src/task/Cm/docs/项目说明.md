# Cm 任务说明

## 任务目标

Cm 从当前 hand-object 状态和未来 hand action chunk 学习交互原因表征 `C_m`，并预测未来点流。模型仍接收 512 个点和 1538 个 hand 点；Scene Cache V1 将前者的语义从 manipulated object 扩展为当前手附近的 local scene points（object + environment），不增加额外 environment loss。

## 主要入口

- 旧 NPZ 数据集：`src/task/Cm/dataset.py`
- Scene Cache V1 数据集：`src/task/Cm/dataset_scene.py`
- Scene cache 构建：`process/GRAB/stage4_cm_scene.py`
- Sampling bank：`src/task/Cm/build_sampling_bank.py`
- DenseToken bank：`src/task/Cm/build_dense_cache.py`
- flow 校准：`src/task/Cm/compute_flow_scale.py`
- 模型与训练：`src/task/Cm/model.py`、`src/task/Cm/runner.py`、`src/task/Cm/train.py`
- V1 指导：[`指导/V1.md`](指导/V1.md)

## V1 数据链

```text
raw GRAB -> scene mmap -> ragged 5cm candidates -> sampling bank -> dense bank -> Cm
```

Scene pool 的 index 顺序是 object 后接 environment。environment 在 GRAB backend 中通过通用 asset 接口读取；Cm 模型不读取 `scene_source_id`，该字段只用于 object/environment 分开统计。Scene cache、sampling bank 和 dense bank 都有 schema/fingerprint 校验，失配时直接报错。

## 运行方式

```bash
python3 -m process.GRAB.stage4_cm_scene --grab-root dataset/GRAB --output-root data/processed_data/cm_scene_v1 --num-obj-points 4096 --num-env-points 4096 --candidate-threshold 0.05 --ds-rate 4 --device cuda:0
python3 -m src.task.Cm.build_sampling_bank --root data/processed_data/cm_scene_v1 --bank-size 4 --num-points 512 --seed 42
python3 -m src.task.Cm.compute_flow_scale --train-path data/processed_data/cm_scene_v1 --min-stride 1 --max-stride 10 --num-obj-points 512
python3 -m src.task.Cm.build_dense_cache --root data/processed_data/cm_scene_v1 --dense-checkpoint src/task/Cm/densetoken_ckpt/best.pt --bank-size 4 --batch-size 64 --dtype float16 --device cuda:0
python3 -m src.task.Cm.train --config src/task/Cm/configs/sequence_full_grab_scene_v1_16slot.yaml
```

正式训练前应将 flow calibration 写入 train root 的 `metadata.json`，并把配置中的 target scale 与校准值同步。当前工作区未发现 GRAB 原始 `.npz`，因此本次只完成合成 cache parity 实验，未运行真实数据建 cache 或训练。
