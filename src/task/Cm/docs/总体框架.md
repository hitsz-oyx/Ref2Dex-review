# CmAction 总体框架

CmAction 学习的是 hand-side 的动作原因表征 `C_m`：手的哪些局部区域以何种运动
作用于当前物体。它不是从未来物体状态编码答案，也不是 object-side effect token。

```text
(O_t, H_t) ── frozen DenseToken ──> (Z_obj,t, Z_hand,t, contact_hand,t)
(Z_hand,t, H_t, normals_t, ΔH_t, contact_hand,t)
    ── hard-gated Slot Attention ──> C_m
(Z_obj,t, O_t, normals_obj,t, C_m) ──> F̂_obj,t
```

所有未来信息只以 `hand_flow` 进入 action branch；`O_{t+s}` 只生成训练目标
`obj_flow_gt`。这避免将未来物体几何泄漏给 Cm。

`C_m` 由 16 个 Slot Attention token 构成。每个 slot 有软手表面 anchor 与法向，
并通过 Hard-Concrete probability + hard threshold 控制是否参与 decoder。若所有 slot
均低于阈值，模型强制保留得分最高的一个 slot，因此不会出现 null-expert 分支。

三个 scale 分工明确：geometry 坐标输入 scale、hand-flow 输入 scale 和 object-flow
target scale。模型对外始终返回米制 flow；Runner 只在 vector Huber loss 内恢复
target scale。使用 train-only metadata 校准，训练启动会检查该统计分布和 config 一致。

评价以 held-out sequence 的点加权 EPE（毫米）为主，最佳 checkpoint 使用
`val/mean_stride_epe_mm`。`C_p` 属于后续阶段：应将当前 `C_m` 通过 correspondence
运输到 object side 后再压缩，而不是独立从未来 object state 产生。
