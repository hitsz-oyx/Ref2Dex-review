## 结论

**(C_m) 继续以 hand 为中心没有问题。**但这里的“hand-centered”应理解为：

> token 锚定在手部作用点或手部 link 上，而不是 token 只包含手自身的信息。

推荐关系是：

[
\boxed{
C_m^{human}
;\xrightarrow[\text{correspondence/interaction transport}]{S_t};
C_p
;\xrightarrow[\text{robot embodiment}]{}
C_m^{robot}
}
]

其中：

* (C_m)：**手侧动作原因**，描述手的哪些区域如何运动、如何作用于物体；
* (C_p)：**物体侧作用结果**，描述物体哪些区域应当产生什么运动；
* 二者不是互相竞争的两个 bottleneck，也不应该被强行训练成相同特征。

真正容易产生干扰的情况是：你让 (C_m) 和 (C_p) 都从同一批 dense token 独立生成，并且都用同一个 scene-flow reconstruction loss。这样两个分支会学成冗余的 object-flow encoder。

---

# 1. 你当前的 dense token 还不是动作 token

你当前实现是单帧：

[
[O_t,H_t]
\xrightarrow{\mathrm{PTv3}}
[Z_t^o,Z_t^h]
]

然后：

[
P_{ij}
======

g_{\mathrm{edge}}(Z_{t,i}^o,Z_{t,j}^h)
]

当前 dense token 的主要训练目标是：

* object-hand correspondence；
* dense hand contact heatmap；
* 从扰动物体位姿恢复 clean contact。

而且 object 和 hand 在同一个 PTv3 中联合编码，所以 (Z_t^o) 和 (Z_t^h) 都是带有交互上下文的单帧静态 token，并不是纯 object token 或纯 hand token。

因此你的架构可以理解为：

[
Z_t^{dense}
===========

\text{当前时刻的交互几何状态}
]

在这个基础上，再增加 temporal action encoder，才能得到真正的 (C_m)。

---

# 2. 两帧生成 (C_m) 是合理的

完整的 (C_m) 将来可以定义为：

[
C_m
===

\left{
m_k,,
\Delta m_k,,
f_k^m,,
a_k
\right}_{k=1}^{K_m}
]

其中：

* (m_k)：手侧作用位置；
* (\Delta m_k)：该作用区域从 (t) 到 (t+1) 的运动；
* (f_k^m)：局部手型、法向、link、接触上下文以及运动特征；
* (a_k)：当前作用是否活跃。

它的核心含义是：

[
C_m
===

\text{“手的哪些部位，以什么局部运动，对当前物体施加作用”}
]

训练目标为：

[
\hat F_{i,t}^{o}
================

D_m(x_{i,t},Z_{i,t}^o,C_{m,t})
]

[
L_{\mathrm{scene}}^m
====================

\sum_iw_i
\left|
\hat F_{i,t}^{o}
----------------

F_{i,t}^{o}
\right|
]

这会迫使 (C_m) 编码 action，而不是只编码当前接触位置。

### 当前实现：完整手部动作场的 Slot Attention

当前 CmAction 保留手侧局部几何与接触先验，并采用：

[
u_j^h
=====
\phi[z_j^h,y_j,n_j,\Delta y_j,c_j,\operatorname{vec}(\Delta T_w)]
]

[
C_m=\operatorname{SlotAttention}({u_j^h}_{j=1}^{1538})
]

其中 (z_j^h) 是冻结 PTv3 的当前交互状态，(y_j,n_j) 是当前手表面局部
几何，(\Delta y_j) 是同一 (hand-root_t) 坐标系中的 `hand_flow`，(c_j)
是冻结 dense hand-contact 概率，(\Delta T_w) 是 wrist SE(3)。Slot
attention weights 在训练后投影为 soft hand region，而不是先做 top-K hard
anchor；该 soft region 同时提供 slot 的位置、平均运动和平均法向给几何
object-flow decoder。

# 3. 但是不能直接拼接当前架构输出的两帧 dense token

这是你目前设计里最需要注意的问题。

假设直接做：

[
C_m
===

Q_m(
Z_t^h,
Z_{t+1}^h
)
]

看起来只是使用了 hand token，但在你当前架构里，(Z_{t+1}^h) 并不是纯手信息。

因为：

1. PTv3 在 (t+1) 时刻联合编码 (O_{t+1}) 和 (H_{t+1})；
2. hand point 的 11D 输入特征包含到 object point 的最近距离、方向和物体中心方向；
3. PTv3 内部 object 与 hand token 直接相互注意。

因此：

[
Z_{t+1}^h
=========

f(H_{t+1},O_{t+1})
]

如果目标是预测：

[
F_t^o=O_{t+1}-O_t
]

那么 (Z_{t+1}^h) 已经间接包含 (O_{t+1})。模型可能绕过“理解手部动作”，直接从未来物体几何读出 object flow。

这属于明显的 target leakage。

## 推荐输入方式

应该使用：

[
\boxed{
O_t,\ H_t,\ \Delta H_t,\ \Delta T_{wrist}
}
]

而不是：

[
O_t,\ H_t,\ O_{t+1},\ \Delta H_t
]

具体可以拆成：

[
(Z_t^o,Z_t^h)=E_{\mathrm{interaction}}(O_t,H_t)
]

[
U_t^h
=====

\phi(Z_t^h,\Delta H_t,\Delta T_{wrist})
]

[
C_{m,t}
=======

\operatorname{SlotAttention}(U_t^h)
]

其中：

* 当前帧使用原来的 unified PTv3，提供 frozen interaction state；
* 下一帧只通过 `hand_flow` 和 wrist SE(3) 进入 Cm；
* 不允许未来物体几何进入 (C_m) encoder；
* 当前 (Z_t^o) 只在 Slot Attention **之后**作为 decoder query；
* (O_{t+1}) 只作为 object-flow GT。

也可以构造一个统一输入：

[
[O_t,H_t,H_{t+1}]
]

加上类型 embedding：

* current object；
* current hand；
* future hand。

但不要放入 future object。

# 4. “以 hand 为中心”分为两件事

需要区分：

## 4.1 Token anchor 以 hand 为中心

这个是合理的：

[
m_k\in\text{hand surface}
]

当前每个 token 对应一个由 Slot Attention 软分配得到的手表面区域；
它可在训练后投影为 fingertip、finger pad、palm 或跨区域 group，而不
预先把它限制为一个离散 MANO face。

这让 (C_m) 可以直接用于生成机器人动作。

## 4.2 坐标系以 hand root 为中心

这个需要额外处理。

你当前 Stage 3 每帧都执行：

[
x_t^{h_t}
=========

R_{h,t}^{T}
(x_t^w-t_{h,t})
]

对于静态 correspondence 没问题，但如果直接计算：

[
F_t=x_{t+1}^{h_{t+1}}-x_t^{h_t}
]

两项处在不同坐标系中，严格来说不是合法的流。

而且每帧分别使用自己的 hand root 会消除 wrist 的全局运动。这样 (H_t) 到 (H_{t+1}) 主要剩下手指关节形变，而 wrist 的平移和旋转被规范化掉了。

## 正确做法

将 (t) 和 (t+1) 都变换到同一个 (t) 时刻 hand-root frame：

[
\bar x_{t+1}
============

R_{h,t}^{T}
(x_{t+1}^{w}-t_{h,t})
]

[
\bar y_{t+1}
============

R_{h,t}^{T}
(y_{t+1}^{w}-t_{h,t})
]

然后：

[
F_{i,t}^{o}
===========

\bar x_{i,t+1}-x_{i,t}^{h_t}
]

[
F_{j,t}^{h}
===========

\bar y_{j,t+1}-y_{j,t}^{h_t}
]

这样：

* wrist 运动被保留；
* finger articulation 被保留；
* object flow 和 hand flow 在同一个坐标系；
* (C_m) 可以表达完整动作。

另一种方案是继续使用每帧 hand-root frame，但单独输入：

[
\Delta T_{wrist,t}
==================

T_{h,t}^{-1}T_{h,t+1}
]

此时 (C_m) 必须显式包含：

* wrist SE(3)；
* finger local motion；
* contact activity。

# 5. (C_m) 和 (C_p) 的具体关系

我更建议把它们设计成**因果传输关系**，而不是两个平行 latent。

## (C_m)：hand-side action

对每个手侧 active region：

[
c_j^m
=====

\left(
y_{j,t},
\Delta y_{j,t},
n_{j,t},
\text{link}_j,
a_j,
f_j
\right)
]

描述：

> 手点 (j) 从哪里出发、往哪里运动、是否接触、属于哪个执行器。

## (C_p)：object-side effect

对每个物体作用区域：

[
c_i^p
=====

\left(
x_{i,t},
\hat F_{i,t}^o,
n_{i,t},
\gamma_i,
g_i
\right)
]

描述：

> 物体点 (i) 因为手的动作，应当产生什么局部运动。

二者通过当前 correspondence 关联：

[
e_i
===

\sum_j
P_{ji,t},
a_j,
\phi
\left(
c_j^m,
x_{i,t}-y_{j,t},
n_i,
n_j
\right)
]

然后从物体侧 dense effect token 压缩：

[
C_p
===

Q_p
\left(
\left{
Z_{i,t}^o,e_i,\hat F_{i,t}^o
\right}_{i=1}^{N_o}
\right)
]

即：

[
\boxed{
C_p=\operatorname{ObjectProjection}(C_m,P_t,S_t)
}
]

而不是：

[
C_m=Q_m(Z^{dense}),
\qquad
C_p=Q_p(Z^{dense})
]

让二者各学各的。

---

# 6. 为什么这样不会干扰

按照上面的关系：

[
C_m
\rightarrow
\hat F^o
\rightarrow
C_p
]

它们的职责不同：

| 表示    | 锚点                  | 表达内容       | 是否依赖手型 |
| ----- | ------------------- | ---------- | ------ |
| (C_m) | hand surface/link   | 手如何运动和作用   | 强依赖    |
| (C_p) | object surface/part | 物体哪里产生什么效果 | 尽量不依赖  |
| (F^o) | dense object points | 最终物体运动     | 不依赖手型  |

因此同一个 (C_p) 可以对应多个 (C_m)：

[
C_p
\leftarrow
C_m^{human}
]

[
C_p
\rightarrow
C_m^{robot}
]

例如推同一个盒子：

* 人可以用食指推；
* Allegro Hand 可以用两指推；
* Shadow Hand 可以用掌面或指尖推。

三者 (C_m) 不同，但目标 (C_p) 可以近似相同。

---

# 7. 什么情况下确实会互相干扰

下面这种训练方式容易产生干扰：

[
C_m=Q_m(Z_t^o,Z_t^h,Z_{t+1}^o,Z_{t+1}^h)
]

[
C_p=Q_p(Z_t^o,Z_t^h,Z_{t+1}^o,Z_{t+1}^h)
]

并且：

[
D_m(C_m)\rightarrow F_t^o
]

[
D_p(C_p)\rightarrow F_t^o
]

如果没有其他结构约束，两个 bottleneck 很可能都编码：

* (O_{t+1})；
* 整体 object transform；
* object flow 的压缩版本。

结果是：

* (C_m) 不再 hand-centered；
* (C_p) 不再 object-effect-specific；
* 两者语义不可辨认；
* downstream robot action generator 不知道应该使用哪一个。

尤其是未来 (O_{t+1}) 进入 unified PTv3 后，这种退化非常容易发生。

# 8. 推荐的训练顺序

## 阶段一：保留当前 correspondence 网络

继续训练：

[
E_{\mathrm{interaction}}
:
(O_t,H_t)\rightarrow(Z_t^o,Z_t^h,P_t)
]

这个网络解决：

* noisy geometry correction；
* dense correspondence；
* 当前接触上下文。

不需要立即修改现有主任务。

## 阶段二：训练 hand-centered (C_m)

输入：

[
Z_t^o,Z_t^h,H_{t+1},F_t^h,\Delta T_{wrist}
]

输出：

[
C_m
]

监督：

[
D_m(S_t,C_m)\rightarrow F_t^o
]

这一阶段可以：

* 先冻结现有 PTv3；
* 或使用明显更小的 backbone learning rate；
* 主要训练 temporal encoder、(C_m) bottleneck 和 scene-flow decoder。

## 阶段三：从 (C_m) 蒸馏 (C_p)

构造：

[
C_p
===

Q_p
\left(
S_t,
P_t,
\operatorname{stopgrad}(C_m)
\right)
]

监督：

[
D_p(S_t,C_p)\rightarrow F_t^o
]

以及：

[
L_{\mathrm{effect-cons}}
========================

\left|
D_p(S_t,C_p)
------------

\operatorname{stopgrad}
D_m(S_t,C_m)
\right|
]

先对 (C_m) stop-gradient，避免 (C_p) 的训练反过来改变已经形成的 hand-action 语义。

## 阶段四：小权重联合微调

联合训练时：

[
L=
L_{\mathrm{corr}}
+
\lambda_mL_{\mathrm{scene}}^m
+
\lambda_pL_{\mathrm{scene}}^p
+
\lambda_cL_{\mathrm{effect-cons}}
]

其中：

[
\lambda_c
]

初期应较小，不要直接用强对比学习把 (C_m) 和 (C_p) 特征拉成一致。

需要对齐的是：

[
D_m(C_m)\approx D_p(C_p)
]

即二者产生的**物体效果一致**，不是 token embedding 本身一致。

---

# 9. 对你当前架构的最小修改版本

可以先不引入完整 (C_p)，只完成以下结构：

[
(O_t,H_t)
\xrightarrow{E_{\mathrm{PTv3}}}
(Z_t^o,Z_t^h)
]

[
U_t^h=\phi(Z_t^h,\Delta H_t,\Delta T_{wrist})
]

[
C_m=\operatorname{SlotAttention}(U_t^h)
]

[
\hat F_t^o
==========

D_m(Z_t^o,C_m)
]

第一阶段先验证：

1. 打乱 (\Delta H_t) 或 (\Delta T_{wrist}) 后，object-flow 性能是否显著下降；
2. 去掉 object context 后，性能是否下降；
3. (C_m) 的 Slot Attention 区域是否落在真正运动或施力的手部区域；
4. 对相同手姿但不同运动方向，(C_m) 是否不同；
5. 对相同运动但不同物体，(C_m) 是否能够通过 scene context 调整效果。

这些验证通过后，再定义：

[
C_p
===

Q_p
\left(
Z_t^o,
P_t,
C_m,
\hat F_t^o
\right)
]

这样风险最低。

## 最终定义

你的 (C_m) 可以而且应该是 hand-centered：

[
\boxed{
C_m
===

\text{hand-anchored、scene-conditioned、temporal action tokens}
}
]

但需要满足三个条件：

1. (C_m) 使用 (H_t,H_{t+1})，不能看到 (O_{t+1})；
2. 两帧数据必须处于同一个 (t)-hand-root 坐标系，或者显式提供 wrist SE(3)；
3. (C_p) 应从 (C_m) 在物体表面的作用投影得到，而不是与 (C_m) 平行竞争同一个 scene-flow loss。

所以不会因为 (C_m) 以 hand 为中心而干扰 (C_p)。真正会干扰的是**二者没有明确的方向关系和信息边界**。
