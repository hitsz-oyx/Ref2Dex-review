

## 现在仍建议处理的三点

### 1. 强制 Sequence Cache 使用 `ds_rate=1`

你要的 1–12 是**原始 GRAB 帧跨度**，所以生成缓存时必须明确：

```bash
--ds-rate 1
```

当前预处理脚本虽然默认是 1，但仍允许用户传入其他值。若误用 `--ds-rate 4`，Dataset 的 `stride=12` 实际对应原始 GRAB 的 48 帧，而代码不会报错。脚本当前只检查 `ds_rate > 0`。

建议对 Cm sequence cache 直接限制：

```python
if args.ds_rate != 1:
    raise SystemExit(
        "Cm dynamic-stride sequence cache requires --ds-rate=1 "
        "so stride denotes original GRAB frames."
    )
```

或者至少把 `ds_rate` 写入每个 NPZ，并在 Dataset 初始化时验证它等于 1。


### 3. 可视化最好增加固定 stride 参数

`visualize.py` 当前没有 `--stride` 参数。

因此可视化和 `assignment-report` 默认使用 epoch 0 下每个当前帧各自抽到的随机跨度，例如：

```text
frame 100 -> stride 3
frame 101 -> stride 11
frame 102 -> stride 5
```

普通查看没有问题，但当你想比较：

* 不同时间位置的 slot 分配稳定性；
* stride 1 与 stride 12 的差异；
* 同一跨度下的连续 rollout；

随机混合跨度会干扰判断。

建议加：

```python
parser.add_argument(
    "--stride",
    type=int,
    default=None,
    choices=range(1, 13),
)
```

并在构造 Dataset 时传入：

```python
min_stride=int(runner.cfg.data.min_stride),
max_stride=int(runner.cfg.data.max_stride),
fixed_stride=args.stride,
```

## 总体判断

当前核心设计已经成立：

[
\boxed{
d\sim\mathcal U{1,\ldots,12}
}
]

[
\boxed{
(O_t,H_t,\Delta H_{t\rightarrow t+d})
\rightarrow C_m
\rightarrow \Delta O_{t\rightarrow t+d}
}
]
