



## 2. 手腕位姿变换可以从模型输入删除

这一点我同意。

当前模型同时输入了：

* 每个手点的 `hand_flow`
* 额外的 `wrist_delta`

代码中会把 `wrist_delta` 的 (3\times4) 部分展开成 12 维，再复制给全部手点。

但当前 `hand_flow` 的计算方式已经是：

[
\Delta H
========

H_{t+d}^{h_t}-H_t^{h_t}
]

也就是未来手点被变换到当前手根坐标系后再相减。它已经同时包含：

* 手腕整体平移；
* 手腕整体旋转；
* 手指关节运动。

当前 Stage 4 文档也明确说明，该定义保留了 wrist 的全局平移、旋转以及手指运动。

因此从 `Cm` 模型输入中删除 `wrist_delta` 是合理的。输入改成：

[
C_m=f(
Z_h,,
H_t,,
N_t^h,,
\Delta H,,
P_{\text{contact}}
)
]

当前附加输入维度为：

```text
hand_points       3
hand_normals      3
hand_flow         3
dense_contact     1
wrist_delta      12
--------------------
总计             22
```

删除手腕变换后变成：

```text
hand_points       3
hand_normals      3
hand_flow         3
dense_contact     1
--------------------
总计             10
```

修改为：

```python
self.hand_motion_encoder = _mlp(
    self.dense_token_dim + 10,
    cm_dim,
    cm_dim,
)
```

并删除：

```python
wrist_features = wrist_delta[:, :3, :4].reshape(
    batch_size, 1, 12
).expand(-1, num_hand, -1)
```

输入改成：

```python
hand_input = torch.cat(
    [
        z_hand,
        hand_points,
        hand_normals,
        hand_flow,
        dense_hand_contact.unsqueeze(-1),
    ],
    dim=-1,
)
```

### 但要保留一个区别

可以删除作为**模型输入**的 `wrist_delta`，但建议暂时保留每帧的：

```text
hand_root_pose_world
```

它只用于在 Dataset 内部把两帧点云统一变换到当前手根坐标系，不送给网络。

因为原始适配器输出的是世界坐标系中的：

```text
obj_points_world
hand_points_world
hand_root_pose
```

如果完全删除手根位姿，改成直接用世界坐标点，模型会重新依赖场景的绝对朝向和位置，而且与当前冻结 DenseToken 模型使用的 `hand_root_t` 坐标系不一致。

所以建议：

> **保留 hand root pose 作为坐标转换工具，但不把任何 wrist pose 或 wrist delta 输入网络。**

## 3. “每个 epoch 随机跨度”不是整个 epoch 使用同一个跨度

你指出的问题是对的。整个 epoch 统一使用同一个跨度是不合理的。

我原来的意思是：

* 每个样本独立随机一个跨度；
* 同一个 batch 中可以同时包含不同跨度；
* epoch 只用于改变随机种子。

其中 epoch 是“完整遍历一次训练集”。

例如一个 batch 有四个样本：

```text
sample A: t=20, d=1
sample B: t=85, d=4
sample C: t=31, d=2
sample D: t=76, d=5
```

下一个 epoch，同一个起点可能变成：

```text
sample A: t=20, d=3
sample B: t=85, d=1
sample C: t=31, d=5
sample D: t=76, d=2
```

因此随机跨度应该写成：

[
d_{i,e}\sim\mathcal U{1,2,3,4,5}
]

其中：

* (i)：样本或当前帧；
* (e)：epoch；
* 每个 (i) 独立采样。

当前 `BaseRunner` 已经会在每个 epoch 调用 Dataset 的 `set_epoch()`，因此可以方便地实现可复现的逐样本随机跨度。

伪代码是：

```python
def __getitem__(self, index):
    path, current_idx = self.samples[index]

    seed = stable_seed(
        base_seed=self.base_seed,
        seq_id=seq_id,
        side=side,
        frame_id=current_frame_id,
        epoch=self.epoch,
    )

    rng = np.random.default_rng(seed)
    stride = int(rng.integers(1, 6))

    next_idx = current_idx + stride
```

这样做不是为了让一个 epoch 内的跨度一致，而是为了：

* 不同样本独立随机；
* 同一训练运行可复现；
* 同一个起点在不同 epoch 看到不同跨度；
* 多个 DataLoader worker 不会产生失控的重复随机数。

## 4. 样本只要求当前帧 5 cm 内有物体点

这一点我也同意。

目前 Dataset 有两个筛选条件：

1. `active_only`：当前帧存在 5 cm 候选物体点；
2. `min_object_flow_norm`：候选物体点的平均位移必须足够大。

第二个条件应该删除。

样本有效条件只保留：

[
\exists,p_o\in O_t:
\min_{p_h\in H_t}|p_o-p_h|\leq 0.05
]

对应：

```python
valid_current_frame = candidate_mask.any()
```

而不再要求：

```python
mean_candidate_flow >= min_object_flow_norm
```

### 静态信息确实是有效监督

以下样本是有意义的：

[
\Delta H\approx0,\qquad
\Delta O\approx0
]

它教模型：

> 手和物体虽然靠得很近，但手没有产生动作，物体就不应该运动。

还有：

[
\Delta H\neq0,\qquad
\Delta O\approx0
]

也可能有意义，例如：

* 手指在物体旁边移动但没有接触；
* 手部运动方向没有向物体施加有效作用；
* 手在调整姿态，物体仍保持静止；
* 手与物体之间存在滑动或弱接触。

如果只保留明显物体位移的样本，模型很容易形成错误先验：

[
\text{只要手在物体旁边移动}
\Rightarrow
\text{物体一定移动}
]

所以不应根据物体位移删除样本。

唯一需要注意的是零流样本比例。如果静态样本过多，模型可能学成始终输出零流。但解决方式不应是硬阈值删除，而应该先记录：

```text
zero_flow_ratio
small_flow_ratio
medium_flow_ratio
large_flow_ratio
```

只有确认零流占比过高并导致模型塌缩后，再使用 batch 内平衡采样，例如一个 batch 中：

```text
50% 静态/小位移
50% 明显运动
```

数据本身仍全部保留。

## 5. 不再生成固定 pair 的 Stage 4：我同意

当前 Stage 4 的主要问题是，它在预处理时固定：

```python
current_idx = ...
next_idx = current_idx + pair_stride
```

然后把每一对的：

```text
hand_flow
obj_flow_gt
wrist_delta
```

提前生成并保存。

当预测跨度变成随机的 1–5 后，固定 pair 数据确实没有必要。

原始 `GRABRawAdapter` 已经能够：

* 使用 `ds_rate=1` 保留完整原始帧；
* 重建每一帧的手表面；
* 生成稳定对应的物体表面点；
* 返回完整的手、物体时间序列；
* 返回每帧的手根位姿。

因此更合理的数据结构是：

[
\boxed{
\text{GRAB Raw}
\rightarrow
\text{Sequence Cache}
\rightarrow
\text{Dataset 动态随机 }d
\rightarrow
\Delta H,\Delta O
}
]

这里的 Sequence Cache 是“序列缓存”，即一条序列只保存一次所有帧，而不是展开成大量帧对。

# Dataset 动态生成样本

## 1. 构造当前帧索引

初始化 Dataset 时，只把满足以下条件的当前帧加入样本：

```python
candidate_mask[current_idx].any()
```

并且为了保证 1–5 均匀采样：

```python
current_idx + max_stride < total_frames
```

即：

```python
for current_idx in range(total_frames - max_stride):
    if candidate_mask[current_idx].any():
        self._samples.append((path, current_idx))
```

我建议直接排除最后 5 帧，而不是对最后几帧缩小随机范围。否则：

* 序列中间帧可以采样 1–5；
* 末尾帧只能采样 1–2；

会导致不同跨度的概率不均匀。

---

## 2. 每个样本独立随机跨度

```python
stride = rng.integers(
    self.min_stride,
    self.max_stride + 1,
)

next_idx = current_idx + stride
```

默认：

```yaml
data:
  min_stride: 1
  max_stride: 5
```

---

## 3. 统一变换到当前手坐标系

```python
hand_root_t = data["hand_root_pose_world"][current_idx]

rotation = hand_root_t[:3, :3]
translation = hand_root_t[:3, 3]
```

定义：

```python
def world_to_current_hand(points_world):
    return (points_world - translation[None]) @ rotation
```

然后：

```python
obj_t = world_to_current_hand(
    data["obj_points_world"][current_idx]
)

obj_next = world_to_current_hand(
    data["obj_points_world"][next_idx]
)

hand_t = world_to_current_hand(
    data["hand_points_world"][current_idx]
)

hand_next = world_to_current_hand(
    data["hand_points_world"][next_idx]
)
```

计算总位移：

```python
obj_flow_gt = obj_next - obj_t
hand_flow = hand_next - hand_t
```

这里没有任何速度归一化，也没有输入步长：

```python
sample = {
    "obj_points": obj_t,
    "obj_normals": obj_normals_t,
    "obj_flow_gt": obj_flow_gt,

    "hand_points": hand_t,
    "hand_normals": hand_normals_t,
    "hand_flow": hand_flow,

    "obj_valid_mask": obj_valid_mask,

    # 只用于调试和评估，不输入模型
    "stride": stride,
    "raw_frame_id": raw_frame_id,
    "next_raw_frame_id": next_raw_frame_id,
}
```

# 模型最终看到的信息

模型输入：

[
\boxed{
O_t,\ N_t^o,\ H_t,\ N_t^h,\ \Delta H_{t\rightarrow t+d}
}
]

DenseToken 提供当前交互特征：

[
Z_t^o,Z_t^h,P_{\text{contact}}
]

Cm 分支：

[
C_m
===

f(
Z_t^h,
H_t,
N_t^h,
\Delta H,
P_{\text{contact}}
)
]

物体预测：

[
\hat{\Delta O}
==============

g(
Z_t^o,
O_t,
N_t^o,
C_m
)
]

其中既没有：

* `stride`；
* `time_delta_sec`；
* `wrist_delta`；
* 未来物体点作为输入。

只使用未来物体点计算监督目标：

[
\Delta O=O_{t+d}-O_t
]

# “一段点流”应该使用总位移还是逐帧序列

当前我建议首先采用：

[
\Delta H_{t\rightarrow t+d}
===========================

H_{t+d}-H_t
]

也就是端点总位移。

不要先输入：

[
[
H_{t+1}-H_t,,
H_{t+2}-H_{t+1},,
\dots,,
H_{t+d}-H_{t+d-1}
]
]

因为后者会产生长度为 1–5 的变长输入，需要额外引入：

* 时间维度 padding；
* temporal attention；
* 时间 mask；
* 顺序编码。

而且模型仍然可以通过序列长度直接知道跨度 (d)。



---

# 最终建议

新的训练链路应当是：

```text
原始 GRAB 全帧序列
        │
        ▼
离线重建并缓存逐帧手/物体点云
        │
        ▼
仅选择当前帧 5cm 内存在物体点的样本
        │
        ▼
每个样本独立随机 d ∈ {1,2,3,4,5}
        │
        ▼
把 t 和 t+d 全部变换到当前 hand-root 坐标系
        │
        ▼
hand_flow = H[t+d] - H[t]
obj_flow  = O[t+d] - O[t]
        │
        ▼
Cm(hand_points, hand_flow)
        │
        ▼
预测 obj_flow
```

对应代码层面的修改范围是：

1. 将 `prepare_cm.py` 改成逐帧序列缓存，不再生成 pair。
2. 在 `Stage4CmDataset.__getitem__()` 内随机生成 `next_idx`。
3. 删除 `min_object_flow_norm` 过滤。
4. 只保留当前帧 `obj_candidate_mask_5cm.any()` 的条件。
5. 从 Dataset 和 Model 中删除 `wrist_delta`。
6. `hand_motion_encoder` 输入维度从 `dense_token_dim + 22` 改为 `dense_token_dim + 10`。
7. 训练仍直接监督位移 `pred_obj_flow ↔ obj_flow_gt`。
8. 训练集随机跨度，验证集分别固定评估 `d=1,2,3,4,5`，但这些 pair 在运行时生成，不再落盘。

注意：
以上代码说的1到5的预测窗口只是作为超参，不要写死到代码里面。还有就是初始的超参我建议设置为1到12随机采样来预测
