### 1. Stage 4 已改成完整序列缓存

现在 `prepare_cm.py` 不再生成固定的 `(t,t+d)` pair，而是使用新格式：

```text
schema_name = ref2dex_cm_sequence
schema_version = 2.0.0
```

每条文件保存完整时间序列的：

```text
obj_points_world

hand_points_world

hand_root_pose_world
obj_candidate_mask_5cm
```

不再落盘 `hand_flow`、`obj_flow_gt`、`wrist_delta` 等 pair 字段。

这部分符合你的设计：

[
\text{GRAB raw}
\rightarrow
\text{完整序列缓存}
\rightarrow
\text{Dataset 运行时生成随机跨度样本}
]

### 2. Dataset 已实现逐样本随机跨度

当前每个训练样本根据：

```text
base_seed
seq_id
side
raw_frame_id
epoch
```

独立生成一个随机 `stride`：

```python
stride = rng.integers(min_stride, max_stride + 1)
future = current + stride
```

同一个 batch 内不同样本可以使用不同跨度，不是整个 epoch 共用一个跨度。

Dataset 随后把当前帧和未来帧都变换到当前手根坐标系：

```python
obj_flow_gt = obj_future - obj_current
hand_flow = hand_future - hand_current
```

没有速度归一化，也没有把 stride 输入模型。

### 3. 只使用当前帧 5 cm 条件筛选

现在初始化样本列表时，只检查：

```python
candidate[current].any()
```

已经删除了 `min_object_flow_norm`，所以静止物体、无效果手部运动等样本都会保留。

这符合：

[
\exists p_o,\quad
\min_{p_h}|p_o-p_h|\leq 5\text{ cm}
]

而不要求：

[
|\Delta O|>\epsilon
]

### 4. 模型已经删除手腕位姿输入

当前 `hand_motion_encoder` 输入维度已经从：

```text
dense_token_dim + 22
```

改成：


输入只有：

这一点处理得较好。

# 当前存在的问题

## 1. 最严重：多进程下 epoch 随机跨度实际上不会更新

Dataset 当前写的是：

```python
self.base_seed, self.epoch = int(base_seed), 0
```

以及：

```python
def set_epoch(self, epoch):
    self.epoch = int(epoch)
```

但正式配置使用：

```yaml
num_workers: 4
persistent_workers: true
```

这会造成一个实际 bug：

* 主进程调用 `dataset.set_epoch(epoch)`；
* 4 个持久化 worker 内各自保存的是 Dataset 副本；
* worker 中的 `self.epoch` 仍然一直是 `0`；
* 因此同一个当前帧在每个 epoch 都会抽到相同 stride。

也就是说，代码表面上实现了“每个 epoch 换随机跨度”，但正式训练配置下实际上会固定。

应改成进程共享值：

```python
import multiprocessing as mp

self._epoch = mp.Value("q", 0, lock=True)

@property
def epoch(self) -> int:
    return int(self._epoch.value)

def set_epoch(self, epoch: int) -> None:
    with self._epoch.get_lock():
        self._epoch.value = int(epoch)
```

临时规避方式是：

```yaml
persistent_workers: false
```

但正式修复应使用 `mp.Value`。

## 3. `visualize.py` 仍然大量依赖旧 Stage 4 格式

基础的单 pair 显示可能还能运行，但以下功能已经确定会报错。

### assignment report 使用不存在的 `pair_index`

```python
raw_pair_indices.append(int(sample["pair_index"]))
```

新 Dataset 并没有返回 `pair_index`，只返回：

```text
raw_frame_id
next_raw_frame_id
stride
```

因此 `--assignment-report` 会直接触发 `KeyError`。

### trajectory rollout 读取旧 NPZ 字段

它仍然访问：

```python
data["obj_points"]
data["obj_normals"]
data["obj_flow_gt"]
```

但新缓存只保存：

```text
obj_points_world
obj_normals_world
```

`obj_flow_gt` 是 Dataset 运行时计算的，不再存在于文件中。

### rollout 仍然使用 `wrist_delta`

```python
current_sample["wrist_delta"]
```

新 Dataset 已删除该字段，因此 trajectory rollout 必然报错。

正确做法不是重新把 `wrist_delta` 加回模型输入，而是可视化内部根据两个时间点的：

```text
hand_root_pose_world[current]
hand_root_pose_world[future]
```

计算坐标系转换。这个变换只服务可视化 rollout，不送入模型。

## 4. `extract.py` 没有明确控制导出跨度

当前导出时这样构造 Dataset：

```python
dataset = Stage4CmDataset(
    input_path,
    num_obj_points=...,
    num_hand_points=...,
    base_seed=...,
    active_only=...,
)
```

它没有传入：

```text
min_stride
max_stride
fixed_stride
```

因此会使用 Dataset 默认的 `1–12`，并在 epoch 0 下为每个当前帧抽取一个固定随机跨度。

这会导致导出的文件混合不同 stride，但用户无法指定：

```bash
--stride 1
--stride 3
--stride 5
```

建议加入：

```python
parser.add_argument("--stride", type=int, default=None)
```

然后：

```python
dataset = Stage4CmDataset(
    ...,
    min_stride=int(runner.cfg.data.min_stride),
    max_stride=int(runner.cfg.data.max_stride),
    fixed_stride=args.stride,
)
```

至少应把 checkpoint 中的训练跨度配置传进来，不能依赖 Dataset 默认值。

---

## 5. checkpoint 目前只根据 stride 1 选择

正式配置为：

```yaml
metric_for_best: val/stride_1/flow_mse
```

虽然 Dataset 会分别构建 stride 1–5 的验证 DataLoader， 但最优模型只看：

[
\operatorname{MSE}_{d=1}
]

这可能选择出“短跨度表现最好，但中长跨度较差”的 checkpoint。

更合理的是在 `CmActionRunner.evaluate_all()` 中增加：

```text
val/mean_stride_flow_mse
```

例如：

[
L_{\text{val}}
==============

\frac{1}{5}
\sum_{d=1}^{5}
L_{\text{flow}}^{(d)}
]

然后：

```yaml
metric_for_best: val/mean_stride_flow_mse
```

这样每个跨度权重相同。

---

## 6. stride 与物体点采样共用同一个随机种子

当前代码：

```python
seed = stable_frame_seed(...)
stride = np.random.default_rng(seed).integers(...)
selected_idx = sample_object_indices(..., seed=seed)
```

而 `stable_frame_seed()` 本身支持 `namespace` 参数。

建议拆开：

```python
stride_seed = stable_frame_seed(
    ...,
    epoch=self.epoch,
    namespace="cm-stride",
)

object_seed = stable_frame_seed(
    ...,
    epoch=self.epoch,
    namespace="cm-object-sampling",
)
```

这样随机跨度和物体点子集相互独立，不会出现某个 stride 总是和某一种采样序列绑定。

# 当前总体判断

核心方案已经实现正确：

[
\boxed{
O_t,H_t,\Delta H_{t\rightarrow t+d}
\rightarrow
C_m
\rightarrow
\Delta O_{t\rightarrow t+d}
}
]

并且已经满足：

* 不做速度归一化；
* 不输入 stride；
* 不输入 wrist delta；
* 每个样本独立随机未来跨度；
* 只根据当前帧 5 cm 邻域筛选；
* 保留静态和零物体流样本；
* 不再提前生成固定 pair。

但在真正开始正式训练前，至少需要先处理：

1. **用共享 epoch 修复 persistent worker 下 stride 固定的问题；**
2. **明确统一使用 1–12；**
3. **修复 `visualize.py` 中旧字段残留；**
4. **让 extract 显式控制 stride；**
5. **用多跨度平均指标选择 checkpoint。**

其中第 1 项最隐蔽：不修复时程序不会报错，但多 epoch 随机跨度增强实际上不会生效。
