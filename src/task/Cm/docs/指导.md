明白。你的目标是：

[
\boxed{
\text{对外输入/输出：m}
\quad
\text{DenseToken：m}
\quad
\text{Cm 可训练模块内部：cm}
}
]

在这个设计下，**把 `obj_points`、`hand_points`、`hand_flow` 一起乘 100 是正确的**。我上一条所说的“只缩放 hand flow”不适用于你现在明确的设计；只缩放 `hand_flow` 反而会让 Cm 内部同时混用米和厘米。

## 正确的数据流

```text
Dataset 输出，单位 m
        │
        ├── obj_points_m ────────┐
        ├── hand_points_m ───────┤
        ├── normals              │
        │                        ▼
        │                 Frozen DenseToken
        │                    输入保持 m
        │                        │
        │                  z_obj, z_hand
        │                        │
        └──────────────┬─────────┘
                       ▼
                Cm trainable head
                       │
              所有几何量 m × 100
                       │
        obj_points_cm / hand_points_cm
               hand_flow_cm
                       │
                 内部预测 ΔO_cm
                       │
                    ÷ 100
                       ▼
             对外输出 pred_flow_m
```

当前代码在调用 DenseToken 时传入的是原始 batch：

```python
z_obj, z_hand, dense_hand_contact = self.dense_encoder(
    obj_points=batch["obj_points"],
    hand_points=batch["hand_points"],
    ...
)
```

这里没有乘 100，因此预训练 DenseToken 仍然看到训练时的米制分布。

进入 Cm head 后才执行：

```python
obj_points_internal = obj_points * scale
hand_points_internal = hand_points * scale
hand_flow_internal = hand_flow * scale
```

因此，当前模型的**结构方向符合你的目标**。

## 为什么三个量都要乘 100

Cm 内部要计算：

[
p_o^{cm}-p_h^{cm}
]

如果只把 `hand_flow` 转成 cm，而点坐标仍是 m，就会出现：

```text
hand_points = 0.10       # m
hand_flow   = 0.50       # 实际表示 0.5 cm
```

它们虽然只是输入不同通道，网络理论上可以学，但物理尺度混乱。

统一转成厘米后：

```text
hand_points_cm = 10.0
hand_flow_cm   = 0.5
```

它们的相对比例仍然正确：

[
\frac{0.5\ \mathrm{cm}}{10\ \mathrm{cm}}
========================================

\frac{0.005\ \mathrm{m}}{0.1\ \mathrm{m}}
=0.05
]

此外，object-to-anchor 相对位置：

```python
relative = obj_points_internal - cm_anchor_pos_internal
```

也必须保证两边都是 cm。当前代码在这里是一致的。

## DenseToken 特征和 cm 坐标拼接没有单位冲突

`z_obj`、`z_hand` 已经是神经网络特征，不再是具有明确“米单位”的物理坐标。

它们的含义是：

```text
z_obj / z_hand：由米制点云提取出的潜在特征
obj_points_cm：Cm 新模块使用的显式几何坐标
hand_flow_cm：Cm 新模块使用的显式动作位移
```

网络特征本来就可以和不同尺度的显式变量拼接。关键要求只是：

> 预训练 DenseToken 的原始输入不能改变尺度。

当前代码满足这一点。

## 现在真正需要修改的是 loss

当前模型内部预测：

```python
pred_obj_flow_internal   # cm
```

对外输出：

```python
pred_obj_flow = pred_obj_flow_internal / 100
```

这一步作为公开接口是正确的。

但 Runner 现在直接使用米制输出和米制 GT 训练：

```python
pred_flow = prediction["pred_obj_flow"]
gt_flow = batch["obj_flow_gt"]

loss = smooth_l1(pred_flow, gt_flow, beta=0.01)
```

这样会经过：

[
\Delta O_m=\frac{\Delta O_{cm}}{100}
]

因此传回内部输出的梯度包含 (1/100)：

[
\frac{\partial L}{\partial \Delta O_{cm}}
=========================================

\frac{1}{100}
\frac{\partial L}{\partial \Delta O_m}
]

语义没有错，但会让 cm decoder 学得偏慢。

## 推荐的 loss 实现

模型接口仍然只输出米：

```python
pred_flow_m = prediction["pred_obj_flow"]
gt_flow_m = batch["obj_flow_gt"].float()
```

Runner 内部重新构造厘米制监督：

```python
scale = float(self.cfg.meta.internal_point_flow_scale)

pred_flow_internal = pred_flow_m * scale
gt_flow_internal = gt_flow_m * scale

beta_m = float(self.cfg.meta.flow_smooth_l1_beta)
beta_internal = beta_m * scale

smooth_l1_map = F.smooth_l1_loss(
    pred_flow_internal,
    gt_flow_internal,
    beta=beta_internal,
    reduction="none",
).mean(dim=-1)

flow_smooth_l1 = (
    smooth_l1_map * valid.float()
).sum() / valid_count.float()
```

因为：

```text
0.01 m × 100 = 1 cm
```

所以原来的：

```yaml
flow_smooth_l1_beta: 0.01
```

仍然可以解释为公开米制配置，Runner 内部自动转换为：

```text
beta_internal = 1.0 cm
```

而 MSE、MAE 和 flow norm 等对外指标继续使用米：

```python
squared_map = (pred_flow_m - gt_flow_m).square().mean(dim=-1)
absolute_map = (pred_flow_m - gt_flow_m).abs().mean(dim=-1)
```

这样日志仍然保持：

```text
flow_mae = 0.003  # 表示 3 mm
flow_mse           # 单位 m²
pred_flow_norm     # 单位 m
```

## 配置还没有真正打开 100

当前默认值仍然是：

```python
internal_point_flow_scale = 1.0
```

而 `sequence_small30_online.yaml` 没有覆盖它，所以直接启动训练仍然使用米制内部计算。

需要加入：

```yaml
meta:
  internal_point_flow_scale: 100.0
```

例如：

```yaml
_base_: src.task.Cm.config:Config

name: cm_sequence_small30_stride12

meta:
  internal_point_flow_scale: 100.0

data:
  train_path: processed_data/generated/cm_sequence_small30
  active_only: true
  min_stride: 1
  max_stride: 12
```



含义为：

* 旧 checkpoint：内部仍按 m，scale=1；
* 新 checkpoint：根据保存配置使用 scale=100；
* DenseToken checkpoint 不受影响。

## 建议增加的单元测试

当前测试只验证零输出：

```python
0 / 100 = 0
```

它不能验证非零转换。

可以把输出层 bias 人工设成 1 cm：

```python
head = CmFlowHead(
    dense_token_dim=4,
    cm_dim=8,
    num_cm_tokens=2,
    num_slot_iters=1,
    internal_point_flow_scale=100.0,
)

with torch.no_grad():
    head.flow_edge[-1].bias[1:] = torch.tensor([1.0, 2.0, 3.0])
```

然后应满足：

```python
expected_m = torch.tensor([0.01, 0.02, 0.03])

torch.testing.assert_close(
    output["pred_obj_flow"][0, 0],
    expected_m,
)
```

同时增加 DenseToken 输入尺度测试，确保进入冻结编码器的值没有乘 100。

## 最终判断

当前实现中：

| 部分                    | 当前状态     |
| --------------------- | -------- |
| Dataset 对外单位为 m       | 正确       |
| DenseToken 输入保持 m     | 正确       |
| `z_obj/z_hand` 后进入 Cm | 正确       |
| Cm 内部点坐标转 cm          | 正确       |
| Cm 内部 hand flow 转 cm  | 正确       |
| 内部相对位置统一为 cm          | 正确       |
| 输出除 100 恢复 m          | 正确       |
| YAML 启用 scale=100     | **尚未设置** |
| loss 在 cm 内部计算        | **尚未实现** |
| 日志指标保持 m              | 当前正确，应保留 |


因此不需要改成“只缩放 hand flow”。应保留当前全 Cm 几何分支统一转 cm 的设计，只补上：

1. YAML 显式设置 `internal_point_flow_scale: 100.0`；
2. Runner 使用 cm 制 SmoothL1 训练；
3. MSE、MAE、norm 继续在 m 制记录；
5. 增加非零单位转换测试。
