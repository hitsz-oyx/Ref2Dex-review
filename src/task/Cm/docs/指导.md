我检查了最新提交 `3236d05`（“改scale，实际测量归一化”）。结论是：

[
\boxed{\text{模型与 Runner 中的 scale 主逻辑已经正确，不需要重新设计。}}
]

但在正式跑完整实验前，有 **两个高优先级问题必须修复**：旧配置静默失效，以及统计脚本没有完全复现训练采样分布。

# 一、当前 scale 主链路是正确的

现在已经拆分成：

```yaml
geometry_input_scale
hand_flow_input_scale
object_flow_target_scale
```

不再让同一个 scale 同时承担坐标输入、手部运动输入和输出目标三个职责。配置中还保存了 `flow_target_rms_m`，方向正确。

模型内部：

```python
obj_points_internal = obj_points * geometry_input_scale
hand_points_internal = hand_points * geometry_input_scale
hand_flow_internal = hand_flow * hand_flow_input_scale
```

Flow head 预测归一化输出：

```python
dynamic_flow_scaled = self.edge_flow_head(edge_features)
```

对外只返回米制最终 flow：

```python
pred_obj_flow = pred_obj_flow_scaled / object_flow_target_scale
```

这符合之前确定的结构。

Runner 再把唯一的米制输出乘回 target scale：

```python
(pred_flow_m - gt_flow_m) * object_flow_target_scale
```

所以模型中的除法和 Runner 中的乘法位于同一计算图中，梯度不会额外缩小 (1/s)。同时指标直接使用米制输出，并转换为毫米记录。

完整链路为：

[
\hat f_s
\xrightarrow{/s}
\hat f_m
\xrightarrow{\times s\text{ 计算训练损失}}
\hat f_s
]

因此这一部分是正确的。

# 二、严重问题：旧配置中的 scale 现在会被静默忽略

例如当前仓库的旧配置仍然写着：

```yaml
meta:
  internal_point_flow_scale: 100.0
```

并且最佳模型指标还是不存在的旧名称：

```yaml
metric_for_best: val/mean_stride_flow_residual_norm_mean
```

`sequence_ds4_online.yaml` 就是这种状态。

问题在于配置系统允许添加未知字段，不会因为 `internal_point_flow_scale` 已从基础配置删除而报错。它会继续把这个字段挂到 `meta` 对象上。

但是 `CmFlowModel` 当前只读取：

```python
meta.geometry_input_scale
meta.hand_flow_input_scale
meta.object_flow_target_scale
```

并没有把：

```python
meta.internal_point_flow_scale
```

传入 `CmFlowHead`。虽然 `CmFlowHead` 构造函数里写了 legacy alias，中文是“旧配置兼容参数”，但这个 alias 实际上不会被 `CmFlowModel` 调用。

因此旧配置会出现：

```text
配置中看起来 scale=100
实际模型：
geometry_input_scale=1
hand_flow_input_scale=1
object_flow_target_scale=1
```

而且不会报错。

## 修复方法

首选方案是一次性迁移所有 Cm YAML：

```yaml
meta:
  geometry_input_scale: 100.0
  hand_flow_input_scale: 100.0
  object_flow_target_scale: 100.0
```

对于经过统计的新实验则填写各自的实际值。

同时统一：

```yaml
metric_for_best: val/mean_stride_epe_mm
```

不建议长期保留旧字段兼容；但为了避免旧实验配置静默改变行为，可以暂时在 `CmFlowModel` 中加入：

```python
legacy_scale = getattr(
    meta,
    "internal_point_flow_scale",
    None,
)

self.head = CmFlowHead(
    dense_token_dim=self.dense_encoder.token_dim,
    cm_dim=int(meta.cm_dim),
    num_cm_tokens=int(meta.num_cm_tokens),
    num_slot_iters=int(meta.slot_iters),
    geometry_input_scale=float(meta.geometry_input_scale),
    hand_flow_input_scale=float(meta.hand_flow_input_scale),
    object_flow_target_scale=float(
        meta.object_flow_target_scale
    ),
    internal_point_flow_scale=legacy_scale,
    slot_threshold=float(meta.slot_threshold),
)
```

这样旧配置至少不会无声地变成 scale 1。

更重要的是，应让配置系统或 Cm Runner 在发现旧字段时打印明显 warning，中文是“警告”，而不是静默接受。

# 三、严重问题：统计脚本和训练样本的 frame 范围不一致

训练 Dataset 构造样本时使用：

```python
for current in range(
    0,
    frame_count - self.max_stride
):
```

也就是说，无论本次随机选择 stride 1 还是 stride 10，合法 current frame 集合都是固定的：

[
0,\ldots,T-\text{max_stride}-1
]

这样每个 current 都保证可以选择任意 stride。

但统计脚本当前使用：

```python
for stride in range(min_stride, max_stride + 1):
    for current in range(frame_count - stride):
```

因此：

* stride 1 会统计到序列结尾附近的额外 frame；
* stride 10 统计的 frame 较少；
* 这些 stride 1 的额外 frame 在真实训练中从来不会被采样。

统计脚本虽然最后让各 stride 等权，但每个 stride 内的 current frame population，中文是“参与统计的当前帧集合”，仍然和训练不一致。

## 应改成

```python
max_current = frame_count - max_stride

for current in range(max_current):
    candidate = candidate_mask[current]

    if active_only and not candidate.any():
        continue

    for stride in range(
        min_stride,
        max_stride + 1,
    ):
        flow = (
            obj_points[current + stride]
            - obj_points[current]
        )
        ...
```

这样统计与 Dataset 使用完全相同的 current frame 集合。

# 四、统计脚本的点权重也没有完全匹配训练

训练时每个 pair 最多采样：

```python
num_obj_points = 512
```

具体规则是：

* 候选点数 (\geq512)：无放回采样 512 个；
* 候选点数 (<512)：全部使用，剩余位置无效；
* loss 只统计有效点。

但是统计脚本当前把该 pair 的**所有候选点**都加入统计。

例如：

```text
Pair A：100 个候选点
Pair B：2000 个候选点
```

真实训练中的有效权重大致为：

```text
Pair A：100
Pair B：512
```

当前统计脚本的权重为：

```text
Pair A：100
Pair B：2000
```

候选区域大的 pair 被过度加权。

由于从 2000 个候选点中均匀抽 512 个，其期望均方模长等于全部 2000 个点的均方模长，所以不用真的重复随机采样；只需要修正权重：

```python
squared_norm = np.einsum(
    "ij,ij->i",
    flow,
    flow,
)

pair_mean_square = float(
    squared_norm.mean()
)

effective_count = min(
    int(squared_norm.size),
    num_obj_points,
)

stride_squared_sum += (
    pair_mean_square * effective_count
)
stride_point_count += effective_count
```

统计脚本应增加：

```bash
--num-obj-points 512
```

或者直接从配置中读取该值。

修复 frame 范围和 point weighting，中文是“点权重”，之后重新计算出的 RMS 可能和现在的：

```yaml
flow_target_rms_m: 0.077851...
object_flow_target_scale: 12.845...
```

有一定差异。当前数值不一定错得很大，但还不能称为严格匹配训练分布。

# 五、统计结果现在只是手工复制，没有一致性校验

统计脚本会把结果写入训练目录的 `metadata.json`，并打印推荐配置值。

但是当前训练配置又手工写了一遍：

```yaml
flow_target_rms_m: 0.07785101714457822
object_flow_target_scale: 12.845047331146437
```

而 `configure_data()` 目前只检查：

* coordinate frame；
* object point 数量；
* hand point 数量。

没有检查：

```text
训练配置中的 scale
是否等于统计 metadata 中的 scale
```

也没有检查：

[
\text{flow_target_rms_m}
\times
\text{object_flow_target_scale}
\approx1
]

## 至少增加配置内部检查

```python
rms_m = self.cfg.meta.flow_target_rms_m
target_scale = float(
    self.cfg.meta.object_flow_target_scale
)

if rms_m is not None:
    normalized_rms = (
        float(rms_m) * target_scale
    )

    if abs(normalized_rms - 1.0) > 1e-3:
        raise ValueError(
            "flow_target_rms_m and "
            "object_flow_target_scale are inconsistent: "
            f"{rms_m} * {target_scale} "
            f"= {normalized_rms}"
        )
```

更可靠的是在 DataLoader metadata 中读取统计结果，并对比配置：

```python
metadata_scale = metadata.get(
    "flow_target_scale"
)

if metadata_scale is not None:
    if not math.isclose(
        float(metadata_scale),
        target_scale,
        rel_tol=1e-5,
    ):
        raise ValueError(...)
```

否则数据重新统计后忘记更新 YAML，训练仍会正常开始。

# 七、测试还没有覆盖最关键的乘除抵消

现有测试验证了：

```python
internal_scale=100
```

时，loss 对**米制公开预测张量**的梯度是 scale 1 的 100 倍。

但真正需要验证的是：

```text
FlowHead 内部 scaled 输出
→ 模型除以 target scale
→ Runner 乘回 target scale
```

整个链路对内部输出的梯度没有多出 (1/s)。

建议增加：

```python
def test_public_meter_output_and_scaled_loss_cancel_scale():
    scale = 20.0

    pred_scaled = torch.tensor(
        [[[1.2, 0.0, 0.0]]],
        requires_grad=True,
    )
    gt_m = torch.tensor(
        [[[0.05, 0.0, 0.0]]]
    )
    valid = torch.ones(
        1, 1, dtype=torch.bool
    )

    pred_m = pred_scaled / scale

    indirect_loss = scaled_flow_smooth_l1(
        pred_m,
        gt_m,
        valid,
        beta_m=0.005,
        target_scale=scale,
    )

    direct_loss = F.smooth_l1_loss(
        torch.linalg.vector_norm(
            pred_scaled - gt_m * scale,
            dim=-1,
        ),
        torch.zeros(1, 1),
        beta=0.005 * scale,
    )

    indirect_grad = torch.autograd.grad(
        indirect_loss,
        pred_scaled,
        retain_graph=True,
    )[0]

    direct_grad = torch.autograd.grad(
        direct_loss,
        pred_scaled,
    )[0]

    torch.testing.assert_close(
        indirect_loss,
        direct_loss,
    )
    torch.testing.assert_close(
        indirect_grad,
        direct_grad,
    )
```

还应增加一个合成数据测试，检查统计脚本：

* 不使用结尾处额外 current frame；
* 候选点超过 512 时权重按 512；
* 每个 stride 等权；
* 只读取 train path。

本次提交没有新增相应测试文件，因此目前这些性质主要依赖人工推导。

# 八、之前的日志聚合问题仍然存在

这次 scale 改动没有处理以下问题：

1. `relative_epe` 仍然是每个 batch 先算比值，再由 BaseRunner 对 batch 比值求平均；
2. `norm_ratio` 同样是 batch ratio 的平均；
3. P90 仍然是每个 batch 计算 P90，之后平均；
4. `evaluate_all()` 仍然把完整 stride 指标汇总后丢弃，只返回少数 summary。

这些不会破坏 scale 训练本身，但会影响验证指标的精确定义。

由于当前已经改用绝对 `mean_stride_epe` 选择 checkpoint，第 1 项的风险暂时降低；但 P90 和完整 stride 保存仍建议后续修正。

# 最终判断

| 部分                        | 评价                  |
| ------------------------- | ------------------- |
| 三个 scale 拆分               | 正确                  |
| 只返回米制最终 flow              | 正确                  |
| Runner 乘回 scale 计算训练 loss | 正确                  |
| 梯度乘除关系                    | 正确                  |
| 只用训练集统计                   | 正确                  |
| 使用统一标量 RMS                | 正确                  |
| 统计 frame 分布               | **与 Dataset 不完全一致** |
| 统计点权重                     | **与 512 点采样不完全一致**  |
| 旧配置兼容                     | **存在静默失效问题**        |
| scale/metadata 一致性        | 尚未校验                |
| 单元测试                      | 覆盖不足                |

当前最合理的处理顺序：

1. 批量迁移或显式兼容所有旧 `internal_point_flow_scale` 配置；
2. 修正统计脚本的 current frame 范围；
3. 按 `min(candidate_count, 512)` 修正统计权重；
4. 重新计算 RMS 和 `object_flow_target_scale`；
5. 增加配置与 metadata 的一致性检查；
6. 增加完整乘除梯度测试；
7. 再开始正式的 10k 或更长训练。

修完前可以做 smoke test，中文是“小规模冒烟测试”，验证程序能正常运行；但不建议用当前统计值直接作为最终对比实验的正式 scale。
