# 已经修好的问题

## 1. `active_only=False` 的统计语义已修正

统计脚本现在始终只统计当前帧 5 cm 候选点：

```python
flow = flow[candidate]
```

`active_only` 只决定是否提前过滤候选为空的 current frame，不再错误地在 `active_only=False` 时统计全部物体表面点。

这一点现在和 Dataset 的实际采样逻辑一致。

---

## 2. metadata 采样分布检查已补齐

现在 metadata 会传播：

```text
statistics_active_only
statistics_num_obj_points
statistics_stride_distribution
statistics_stride_weighting
statistics_point_weighting
```

Runner 也会核对它们是否匹配当前训练配置：

```python
calibration_checks = {
    "statistics_split": ("train", str),
    "statistics_active_only": (
        bool(self.cfg.data.active_only),
        bool,
    ),
    "statistics_num_obj_points": (
        int(self.cfg.meta.num_obj_points),
        int,
    ),
    "statistics_stride_distribution": (
        f"uniform_{min_stride}_to_{max_stride}",
        str,
    ),
    ...
}
```

这解决了“用 stride 1～5 统计，却拿去训练 stride 1～10”之类的静默错误。

---

## 3. `relative_epe` 和 `norm_ratio` 的验证聚合已正确

之前是：

[
\frac{1}{B}\sum_b
\frac{\mathrm{EPE}_b}{\mathrm{GTNorm}_b}
]

现在先使用 `MetricStat` 对 EPE、GT norm、pred norm 按有效点全局聚合：

```python
"flow/epe_mm": MetricStat(
    residual_sum * 1000,
    valid_count,
),
"flow/gt_norm_mm": MetricStat(
    gt_norm_sum * 1000,
    valid_count,
),
"flow/pred_norm_mm": MetricStat(
    pred_norm_sum * 1000,
    valid_count,
),
```

然后在完整 loader 聚合后计算：

```python
relative_epe = epe_mm / gt_norm_mm
norm_ratio = pred_norm_mm / gt_norm_mm
```

这已经不再受 batch 如何切分的影响。

这是这次最重要的正确修改之一。

---

## 4. 完整 stride 结果不再丢失

现在：

```python
detailed = super().evaluate_all()

return {
    **detailed,
    **self._summarize_stride_metrics(
        detailed,
        split="val",
    ),
}
```

因此：

* JSONL 保留 stride 1～10 的完整指标；
* checkpoint 仍使用 summary；
* W&B 再单独过滤展示项。

这比之前直接丢弃详细结果合理。

## 5. 错误的 best metric 会直接报错

现在 `_save_if_best()` 中：

```python
if key not in metrics:
    raise KeyError(
        f"metric_for_best={key!r} "
        f"is unavailable. "
        f"Available metrics: {sorted(metrics)}"

```

不会再出现训练正常结束、但 `best.pt` 从未生成的静默失败。

---

## 6. overfit 配置已经正确处理

没有验证集的 overfit 配置改为：

```yaml
metric_for_best: null
```

BaseRunner 也支持 `metric_for_best=None`。这样 overfit 实验只保存普通 checkpoint，不再假装能够通过训练指标选择 best。

# 还存在的问题

## 一、中等：训练侧 `norm_ratio` 实际已经不再记录

`select_step_metrics()` 仍然保留：

```python
"flow/norm_ratio"
```

但 `step()` 当前不再产生这个指标。

当前 `step()` 只产生：

```text
flow/epe_mm
flow/gt_norm_mm
flow/pred_norm_mm
```

而 `norm_ratio` 只在：

```python
evaluate_loader()
```

中针对验证集计算。

因此实际表现是：

```text
train_step/flow/norm_ratio：不会出现
epoch/flow/norm_ratio：也不会出现
val/.../flow/norm_ratio：正常出现
```

### 推荐做法

不建议重新记录 batch 级 ratio，因为它仍会受 batch 组成影响。

只在训练 epoch 聚合完成后计算：

```python
def select_epoch_metrics(
    self,
    metrics: dict[str, float],
) -> dict[str, float]:
    result = ...

    gt_norm = metrics.get(
        "train_epoch/flow/gt_norm_mm"
    )
    pred_norm = metrics.get(
        "train_epoch/flow/pred_norm_mm"
    )
    epe = metrics.get(
        "train_epoch/flow/epe_mm"
    )

    if gt_norm is not None:
        result["epoch/flow/norm_ratio"] = (
            pred_norm / max(gt_norm, 1e-8)
        )
        result["epoch/flow/relative_epe"] = (
            epe / max(gt_norm, 1e-8)
        )
        result[
            "epoch/flow/zero_flow_improvement"
        ] = (
            1.0
            - result["epoch/flow/relative_epe"]
        )

    return result
```

同时从 step 核心指标中删除：

```python
"flow/norm_ratio"
```

最终建议：

```text
step：EPE
epoch：EPE + norm ratio + relative EPE
validation：完整指标
```

## 二、中等：测试集的 stride 1/5/10 不会进入 W&B

当前 W&B 筛选代码先删除所有：

```text
val/stride_*
test/stride_*
```

随后只重新加入：

```python
prefix = (
    f"val/stride_{stride}/flow/epe_mm"
)
```

这里硬编码成了 `val`。

所以：

* validation 的 stride 1、5、10 能进入 W&B；
* test 的 stride 1、5、10 全部被过滤；
* test 只剩平均 summary。

JSONL 不受影响，仍有完整数据。但 W&B 测试面板会缺少三个关键 horizon。

### 修改为

```python
def select_eval_metrics(
    self,
    metrics: dict[str, float],
) -> dict[str, float]:
    keep = {
        key: value
        for key, value in metrics.items()
        if not key.startswith(
            ("val/stride_", "test/stride_")
        )
    }

    for split in ("val", "test"):
        for stride in (1, 5, 10):
            key = (
                f"{split}/stride_{stride}"
                "/flow/epe_mm"
            )
            if key in metrics:
                keep[key] = metrics[key]

    return keep
```

## 三、中等：calibration metadata 仍然是“存在才检查”

当前逻辑是：

```python
if key in metadata:
    检查是否匹配
```

这意味着如果训练目录里根本没有：

```text
metadata.json
```

或 metadata 中缺少这些字段，训练仍然可以继续。

例如配置写了：

```yaml
flow_target_rms_m: 0.07591
object_flow_target_scale: 13.1734
```

但训练数据目录没有任何校准记录，当前只会检查这两个配置数值互为倒数，不会确认它们确实来自这个训练集。

### 正式训练建议使用严格模式

增加配置：

```yaml
meta:
  require_flow_calibration: true
```

然后：

```python
required_keys = {
    "flow_target_rms_m",
    "flow_target_scale",
    "statistics_split",
    "statistics_active_only",
    "statistics_num_obj_points",
    "statistics_stride_distribution",
    "statistics_stride_weighting",
    "statistics_point_weighting",
}

if self.cfg.meta.require_flow_calibration:
    missing = required_keys.difference(
        metadata
    )
    if missing:
        raise ValueError(
            "Missing Cm flow calibration "
            f"metadata: {sorted(missing)}"
        )
```

这样正式实验不会因为忘记运行统计脚本而悄悄使用 YAML 中手填的数值。

# 关于 P90

这次并不是计算出了真正的全局 P90，而是**把不准确的 batch-P90 删除了**。

当前 runner 中已经没有：

```text
flow/epe_p90_mm
```

也没有任何 `torch.quantile`。

这是合理的临时选择：

* 删除错误定义，比保留“平均 batch P90”更好；
* 但现在完全没有尾部误差指标。

如果当前主要目的是验证 scale 和模型是否正常收敛，可以暂时只使用：

```text
mean EPE
stride 1/5/10 EPE
mean stride EPE
```

后面需要分析异常大误差时，再增加真正的全局 P90。可以在验证阶段收集残差，或使用固定直方图近似，不要重新使用 batch P90 的平均。

# 一个设计层面的注意点

当前只要训练目录 metadata 中存在：

```text
flow_target_scale
```

配置中的：

```yaml
object_flow_target_scale
```

就必须与其一致。

这很适合正式训练，能防止误用 scale；但也意味着同一个数据目录不能直接进行：

```text
scale=1
scale=13.17
scale=20
scale=100
```

的对照实验。

若后续要做 scale ablation，中文是“scale 消融实验，即只改变 scale 进行对照”，建议增加：

```yaml
meta:
  enforce_flow_calibration: true
```

消融时显式设为：

```yaml
enforce_flow_calibration: false
```

否则不得不修改或移除数据目录中的 metadata。
