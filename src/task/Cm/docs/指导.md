# 4. 当前 straight-through 实现存在一个关键问题

当前代码是：

```python
slot_gate = (
    slot_nonzero_prob
    + (
        hard_slot_mask.float()
        - slot_nonzero_prob
    ).detach()
)

routing_logits = (
    dynamic_logits
    + torch.log(
        slot_gate[:, None, :].clamp_min(1e-8)
    )
)
```

表面上：

* 前向使用硬 0/1；
* 反向对连续概率传梯度。

但在后续经过 `clamp_min()` 和 `log()` 后，实际效果不是这样。

## 对未选中的 slot

未选中时，前向：

[
g_k=0
]

随后：

[
\operatorname{clamp}(g_k,10^{-8})=10^{-8}
]

由于输入处于 clamp 的截断区域，对原始 gate 的梯度为零：

[
\frac{\partial,\operatorname{clamp}(g_k)}
{\partial g_k}=0
]

因此未选中的 slot 无法通过 flow loss 得到：

> 你的候选流可能更好，应该提高开启概率。

也就是说：

[
\boxed{\text{inactive slot 的 flow-to-gate 梯度仍然被切断}}
]

## 对唯一选中的 slot

假设只有一个 slot 开启，routing softmax 近似是：

[
q_{\text{active}}\approx1
]

其余权重约为：

[
10^{-8}
]

softmax 对活跃 logit 的梯度：

[
q(1-q)\approx0
]

因此唯一活跃 slot 的 gate 从 flow loss 收到的梯度也很小。

最终结果是：

[
\boxed{\text{gate 主要由 count loss 和 confidence loss 控制，而不是由点流效果控制}}
]

点流损失主要训练被选中 slot 的 token 和 flow decoder，却很难告诉 gate：

* 应该换另一个 slot；
* 应该增加第二个 slot；
* 哪个 slot 能使点流误差更低。

# 5. 这解释了为什么一个 slot 会长期垄断

训练过程形成了以下正反馈：

```text
某个 slot 初期概率略高
→ fallback 或阈值选择它
→ 它获得主要点流训练
→ 它的 token 和候选流更成熟
→ 模型继续使用它
→ 其他 slot 缺少有效点流监督
```

当前 decoder 本身又很强，一个 slot 可以看到：

* 物体点特征；
* slot token；
* 相对几何位置；
* anchor normal。

因此一个 slot 完全可以逐渐学成“通用点流预测器”。

日志中也能看到：

```text
epoch 54:
candidate flow pairwise cosine ≈ 0.909
```

即不同 slot 的候选流仍然高度同向。

所以目前没有明显证据表明它们形成了清楚的运动分工。

# 6. confidence loss 和 count loss 的平衡点还有数学问题

当前配置：

```yaml
loss_slot_count_weight: 0.001
loss_slot_confidence_weight: 0.1
slot_threshold: 0.85
```

假设只考虑一个赢家概率 (p)，当前正则项近似为：

[
\mathcal L_{\text{reg}}
=======================

0.001p
+
0.1[\max(0,0.85-p)]^2
]

当 (p<0.85) 时求导：

[
\frac{\partial\mathcal L}{\partial p}
=====================================

0.001-0.2(0.85-p)
]

令其等于零：

[
p^\ast
======

# 0.85-\frac{0.001}{0.2}

0.845
]

也就是说，仅从这两个正则项看，最优概率是：

[
\boxed{p^\ast=0.845<0.85}
]

它恰好低于硬阈值。

因此系统可能倾向于：

```text
赢家概率长期略低于阈值
→ 每次依赖 fallback 强制选中
```

平方 confidence loss 在阈值处梯度变为零，而 count loss 仍然继续压低概率，所以其平衡点必然略低于阈值。

日志中的 `sampled_active_mean` 已经经过 fallback，无法区分：

* slot 自己超过阈值；
* 所有 slot 都没超过阈值，靠 fallback 选出一个。

因此现在需要增加 fallback 指标才能确认实际比例。

# 9. 建议的最小修改

当前结构不需要重新加入 null 或 effect gate。保留：

```text
硬阈值
+ 全部未达标时 top-1 fallback
```

即可，但建议修改两处。

## 修改一：在 weight 层做 straight-through

训练时先计算软路由：

```python
soft_routing_logits = (
    dynamic_logits
    + torch.log(
        slot_nonzero_prob[:, None, :]
        .clamp_min(1e-6)
    )
)

soft_weight = torch.softmax(
    soft_routing_logits,
    dim=2,
)
```

再计算硬路由：

```python
hard_routing_logits = dynamic_logits.masked_fill(
    ~hard_slot_mask[:, None, :],
    -1e4,
)

hard_weight = torch.softmax(
    hard_routing_logits,
    dim=2,
)
```

最后：

```python
edge_weight = (
    soft_weight
    + (hard_weight - soft_weight).detach()
)
```

这样：

* 前向严格使用硬 mask；
* 反向通过 `soft_weight`；
* 所有 slot 的概率都能从 flow loss 获得梯度；
* 未激活 slot 也有机会因为点流贡献更好而被打开。

这比当前对 `slot_gate` 做 straight-through 后再 `clamp + log` 更正确。

## 修改二：不要惩罚必需的第一个 slot

既然规定每个样本最少一个 slot，那么 slot count loss 不应继续惩罚这个必需赢家。

可以改成：

[
\mathcal L_{\text{count}}
=========================

\sum_kp_k-\max_kp_k
]

代码：

```python
max_probability = slot_nonzero_prob.max(
    dim=-1
).values

slot_count_loss = (
    slot_nonzero_prob.sum(dim=-1)
    - max_probability
).mean()
```

含义是：

* 最大概率 slot 免费；
* 只惩罚其他额外 slot；
* 复杂动作若确实需要多个 slot，flow loss 可以支付额外代价打开它们；
* 不再把赢家概率从阈值上方向下压。

confidence loss可以继续使用：

```python
confidence_loss = torch.relu(
    slot_threshold - max_probability
).square().mean()
```

此时它不再与第一名的 count penalty 正面冲突。

# 10. 应增加的诊断指标

至少增加：

```python
pre_fallback_mask = (
    slot_nonzero_prob >= slot_threshold
)

fallback_used = ~pre_fallback_mask.any(
    dim=-1
)

metrics.update({
    "slot/pre_fallback_active_mean":
        pre_fallback_mask.float().sum(dim=-1).mean(),

    "slot/fallback_ratio":
        fallback_used.float().mean(),

    "slot/max_probability_mean":
        slot_nonzero_prob.max(dim=-1).values.mean(),

    "slot/max_probability_min":
        slot_nonzero_prob.max(dim=-1).values.min(),
})
```

当前的：

```text
sampled_active_mean >= 1
```

因为已经包含 fallback，掩盖了真正没有 slot 达标的情况。

还应统计 fallback winner 索引的频率，以确认 slot 6 是否对几乎所有样本形成固定垄断。

# 最终判断

当前实验可以概括为：

[
\boxed{
\text{点流预测成功，但动态 slot 选择尚未真正由点流误差驱动}
}
]

更具体地说：

* **好的部分**：删除 null 后没有再发生零流 shortcut；训练点流已经收敛；硬 fallback 保证了解码路径不断开。
* **当前问题**：slot 6 长期占主导；未激活 gate 基本收不到 flow 梯度；平方 confidence 与 count loss 的平衡点低于阈值；训练中存在阈值震荡。
* **不能得出的结论**：不能根据当前训练误差证明多 slot 已产生分工，也不能证明动态 slot 数能够随动作复杂度合理变化。

当前结果反而给出了一个重要基线：

> 对 smoke12 训练集而言，单个强 slot 已经可以把点流拟合到约 1.9 mm MAE。

下一步应先修正 weight-level straight-through，并增加 fallback ratio；否则继续调 count/confidence 权重，只是在调整一个主要由正则项控制的 gate。
