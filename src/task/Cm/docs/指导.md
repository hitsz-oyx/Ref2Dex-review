### 已经改对的部分

**1. 完整版 (U^h) 保留了。**

当前输入确实是：

```python

    z_hand,
    hand_points,
    hand_normals,
    hand_flow,
    dense_hand_contact.unsqueeze(-1),
    wrist_features,

```

因此维度仍然是：

[

再经过 `hand_motion_encoder` 得到 (U^h)。

**2. `motion_to_scene`、`activity_head`、hard Top-K 都删掉了。**

现在直接：

```python
u_hand = self.hand_motion_encoder(hand_input)
cm_tokens, cm_assignment = self.slot_attention(u_hand)
```

也就是：

[
U^h\rightarrow SlotAttention\rightarrow C_m
]

没有在中间再读取 (Z^o)。这是我们要的干净 bottleneck。

**3. (Z^o) 只在 Slot bottleneck 之后进入 decoder。**

当前 object branch：

[
U_i^o=\phi(Z_i^o,x_i,n_i)

这意味着结构上已经真正形成：

[
\boxed{
\text{hand-side }U^h

}
]

**4. hard anchor 已经换成 soft hand region。**

现在：

[

代码实现正确。

**5. activity 已经彻底从训练目标删除。**

[

* Slot iterations = 3
* 无 `loss_activity_weight`

## 现在有一个需要注意的命名/语义问题：`cm_assignment`

当前 Slot Attention 内实际上有两个不同的矩阵。

先计算：

[
A_{kj}
======

\operatorname{softmax}*{k}(l*{kj})
]

代码：

```python
slot_assignment = torch.softmax(logits, dim=1)
```

这才是真正意义上的：

> 对于 hand point (j)，它在不同 slots 之间如何分配。

满足：

[
\sum_k A_{kj}=1
]

然后代码又计算：

```python
slot_weights = slot_assignment / slot_assignment.sum(
    dim=-1, keepdim=True
)
```

即：

[
W_{kj}
======

\frac{A_{kj}}
{\sum_jA_{kj}}
]

满足：

[
\sum_jW_{kj}=1
]

这是用于计算每个 slot 的 soft anchor 和 pooled feature 的**聚合权重**。

但函数最后返回的是：

```python
return slots, slot_weights
```

然后外面把它命名成：

```python
cm_tokens, cm_assignment = self.slot_attention(u_hand)
```

所以目前导出的：

```text
cm_assignment
```

实际上不是原始 assignment (A)，而是**per-slot normalized aggregation weights (W)**。

这不是计算错误，soft anchor 用 (W) 是正确的。

但语义最好改清楚：

```python
cm_tokens, cm_weights = self.slot_attention(u_hand)
```

然后：

```python
cm_anchor_pos = einsum(cm_weights, hand_points)
```

导出字段叫：

```text
cm_slot_weights
```

若后面真的要分析：

> 每一个 hand point 属于哪个 slot？

则应该同时返回原始：

[
A_{kj}=\operatorname{softmax}*k(l*{kj})
]

因为 (W) 再按 hand point 看时，不再满足：

[
\sum_k W_{kj}=1
]

当前测试也只验证了：

```python
cm_assignment.sum(dim=-1) == 1
```

其实验证的是“每个 slot 对所有 hand points 的聚合权重和为 1”。

### 建议

SlotAttention 返回三个量：

```python
return slots, slot_assignment, slot_weights
```

分别：

[
C_m,\quad A,\quad W
]

* `slot_assignment`: `[B,K,1538]`，对 slot 维归一化；
* `slot_weights`: `[B,K,1538]`，对 hand-point 维归一化；
* soft anchor 使用 `slot_weights`；
* 可视化“哪个点属于哪个 slot”使用 `slot_assignment`。

这是我认为当前最值得立刻修的小问题。

## 第二个问题：当前所有 16 个 Slot 永远都会参与 object flow

decoder 目前：

[
a_{ik}
======

\operatorname{softmax}*k(e*{ik})
]

然后：

[
\hat F_i
========

\sum_k a_{ik}f_{ik}
]

这作为第一版没有问题。

但要理解它的含义：

[
K=16
]

目前不是“最多 16 个 active action token”，而是：

> 永远有 16 个 latent slots，decoder 自己决定每个 object point 更依赖哪个 slot。

所以现在先不要把 (C_m) 解释成：

> 自动发现实际有几个接触动作。

当前只能解释成：

[
\boxed{
16\text{ 个固定容量的稀疏动作槽位}
}
]

等验证有效后，再考虑 slot presence/activity。

## 第三个问题：Slot collapse 目前完全没有检测

代码目前没有：

* diversity loss；
* entropy；
* overlap metric；
* slot usage metric。

这是第一版可以不加 loss，但**应该至少加 metric**。

否则可能出现 16 个 slots：

[
W_1\approx W_2\approx\cdots\approx W_{16}
]

全部关注整只手的类似区域，但 object flow 仍然能拟合。

建议现在不加正则，只记录两个诊断指标。

### Slot assignment entropy

对于每个 hand point：

[
H_j
===

-\sum_kA_{kj}\log(A_{kj}+\epsilon)
]

如果一直接近：

[
\log16
]

说明每个点平均分给所有 slots，Slot Attention 没有分组。

### Slot overlap

用 (W_k)：

[
O_{kl}
======

\frac{W_k^\top W_l}
{|W_k||W_l|}
]

如果所有非对角元素都接近 1：

[
W_k\approx W_l
]

说明 slots collapse。

**先作为 metric，不加入 loss。**

## 第四个问题：当前测试还太弱

新增了 `test_cm_slot_attention.py`，已经覆盖：

* 输入确实是 `dense_token_dim + 22`；
* (C_m) shape；
* assignment shape；
* soft anchor shape；
* normal shape；
* flow output shape；
* invalid object flow 为 0。

这些是好的 smoke test。

但至少还建议加两个测试：

### 1. Slot competition

对于真正的 `slot_assignment`：

[
\sum_kA_{kj}=1
]

当前测试只检查了返回的 `slot_weights`：

[
\sum_jW_{kj}=1
]

应该两个都验证。

### 2. Determinism

同样输入连续 forward 两次：

```python
out1 = head(...)
out2 = head(...)
assert_close(out1["cm_tokens"], out2["cm_tokens"])
```

因为这里使用 learnable deterministic `slot_init`，不是随机采样 slot initialization，代码设计目标也是 deterministic extraction。

## 第五个小问题：SlotAttention 的 docstring 和实际输入有一句矛盾

SlotAttention 类注释写：

> 可以定位 slot，而“不把 position 作为 motion encoder 输入”。

但实际完整版 (U^h) 明确输入了：

```python
hand_points
```

也就是 (y_j)。

这只是文档错误，不是模型错误。

应改成类似：

> `slot_weights` can be projected back onto hand geometry to localize each learned slot.

不要写 “without making position an input”。

# 当前整体评价

这次变更后的主架构我认为已经可以继续实验：

[
\boxed{
(Z_h,y,n,\Delta y,c,\Delta T_w)
\rightarrow U^h
\rightarrow SlotAttention_{K=16}
\rightarrow C_m
}
]

[
\boxed{
(Z_o,x_o,n_o,C_m,\text{soft geometry})
\rightarrow\hat F^o
}
]

相比上一个版本，最重要的三个问题已经解决：

1. **没有 hard Top-K 不可微选点；**
2. **没有 activity 退化解；**
3. **object context 不再绕过 bottleneck 进入 (U^h\rightarrow C_m)。**

现在我不会急着继续改架构。

我会先修一个东西：**把 `slot_assignment` 和 `slot_weights` 分开返回**。然后跑 overfit，并重点看：

[
L_{\text{flow}}\downarrow
]

的同时，16 个 Slot 的空间权重是否真的分开。如果 flow 能拟合，但 16 个 slot 全部重叠，那么下一步才需要处理 slot collapse，而不是现在提前加复杂正则。
