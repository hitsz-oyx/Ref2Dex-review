你们现在的 W&B 指标确实过多，主要问题是：

1. 同一信息被多个指标重复表达；
2. 16 个 slot 被逐个展开，直接增加几十条曲线；
3. 一些指标只适合排查问题，不适合长期保留；
4. 一些指标本身容易被未激活 slot 干扰。

当前代码同时记录了逐坐标 MSE、MAE、流模长、多个 gate 指标、slot 数量、16 个 slot 的使用率和 fallback winner 等。

建议分成三层。

# 一、训练过程中必须保留

每隔 100 step 记录一次，控制在 **10 个左右**。

| 指标                               | 是否保留 | 用途                    |
| -------------------------------- | ---- | --------------------- |
| `loss`                           | 保留   | 总训练目标                 |
| `flow_loss`                      | 保留   | 真实点流训练损失              |
| `flow/epe_mean`                  | 保留   | 三维平均端点误差              |
| `flow/norm_ratio`                | 保留   | 判断是否低估或高估运动幅值         |
| `lr`                             | 保留   | 检查学习率调度               |
| `grad_norm`                      | 保留   | 检查梯度爆炸                |
| `slot/expected_active_mean`      | 保留   | soft gate 认为需要多少 slot |
| `slot/sampled_active_mean`       | 保留   | 前向实际使用多少 slot         |
| `slot/fallback_ratio`            | 保留   | gate 是否频繁未达到阈值        |
| `decoder/effective_branch_count` | 保留   | decoder 实际有效使用多少分支    |
| `decoder/top1_usage`             | 保留   | 判断是否由单个 slot 垄断       |

建议直接将：

```python
gt_flow_norm
pred_flow_norm
```

替换成：

```python
flow_norm_ratio = (
    pred_flow_norm / gt_flow_norm.clamp_min(1e-8)
)
```

这样原来两条曲线变成一条，而且更容易理解：

```text
flow_norm_ratio = 1.0    幅值准确
flow_norm_ratio < 1.0    预测幅值偏小
flow_norm_ratio > 1.0    预测幅值偏大
```

推荐的训练核心指标：

```python
core_metrics = {
    "loss": total_loss,
    "flow/loss": flow_loss,
    "flow/epe_mean": flow_epe_mean,
    "flow/norm_ratio": flow_norm_ratio,
    "optim/lr": lr,
    "optim/grad_norm": grad_norm,
    "slot/expected_active_mean": expected_active_count.mean(),
    "slot/hard_active_mean": sampled_active_count.mean(),
    "slot/fallback_ratio": fallback_used.float().mean(),
    "slot/effective_branch_count": effective_branch_count,
    "slot/top1_usage": mean_decoder_slot_usage.max(),
}
```

# 二、只在每个 epoch 或验证时记录

这些指标有价值，但不需要每 100 step 都画曲线。

## 点流质量

保留：

```text
flow/epe_mean
flow/epe_p90
flow/epe_p95
flow/zero_flow_improvement
flow/norm_ratio
```

其中：

[
\text{zero_flow_improvement}
============================

1-\frac{EPE_{\mathrm{model}}}{EPE_{\mathrm{zero}}}
]

它能直接说明模型比“始终预测零运动”好多少。

例如：

```text
0.0  = 与零流一样
0.3  = 误差比零流降低 30%
0.7  = 误差比零流降低 70%
```

`P90` 指 90% 的点误差不超过该数值，比单纯平均值更能反映长尾误差。

## 训练稳定性

保留：

```text
optim/grad_norm_mean
optim/grad_clipped_fraction
```

`grad_clipped_fraction` 指一个 epoch 内发生梯度裁剪的 step 比例。

不要再记录每一步的：

```text
grad_clipped = 0 或 1
```

单步二值曲线基本没有分析价值。

## Slot 诊断

每个 epoch 保留：

```text
slot/assignment_entropy
slot/active_overlap
slot/max_probability_mean
```

但这三项属于研究诊断指标，不应放在主训练面板。

---

# 三、建议删除的指标

## 1. 删除所有逐 slot 的标量曲线

删除：

```text
decoder_slot_usage/slot_00
decoder_slot_usage/slot_01
...
decoder_slot_usage/slot_15
```

以及：

```text
fallback_winner/slot_00
fallback_winner/slot_01
...
fallback_winner/slot_15
```

这些一次就产生 32 条曲线，是 W&B 混乱的主要来源。最新日志中每一步都展开了所有 slot 使用率和 fallback winner。

替代方式：

* 保留 `top1_usage`；
* 保留 `effective_branch_count`；
* 每个 epoch 上传一次 slot usage histogram，中文是“slot 使用率直方图”；
* 或者使用 W&B Table 保存 16 个 slot 的使用率。

例如：

```python
wandb.log({
    "slot/usage_histogram": wandb.Histogram(
        mean_decoder_slot_usage.detach().cpu().numpy()
    )
})
```

这样不会产生 16 条长期曲线。

---

## 2. 删除 `decoder_slot_usage_entropy`

你已经有：

```python
effective_branch_count = exp(usage_entropy)
```

两者表达的是同一件事。

相比 entropy，中文是“熵，表示分配的不确定或均匀程度”，`effective_branch_count` 更直观：

```text
1.0  ≈ 实际只用一个分支
2.0  ≈ 实际使用两个分支
4.0  ≈ 实际使用四个分支
```

因此保留：

```text
effective_branch_count
```

删除：

```text
decoder_slot_usage_entropy
```

---

## 3. 删除 gate 的原始 log-alpha

删除：

```text
gate/log_alpha_min
gate/log_alpha_mean
gate/log_alpha_max
```

`log_alpha` 是 Hard Concrete gate 的内部参数，对最终行为不够直观。

你已经有更容易解释的：

```text
expected_active_mean
hard_active_mean
fallback_ratio
max_probability_mean
```

这些已经足够判断 gate 是否正常。

同时可以删除：

```text
gate_probability_mean
```

因为：

[
\text{expected active}
======================

\sum_k p_k
]

对于固定的 16 个 slot：

[
\text{gate probability mean}
============================

\frac{\text{expected active}}{16}
]

两者完全冗余。

---

## 4. 删除 active 数量的最大值和最小值

删除：

```text
sampled_active_min
sampled_active_max
```

它们很容易被极少数异常样本影响，而且每个 batch 都会剧烈跳动。

保留：

```text
sampled_active_mean
```

在验证时需要观察分布，可以额外记录：

```text
sampled_active_p90
```

不需要同时保留 min、max。

---

## 5. 删除 `pre_fallback_active_mean`

这个指标可以由下面两项大致解释：

```text
sampled_active_mean
fallback_ratio
```

当前真正关心的是：

* 最终实际用了多少 slot；
* 有多少样本必须触发 fallback。

因此：

```text
pre_fallback_active_mean
```

可以移到 debug 模式。

---

## 6. 删除固定常数

删除：

```text
grad_clip_threshold
valid_object_count
```

`grad_clip_threshold` 是固定配置，不需要每一步重复写入。

`valid_object_count` 在数据管道正常后也没有必要长期记录。它可以在训练开始时打印一次，或者只在发现 mask 问题时打开。

---

## 7. 删除重复的梯度指标

你们当前有：

```text
grad_norm
grad_clip_ratio
grad_clipped
grad_clip_threshold
```

日志中 `grad_clip_ratio` 经常与 `grad_norm / threshold` 基本等价，而 threshold 固定为 1。

建议只保留：

```text
step 级：grad_norm
epoch 级：grad_clipped_fraction
```

其余删除。

---

## 8. 删除旧的 xyz MAE/MSE 主指标

如果已经确定采用三维 EPE：

删除主面板中的：

```text
flow_mae
flow_mse
```

因为它们是逐坐标指标：

[
\frac{|e_x|+|e_y|+|e_z|}{3}
]

而你真正关心的是：

[
\sqrt{e_x^2+e_y^2+e_z^2}
]

可以暂时保留一个旧指标用于与历史实验对齐，但不要继续把它作为主要评价标准。

推荐：

```text
主指标：flow/epe_mean
辅助指标：flow/epe_p90
历史兼容：flow/xyz_mae，仅在 epoch 级记录
```

---

## 9. 当前 candidate flow 指标不建议放主面板

删除或仅 debug 记录：

```text
candidate_flow/dynamic_pairwise_cosine
candidate_flow/dynamic_slot_std
```

原因是这两个指标对全部 16 个候选 slot 统计，包括完全不被使用的 slot。

未激活 slot 的输出发生漂移，也会让：

```text
dynamic_pairwise_cosine 下降
dynamic_slot_std 上升
```

但这不代表真正被使用的 slot 形成了有效分工。

更合理的是以后改成：

```text
candidate_flow/usage_weighted_cosine
candidate_flow/active_slot_std
```

也就是只统计有效使用的 slot。

在修改之前，不建议保留在主面板。

---

## 10. Loss 分项如何处理

当前总损失中包含：

```text
flow loss
slot count loss
confidence loss
active overlap loss
```

代码中这些分项被加入总损失。

建议：

* `flow_loss`：每 100 step 保留；
* `slot_count_loss`：每个 epoch 保留；
* `slot_confidence_loss`：每个 epoch保留；
* `active_overlap_loss`：只有权重非零时保留。

如果：

```yaml
loss_active_overlap_weight: 0.0
```

则直接不记录：

```text
active_overlap_loss
```

因为它不会影响模型训练。

# 推荐的最终结构

## Train 主面板：11 项

```text
train/loss
train/flow_loss
train/flow_epe_mean
train/flow_norm_ratio
train/lr
train/grad_norm
train/slot_expected_active
train/slot_hard_active
train/slot_fallback_ratio
train/slot_effective_branch_count
train/slot_top1_usage
```

## Epoch 诊断面板：7 项

```text
epoch/flow_epe_p90
epoch/grad_clipped_fraction
epoch/slot_assignment_entropy
epoch/slot_active_overlap
epoch/slot_max_probability
epoch/slot_count_loss
epoch/slot_confidence_loss
```

## Validation 主面板

```text
val/mean_stride_epe
val/mean_stride_relative_epe
val/stride_1_epe
val/stride_5_epe
val/stride_10_epe
val/epe_p90
val/zero_flow_improvement
```

不要为 stride 1～10 的全部指标生成几十条独立曲线。完整 stride 数据建议上传成 W&B Table：

| stride | EPE mean | EPE P90 | GT norm | norm ratio | zero-flow improvement |
| -----: | -------: | ------: | ------: | ---------: | --------------------: |

用于选择最佳 checkpoint 的指标建议从：

```yaml
metric_for_best: val/mean_stride_flow_mse
```

改为：

```yaml
metric_for_best: val/mean_stride_relative_epe
```

`relative_epe` 指相对于真实运动幅值归一化后的三维误差。这样不会因为 stride 越长、真实位移天然越大，就让长 stride 完全支配模型选择。

最终可以将当前数十甚至上百条曲线压缩到：

[
\boxed{\text{约 11 条训练曲线 + 7 条验证核心指标}}
]

同时保留判断收敛、点流精度、梯度稳定性和 slot 塌缩所必需的信息。
