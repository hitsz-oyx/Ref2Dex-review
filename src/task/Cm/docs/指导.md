要实现的是：

> **最多 16 个候选 slot，但每个样本动态选择其中 (K_{\text{active}}\leq16) 个参与点流解码。**

这比直接把 `num_cm_tokens` 固定改小更合理，因为简单动作可以只用少量 slot，复杂的双手或长时间跨度动作可以使用更多 slot。

不过不建议直接写成：

```python
cm_tokens = cm_tokens * mask
```

然后仍然对 16 个 slot 做 softmax。更合适的是增加一个**样本级 slot gate（门控器）**，在点流解码器的 slot 归一化阶段真正屏蔽不需要的 slot。

---

# 一、推荐的整体结构

```text
手部点特征
    │
    ▼
Slot Attention
生成最多 16 个 Cm slot
    │
    ├───────────────┐
    │               │
    ▼               ▼
slot gate head     点流 edge decoder
预测每个 slot      每个物体点 × 每个 slot
是否需要            预测 logit 和 flow
    │               │
    └──── mask ─────┘
            │
            ▼
    masked normalization
            │
            ▼
       物体点流预测
```

可以写成：

[
C_m={c_1,\ldots,c_{16}}
]

门控器为每个 slot 输出：

[
p_k=\sigma(f_{\text{gate}}(c_k))
]

其中：

* (p_k)：第 (k) 个 slot 被启用的概率；
* (g_k\in{0,1})：最终二值 mask；
* (K_{\text{active}}=\sum_k g_k)。

损失变成：

[
\mathcal L
==========

\mathcal L_{\text{flow}}
+
\lambda_{\text{slot}}
\mathbb E[K_{\text{active}}]
]

第一项保证点流准确，第二项惩罚使用过多 slot。简单样本中，多开启一个 slot 带来的点流收益不够抵消惩罚，它就会关闭；复杂样本中，多使用 slot 能显著降低点流误差，模型就会保留更多 slot。

---

# 二、mask 应该放在哪里

你当前解码器对每个物体点和每个 slot 计算：

```python
edge_output = self.flow_edge(edge_input)

edge_weight = torch.softmax(
    edge_output[..., 0],
    dim=2,
)

pred_obj_flow = (
    edge_weight.unsqueeze(-1)
    * edge_output[..., 1:]
).sum(dim=2)
```

也就是：

[
\hat F_i
========

\sum_{k=1}^{16}
q_{ik}F_{ik}
]

其中 (q_{ik}) 是第 (i) 个物体点对第 (k) 个 slot 的权重。当前所有 16 个 slot 都参与 softmax 和点流加权。

应该改成：

[
\widetilde q_{ik}
=================

\frac{
g_k\exp(l_{ik})
}{
\sum_j g_j\exp(l_{ij})
}
]

其中 (g_k=0) 的 slot 权重严格为零。

代码不要简单地：

```python
edge_weight = torch.softmax(logits, dim=2)
edge_weight = edge_weight * slot_mask[:, None, :]
```

因为这样 mask 后权重之和不再等于 1。

应当在归一化之前加入 gate：

```python
edge_logits = edge_output[..., 0]        # [B, O, K]
edge_flow = edge_output[..., 1:]         # [B, O, K, 3]

# slot_gate: [B, K]，训练时可为 [0,1] 连续值，推理时为 0/1
gate = slot_gate[:, None, :]             # [B, 1, K]

# 数值稳定
shifted_logits = edge_logits - edge_logits.max(
    dim=2,
    keepdim=True,
).values

unnormalized = torch.exp(shifted_logits) * gate

edge_weight = unnormalized / unnormalized.sum(
    dim=2,
    keepdim=True,
).clamp_min(1e-8)

pred_obj_flow_internal = (
    edge_weight.unsqueeze(-1) * edge_flow
).sum(dim=2)
```

这样：

* 被关闭的 slot 不参与点流解码；
* 剩余 slot 权重重新归一化；
* gate 能收到点流损失的梯度。

---

# 三、最好增加一个 zero-flow 分支

如果 16 个 slot 全部关闭，上面的分母会变成零。

一种做法是强制至少启用一个 slot。但对你的任务，更合理的是添加一个不计入 16 个 Cm slot 的：

> **null expert：零作用分支，固定预测零点流。**

结构变成：

```text
null expert：始终存在，flow = 0
dynamic Cm slots：最多 16 个，可全部关闭
```

数学上：

[
\hat F_i
========

q_{i,0}\cdot 0+
\sum_{k=1}^{16}q_{ik}F_{ik}
]

其中第 0 个分支不是动作 slot，只表示：

```text
当前动作没有使这个物体点产生明显运动
```

这与你的数据非常匹配，因为即使手靠近物体，物体也可能保持静止。增加 null 分支后：

* 简单静止样本可以使用 0 个动态 slot；
* 不需要强制浪费一个 slot 表示零流；
* 不会出现所有 gate 关闭导致除零；
* 不影响“最多 16 个动作 slot”的定义。

代码可以这样组织：

```python
edge_logits = edge_output[..., 0]       # [B, O, 16]
edge_flow = edge_output[..., 1:]        # [B, O, 16, 3]

# 可学习的 null logit，也可以先直接设成 0
null_logits = self.null_logit(obj_context)  # [B, O, 1]
null_flow = torch.zeros_like(edge_flow[:, :, :1])

all_logits = torch.cat(
    [null_logits, edge_logits],
    dim=2,
)

all_flow = torch.cat(
    [null_flow, edge_flow],
    dim=2,
)

all_gate = torch.cat(
    [
        torch.ones_like(slot_gate[:, :1]),
        slot_gate,
    ],
    dim=1,
)

shifted = all_logits - all_logits.max(
    dim=2,
    keepdim=True,
).values

score = torch.exp(shifted) * all_gate[:, None, :]

weight = score / score.sum(
    dim=2,
    keepdim=True,
).clamp_min(1e-8)

pred_obj_flow_internal = (
    weight.unsqueeze(-1) * all_flow
).sum(dim=2)
```

建议第一版使用这个方案。

---

# 四、slot mask 怎么预测

在 `SlotAttention` 输出之后加入一个共享 MLP：

```python
self.slot_gate_head = nn.Sequential(
    nn.LayerNorm(cm_dim),
    nn.Linear(cm_dim, cm_dim // 2),
    nn.GELU(),
    nn.Linear(cm_dim // 2, 1),
)
```

然后：

```python
slot_gate_logits = self.slot_gate_head(
    cm_tokens
).squeeze(-1)  # [B, 16]
```

这里同一个 `slot_gate_head` 作用于全部 slot，而不是为 16 个 slot 分别设计不同网络。这样可以保留 Slot Attention 的**置换对称性**：slot 没有固定的“第一个是拇指、第二个是食指”语义，而是通过竞争动态绑定输入。原始 Slot Attention 本身就是通过竞争式注意力产生可交换 slot。([arXiv][1])

初始版本只输入 `cm_tokens` 就够了。进一步可以加入：

```python
slot_hand_flow = torch.einsum(
    "bkh,bhd->bkd",
    cm_slot_weights,
    hand_flow_internal,
)

slot_assignment_mass = cm_assignment.mean(
    dim=-1,
    keepdim=True,
)

gate_input = torch.cat(
    [
        cm_tokens,
        slot_hand_flow,
        slot_assignment_mass,
    ],
    dim=-1,
)
```

这样 gate 能直接看到：

* slot 表征了什么；
* 对应手部区域移动了多少；
* 有多少手点归属于该 slot。

不过你的 `cm_tokens` 已经编码了 `hand_flow` 和接触先验，因此建议先从仅使用 `cm_tokens` 的最简版本开始。

---

# 五、不要直接用普通 sigmoid + 0.5 阈值训练

直接写：

```python
mask = (torch.sigmoid(logits) > 0.5).float()
```

会导致阈值操作不可导，gate 学不到东西。

推荐使用 **Hard-Concrete gate**，中文可以理解为：

> 训练时使用连续、可求导的随机门；训练完成后能产生精确的 0/1 门控。

Hard-Concrete 方法可以对“使用了几个门”进行可微的 (L_0) 正则化，正适合你这种动态 slot 数量选择。([arXiv][2])

核心接口可以写成：

```python
slot_gate, slot_gate_prob = self.slot_gate_sampler(
    slot_gate_logits
)
```

其中：

* `slot_gate`：实际进入解码器的 gate；
* `slot_gate_prob`：用于计算预期 slot 数；
* 训练时 `slot_gate` 在 `[0,1]` 内并能出现精确 0；
* 推理时根据阈值得到二值 mask。

预期启用数量：

```python
expected_active_slots = slot_gate_prob.sum(dim=-1)
```

稀疏损失：

```python
slot_count_loss = (
    expected_active_slots / self.num_cm_tokens
).mean()
```

总损失：

```python
total_loss = (
    self.cfg.meta.loss_flow_weight * flow_smooth_l1
    + self.cfg.meta.loss_slot_count_weight * slot_count_loss
)
```

你当前 Runner 的总损失只有点流 Smooth-L1，slot entropy、overlap 和 decoder usage 都只是记录指标，没有参与反向传播。因此必须显式增加 `slot_count_loss`，否则模型没有动力关闭 slot。

---

# 六、稀疏系数不能一开始就开得很大

如果从随机初始化开始就强烈惩罚 slot 数，模型很容易在还没有学会 slot 分工之前直接退化为：

```text
所有样本只使用 0～1 个 slot
```
---

# 八、保持固定形状，不要保存成变长数组

虽然有效 slot 数可变，但导出数据仍建议保存：

```python
cm_tokens       # [B, 16, D]
cm_slot_mask    # [B, 16]
cm_gate_prob    # [B, 16]
num_active      # [B]
```

而不是保存成：

```text
样本 A：[3,D]
样本 B：[7,D]
样本 C：[1,D]
```

固定长度加 mask 的优势是：

* Batch 组织不需要 padding；
* checkpoint 和模型接口稳定；
* 可视化方便；
* 后续 (C_p) 投影可以直接使用 mask；
* 仍然可以统计每个样本实际用了几个 slot。

导出时可以额外提供：

```python
cm_tokens_masked = (
    cm_tokens * cm_slot_mask.unsqueeze(-1)
)
```

但建议同时保留未乘 mask 的原始 slot，方便诊断 gate 是否关错了 slot。

# 九、需要新增的监控指标

至少记录：

```python
metrics = {
    "active_slots/mean": hard_mask.sum(-1).float().mean(),
    "active_slots/min": hard_mask.sum(-1).float().min(),
    "active_slots/max": hard_mask.sum(-1).float().max(),
    "slot_gate/prob_mean": gate_prob.mean(),
    "slot_gate/null_usage": null_weight.mean(),
}
```

并按 stride 分别统计：

```text
stride_1/active_slots_mean
stride_2/active_slots_mean
...
stride_10/active_slots_mean
```

最关键的图是：

[
\text{flow MSE}
\quad\text{vs.}\quad
K_{\text{active}}
]

需要检查以下退化：

1. 所有样本始终使用 16 个 slot：稀疏损失太弱；
2. 所有样本始终使用 0 或 1 个 slot：稀疏损失太强；
3. gate 关闭了 slot，但 decoder 之前本来也不使用它：正常的无损裁剪；
4. 长 stride 和短 stride 使用完全相同数量：可能需要显式时间条件；
5. 相邻帧 mask 高频跳变：需要时序一致性约束或推理时迟滞阈值。

# 十、第一版最合适的实现范围

建议第一版只完成：

```text
1. Slot Attention 仍然生成 16 个候选 slot
2. 每个样本预测 [16] gate
3. 增加一个固定零流 null 分支
4. gate 只作用于点流 decoder
5. 使用 Hard-Concrete + expected L0 slot count loss
6. 导出固定 [16,D] tokens + [16] mask
```

暂时不要把 gate 加进 Slot Attention 内部。因为当前 Slot Attention 在 16 个 slot 之间进行竞争，如果在每轮迭代内部动态关闭 slot，会改变 `cm_assignment` 的归一化过程，训练稳定性明显更难控制。

第一版虽然仍然计算全部 16 个 slot，但：

* 下游表征只使用少量 active slot；
* 点流解码只依赖 active slot；
* 可以验证动态 slot 数是否真的有效；
* 后续再考虑将 gate 加入 Slot Attention 内部以节省计算。

最终结构可以概括为：

[
\boxed{
16\text{ 个候选 }C_m
\rightarrow
\text{sample-wise Hard-Concrete gate}
\rightarrow
0\sim16\text{ 个有效 }C_m
\rightarrow
\text{masked point-flow decoder}
}
]

这是目前与你的模型改动量、训练稳定性和后续数据组织最平衡的方案。

[1]: https://arxiv.org/abs/2006.15055?utm_source=chatgpt.com "Object-Centric Learning with Slot Attention"
[2]: https://arxiv.org/abs/1712.01312?utm_source=chatgpt.com "Learning Sparse Neural Networks through $L_0$ Regularization"
可以不加时间条件。没有预训练 checkpoint 也不影响这个方向，但建议采用**同一次训练中的分阶段启用门控**，否则模型一开始既要学习 slot 分工，又要决定关闭哪些 slot，容易全部关闭或退化成单 slot。

先给结论：

[
\boxed{
\mathcal L
==========

\mathcal L_{\mathrm{flow}}
+
\lambda_{L_0}\mathcal L_{\mathrm{slot\ count}}
+
\lambda_{\mathrm{overlap}}\mathcal L_{\mathrm{active\ overlap}}
}
]

第一版建议：

* `flow loss`：参与反传，主损失；
* `Hard-Concrete slot count loss`：参与反传，负责减少 slot；
* `slot_weight_overlap`：可选，小权重，并且只计算 active slot；
* `slot_assignment_entropy`：先只记录；
* `decoder_slot_usage_entropy`：只记录，不建议反传。

# 1. `slot_assignment_entropy` 是什么

当前 Slot Attention 中，对每个手点 (h)，会计算它属于各个 slot 的概率：

[
p_{k,h}
=======

P(\text{手点 }h\text{ 属于 slot }k)
]

代码中的：

```python
slot_assignment = torch.softmax(logits, dim=1)
```

`dim=1` 是 slot 维度，所以对于每个手点：

[
\sum_{k=1}^{16}p_{k,h}=1
]

当前指标是：

[
H_{\mathrm{assign}}
===================

-\frac{1}{H}
\sum_{h=1}^{H}
\sum_{k=1}^{K}
p_{k,h}\log p_{k,h}
]

对应代码：

```python
cm_assignment = prediction["cm_assignment"].clamp_min(1e-8)

slot_assignment_entropy = -(
    cm_assignment * cm_assignment.log()
).sum(dim=1).mean()
```

当前代码确实按“每个手点在 slot 间的分配熵”计算。

## 数值代表什么

对于 16 个 slot：

[
0\le H_{\mathrm{assign}}\le\log 16\approx2.77
]

### 熵低

例如：

```text
手点 h:
[0.99, 0.01, 0, 0, ...]
```

说明这个手点明确属于某个 slot。

### 熵高

例如：

```text
手点 h:
[0.0625, 0.0625, ..., 0.0625]
```

说明这个手点平均分给全部 16 个 slot，分工很模糊。

## 是否适合反传

可以最小化它：

[
\mathcal L_{\mathrm{entropy}}
=============================

H_{\mathrm{assign}}
]

从而让分配更明确。但是它有一个严重问题：

> **低熵不等于合理分工。**

模型可能让所有 1538 个手点都属于同一个 slot：

```text
所有手点 → slot 0
其他 15 个 slot → 没有点
```

这种情况下熵同样很低，但发生了 `slot collapse`，即 **slot 塌缩：多个 slot 失去作用，只剩一个 slot 工作**。

因此：

* 最小化 assignment entropy：促进清晰分配，也可能促进塌缩；
* 最大化 assignment entropy：让每个点分给多个 slot，通常不是你想要的；
* 单独使用它不安全。

### 对你的建议

第一版只记录，不加入损失。

后续若发现：

```text
每个手点同时模糊地分给很多 active slot
```

再对**有效 slot 重新归一化后**加很小的熵最小化约束。

---

# 2. `slot_weight_overlap` 是什么

`cm_slot_weights[k,h]` 表示：

> slot (k) 聚合第 (h) 个手点时所使用的权重。

与 `slot_assignment` 的区别是：

* `slot_assignment[:, k, h]`：从手点角度看，它属于哪个 slot；
* `slot_weights[:, k, h]`：从 slot 角度看，它主要聚合哪些手点。

在当前实现中，每个 slot 的权重在所有手点上归一化：

[
\sum_h w_{k,h}=1
]

当前代码将每个 slot 的权重向量做归一化，然后计算任意两个 slot 的余弦相似度：

[
S_{k,l}
=======

\frac{
\mathbf w_k^\top\mathbf w_l
}{
|\mathbf w_k|_2|\mathbf w_l|_2
}
]

最后平均所有非对角项：

[
\mathcal L_{\mathrm{overlap}}
=============================

\frac{1}{K(K-1)}
\sum_{k\neq l}S_{k,l}
]

当前代码就是这样计算不同 slot 聚合区域的重叠程度。

## 数值代表什么

### overlap 高

```text
slot 0 主要看拇指
slot 1 也主要看拇指
slot 2 还是主要看拇指
```

多个 slot 在重复编码相同手部区域。

### overlap 低

```text
slot 0 主要看拇指
slot 1 主要看食指
slot 2 主要看手掌
```

slot 的分工更不同。

## 是否适合反传

这个指标比 assignment entropy 更适合作为辅助损失：

[
\mathcal L_{\mathrm{overlap}}
=============================

\operatorname{mean}_{k\neq l}
\operatorname{cosine}(\mathbf w_k,\mathbf w_l)
]

最小化它可以减少 slot 重复。

但你的模型存在动态 gate 后，不能继续对全部 16 个 slot 计算。否则：

* 已经关闭的 slot 也被强迫寻找不同区域；
* 无效 slot 仍然影响 Slot Attention；
* 模型为了降低 overlap，可能维持许多无用的不同 slot。

应该只计算两个都开启的 slot：

[
\mathcal L_{\mathrm{active\ overlap}}
=====================================

\frac{
\sum_{k\neq l}g_kg_lS_{k,l}
}{
\sum_{k\neq l}g_kg_l+\epsilon
}
]

代码示意：

```python
weights = F.normalize(
    cm_slot_weights,
    dim=-1,
    eps=1e-8,
)  # [B, K, H]

similarity = (
    weights @ weights.transpose(1, 2)
)  # [B, K, K]

pair_gate = (
    slot_gate.unsqueeze(2)
    * slot_gate.unsqueeze(1)
)

eye = torch.eye(
    similarity.shape[1],
    device=similarity.device,
    dtype=torch.bool,
).unsqueeze(0)

pair_gate = pair_gate.masked_fill(eye, 0.0)

active_overlap_loss = (
    similarity * pair_gate
).sum() / pair_gate.sum().clamp_min(1.0)
```

### 对你的建议

适合参与反传，但满足三个条件：

1. 只约束 active slot；
2. 权重很小；
3. 在 gate warm-up 后再启用。

它是辅助约束，不能压过 point-flow loss。

---

# 3. `decoder_slot_usage` 是什么

你的解码器对每个物体点 (i) 和每个 slot (k) 计算：

```python
edge_output[..., 0]
```

然后在 slot 维度做 softmax：

[
q_{i,k}
=======

\frac{\exp(l_{i,k})}
{\sum_j\exp(l_{i,j})}
]

物体点流是：

[
\hat{\mathbf F}_i
=================

\sum_kq_{i,k}\mathbf F_{i,k}
]

因此，(q_{i,k}) 表示：

> 第 (i) 个物体点在预测点流时，对第 (k) 个 slot 的依赖程度。

当前 `decoder_slot_usage` 是对所有有效物体点取平均：

[
u_k
===

\frac{1}{N_{\mathrm{valid}}}
\sum_{i\in\mathrm{valid}}q_{i,k}
]

所以：

```text
u = [0.8, 0.1, 0.05, 0.05, 0, ...]
```

表示当前样本的物体点流解码主要使用 slot 0。

当前 Runner 又在 batch 上平均：

```python
mean_decoder_slot_usage = decoder_slot_usage.mean(dim=0)
```

然后计算熵：

[
H_{\mathrm{decoder}}
====================

-\sum_ku_k\log u_k
]

当前指标因此更准确地说是：

> 一个 batch 内，点流解码器总体上把注意力分配给多少个 slot。

## 熵高和熵低代表什么

### 熵低

```text
usage = [0.95, 0.01, 0.01, ...]
```

解码器主要依赖一个 slot。

### 熵高

```text
usage = [0.0625, ..., 0.0625]
```

解码器平均使用很多 slot。

## 是否适合反传

### 不建议最小化

最小化 decoder usage entropy 会直接鼓励：

```text
所有点流都由一个 slot 解释
```

这会促进 decoder collapse。

### 也不建议最大化

最大化它会鼓励：

```text
所有 16 个 slot 都被平均使用
```

这与你“尽量少用 slot”的目标直接冲突。

而且当前指标先对 batch 求平均，可能出现：

```text
样本 A 只使用 slot 0
样本 B 只使用 slot 1
样本 C 只使用 slot 2
```

batch 平均后熵仍然很高，但单个样本其实只使用一个 slot。因此它不适合作为单样本 slot 数量约束。

### 对你的建议

只作为诊断指标，不反传。

加入 gate 后，应把它改为使用 masked decoder weight，并记录：

```text
decoder_slot_usage/slot_XX
decoder_active_usage_entropy
decoder_null_usage
```

# 4. 三个指标的最终处理建议

| 指标                           | 代表什么                | 适合反传吗                  |
| ---------------------------- | ------------------- | ---------------------- |
| `slot_assignment_entropy`    | 每个手点属于哪个 slot 是否明确  | 第一版不加                  |
| `slot_weight_overlap`        | 不同 slot 是否聚合了重复手部区域 | 可选，小权重，只约束 active slot |
| `decoder_slot_usage_entropy` | 解码器总体使用 slot 是否集中   | 不加，只监控                 |
| `decoder_slot_usage_max`     | 最被依赖的 slot 占比       | 不加，只监控                 |

你的第一版损失建议是：

[
\boxed{
\mathcal L
==========

\mathcal L_{\mathrm{flow}}
+
\lambda_{L_0}
\frac{1}{B}
\sum_b
\mathbb E[K_{\mathrm{active}}^{(b)}]
+
\lambda_{\mathrm{overlap}}
\mathcal L_{\mathrm{active\ overlap}}
}
]

不要一次性加入所有指标。否则很难判断训练失败来自哪个约束。

# 5. 普通 sigmoid gate 为什么不够好

最直接的 gate 是：

[
a_k=\sigma(r_k)
]

然后：

```python
masked_score = torch.exp(edge_logits) * gate
```

但是 sigmoid 永远满足：

[
0<a_k<1
]

它不会真正得到 0。

你可能想在训练时惩罚：

[
\sum_ka_k
]

但你的解码器后面还会重新归一化：

[
q_{i,k}
=======

\frac{a_k\exp(l_{i,k})}
{\sum_ja_j\exp(l_{i,j})}
]

如果模型把所有 gate 同时从 1 缩小到 0.01：

[
\frac{0.01e^{l_{i,k}}}
{\sum_j0.01e^{l_{i,j}}}
=======================

\frac{e^{l_{i,k}}}
{\sum_je^{l_{i,j}}}
]

解码结果完全不变，但：

[
\sum_ka_k
]

变小了 100 倍。

因此模型可以“作弊”：

```text
所有 16 个 gate 都变得很小，
但经过重新归一化后仍然使用全部 16 个 slot。
```

这正是普通连续 sigmoid gate 在你这个 masked-normalization 解码器中的主要问题。

# 6. Hard-Concrete gate 是什么

Hard-Concrete 可以理解为：

> **训练时可求导，但又能真正取到 0 或 1 的随机开关。**

普通二值 mask：

[
g_k=
\begin{cases}
1,&r_k>0\
0,&r_k\leq0
\end{cases}
]

不能直接训练，因为阶跃函数几乎处处梯度为零。

Hard-Concrete 通过三个步骤解决这个问题。

## 第一步：生成可微随机变量

采样：

[
u\sim\operatorname{Uniform}(0,1)
]

计算：

[
s
=

\sigma\left(
\frac{
\log u-\log(1-u)+\log\alpha
}{
\beta
}
\right)
]

其中：

* (\log\alpha)：模型预测的 gate logit；
* (\beta)：温度，控制 gate 是平滑还是接近离散；
* (s\in(0,1))。

因为随机性被写成关于 (u) 和 (\log\alpha) 的可微函数，所以梯度可以传给 gate head。这叫**重参数化**，即把随机采样改写成可微的确定性计算加外部噪声。

## 第二步：把范围拉伸到超过 ([0,1])

[
\bar s
======

s(\zeta-\gamma)+\gamma
]

通常选择：

[
\gamma<0,\qquad\zeta>1
]

例如：

```python
gamma = -0.1
zeta = 1.1
```

于是 (\bar s) 的范围可能小于 0，也可能大于 1。

## 第三步：裁剪到 ([0,1])

[
g
=

\min(1,\max(0,\bar s))
]

这样 gate 会具有三种情况：

```text
g = 0       完全关闭
0 < g < 1   训练阶段的软门
g = 1       完全打开
```

因为拉伸后有一部分概率落到 0 以下或 1 以上，再经过裁剪，就会产生**精确的 0 和 1**。

Hard-Concrete 正是为可微 (L_0) 稀疏化提出的：它通过随机非负 gate 决定哪些结构为零，并且能够计算“gate 非零”的可微期望。([arXiv][1])

---

# 7. 为什么叫 (L_0) gate

(L_0) 在这里不是普通范数，而是计算非零项数量：

[
|\mathbf g|_0
=============

\sum_k\mathbb 1[g_k\neq0]
]

对你的模型：

[
K_{\mathrm{active}}
===================

\sum_{k=1}^{16}\mathbb 1[g_k\neq0]
]

直接对这个整数求梯度不可能。

Hard-Concrete 可以解析计算每个 gate 非零的概率：

[
P(g_k>0)
========

\sigma\left(
\log\alpha_k
------------

\beta\log\frac{-\gamma}{\zeta}
\right)
]

于是预期使用 slot 数量为：

[
\mathbb E[K_{\mathrm{active}}]
==============================

\sum_{k=1}^{16}P(g_k>0)
]

这个量对 (\log\alpha_k) 可导，所以可以直接作为损失：

[
\mathcal L_{\mathrm{slot\ count}}
=================================

\frac{1}{BK}
\sum_{b=1}^{B}
\sum_{k=1}^{K}
P(g_{b,k}>0)
]

这里惩罚的是：

> gate 非零的概率。

而不是 gate 数值有多大，因此模型不能通过把所有 gate 同时缩成 0.01 来作弊。

# 8. 在你的模型里怎么使用

原始 Hard-Concrete 常用于给网络权重设置 gate。你的情况可以改成**样本条件门控**：

```text
每个样本的 cm_token
        ↓
slot_gate_head
        ↓
该样本对应的 16 个 log_alpha
        ↓
Hard-Concrete
        ↓
该样本对应的 16 个 gate
```

这是你架构上的条件化扩展：

```python
self.slot_gate_head = nn.Sequential(
    nn.LayerNorm(cm_dim),
    nn.Linear(cm_dim, cm_dim // 2),
    nn.GELU(),
    nn.Linear(cm_dim // 2, 1),
)
```

得到：

```python
log_alpha = self.slot_gate_head(
    cm_tokens
).squeeze(-1)  # [B, 16]
```

Hard-Concrete 实现可以写成：

```python
import math

import torch
from torch import nn


class HardConcreteGate(nn.Module):
    def __init__(
        self,
        temperature: float = 2.0 / 3.0,
        gamma: float = -0.1,
        zeta: float = 1.1,
        eps: float = 1e-6,
    ) -> None:
        super().__init__()

        if temperature <= 0:
            raise ValueError("temperature must be positive")
        if not gamma < 0:
            raise ValueError("gamma must be negative")
        if not zeta > 1:
            raise ValueError("zeta must be greater than 1")

        self.temperature = float(temperature)
        self.gamma = float(gamma)
        self.zeta = float(zeta)
        self.eps = float(eps)

    def nonzero_probability(
        self,
        log_alpha: torch.Tensor,
    ) -> torch.Tensor:
        offset = self.temperature * math.log(
            -self.gamma / self.zeta
        )
        return torch.sigmoid(log_alpha - offset)

    def forward(
        self,
        log_alpha: torch.Tensor,
    ) -> tuple[torch.Tensor, torch.Tensor]:
        nonzero_prob = self.nonzero_probability(log_alpha)

        if self.training:
            uniform = torch.rand_like(log_alpha).clamp(
                self.eps,
                1.0 - self.eps,
            )

            logistic_noise = (
                torch.log(uniform)
                - torch.log1p(-uniform)
            )

            soft_gate = torch.sigmoid(
                (log_alpha + logistic_noise)
                / self.temperature
            )
        else:
            soft_gate = torch.sigmoid(log_alpha)

        stretched_gate = (
            soft_gate * (self.zeta - self.gamma)
            + self.gamma
        )

        gate = stretched_gate.clamp(0.0, 1.0)

        return gate, nonzero_prob
```

使用：

```python
slot_gate, slot_nonzero_prob = self.hard_concrete(
    slot_gate_logits
)

expected_active_slots = slot_nonzero_prob.sum(dim=-1)

slot_count_loss = (
    expected_active_slots
    / self.num_cm_tokens
).mean()
```

# 11. 最关键的监控指标

加入 gate 后记录：

```text
slot/expected_active_mean
slot/hard_active_mean
slot/hard_active_min
slot/hard_active_max
slot/gate_probability_mean
slot/active_overlap
slot/assignment_entropy
decoder/null_usage
decoder/active_usage_entropy
```

其中：

```python
hard_mask = (
    prediction["slot_nonzero_prob"] > 0.5
)

hard_active_count = hard_mask.sum(dim=-1)
```

最终主要观察两条曲线：

[
\text{平均 active slot 数}
]

和：

[
\text{point-flow error}
]

你的目标不是让 slot 越少越好，而是找到：

> 再减少一个 slot 后，点流误差开始明显恶化的位置。

因此，当前最合适的训练策略是：

[
\boxed{
\text{Flow Loss}
+
\text{Hard-Concrete }L_0\text{ 门控}
+
\text{小权重 active-slot overlap}
}
]

assignment entropy 和 decoder usage 暂时只用于判断是否发生模糊分配、slot 重复或 decoder 塌缩。

[1]: https://arxiv.org/abs/1712.01312?utm_source=chatgpt.com "Learning Sparse Neural Networks through $L_0$ Regularization"
可以，这个思路本身是成立的。更准确地说，建议把它做成：

> **16 个动态手部 slot + 1 个固定零流 expert（零流专家分支）**，共同参与物体点流的混合解码。

但不要把零流分支真的塞进 Slot Attention，让它和 16 个手部 slot 竞争手点。应当在 Slot Attention 之后、点流解码阶段追加。

## 推荐结构

Slot Attention 仍然输出：

[
C_m={c_1,\ldots,c_{16}}
]

每个动态 slot 有一个样本级 gate：

[
g_k\in[0,1]
]

对于第 (i) 个物体点，每个动态 slot 输出：

* 解码权重 logit：(l_{i,k})
* 候选点流：(\mathbf f_{i,k})

另外增加零流分支：

[
\mathbf f_{i,0}=\mathbf 0
]

零流分支也有一个解码权重 logit：

[
l_{i,0}
]

然后统一归一化：

[
Z_i
===

\exp(l_{i,0})
+
\sum_{k=1}^{16}
g_k\exp(l_{i,k})
]

[
q_{i,0}
=======

\frac{\exp(l_{i,0})}{Z_i}
]

[
q_{i,k}
=======

\frac{g_k\exp(l_{i,k})}{Z_i}
]

最终点流：

[
\hat{\mathbf f}_i
=================

q_{i,0}\mathbf 0
+
\sum_{k=1}^{16}q_{i,k}\mathbf f_{i,k}
]

因为第一项为零，也可以写成：

[
\hat{\mathbf f}_i
=================

\sum_{k=1}^{16}q_{i,k}\mathbf f_{i,k}
]

但零流分支仍然通过分母控制动态点流的整体幅值。

这正符合你的想法：

* 其他 slot gate 都很小时，零流分支自动占主要权重；
* 某些 slot 有用时，零流与这些 slot 一起混合；
* 16 个动态 slot 可以全部关闭；
* 不会发生 masked softmax 分母为零。

---

## 不是“拼接点流”，而是加权混合

这里不要将：

```python
zero_flow
slot_1_flow
slot_2_flow
```

直接在特征维度拼接后，再额外经过一个网络解码。那样会让 slot 的独立贡献难以解释。

更合适的是：

```python
pred_flow = (
    decoder_weight.unsqueeze(-1)
    * candidate_flow
).sum(dim=slot_dim)
```

即每个分支给出一个候选点流，再通过权重加权求和。你当前解码器本来就是这种 mixture（混合专家）形式：每个物体点对各 slot 的结果做 softmax 加权。

---

## 代码怎么改

你当前大致是：

```python
edge_output = self.flow_edge(edge_input)
edge_logits = edge_output[..., 0]       # [B, O, K]
slot_flow = edge_output[..., 1:]        # [B, O, K, 3]

edge_weight = torch.softmax(edge_logits, dim=2)

pred_flow = (
    edge_weight.unsqueeze(-1) * slot_flow
).sum(dim=2)
```

建议增加：

```python

    nn.Linear(cm_dim, cm_dim // 2),
    nn.GELU(),
    nn.Linear(cm_dim // 2, 1),
)
```

使用物体当前特征预测每个物体点的零流 logit：

```python
null_logits = self.null_logit_head(
    obj_context
)  # [B, O, 1]
```

动态 slot gate：

```python
slot_gate = prediction_or_hard_concrete_gate  # [B, K]
```

统一计算：

```python
dynamic_logits = edge_output[..., 0]     # [B, O, K]
dynamic_flow = edge_output[..., 1:]      # [B, O, K, 3]

# 比直接 log(gate) 更稳定，避免 log(0)
masked_dynamic_score = (
    torch.exp(
        dynamic_logits
        - dynamic_logits.max(dim=2, keepdim=True).values
    )
    * slot_gate[:, None, :]
)

null_score = torch.exp(
    null_logits
    - dynamic_logits.max(dim=2, keepdim=True).values
)

denominator = (
    null_score
    + masked_dynamic_score.sum(dim=2, keepdim=True)
).clamp_min(1e-8)

null_weight = null_score / denominator

dynamic_weight = (
    masked_dynamic_score / denominator
)

pred_obj_flow_internal = (
    dynamic_weight.unsqueeze(-1)
    * dynamic_flow
).sum(dim=2)
```

不过上面用动态 logit 的最大值作为共同平移还不够严谨，因为 null logit 也可能更大。更稳妥的写法是先拼接 logit，并对关闭的动态 slot 使用极小值：

```python
dynamic_logits = edge_output[..., 0]       # [B, O, K]
dynamic_flow = edge_output[..., 1:]         # [B, O, K, 3]
null_logits = self.null_logit_head(obj_context)  # [B, O, 1]

log_gate = torch.log(
    slot_gate[:, None, :].clamp_min(1e-8)
)

gated_dynamic_logits = dynamic_logits + log_gate

all_logits = torch.cat(
    [null_logits, gated_dynamic_logits],
    dim=2,
)

all_weight = torch.softmax(all_logits, dim=2)

null_weight = all_weight[..., :1]
dynamic_weight = all_weight[..., 1:]

pred_obj_flow_internal = (
    dynamic_weight.unsqueeze(-1)
    * dynamic_flow
).sum(dim=2)
```

推理时如果 gate 是严格的 0/1，最好直接 mask：

```python
gated_dynamic_logits = dynamic_logits.masked_fill(
    ~slot_mask[:, None, :],
    torch.finfo(dynamic_logits.dtype).min,
)
```

# 主要风险：零流分支可能成为捷径

这个结构最大的风险不是计算问题，而是：

> 模型可能过度使用零流分支，尤其是训练早期、短预测跨度或数据中静止样本很多时。

因为输出零流非常容易，而动态 slot 解码准确运动更难。

可能出现：

```text
GT 点流平均 2 cm
模型预测 0.2 cm
null weight 很高
训练损失下降缓慢但稳定
```

也就是零流分支把预测幅值压小，模型形成保守解。

## 为什么 flow loss 不一定立即阻止它

理论上，真实运动样本上的点流误差会迫使模型降低 null 权重。但从零训练时：

* 动态 slot 一开始预测很差；
* 零流反而可能比随机点流更接近 GT；
* optimizer 会先提高 null 权重；
* 动态分支获得的有效梯度进一步减少；
* 形成正反馈。

因此需要控制训练过程。

---

# 从零训练时的推荐策略

你没有预训练 checkpoint，可以在同一次训练中分阶段进行。

## 第一阶段：暂时降低 null 的竞争力

前 5%～10% 训练步，可以：

```python
null_logits = torch.full_like(
    null_logits,
    -3.0,
)
```

或冻结 `null_logit_head`，使初始：

[
q_{\text{null}}
]

较小，但不是严格为零。

让动态 slot 先学会基本点流。

## 第二阶段：开放 null head

随后恢复可学习：

```python
null_logits = self.null_logit_head(obj_context)
```

并逐渐启用 slot 数量惩罚。

这样模型先学会“怎么用 slot”，再学习“哪些情况下不用 slot”。

---

# 零流分支是否需要额外监督

第一版不一定需要。

只用点流损失就能训练：

[
\mathcal L_{\text{flow}}
]

因为：

* GT 流接近零时，增加 null 权重有利；
* GT 流明显时，null 权重过大将增加误差。

但建议记录：

```python
null_weight_mean
null_weight_vs_gt_flow_norm
active_slot_count
pred_flow_norm
gt_flow_norm
```

特别要看：

[
q_{\text{null}}
\quad\text{与}\quad
|\mathbf f^{GT}|
]

是否负相关。理想情况是：

```text
GT flow 小 → null weight 高
GT flow 大 → null weight 低
```

如果所有样本的 null weight 都很高，就是塌缩。

---

# 是否要对 null weight 加惩罚

先不要固定加入。

直接惩罚：

[
\lambda_{\text{null}}\operatorname{mean}(q_{\text{null}})
]

会与“允许模型正确表达静止”产生冲突。

更合理的做法是只在发现塌缩后，考虑基于 GT 流幅值的辅助监督：

[
y_{\text{static}}
=================

\mathbb 1
\left[
\operatorname{mean}_i
|\mathbf f_i^{GT}|
<\epsilon
\right]
]

然后给样本级或点级 null weight 一个 BCE 辅助损失。但这会引入人为阈值，第一版不必加。

---

# 零流分支与 Hard-Concrete gate 的关系

它们各自负责不同事情：

* Hard-Concrete gate：决定每个动态 slot 是否存在；
* null decoder branch：当动态 slot 不需要或不足时，提供零流选择。

组合后：

```text
16 个动态 slot
   ↓ Hard-Concrete
0～16 个 active slot
   ↓
与始终开启的 null 分支共同 softmax
   ↓
点流混合
```

这样允许：

### 情况一：静止样本

```text
active slot = 0
null weight ≈ 1
predicted flow ≈ 0
```

### 情况二：简单动作

```text
active slot = 1～2
null weight 仍可能占一部分
```

这里 null 权重可以理解为“动态 slot 没有解释的零运动成分”。

### 情况三：复杂动作

```text
active slot = 4～8
null weight 较低
```

---

# 逐点 null 是否会有问题

有潜在问题，但不是不能用。

你的物体是刚体，所以真实情况下整个物体点流由同一个刚体变换产生。逐点 null 可能让模型预测：

```text
部分点静止
部分点运动
```

产生非刚体流。

不过你当前解码器本身已经允许不同物体点对不同 slot 使用不同权重，所以模型本来就可能产生非严格刚体的点流。零流分支只是在这个混合中增加了一个候选。

如果你的目标是学习通用局部点流，而不是显式约束刚体 SE(3)，逐点 null 可以接受。

如果之后发现预测有明显局部撕裂，可以增加刚体一致性约束，或者把 null 改成样本级权重。但第一版没有必要过早复杂化。

---

# 最终判断

你的方案可行，推荐形式是：

[
\boxed{
\text{16 个手部动态 slot}
+
\text{1 个固定零流 decoder expert}
}
]

关键要求：

1. 零流分支不要进入 Slot Attention；
2. 零流的候选向量固定为 (\mathbf 0)；
3. 零流和 active slot 的权重一起归一化；
4. 不要通过简单阈值判断“其他概率都小才使用”，让 softmax 自动竞争；
5. 从零训练时先限制 null，避免早期全部退化成零流；
6. 记录 null usage 与 GT flow norm 的关系；
7. 仍使用 Hard-Concrete 对 16 个动态 slot 做数量稀疏化，null 不计入 active slot 数。

这比“强制至少保留一个动态 slot”更符合你希望 16 只是上限、允许 0 个有效动作 slot 的目标。
