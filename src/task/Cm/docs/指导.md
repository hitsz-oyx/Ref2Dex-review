可以只返回一个输出，而且这个输出保持米制。训练时在 Runner 里把它乘回目标 scale 后计算 loss 即可。

核心结构：

[
\text{FlowHead输出归一化flow}
\rightarrow
\div s_f
\rightarrow
\text{模型只返回米制flow}
]

训练时：

[
\text{米制预测}\times s_f
\rightarrow
\text{归一化空间计算loss}
]

这样既只有一个输出，又不会把梯度缩小。

# 1. 模型只返回米制 flow

Flow head 实际预测归一化后的 flow：

```python
dynamic_flow_scaled = self.edge_flow_head(edge_features)

pred_obj_flow_scaled = (
    edge_weight.unsqueeze(-1)
    * dynamic_flow_scaled
).sum(dim=2)
```

在返回之前恢复成米：

```python
flow_target_scale = self.object_flow_target_scale

pred_obj_flow_m = (
    pred_obj_flow_scaled
    / flow_target_scale
)

pred_obj_flow_m = (
    pred_obj_flow_m
    * obj_valid_mask.unsqueeze(-1).float()
)
```

只返回：

```python
return {
    "pred_obj_flow": pred_obj_flow_m,
    ...
}
```

不需要返回：

```python
"pred_obj_flow_scaled"
```

你们当前模型本来就采用类似的“内部输出除以 scale，再返回米制”的结构。

# 2. Runner 中乘回 scale 计算训练 loss

Runner 获取的预测仍然是米制：

```python
pred_flow_m = prediction["pred_obj_flow"]
gt_flow_m = batch["obj_flow_gt"].float()
```

计算 loss 前，两者同时乘上 target scale：

```python
flow_target_scale = float(
    self.cfg.meta.object_flow_target_scale
)

pred_flow_scaled = (
    pred_flow_m * flow_target_scale
)

gt_flow_scaled = (
    gt_flow_m * flow_target_scale
)

flow_loss = loss_fn(
    pred_flow_scaled,
    gt_flow_scaled,
)
```

这样模型接口始终只有：

```text
pred_obj_flow，单位：米
```

但优化发生在 (O(1)) 的归一化空间。

# 3. 为什么梯度不会被 `/ scale` 缩小

模型内部：

[
\hat f_m
========

\frac{\hat f_s}{s_f}
]

Runner 中又执行：

[
\hat f_s'
=========

s_f\hat f_m
]

代入后：

[
\hat f_s'
=========

# s_f\frac{\hat f_s}{s_f}

\hat f_s
]

因此前向值完全恢复成内部输出。

梯度同样抵消：

[
\frac{\partial(s_f\hat f_m)}
{\partial\hat f_s}
==================

\frac{\partial}
{\partial\hat f_s}
\left(
s_f\frac{\hat f_s}{s_f}
\right)
=1
]

所以不会出现：

[
\frac{1}{s_f}
]

导致的梯度缩小。

关键是不能写 `.detach()`，也不能先转 NumPy。只要整个乘除过程都在 PyTorch 计算图中，自动求导会自动完成抵消。

# 4. 所有指标直接使用唯一的米制输出

```python
pred_flow_m = prediction["pred_obj_flow"]
gt_flow_m = batch["obj_flow_gt"].float()

residual_norm_m = torch.linalg.vector_norm(
    pred_flow_m - gt_flow_m,
    dim=-1,
)

flow_epe_m = residual_norm_m[valid].mean()
flow_epe_mm = flow_epe_m * 1000.0
```

因此：

```text
训练 loss：归一化空间
EPE、可视化、推理：米制空间
模型返回值：只有米制 flow
```

# 5. 推荐的完整写法

## 模型

```python
# Flow head 预测归一化后的目标
dynamic_flow_scaled = self.edge_flow_head(
    edge_features
)

pred_obj_flow_scaled = (
    edge_weight.unsqueeze(-1)
    * dynamic_flow_scaled
).sum(dim=2)

# 对外统一返回米制
pred_obj_flow = (
    pred_obj_flow_scaled
    / self.object_flow_target_scale
)

pred_obj_flow = (
    pred_obj_flow
    * obj_valid_mask.unsqueeze(-1).float()
)

return {
    "pred_obj_flow": pred_obj_flow,
    "cm_tokens": cm_tokens,
    "cm_tokens_masked": (
        cm_tokens
        * hard_slot_mask.unsqueeze(-1)
    ),
    "cm_anchor_pos": cm_anchor_pos,
    "cm_anchor_normal": cm_anchor_normal,
    "cm_assignment": cm_assignment,
    "cm_slot_weights": cm_slot_weights,
    "slot_gate": hard_slot_mask.float(),
    "slot_hard_mask": hard_slot_mask,
    "slot_nonzero_prob": slot_nonzero_prob,
    "slot_fallback_used": (
        all_below_threshold.squeeze(-1)
    ),
    "decoder_slot_usage": decoder_slot_usage,
}
```

## Runner

```python
pred_flow_m = prediction["pred_obj_flow"]
gt_flow_m = batch["obj_flow_gt"].float()

target_scale = float(
    self.cfg.meta.object_flow_target_scale
)

# 重新进入归一化目标空间
pred_flow_for_loss = (
    pred_flow_m * target_scale
)

gt_flow_for_loss = (
    gt_flow_m * target_scale
)

flow_loss = loss_fn(
    pred_flow_for_loss,
    gt_flow_for_loss,
)

# 物理指标始终使用米
residual_norm_m = torch.linalg.vector_norm(
    pred_flow_m - gt_flow_m,
    dim=-1,
)

flow_epe_mean = (
    residual_norm_m[valid].mean()
)
```

# 6. 配置建议

把原来的混合 scale 拆开：

```yaml
meta:
  geometry_input_scale: 100.0
  hand_flow_input_scale: 20.0
  object_flow_target_scale: 20.53
```

其中：

```text
geometry_input_scale
只影响点坐标输入特征

hand_flow_input_scale
只影响手部 flow 条件输入

object_flow_target_scale
只影响 flow head 的目标输出尺度
```

不要再让一个 `internal_point_flow_scale` 同时控制三者。

# 7. Loss 日志怎么命名

由于训练 loss 是在归一化空间计算的，建议明确命名：

```python
metrics = {
    "flow/loss_scaled": flow_loss,
    "flow/epe_mm": flow_epe_mean * 1000.0,
}
```

不要把它称作：

```text
flow/loss_m
```

因为它不是米制 loss。

Checkpoint 选择使用米制 EPE：

```yaml
train:
  metric_for_best: val/mean_stride_epe
  lower_is_better: true
```

# 最终数据流

[
\boxed{
\begin{aligned}
\text{FlowHead}
&\rightarrow \hat f_s\
\text{模型返回}
&\rightarrow \hat f_m=\hat f_s/s_f\
\text{Runner训练}
&\rightarrow s_f\hat f_m=\hat f_s\
\text{Runner评价}
&\rightarrow |\hat f_m-f_m^{GT}|_2
\end{aligned}
}
]

所以完全可以只返回一个 `pred_obj_flow`，单位始终为米；Runner 在计算训练 loss 时临时乘回固定的 `object_flow_target_scale` 即可。
