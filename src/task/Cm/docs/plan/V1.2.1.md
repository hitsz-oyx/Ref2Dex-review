## 目标

把当前已经存在的框架原型收口为可审计、可失败快速的最小闭环：

1. train 和 eval 都生成不会静默覆盖历史运行的 `run_manifest.json`，并过滤自引用路径；
2. Cm object-v2、Stage4、HRDexDB 在 loader 初始化时确认选定数据根的坐标系一致，禁止同一 loader 混用 `object_pose_t` 与 `hand_root_t`；
3. 修复 V1.2.1 指导中指出的 persistent worker epoch 共享与 object-v2 mmap 打开句柄无界增长。

## 文件范围

- 共享运行时：`src/base/base_runner.py`、`src/base/run_manifest.py`；
- Cm loader 与入口：`src/task/Cm/dataset/object_v2.py`、`stage4.py`、`hrdexdb.py`、`scene.py`、`src/task/Cm/src/eval.py`；
- 回归测试与日志：相关 `tests/`、`docs/logs/`、`src/task/Cm/docs/logs/`。

不在范围内：模型结构、loss、GT、采样科学定义、数据 split 内容、训练超参数、checkpoint 内容、正在运行的进程、`outputs/` 与 cache 产物。

## 不变量与兼容策略

- 不恢复或新增 SHA-256 等加密 hash；run manifest 只记录文件存在性、大小和修改时间等轻量 provenance。
- 既有 `hand_root_t` cache/config 继续可读；`object_pose_t` 只在所有被选序列都提供 object pose 时启用；混合根立即报错。
- 训练 resume 不覆盖原始 `config.json`、`metadata.json` 或 `run_manifest.json`；需要新尝试时写入带时间戳的 continuation manifest。
