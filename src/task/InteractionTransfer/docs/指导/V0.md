我建议新 Task 叫：

[
\boxed{\texttt{InteractionTransfer}}
]

目录：

```text
src/task/InteractionTransfer/
```

这个名字比 `CmV2`、`DynamicCm` 更合适，因为现在真正要研究的已经不是“换一种 Cm token”，而是：

[
\boxed{
\text{Current Relation}
+
\text{Action}
\rightarrow
\text{Transferred Interaction}
\rightarrow
\text{Effect}
}
]

即“动作如何通过当前 hand-object relation 被传递到物体”。

`InteractionDynamics` 已经存在，`DynamicInteractionField` 又容易让人误以为 Cm 本身是 object field；`InteractionTransfer` 对现在的定义最准确。仓库现有 Task 也是这种概念级命名方式。

---

# 一、先把新 Task 的概念彻底固定

我建议以后在这个 Task 里固定四个符号，不再混用。

### 1. Current Relation

[
\boxed{
R_{ij}
======

E_R(O_t,H_t;i,j)
}
]

表示当前 hand point (h_j) 和 object point (o_i) 的关系。

它**不包含动作**。

---

### 2. Hand Action

[
\boxed{
A_j=\Delta h_j
}
]

表示这个 hand point 接下来怎么动。

---

### 3. Dynamic Interaction Message

[
\boxed{
M_{ij}\equiv C_{m,ij}
}
]

表示：

> 当前 (h_j) 的动作，通过当前 (R_{ij})，实际向 (o_i) 传递出来的作用。

这个才是真正的 Cm。

---

### 4. Object Interaction Field

[
\boxed{
C_i^O
=====

\operatorname{Agg}*{j\in\mathcal N(i)}
C*{m,ij}
}
]

它不是 Cm 本体，而是把所有 edge interaction 汇总到 object 上以后得到的公共表示。

最后：

[
\boxed{
(O_t,C^O)\rightarrow\Delta O_t
}
]

整个计算图：

```text
                 O_t , H_t
                     │
                     ▼
             Static Relation
                  R_ij
                     │
                     │ modulation
Δh_j ────────────────┤
                     ▼
          Dynamic Interaction
                 Cm_ij
                     │
                     ▼
          Object Aggregation
                  C_i^O
                     │
                     ▼
           Object-only Decoder
                     │
                     ▼
                   ΔO_t
```

---

# 二、这里我会对刚才的方案做一个重要修改

**不能简单写：**

[
C_{m,ij}=\operatorname{MLP}([R_{ij},\Delta h_j]).
]

因为这样非常容易出现：

[
\Delta h_j=0
]

但：

[
C_{m,ij}\neq0
]

网络把静态 (R_{ij}) 偷偷塞进 Cm。

这正是你一直担心的：

> 最后 Cm 又变成 static representation。

所以我建议从**网络结构上直接禁止这种情况**。

---

# 三、Cm 用“Relation 调制 Action”，而不是 concat

先得到 action embedding：

[
a_{ij}
======

E_A(
\Delta h_j,
v_{ij}^{n},
v_{ij}^{t}
)
]

其中：

[
v_{ij}^{n}
==========

\Delta h_j\cdot n_i^O
]

表示沿 object 法向的运动。

切向：

[
v_{ij}^{t}
==========

\Delta h_j-
v_{ij}^{n}n_i^O.
]

然后 (R_{ij}) 只生成一个 modulation：

[
\gamma_{ij}
===========

\sigma(E_G(R_{ij}))
]

最终：

[
\boxed{
C_{m,ij}
========

E_M(
\gamma_{ij}\odot a_{ij}
)
}
]

这里 `⊙` 是逐元素乘法。

最重要的是：

**Action Encoder 和 Message Encoder 使用无 bias 的网络或保证 zero-preserving。**

从结构上保证：

[
\boxed{
\Delta h_j=0
\Rightarrow
C_{m,ij}=0.
}
]

这样 Cm 就不可能退化成纯 static relation。

这是我认为新 Task V0 最应该坚持的设计。

---

# 四、(R_{ij}) 就用 DenseToken bootstrap

你们现有 DenseToken 正合适。

因为它严格只输入：

[
(O_t,H_t)
]

不输入 hand flow，也不看 future object，所以它天然适合提取 current relation。

而且当前 `correspondence_ptv3_v2` 本来就已经存在：

[
[z_i^O,z_j^H]
\rightarrow
e_{ij}^{dense}
\rightarrow
p_{ij}^{contact}.
]

它的 `edge_shared_backbone` 已经在学习 hand-object pair relation。

所以 V0：

[
e_{ij}^{dense}
==============

E_{\rm dense}(z_i^O,z_j^H)
]

然后显式加入：

[
g_{ij}.
]

定义：

[
\boxed{
R_{ij}
======

E_R([
e_{ij}^{dense},
g_{ij},
p_{ij}^{contact}
])
}
]

其中：

[
g_{ij}
======

[
h_j-o_i,
d_{ij},
n_i^O,
n_j^H,
\hat r_{ij}\cdot n_i^O,
-\hat r_{ij}\cdot n_j^H,
n_i^O\cdot n_j^H
].
]

DenseToken 本身也已经使用最近距离和法向投影等 hand-object 几何信息。

# 十一、`interaction_message.py`

这是整个 Task 最核心的模块。

```python
relation_gate = sigmoid(
    relation_to_gate(R_ij)
)

action_feat = action_encoder(A_ij)

transmitted = relation_gate * action_feat

Cm_ij = message_encoder(transmitted)
```

维度：

[
R_{ij}:64
]

[
A_{ij}:32
]

[
C_{m,ij}:32.
]

并强制：

[
\boxed{
A=0\Rightarrow C_m=0.
}
]

这一条直接写 unit sanity，不需要大规模单测：

```python
assert cm_zero.abs().max() < 1e-6
```

这一个 sanity 很值得保留。

# 十二、object aggregation 不要简单 `sum`

这是之前我们发现的风险：

[
\text{pinch}
]

不是简单两个 contact contribution 的线性和。

所以我不建议：

[
C_i^O=\sum_j C_{m,ij}.
]

V0 用一个很轻量的 attention pooling：

```text
K edge messages
[N_obj, K, 32]
       │
       ▼
2-layer self attention
       │
       ▼
object query attention
       │
       ▼
C_obj_i [64]
```

数学上：

[
\tilde M_i
==========

\operatorname{SelfAttn}
(
{C_{m,ij}}_{j=1}^{K}
)
]

再：

[
C_i^O
=====

\operatorname{AttnPool}(\tilde M_i).
]

这样允许：

> finger 1 的作用意义依赖 finger 2 是否同时存在。

这对 pinch / grasp 很重要。

# 十三、Effect Decoder

这里必须遵守一个非常硬的原则：

[
\boxed{
\text{Effect decoder 不允许看 }H,\Delta H,R,C_m^{edge}.
}
]

只能看：

[
(O,C^O).
]

第一版：

```text
object xyz
object normal
C_obj
    │
    ▼
small object-only PTv3
    │
    ▼
MLP
    │
    ▼
ΔO
```

我不建议 pointwise MLP 作为最终版本，因为局部 interaction 需要传播成整个 rigid object motion。

所以可以复制一个**小型 PTv3**：

```text
2~3 stage
object-only
```

输入：

[
[o_i,n_i,C_i^O].
]

然后：

[
\Delta o_i.
]

这样：

```text
local interaction
      ↓
object spatial propagation
      ↓
global rigid effect
```

比较合理。

检查三个东西。

### Action leakage

[

[

]

很可能还是 ActionToken。

### Static leakage

]

如果不需要 action：

[

]

# 十九、一个需要提前承认的问题：DenseToken 现在只适合 bootstrap

这是必须说清楚的。

当前 pretrained DenseToken 是在人类 hand representation 和固定点数上训练的；你们现在 wrapper 也明确要求 `512 object / 1538 hand`。

所以：

[
\boxed{
\text{V0 用 DenseToken 验证 interaction-transfer 假设可以}
}
]

但不能直接说：

> 这个 DenseToken 本身就是最终 cross-embodiment encoder。

以后 robot：

```text
parallel gripper
Shadow Hand
Allegro
...
```

点数、形态都不同。

所以路线应该是：

```text
V0
Human-only + pretrained DenseToken
        ↓
验证 InteractionTransfer 是否成立
        ↓
V1
generic surface relation encoder
        ↓
Human + Robot
        ↓
cross-embodiment Cm
```

不要在第一步同时解决两个难题。
