这个问题建议分两层解决：

[
\boxed{\text{先用独立进程彻底解决内存泄漏/滞留}}
]

然后：

[
\boxed{\text{把 Frozen DenseToken 离线缓存，彻底避免重复加载 PTv3}}
]

第二层其实更适合你现在这个实验，因为 DenseToken 是冻结的。

## 1. 立即可用的修复：Cm 和 DirectEdge 分进程跑

不要再写成：

```python
cm = InteractionTransfer()
train(cm)
eval(cm)

del cm
gc.collect()

direct = DirectEdge()
train(direct)
eval(direct)
```

即使 Python 对象删掉了，PyTorch / spconv / libc native allocator（原生内存分配器）保留的 CPU 内存页也不一定马上归还操作系统。

改成：

```text
benchmark_v05.py               ← 轻量主进程，不 import torch
│
├── python train_eval_cm.py
│     ├── load PTv3
│     ├── train Cm
│     ├── eval Cm interventions
│     ├── 写 cm_result.json
│     └── 进程退出 → OS 强制回收全部 CPU/GPU 内存
│
└── python train_eval_direct.py
      ├── load PTv3
      ├── train DirectEdge
      ├── eval DirectEdge
      ├── 写 direct_result.json
      └── 进程退出 → OS 强制回收
```

这里关键不是 `gc.collect()`，而是：

[
\boxed{\text{process exit}}
]

进程退出后操作系统一定回收该进程的整个 address space（地址空间），包括 PTv3/spconv native memory。

### 主 benchmark 推荐直接用 `subprocess.run`

不要优先用 `multiprocessing + fork`，因为 CUDA/spconv 和 `fork` 混合更容易产生奇怪问题。

```python
# benchmark_v05.py
import json
import subprocess
import sys
from pathlib import Path

root = Path("output/exp/interaction_transfer_v05")
root.mkdir(parents=True, exist_ok=True)

common = [
    "--root", "data/processed_data/interaction_dynamics_v1/data/grab",
    "--device", "cuda:0",
    "--steps", "10000",
]

subprocess.run(
    [
        sys.executable,
        "-m",
        "src.task.InteractionTransfer.research.train_eval_cm_v05",
        *common,
        "--output",
        str(root / "cm.json"),
    ],
    check=True,
)

subprocess.run(
    [
        sys.executable,
        "-m",
        "src.task.InteractionTransfer.research.train_eval_direct_v05",
        *common,
        "--output",
        str(root / "direct_edge.json"),
    ],
    check=True,
)

cm = json.loads((root / "cm.json").read_text())
direct = json.loads((root / "direct_edge.json").read_text())

summary = {
    "cm": cm,
    "direct_edge": direct,
    "cm_direct_ratio": (
        cm["gt"]["point_error_m"]
        / direct["gt"]["point_error_m"]
    ),
}

(root / "summary.json").write_text(
    json.dumps(summary, indent=2),
    encoding="utf-8",
)

print(json.dumps(summary, indent=2))
```

注意主进程**不要 import torch、InteractionTransfer、PTv3**。让它真的只是 launcher + JSON aggregator。

DirectEdge 同理。

# 3. 但更推荐的最终解决方案：DenseToken 离线预计算

因为你当前定义里：

[
E_{\text{DenseToken}}(O_t,H_t)
]

是完全 frozen 的。

它不依赖训练参数，也不依赖：

[
\Delta H.
]

甚至当前 pretrained edge head：

[
e_{ij}^{dense},\quad p_{ij}^{contact}
]

也是 frozen。

所以每次 epoch / 每次模型 forward 都重新跑 PTv3，其实完全没必要。

你真正训练所需的是：

[
\boxed{
e_{ij}^{dense},
p_{ij}^{contact},
g_{ij},
\Delta h_j,
\Delta O_i
}
]

其中最贵的只有：

[
e_{ij}^{dense},p_{ij}^{contact}
]

这部分可以提前算一次。

## 4. 我建议增加一个 `precompute_static_v05.py`

流程：

```text
raw GRAB transition
       │
       ▼
Frozen DenseToken/PTv3
       │
       ├── Dense object/hand token
       │
       ▼
KNN edge builder
       │
       ▼
pretrained edge head
       │
       ├── dense_edge_feature
       └── contact_prob
       │
       ▼
save static cache
```

每个 transition 保存：

```python
{
    "object_points": ...,
    "object_normals": ...,

    "hand_points": ...,
    "hand_normals": ...,

    "hand_flow": ...,
    "object_flow": ...,

    "edge_idx": ...,
    "edge_valid": ...,

    "dense_edge": ...,
    "contact_prob": ...,
}
```

其中：

```text
dense_edge   [512, 16, 32]
contact_prob [512, 16]
```

如果是 FP32，一个样本的 `dense_edge` 大概：

[
512\times16\times32\times4
\approx 1\text{ MB}
]

64 个 transition 也才约：

[
64\text{ MB}
]

加其他数据仍然很小。

甚至可以把 frozen feature 存成 FP16：

[
\approx32\text{ MB}.
]

训练时再 `.float()`。

# 5. 这样 Cm 模型本身就不应该再包含 PTv3

目前是：

```text
InteractionTransfer
├── FrozenDenseStateEncoder  ← 91M，大头
├── RelationEncoder
├── InteractionMessage
├── Aggregator
└── EffectDecoder
```

建议拆成：

```text
StaticInteractionEncoder
    ↓ 只用于 cache generation

InteractionTransferCore
├── RelationEncoder
├── InteractionMessage
├── Aggregator
└── EffectDecoder
```

训练阶段：

```text
cached dense_edge/contact
             +
      current geometry
             ↓
       RelationEncoder
             ↓
            R_ij
             +
           Δh_j
             ↓
           Cm_ij
             ↓
         C_obj_i
             ↓
          Effect
```

这样正式训练时模型可能从：

[
91M+
]

直接降到几百万参数。

CPU RSS、初始化时间、GPU 显存都会大幅下降。

# 6. DirectEdge 也使用完全相同的 cache

这还有一个很大的实验优势。

Cm：

[
e_{ij}^{dense},p_{ij},g_{ij}
\rightarrow
R_{ij}
]

然后：

[
R_{ij},a_{ij}
\rightarrow
\boxed{C_{m,ij}}
\rightarrow
C^{obj}
\rightarrow
\Delta O.
]

DirectEdge：

[
e_{ij}^{dense},p_{ij},g_{ij}
\rightarrow
R_{ij}
]

然后直接：

[
\boxed{
M_{ij}^{direct}
===============

MLP([R_{ij},a_{ij}])
}
]

再：

[
M^{direct}
\rightarrow
C^{obj}
\rightarrow
\Delta O.
]

这样两者完全共享：

* 数据；
* DenseToken；
* KNN edge；
* pretrained relation prior；
* effect decoder capacity；
* aggregation capacity。

唯一变化就是：

```text
Cm:
Relation × Action
    ↓
zero-preserving bottleneck
    ↓
Cm

DirectEdge:
Relation + Action
    ↓
unrestricted MLP
```

这才是非常干净的 ablation。

# 8. 内存监控继续保留，但不要放太复杂

每个关键阶段打印：

```python
import os
import psutil
import torch

def report_memory(tag):
    process = psutil.Process(os.getpid())
    rss = process.memory_info().rss / 1024**2

    if torch.cuda.is_available():
        allocated = torch.cuda.memory_allocated() / 1024**2
        reserved = torch.cuda.memory_reserved() / 1024**2
    else:
        allocated = reserved = 0

    print(
        f"[{tag}] "
        f"RSS={rss:.1f} MiB | "
        f"GPU allocated={allocated:.1f} MiB | "
        f"GPU reserved={reserved:.1f} MiB",
        flush=True,
    )
```

重点记录：

```text
process start
after dataset
after DenseToken/cache load
after model init
after train
before eval
after eval
```

# 9. 还有一个需要修的地方：真正冻结 DenseToken eval mode

即使使用独立进程，当前这个问题也要修。

你现在：

```python
self.static_encoder.eval()
```

初始化时执行了，但外部：

```python
model.train()
```

会递归把它重新切回 training mode。

所以建议：

```python
class FrozenDenseStateEncoder(nn.Module):
    ...

    def train(self, mode: bool = True):
        super().train(False)
        return self
```

或者在 `InteractionTransfer`：

```python
def train(self, mode=True):
    super().train(mode)
    self.static_encoder.eval()
    return self
```

保证 PTv3 永远：

```python
training == False
```

并加一个 sanity：

```python
model.train()

assert not model.static_encoder.training
assert not model.static_encoder.backbone.training
```

1. **立刻把 benchmark 改成 Cm / DirectEdge 两个独立 subprocess。**
   这能马上解决当前被系统杀掉的问题。

2. **修 Frozen DenseToken 的 `train/eval` 状态。**

3. **确认 pretrained `edge_shared_backbone / cross_edge_head` 权重真正加载成功。**

4. 跑通一次完整 V0.5 benchmark。

5. 然后做：
   [
   \boxed{\text{offline DenseToken cache}}
   ]
   把 PTv3 从正式训练循环完全移除。

我更推荐最终采用第 5 点。因为 DenseToken 既然是冻结的，那么**每个 epoch 都重新运行一遍 91M PTv3 本身就是没有必要的计算和内存负担**。缓存以后不仅解决 CPU RSS，这个 V0.5 benchmark 也会变得更快、更干净、更容易做 Cm 与 DirectEdge 的公平对比。
