可以，而且我认为这三个改动是同一个方向：**降低模型对固定 MANO 点、固定 33 ms 时间尺度、单右手数据分布的依赖**。但不建议直接在当前 V0.10 cache 上打补丁，最好把 dataset/cache 重新整理一次。

当前仓库的限制很明确：hand input 固定 1538 点，实际上对应 MANO 的 1538 个 face-center；dataset 固定 `gap=1`；并且只保留 `right active + left inactive`。

## 1. 随机 MANO 手点采样：可以，但不能只是 shuffle

现在：

[
H_t\in\mathbb R^{1538\times3}
]

恰好就是 MANO 1538 个三角面的中心。如果写：

```python
idx = torch.randperm(1538)
hand = hand[idx]
```

然后还是取全部 1538 个点，本质只是排列顺序变化，几何完全没变。

我更建议真正做：

[
\boxed{\text{MANO surface}\rightarrow\text{random 1538 surface points}}
]

最适合当前 MANO 的方式是用三角面的 **barycentric coordinate（重心坐标，即三角形内部一个点由三个顶点加权得到）**。

对于三角面：

[
(v_0,v_1,v_2)
]

随机：

[
b_0+b_1+b_2=1
]

得到：

[
p=b_0v_0+b_1v_1+b_2v_2.
]

关键是同一个 transition 的：

[
t,\quad t+g
]

必须使用**同一个 face id + 同一组 barycentric 权重**：

[
p_t=b_0v_{0,t}+b_1v_{1,t}+b_2v_{2,t}
]

[
p_{t+g}=b_0v_{0,t+g}+b_1v_{1,t+g}+b_2v_{2,t+g}
]

这样：

[
\Delta h=p_{t+g}-p_t
]

才是真正同一个物理表面点的运动。

绝对不能：

```text
t 随机采一批点
t+g 又独立随机采一批点
```

否则两批点没有 correspondence（点对应关系），`hand_flow` 就失去物理意义。

### 更推荐的 MANO cache

当前 Stage4 存的是：

```text
hand_points_world  [T,1538,3]
```

我反而建议下一版存：

```text
hand_vertices_world [T,778,3]
mano_faces           [1538,3]   # 静态，可不重复存
```

然后训练时在线随机 surface sampling。

778 个顶点甚至比现在 1538 face-center 更省空间，同时以后你想：

```text
512 points
768 points
1538 points
2048 points
```

都可以随便采。

# 2. 随机时间步：很适合现在做

当前 cache 本身其实已经是完整 sequence：

```text
frame 0
frame 1
frame 2
...
```

Stage4 存了完整 object/hand trajectory，并不是只存 `(t,t+1)`。真正把它限制成 `gap=1` 的是 `GRABOneStepDataset`：

```python
if tuple(int(gap) for gap in gaps) != (1,):
    raise ValueError(...)
```

所以可以改成训练时：

[
g\sim{1,2,4,8}
]

比如：

| gap |   时间跨度 |
| --: | -----: |
|   1 |  33 ms |
|   2 |  67 ms |
|   4 | 133 ms |
|   8 | 267 ms |

每次：

[
j=i+g
]

构造：

[
\Delta H=H_j-H_i
]

[
\Delta O=O_j-O_i.
]

也就是说：

```text
同一个 current state

这次训练：
t → t+1

下次：
t → t+4

再下次：
t → t+2
```

这个我认为很有价值。

---

# 3. 我建议随机时间步以后把 dt 显式告诉模型

当前 action 是：

[
A_{ij}
======

[\Delta h_j,v_n,v_t,|\Delta h_j|]
]

8 维。

如果开始混：

[
33/67/133/267\text{ ms}
]

最好增加：

[
\Delta t.
]

变成：

[
\boxed{
A_{ij}
======

[
\Delta h_j,
v_n,
v_t,
|\Delta h_j|,
\Delta t
]
}
]

也就是 9D。

原因很简单：

同样：

[
\Delta h=2\text{ cm}
]

可以是：

```text
33 ms 内移动 2 cm
```

也可能是：

```text
267 ms 内移动 2 cm
```

物理意义并不完全相同。

所以让模型知道：

[
\boxed{\text{移动了多少 + 花了多长时间}}
]

会更合理。

可以用归一化：

[
\tau=\frac{\Delta t}{1/30}=g
]

或者：

[
\tau=\log g.
]

第一版直接用 normalized gap 就够。

# 4. 双手也可以，而且我建议模型总 hand points 仍保持 1538

如果你希望算力基本不增加，可以：

[
N_H=1538
]

不变。

双手情况下：

[
N_L=769,\qquad N_R=769.
]

所以：

```text
Left MANO  → random 769
Right MANO → random 769

concat
   ↓
1538 hand points
```

模型整体 tensor size 基本保持：

[
512\ object +1538\ hand.
]

这和你“总点数不变”的要求是吻合的。

# 5. 双手我不建议简单做一个普通 KNN

当前：

[
\text{每个 object point}\rightarrow K=16\text{ nearest hand points}.
]

如果我们直接把左右手 concat：

```text
769 Left + 769 Right
        ↓
       KNN16
```

可能出现：

```text
16 个 neighbor 全来自右手
```

即使左手也在接触。

我更建议：

[
\boxed{K_L=8,\qquad K_R=8}
]

也就是：

```text
                 object point i
                /             \
        Left KNN 8           Right KNN 8
           │                    │
         M_iL                 M_iR
           \                    /
            \                  /
              aggregation
                  ↓
                C_obj
```

总 edge 数仍然：

[
8+8=16
]

所以计算量几乎和现在一致。

而且保证双手 interaction 都有机会进入：

[
C_i^O.
]

如果某只手离物体超过 5 cm，相应：

```text
edge_valid = False
```

就行。

这个结构我非常推荐。

# 6. 模型其实不一定需要知道“这是左手还是右手”

这一点我倾向于**第一版不要加入 left/right embedding**。

也就是说不要告诉模型：

```text
side = left
side = right
```

让模型只看：

[
\text{geometry}+
\text{normal}+
\text{action}.
]

因为我们的目标本来就是 interaction transfer。

理想情况应该是：

> 我不在乎你是左手、右手、Allegro 还是另一只机器人手；只要局部 geometry/action 一样，就应该产生类似 (M)。

所以：

[
M_{ij}=F(R_{ij},A_{ij})
]

保持 embodiment-agnostic（不依赖具体执行器身份）反而更漂亮。

左右手信息只在 **edge builder** 里用于保证 `8+8` 采样均衡，不输入网络。

# 7. Dataset 应该同时包含三种情况

目前训练只接受：

[
R=active,\qquad L=inactive.
]

下一版应该包含：

```text
Right-only
Left-only
Bimanual
```

也就是：

[
R\lor L=active.
]

我建议第一版依然保持 interaction-only：

[
(R_{active}\lor L_{active})
]

在整个：

[
[i,i+g]
]

时间窗口内连续成立。

也就是：

```python
active = right_active | left_active

active[i:j+1].all()
```

先避免：

```text
没接触
→ 接触
→ 离开
→ 又接触
```

这种复杂事件把随机 timestep 实验搞混。

等模型稳定后再放宽。

# 9. 最大的问题其实是现有 static cache

这三个改动里面：

* random timestep 本身不要求重建 Stage4；
* 双手的数据 Stage4 已经有 `left.npz/right.npz`；
* **真正破坏 static cache 的是随机 hand surface sampling + 双手 geometry。**

当前 V0.8 static cache 已经把：

```text
edge_idx
edge_valid
dense_edge
geom_contact
```

全部提前算死，而且明确是：

```text
right-active
left-inactive
gap=1
fixed hand points
```

一旦手点每个 epoch 都随机变：

[
H_t^{(epoch1)}
\neq
H_t^{(epoch2)}
]

那么：

[
edge_{ij}
]

以及：

[
DenseToken(H_t)
]

都会变。

所以原来的：

[
\boxed{\text{static feature cache}}
]

不能继续直接使用。

## 我建议一次性这样升级

不要分别搞三个临时 flag。我会把下一版本定义为：

```text
Random Surface
    MANO online random sampling
    total hand points = 1538

Random Horizon
    gap ∈ {1,2,4,8}
    explicit Δt

Bimanual
    left = 769
    right = 769
    K = 8 + 8

Output
    object points = 512
    predict ΔO
```

模型核心：

[
\boxed{
R\rightarrow M\rightarrow C_{obj}\rightarrow\Delta O
}
]

**完全不用推倒重来。**

真正变化主要发生在：

```text
dataset
edge builder
action feature 8D → 9D
cache
inverse rigid 6D → 12D
viewer
```

而 `M → C_obj → Effect Decoder` 这条核心研究思想可以保持不动。

唯一需要提前接受的是：**真正随机 MANO surface sampling 与当前“Frozen DenseToken static cache 一次算完、训练 20 epoch 不再跑 PTv3”的方案天然冲突。** 如果坚持每 epoch 真随机，就要重新跑 frozen PTv3；或者以后做少量 sampling-bank cache。这个性能问题需要单独处理，但从研究设计上，我认为这三个改动值得一起做。
