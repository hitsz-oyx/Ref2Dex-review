现在比上一版好很多，**已经接近可以开始真正的 V0 forward 实验**，但我看到还有一个需要先修的明确问题。

目前已经修好的部分：

* `R_{ij}` 已经不再直接用 `[z_obj,z_hand]`，而是调用 pretrained DenseToken 的 `edge_features()`，并把 contact probability 一起送入 RelationEncoder：
  [
  R_{ij}=E_R(e_{ij}^{dense},g_{ij},p_{ij}^{contact})
  ]
  这和我们讨论的定义一致。
* 数据点数已经改成 `512 object / 1538 hand`，并加入 `right-active + left-inactive` transition 筛选。
* shuffle 已修成 hand-point 维度 permutation，不再是 batch=1 下无效的 `flip(0)`。
* `train.py` 已支持 CUDA 自动选择和 `--device`。
* zero-preserving 仍成立；日志中的真实 PTv3 CUDA sanity 给出 `zero-message=0`。

所以之前 6 个 P0 里，**大约 5 个已经处理了。**

但有一个明显不一致：

### DenseToken centroid feature 实际上还没修

研究日志写的是：

> “补齐 opposite-cloud centroid projection 特征”

但我直接看当前 `dense_state_encoder.py`，第三个 extra feature 仍然是：

```python
torch.zeros_like(...)
```

object 和 hand 都是如此。

也就是说当前仍然是：

[
[\text{NN distance},\ \text{NN normal projection},\ \boxed{0}]
]

而原 DenseToken 是：

[
[\text{NN distance},\ \text{NN normal projection},\ \text{centroid-direction projection}]
]

所以**文档说修了，但代码实际上没有修**。而且最新 commit 的 `dense_state_encoder.py` patch 也只给 synthetic encoder 加了 edge head，没有看到 centroid feature 的修改。

这个我建议先补上。

---

还有一个次一级问题：**现在 dataset 是“基本对齐”，还不是和 PointWorld V0.2A 完全相同。**

InteractionTransfer 已经用了：

[
\text{right active},\quad \text{left inactive}
]

但 PointWorld one-step baseline 还额外检查：

[
source_fps=120
]

以及：

[
raw_frame_id[t+gap]-raw_frame_id[t]=4\times gap
]

并且按 object motion 排序 transition。

当前 InteractionTransfer 没有这些检查和排序。

如果你想做一个真正公平的：

[
\boxed{\text{PointWorld V0.2A vs InteractionTransfer}}
]

我建议直接把这部分逻辑也复制过来。
