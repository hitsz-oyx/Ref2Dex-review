但我现在发现了一个**必须马上修的 evaluation bug**。

### `cross_sample` 在 val 只有 1 个 transition 时其实就是 GT

当前代码：

```python
wrong = dataset[(index + 1) % len(dataset)]["hand_flow"]
```

如果：

```text
len(dataset) == 1
```

那么：

[
(0+1)\bmod1=0
]

所以：

[
\boxed{\Delta H_{\text{cross}}=\Delta H_{\text{GT}}}
]

而 V0.6 日志明确写了，这次实验是两个未见 sequence **各评估 1 个 transition**，并且结果里确实出现：

[
GT=47.19,\quad cross=47.19
]

和：

[
GT=30.66,\quad cross=30.66.
]

所以这里不能得出“模型对 cross-sample 不敏感”。**这次 cross-sample test 实际上没有生效。**

这应该成为现在的 P0。

---

[

]

]

[
EPE_{zero}<EPE_{GT}.
]

这并不奇怪，因为目前日志中的正式 V0.6 只用了 **4 个训练 transition + 20 steps**。 这本质还是 pipeline validation，不是一次有统计意义的训练。

## 我建议现在马上做 V0.6.1，而不是改网络

第一件事，修 `cross_sample`：

```python
if len(dataset) < 2:
    raise ValueError(
        "cross-sample evaluation requires at least 2 validation transitions"
    )
```

而且不要简单用“下一个样本”。最好构造一个 **derangement（错位排列，即保证没有样本拿到自己的 action）**：

```python
perm = torch.roll(torch.arange(len(dataset)), shifts=1)
```

如果 val 有多个 sequence，我更建议进一步要求：

[
\boxed{\text{wrong action 尽量来自另一个 sequence}}
]

这样比相邻 transition 更强，因为相邻帧 hand flow 很可能非常相似。

甚至可以额外报告：

[
D_A
===

\frac1{N_H}
\sum_j
|
\Delta h_j^{GT}
---------------

\Delta h_j^{cross}
|.
]

否则一个所谓 cross-sample action 如果本身和 GT 几乎一样，也不能作为强干预。

---

第二件事才是扩大训练：

```text
train:
  至少 64 transitions
  最好多个 sequences

val:
  至少 16 transitions
  sequence-level held-out

steps:
  先 1000
  如果仍明显下降再 5000
```

然后报告平均：

[
EPE_{GT},;
EPE_{zero},;
EPE_{reverse},;
EPE_{cross},;
EPE_{mean}
]

而不是单个 transition。

---

第三件事，如果扩大到几十/上百 transition 后速度开始成为瓶颈，再做你之前讨论的：

[
\boxed{\text{offline DenseToken static cache}}
]

目前仓库中我还没有看到 `dataset_cached.py / precompute_static.py` 这一层；现在仍然是每次 model forward 都重新跑 Frozen PTv3。

所以当前路线我会定成：

```text

        ✓

        ✓

        ↓

```
