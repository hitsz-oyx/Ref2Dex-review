# 1. Task 目标

新 Task：

```text
src/task/InteractionTransfer/
```

核心问题只验证：

[
\boxed{
(O_t,H_t,\Delta H_t)
\rightarrow
C_{m,t}
\rightarrow
\Delta O_t
}
]

但内部明确拆成：

[
(O_t,H_t)
\rightarrow
R_{ij}
]

[
(R_{ij},\Delta h_j)
\rightarrow
C_{m,ij}
]

[
{C_{m,ij}}_j
\rightarrow
C_i^{obj}
]

[
(O_t,C^{obj})
\rightarrow
\Delta O_t
]

其中：

[
\boxed{R_{ij}}
]

是当前 hand-object relation，即“当前手点和物体点之间是什么关系”。

[
\boxed{C_{m,ij}}
]

才是真正的动态 Cm：

> hand point (j) 的当前动作，通过当前 relation，对 object point (i) 施加了什么动态作用。

而：

[
C_i^{obj}
]

只是 edge Cm 聚合后的 object-side interaction field，用于预测 effect 和以后跨 embodiment 对齐。

# 2. 整体网络

我建议正式固定成：

```text
                    current O_t, H_t
                           │
                           ▼
                 Frozen DenseToken
                           │
                 z_obj_i , z_hand_j
                           │
                           ▼
              hand-object edge builder
                           │
        ┌──────────────────┴──────────────────┐
        │                                     │
        ▼                                     ▼
 pretrained edge feature              explicit geometry
 e_dense_ij + contact p_ij                 g_ij
        │                                     │
        └──────────────────┬──────────────────┘
                           ▼
                    RelationEncoder
                           │
                          R_ij
                           │
                           │ gate
                           ▼
 Δh_j ──► ActionEncoder ── × ──► MessageEncoder
                                     │
                                     ▼
                                  Cm_ij
                                     │
                                     ▼
                              Edge Aggregator
                                     │
                                     ▼
                                  C_obj_i
                                     │
                                     ▼
                         Object-only Effect Decoder
                                     │
                                     ▼
                                  ΔO_i
```

最重要的一条信息约束：

[
\boxed{
D_{\text{effect}}
\text{ 绝对不能直接看到 }
H,\Delta H,R
}
]

只能：

[
\boxed{
\Delta O=D(O,C^{obj})
}
]

否则 Cm bottleneck（信息瓶颈，即强迫信息必须经过 Cm）就没有意义了。

# 3. (R_{ij}) 怎么实现

DenseToken 冻结：

[
(z_i^O,z_j^H)=E_{\rm DenseToken}(O,H)
]

使用已经训练好的：

```text
src/task/Cm/densetoken_ckpt/best.pt
```

但是 **InteractionTransfer 内部自己实现 loader 和 PTv3 wrapper**。

不要：

```python
from src.task.Cm...
```

也不要：

```python
from src.task.correspondence_ptv3_v2...
```

checkpoint 可以共享，代码不要共享。

DenseToken 输入保持原训练分布：

[
[
xyz,\ type,\ normal,\ d_{NN},\ proj_{NN},\ proj_{centroid}
]
]

然后 pretrained edge head：

[
e_{ij}^{dense}
==============

E_{\rm edge}(z_i^O,z_j^H)
]

以及：

[
p_{ij}^{contact}
================

\sigma(H_{\rm contact}(e_{ij}^{dense})).
]

显式 geometry：

[
r_{ij}=h_j-o_i
]

[
d_{ij}=|r_{ij}|
]

再加入：

[
n_i^O,\quad n_j^H
]

以及：

[
\hat r_{ij}\cdot n_i^O
]

[
-\hat r_{ij}\cdot n_j^H
]

[
n_i^O\cdot n_j^H.
]

于是：

[
g_{ij}\in\mathbb R^{13}
]

左右。

最终：

[
\boxed{
R_{ij}
======

E_R(
[
e_{ij}^{dense},
p_{ij}^{contact},
g_{ij}
]
)
}
]

建议：

[
R_{ij}\in\mathbb R^{64}.
]

# 4. Edge 怎么建

每个 object point：

[
o_i
]

找：

[
K=16
]

个最近 hand point。

同时要求：

[
d_{ij}<5cm.
]

得到：

```python
edge_idx:   [B, N_obj, K]
edge_valid: [B, N_obj, K]
```

目前：

[
N_O=512,\quad N_H=1538
]

所以最多：

[
512\times16=8192
]

条 edge，完全可接受。

V0 不需要 all-to-all。

# 5. Action representation

第一版不要 MANO ActionToken。

直接使用最干净的：

[
\Delta h_j=h_{j,t+1}-h_{j,t}.
]

对于每条 edge，再计算：

法向运动：

[
v_{n,ij}
========

\Delta h_j^\top n_i^O
]

切向运动：

[
v_{t,ij}
========

\Delta h_j-v_{n,ij}n_i^O.
]

于是：

[
a_{ij}
======

[
\Delta h_j,
v_{n,ij},
v_{t,ij},
|\Delta h_j|
].
]

一共：

[
3+1+3+1=8D.
]

---

# 6. Cm 怎么生成

这是整个设计最关键的地方。

我建议继续保持现在这个结构：

[
a'*{ij}=E_A(a*{ij})
]

其中 ActionEncoder 全部：

```python
bias=False
```

然后：

[
\gamma_{ij}
===========

\sigma(E_G(R_{ij}))
]

relation 只作为 gate：

[
\tilde a_{ij}
=============

\gamma_{ij}\odot a'_{ij}.
]

最后：

[
\boxed{
C_{m,ij}
========

E_M(\tilde a_{ij})
}
]

MessageEncoder 也：

```python
bias=False
```

于是结构上严格保证：

[
\boxed{
\Delta h_j=0
\Rightarrow
C_{m,ij}=0
}
]

这条非常重要。

因为这样 (R_{ij}) 无论多强，都不能单独产生动态 Cm。

建议维度：

[
C_{m,ij}\in\mathbb R^{32}.
]

第一阶段不要扩成 128/256。

---

# 7. Object-side aggregation

第一版我建议**暂时保留当前 attention pooling**，不要现在上 SetTransformer。

对于一个 object point：

[
{C_{m,ij}}_{j=1}^{K}
]

先：

[
s_{ij}=E_s(C_{m,ij})
]

然后：

[
w_{ij}
======

\operatorname{softmax}*j(s*{ij})
]

最后：

[
\bar C_i
========

\sum_jw_{ij}C_{m,ij}.
]

再：

[
\boxed{
C_i^{obj}=W\bar C_i
}
]

projection 必须：

```python
bias=False
```

从而：

[
C_m=0
\Rightarrow
C^{obj}=0.
]

建议：

[
C_i^{obj}\in\mathbb R^{64}.
]

多指非线性 aggregation 暂时作为后续 ablation（消融实验，即替换某一模块比较影响），不要现在引入。

---

# 8. Effect Decoder

V0 我反而建议保持简单。

输入：

[
[o_i,n_i,C_i^{obj}]
]

再提供一个全局 interaction summary：

[
\bar C
======

\frac1{N_O}
\sum_i C_i^{obj}.
]

因此：

[
x_i=
[o_i,n_i,C_i^{obj},\bar C].
]

然后：

```text
Linear
GELU
Linear
GELU
Linear → 3
```

输出：

[
\Delta o_i.
]

暂时不用 PTv3 decoder。

因为我们第一阶段不是追求 SOTA，而是先判断：

> Cm 这个 bottleneck 到底能不能保留足够的 effect information。

如果 pointwise decoder 都能做到很好，那反而是很强的证据。

如果效果明显不够，再做：

[
C^{obj}+O
\rightarrow
\text{object-only PTv3}
\rightarrow
\Delta O.
]

# 12. 真正关键的 intervention

模型训练好以后，不是只测 GT。

固定：

[
O_t,H_t.
]

构造四个 action：

[
A^{GT}
]

[
A^{zero}=0
]

[
A^{reverse}=-A^{GT}
]

[
A^{shuffle}
===========

\operatorname{permute}_{handpoints}(A^{GT}).
]

分别得到：

[
C^{GT},C^{zero},C^{reverse},C^{shuffle}
]

以及：

[
\hat E^{GT},
\hat E^{zero},
\hat E^{reverse},
\hat E^{shuffle}.
]

必须报告：

[
EPE_{GT}
]

[
EPE_{zero}
]

[
EPE_{reverse}
]

[
EPE_{shuffle}.
]

理想：

[
\boxed{
EPE_{GT}
<
EPE_{zero},
EPE_{reverse},
EPE_{shuffle}
}
]

而且差距明显。

这才说明：

> 模型真的在使用 hand motion，而不是靠 object pose 猜 effect。

# 15. V0 结束的生死判据

我会把 V0 的结论压缩成三个问题：

[
\boxed{
1.\quad
C_m\text{ 是否保留足够 effect information？}
}
]

看：

[
EPE_{\rm Cm}\approx EPE_{\rm direct}.
]

---

[
\boxed{
2.\quad
C_m\text{ 是否真的依赖 action？}
}
]

看：

[
GT\ll zero/reverse/shuffle.
]

---

[
\boxed{
3.\quad
C_m\text{ 是否不是单纯 static contact map？}
}
]

固定：

[
O,H
]

改变：

[
\Delta H
]

必须得到明显不同：

[
C_m.
]

只有这三条都过了，才进入下一阶段：

[
\boxed{
\min_A D(C(A),C^*)
}
]

也就是用 Cm 反向优化动作。

**现在最应该做的不是再改架构，而是把这版 V0 固定住，删掉最后的跨 Task import，建立 direct baseline，然后正式跑完整 forward + intervention 实验。**
