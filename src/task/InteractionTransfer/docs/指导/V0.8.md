可以。那我建议下一版直接定成 **InteractionTransfer V0.8：单手右手 + 全量 transition + 20 epoch**。这次不改模型结构，只把训练流程正式化。

### 1. 这版什么都不改

模型仍然是：

[
A_j \rightarrow M_{ij} \rightarrow C_i^O \rightarrow \Delta O_i
]

明确不做：

* Slot Attention
* action-level aggregation
* 双手
* rigid-only training
* translation / rotation metric
* 新 decoder

当前 dataset 本来就是只选：

[
\text{right active}\land \text{left inactive}
]

所以继续保持右手单手即可。

评价指标只保留：

[
\boxed{
EPE=
\frac{1}{BN_O}
\sum_{b,i}
|\Delta o_{bi}^{pred}-\Delta o_{bi}^{GT}|_2
}
]

当前 `metrics.py` 已经有这个量，就是 `point_error_m`；不过它同时还计算 translation 和 rigid rotation，我建议 V0.8 单独写一个 `epe()`，避免每次 validation 还做没必要的 Kabsch/SVD。

---

## 2. “全量数据”怎么定义

这里我建议明确：

> **全量 = train split 中所有满足右手 active、左手 inactive 的 transition。**

而不是把 validation/test 也塞进训练。

现在小实验的问题是：

```python
max_transitions=64
```

或者默认：

```python
max_transitions=16
```

人为截了一小部分。

V0.8 改成：

```python
GRABOneStepDataset(
    ...,
    max_transitions=0,
)
```

当前 dataset 中 `max_transitions=0` 本身就代表**不截断**：

```python
if max_transitions:
    self.items = self.items[:max_transitions]
```

所以 dataset 核心逻辑甚至不需要改。

---

# 3. 必须按 sequence 划 Train / Val / Test

继续保持：

```text
GRAB sequences
      ↓
sequence-level split

80% Train
10% Validation
10% Test
```

绝对不能随机拆 transition，否则同一段动作的相邻帧会泄漏到 validation。

仓库里其实已经有 deterministic sequence split 的实现，默认就是：

```text
seed = 42
train = 0.8
val   = 0.1
test  = 0.1
```

不过现有 `build_cm_split.py` 输出的是：

```text
s1/xxx/right.npz
s1/xxx/left.npz
```

而 `GRABOneStepDataset` 接收的是：

```text
s1/xxx
```

所以我建议给 InteractionTransfer 单独生成：

```text
src/task/InteractionTransfer/splits/grab_seed42/
├── train.txt
├── val.txt
└── test.txt
```

里面每行只写：

```text
s1/sequence_x
s1/sequence_y
s2/sequence_z
```

不写左右手。

dataset 自己仍然只读取 `right.npz`。

---

# 4. 把 step-based training 正式改成 epoch-based

这是这次最重要的代码改动。

当前训练是：

```python
for step in range(1, steps + 1):
```

而且 DataLoader 用完后重新生成 iterator，所以所谓 1000 steps 和“数据过了多少遍”没有直接关系。

V0.8 改为真正的：

```python
for epoch in range(1, epochs + 1):
    model.train()

    for batch in train_loader:
        ...
```

于是：

[
\boxed{1\ epoch=所有训练 transition 恰好过一遍}
]

你要的就是：

```text
20 epochs
```

而不是人为猜：

```text
5000 steps
10000 steps
```

现在是固定：

```python
batch_size=1
```

我建议改成可配置：

```python
train_loader = DataLoader(
    train_dataset,
    batch_size=args.batch_size,
    shuffle=True,
    num_workers=args.num_workers,
    pin_memory=True,
    persistent_workers=args.num_workers > 0,
    drop_last=False,

```

第一轮建议：

```text
batch_size = 4
num_workers = 4
```

你那边如果是 A100，可以再测试：

```text
4 → 8
```

不要一开始为了 batch size 改任何网络。

# 6. 训练 loss 不需要跟着改

这里要区分：

### Train objective

当前：

```python
flow_loss = SmoothL1
```

继续用：

[
L=\operatorname{SmoothL1}(\Delta O^{pred},\Delta O^{GT})
]

### Model selection / report

只看：

[
\boxed{EPE}
]

也就是：

```text
train_loss
val_epe
```

不要为了“只看 EPE”连训练 loss 也一起改掉，那会同时改变两个实验变量。

# 7. 每个 epoch 做一次 Validation

流程直接：

```text
Epoch 1
  train full epoch
  ↓
  val EPE
  ↓
  save if best

Epoch 2
  train full epoch
  ↓
  val EPE
  ↓
  save if best

...

```

输出类似：

```text

Epoch 02/20 | train_loss=0.00184 | val_EPE=14.17 mm
...

...
```

```text
Epoch 11 best checkpoint
```

而不是 Epoch 20。

# 8. checkpoint 不保存 Frozen PTv3

这个必须继续保持现在 V0.7 的思路。

DenseToken/PTv3 是冻结的，而且很大。当前 best checkpoint 已经只复制 `requires_grad=True` 的参数。

正式 checkpoint 建议保存：

```python
{
    "epoch": epoch,
    "best_val_epe": best_val_epe,
    "model": trainable_state_dict,
    "optimizer": optimizer.state_dict(),
    "config": {...},
    "split": {...},
}
```

目录：

```text
outputs/InteractionTransfer/v08_full_20ep/
├── best.pt
├── last.pt
├── metrics.json
├── config.json
└── split.json
```

`metrics.json`：

```json
{
  "epoch": [1, 2, 3],
  "train_loss": [0.01, 0.005, 0.003],
  "val_epe_mm": [20.3, 14.7, 11.2]
}
```

# 9. 我建议顺便把 Frozen DenseToken 做 cache

这个对于“全量 × 20 epoch”很重要。

现在每一个 training step 都会重新跑：

```text
object + hand
     ↓
Frozen PTv3
     ↓
DenseToken
     ↓
edge features
```

虽然 `FrozenDenseStateEncoder.forward()` 已经是 `@torch.no_grad()`，而且整个 encoder 强制处于 eval 状态，但 **20 epoch 就意味着同一个 sample 的 frozen PTv3 重复算 20 次**。

这是纯浪费。

因为下面这些东西对一个 transition 来说都是固定的：

```text
object_points
object_normals
edge_idx
edge_valid
dense_edge
contact_prob
geom
hand_flow
object_flow
```

所以加：

```text
precompute_static.py
```

一次性：

```text
raw GRAB
   ↓
Frozen DenseToken
   ↓
static cache
```

以后 20 epoch：

```text
static cache
    ↓
RelationEncoder
    ↓
InteractionMessage
    ↓
ObjectAggregator
    ↓
EffectDecoder
```

**这不会改变模型，只是把冻结网络的重复计算提前。**

我认为全量训练最好直接把这个一起做掉。

---

# 10. 模型代码建议拆成两个 forward

不要维护两个不同模型。

`model.py` 改成：

```python
def encode_static(...):
    ...
    return {
        "object_points": ...,
        "object_normals": ...,
        "edge_idx": ...,
        "edge_valid": ...,
        "dense_edge": ...,
        "geom_contact": ...,
    }
```

然后：

```python
def forward_core(
    object_points,
    object_normals,
    edge_idx,
    edge_valid,
    dense_edge,
    geom_contact,
    hand_flow,
):
    ...
```

普通 forward：

```python
static = self.encode_static(...)
return self.forward_core(**static, hand_flow=hand_flow)
```

cache training：

```python
return self.forward_core(
    ...cached tensors...
)
```

这样可以做一个 sanity check：

[
\boxed{
\Delta O_{\text{raw forward}}
=============================

\Delta O_{\text{cached forward}}
}
]

允许浮点误差，比如：

```text
max abs diff < 1e-5
```

确认 cache 没改变模型。
