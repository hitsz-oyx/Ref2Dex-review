# 四、正式 Test 只用 EPE

定义：

[
EPE
===

\frac{1}{N_ON}
\sum_{n=1}^{N}
\sum_{i=1}^{N_O}
\left|
\Delta o_{ni}^{pred}
--------------------

\Delta o_{ni}^{GT}
\right|_2
]

统一输出 mm。

不要再算：

```text
translation error
rotation error
rigid fitting error
```

Object Flow EPE

# 五、需要跑四种 Action Intervention

保持相同：

[
O_t,H_t
]

只改变：

[
\Delta H
]

### GT

真实动作：

[
\Delta H^{GT}
]

回答：

> 正常情况下模型预测得准不准？

---

### Zero

[
\Delta H^{zero}=0
]

回答：

> 如果没有动作，模型还能不能凭静态场景瞎猜 object flow？

我们期望：

[
EPE_{GT}\ll EPE_{zero}
]

---

### Reverse

[
\Delta H^{reverse}
==================

-\Delta H^{GT}
]

回答：

> 模型是否真的理解动作方向？

期望：

[
EPE_{GT}\ll EPE_{reverse}
]

---

### Cross-sample

同一个：

[
O_t,H_t
]

换成另一个 test transition 的 action：

[
\Delta H^{cross}
]

回答：

> 模型是否依赖正确的 state-action pairing？

期望：

[
EPE_{GT}\ll EPE_{cross}
]

# 十、Layer 2：Edge Interaction (M_{ij})

这是最重要的一层。

当前：

[
M_{ij}\in\mathbb R^{32}
]

先定义：

[
s_{ij}
======

|M_{ij}|_2
]

然后用：

```text
edge opacity / thickness
```

表示强度。

也就是说：

```text
弱 M_ij
→ 边细、透明

强 M_ij
→ 边粗、明显
```

这样能够直接看到：

> 模型认为哪些 hand-object edge 真正在传递 interaction。

---

# 十一、不要默认把所有 512×16 条边全显示

因为总共：

[
512\times16=8192
]

条 edge。

全部打开会非常乱。

所以做两个模式。

### Global edge mode

只显示：

```text
Top-K strongest M edges
```

例如：

```text
Top 100
Top 300
Top 500
```

---

### Selected object point mode

鼠标选择 object point (i)。

只显示：

[
M_{i1},\dots,M_{i16}
]

也就是它对应的 16 个 hand neighbors。

这个是最适合调试的：

```text
               hand j1
                 ╲
                  ╲
hand j2 ───── object i
                  ╱
                 ╱
               hand j3
```

---

# 十二、同时把 attention 显示出来

我们现在：

[
C_i^O
=====

\operatorname{Agg}*j M*{ij}
]

里面实际上有 attention weight：

[
\alpha_{ij}.
]

所以选择一个 object point 后，旁边显示：

```text
Object point: #183

neighbor    ||M_ij||    attention
---------------------------------
j=812        1.54        0.41
j=301        1.21        0.27
j=520        0.82        0.16
...
```

这样就能区分：

> edge message 本身很强

和：

> aggregation 真正选择了这条 edge。

这两个不能混在一起。

# 十三、Layer 3：Object Field (C_i^O)

当前：

[
C_i^O\in\mathbb R^{64}.
]

这是我们压缩后的主要中间表示。

第一版先做两种模式。

### Norm heatmap

[
s_i=|C_i^O|_2
]

映射到 object point color。

它回答：

> 物体哪些位置承担了较强的 interaction representation？

---

### PCA-RGB

再增加：

[
C_i^O\in\mathbb R^{64}
\rightarrow
PCA
\rightarrow
z_i\in\mathbb R^3
]

PCA 就是“主成分分析”，把 64 维特征压到最主要的三个变化方向。

然后：

```text
PCA dim 1 → R
PCA dim 2 → G
PCA dim 3 → B
```

于是：

> feature 类似的 object points，会有类似颜色。

这比只看 norm 能看到更多结构信息。

---

# 十四、M 也可以做 PCA-RGB

同理：

[
M_{ij}\in\mathbb R^{32}
\rightarrow
PCA
\rightarrow
RGB.
]

所以 Viewer 的：

```text
Edge display:
○ Message Norm
○ Message PCA-RGB
○ Attention
```

三种模式是比较合理的。

这个非常有价值。

## 我建议把这版定义成两个明确 gate

### Quantitative Gate

[
\boxed{
EPE_{GT}^{test}
\ll
EPE_{Zero/Cross/Reverse}^{test}
}
]

回答：

> 模型是不是正确使用 action。

### Representation Gate

Viser 里应该能看到：

```text
Hand action change
        ↓
M edge pattern changes
        ↓
C_obj spatial field changes
        ↓
Pred object flow changes
```

也就是：

[
\boxed{
\Delta H
\rightarrow
M
\rightarrow
C^O
\rightarrow
\Delta O
}
]

这条因果链在中间 representation 上也是可观察的。

这两件事跑通以后，我们才有充分理由说当前 forward InteractionTransfer 已经稳定，再进入 inverse，而不是继续往网络里加 Slot 或新的聚合模块。
