### 1. 现在证明的是“整体动作重要”，还没证明“局部 interaction 重要”

结果里：

[
EPE_{point\ shuffle}=4.89\text{ mm}
]

[
EPE_{mean\ flow}=4.89\text{ mm}
]

甚至比：

[
EPE_{GT}=5.44\text{ mm}
]

还略好。

而之前 action-field diagnostic 已经发现 hand point flow 的 local ratio 只有约：

[
0.0599
]

也就是说 one-step hand motion 绝大部分接近整体运动，局部 point-to-point 差异很小。

所以目前更准确的结论是：

[
\boxed{
\text{模型知道“手往哪个方向整体运动”很重要}
}
]

但还没有证明：

[
\boxed{
C_{m,ij}
\text{ 真正在编码局部 hand-object interaction}
}
]

这恰好是我们这个工作的核心。

---

### 2. DirectEdge baseline 现在还不能算训练公平

现在记录的是：

[
L_{Cm}:0.06017\rightarrow0.000811
]

而：

[
L_{DirectEdge}:0.04140\rightarrow0.010756
]

两者都训练 1000 steps，但 DirectEdge 明显还没有收敛到 Cm 的程度。

于是目前：

[
EPE_{Cm}=5.44\text{ mm}
]

[
EPE_{DirectEdge}=34.53\text{ mm}
]

得到：

[
\frac{EPE_{Cm}}{EPE_{DirectEdge}}=0.158
]

虽然看起来非常漂亮，但我不会把它当作“Cm bottleneck 比 unrestricted direct 更强”的结论。

因为 baseline 本身没训好。

更公平的做法应该是：

```text
Cm：
训练到 convergence / best validation

DirectEdge：
训练到 convergence / best validation

再比较各自 best checkpoint
```

而不是强制相同步数。

## 我认为接下来最值得做的是 V0.7：局部交互验证

不要改网络。

先把 hand flow 分解成：

[
\Delta h_j
==========

\underbrace{\bar v}*{整体平移}
+
\underbrace{\delta h_j}*{局部差异}
]

现在的 `mean_flow` 就相当于：

[
\Delta h_j^{mean}=\bar v.
]

既然它和 GT 一样好，我们下一步就应该专门问：

> 模型到底有没有利用 (\delta h_j)？

但比 point shuffle 更物理的做法是进一步做 **rigid twist decomposition（刚体速度分解，即把手的动作拆成平移和旋转）**：

[
\boxed{
v_j=t+\omega\times(h_j-c)
}
]

分别构造：

```text
GT
translation-only
rotation-only
wrong translation
wrong rotation
cross-sample full action
```

尤其筛一批：

[
|\omega|
]

大的 hand-rotation transitions。

如果这些样本上：

[
EPE_{GT}
\ll
EPE_{translation-only}
]

那才能说明模型真的使用了：

[
\boxed{\text{不同 hand point 的空间运动结构}}
]

而不只是整只手的平均速度。

这个实验比继续随机 point shuffle 有价值很多。

---

### 同时把 DirectEdge 训到收敛

我建议直接改 worker：

```text
最大 steps = 5000 或 10000
每 N steps eval
保存 best validation checkpoint
early stopping
```

Cm 和 DirectEdge **各训各的**，最后比较：

[
EPE_{Cm}^{best}
\quad vs\quad
EPE_{DirectEdge}^{best}.
]

当前 `train_eval_v05.py` 还是固定 step 后直接拿最后模型 evaluation，没有 best checkpoint 机制。

### offline cache 可以开始做，但它是工程优化，不是下一个科学问题

当前目录里依然没有 `dataset_cached.py / precompute_static.py` 这一层，V0.6.1 记录里也明确还是“offline static cache 尚未实现”。

我建议现在可以实现，因为下一步要跑 5000～10000 step：

```text
raw transition
    ↓ 一次性
Frozen DenseToken
    ↓
dense_edge
contact_prob
edge_idx
edge_valid
    ↓ save
```

正式训练就不再反复跑 91M PTv3。

这样可以大幅提高 V0.7 实验速度。
