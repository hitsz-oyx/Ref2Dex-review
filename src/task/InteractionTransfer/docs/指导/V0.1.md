浏览了。当前 `oyx` 分支最新提交已经是 `7e25b090... 实现 InteractionTransfer V0 动态交互传递`，新 Task 已经建在 `src/task/InteractionTransfer/`。

整体方向**和我们刚才讨论的计算图已经一致**：

[
(O,H)\rightarrow R_{ij},
\qquad
(R_{ij},\Delta h_j)\rightarrow C_{m,ij},
]

然后

[
{C_{m,ij}}_j
\rightarrow C_i^O
\rightarrow \Delta o_i.
]

代码里也是先构 KNN hand-object edges，再构 relation、action feature、dynamic message，最后聚合到 object field，并且 Effect Decoder 看不到 hand/relation edge。

不过我认为**当前版本还只是 skeleton（骨架），还不能开始正式评价 Cm 路线**。有几个地方必须先修：

1. **最大问题：现在根本没有真的使用 DenseToken。** `FrozenDenseStateEncoder` 只是两个 `Linear(6→64→64)` 的 MLP，而且创建后立刻冻结。也就是说它们是**随机初始化后冻结的随机特征映射**，没有加载现有 DenseToken checkpoint，也没有 PTv3，更没有 pretrained correspondence 信息。

   现在实际是：
   [
   (xyz,normal)\xrightarrow{\text{random frozen MLP}}z_O,z_H
   ]
   而不是我们设计的：
   [
   (O,H)\xrightarrow{\text{pretrained DenseToken}}z_O,z_H.
   ]
   这个是 **P0 必改**。应该把 `correspondence_ptv3_v2` 里必要的 PTv3 backbone、point feature、edge head checkpoint loader **复制进 InteractionTransfer**，但不要跨 Task import。

2. **`Cm_{ij}` 的 zero-preserving 设计做对了。** 当前 action path 和 message path 都 `bias=False`：
   [
   \Delta h=0\Rightarrow C_{m,ij}=0.
   ]
   `RelationEncoder` 只能通过 sigmoid gate 调制 action，不能直接塞到 Cm 中。 这一点应该保留。

3. **但是 zero-preserving 在 `C_obj` 这里被破坏了。** 当前：

   ```python
   self.proj = nn.Linear(message_dim, object_dim)
   ```

   默认带 bias。所以即使：
   [
   C_{m,ij}=0,
   ]
   聚合后 `pooled=0`，仍然有：
   [
   C_i^O=b_{\rm proj}\neq0.
   ]

   我建议直接：

   ```python
   self.proj = nn.Linear(message_dim, object_dim, bias=False)
   ```

   至少保证：
   [
   C_m=0\Rightarrow C^O=0.
   ]

4. **当前 aggregator 还不是我们说的 multi-contact interaction。** 现在只是：
   [
   w_{ij}=\operatorname{softmax}(\operatorname{MLP}(C_{m,ij}))
   ]
   [
   C_i^O=\sum_jw_{ij}C_{m,ij}.
   ]

   这意味着各 edge 在计算 score 之前**互相没有通信**。所以“两指共同形成 pinch”这种高阶关系仍然很难表达。第一轮 forward capacity 可以暂时保留；如果 V0 能学，再升级成 1–2 层 Set Attention，不要现在增加复杂度。

5. **Effect Decoder 太弱，同时又存在 shortcut（捷径学习）风险。** 当前只是：
   [
   [o_i,n_i,C_i^O,\operatorname{mean}(C^O)]
   \rightarrow MLP\rightarrow\Delta o_i.
   ]

   好处是 bottleneck 很干净；坏处是对于“局部手指作用 → 整体刚体运动”，一个 global mean + MLP 可能不够。另外 decoder 可以直接利用 xyz/normal 学 sequence/pose correlation，从而弱化 (C^O)。

   所以**第一版暂时别改 decoder**，反而要靠 intervention 验证它有没有绕过 Cm。

6. **当前 edge builder 是合理的 V0。** 对每个 object point 取 `K=16` 最近 hand points，同时 `radius=5 cm` 决定有效 edge。 这个先不要复杂化。以后再考虑 current+future candidate graph。

7. **Dataset 和我们之前 PointWorld V0.2A 还没有完全对齐。** 当前直接：

   * object 下采样到 1024；

   * hand 下采样到 256；

   * 只读右手；

   * 用 `linspace` 固定取点；

   * 当前 object centroid 做中心化。

   这个可以做 smoke test，但正式和 PointWorld V0.2A 比 EPE 时，**必须统一数据、点数、transition、坐标系和 train/eval split**，否则比较没有意义。

8. **目前还没真正训练。** research log 明确写的是：仅合成张量通过 shape/finite 检查，并验证 zero hand-flow 时 edge message 为 0；真实 GRAB cache 尚未启动，因此没有 EPE。 当前 `diag_forward.py` 也只做了这两个 sanity。

### 我建议现在下一步不要继续扩架构

先把 V0 修成：

```text
                 O_t , H_t
                     │
                     ▼
        copied pretrained DenseToken
                 frozen
                     │
              zO_i , zH_j
                     │
          + explicit geometry
                     ▼
                   R_ij
                     │
                     │ gate
Δh_j → zero-preserving ActionEncoder
                     │
                     ▼
                  Cm_ij
                     │
              attention pool
                     ▼
                  C_obj_i
                     │
                     ▼
         simple Object Decoder
                     │
                     ▼
                   ΔO_i
```

然后只跑三个实验：

[
\textbf{A. Direct baseline}
\quad
(O,H,\Delta H)\rightarrow\Delta O
]

[
\textbf{B. InteractionTransfer}
\quad
(O,H,\Delta H)\rightarrow C_m\rightarrow\Delta O
]

以及固定 (O,H) 后：

[
\Delta H_{\rm GT},;0,;-\Delta H_{\rm GT},;\text{shuffle}(\Delta H).
]

我认为**现在最优先要让 Codex 改的是“真正接入现有 DenseToken checkpoint”，而不是继续研究 inverse 或 SetTransformer**。当前代码已经把新的思想骨架搭起来了，但 `FrozenDenseStateEncoder` 用随机冻结 MLP 这件事会让第一轮实验失去我们原本设计 (R_{ij}) 的意义。
