## 已经修正的部分

### 1. 旧 (C_m) checkpoint 可以热启动

现在新增了：

```yaml
meta:
  warm_start_checkpoint: ...
  freeze_cm_encoder: true
  loss_object_weight: 0.0
  loss_hand_weight: 1.0
```

加载旧 checkpoint 时只读取形状和名称兼容的旧参数，新加入的：

* `hand_context_encoder`
* `hand_token_score`
* `hand_articulation_decoder`
* `wrist_decoder`

保持随机初始化。不会恢复旧 optimizer、scheduler 和训练步数。随后只将这四部分设置为可训练，原来的 (C_m) encoder 和物体流 decoder 全部冻结。这个实现符合我们前面确定的方案。

### 2. (C_m\rightarrow F_m) 接口已经独立出来

现在有明确的：

```python
decode_hand_from_cm(
    cm_tokens,
    z_hand,
    hand_points,
    hand_normals,
)
```

它只使用：

[
C_m,\quad H_t,\quad Z_t^h
]

不会读取：

* GT `hand_flow`
* GT `wrist_delta`
* `cm_hand_flow`
* 未来手几何

输出包含：

[
\hat F_m,\quad
\hat F_m^{rigid},\quad
\hat F_m^{art},\quad
\hat R_w,\quad
\hat t_w
]

因此这条路径现在是干净的。

### 3. (C_p) 已经真正复用了预训练 (C_m) 空间

原来 `Cp` 自己建立：

```text
teacher_encoder
teacher_slots
hand_decoder
```

的问题已经被删除。

现在 `FrozenCmHandDecoder` 会直接读取完整的 (C_m) checkpoint，构建 `CmFlowModel`，冻结所有参数，并使用原来的 dense encoder 计算当前手特征，再调用原始的 `decode_hand_from_cm()`。

闭环现在是：

[
C_p+Z_t^h+H_t
\rightarrow
\hat C_m
\overset{\text{Frozen }D_m}{\longrightarrow}
\hat F_m
]

其中闭环生成器有自己独立的：

```text
closure_hand_state
cp_to_hand
closure_cm_slots
```

不会与冻结 decoder 共用 hand encoder，因此生成器和 decoder 无法共同篡改 (C_m) 编码协议。

### 4. (C_p) effect decoder 不再简单平均 Slot

之前是：

```python
decoded.mean(dim=2)
```

现在每个物体点会对不同 (C_p) Slot 预测 mixture logit，再经 softmax 加权输出接触和物体流：

[
a_{ik}=\operatorname{softmax}*k(s*{ik})
]

[
\hat c_i=\sum_k a_{ik}\hat c_{ik}
]

[
\hat F_{o,i}=\sum_k a_{ik}\hat F_{o,ik}
]

这个修改是正确的。

### 5. 闭环复用了 (C_m) 的加权手流 Loss

`Cp/runner.py` 现在已经复用：

* wrist translation loss；
* wrist rotation loss；
* contact 加权 articulation loss；
* articulation magnitude 加权；
* 全手低权重保护。

不再是之前所有1538点直接等权 SmoothL1。

Stage 5 也补充了：

```text
wrist_delta
hand_to_obj_min_dist
```

因此所需监督字段已经齐全。

`Cp/configs/baseline.yaml` 固定写着：

```text
hand_flow_epe_p90_mm
```

没有 `obj_flow_epe_mm`。

所以现在按照文档命令运行：


## 问题二：(C_p) Slot Attention 没有屏蔽无效物体点

Stage 5 将不足512个候选点的位置填成零，并用：

```python
obj_valid_mask
```

标记。

但目前 `encode_cp()` 直接把全部512个点送入 Slot Attention：

```python
effect = torch.cat([...], dim=-1)
return self.cp_slots(self.cp_encoder(effect))
```

没有使用 `obj_valid_mask`。

由于 MLP 有 bias，零填充点经过 `cp_encoder` 后不一定还是零。如果一个样本有效点很少，大量 padding token 可能参与 Slot 聚合，导致 (C_p) 学到填充模式。

需要让 Slot Attention 支持 mask，例如：

```python
def forward(
    self,
    inputs: torch.Tensor,
    valid_mask: torch.Tensor | None = None,
):
    normalized = self.norm_inputs(inputs)
    keys = self.to_key(normalized)
    values = self.to_value(normalized)

    ...

    logits = torch.einsum("bkd,bnd->bkn", queries, keys) * self.scale

    if valid_mask is not None:
        logits = logits.masked_fill(
            ~valid_mask[:, None, :],
            torch.finfo(logits.dtype).min,
        )

    assignment = torch.softmax(logits, dim=1)

    if valid_mask is not None:
        assignment = assignment * valid_mask[:, None, :]

    weights = assignment / assignment.sum(
        dim=-1,
        keepdim=True,
    ).clamp_min(1e-8)
```

然后：

```python
return self.cp_slots(
    self.cp_encoder(effect),
    valid_mask=batch["obj_valid_mask"],
)
```

这个问题不会立刻报错，但会实质影响 (C_p) 的表示质量，建议训练 (C_p) 前修掉。

# 另外三个次要问题

### 1. 应检查 (C_m) Slot 数量

当前只检查了：

* `cm_dim`
* `dense_token_dim`

但没有检查：

[
K_m^{closure}=K_m^{pretrained}
]

最好再加入：

```python
if int(meta.num_cm_tokens) != self.cm_hand_decoder.cm_model.num_cm_tokens:
    raise ValueError(...)
```

当前都是16，所以暂时不会出错。

### 2. 多卡训练可能访问不到 `model.cm_hand_decoder`

Runner 中直接使用：

```python
cm_decoder = model.cm_hand_decoder
```

如果 `model` 被 DDP 包装，通常应该：

```python
from src.base.checkpoint import unwrap_model

cm_decoder = unwrap_model(model).cm_hand_decoder
```

单卡没有问题，多卡需要修。

### 3. 普通 (C_m) 训练的默认 best metric 被全局改成了 hand EPE

`Cm/config.py` 的默认指标从：

```text
val/flow_mse
```

改成：

```text
val/hand_epe_mm
```

这个对 hand-decoder warm start 是正确的，但会同时改变普通联合训练 `baseline.yaml` 的 checkpoint 选择逻辑。更安全的做法是：

* `Cm/config.py` 保持原默认 `val/flow_mse`；
* `hand_decoder_warm_start.yaml` 单独设置 `val/hand_epe_mm`。

# 总体判断

这次改动已经解决了上一版最核心的问题：

[
\boxed{
C_p\text{ 现在确实在预训练的 }C_m\text{ 空间中生成动作，}
\quad
C_m\rightarrow F_m\text{ 的完整解释器也被冻结。}
}
]

现在不是架构需要推倒重来，而是补几个工程边界。

优先级建议：

1. 修复 closed-loop 的 `metric_for_best`；
2. 给 (C_p) Slot Attention 加 `obj_valid_mask`；
3. 增加 `num_cm_tokens` 检查；
4. 修复 DDP 下的 `model.cm_hand_decoder`；
5. 再开始正式训练 warm-start hand decoder 和 (C_p)。

目前没有看到该提交对应的自动化状态检查，因此以上结论来自代码审查，还没有替代实际的单样本 overfit 和完整训练运行验证。
