# 你刚才问的手点权重，仓库里已经实现了

当前已经把总手点流拆成：

[
F_m^{GT}=F_m^{rigid,GT}+F_m^{art,GT}
]

其中手腕刚体运动单独监督，点级权重只主要用于 articulation flow。

当前权重实际是：

[
w_j=
0.2
+
1.5,w_j^{contact}
+
0.8,w_j^{art}
]

其中：

[
w_j^{contact}
=============

\exp\left[
-\frac12
\left(
\frac{d_j}{0.005}
\right)^2
\right]

[
w_j^{art}
=========

\operatorname{clip}
\left(
\frac{|F_j^{art,GT}|}{0.01},

\right)

* 最大截断到 (3.0)；

# 但目前有几个重要问题

## 1. 当前还不是真正的“手动作自回归训练”

当前训练只做单步：

[
H_t
\rightarrow
\hat F_{m,t}
\rightarrow
\hat H_{t+\Delta}
]

Runner 中没有：

[
\hat H_{t+\Delta}
\rightarrow
\hat H_{t+2\Delta}
]

这样的多步 self-fed loss。模型只输出当前 pair 的一次 `pred_hand_flow`。

当前 viewer 中的 trajectory rollout 主要是把**预测物体点**传入下一步；下一步使用的手点仍来自 dataset 的真实 `hand_points`。

因此准确称呼应该是：

[
\boxed{\text{单步手点流重建监督}}

而不是真正的 hand autoregressive rollout training。

## 2. 当前 (C_p) 没有真正复用已有 (C_m) 空间

`CpHumanClosureModel` 又单独创建了：

```python

teacher_slots
hand_state
hand_decoder
```

也就是说它重新学习了一套：

[
F_m\rightarrow C_m^{teacher}\rightarrow F_m
]

而不是读取当前 `CmFlowHead` 训练出来的 `cm_tokens` 和 hand decoder。

其 teacher 输入甚至只是：

[

hand_points,
hand_normals,
hand_flow,
zeros
]

没有现有 (C_m) 使用的：

* `z_hand`
* dense contact
* wrist delta
* 现有 hand-motion encoder

所以当前 `Cp` 中的 (C_m) 和已经训练好的 `Cm` 中的 (C_m)，实际上是两套不同 latent space。

[
\boxed{
C_m^{Cp}\neq C_m^{pretrained}
}
]

这是目前最需要修正的地方。

---

## 3. `closed_loop` 没有真正冻结完整的 (C_m\rightarrow F_m) decoder

当前 closed-loop 只加载并冻结：

```python
("hand_decoder",)
```

但实际 `decode_hand()` 还依赖：

```python
hand_state
```

来编码 (H_t)，并计算每个手点对 (C_m) 的注意力。

更严重的是，`closure_cm()` 也共用了同一个 `hand_state`。

因此现在：

* 最后一层 `hand_decoder` 被冻结；
* `hand_state` 没有一起加载并冻结；
* (C_m\rightarrow F_m) 的完整语义解释器仍可变化；
* generator 和 decoder 仍然可能共同改变编码协议。

正确做法应该拆成：

```text
decoder_hand_state       frozen
hand_decoder_attention   frozen
hand_articulation_decoder frozen
wrist_decoder            frozen

closure_hand_state       trainable
Cp→Cm generator          trainable
```

不能共用一个 `hand_state`。

---

## 4. `Cp` 的 hand decoder 仍是全点等权监督

`Cp/runner.py` 的 `hand_decoder` 和 `closed_loop` 阶段目前直接使用：

```python
F.smooth_l1_loss(predicted_hand_flow, batch["hand_flow"])
```

所有1538个手点等权，没有：

* wrist/articulation 分解；

* contact 权重；

* articulation 权重；

* 全局低权重保护。

所以你前面担心的“并不是每个手点都同等关键”，在 `Cm` 里已经处理了，但在 `Cp` 闭环里又退回了全点等权。

最合理的方案不是在 `Cp` 中重新实现一份，而是：

[
\boxed{
Cp\text{ 直接调用并冻结现有 }Cm\text{ 的完整 hand decoder}
}
]

同时复用 `CmActionRunner` 中的 wrist/articulation 加权 loss。

---

## 5. 当前物体点流 decoder 仍存在 GT hand-flow 旁路

现有 (C_m) object decoder 除了使用 `cm_tokens`，还显式使用：

[
cm_hand_flow
============

W^{cm}F_m^{GT}
]

因此当前的：

[
C_m\rightarrow \hat F_o
]

并不是严格只靠 (C_m) token，真实手点流还通过 `cm_hand_flow` 直接送进了 object decoder。

这意味着：

> 当前物体点流预测很好，并不能完全证明 `cm_tokens` 自己包含了全部动作信息。

现在新增的：

[
C_m+H_t\rightarrow\hat F_m
]

反而是更干净的 (C_m) 验证方式，因为 hand decoder 没有直接读取 GT hand flow。

后续若要做：

[
C_p\rightarrow C_m\rightarrow F_o
]

应将 object decoder 输入中的 `cm_hand_flow` 改成：

[
\widehat{cm_hand_flow}
]

即由预测的：

[
\hat F_m
]

根据 slot weights 聚合获得，不能继续使用 GT。

---

## 6. 当前 (C_p) decoder 对所有 slots 直接平均

当前 (C_p) effect decoder 是：

```python
decoded = cp_decode(...)
pred = decoded.mean(dim=2)
```

也就是每个 object point 对8个 (C_p) slot 的输出等权平均。

这样没有真正利用：

* slot与object point的位置关系；
* slot assignment；
* 每个点对不同 (C_p) slot 的重要性。

容易造成所有 (C_p) slots 输出类似信息。

更合适的是像现有 (C_m) object decoder 一样预测：

[
a_{ik}=\operatorname{softmax}*k(s*{ik})
]

然后：

[
\hat F_{o,i}
============

\sum_k a_{ik}\hat F_{o,ik}
]

而不是简单 `.mean(2)`。

# 一、不要直接使用 `train.resume`

当前 `BaseRunner` 恢复训练时会完整执行：

```python
unwrap_model(self.model).load_state_dict(checkpoint["model"])
```

也就是严格加载整个模型。

而 `CmFlowModel.load_state_dict()` 虽然内部先用 `strict=False`，但最终仍会检查所有非 `dense_encoder` 的缺失参数，并在 strict 模式下报错。

旧 checkpoint 没有新增的 hand decoder 参数，因此：

```yaml
train:
  resume: old_cm_checkpoint.pt
```

大概率会因为缺少以下参数失败：

```text
head.hand_context_encoder.*
head.hand_token_score.*
head.hand_articulation_decoder.*
head.wrist_decoder.*
```

所以这里应该做的是：

[
\boxed{\text{warm start（权重热启动），而不是 resume（完整恢复训练）}}
]

`warm start` 的意思是只加载形状匹配的旧权重，不加载旧 optimizer、scheduler 和训练步数。

# 三、增加一个专用 legacy warm-start loader

建议不要改通用 `BaseRunner`，而是在 `CmActionRunner` 或 `CmFlowModel` 中增加专门函数。

```python
from pathlib import Path

import torch


def load_legacy_cm_warm_start(
    model: torch.nn.Module,
    checkpoint_path: str | Path,
) -> None:
    payload = torch.load(
        Path(checkpoint_path),
        map_location="cpu",
    )
    checkpoint_state = payload.get("model", payload)
    current_state = model.state_dict()

    compatible_state = {
        key: value
        for key, value in checkpoint_state.items()
        if key in current_state
        and current_state[key].shape == value.shape
    }

    incompatible = model.load_state_dict(
        compatible_state,
        strict=False,
    )

    allowed_new_prefixes = (
        "head.hand_context_encoder.",
        "head.hand_token_score.",
        "head.hand_articulation_decoder.",
        "head.wrist_decoder.",
        "dense_encoder.",
    )

    unexpected_missing = [
        key
        for key in incompatible.missing_keys
        if not key.startswith(allowed_new_prefixes)
    ]

    if unexpected_missing:
        raise RuntimeError(
            "Legacy Cm checkpoint unexpectedly misses old parameters: "
            f"{unexpected_missing}"
        )

    print(
        f"Warm-started {len(compatible_state)} tensors from "
        f"{checkpoint_path}"
    )
    print(
        "New hand decoder parameters initialized from scratch: "
        f"{incompatible.missing_keys}"
    )
```

配置中另加：

```yaml
meta:
  warm_start_checkpoint: outputs/train/cm_action/checkpoint_best.pt
  freeze_cm_encoder: true
```

而不是使用：

```yaml
train:
  resume: ...
```

# 六、旧 (C_m) 可能解不出好的 (F_m)

这确实存在风险。

旧 object decoder 除了使用 `cm_tokens`，还直接使用：

[
cm_hand_flow
============

W^{cm}F_m^{GT}

因此旧训练可能出现：

> object flow 预测很好，但部分手动作信息主要由显式 `cm_hand_flow` 提供，未必全部压进 `cm_tokens`。

所以第一阶段只训练 decoder，实际上就是在做一个诊断：

\rightarrow
\hat C_m
\rightarrow
D_m^{frozen}

确实没有保留足够的动作信息。

```text
contact + object flow
```

当前 (C_p) 的 effect encoder 本来就是从：

[
[x_i,n_i,c_i,F_{o,i}]
]

直接构造 (C_p)，不依赖新的 (C_m\rightarrow F_m) decoder。

所以：

[
\boxed{
C_p\text{ 的 effect 阶段可以先训练，只有 closed-loop 阶段需要等待 }D_m
}
]

暂时不要开始：

[
C_p+H_t\rightarrow C_m\rightarrow F_m
]

因为此时还没有可靠、冻结的 (C_m\rightarrow F_m) 解释器。

---

# 九、推荐实际顺序

```text
1. 加 legacy warm-start 加载器
             ↓
2. 加载旧 Cm checkpoint
             ↓
3. 冻结旧 Cm encoder / slots / object decoder
             ↓
4. 只训练新增 Cm→Fm decoder
             ↓
5. 查看 GT / Pred future hand
             ↓
6. 若结果好：直接冻结并用于 Cp
             ↓
7. 若结果差：小学习率解冻 Cm encoder + slots
```

与此同时：

```text
独立训练 Cp effect autoencoder
```

最后二者汇合：

```text
trained Cp encoder
        +
old-Cm-space pretrained hand decoder
        ↓
Cp + Ht → Cm → Fm
```

---

## 最关键的判断

你现在手里的旧 checkpoint **不是没用了**。相反，它应该作为当前 (C_m) 空间的起点。

不要：

[
\text{随机初始化整个新模型重新训练}
]

而应该：

[
\boxed{
\text{旧 }C_m\text{ checkpoint 热启动}
\rightarrow
\text{先只训练新增 hand decoder}
\rightarrow
\text{必要时再轻量微调 }C_m
}
]

这样既能节省重新训练成本，也能通过 `old Cm → Fm` 的可视化明确判断：原来训练出的 (C_m) 是否真的包含了足够的手动作信息。
