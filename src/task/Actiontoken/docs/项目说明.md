# Actiontoken 项目说明

## 1. 目标

冻结预训练 Static PoseEncoder，用相邻 PoseToken pair 编码纯 articulation motion。V1 不读取真实 point flow、不含 root motion、物体、contact 或 InteractionDynamics。

指导入口：[`指导/V1.md`](指导/V1.md)。研究记录：[`../research/log.md`](../research/log.md)。

## 2. 数据与模型

数据为 beta=0、root 不动的 synthetic MANO 9-frame trajectory。初始 pose 使用 Posetoken 的 PCA mixture；速度按 `v[t+1]=0.9v[t]+epsilon` 平滑更新。1538 个 face centers 和 PoseToken canonical `64×32` atlas 保持稳定 correspondence。

冻结 PoseEncoder 一次性编码 9 帧，得到 local `[B,9,64,384]` 和 global `[B,9,128]`。DynamicActionEncoder 对每个 transition 拼接 `P_t,P_t+1,deltaP,z_t,z_t+1`，经 MLP 和两层 per-patch temporal Transformer 得到 `[B,8,64,384]` ActionToken；decoder 重建每个 patch 32 点的相邻 flow。

pair encoder、temporal readout 和 flow decoder 都取 forward/reverse 的反对称分量，因此 static pair 解析地输出零，完整 transition sequence swap 后解析地反向。该约束不使用额外 loss。

## 3. 当前结果

32 trajectories controlled overfit 使用 V2 morphology-normalized PoseEncoder，6000 steps / 5:48。最佳 checkpoint 为 step 5808：val RMSE `0.00865 cm`，zero `0.03576 cm`，改善 `75.1%`，EPE `0.0991 mm`；slow/medium/fast RMSE 为 `0.00261/0.00999/0.02378 cm`。static/reverse residual 均严格为零。

改用 V1 fixed-morphology PoseEncoder 的 4000-step 对照，最佳改善为 `74.0%`，没有改善瓶颈。当前 controlled-overfit 未达到指导要求的 80%，所以没有运行 full synthetic generalization，也没有实现 RootToken 或回接 InteractionDynamics。

## 4. 运行

```bash
conda run -n graspenv python -m src.task.Actiontoken.train \
  --config src/task/Actiontoken/configs/mano_v1_overfit.yaml --device cuda
```

默认从 `output/Posetoken/research/pose_encoder_v2_morph.pt` 加载 encoder。可以通过 `--set meta.pose_encoder_checkpoint=<path>` 更换。

## 5. 下一步

先诊断 frozen PoseToken pair 对 dense adjacent flow 的可读上限，例如冻结 pair features 做线性/小 MLP probe，并与直接输入 surface pair 的同容量 oracle 对齐。若 PoseToken pair 本身足够，再检查 temporal Transformer 是否损失 patch 内细节；在 controlled-overfit 超过 80% 前不扩大数据、不做 RootToken、不修改 InteractionDynamics。
