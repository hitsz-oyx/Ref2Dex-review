# ActionToken V2：纯局部运动表示

## 0. 目标

ActionToken V2 重新定义 ActionToken。

旧版本：

[
(P_t,P_{t+1})
\rightarrow
A_t
]

并进一步使用 8-step Temporal Transformer。

V2 改为：

[
\boxed{
\Delta H_t^{art}
\rightarrow
A_t^{art}
}
]

ActionToken 只负责回答：

> 当前执行体的各个局部表面区域发生了怎样的运动？

不负责表达：

* 当前姿态；
* 当前物体；
* 当前环境；
* 动作处于一段 trajectory 的什么阶段；
* 之前或之后发生什么。

这些信息分别留给 Pose / World / Interaction 模块。

---

# 1. 表示体系重新定义

整个 Ref2Dex 后续统一按照：

## Pose

[
\boxed{
S_t=E_P(H_t)
}
]

表示：

> 当前主体处于什么状态。

---

## Action

[
\boxed{
A_t=E_A(\Delta H_t)
}
]

表示：

> 主体局部表面如何变化。

---

## World

[
\boxed{
W_t=E_W(H_t,O_t)
}
]

表示：

> 当前主体与物体构成什么样的三维环境。

---

## Interaction

最终：

[
\boxed{
C_{m,t}
=======

F(A_t,W_t)
}
]

第一版：

[
\boxed{
C_{m,t}
=======

CrossAttn(
Q=A_t,
KV=W_t
)
}
]

因此：

> 同样的 ActionToken 在不同初始姿态、不同物体位置下，会因为 WorldToken 不同而得到不同的交互含义。

ActionToken 本身无需重复编码当前姿态。

---

# 2. V2 删除的内容

从 ActionToken 正式架构中删除：

```text
Frozen PoseEncoder
Local PoseToken Pair
Global PoseToken Pair
Pair MLP
8-frame / 9-frame trajectory requirement
Temporal Transformer
Temporal positional embedding
Temporal odd projection
```

ActionToken 不再依赖 PoseToken checkpoint。

即：

[
\boxed{
PoseToken\not\rightarrow ActionToken
}
]

两者改为平行表示：

```text
             Hand State
             /        \
            /          \
           ↓            ↓
      PoseToken      Point Flow
                       ↓
                  ActionToken
```

# 3. V2 只编码单个 transition

不再生成：

[
H_0,H_1,\dots,H_8.
]

训练样本只需要：

[
\boxed{
(H_t,H_{t+1})
}
]

因此输入 surface：

[
H_t,H_{t+1}
\in
\mathbb R^{B\times1538\times3}.
]

或者 Dataset 内部保存：

```text
[B, 2, 1538, 3]
```

即可。

---

# 4. 必须使用 root-local surface

ActionToken V2 第一阶段只编码 articulation。

对每一帧：

[
H_t^{root}
==========

(T_t^{root})^{-1}H_t^{world}.
]

下一帧：

[
H_{t+1}^{root}
==============

(T_{t+1}^{root})^{-1}H_{t+1}^{world}.
]

然后：

[
\boxed{
\Delta H_t^{art}
================

## H_{t+1}^{root}

H_t^{root}
}
]

得到：

[
\Delta H_t^{art}
\in
\mathbb R^{B\times1538\times3}.
]

这样整体 wrist/root 的刚体平移和旋转不会进入 articulation ActionToken。

Root motion 后续独立编码。

---

# 5. 为什么直接计算 Point Flow

当前 MANO surface 使用稳定的 1538 个 face centers。

因此：

[
h_{t,i}
\leftrightarrow
h_{t+1,i}
]

具有确定 correspondence。

所以：

[
\Delta h_{t,i}
==============

h_{t+1,i}-h_{t,i}
]

是解析可得的。

没有必要让网络重新从：

[
(H_t,H_{t+1})
]

中学习 correspondence 或 subtraction。

因此 ActionEncoder 的真实输入是：

[
\boxed{
\Delta H_t
}
]

而不是两个完整点云分别编码后再比较。

# 7. ActionToken 不显式输入 PoseToken

V2 第一版不要：

[
A=F(P_t,\Delta H).
]

也不要 Pose gate：

[
A=M\odot g(P_t).
]

原因：

Pose 是 state；

Action 是 motion。

如果把 PoseToken 提前混入 ActionToken：

[
A=F(State,Motion)
]

会重新产生表示纠缠，不利于以后 Human / Robot action 对齐。

当前 configuration 的作用留给：

[
A\rightarrow W
]

时处理。

# 8. “同样 flow 在不同主体部位意义不同”怎么处理

当前：

[
\Delta H^{patch}
\in
[B,64,32,3]
]

不是匿名的 point cloud。

64 个 patch 始终保持固定顺序和固定 canonical correspondence。

因此：

```text
patch 0
patch 1
...
patch 63
```

在整个 dataset 内保持稳定 surface identity。

第一版 ActionEncoder 使用共享 encoder：

[
E_A(\Delta H_j).
]

不额外加入 PoseToken。

也暂时不加入 learnable patch embedding。

保留：

[
A\in[B,64,384]
]

的稳定 token ordering。

以后进入 InteractionDynamics 时，再利用：

* 当前 patch 3D center；
* WorldToken；
* spatial position embedding；

完成 scene grounding。

---

# 9. 为什么第一版不加入 patch embedding

如果直接：

[
A_j
===

E(\Delta H_j)+e_j
]

会导致：

[
\Delta H_j=0
]

时仍：

[
A_j=e_j\neq0.
]

这与 ActionToken 的物理定义冲突。

Action 应满足：

[
\boxed{
\Delta H=0
\Rightarrow
A=0.
}
]

所以 V2 第一版不直接加入常数型 patch embedding。

如果以后实验证明 patch identity 不足，可以测试 multiplicative patch conditioning，但不是 V2 的必要组成。

# 24. FlowActionEncoder 最小实现

结构应接近：

```python
class FlowActionEncoder(nn.Module):
    def __init__(self, dim=384, patch_size=32):
        super().__init__()

        self.encoder = nn.Sequential(
            nn.Linear(patch_size * 3, 256),
            nn.GELU(),
            nn.Linear(256, dim),
        )

        self.decoder = nn.Sequential(
            nn.Linear(dim, 256),
            nn.GELU(),
            nn.Linear(256, patch_size * 3),
        )

        self.patch_size = patch_size

    def encode(self, flow):
        B, P, K, _ = flow.shape
        x = flow.reshape(B, P, K * 3)

        token = 0.5 * (
            self.encoder(x)
            - self.encoder(-x)
        )

        return token

    def decode(self, token):
        flow = 0.5 * (
            self.decoder(token)
            - self.decoder(-token)
        )

        return flow.reshape(
            token.shape[0],
            token.shape[1],
            self.patch_size,
            3,
        )

    def forward(self, flow):
        token = self.encode(flow)
        pred = self.decode(token)

        return {
            "action_tokens": token,
            "pred_dense_flow_internal": pred,
        }
```

# 36. 最终设计原则

ActionToken V2 必须满足：

### 纯动作

[
A
]

不包含：

```text
Pose
World
Object
Contact
Temporal context
```

---

### 局部

每个：

[
A_j
]

对应一个稳定 surface region。

---

### 静止为零

[
\boxed{
\Delta H=0
\Rightarrow
A=0.
}
]

---

### 方向明确

[
\boxed{
A(-\Delta H)
============

-A(\Delta H).
}
]

---

### 单 transition

[
\boxed{
ActionEncoder
\text{ 不知道 trajectory length}
}
]

---

### 状态依赖留到 Interaction

[
\boxed{
Action=\text{motion}
}
]

[
\boxed{
World=\text{state}
}
]

[
\boxed{
Interaction=F(Action,World)
}
]

```text

6. Odd Flow Encoder
```

在第 10 步通过以前，不增加任何 temporal 或 interaction 模块。
