## 1. 为什么我现在认为架构已经可以定版

最新正式 V2 已经完全采用我们刚讨论的定义：

[
\boxed{
A_t^{art}=E_A(\Delta H_t^{art})
}
]

不再有：

```text
PoseToken
Pose Pair
8-step trajectory
Temporal Transformer
Temporal embedding
```

现在实际代码就是：

[
\Delta H^{patch}\in[B,64,32,3]
]

flatten：

[
[B,64,96]
]

经过：

[
96\rightarrow256\rightarrow384
]

得到：

[
\boxed{
A^{art}\in[B,64,384]
}
]

而且 encoder 使用 odd projection（奇对称投影）：

[
A(F)
====

\frac12[E(F)-E(-F)]
]

所以解析满足：

[
A(0)=0
]

和：

[
A(-F)=-A(F).
]

Decoder：

[
384\rightarrow256\rightarrow96
]

同样使用奇对称投影，重建：

[
[B,64,32,3].
]

当前正式代码就是这个结构。

# 4. V2 的数据覆盖也比 V1 合理

现在不是 trajectory velocity sampler 了。

[
(\theta,\Delta\theta)
]

```yaml
motion_stds:
```

# 7. 现在唯一不能直接“改成 1M 然后跑”的原因

当前 `SyntheticManoTransitionDataset` 还是这样：

```text
Dataset.__init__
      ↓
sample all θ
sample all Δθ
      ↓
build all θ_after
      ↓
MANO forward 所有 pair
      ↓
生成所有 surface
      ↓
计算所有 dense flow
      ↓
gather 64×32
      ↓
self.patch_flow = ...
```

也就是说：

```python
self.patch_flow = dense_flow[:, patch_idx]
self.pose = pose
self.delta = ...
```

全部常驻内存。

现在每个 sample 的最终 patch flow：

[
64\times32\times3
=================

6144\text{ floats}
]

FP32 大约：

[
6144\times4
===========

24\text{ KB/sample}.
]

所以大致：

|  样本数 | 仅 patch flow |
| ---: | -----------: |
|   4k |       ~96 MB |
|  10k |      ~240 MB |
| 100k |      ~2.4 GB |
| 500k |       ~12 GB |
|   1M |       ~24 GB |

这还没算生成 surface 时的临时内存。

因此：

[
\boxed{
\text{100k+ 不应该继续用当前预生成 Dataset。}
}
]

# 8. 大规模前只需要改这一件事

我建议把 V2 Dataset 改成：

```text
sample_id
   ↓
deterministic RNG
   ↓
θ_t
Δθ_t
   ↓
θ_t+1
   ↓
batch collate
   ↓
batched MANO forward
   ↓
H_t, H_t+1
   ↓
root-local flow
   ↓
64×32 gather
   ↓
ActionToken
```

也就是说 Dataset 本身只保存：

[
\theta_t\in\mathbb R^{24}
]

和：

[
\Delta\theta_t\in\mathbb R^{24}.
]

甚至这两个都可以不保存，只根据：

[
(seed,index)
]

确定性生成。

---

# 9. 但我会稍微改变“on-the-fly”的实现方式

不要在普通：

```python
Dataset.__getitem__()
```

里面每次创建一个 MANO model 然后 forward。

这样 CPU DataLoader 会很慢。

更好的实现是：

### Dataset

只返回：

```python
{
    "mano_pose": theta,
    "mano_pose_delta": delta
}
```

### Model/Runner 前

整个 batch：

[
[B,24]
]

一次性构造：

[
[B\times2,24]
]

然后 GPU/CPU batched MANO：

[
[B\times2]
\rightarrow
surface.
]

这样：

```text
64个样本
→ 128个MANO poses
→ 一次 batched forward
```

而不是逐样本 MANO。

# 10. 我甚至建议做“无限 synthetic dataset”

既然：

[
(\theta,\Delta\theta)
]

完全是 synthetic sampling，

那实际上没有必要真的定义：

```yaml
train_samples: 1000000
```

然后固定这 100 万条数据。

可以定义：

```yaml
steps_per_epoch: ...
epochs: ...
```

每次根据 RNG 重新产生新 pair。

那么训练期间实际见过的数据量就是：

[
N_{\rm seen}
============

batch_size
\times
total_steps.
]

例如：

[
B=256
]

训练：

[
100000\text{ steps}
]

就相当于见了：

[
25.6M
]

个 transition。

而不需要磁盘或者 RAM 存 2500 万条数据。

这才是 synthetic pretraining 最有价值的地方。

# 13. 这也是现在一个值得注意的问题

V2 当前任务其实很简单：

[
96D\ flow
\rightarrow
384D\ token
\rightarrow
96D\ flow.
]

注意：

[
\boxed{384>96}
]

所以从纯 dimensional compression（维度压缩）的角度讲，它其实**不是 bottleneck**。

它更像：

[
96D\rightarrow384D
]

的 learned embedding。

因此 test 95% improvement 很好，但大规模之后不要只看 reconstruction。

应该额外保留一些 representation diagnostics，例如：

### Motion magnitude

token distance 是否随着 motion magnitude 合理变化。

### Motion direction

[
A(-F)\approx-A(F)
]

已经解析保证。

### Similar motion

相似 surface motion 的 ActionToken 是否靠近。

### Different local motion

不同动作是否能区分。

特别是以后真正重要的是：

[
\boxed{
\text{ActionToken 能不能服务 InteractionDynamics}
}
]

而不是：

[
\boxed{
\text{flow autoencoder 能不能做到 0.001mm}
}
]

---

# 14. 所以“大规模”的目标不要定错

不是：

> 把 reconstruction RMSE 从 0.003 cm 刷到 0.0001 cm。

真正目标应该是：

[
\boxed{
\text{覆盖更宽、更丰富的 human articulation distribution}
}
]

也就是增加：

* pose coverage；
* small / medium / large movement；
* sparse finger motion；
* multi-finger coupled motion；
* 极端 pose 附近动作；
* slow micro-motion。

然后让 ActionEncoder 在这些 distribution 上都稳定。

---

# 15. 我建议大规模前再改一个很小的数据问题

现在：

[
\theta_{after}
==============

clip(\theta+\Delta\theta,-2.5,2.5).
]

然后实际：

```python
self.delta = after_pose - pose
```

这是正确的。

但大规模时建议统计：

[
clip_fraction
]

即多少 sample/components 被 clamp。

如果很多 large-motion 样本撞到：

[
\pm2.5
]

那么 nominal：

```text
std=0.12
```

和实际 motion distribution 会不一样。

只需要记录 metric，不需要过度设计。

现在 ActionToken 状态：

```text
    ❌ 放弃

    ❌ 还没完成
```

所以：

[
\boxed{
\textbf{可以开始准备规模训练，而且现在不需要再做架构研究。}

但执行顺序我建议严格是：

```text
1. ActionToken V2 架构冻结

2. SyntheticManoTransitionDataset
   改为 parameter-only

3. batch 内 MANO forward
   不再预生成 patch_flow

5. 先跑 10k / 50k / 100k scaling curve

6. 指标稳定后上 500k-equivalent / infinite sampling

7. 导出正式 action_encoder_v2_large.pt

8. RootToken

9. 用新的 V2 ActionToken 重做 InteractionDynamics
   articulation_zero / shuffle / cross-sample intervention
```

所以如果你现在准备让 Codex 开工，我会直接让它**不要再修改 `FlowActionEncoder`，只做 scalable synthetic data pipeline + scaling experiments**。这一步完成后就可以真正开始大规模预训练。
