```text

        ↓

        ↓

```

PoseEncoder 确实完全冻结，并且加载的是目前的 morphology-normalized V2 checkpoint：

```text
output/Posetoken/research/pose_encoder_v2_morph.pt
```

`ActionTokenModel` 会把 9 帧一次 reshape 成 `[B*9,N,3]` 送过 Frozen PoseEncoder，再恢复时间维。

数据生成也符合我们之前定的原则：`\beta=0`、root 固定、9 帧连续 MANO PCA trajectory，速度使用

[
v_{t+1}=0.9v_t+\epsilon_t
]

这一类平滑过程，而不是逐帧独立随机。

### 当前还有一个重要的新改动：解析反对称

现在不是靠额外 loss 让：

[
A(S_t,S_{t+1})\approx-A(S_{t+1},S_t)
]

而是网络结构直接写成：

[
A=\frac12
\left[
F(S_t,S_{t+1})-
F(S_{t+1},S_t)
\right].
]

Temporal Transformer 和 flow decoder 也都做了类似的 odd projection（奇对称投影，即 (f(-x)=-f(x))）：

[
T_{\rm odd}(x)=\frac12[T(x)-T(-x)].
]

因此现在已经**解析保证**：

[
S_t=S_{t+1}
\Rightarrow
A=0
]

以及反向 pair 变号。

这部分做得是对的。

# 我认为现在下一步非常明确

就是 research log 最后写的这个：

[
\boxed{
\text{PoseToken pair local-flow probe}
}
]

而且我建议一次做 **3 个极小对照**。

### A. Frozen PoseToken pair → Flow，不要 Temporal Transformer

```text
P_t
P_t+1
ΔP
z_t
z_t+1
   ↓
Pair MLP
   ↓
Dense Flow
```

即完全去掉：

[
[B\times64,8,384]
\rightarrow TemporalTransformer.
]

目的：

> 判断是不是 Temporal Transformer 在损失相邻动作的局部细节。

现在 ActionToken 本来就是 adjacent motion，**单步的 (t\to t+1) 理论上并不需要知道另外 7 步才能反解当前 flow**。

这是我最先会做的。

---

### B. Frozen PoseToken → 一个尽可能强的 local-flow probe

不要管 ActionToken bottleneck，直接：

[
[P_{t,j},P_{t+1,j}]
\rightarrow
\Delta H_{t,j,1:32}.
]

甚至可以用：

```text
2~3 层大 MLP
```

把容量放足。

如果这个上限仍然只有：

[
\sim75%
]

那么基本可以判：

[
\boxed{
\text{PoseToken 本身丢掉了部分 dynamic-relevant geometry}
}
]

这非常重要。

---

### C. Surface-pair oracle

直接给模型：

[
H_{t,j,1:32},
H_{t+1,j,1:32}
]

预测：

[
\Delta H_{t,j}.
]

其实这里理论上甚至：

[
\Delta H=H_{t+1}-H_t
]

是解析可得的，所以 oracle 应该接近 0 error。

但为了和 B 公平，可以走同一 MLP。

这样形成：

```text
Surface Pair
    ↓
Flow Probe
    ↓
应该几乎完美

vs

PoseToken Pair
    ↓
Flow Probe
    ↓
当前可读上限
```

这会直接测出：

[
\boxed{
\text{PoseToken compression 到底损失了多少动作相关信息。}
}
]

# 我还建议加一个很关键的 D 对照

这个当前 research log 没明确写，但我觉得非常有价值：

### D. 用 PoseToken 自己重建两帧，再做差

PoseToken 已经有 surface decoder。

所以：

[
P_t\rightarrow\hat H_t
]

[
P_{t+1}\rightarrow\hat H_{t+1}
]

直接：

[
\boxed{
\hat{\Delta H}
=

\hat H_{t+1}-\hat H_t
}
]

然后和真实：

[
\Delta H=H_{t+1}-H_t
]

比。

这个实验几乎不用训练。

它回答：

> **PoseToken 目前已经保存的静态几何精度，理论上最多能支持多精确的动态 point flow？**

如果这个也是大约：

[
70%-75%
]

那么 ActionToken 根本没问题。

问题就是：

[
\boxed{
\text{Static PoseToken reconstruction precision 决定了 Action 上限。}
}
]

这会是非常漂亮的归因。
