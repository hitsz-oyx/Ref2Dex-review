# 4. Object 点先不要 4096 全塞

你现在 Stage2 已经有稳定对应的：

[
4096
]

个 rigid object surface points。

V0 建议：

[

]

按固定 `obj_point_id` 抽。

最关键的是：

> **一个 sequence/window 内所有时间步必须使用同一批 point IDs。**

因为我们需要真正的：

[
p_i^0\rightarrow p_i^1\rightarrow\cdots
]

而不是每帧重新 sample。

以后显存允许再变：

[
1024\rightarrow2048\rightarrow4096.

# 5. Hand 点也不要直接用 1538

你当前 Stage2 hand representation 已经是 MANO face-center，共 1538 个固定点，并且带稳定 `hand_point_id`。

HAND_IDS = fixed_ids[256]

这样：

是真正的 hand point flow。

# 6. 坐标系第一版这样处理

不要先做 hand-root canonicalization。

因为你现在要让模型学：

> 手怎么带着刚体运动。

直接以：

[
c_0=
\frac1N\sum_i p_{i,0}^{obj}
]

为原点：

[
\tilde p_{i,t}^{obj}
====================

p_{i,t}^{obj}-c_0
]

[
\tilde h_{j,t}
==============

h_{j,t}-c_0.
]

即整个 window 同时平移。

**不要每帧重新减 object centroid。**

否则：

[
\text{object translation}
]

会被你自己消掉。

也先不要把物体每帧 rotation canonicalize 掉。

我们就是要保留：

[
SE(3)
]

刚体运动作为 effect。

# 17. Forward loss 第一版只有一个

不要先堆十种 loss。

[
\boxed{
L_F
===

\operatorname{Huber}
(
\hat\Phi,
\Phi^{GT}
)
}
]

但有一个问题：

GRAB 中大量 frame object 不动。

所以必须加 motion weighting：

[
w_{i,t}
= = = = = = =

1+\lambda_m
\mathbf 1(
|\Phi_{i,t}|>\epsilon
)
]

然后：

[
L_F
===

\frac{
\sum w_{i,t}
\operatorname{Huber}(\hat\Phi_{i,t},\Phi_{i,t})
}{
\sum w_{i,t}
}.
]

否则最容易出现：

[
\hat\Phi=0
]

也能得到很漂亮的 loss。

# 32. 这里一定不要一开始把 PointWorld 跟着 inverse 一起更新

否则会出现一个非常危险的作弊：

inverse generator 生成错误 MANO，

PointWorld 为了降低：

[
L_{effect}
]

自己适应成：

> “这个错误手动作也能产生正确 object effect”。

于是：

[

## 最后给你一个最重要的范围判断

**第一周/第一版不要“改 PointWorld 成 WAM”。**

[

\textbf{Q1: PointWorld 的 3D interaction prior 能否迁移到 MANO→GRAB rigid dynamics？}
}

如果 Q1 成立，再问：

\boxed{
\textbf{Q2: 能否训练一个无需搜索的 inverse MANO generator，

}
]

这两个答案都是“是”，你才真正有理由把两边 joint-train，正式叫 **PointWorld-WAM / 3D Dexterous WAM**。

**所以你现在应该先让 Codex 实现 E0～E3，不要让它实现 inverse branch。**这会最符合你仓库现在“尽快验证 idea、少做无关框架”的研究规范。
