可以。把目前的讨论收敛后，我建议把现有 `WAMV1` 保留不动，新开一版 **Chunk Joint WAM**。核心变化不是简单把 one-step 改成 10-step，而是从“inverse 单独生成 action”升级成：

[
\boxed{
p_\theta(\Phi^{obj}*{1:K},A^L*{1:K},A^R_{1:K}\mid S_t)
}
]

即同一个模型联合建模 **世界变化 chunk + 双手动作 chunk**。Forward / Inverse 只是不同的加噪和条件模式，不是两个独立网络。

# 一、最终任务定义

固定 30 Hz，第一版：

[
\boxed{K=10}
]

对应约：

[
333\text{ ms}.
]

当前状态：

[
S_t=
(P_t,\Delta P_{t-1},H_t^L,H_t^R,\theta_t^L,\theta_t^R)
]

其中：

* (P_t)：当前 object 点云；
* (\Delta P_{t-1}=P_t-P_{t-1})：上一时刻 object motion；
* (H_t^{L/R})：当前完整 1538 MANO surface；
* (\theta_t^{L/R})：当前 MANO state。

World chunk：

[
\boxed{
\Phi^{obj}*k=P*{t+k}-P_t,\qquad k=1,\ldots,K
}
]

Action chunk 每个时刻都 **relative to 当前 (t)**，不要逐帧累加：

[
\boxed{
A^s_k=
[
x^s_{t+k}-x^s_t,;
\log((R_t^s)^TR_{t+k}^s),;
q^s_{t+k}-q^s_t
]
}
]

其中：

[
A^s_k\in\mathbb R^{30},\qquad s\in{L,R}.
]

所以：

[
A^{L/R}_{1:K}\in\mathbb R^{K\times30}.
]

这样 world 和 hand action 完全对称：

[
\boxed{
P_{t+k}-P_t
\leftrightarrow
MANO_{t\rightarrow t+k}
}
]

---

# 二、不要把 current + future 两套点都塞给 PTv3

这是我们已经确定的原则。

对于第 (k) 个 future timestep，模型内部有 noisy world/action state：

[
\tilde\Phi^{obj}_{\tau_o,k}
]

[
\tilde A^{L/R}_{\tau_a,k}.
]

先构造 candidate future geometry。

Object：

[
\boxed{
\tilde P_{\tau_o,k}
===================

P_t+
\tilde\Phi^{obj}_{\tau_o,k}
}
]

Hand：

[
\boxed{
\tilde H^{L/R}_{\tau_a,k}
=========================

MANO(\theta_t^{L/R},\tilde A^{L/R}_{\tau_a,k})
}
]

然后 PTv3 的 **coordinate** 使用：

[
\boxed{
[
\tilde P_{\tau_o,k},
\tilde H^L_{\tau_a,k},
\tilde H^R_{\tau_a,k}
]
}
]

而不是 current geometry。

---

# 三、Current 信息放在 feature 里

这样 stable correspondence 就不会浪费。

## Object token

coordinate：

[
x^{obj}_{i,k}
=============

P_{t,i}
+
\tilde\Phi^{obj}_{\tau_o,k,i}.
]

feature 建议：

[
f^{obj}_{i,k}
=============

[
P_{t,i},
n_{t,i},
\Delta P_{t-1,i},
\tilde\Phi^{obj}_{\tau_o,k,i}
]
]

再加：

* object type embedding；
* physical timestep (k) embedding；
* world noise time (\tau_o) embedding。

---

## Hand token

coordinate：

[
x^s_{j,k}
=========

\tilde H^s_{\tau_a,k,j}.
]

feature：

[
\boxed{
f^s_{j,k}
=========

[
H^s_{t,j},
H^{cano,s}*j,
n^s*{t,j},
\tilde H^s_{\tau_a,k,j}-H^s_{t,j},
E_{\text{finger}},
E_{\text{region}}
]
}
]

再加：

* left/right type embedding；
* physical timestep (k)；
* action noise time (\tau_a)。

也就是说：

```text
coordinate:
candidate future xyz

feature:
current xyz
current → candidate flow
canonical MANO xyz
finger identity
region identity
current normal
```

这比：

```text
current points + future points
```

作为两套 token 更干净。

# 四、必须把 hand identity 真正用起来

当前 cache 已经有：

```text
hand_cano_points
hand_finger_id
hand_region_id
hand_point_id
```

新版 dataset 必须输出：

```python
left_hand_cano_points
left_finger_id
left_region_id

right_hand_cano_points
right_finger_id
right_region_id
```

第一版不用 `point_id embedding`。

因为：

[
H^{cano}
]

已经是很强的连续 point identity。

`finger_id` 和 `region_id` 再补语义：

```text
这是拇指
这是食指
这是 fingertip
这是 finger pad
这是 palm
```

这样 1538 points 才不是纯粹一堆匿名 xyz。

# 五、每个 future timestep 共享同一个 Spatial PTv3

对于：

[
k=1,\ldots,10
]

做：

```text
candidate object_k
+
candidate left hand_k
+

        ▼

        │
 ┌──────┼──────┐
```

所有 (k)：

不是 10 个 PTv3。

后续性能优化再把：

[
[B,K]

展成：

[
[BK]

一次并行送 PTv3。

# 六、不要再直接 global max pool

这一版按 PointWorld 的思路来。

PTv3 后：

[
F^{obj}_k\in\mathbb R^{1024\times D}
]

[
F^L_k,F^R_k\in\mathbb R^{1538\times D}.
]

**这些逐点 feature 保留。**

但 Temporal Transformer 不可能直接吃：

[
10\times4100
]

个 token，所以在空间层后增加 learned queries。

# 七、用 learned queries 提取 compact interaction tokens

例如每个时刻：

```yaml
num_object_queries: 8
num_hand_queries: 8
```

于是：

[
Q^{obj}_k
\xrightarrow{\text{cross-attn}}
F^{obj}_k
]

得到：

[
Z^{obj}_k\in\mathbb R^{8\times D}.
]

左手：

[
Q^L_k
\xrightarrow{\text{cross-attn}}
F^L_k
]

右手同理。

因此一个 timestep 只有：

[
8+8+8=24
]

个 compact tokens。

10 timestep：

[
240
]

个 token。

这就非常适合 Transformer。

# 八、Current PCA state 显式进入 action decoder

当前 V1 实际上是：

[
1538\ point\ features
\rightarrow maxpool
\rightarrow MLP
\rightarrow PCA\ velocity.
]

新版不要再让模型隐式从 points 反解当前 PCA。

dataset 已经知道：

[
q_t^{L/R}\in\mathbb R^{24}
]

[
r_t^{L/R}\in\mathbb R^3
]

[
x_t^{L/R}\in\mathbb R^3.
]

直接组成：

[
\theta_t^s=
[x_t^s,r_t^s,q_t^s]
\in\mathbb R^{30}.
]

经过：

[
E_\theta^s=MLP(\theta_t^s)
]

加到对应 left/right action query 上。

这样 action decoder 的任务从：

> 从 1538 点猜当前 MANO 参数，再猜应该怎么变

变成：

> 当前 MANO state 已经明确给你，根据 point interaction 判断应该如何修改它。

# 九、整个 chunk 再进入一个联合 World-Action Transformer

Spatial PTv3 后得到：

[
{
Z^{obj}*k,Z^L_k,Z^R_k
}*{k=1}^{K}.
]

把所有 token 一起输入：

[
\boxed{\text{World-Action Temporal Transformer}}
]

结构：

```text
time 1
  Obj queries
  Left queries
  Right queries

time 2
  Obj queries
  Left queries
  Right queries

...

time 10
        │
        ▼
┌──────────────────────────────┐
│ World-Action Transformer     │
│                              │
│ full bidirectional self-attn │
└──────────────┬───────────────┘
               │
       ┌───────┴────────┐
       ▼                ▼
   world context    action context
```

第一版：

[
\boxed{\text{全双向 self-attention}}
]

先不设计复杂 Fast-WAM mask。

# 十、Forward / Inverse 不是两个 branch

这个必须在代码设计里体现出来。

模型输入永远是：

[
(
\tilde\Phi^{obj},
\tilde A^L,
\tilde A^R,
\tau_o,\tau_a
)
]

输出永远是：

[
\boxed{
(v^{obj},v^{A,L},v^{A,R})
}
]

只是不同训练 mode 设置不同 noise level。

---

## Inverse mode

World 是 clean desired effect：

[
\boxed{\tau_o=1}
]

Action：

[
\tau_a\sim U(0,1).
]

所以：

```text
Desired Object Chunk = clean
Action Chunk         = noisy
           ↓
     same joint WAM
           ↓
     predict v_action
```

loss：

[
L_A.
]

---

## Forward mode

Action clean：

[
\boxed{\tau_a=1}
]

World：

[
\tau_o\sim U(0,1).
]

```text
Action Chunk = clean
World Chunk  = noisy
       ↓
  same joint WAM
       ↓
 predict v_world
```

loss：

[
L_W.
]

---

## Joint mode

两边都 noisy：

[
\tau_o\sim U(0,1)
]

[
\tau_a\sim U(0,1)
]

并且建议：

[
\boxed{\tau_o,\tau_a\text{ 独立采样}}
]

同一个模型同时输出：

[
(v_W,v_A).
]

这才是 unified WAM。

---

# 十一、Flow Matching 路径

Action 先 normalize：

[
\bar A=
\frac{A-\mu_A}{\sigma_A}.
]

整个 chunk 共用一个 (\tau_a)：

[
A_0\sim\mathcal N(0,I)
]

[
A_{\tau_a}
==========

(1-\tau_a)A_0+
\tau_a A_1.
]

target：

[
v_A^*=A_1-A_0.
]

---

World flow 同样建议 normalize 后再做 FM：

[
\bar\Phi=
\frac{\Phi-\mu_\Phi}{\sigma_\Phi}.
]

然后：

[
\Phi_{\tau_o}
=============

(1-\tau_o)\Phi_0+
\tau_o\Phi_1.
]

真正建立 PTv3 coordinate 时再 denormalize：

[
P_{\tau_o}
==========

P_t+
Denorm(\Phi_{\tau_o}).
]

这样 Gaussian noise 和 metric geometry 不冲突。

---

# 十二、World 输出仍然必须逐点

这里不要因为 Temporal Transformer 又把 world 输出做成 global。

原始 PTv3：

[
F^{obj}_k
]

一直保留。

Temporal Transformer 给该时刻输出一个 world/action context：

[
C_k.
]

然后按 PointWorld 风格：

[
\boxed{
\tilde F^{obj}_{i,k}
====================

F^{obj}_{i,k}
+
G(C_k)
}
]

其中：

[
G(C_k)
]

broadcast 给所有 object points。

最后：

[
\tilde F^{obj}*{i,k}
\rightarrow
v^{obj}*{i,k}\in\mathbb R^3.
]

因此 world 永远是：

[
\boxed{
K\times1024\times3
}
]

的显式 point-flow velocity。

绝对不能改成一个 rigid/global vector。

---

# 十三、Action 输出

Temporal Transformer 后左手 query：

[
Z^{L,out}_k
]

结合：

* current MANO state embedding；
* noisy action (A_{\tau,k}^L) embedding；
* (\tau_a)；
* timestep (k)。

再：

[
D_L(Z^{L,out}*k)
\rightarrow
v^L*{A,k}\in\mathbb R^{30}.
]

右手同理。

所以最终：

[
v_A\in\mathbb R^{K\times2\times30}.
]

---

# 十四、辅助 MANO surface loss

这个确定加入。

从某个 FM interpolation point：

[
A_{\tau}
]

和预测：

[
\hat v_A
]

直接估计 endpoint：

[
\boxed{
\hat A_1
========

A_\tau+(1-\tau_a)\hat v_A
}
]

然后：

[
\hat A_{1,k}
\xrightarrow{MANO}
\hat H_{t+k}.
]

计算：

[
L_{surface}
===========

\frac{1}{2K1538}
\sum_{s,k,j}
|
\hat H^s_{t+k,j}
----------------

H^{s,GT}_{t+k,j}
|.
]

最终：

[
\boxed{
L=
\lambda_WL_W
+
\lambda_AL_A
+
\lambda_SL_{surface}
}
]

其中 `surface loss` 只在 action 被训练的 inverse/joint mode 使用。

第一版：

```text
不加 smoothness
不加 effect-consistency
不加 rigid loss
```

先保持干净。

# 二十、第一轮实现不要直接跑 full GRAB

