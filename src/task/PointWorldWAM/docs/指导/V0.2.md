可以。建议把这次改动定成一个明确的 **PointWorldWAM V0.2 → V0.3 路线**，核心原则不变：

[
\boxed{\text{Hand Point Flow}\rightarrow\text{Object Point Flow}}
]

不加 SE(3) head，不改成 pose prediction，也暂时不换 backbone。先确认 **PointWorld 预训练 PTv3 能不能把细粒度单步动力学学好**。

# 一、我们现在要验证的核心假设

当前 PointWorld 是：

[
(P_0,H_{0:10})
\rightarrow
\Phi^{obj}_{0:10}
]

11 帧 hand 全部拼进去，一次输出未来 10 帧 object flow。

改成局部 transition：

[
\boxed{
(P_t,H_t,\Delta H_{t\rightarrow t+k},\Delta t)
\rightarrow
\Delta P^{obj}_{t\rightarrow t+k}
}
]

其中：

[
\Delta H_{t\rightarrow t+k}
===========================

H_{t+k}-H_t
]

[
\Delta P^{obj}_{t\rightarrow t+k}
=================================

P_{t+k}-P_t
]

[
\Delta t
========

\frac{
raw_frame_id_{t+k}-raw_frame_id_t
}{120}.
]

也就是模型只回答：

> 当前手和物体处于这个几何状态，手在接下来 (\Delta t) 内产生这段 point flow，物体会产生什么 point flow？

---

# 二、V0.2：先做最干净的 one-step capacity test

第一阶段**不要直接搞 rollout，也不要一次加入 history**。

先测试：

[
\boxed{
(P_t,H_t,\Delta H_t)
\rightarrow
\Delta P_t
}
]

GRAB 当前是 30 Hz，因此：

[
\Delta t=\frac1{30}\approx33.3ms.
]

这一版 (\Delta t) 虽然可以作为接口保留，但由于固定不变，它实际上不是关键变量。

## 输入

### Object tokens

坐标：

[
x_i^{obj}=P_{t,i}
]

feature 建议：

[
f_i^{obj}
=========

[
P_{t,i},
n_{t,i},
d(P_{t,i},H_t)
]
]

即：

```text
xyz          3
normal       3
dist2hand    1
----------------
             7D
```

这里**不再使用未来 11 帧 dist-to-hand**。

---

### Hand tokens

坐标：

[
x_j^{hand}=H_{t,j}
]

feature：

[
f_j^{hand}
==========

[
H_{t,j},
n_{t,j},
\Delta H_{t,j}
]
]

即：

```text
xyz           3
normal        3
hand flow     3
----------------
              9D
```

注意这个 `hand flow` 就是 action：

[
\boxed{A_t=\Delta H_t}
]

非常符合我们最终 WAM 的表征。

# 三、PTv3 主体保持不变

仍然：

```text
object points at t
        +
hand points at t
        ↓
   joint PTv3
        ↓
per-object-point feature
        ↓
pointwise MLP
        ↓
object point flow
```

继续保留已经验证有效的：

```yaml
grid_size: 0.005
enable_rpe: true
drop_path: 0.0
shuffle_orders: false
use_xyz_feature: true
```

也就是：

[
\boxed{
\text{representation 不换，PointWorld pretrained interaction backbone 不换}
}
]

只改变 temporal formulation。

# 四、输出 head 改成真正的 one-step point-flow head

当前 PointWorld：

```python
Linear(128, 3 * 10)
```

一次输出：

[
[\Delta p^1,\ldots,\Delta p^{10}]
]

V0.2 改成：

```python
Linear(128, 3)
```

即每个 object point：

[
f_i
\rightarrow
\Delta \hat P_i.
]

最终：

[
\boxed{
\Delta\hat P
\in\mathbb R^{N_{obj}\times3}
}
]

然后：

[
\hat P_{t+1}
============

P_t+\Delta\hat P_t.
]

这仍然是逐点 MLP。

---

# 五、DROID normalization 全部拿掉

这次我建议不要再折中。

删除：

```text
DROID output_mean
DROID output_std
norm_stats_path
```

不要：

[
\hat\Phi
========

\sigma_{DROID}\hat y+\mu_{DROID}.
]

直接：

[
\boxed{
\hat\Phi=\text{head}(f)
}
]

单位就是 meter。

Loss 也直接在 point-flow 上：

[
L
=

\operatorname{Huber}
(
\Delta\hat P,
\Delta P^{GT}
).
]

不要再：

```python
pred_tracks vs object_points
```

而是明确：

```python
target_flow = obj_next - obj_current
pred_flow = model(...)

loss = weighted_huber(
    pred_flow,
    target_flow,
)
```

这样整个任务定义没有任何歧义：

[
\boxed{\text{point flow supervised by point flow}}
]

---

# 六、PointWorld checkpoint 怎么加载

**只迁移真正有价值的 interaction prior。**

加载：

```text
predictor_model.*
```

也就是 pretrained PTv3。

可以同时保留：

```text
skip_film_gamma/beta
robot_film_gamma/beta
```

因为它们只是 feature fusion 参数。

但不要加载：

```text
old dynamics_head
log_var_head
DROID normalization stats
```

新的：

```text
one_step_dynamics_head
```

随机初始化。

所以变成：

```text
PointWorld pretrained PTv3
          ↓
GRAB-specific one-step head
          ↓
metric object point flow
```

# 七、optimizer 必须重新分组

当前最大的问题之一就是新模块和 pretrained backbone 混在一起用了 `1e-5`。

建议：

```yaml
lr_head: 3e-4
lr_new: 1e-4
lr_backbone: 1e-5
```

### `3e-4`

```text
one_step_dynamics_head
```

### `1e-4`

### `1e-5`

```text
pretrained PTv3 backbone
```

`log_var_head` 直接不要了。

# 八、V0.2A 数据怎么做

当前 `11-frame window` 改成：

```text
transition pair
```

例如：

```text
frame 100 → frame 101
frame 101 → frame 102
frame 102 → frame 103
...
```

对 cache 来说实际 raw frame 是：

```text
100 → 104
104 → 108
```

因为：

```text
source FPS = 120
ds_rate = 4
```

所以：

[
\Delta t=\frac4{120}=\frac1{30}s.
]

cache 本身已经保存 `raw_frame_id` 和 `source_fps`。

# 九、这里一定要修 hand-action completeness

这个和 one-step architecture 是两个独立问题，但必须同时保证。

现在不能再：

> object movement 大就拿来训练，同时固定 `side:right`。

必须先保证：

[
\boxed{
\text{当前 transition 的 object motion 确实由输入 hand 解释得了}
}
]

第一轮建议最简单：

### 只选明确 right-hand interaction 的 transition

利用已有：

```text
right obj_candidate_mask_5cm
left obj_candidate_mask_5cm
```

优先选：

```text
right hand 接近/接触 object
+
left hand 不参与或明显更远
```

先把 single-hand causal mapping 做干净：

[
(P_t,H_t^{right},\Delta H_t^{right})
\rightarrow
\Delta P_t.
]

**暂时不要马上改双手 architecture。**

如果发现我们目前那两个 sequence 本身就是双手协作，再单独升级成：

[
H^{left}+H^{right}.
]

---

# 十、V0.2A 的判断标准不能再照搬 11-frame ADE

因为现在每次只预测 33 ms。

所以除了绝对误差，要同时记录：

### one-step point error

[
E_{1step}
=========

|\Delta\hat P-\Delta P|.
]

希望训练集至少做到：

[
\boxed{1\sim2\text{ mm 级}}
]

如果 64 个 transition 都过拟合不到这个量级，就说明：

* PTv3 interface；
* head；
* feature；
* optimizer；

还有问题。

---

### static baseline

预测：

[
\Delta P=0.
]

然后必须明显优于 static。

否则即使 ADE 很小，也只是因为 33 ms 内物体没怎么动。

---

### action shuffled

将：

[
\Delta H_t
]

打乱。

应该明显恶化：

[
E_{GT-action}
\ll
E_{shuffled-action}.
]

这样才能证明模型真的使用 hand flow。

---

# 十一、V0.2B：单步跑通后再真正加入“时间跨度”

这个是你刚才想法里我觉得非常好的部分。

不能只告诉模型 (\Delta t)，却让所有样本的 (\Delta t) 都是 33 ms。

要真正训练：

[
\boxed{
(P_t,H_t,\Delta H_{t:t+k},\Delta t_k)
\rightarrow
\Delta P_{t:t+k}
}
]

例如先用：

```text
gap = 1 : 33 ms
gap = 2 : 67 ms
gap = 3 : 100 ms
gap = 4 : 133 ms
```

不要一下拉到 333 ms。

因为我们现在的目标就是 **local interaction dynamics**。

---

## Δt 输入

直接根据：

```python
dt = (
    raw_frame_id[next]
    - raw_frame_id[current]
) / source_fps
```

再过一个小：

```text
TemporalEmbedding / MLP
```

得到：

[
e_{\Delta t}.
]

然后可以加到所有 token：

[
f^{obj}\leftarrow f^{obj}+e_{\Delta t}
]

[
f^{hand}\leftarrow f^{hand}+e_{\Delta t}.
]

这样模型知道：

> 这段 hand flow 是发生在 33 ms 还是 133 ms 内。

# 十四、history 暂时不要现在加

我们前面说过：

[
(P_t,H_t,\Delta H_t)
]

理论上可能缺少：

* object velocity；
* contact history；
* sliding state。

这是真的。

但**不要现在就把 previous flow 加进去**。

先跑 V0.2。

如果出现：

```text
one-step GT输入
仍然无法精确拟合
```

再检查是否是 state aliasing（状态混叠：当前几何一样，但由于过去运动不同，下一步结果不同）。

那时再加：

[
\Delta P_{t-1}
]

形成：

[
\boxed{
(P_t,\Delta P_{t-1},H_t,\Delta H_t,\Delta t)
\rightarrow
\Delta P_t
}
]

这应该是后续升级，不是第一版。

# 最终执行顺序

我建议 Codex 就按这个顺序做：

```text
V0.2A
│
├─ 1. dataset 改成相邻 transition pair
├─ 2. object_t + hand_t + Δhand_t
├─ 3. PointWorld PTv3 pretrained backbone
├─ 4. 新 3D point-flow head
├─ 5. 删除 DROID normalization
├─ 6. 修 optimizer LR 分组
├─ 7. 筛干净 right-hand driven transitions
└─ 8. one-step overfit + static/shuffled diagnostics
        │
        ├─ <1~2 mm → 继续
        └─ 仍明显偏大 → 先查模型接口，不做 rollout


V0.2B
│
├─ gap ∈ {1,2,3,4}
├─ 输入真实 Δt
└─ variable-span point-flow prediction
        │
        ▼

V0.3
│
├─ autoregressive rollout 3~5 steps
└─ 最终比较 10-step trajectory ADE
        │
        ▼

决定 PointWorld 路线是否继续
```

最重要的是，这次从头到尾都没有改变我们真正要做的东西：

[
\boxed{
\text{局部 Hand Point Flow}
\rightarrow
\text{局部 Object Point Flow}
}
]

然后未来 inverse/WAM 仍然自然对应：

[
\boxed{
\text{Desired Object Point Flow}
\rightarrow
\text{Hand Point Flow}
}
]

这条路线是连续的。
