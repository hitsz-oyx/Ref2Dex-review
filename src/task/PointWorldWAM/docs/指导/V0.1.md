# 二、第一项：把 xyz 放回 feature

这是最应该改的。

PointWorld 原版明确将：

```python
robot_flows
```

和：

```python
scene_flows
```

本身加入 feature，而不仅仅作为 PTv3 的 `coord`。

你现在的：

```python
scene_raw = torch.cat([
    object_normals[:, 0],
    dist,
], dim=-1)
```

改成：

```python
scene_raw = torch.cat([
    object_points[:, 0],
    object_normals[:, 0],
    dist,
], dim=-1)
```

原来：

[
3+11=14D
]

现在：

[
3_{\rm xyz}
+
3_{\rm normal}
+
11_{\rm dist}
=============

17D.
]

---

hand 原来：

```python
hand_raw = torch.cat([
    hand_normals,
    velocity,
    acceleration,
], dim=-1)
```

改成：

```python
hand_raw = torch.cat([
    hand_points,
    hand_normals,
    velocity,
    acceleration,
], dim=-1)
```

变成：

[
3+3+3+3=12D.
]

所以 `__init__`：

原来：

```python
self.scene_adapter = AdapterMLP(14, channels)
self.hand_adapter = AdapterMLP(9, channels)
```

改：

```python
self.scene_adapter = AdapterMLP(17, channels)
self.hand_adapter = AdapterMLP(12, channels)
```

这一步非常重要。

# 三、为什么 xyz 要同时保留在 coord 和 feature

不要因为：

```python
object_points
```

已经作为：

```text
coord
```

进入 PTv3，就觉得 feature 里的 xyz 重复。

它们职责不同。

### `coord`

用于：

```text
voxelization
serialization
sparse convolution
neighborhood
```

也就是：

> 哪些点空间上靠近。

---

### xyz feature

用于：

> 这个点精确位于哪里。

特别是刚体 rotation：

[
\Delta p_i=(R-I)p_i+t
]

没有：

[
p_i
]

这个连续位置，想精确预测 rotation 本来就困难。

# 四、第二项：grid 直接改成 5 mm

现在配置：

```yaml

```

直接改：

```yaml

```

也就是：

[
\boxed{15\text{ mm}\rightarrow5\text{ mm}}

我赞成你直接跳到 5 mm。

不用先试 10 mm。

对于灵巧手：

* 指尖；
* fingertip contact；
* finger pad；
* 小物体 rotation；
* relative hand-object geometry；

PTv3 当前确实根据：

```python
grid_coord = trunc(
    (coord - coord.min()) / grid_size

```

进行空间离散。

所以这个修改是真正会改变 PTv3 空间结构的。

# 六、第四项：打开 RPE

PointWorld 官方当前明确：

```python

```

RPE 是：

**Relative Position Encoding（相对位置编码）**

意思就是 attention 不仅知道：

```text
token A
token B
```

还显式知道：

> B 相对 A 在哪个方向、距离多远。

对于你的任务非常合理。

因为 interaction 本身依赖：

[
p^{hand}-p^{object}.
]

特别是：

```text
finger 在物体左侧
```

和：

```text
finger 在物体右侧
```

虽然局部 feature 可能相似，但作用 torque 完全不同。

所以我建议：

```yaml
enable_rpe: true
```

# 十一、pretrained checkpoint 怎么办？

继续加载。

不用放弃。

因为这四项里面：

### xyz feature

只改变：

```text
scene_adapter
hand_adapter
```

它们本来就是新训练的。

---

### grid size

不改变任何 parameter shape。

---

### DropPath

没有参数。

---

### shuffle order

没有参数。

---

### RPE

会新增 RPE 相关参数。

所以 PointWorld checkpoint：

```text
PTv3 backbone 原有参数
```

仍然能加载。

只有：

```text
RPE parameters
```

因为官方 checkpoint 没有，保持随机初始化。

所以 partial load 时预期看到：

```text
existing PTv3 weights -> loaded
new RPE weights        -> missing / random init
```

这是正常的。

**不要因为 missing 增加就报错。**

但要在 `load_report` 里打印：

```text
loaded pretrained tensors
missing RPE tensors
```

确认除了新 RPE 以外，没有大量旧参数莫名其妙 load 失败。

所以先：

之后正式大规模 GRAB train 时，再考虑打开。
