# ObjectInteractionCm V1.3 指导

- 状态：`final`
- 日期：2026-09-10
- 来源：用户确认 V1.3 配置、cache 语义和 unique-KNN-hand supervision 语义
- modification_version：`V1.3`

## 1. 研究与数据目标

在不改变现有 ObjectInteractionCm 数据 split、GT、坐标系和物体点池语义的前提下，建立新的全量
KNN cache，供后续 V1.3 训练使用。

固定范围：

- 沿用 V1.2.5 的 630 条序列和 train/val/test split；
- 处理全部 159476 帧，包含 train、val、test；
- 右手、30 Hz、`object_pose_t` 坐标系；
- 完整物体点池为 4096 点，训练时仍随机采样 1024 点；
- MANO KNN 手点数为 2048；
- Inspire KNN 手点数为 10135；
- 物体到手 KNN `K=32`；
- interaction radius 为 2 cm；
- hand supervision radius 为 2 cm。

## 2. 高分辨率手点与训练监督

MANO 的 2048 点和 Inspire 的 10135 点是 V1.3 的高分辨率 hand source。对每个训练样本：

1. 从完整 4096 个 object pool 点中随机采样 1024 个点；
2. 用 cache 中每个 object 点的 32 个 hand ID，运行时重新计算这 32 条边的距离；
3. 只保留 `distance <= 0.02 m` 的有效 KNN 边；
4. 交互特征使用这些有效边；
5. 将有效边中的 hand ID 去重，hand decoder 和 hand-flow loss 只对这些唯一 hand 点计算一次；
6. 不监督没有出现在本次有效 KNN 边中的其他 2 cm 内 hand 点。

hand 点张量按当前 batch 内实际选出的最大唯一 hand 点数动态 padding，并通过
`hand_valid_mask` 排除 padding。不会固定 padding 到 10135；只有 batch 中实际出现的最大点数决定
本 batch 的 hand 维度。若一个样本没有有效边，保留一个 `valid=false` 的占位点以维持张量维度，
该样本由 interaction validity 逻辑跳过 loss。

旧的 1538 点 decoder stream 和对应 mask 可以保留作 V1.2.5/V1.3 兼容输入，但不参与 V1.3
新的 hand feature 或 hand supervision。

## 3. Cache 与运行时合同

每条 sequence 的 geometry 至少包含：

- `hand_points_world.npy`、`hand_normals_world.npy`：保留的旧 1538 点兼容 stream；
- `knn_hand_points_world.npy`、`knn_hand_normals_world.npy`：MANO 2048 或 Inspire 10135 点完整
  高分辨率 hand stream；
- `obj_knn_indices.npy`：形状 `[T,4096,32]`，dtype `uint16`，索引指向当前 sequence 的 KNN hand stream；
- `obj_candidate_mask_2cm.npy`：形状 `[T,4096]` 的完整物体池 2 cm mask；

不保存 KNN 距离数组。训练时先按随机抽取的 1024 个物体点 gather 对应的 32 个 hand index，
再用当前 object/hand 几何重新计算这 32 个距离，并施加 `distance <= 0.02 m`。有效边中的
hand ID 在训练样本内去重后作为 decoder/loss hand 点。训练路径不再对 4096 个物体点和全部
高分辨率手点执行完整 `cdist`。现有 `obj_knn_indices`、完整高分辨率 hand 点和 future frame
geometry 已经足够实现该合同，不需要新增 high-resolution hand supervision mask 或完整距离数组。

`active_only` 只影响 loader 的 frame row 过滤；cache 本身仍保存所有帧。旧
`object_interaction_cm_dexplore_rl_v1_2_5` cache 必须保留，新 cache 使用独立路径。

## 4. 计算资源

采用 GPU batched KNN。默认按 sequence 分片使用物理 GPU `2,4,5,6`，每张卡一个 worker；不占用
已有任务所在的 GPU `1,3,7`。每个 worker 使用固定 frame batch，按 sequence 独立写入，最后由
finalize 步骤合并 index 和 run manifest。

## 5. 禁止事项

- 不改变现有 sequence split、GT、hand side、坐标系和 4096/1024 物体点语义；
- 不覆盖或重写 V1.2.5 cache、配置、checkpoint 和训练输出；
- 不把 KNN 距离数组写入正式 cache；
- 不把没有出现在当前样本有效 KNN 边中的 hand 点接入 hand supervision；
- 不因 batch padding 对同一个 hand 点重复计算 hand-flow loss；
- 不因 cache 构建成功而宣称科研效果成立。
