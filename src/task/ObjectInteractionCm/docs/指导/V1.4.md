# ObjectInteractionCm V1.4 指导

- 状态：`final`
- 日期：2026-09-14
- 来源：用户确认的扩容方案
- modification_version：`V1.4`

## 1. 目标

扩大 ObjectInteractionCm 的训练数据，使用完整 GRAB 和 ARCTIC；每条 MANO/SMPL-X 双手动作都分别几何重定向到左右 Inspire 手，再将两只手作为无 side-ID 的统一 hand stream 训练 OI-Cm。

## 2. 固定边界

- GRAB 使用完整 1335 条原始序列；不沿用 Dexplore 的 660 条过滤作为训练上限。
- ARCTIC 参与训练，并保留铰接物体的跨帧几何与 articulation 状态。
- 左右手点在 MANO 和 Inspire 中都拼接后统一统计；模型输入不提供 left/right、finger、source 或 semantic ID。
- Inspire 只使用 geometric retarget 结果，不使用 Dexplore RL rollout 或实际仿真物体轨迹。
- 现有 val/test 的序列成员和帧索引保持不变；新增序列只进入 train。val/test 按新双手表示重新生成 cache，但不改其成员、帧范围和评估 stride。
- 保持模型结构、loss、采样点数、KNN 半径、optimizer、学习率和 epoch 总数；训练 `max_steps` 按新的 train loader 每 epoch 样本数重新计算。
- 主重定向路线优先复用 Dexplore 的 dex-retargeting；TopoRetarget 只作为独立候选 pilot，不能未经验证替换主路线。

## 3. 禁止事项

- 不覆盖 V1.3 cache、split、checkpoint、配置或输出。
- 不把左右手分别作为 source 类别，也不在训练时加入 side token。
- 不把 geometric 与 RL Inspire 轨迹混在同一 cache/source 名称下。
- 不把 ARCTIC 的 articulated object 当作静态刚体；object point ID、part 和当前帧 pose 必须跨帧一致。
- 不使用 val/test 统计校准 scale，不按结果修改 split，不因 smoke 成功宣称科研效果成立。

## 4. 数据合同

新的 V1.4 cache 独立于 V1.3，至少保存：

- object pool `[T,4096,3]`、normals、当前帧 `object_pose_t` 和 future frame geometry；
- 双手兼容 stream `[T,3076,3]`（左右各 1538）；
- 双手高分辨率 KNN stream `[T,4096,3]`（MANO 2048×2，Inspire 10135×2）；
- `obj_knn_indices [T,4096,32] uint16`、2 cm candidate mask 和双手合并后的 supervision 信息；
- ARCTIC 的 articulated object part/angle 字段及稳定 point correspondence；
- source、sequence、原始 frame ID、split、坐标系、单位、输入资产 hash 和导出版本。

双手合并时先为左右手建立不重叠的点 ID，再在统一坐标系中拼接；KNN 和 hand loss 只把合并后的点视为一个点集。

## 5. 重定向

- GRAB：从完整 canonical InterAct/GRAB 表示得到左右 MANO/SMPL-X hand joints，分别调用 Inspire right/left geometric retarget，保留同一 object pose 和 30 Hz 时间轴。
- ARCTIC：从原始左右 MANO 参数和 articulated object pose 得到双手关键点，分别调用 Inspire right/left geometric retarget；物体两部件的 canonical mesh、part ID 和 articulation angle 保持一致。
- 每条序列必须通过双手 FK、手-物距离、finite、时间长度、object pose 和 point correspondence 检查；失败序列进入显式错误清单，不静默丢弃。
- TopoRetarget 输入合同是 MediaPipe 21 点，目前没有 Inspire 模型；只允许在少量 GRAB/ARCTIC 序列上做适配性 pilot。

## 6. 训练预算

新 train sequence 数量和实际 rows 生成后，按旧 V1.3 的 epoch 语义计算新的 `max_steps`，保持 epoch 总数不变。source sampling 仍使用 MANO/ARCTIC-MANO 与 Inspire-geometric 两类等权采样；具体 source label 和比例写入新 manifest。

## 7. 验证顺序

1. 上游 InterAct/ARCTIC 输入与依赖盘点。
2. GRAB/ARCTIC 各一条序列、左右 Inspire 各一只的重定向 pilot。
3. 双手合并 cache schema、KNN、object articulation 和 val/test 成员冻结检查。
4. 新 loader/model CPU synthetic 与小 GPU smoke。
5. 全量 geometric 导出、V1.4 cache finalize、train-only scale。
6. 按新 max steps 启动正式 OI-Cm 训练。

工程 smoke 只记 `ENGINEERING_PASS`；模型效果需要正式训练和预定评估后再给出 `SUPPORTED`、`REFUTED` 或 `INCONCLUSIVE`。
