- 状态：`final`

## 1. 目标与不变量

实现 V1.2.1 的物体侧 interaction-Cm：`D=128` 延迟压缩，5 cm KNN 邻域，mask-before-top-k，双路 geometry/flow interaction，硬 mask SlotAttn，`B` 不变的 sample-level mask，两个 additive decoder。object decoder 只接原始 object point/normal + Cm + anchor geometry；hand decoder 不接 GT flow。保持 object frame、GT、split、loss 语义、评估指标和已有 cache 不变。

禁止：`B→B'` 动态 compact、语义 nullCm、将 U/Ofeat/Iflow 旁路给 object decoder、route softmax、padding 参与 top-k、重复导出 cache、修改共享 `src/base` 合同。

## 2. 影响等级、审批和回滚

- 级别：`L1`（Task 内模型/runner/config 实现）+ `L0`（架构/计划/诊断脚本），训练为 `operation`；不触碰共享 base、数据 schema 或 split。
- 审批：`user-approved`；依据是本条消息中“按照 V1.2.1 继续修改架构、直接开始写 plan、准备训练，先 smoke 再全量、cache 可复用则不重复导出”。
- 回滚入口：删除/恢复本次新增的 V1.2.1 文档、task 内代码/config/script 和新增 outputs；旧 V1.1 文件、cache、checkpoint 不修改。

## 3. 文件范围

### 文档与配置

1. 新增 `docs/architecture/V1.2.1.md`（本架构快照）。
2. 新增本文件并在完成时记录最终验证。
3. 新增 V1.2.1 active config 与 smoke config；不覆盖 V1.1 YAML。
4. 更新 Task 级 activity，记录 cache 复用、scale、实现和运行入口。

### 模型实现

1. `model.py`：`LocalHandInteraction` 拆分 geometry/flow 编码和 value，加入 train-calibrated scale，mask-before-top-k，输出 `Igeo/Iflow/vbar/sbar`；主模型使用 `D=128,C=32`，输出 `sample_valid`，保持 B。
2. `slot_attention.py`：新增 `[B,N]` hard mask 和全空行 dummy computational path，保持输出 B 不变并避免 NaN。
3. `decoder.py`：object/hand decoder 改为 additive per-slot contribution；object decoder只读 raw object geometry + Cm，hand decoder保留 raw hand geometry后再压到 D；保留 contribution usage 诊断。
4. `runner.py`：按 sample 先求点平均再 mask/归一化；空 batch 返回零图并跳过 optimizer step；所有 EPE/slot/interaction 指标按 `sample_valid` 屏蔽，记录 miss/valid 统计。
5. 必要时仅在 Task 目录增加兼容性测试，不改共享 runner。

### 数据与诊断

1. 新增 `tools/data/calibrate_scales.py`：只读现有 index/cache，按 train source/stride 等权统计 `s_geo/s_hand_flow/s_obj_flow`，输出小型 JSON；不导出任何重复 cache。
2. 新增 `tools/data/analyze_sampling_miss.py`（或由校准脚本同时输出）：比较完整 4096 pool 与随机 1024 sample 的 active 数，估计条件 miss ratio，决定 retry 默认值。
3. 先运行 cache/index validator 和 dataset probe；现有 `object_interaction_cm_v1_1/index.json` 可直接复用则不写 adapter。

## 4. 配置和接口

V1.2.1 active config 固定 `num_obj_pool=4096,num_obj_points=1024,num_hand_points=1538,max_hand_points=3076,processing_dim=128,cm_dim=32,num_cm_tokens=16,slot_iters=3,knn_k=8,interaction_radius_m=0.05,hand_supervision_radius_m=0.03`。`scale_manifest_path` 指向 train-only JSON；`sampling_retry_attempts` 初始为 0，依据 miss 分析决定是否改为 4（若改动需在 activity 说明）。

模型输出最低合同：`pred_obj_flow [B,N,3]`、`pred_hand_flow [B,H,3]`、`cm_tokens [B,S,C]`、`cm_assignment [B,S,N]`、`cm_slot_weights [B,S,N]`、`sample_valid [B]`、`object/hand_contribution_usage` 和 interaction diagnostics。旧测试需要的 routing key 可作为兼容 alias，但不得影响 additive forward。

## 5. 实施顺序

1. 只读确认当前 dirty worktree、指导/日志、index/schema 和旧测试。
2. 写入并定稿本 V1.2.1 架构/plan（完成）。
3. 实现 KNN、scale 注入、双路 interaction、masked SlotAttn、additive decoders、sample-masked runner。
4. 写 active/smoke YAML 与 scale/miss 分析脚本。
5. 执行静态检查和 Task 定向测试：`py_compile`、`pytest src/task/ObjectInteractionCm/tests tests/test_object_interaction_cm.py`（若旧测试存在兼容断言则保留）。
6. 执行 cache probe；运行 scale/miss 诊断，产出 `scales_train.json` 和分析 JSON。若 cache 不兼容才实现最小读取 adapter。
7. 使用 smoke config 启动 2~10 steps（依显存调整），检查 forward/backward 无 NaN、sample mask、dummy path、manifest、metrics/train log、checkpoint 可加载。smoke 结论只标记工程 `SUPPORTED`，不作科研效果结论。
8. smoke 通过后启动全量 config；不覆盖旧 run，使用新的 `outputs/ObjectInteractionCm/<run_id>/`。按分钟级等待，记录 run_id/status、命令、base commit、scale/cache manifest 和最终 metrics/checkpoint。

## 6. 验证口径

- 工程：mask-before-top-k、全空 SlotAttn finite、`sample_valid` 维度/梯度、additive contribution 求和、raw decoder 输入、cache schema、manifest 链接。
- 诊断：train-only scale group、`N_active_4096/N_active_1024`、条件 miss、retry_count、有效样本比例、source/stride 汇总。
- 科研：只有全量训练并与旧 Cm parity（同 split/stride/seed/target scaling）比较后才给 `SUPPORTED/REFUTED/INCONCLUSIVE`；smoke 不代表效果。
