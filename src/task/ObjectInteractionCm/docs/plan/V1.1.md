## 二、目标与非目标

### 目标

建立一个与旧 Cm 独立的 `ObjectInteractionCm` Task，验证以下最小表示：

\[
\text{object intrinsic feature} + \text{local dual-hand interaction}
\rightarrow 16\times32\ C_m
\]

并同时训练：

\[
C_m\rightarrow\Delta P_o,
\qquad
(C_m,P_L\cup P_R)\rightarrow\Delta P_L\cup\Delta P_R.
\]

### 非目标

- 不继承旧 Cm 的 DenseToken、FrozenDenseToken、contact prior、HardConcrete gate、slot pruning、TopK、
  fallback slot 或旧 checkpoint 兼容逻辑；
- 不向输入暴露 left/right ID、finger ID、source ID、MANO 顶点对应关系或 GT object flow；
- 不改变仓库已有 object-frame 的科学语义，不迁移或重建旧 cache；
- 不在本计划中加入 adaptive slot、contact auxiliary loss、radius query 替代 KNN 或多种复杂 ablation。

## 三、拟冻结的 V1.1 合同（以指导 V1.1 为主）

指导文件保留了方案讨论的原始对话；其中早期的 `32×128`、`512` 点和三组实验矩阵描述，按用户确认的
`16×32`、`1024` 点、“available-hand union”和“先不跑矩阵”决策解释，不回写对话原文。

### 3.1 样本与坐标

每个样本由同一 source、sequence、current frame 和同一 stride 的所有可用 hand 流组成：

```text
shared + available hand streams
        ↓
P_h = ⋃ P_{hand}
```

GRAB 对外读取 left/right 后拼接；Inspire-F1 对外读取单一机器人 hand 流。为保证 batch 形状，Dataset 统一输出最多
`3076` 个 hand 点，并附带 `hand_valid_mask`；padding 点不参与 KNN、attention 或 loss。建议字段为：

```python
{
    "obj_points":      [B, 1024, 3],
    "obj_normals":     [B, 1024, 3],
    "obj_flow_gt":     [B, 1024, 3],
    "hand_points":     [B, 3076, 3],
    "hand_normals":    [B, 3076, 3],
    "hand_flow":       [B, 3076, 3],
    "hand_valid_mask": [B, 3076],
    "obj_valid_mask":  [B, 1024],
    "delta_time_s":    [B],
}
```

所有参与模型计算的点和法向必须最终位于 `object_pose_t`。当前仓库的 cache 通常以 world-frame 文件存储，
再用当前帧 `obj_pose_world` 映射到 `object_pose_t`；这属于复用现有转换合同，不是新增坐标系。没有
`obj_pose_world`、source 内 hand 帧不对齐或混入其他坐标合同时必须显式失败。

### 3.2 当前帧 5 cm 过滤

只使用当前帧的 available-hand union 判断：

\[
d_{\min}=\min_{p_h\in \bigcup P_{hand},\;p_o\in P_o}\|p_h-p_o\|.
\]

`d_min > 0.05 m` 的 current frame 不进入 `_samples`；future frame 不参与筛选。GRAB 复用左右
candidate/activity 的 union；Inspire 复用 episode 的 object candidate mask；两者均用数据 smoke 复核其等价于
当前帧 available-hand union 距离规则。

### 3.3 Object 点与局部 hand edge

V1.1 模型输入为 1024 个 object point；object pool 保持现有缓存的 4096 点表面池，不重新 FPS。每个 object
point 在 available-hand union 中取 `K=8` 个最近有效 hand points。每条 edge 使用：

\[
r_{ij}=p_j^h-p_i^o,\quad d_{ij}=\|r_{ij}\|,\quad
s_{ij}=n_i^o\cdot n_j^h.
\]

边特征使用 `[r_ij, d_ij, n_j^h, s_ij, Δp_j^h]`，总维度 11；V1.1 只使用可在推理时获得的 hand flow，
不使用 GT object flow；超过 5 cm 的边使用 radius mask。
padding hand points 不进入 KNN；没有合法邻居时该 object point 的 interaction feature 为零，并保留可诊断的
`has_interaction`/邻居计数。

### 3.4 Object feature、cross-attention 与融合

object 自身特征必须是主干而非被 hand feature 替换：

```text
[obj_xyz, obj_normal] 6 -> 64 -> 32 = o_i
edge 11 -> 64 -> 32 = e_ij
```

每个 object query 对该点的 8 条 local edge 做 single-head cross-attention：

\[
q_i=W_q o_i,\quad k_{ij}=W_k e_{ij},\quad v_{ij}=W_v e_{ij},
\]

\[
\alpha_{ij}=\operatorname{softmax}_j(q_i k_{ij}^{\mathsf T}/\sqrt{32}),\qquad
h_i=\sum_j\alpha_{ij}v_{ij}.
\]

该实现与 additive/Bahdanau scalar attention 都是 query-key 打分后聚合，但不宣称二者数学等效；V1.1
按指导 V1.1 使用标准 dot-product cross-attention，mask 后全无效时直接置零。

最终 object token 显式保留 object intrinsic：

```text
u_i = MLP([o_i, h_i])       # 64 -> 32
U_o = [B, 1024, 32]
```

不把 `z_obj`、`z_hand`、contact 或 future/GT flow 绕过 Cm 注入 decoder。

### 3.5 Slot Attention 与 anchor

```text
num_slots = 16
slot_dim = 32
slot_iters = 3
```

输入 `U_o [B,1024,32]`，输出 `C_m [B,16,32]`。第一版不使用 gate、pruning、TopK、L0、fallback 或 active
threshold，所有 16 个 slot 参与。Slot assignment 必须可回投到 object point，得到 object-side anchor：

\[
p_k^{Cm}=\sum_i A_{ki}p_i^o,\qquad
n_k^{Cm}=\operatorname{Normalize}(\sum_i A_{ki}n_i^o).
\]

### 3.6 两个 flow decoder 与 loss

- object decoder：复用旧 Cm decoder 的必要几何/slot routing 思路，但重写为 `cm_dim=32`、`16` slots；不
  加载旧 Cm checkpoint；输出 `pred_obj_flow [B,1024,3]`。
- hand decoder：所有 source 共用一个 head，输入为 padded available-hand union 及 `C_m` 和 anchor geometry，输出
  `pred_hand_flow [B,3076,3]`，按 `hand_valid_mask` 和 source 统计。
- hand loss 只使用 current frame 的 `d(p_j^h,P_o)<0.03 m` mask 与 `hand_valid_mask`，不对 source 或手点加独立权重；没有有效 3 cm
  点的样本 hand loss 记为 0 并计入诊断，不因该条件再次改变 5 cm 样本筛选。
- 总损失暂定 `L = L_obj + 1.0 * L_hand`；slot sparsity/diversity 只监控，不进入 V1.1 loss。

## 五、分阶段执行与验证

### Step 0 — 合同确认

已完成用户确认，`plan/V1.1.md` 作为 `final` 执行；实现过程中仍检查 Task 的版本指针和
`modification_version` 是否保持为 `V1.1`。

### Step A — Available-hand Dataset 与 source adapter（已完成）

1. 为 GRAB mmap 与 Inspire-F1 layered-v4 建立 source adapter，以各自 source 的 frame timeline 严格校验 hand、object、pose 和 future stride；不改写原 cache；
2. 用当前帧 available-hand union 做 5 cm frame filter，生成 `_samples`，不读取 future frame 做筛选；
3. 从完整 4096 点 object pool 采样 1024 object points；将 GRAB 的左右 hand 或 Inspire 的单 hand 写入最多 3076 点的 union，并生成 `hand_valid_mask`；
4. 用真实 GRAB/Inspire cache smoke 检查保留比例、当前最小距离、有效 hand 点数、`delta_time_s` 和 source 标识；
5. 新增轻量 index/manifest 只写到 `data/processed_data/...`，通过引用现有 source cache 避免大规模复制；GRAB 两个损坏序列重新导出后再纳入。

### Step B — Object local aggregation（已完成 smoke）

用合成 batch 和每个 source 的真实 batch 验证 `[B,1024,8]` KNN、5 cm edge mask、11D edge encoding、cross-attention
权重及 `h_i=0` 的全无效分支；输出最近距离、合法邻居数、最大 attention 和 attention entropy 诊断。

### Step C — 16×32 Cm（已完成 smoke）

接入 object-preserving fusion 和 Slot Attention，检查 `U_o [B,1024,32]`、`C_m [B,16,32]`、assignment
`[B,16,1024]`，并验证所有 `p_k^{Cm}` 落在 object surface 的加权包络内；观察 slot assignment 是否全挤在
同一 contact region，但不据此加入 gate。

### Step D — 两个 flow decoder（已完成 smoke；全量训练已启动）

最后接 object/hand decoder，先在小数据上 overfit，检查 object flow、3 cm hand flow、padding/空 hand mask、梯度和
NaN/Inf；通过后再讨论正式训练。正式训练/评估必须单独生成配置快照、`run_manifest.json`、`summary.json`
并写入 Task activity/experiment 记录；smoke 只作为工程证据，不作为效果结论。

## 八、已确认的语义决策

以下决策由用户在 2026-09-02 确认，已纳入 V1.1 最终计划：

1. edge flow feature 只使用 hand flow，不使用 GT object flow 或其他 future object motion 输入；
2. object pool 保持完整 4096 点，模型每帧采样 1024 个 object points；
3. 3 cm hand-supervision mask 使用完整 4096 点 object pool 计算；
4. 输入使用所有真实可用 hand points 的 union：GRAB 为 left/right，Inspire-F1 为单 hand；padding 用 valid mask，
   不复制或零填充伪造手；
5. GRAB/Inspire-F1 在同一 run 按 `0.5/0.5` 混合，分别沿用 `1..10` 与偶数 `2..20` stride 约定；
6. V1.1 先只完成和验证架构，不运行 old Cm/OI-Cm 实验矩阵；
7. 指导和计划统一使用 `V1.1` 命名，细分实现版本使用 `V1.1.<k>`。

目前没有新的阻塞性问题。若实现阶段发现 cache 中 4096 点池或 object pose 字段与上述合同不一致，将暂停并重新
协商，不通过隐式转换改变研究语义。
