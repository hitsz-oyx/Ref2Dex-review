## 1. 目标与问题边界

V1.2 只解决三个互相关联的问题：

1. Inspire-F1 的 hand padding 必须在 KNN `topk` 之前排除，不能让 zero padding 占据邻居名额。
2. object-side SlotAttn 只聚集确实存在交互邻居的物体点，避免 1024 个物体 token 中的大量无交互点稀释 Cm。
3. 保留交互边和手流的高维原始表征，直到 SlotAttn 完成后才压缩成 Cm；物体 decoder 只使用原始 object point/normal、Cm 和 object-anchor 几何，不能绕过 Cm 读取 interaction/hand-flow 特征。

V1.2 不改变研究问题“由交互物体点聚集 Cm 并预测双流”的定义，不修改坐标系、数据 split、GT、物体候选点的物理语义或评估指标含义。

## 2. 明确不做的事情

- 不重写 `src/base`，不改变公共 `BaseRunner`、manifest 或 checkpoint schema。
- 不迁移旧 cache，不覆盖旧输出、checkpoint 或用户已有的 V1.1 文档改动。
- 不把预测的 hand flow 或 object flow 当作下一时刻输入；模型输入仍为当前帧几何、法向、接触标签和 hand-flow GT/特征字段中允许的观测量。
- 不在本计划内同时搜索 slot 数、KNN 半径、数据 split、loss 权重和初始化策略；这些变量在公平比较实验中冻结。
- 不把“smoke 可运行”解释为 object EPE 提升；研究结论必须来自 parity run 和固定 stride 的结果。

## 3. 冻结的张量与接口合同

以下是首版实现的默认合同，除非计划评审时明确修改，不在代码中隐式变更：

| 名称 | 形状 | 说明 |
|---|---:|---|
| `object_points` | `[B,1024,3]` | 当前物体坐标系采样点 |
| `object_normals` | `[B,1024,3]` | 与物体点同序 |
| `hand_points` | `[B,3076,3]` | 左右手合并；padding 由 `hand_valid_mask` 标示 |
| `hand_normals` | `[B,3076,3]` | 与手点同序 |
| `hand_flow` | `[B,3076,3]` | 当前 hand-flow 特征；不在 edge 输入前压到 32 维 |
| `hand_valid_mask` | `[B,3076]` | padding 必须为 false |
| `edge_valid_mask` | `[B,1024,8]` | KNN 邻居是否为真实且在半径内的手点 |
| `object_pool_mask` | `[B,1024]` | `object_valid_mask & edge_valid_mask.any(-1)`，仅供 SlotAttn |
| `sample_keep` | `[B]` | `object_pool_mask.any(-1)`；false 样本从 SlotAttn、decoder、loss 和指标中移除 |
| `object_intrinsic` | `[B,1024,128]` | 纯物体几何表征，仅供 interaction query、fusion 和 SlotAttn |
| `interaction_geo` | `[B,1024,128]` | 由 edge geometry value 聚合得到的局部表征 |
| `interaction_flow` | `[B,1024,128]` | 由 hand-flow value 独立聚合得到的局部表征 |
| `flow_mean` / `flow_mag` | `[B,1024,3]` / `[B,1024,1]` | 未经 feature projection 的显式 hand-flow 统计 |
| `cm_raw` | `[B',16,128]` | `sample_keep=True` 子 batch 的 masked SlotAttn 输出，未压缩 |
| `cm_tokens` | `[B',16,32]` | `cm_raw` 经过唯一的 late projection 后的 Cm |
| `object_flow` | `[B',1024,3]` | 保留样本的物体 decoder 输出 |
| `hand_flow_pred` | `[B',3076,3]` | 保留样本的 hand decoder 输出 |

处理宽度设为 `processing_dim=128`，Cm 接口宽度仍为 `cm_dim=32`。这不是把 Cm 改成 128，而是把 128→32 的语义瓶颈推迟到 SlotAttn 之后。
`sample_keep=True` 的样本压缩为有效子 batch `B'` 后，SlotAttn、Cm、decoder 和 loss 的 batch 维统一使用 `B'`；`B'` 可能小于原始 `B`。

## 4. 实施阶段与文件范围

### 阶段 A：先修 mask 合同并写回归测试

涉及：`src/task/ObjectInteractionCm/model.py`、必要时 `dataset.py`、`src/task/ObjectInteractionCm/tests/`。

- 在 `LocalHandInteraction` 中先根据 `hand_valid_mask` 将无效 hand 距离设为 `inf`，再执行 `topk`。
- `edge_valid_mask` 同时要求 hand 有效、距离不超过 `knn_radius`，并保持 `[B,N,K]` 对齐。
- 为“有效 hand 远、padding zero 近”的合成输入写测试；断言 top-k 不包含 padding，且全 padding 样本返回全 false mask 与零 interaction。
- 保留 GRAB 全有效路径的行为测试，避免修复 Inspire padding 时改变正常样本的邻居排序。

### 阶段 B：延迟压缩的特征路径

涉及：`model.py`、可能拆出的局部 encoder 文件、配置读取处。

- object intrinsic：`[xyz, normal] 6 → 64 → 128`。
- edge geometry：`[relative_xyz, distance, local_normal, normal_dot]` 共 8 维，`8 → 64 → 128`。
- hand-flow 专支路：`hand_flow 3 → 64 → 128`，与几何支路分别归一化和编码；禁止在输入 edge 时直接合并成 32 维。
- 局部 Q/K/V 和 edge 聚合均使用 128 维；key 可以使用 `LayerNorm(E_geo+E_flow)`，但 value 分成 `I_geo` 和 `I_flow` 两路。
- 额外保留未经过 feature projection 的 `vbar_i∈R^3` 和 `sbar_i∈R`，再用 `u_i = LayerNorm(object_intrinsic_i + F([object_intrinsic_i, I_geo_i, I_flow_i, vbar_i, sbar_i]))` 融合。
- `u_i` 只进入 SlotAttn；object decoder 只接收原始 object point/normal、`cm_tokens` 和 object-anchor 几何，防止 interaction/hand-flow 绕过 Cm。

### 阶段 C：硬 mask SlotAttn

涉及：`slot_attention.py`（若不存在则在 Task 内新增）、`model.py`、配置。

- `object_pool_mask = object_valid_mask & edge_valid_mask.any(-1)`。
- masked SlotAttn 只接收 `sample_keep=True` 的子 batch，输入为 `[B',1024,128]`；保留下来的样本中，无交互点不参与 assignment，也不参与 slot weight 分母。
- assignment 仍按每个点在 slot 维归一化（`softmax(dim=slots)`）；不要误改成在点维归一化。
- 16 个 slot、3 次迭代作为默认值；输出 `cm_raw=[B',16,128]`，随后单独 `Linear(128,32)` 得到 `cm_tokens=[B',16,32]`（恢复原 batch 对齐时对空样本不填值）。
- 若一个 frame 的 1024 个采样物体点均无交互点，计算 `sample_keep=False`，将该样本从本次 batch 的 SlotAttn、decoder、loss 和指标中移除；不得使用 `null-Cm`、填零流或静默退回全体物体点。全 batch 被移除时跳过 optimizer step 并记录。
- 若均匀 1024 点采样造成交互点不足，优先增加“交互候选配额”的确定性采样策略；该策略需单独开关和指标，不与硬 mask 混为一个变量。

### 阶段 D：decoder 与 loss 解耦

涉及：`decoder.py`、`runner.py`、配置。

- object decoder 输入：原始 object point/normal 共 6 维、`cm_tokens(32)`、相对几何和 anchor normals；单个 point-slot 输入为 `6+32+3+3=44` 维，hidden width 128。
- object 和 hand decoder 都使用真正的 additive slot contributions：每个 slot 独立产生 3D contribution，沿 slot 维直接求和；不使用 RouteHead/softmax 作为 flow 权重。slot usage 只由 contribution 范数计算 diagnostic。
- hand decoder 继续使用当前手点几何和 Cm，不将 GT hand-flow 作为 decoder 的捷径输入。
- object loss 对当前采样的 `obj_valid_mask` 计算；hand loss 保持 `hand_supervision_mask & hand_valid_mask`，3 cm 接触阈值和 Huber 形式不在本阶段改变。
- target scaling 与 input feature scaling 分离记录；不得用改变输入尺度来掩盖维度瓶颈。

### 阶段 E：工程验证与短跑

1. 静态检查和单元测试。
2. CPU synthetic forward：检查所有张量形状、mask、NaN/Inf、空交互样本 drop 和全 batch drop。
3. 小数据 overfit/短 GPU smoke：确认 loss 下降、checkpoint 可保存加载、manifest 完整。
4. 仅在前述检查通过后开展 parity 训练；不在 smoke 阶段比较最终科研结论。

## 6. parity 实验合同（实现通过后再执行）

与旧 Cm C64 比较时冻结：GRAB/Inspire split、样本实例、物体采样数、评估 stride、目标坐标系、optimizer、学习率 schedule、target scale、global batch、初始化来源和训练总样本数。至少记录：

- source-level object/hand EPE 以及 equal-source 汇总；固定 stride，不用不同 stride 的数字直接比较；
- `valid_neighbors`、`object_pool_mask` active ratio、`dropped_no_interaction_count/ratio`、全 batch drop 次数；
- `N_active_4096`、`N_active_1024` 以及 `P(N_active_1024=0 | N_active_4096>0)`，判断 sample drop 是否主要由随机采样造成；
- object/hand slot contribution usage（仅 diagnostic，不参与 additive 求和）；
- flow branch ablation（zero/shuffle hand-flow）和 interaction mask ablation；
- slot entropy、max mass、每 slot 有效点数，确认没有把 mask 稀疏误判为 slot collapse。

只有 parity 条件满足且结果重复后，才给出 `SUPPORTED`、`REFUTED` 或 `INCONCLUSIVE`；工程 smoke 只记为 `ENGINEERING_PASS`。
