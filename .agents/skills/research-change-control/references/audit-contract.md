# 审计合同

随附的审计脚本刻意保持窄范围。它按条目的 `timestamp` 选择最新 activity，而不依赖文档排序。它可以
检查最新条目是否列出了选定 Git 差异中的文件，并包含等级、审批、分支、范围、原因和验证段；在需要
时也能报告缺失或未跟踪路径。

启用 `--check-links` 后，脚本还会解析最新条目中的本地 Markdown 链接，并按 activity 文档所在目录
解析相对目标。外部 URL 和纯页内锚点不检查；绝对本地链接不允许。目标必须存在，唯一例外是
`run_status: STARTED` 或 `RUNNING` 且链接所在行明确标记 `PENDING`。校验只覆盖最新活动条目，不批量
追究历史日志，也不验证 Markdown 标题锚点是否存在。

它不能判断 AI 是否选择了正确等级、科研结论是否有效，或用户是否确实同意了某项修改。这些仍由人复核。

交接时使用 staged 模式，使无关的未暂存工作不会影响审计。只有在整个工作树差异都明确属于当前任务
时，才使用 worktree 模式。链接检查是本机交接校验：被 Git 忽略的输出仍会按本机路径检查，不表示
这些产物应被提交或能在其他 clone 中复现。
