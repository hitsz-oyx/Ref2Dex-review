# 二、AGENTS.md 应该彻底瘦身

你现在的 `AGENTS.md` 思路是对的，但承担的事情太多。

以后它只负责**永久规则**。

最好控制在大约 100～200 行，不要继续增长。

它只写下面几类内容。

## 1. 权威信息在哪里

例如：

```text
仓库导航：
docs/README.md

当前 research version：
docs/current_versions.yaml

Task 当前状态：
src/task/<Task>/docs/README.md

研究目标：
src/task/<Task>/docs/指导/Vx.md

重大版本实施方案：
src/task/<Task>/docs/plan/Vx.md

实验结果：
src/task/<Task>/docs/experiments/

目录规范：
docs/目录规范.md
```

---

## 2. AI 工作模式

保留四种就够：

```text
inspect
change
run
governance
```

对应：

```text
inspect
只读分析，不修改

change
修改代码 / config / tests / docs

run
训练 / eval / benchmark / 数据处理

governance
修改 AGENTS / Skill / 公共规范
```

不要再产生很多相似模式。

---

## 3. 风险等级

保留 L0～L3，但重新简化：

```text
L0
文档、测试、格式、小型工具，不影响研究语义

L1
Task 内代码实现变化，但 research contract 不变

L2
改变研究语义：
observation / action / reward / GT /
coordinate / unit / dataset split / metric /
checkpoint semantics / model formulation

L3
共享 src/base、数据迁移、破坏性操作、
仓库治理、正式长时高成本运行
```

审批规则：

```text
L0/L1
AI 可以执行，完成后汇报

L2/L3
必须先告诉用户：
准备改变什么
保持什么不变
怎么验证
然后用户确认
```

够了。

---

## 4. Git 规则

直接写死：

```text
oyx 是稳定集成分支。

除非用户明确要求，
AI 不直接在 oyx 上开发。

每个独立任务：
oyx
→ ai/<task>/<description>
→ implementation
→ verify
→ PR
→ merge
→ delete branch
```

并规定：

```text
一个任务一个 branch。

实验参数变化不创建 branch。

不得 reset / overwrite 用户已有修改。

不得提交 outputs、checkpoint、cache、大型日志。
```

---

## 5. AI 完成任务的唯一门禁

AGENTS 里不要再列十几条验证命令。

只规定：

```bash
python tools/verify.py --changed
```

必须 PASS。

然后 Skill 决定具体怎么调用。

这是非常重要的变化。

# Skill 1：`research-change-control`

负责：

> **AI 改东西的时候怎么做。**

流程应该固定为：

```text
确定 Task
↓

↓

↓

↓
L2/L3 → 用户审批
↓
建立 task branch
↓
实施
↓
补定向测试
↓

↓

↓

```

它最重要的一条应该是：

> **不要为了遵守流程读取所有历史。**

默认只加载：

```text

docs/current_versions.yaml
Task/docs/README.md
当前 research version 的指导
相关代码

```

只有出现历史问题时，再搜索：

```text
experiment
activity archive
Git history
decision
```

而不是每次先读 430 KB activity log。

## change Skill 不应该负责

```text

实验结论是什么
```

# Skill 2：`research-experiment-workflow`

负责：

> **训练、评估、benchmark、数据处理怎么跑。**

标准流程：

```text
确认运行代码已经固定
↓
确定 git_commit
↓
确定 research_version
↓
定义 hypothesis
↓
定义变量
↓
定义 metric
↓
定义预算
↓
定义 stop condition
↓
生成 run_id
↓
生成 run_manifest
↓
运行
↓
结束
↓
提炼结果
↓

```

必须明确区分：

```text

```

例如：

```text

```

```text

+

```

这是科研工作流很重要的一点。

# 我的最终建议

你整个仓库以后只需要记住七句话：

1. **`AGENTS.md` 管永恒规则。**
2. **Skill 管 AI 怎么工作。**
3. **Task README 管当前状态。**
4. **指导管研究意图，plan 只管重大版本。**
5. **Git commit 管代码版本，run_id 管实验运行。**
6. **experiment card 管科学证据。**

按照这个体系，你现在那些看起来很乱的：


会自然重新归位，不需要继续增加新概念。

**你现在最适合做的下一件事，就是先只针对“治理层”开一个 branch，把 `AGENTS.md + 两个 Skill + modification_policy + current_versions` 按这套规则重写；科研代码一行不动。**之后再单独做 verify/CI。
