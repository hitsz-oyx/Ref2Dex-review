我看了最新 `oyx`。最新提交是 **`1372b0a`「加1.5cm的远样本接触监督」**。

我的判断是：

> **1–1.5 cm hard negative 的 sampler 改法是合理的；但当前 auxiliary 改成 binary BCE 后，出现了一个新的 objective conflict。这个比采样本身更值得注意。**

---

## 一、当前 sampler 设计是对的

现在仍然是 **object-centric**：

```python
for obj_idx in np.flatnonzero(obj_valid_mask):
    dist_row = distance[obj_idx]
```

即：

```text
固定 object point i
        ↓
查看所有 hand points j
        ↓
按距离/contact strength 采 edge(i,j)
```

四档 positive：

[
(0,0.25],\quad
(0.25,0.5],\quad
(0.5,0.75],\quad
(0.75,1]
]

再加：

[
d\in[0.01,0.015)
]

的 hard negative。代码明确要求 hard negative 同时满足 `target_row <= 0`。

所以任务定义没被改：

[
r_{\rm contact}=1\text{ cm}
]

没有把 1.5 cm 错当 contact。

这部分我认可。

---

## 二、`λ_contact=0.05` 也改对了

当前：

```yaml
loss_cross_edge_weight: 1.0
loss_contact_aux_weight: 0.05
```

这是针对上一轮：

[
L_c\approx20\sim30L_r
]

的直接修正。

如果原始量级仍类似：

[
L_r\approx0.0008
]

[
L_c\approx0.02
]

那么：

[
0.05L_c\approx0.001
]

于是：

[
L_r:0.05L_c\approx1:1.25
]

从 loss 数值尺度看，比之前健康很多。

---

# 三、但当前 auxiliary 已经不是“contact strength supervision”了

runner 现在做：

```python
contact_binary_target = (contact_edge_target > 0).float()
```

然后：

```python
contact_binary_bce_map = BCE(
    contact_logits,
    contact_binary_target,
)
```

最终真正进入 loss 的是：

```python
"cross_edge_contact_aux":
    loss_contact_aux_weight
    * cross_edge_contact_aux_bce
```

也就是说 auxiliary 的目标变成：

[
y>0\Rightarrow t_c=1
]

[
y=0\Rightarrow t_c=0
]

因此：

```text
真实 y=0.05 → aux target=1
真实 y=0.20 → aux target=1
真实 y=0.80 → aux target=1
真实 y=1.00 → aux target=1
```

这已经不是：

> contact quality learning

而是：

> contact existence classification

---

# 四、这里存在明确的梯度冲突

考虑一条 weak positive：

[
y=0.1
]

假设当前模型：

[
p=0.2
]

### random QFL

random stream 希望：

[
p\rightarrow0.1
]

因为 soft GT 是：

[
y=0.1
]

### contact auxiliary BCE

aux stream 做：

[
\mathbb 1[y>0]=1
]

所以希望：

[
p\rightarrow1
]

即：

[
\boxed{
L_r:p\downarrow
\qquad
L_c:p\uparrow
}
]

而且两个 stream 用的是**同一个 edge head**。模型共享 `edge_shared_backbone` 和 `cross_edge_head`。

因此这不是抽象意义上的“可能冲突”。

是 objective 数学定义上确实冲突。

---

## hard negative 只能解决一半问题

加入：

[
10\sim15\text{ mm}
]

negative 后：

```text
d=12 mm
aux target=0
```

模型会学习：

[
p\downarrow
]

这有助于抑制：

```text
near ⇒ 全部预测偏高
```

很好。

但它没有解决：

```text
y=0.05
aux要求p→1
random要求p→0.05
```

所以现在实际上是：

[
L=
L_{\rm quality}
+
0.05L_{\rm contact-existence}
]

这是一种**多任务正则化**。

它不是错。

但是你必须清楚自己现在的方法定义已经变了。

# 五、我个人更推荐 soft target auxiliary 继续用 QFL

现在有 hard negative 后，我反而认为：

[
\boxed{
L_c=\operatorname{QFL}(p,y)
}
]

更自然。

因为 auxiliary stream 已经包含：

```text
very strong positive  y≈1
strong positive       y≈0.6
medium positive       y≈0.4
weak positive         y≈0.1
hard negative         y=0
```

这本身就是一个非常好的 contact-quality stratified set。

例如：

[
y=0.1,p=0.5
]

QFL：

[
p\rightarrow0.1
]

而：

[
y=0,p=0.5
]

QFL：

[
p\rightarrow0
]

以及：

[
y=0.9,p=0.5
]

QFL：

[
p\rightarrow0.9
]

完全符合你的最终 edge 输出定义。

所以我的推荐其实是：

```python
losses = {
    "cross_edge_random":
        1.0 * cross_edge_random_qfl,

    "cross_edge_contact_aux":
        0.05 * cross_edge_contact_aux_qfl,
}
```

而不是 binary BCE。

# 六、当前 diagnostics 也和 binary BCE 不完全对齐

你现在记录：

```python
contact_aux_pred_mean
contact_aux_target_mean
contact_aux_nonzero_mae
contact_aux_edge_y_xxx_mae
```

这些全部是对 **soft target (y)** 算的。

但真正优化的是：

[
t_c=\mathbb 1[y>0]
]

所以可能发生：

```text
weak positive:
y=0.1
prediction: 0.8
```

对于 auxiliary BCE：

```text
很好
```

因为：

[
t_c=1
]

但你的 MAE：

[
|0.8-0.1|=0.7
]

会显示：

```text
非常差
```

所以训练日志会出现：

> `contact_aux_bce` 越来越好，但 `contact_aux_mae` 越来越差。

这不是模型异常。

是 metric 和 training objective 不一致。

hard_neg_mask = (

# 八、测试还有一个描述错误

当前测试叫：

```python
test_sample_contact_sampler_no_contact_yields_zero_valid_edges
```

注释：

> when every distance is `>= r`, no contact edges are sampled.

这个描述在新设计下已经不对。

因为：

[
d=12\text{ mm}\ge r
]

应该采到 hard negative。

测试之所以通过，是因为它构造的是：

```python
hand = 5.0 m away
```

正确语义应该是：

```python
test_contact_sampler_outside_auxiliary_range_yields_zero_valid_edges
```

即：

> 当没有 positive，且没有 `[1cm,1.5cm)` hard negative 时，valid edge 为0。

这是测试命名/注释问题，不影响训练。

## 我的最终判断

### sampler

[
\boxed{\text{通过}}
]

object-centric + 四档 contact strength + 1–1.5 cm hard negative，我认为方向合理。

### 权重

[
\boxed{\lambda_c=0.05\text{ 合理}}
]

### 当前主要争议

[
\boxed{
\text{binary BCE auxiliary 是否符合你的最终任务}
}
]

我的意见是：**不太符合。**

因为最终 edge 输出本身就是：

[
y\in[0,1]
]

的 contact quality。

我更推荐：

[
\boxed{
L=L_{\rm random}^{QFL}
+
0.05L_{\rm stratified+hardneg}^{QFL}
}
]

这样两条流：

```text
random128:
    保留真实 edge distribution

contact-aware:
    提高 contact/boundary coverage
```

但**两者优化完全相同的 pairwise quality target**。

这是我认为现在最干净的版本。

当前 binary BCE 版本不是不能跑，但它已经变成“quality regression + contact classification auxiliary multi-task”。对于你现在只想验证 sampling coverage hypothesis 的实验，**多引入了一个 loss-definition 变量，我不建议。**
