# 上一轮指出的 BCE/MAE 热路径问题仍然存在

当前 `_compute_losses()` 还是每一步无条件计算：

```python
random_bce_map
random_mae_map
cross_edge_random_bce
cross_edge_random_mae
```

contact 同样每一步算：

```python
contact_soft_bce_map
contact_mae_map
cross_edge_contact_aux_soft_bce
cross_edge_contact_aux_bce
cross_edge_contact_aux_mae
```

而且这些 metric 每步都放进：

```python
aux_metrics
```

所以：

[
\boxed{\text{diagnostic_every_steps=20 目前只屏蔽了重 diagnostics 的一部分}}
]

BCE/MAE 仍然白算 20/20 steps。

这个还得改。

我建议普通 step 只保留：

```python
random_qfl_map = ...
cross_edge_random_qfl = ...

contact_qfl_map = ...
cross_edge_contact_aux_qfl = ...

aux_metrics = {
    "cross_edge_random_qfl": cross_edge_random_qfl,
    "contact_aux_qfl": cross_edge_contact_aux_qfl,
}
```

然后：

```python
if compute_diagnostics:
    random_bce_map = ...
    random_mae_map = ...
    contact_soft_bce_map = ...
    contact_mae_map = ...
```

注意这样 train epoch 的 BCE/MAE 就是**每 20 step sampled diagnostic average**，不是所有 batch 的严格 epoch average。

我认为可以接受。`val` 仍然 `mode == "eval"`，会全量计算 diagnostics。当前代码的判断逻辑保证了这一点。

# GPU→CPU sync 还是没有解决

这个目前比 BCE 本身更明显。

`MetricAverager.update()` 仍然：

```python
self.meters[key].update(float(value), n)
```

对于 CUDA scalar：

```python
float(value)
```

就是同步。

当前普通 step 返回多个 CUDA scalar metric，因此会逐个 sync。

而且还有一个更隐蔽的地方：

```python
metrics.setdefault(
    "loss",
    float(loss.detach().cpu()),
)
```

虽然 task runner 已经：

```python
metrics["loss"] = total_loss
```

但是 Python 调函数前会先求值参数，因此：

```python
float(loss.detach().cpu())
```

**仍然会执行。**

所以这句实际上每 step 必 sync。

应该改成：

```python
if "loss" not in metrics:
    metrics["loss"] = float(loss.detach().cpu())
```

不要用带昂贵 default expression 的 `setdefault`。

不过更彻底应该是：

```python
if "loss" not in metrics:
    metrics["loss"] = loss.detach()
```

最后统一 batch transfer metrics。

# grad norm 也必 sync

现在：

```python
grad_norm_value = float(
    grad_norm.detach().cpu()
)
```

每一步发生。

这个比较麻烦，因为你还要记录：

```text
grad_norm
grad_clip_ratio
grad_clipped
```

我的建议是：

> grad clipping 保持每 step，但 grad metric 只在 log step 转 CPU。

例如：

```python
should_log = (
    (self.global_step + 1)
    % self.cfg.train.log_every_steps
    == 0
)
```

`clip_grad_norm_` 照常执行。

但：

```python
if should_log:
    grad_norm_value = float(grad_norm.detach().cpu())
    metrics["grad_norm"] = grad_norm_value
    ...
```

否则不返回 grad diagnostics。

这样不影响优化器：

[
\text{gradient clipping semantics unchanged}
]

只是少记日志。
