## 1. Hand-root 主链路本身是对的

ARCTIC 用：

[
T_{\text{world}\leftarrow\text{hand}}
=====================================

[R_{\text{global orient}},J_{\text{wrist}}]
]

代码明确用 `global_orient` 构造旋转、`joint 0` 作为 wrist 原点。

GRAB 也是同样定义。

Stage 3 做：

[
x_h=R_h^T(x_w-t_{\text{wrist}})
]

法向做：

[
n_h=R_h^Tn_w
]

object 和 hand 使用同一个变换。

这一部分我没有意见。

而且测试覆盖了：

* world → hand-root → world round trip；

* wrist 映射到原点；

* normal 保持单位长度；

* object frame / hand-root frame 下 distance、candidate mask、KNN index 一致。

所以**变换数学没写错**。

# 6. hand-root 下，当前 perturbation 语义需要重新讨论

这个不是代码 bug，但我认为必须想清楚。

当前 dataset 进入 Stage 3 hand-root frame 后，再做 hand perturb：

```python
center = input_hand_points.mean(axis=0)

input_hand_points = (
    (input_hand_points - center) @ rotation.T
    + center
    + translation
)
```

object 不动，只动 hand。

在 object frame 下，这很好理解：

> 模拟 hand observation 的整体 SE(3) 误差。

但到了 hand-root frame，如果真实推理流程是：

```text
估计 MANO root
        ↓
用估计 root 建 hand-root frame
        ↓
hand/object 转进该 frame
```

那么一个 global hand-root estimation error (\Delta T) 的结果其实是：

```text
hand local geometry 基本保持 canonical
object relative position 被 ΔT^-1 改变
```

而不是：

```text
object 固定
hand 在 hand-root frame 中整体漂走
```

所以当前 augmentation 更像：

> **在 clean hand-root frame 内人为错位 hand geometry。**

它不完全等价于：

> root pose estimation noise。

这里我建议先别急着改，但需要明确你究竟要模拟什么。

如果是：

```text
MANO articulation / mesh fitting noise
```

当前 perturb hand 可以保留。

如果是：

```text
whole-hand root SE(3) estimation noise
```

hand-root frame 下应该考虑 perturb frame，从而主要改变 object-relative coordinates。

这两个 augmentation 应该拆成：

```text
hand_articulation_or_mesh_noise
hand_root_pose_noise
```

不要混成一个 `hand_rot_std_deg / hand_trans_std`。

## 1. perturbation 改成扰动物体：对，而且可以在采样 512 点之后做

当前 perturb 是围绕 hand centroid 对整只手施加一个刚体扰动，只改 input hand，GT hand 保持 clean。

切到 hand-root frame 后，我认为这确实不自然。更合理的任务是：

[
\text{clean hand in hand-root frame}
+
\text{noisy object pose}
\rightarrow
\text{clean contact}
]

即：

[
o_i^{input}
===========

R_{\Delta}o_i^{gt}+t_{\Delta}
]

而：

[
h_j^{input}=h_j^{gt}
]

GT contact 仍由 clean geometry：

[
(o_i^{gt},h_j^{gt})
]

计算。

### 可以先采 512 object points，再加扰动

我认为这是正确的。

当前 dataset 本来就是先根据 clean candidate mask 采 object index，再取 512 个 object points。

只要你对 512 个点施加的是**同一个刚体 SE(3)**：

[
T_\Delta=\left(R_\Delta,t_\Delta\right)
]

那么：

[
S(T_\Delta O)=T_\Delta S(O)
]

这里 (S) 是按固定 index 选取 512 点。

所以：

```text
4096 points
    ↓ clean sampling
512 points
    ↓ one shared SE(3) perturbation
noisy 512 points
```

和：

```text
4096 points
    ↓ one shared SE(3)
noisy 4096 points
    ↓ select same indices
noisy 512 points
```

数学上完全等价。

因此没必要先扰动 4096 点。

### 但绝对不要做 per-point jitter

不要：

[
o_i'=o_i+\epsilon_i
]

这模拟的是 surface noise / depth noise。

你现在要模拟的是：

> object pose estimation error。

所以必须：

[
\boxed{
o_i'=R_\Delta o_i+t_\Delta,\quad \forall i
}
]

全部 512 点共用同一个 (R_\Delta,t_\Delta)。

法向：

[
n_i'=R_\Delta n_i
]

我建议把现在：

```text
hand_rot_std_deg
hand_trans_std
hand_perturb_prob
```

直接改成：

```text
obj_rot_std_deg
obj_trans_std
obj_perturb_prob
```

语义不要再叫 hand perturb。

---

### 有一个实验语义需要注意

现在 object index 是根据 clean：

```python
obj_candidate_mask_5cm
```

采出来之后再 perturb。

因此你模拟的是：

> 已经找到正确 interaction-region object points，但 object pose 有误差。

不是：

> noisy object pose 导致 candidate selection 本身也错。

我认为当前阶段这样反而更好，因为变量更少。

以后要研究 proposal/candidate robustness，再单独把 sampling noise 加进去。

## 但是不要从 sampled cross edges 聚合

绝对不要写：

```python
hand_target = edge_contact_target.max(dim=...)
```

因为当前 cross supervision：

```text
512 object points
×
random 128 hand edges/object
```

不是完整 bipartite graph。

甚至 512 object points 本身也是从 4096 pool 中采出来的。

所以：

[
\max_{\text{sampled }i}y_{ij}
]

只满足：

[
\max_{\text{sampled }i}y_{ij}
\le
\max_{\text{all }i}y_{ij}
]

会系统性低估 hand contact。

例如真实最近 object point 没采到：

```text
真实:
hand point j 距 object 2 mm
target = 0.8

512 sampled object:
最近只有 12 mm
target = 0
```

那么 hand target 直接错了。

# 最好的实现：Stage 3 用完整 4096 object pool 算 hand min distance

Stage 3 当前已经做：

```python
dist = torch.cdist(obj, hand)
```

其中：

[
dist\in\mathbb R^{B\times4096\times1538}
]

并从 object 维度得到：

```python
obj_to_hand_min_dist
```

当前代码取：

```python
batch_min = knn_dist[..., 0]
```

得到 object → hand 最近距离。

我建议直接在同一个 `dist` 上再取：

[
d_j^{hand}
==========

\min_i dist_{ij}
]

代码概念上：

```python
obj_to_hand_min_dist = dist.min(dim=2).values
hand_to_obj_min_dist = dist.min(dim=1).values
```

于是 Stage 3 保存：

```text
obj_to_hand_min_dist    [T, 4096]
hand_to_obj_min_dist    [T, 1538]
```

然后 dataset：

```python
hand_min_dist = data["hand_to_obj_min_dist"][frame_idx]
```

GT：

```python
hand_contact_target = contact_target_from_distance(
    hand_min_dist,
    contact_radius=self.contact_radius,
)
```

这样 target 来自：

[
\boxed{\text{clean full 4096 object pool}}
]

不会受到 512 object sampling 和 random128 edge sampling影响。

而且 hand-root/object frame 之间距离不变，所以这个字段也是 coordinate-frame invariant。

# 5. 它还能缓解 random128 的监督稀疏问题

这是我觉得最有价值的一点。

cross edge random128 可能一帧只采到约：

[
12
]

条 nonzero edge。

但是 hand contact head 每帧始终监督：

[
1538
]

个 hand points。

假设有 50 个 hand surface points 接近物体，那么：

```text
edge head:
可能随机只看到很少 positive pair

hand head:
完整看到 50 个 positive hand point
```

所以 backbone 会先学到：

> 哪些 hand region 当前处于 interaction state。

edge head 再学习：

> 具体这个 hand point 与哪个 object point 对应。

我认为任务层次很自然：

[
\boxed{
\text{hand contact}
\rightarrow
\text{pairwise correspondence/contact}
}
]

当然 architecture 不是显式级联，只是共享 backbone 的 multi-task supervision。
