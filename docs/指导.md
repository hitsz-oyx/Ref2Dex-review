# 1. 核心判断

当前代码已经逐渐形成三个明确且正交的实验组件轴：

```text
model
    ptv3_concat
    ptv3_pairgeo      # future

contact supervision
    bin
    soft

edge sampler
    balanced
    stratified
    dense
```

目前代码已经手写了：

```text
composition.py
EdgeSamplerConfig
ContactSupervisionConfig
CorrespondenceModelConfig
ResolvedCorrespondenceComponents
build_edge_sampler
build_contact_supervision
build_correspondence_model
```

这实际上已经在手工实现一个轻量 component composition system。

本次决定：

> 正式使用 Hydra 的 config groups + `_target_` + `hydra.utils.instantiate()` 负责 task-local experiment component 的选择和构造。

因此，本次**不要再实现新的 registry**。

不要新增：

```text
EDGE_SAMPLER_REGISTRY
MODEL_REGISTRY
SUPERVISION_REGISTRY
register_sampler decorator
PluginManager
GlobalRegistry
自动 module scan
```

Hydra 已经承担：

```text
component selection
config composition
_target_ -> Python class
object instantiation
```

继续维护：

```text
name -> class registry
```

属于重复机制。

但是必须明确：

> Hydra 只替代 composition / selection / construction mechanism，不替代 Python 中的 task contract 和架构边界。

Hydra 不能自动解决：

```text
Dataset 应该知道什么
EdgeSample 应该包含什么
near/far 属于谁
training batch 应该输出什么
```

这些仍然必须通过代码边界修正。

# 2. 本次重构的总原则

## 2.1 Hydra 只用于 task-local component composition

本次不要让 Hydra 接管整个 Base training framework。

当前 BaseRunner 明确依赖：

```text
cfg.meta
cfg.data
cfg.train
cfg.wandb
TaskConfig
explicit_override_keys
```

`BaseRunner.__init__()` 内还会直接：

```text
初始化 distributed
解析 run identity
setup train/eval
构造 dataloader
构造 model
```

因此本次不要粗暴改成：

```python
@hydra.main(...)
def main(cfg):
    runner = instantiate(cfg.runner)
```

也不要做：

```yaml
runner:
  _target_: ...
  dataset:
    _target_: ...
    sampler:
      _target_: ...
```

然后整棵 object graph recursive instantiate。

这会把任务依赖关系藏进 YAML，并迫使 BaseRunner 一起重写。

本次目标是：

```text
Hydra/OmegaConf
    负责加载和组合 task config

Hydra instantiate
    只在明确 component boundary 构造：
        edge_sampler
        contact_supervision
        model

BaseRunner
    保持现有 lifecycle

CorrStaticDataset
    保持普通 Python Dataset
```

---

## 2.2 Dataset 不解释 experiment config

最终 `CorrStaticDataset` 不应该知道：

```text
balanced
stratified
dense
near
far
S0/S1/S2/S3/S4
logit_sampling_mode
k_near_logit
k_far_logit
logit_stratified_distance_edges
logit_stratified_quotas
logit_near_radius
logit_far_min_radius
```

Dataset 只知道：

```text
self.edge_sampler
```

然后：

```python
supervision_edges = self.edge_sampler.sample(
    gt_obj_points=geometry.gt_obj_points,
    gt_hand_points=geometry.gt_hand_points,
    obj_valid=obj_sample.valid_mask,
    seed=self._sample_seed(frame, namespace="logit-neighbors"),
)
```

Dataset 不负责：

```text
选择 sampler
解析 sampler config
兼容旧 sampler 字段
根据 mode 构造 sampler
把 sampler config 反写到自身成员
```

### BalancedEdgeSampler

自己的参数：

```text
k_near_logit
k_far_logit
logit_near_radius
logit_far_min_radius
```

自己的算法词汇：

```text
near

```

### StratifiedEdgeSampler

自己的参数：

```text

quotas
```

自己的算法词汇：

```text
bucket / stratum

```

Stratified sampler **不再接受**：

```text
logit_near_radius
logit_far_min_radius
```

因为它们不参与 sampling policy。

### DenseEdgeSampler

Dense sampler 不需要 sampler 参数。

目标构造应允许：

```python

```

Dense sampler **不再接受**：

```text

logit_far_min_radius
```

Dense sampling 不应该为了历史统计额外计算完整距离矩阵。

# 5. 不要直接用 `@hydra.main` 重写整个训练入口

这是本次实现中非常重要的限制。

当前 `train.py` 使用：

```text
build_train_parser
load_train_config_from_args
CorrespondencePTV3Runner(cfg).run()
```

BaseRunner 使用自定义 `TaskConfig` runtime object。

本次建议新增 task-local：

```text
src/task/correspondence_ptv3/config_loader.py
```

它负责：

```text
Hydra compose
    ↓
OmegaConf composed config
    ↓
plain mapping
    ↓
TaskConfig runtime view
```

建议接口类似：

```python
def load_correspondence_config_from_args(args) -> TaskConfig:
    ...
```

`train.py` 仍保持简单：

```python
args = parser.parse_args()
cfg = load_correspondence_config_from_args(args)
CorrespondencePTV3Runner(cfg, mode="train").run()
```

不要让 `train.py` 自己解释 sampler/model/supervision。

现有 CLI 支持：

```text

--set
--data
--output-dir
--device
--distributed
```


## 6.3 `_target_` 不能在 TaskConfig 转换和 checkpoint 保存时丢失

这是本次迁移的高风险点。

当前 `BaseConfig._object_to_dict()` 会过滤：

```python
if not key.startswith("_")
```

因此，如果把 Hydra component config 转成 `ConfigNode`：

```text
edge_sampler._target_
model._target_
contact_supervision._target_
```

后续 `cfg.to_dict()` / `save_config()` 时可能丢失 `_target_`。

这是不允许的。

必须保证保存后的 resolved config / checkpoint config 仍包含：

```yaml
edge_sampler:
  _target_: ...

contact_supervision:
  _target_: ...

model:
  _target_: ...
```

推荐的最小改法：

> Hydra compose 完成后，将 component config 保持为普通 `dict`，不要转换成 `ConfigNode`。

例如逻辑上：

```python
raw = OmegaConf.to_container(composed, resolve=True)
cfg = task_config_from_dict(raw)

cfg.edge_sampler = copy.deepcopy(raw["edge_sampler"])
cfg.contact_supervision = copy.deepcopy(raw["contact_supervision"])
cfg.model = copy.deepcopy(raw["model"])
```

这是示意，不要求逐字复制。

关键要求：

```text
cfg.meta / cfg.data / cfg.train / cfg.wandb
    继续使用 BaseRunner 兼容的 attribute-style runtime config

cfg.edge_sampler / cfg.contact_supervision / cfg.model
    可以保持 plain dict
    保留 Hydra special keys
```

不要为了支持 `_target_`，立刻修改整个 `BaseConfig` 序列化协议。

除非真实代码证明 task-local 方案不可行，否则不要让 Base 依赖 Hydra。

# 7. 删除 `composition.py` 的 component interpretation 责任

当前 `composition.py` 处理：

```text
EdgeSamplerConfig
ContactSupervisionConfig
CorrespondenceModelConfig
ResolvedCorrespondenceComponents
selector conflict
legacy selector fallback
balanced config resolution
stratified config resolution
bin config resolution
model name resolution
```

Hydra migration 后，这些大部分应该消失。

目标：

```text
composition.py
```

不再作为 canonical component composition system。

优先方案：

```text
删除 composition.py
```

如果旧 checkpoint / legacy config 迁移确实需要兼容，可暂时保留：

```text
legacy_config.py
```

它只负责：

```text
legacy config mapping
    ↓
canonical Hydra-style raw mapping
```

例如：

```text
meta.logit_sampling_mode=stratified
    ↓ migration only
edge_sampler._target_=...StratifiedEdgeSampler
```

但是：

```text
new experiment configs
runner
dataset
model
visualizer
```

都不能再依赖 legacy resolver。

不要保留一个 400 行 `composition.py`，然后在 Hydra 外面继续维护第二套 component interpretation。

# 9. `EdgeSample` contract 必须纯化

当前：

```python
@dataclass(frozen=True)
class EdgeSample:
    idx: np.ndarray
    valid_mask: np.ndarray
    loss_weight: np.ndarray
    stats: dict[str, np.ndarray]
```

修改为：

```python
@dataclass(frozen=True)
class EdgeSample:
    idx: np.ndarray
    valid_mask: np.ndarray
    loss_weight: np.ndarray
```

删除：

```text
stats
near_count
far_count
```

generic edge supervision contract 只有：

```text
which edges
which edges are valid
how edges are weighted in loss
```

即：

```text
idx
valid_mask
loss_weight
```

# 10. Sampler diagnostics 不进入 training batch

从 Dataset `_pack_sample()` 删除：

```text
input_obj_to_hand_logit_near_count
input_obj_to_hand_logit_far_count
```

training batch 不应该携带：

```text
near_count
far_count
bucket_count
sampler_name
sampling_mode
```

这些字段不参与：

```text
model
loss
target
metric
```

因此不属于 batch contract。

如果 sampler characterization test 需要统计 near/far：

> 测试根据返回的 `idx` 和输入 geometry 自己计算。

例如测试逻辑可以：

```text
sample.idx
    ↓ gather selected hand points
    ↓ distance to object point
    ↓ test locally count <= radius / > radius
```

不要为了测试方便污染 production `EdgeSample`。

Stratified sampling 的 bucket coverage 同理。

如果未来确实需要在线 sampler monitoring，再设计独立：

```text
sampling audit hook
```

本次不要预先设计 diagnostics framework。

# 11. 修正三种 EdgeSampler

## 11.1 `BalancedEdgeSampler`

保持当前 sampling algorithm 和随机语义。

它可以继续拥有：

```python
@dataclass(frozen=True)
class BalancedEdgeSampler:
    k_near_logit: int
    k_far_logit: int
    logit_near_radius: float
    logit_far_min_radius: float
```

返回：

```python
EdgeSample(
    idx=logit_idx,
    valid_mask=logit_valid,
    loss_weight=logit_weight,
)
```

删除 `near_count` / `far_count` production computation。

---

## 11.2 `StratifiedEdgeSampler`

修改 constructor：

```python
@dataclass(frozen=True)
class StratifiedEdgeSampler:
    distance_edges: tuple[float, ...] | list[float]
    quotas: tuple[int, ...] | list[int]
```

删除：

```text
logit_near_radius
logit_far_min_radius
```

保持当前：

```text
S0-S4 bucket definition
initial quota
Phase 1: S1/S2/S3 round-robin
Phase 2: S0
Phase 3: S4
```

不允许因重构改变 selection distribution。

删除：

```python
selected_dist = dist_row[chosen]
near_count[...] = ...
far_count[...] = ...
```

返回纯 `EdgeSample`。

---

## 11.3 `DenseEdgeSampler`

目标：

```python
@dataclass(frozen=True)
class DenseEdgeSampler:
```

# 30. 本次重构的最终目的

不要把 Ref2Dex 做成通用 ML framework。

目标是：

> 让研究实验轴与代码组件边界一致。

当前主要实验轴是：

```text
模型如何形成 pair interaction representation
监督 edge 如何选择
contact target / loss 如何定义
```

因此代码应该允许我们分别替换：

```text
model
edge sampler
contact supervision
```

而不让：

```text
Balanced 的 near/far vocabulary
```

泄漏到：

```text
Dataset
Dense sampler
Stratified sampler
metadata
Runner config synchronization
```

同时，也不要为了“架构漂亮”引入比研究问题更复杂的框架。

本次采用 Hydra 的理由不是追求配置框架高级化，而是当前已经存在多个正交 component axis，继续维护：

```text
Config dataclass
composition resolver
factory if/elif
legacy selector
```

开始形成重复机制。

最终原则：

> Hydra 负责“选谁、配什么参数、怎么构造”；Python contract 负责“组件之间允许交换什么”；Dataset 负责“固定任务语义下如何组装一个训练样本”。
