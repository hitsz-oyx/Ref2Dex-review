# Ref2Dex `correspondence_ptv3` 第二轮结构收敛任务

## 0. 背景与目标

当前分支：

```text
reconstruct
```

当前已完成第一轮重构：

* 引入 Hydra config groups；
* `EdgeSampler` 已拆分为 `BalancedEdgeSampler / StratifiedEdgeSampler / DenseEdgeSampler`；
* `ContactSupervision` 已拆分为 `bin / soft`；
* Dataset 不再感知 balanced / stratified / dense；
* Dataset 的 supervision edge contract 已统一为：

  * `idx`
  * `valid_mask`
  * `loss_weight`
* `near_count / far_count` 已从训练 batch contract 中删除；
* model、sampler、contact supervision 已可通过 Hydra `_target_` 实例化。

这一轮**不要重新设计整个框架**。

目标是：

> 在保持现有实验变量边界清晰的前提下，收敛当前过度分散的脚本和兼容层，清理 legacy config，并使 model component 真正拥有自己的模型配置。

核心原则：

1. 不破坏当前训练语义；
2. 不修改 contact target、loss、edge reducer 的数学定义；
3. 不改变 balanced / stratified / dense 的采样行为，除非本文明确要求；
4. 不引入 Registry、PluginManager、DependencyContainer 等新框架；
5. Hydra 继续作为 component composition 机制；
6. 优先删除重复路径和兼容 shell，而不是重新制造 abstraction；
7. 新增模型实验时，应主要增加 model implementation + model config，而不是继续向 generic `meta` 添加 flag。

## 2.3 Model 构造接口


# 11. 简化 `config_loader.py`

当前 `config_loader.py` 同时处理：

```text
Hydra composition
resolved config dict
saved JSON
external YAML
manual component group replacement
runtime overrides
explicit override tracking
```

职责过重。

尤其当前存在：

```python
COMPONENT_KEYS = (...)
```

以及手工：

```text
CONFIG_DIR / group / <name>.yaml
```

加载 component group。

这相当于在 Hydra 外再维护一套 selector resolver。

需要简化。

## 推荐只支持两种 config source

### A. Hydra recipe

输入：

```text
base
soft_strat128
soft_contact_baseline
```

或 `CONFIG_DIR` 内 recipe path。

通过：

```python
compose(
    config_name=...,
    overrides=...
)
```

完成 Hydra composition。

Component override：

```text
edge_sampler=stratified
contact_supervision=soft
model=ptv3_concat
```

优先直接由 Hydra 处理。

### B. Resolved config

用于：

```text
checkpoint["config"]
saved config.json
Mapping
TaskConfig
```

这些配置已经包含：

```text
_target_
```

不需要重新进行 config-group composition。

只需要：

```text
load
copy
runtime scalar override
convert to TaskConfig
```

## 外部 YAML

不要提供“看起来支持 Hydra defaults，但实际上不 compose”的半支持状态。

可以选择：

1. 仅支持 `CONFIG_DIR` 内 Hydra YAML；
2. 对 CONFIG_DIR 外 YAML 明确作为 resolved YAML 处理，并在检测到 `defaults` 时直接报清晰错误。

例如：

```text
External YAML with Hydra defaults is not supported.
Move the recipe under correspondence_ptv3/configs or use a config name.
```

不要静默 `OmegaConf.load` 后留下 `defaults` 字段。

## 目标

简化 `config_loader.py`。

不要为了减少行数牺牲 checkpoint reload。

以下测试必须保留：

```text
saved config preserves _target_
saved config can reload
checkpoint reload restores sampler
checkpoint reload restores contact supervision
checkpoint reload restores model
CLI override tracks explicit keys
```

# 13. 修复 Runner 的两个问题

## 13.1 `build_model(model_cfg)` 不应忽略参数

当前可能是：

```python
def build_model(self, model_cfg):
    del model_cfg
    return instantiate(self.cfg.model, ...)
```

修改为：

```python
def build_model(self, model_cfg):
    return instantiate(
        model_cfg,
        ...
    )
```

BaseRunner 已经把 model config 作为 hook 参数传入。

不要丢弃参数后反查 `self.cfg.model`。

---

## 13.2 RankK weight 为 0 时不要计算 RankK objective

当前 baseline：

```yaml
loss_cross_edge_rankk_weight: 0.0
```

但 Runner 可能仍无条件：

```python
self.rankk_objective.compute(...)
```

`CrossEdgeRankKObjective.compute()` 会执行：

```text
topk
gather
label_gap
score_gap
pair matrix
```

这在 weight=0 时是不必要的。

修改为：

```python
rankk_weight = float(
    getattr(meta, "loss_cross_edge_rankk_weight", 0.0)
)

if rankk_weight > 0.0:
    cross_edge_rankk_loss, cross_edge_rankk_pairs = (
        self.rankk_objective.compute(...)
    )
else:
    cross_edge_rankk_loss = zero
    cross_edge_rankk_pairs = zero
```

保证 metric key 如当前日志依赖它，可以继续输出 0。

不要改变 RankK objective 数学定义。
