

# 4. 必须改：hand loss 现在多乘了 batch size

这里是明确 bug。

当前：

```python
denom = hand_qfl_map.new_tensor(
    float(hand_qfl_map.shape[1])
).clamp_min(1.0)

hand_contact_qfl = hand_qfl_map.sum() / denom
```

假设：

[
hand_qfl_map\in\mathbb R^{B\times1538}
]

当前计算是：

[
L_h
===

\frac{
\sum_{b=1}^{B}
\sum_{j=1}^{1538}
\ell_{bj}
}{
1538
}
]

正确应该是：

[
\boxed{
L_h
===

\frac{
\sum_{b=1}^{B}
\sum_{j=1}^{1538}
\ell_{bj}
}{
B\times1538
}
}
]

因此当前：

[
L_h^{current}
=============

B L_h^{correct}
]

默认：

```yaml
batch_size: 8
```

所以：

[
\boxed{
L_{hand}\text{ 被放大了 }8\text{ 倍}
}
]

更糟糕的是 validation：

```yaml
val_batch_size: 24
```

于是 metric 又放大 24 倍。

直接改：

```python
hand_contact_qfl = hand_qfl_map.mean()
hand_contact_bce = hand_bce_map.mean()
hand_contact_mae = hand_mae_map.mean()
```

就行。

或者统一使用：

```python
reduce_loss_map(
    hand_qfl_map,
    torch.ones_like(hand_target, dtype=torch.bool),
)
```

但因为 1538 个 hand points 全部有效，我认为 `.mean()` 最清楚。

### 为什么测试没抓出来

现有 runner 测试的 batch size 是 1：

```python
pred_hand_contact_logits = torch.zeros(1, 4)
```

所以：

[
B=1
]

当前错误公式和正确公式数值完全相同。

建议补一个非常简单的 test：

```python
batch1_loss = ...
batch2_loss = same_sample.repeat(2, ...)
assert_close(batch1_loss, batch2_loss)
```

即：

> 相同 sample duplicate 到 batch 维后，mean loss 不应该变化。

# 5. `augment_scale` 下 hand target 有语义不一致

目前 baseline：

```yaml
augment_scale: false
```

所以**现在不会影响训练**。

但代码里有一个潜在 bug。

global scale 会把 GT geometry 也缩放：

```python
gt_obj_points = transform_points(gt_obj_points)
gt_hand_points = transform_points(gt_hand_points)
```

因此 edge distance 变成：

[
d'*{ij}=s d*{ij}
]

edge target 自然基于：

[
f(sd_{ij})
]

但是 hand min distance 当前明确**不乘 `distance_scale`**：

```python
# we do NOT rescale it
```

于是 hand target 还是：

[
f(d_j)
]

这导致：

[
y_h=f(d)
]

但：

[
y_{edge}=f(sd)
]

破坏了我们刚才定义的：

[
y_j^{hand}=\max_i y_{ij}^{edge}
]

所以应该：

```python
hand_min_dist *= float(geometry.distance_scale)
```

和 `obj_min_dist` 一样。

或者彻底删 `augment_scale`。

我的意见是：**既然当前不用 scale augmentation，v2 直接删掉这条不成熟路径也可以。**

# 6. 一个小 footgun：Stage 3 function 默认仍是 object

CLI 已经改成：

```python
default="hand_root"
```

Config 也是：

```python
coordinate_frame = "hand_root"
```

baseline 也明确：

```yaml
coordinate_frame: hand_root
```

但是函数：

```python
def build_stage3_sequence(
    ...
    coordinate_frame: str = "object",
)
```

仍默认 `object`。

正常 CLI 路径没问题，因为总是显式传参。

但程序调用：

```python
build_stage3_sequence(...)
```

会静默回 object frame。

既然 v2 已正式切 hand-root，我建议统一：

```python
coordinate_frame: str = "hand_root"
```

不然语义有两个默认值。
