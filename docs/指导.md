# 更大的残留：你仍然每 step GPU→CPU sync

这是目前我认为最值得继续优化的地方。

BaseRunner 每个 batch：

```python
metrics = self.train_step(batch)
averager.update(metrics, n=self.batch_size(batch))
```

而 `MetricAverager.update`：

```python
self.meters[key].update(float(value), n)
```

假设：

```python
value = cuda_tensor
```

那么：

```python
float(value)
```

就是：

[
\boxed{\text{GPU synchronization}}
]

现在普通 step 至少返回：

```text
cross_edge_random
cross_edge_contact_aux

cross_edge_random_qfl
cross_edge_random_bce
cross_edge_random_mae

contact_aux_qfl
contact_aux_bce
contact_aux_soft_bce
contact_aux_mae

loss
```

等于每一步大量：

```python
float(cuda_tensor)
```

所以即使：

```python
diagnostic_every_steps = 20
```

你还是在每 step sync。

而且 YAML 目前还是：

```yaml
log_every_steps: 1
```

## 我建议先做最小修改

### 第一层：`log_every_steps: 20`

直接改：

```yaml
log_every_steps: 20
```

这是最简单的。

### 第二层：普通 step 只返回必要 metric

普通 step：

```python
aux_metrics = {
    "cross_edge_random_qfl": cross_edge_random_qfl,
    "contact_aux_qfl": cross_edge_contact_aux_qfl,
}
```

加两个 loss：

```text
cross_edge_random
cross_edge_contact_aux
loss
```

总共 5 个。

不要每步返回 BCE/MAE。

### 第三层：修改 `MetricAverager.update`

当前：

```python
for key, value in metrics.items():
    ...
    self.meters[key].update(float(value), n)
```

至少改成一次性 transfer：

```python
tensor_items = [
    (key, value)
    for key, value in metrics.items()
    if torch.is_tensor(value)
]

if tensor_items:
    tensor_values = torch.stack([
        value.detach().float()
        for _, value in tensor_items
    ])

    cpu_values = tensor_values.cpu().tolist()

    for (key, _), value in zip(tensor_items, cpu_values):
        self.meters[key].update(value, n)
```

这样：

```text
原来：
tensor1 → CPU sync
tensor2 → CPU sync
tensor3 → CPU sync
...
```

变成：

```text
stack metrics on GPU
        ↓
one D2H
        ↓
one sync
```

注意这仍然每 step 有一次 sync，但比逐 metric sync 干净很多。

更极致是 GPU epoch accumulator，epoch 末再 sync 一次，但我认为可以第二轮优化再做。

# 我对 hash-score sampler 的评价

你现在没有用：

```python
torch.rand(...)
```

而是：

```python
hashed = seed ^ (...) ^ (...)
hashed = (hashed * 1103515245 + 12345) & 0x7FFFFFFF
score = hashed.float() / 2147483648.0
```

它的优点很明显：

* deterministic
* per-frame seed
* batch order independent
* chunk size independent
* 没有 CPU generator
* 没有 generator state 管理

**作为工程 pseudo-random score，我没发现直接 correctness bug。**

但我要严格说：

[
\boxed{\text{它不能被数学上声明为 iid uniform random key}}
]

因此也不能严格推出：

[
P(E=S)=\frac1{\binom NK}
]

即“严格 uniform without replacement”。

之前我建议 random-key topk 的理论成立，前提是：

[
u_j\overset{iid}{\sim}U(0,1)
]

你现在这个 hash score 是 deterministic correlated pseudo-random sequence。

我简单检查了它在 1538 hand indices、多个 seed 下的单点选择频率，没有看到明显严重偏置，所以**我不会把它列为 blocker**。

但研究代码里我更倾向于真正 Torch RNG。

考虑你当前：

```yaml
batch_size: 8
```

直接为 contact sampler 生成：

[
[8,512,1538]
]

FP32 random score 大约只占 24 MiB。

完全能接受。

我建议：

```python
score = torch.empty(
    batch_size,
    num_obj,
    num_hand,
    device=gt_obj.device,
)

for batch_idx, seed in enumerate(contact_seed_list):
    generator = torch.Generator(device=gt_obj.device)
    generator.manual_seed(seed)

    score[batch_idx].uniform_(
        generator=generator
    )
```

然后 chunk 内：

```python
score_chunk = score[:, start:end]
```

这样：

[
\boxed{\text{真实 Torch GPU RNG + iid random key + uniform without replacement}}
]

只有 batch axis 8 次 generator call，不是 object axis 512 次。

我觉得比自定义 LCG hash 更适合你的研究代码。
