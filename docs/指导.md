**按现在的任务定义，global augmentation 没有必要，甚至会制造 train–test distribution mismatch。**

核心不是“增强有没有数学作用”，而是：

> **真实推理输入永远会先被预处理到 hand-root frame。**

你的数据链路实际目标是：

[
x^{world}
\xrightarrow{T_{hand}^{-1}}
x^{hand-root}
\xrightarrow{\text{model}}
contact
]

因此无论原始场景里手整体：

* 平移到哪里；
* 朝哪个方向；
* 整个场景怎么旋转；

最终都应该被：

[
T_{hand}^{-1}
]

消掉。

例如整个场景施加共同 SE(3)：

[
x'=R_ax+t_a
]

重新根据变换后的 hand root 做 canonicalization 后：

[
x'*{hr}=x*{hr}
]

所以从模型任务定义来看：

[
\boxed{
\text{global scene SE(3) 根本不是模型需要处理的变量}
}
]

---

## 当前 global augmentation 反而人为制造了不存在的输入

当前代码是先生成 hand-root frame，再随机旋转整个 hand-object geometry。global transform 同时作用于 input/GT 的 hand 和 object。

于是训练输入变成：

[
R_{aug}x^{hand-root}+t_{aug}
]

但部署时你不会这么干。

部署是：

```text
world observation
↓
estimate hand root
↓
transform to hand-root frame
↓
model
```

不会是：

```text
hand-root frame
↓
randomly rotate entire scene
↓
model
```

所以训练在要求模型额外学习一个不需要的性质：

[
f(Rx+t)=f(x)
]

即 SE(3) invariance。

但我们明明已经通过 preprocessing 主动 canonicalize 了。

这相当于：

> **先用解析方法消除 nuisance variable，再人工把 nuisance variable 加回来让神经网络学着消除。**

确实没必要。

---

## 扰动完全是另一个概念

你这个区分是对的。

### Global augmentation

[
o'=Ro+t
]

[
h'=Rh+t
]

所以：

[
o'-h'=R(o-h)
]

hand-object 相对关系不变。

它改变的是：

[
\text{coordinate frame}
]

### Object perturbation

现在代码只动 sampled object：

[
o^{input}=R_\Delta o^{gt}+t_\Delta
]

[
h^{input}=h^{gt}
]

当前实现确实是 512 个 object points 共用一个 SE(3)。

于是：

[
o^{input}-h
\neq
o^{gt}-h
]

它改变的是：

[
\boxed{
\text{observed relative hand-object geometry}
}
]

而 GT 仍然来自 clean geometry：

[
y=f(|o^{gt}-h^{gt}|)
]

这才是你的模型真正需要解决的问题：

> 输入 object pose 有误差，但希望恢复 clean contact relation。

---

## 所以我建议 v2 直接删 global augmentation

不是简单：

```yaml
augment_rotation: false
augment_translation: false
```

我甚至建议从 v2 代码层直接删除：

```text
augment
augment_rotation
augment_translation
rotation_range
translation_range
apply_global_aug
```

`augment_geometry()` 也可以改名。

现在这个函数实际上只应该做：

```python
perturb_object_geometry(...)
```

数据流明确成：

```text
Stage 3
    ↓
hand-root canonicalization
    ↓
clean candidate sampling
    ↓
sample 512 object points
    ↓
copy clean GT
    ↓
object-only SE(3) perturb
    ↓
model input
```

即：

[
\boxed{
canonicalization
\neq
augmentation
\neq
perturbation
}
]

我认为现在应该严格分开这三个概念：

[
\textbf{Canonicalization}
]

消除模型不需要处理的自由度：

[
world\rightarrow hand\ root
]

[
\textbf{Perturbation}
]

模拟实际输入误差：

[
T_{obj}^{input}\neq T_{obj}^{gt}
]

而当前这种：

[
\textbf{Global augmentation}
]

在你的任务里没有明确物理来源，也没有部署对应变量。

**所以我支持直接从 v2 删除 global augmentation，而不是仅在 baseline 里关掉。** 这样整个任务定义会干净很多。


我看了最新提交 `75a95ed60b13`，提交信息是“把默认配置改到hand，修loss的加batchbug”。相对 `aaeb18f7` 只有 1 个提交。

结论：

> **上次指出的三个实现问题基本都修对了。但我现在看到一个更重要的设计冲突：你一边切 hand-root canonical frame，一边又在正式训练默认做 ±180° 的全局旋转增强。这个实际上把 hand-root 的方向 canonicalization 又打乱了。**



# 5. 新增 batch-invariance test 其实没有测到 runner

测试名是：

```python
test_hand_contact_loss_is_batch_size_invariant
```

但测试实际做的是：

```python
qfl_map = quality_focal_loss_map(...)
single_qfl = qfl_map.mean()

qfl_b4 = qfl_map.repeat(4, 1)
assert torch.allclose(qfl_b4.mean(), single_qfl)
```

这个测试只证明：

[
mean(repeat(x))=mean(x)
]

这当然成立。

但它**完全没有调用**：

```python
runner._compute_losses(...)
```

所以假设以后 runner 又被改回：

```python
hand_contact_qfl = hand_qfl_map.sum() / hand_qfl_map.shape[1]
```

这个 test：

> **仍然会通过。**

所以它没有真正 catch 我们刚才那个 regression。

### 正确测试应该直接测 runner

构造 batch 1：

```python
loss1 = runner._compute_losses(preds1, batch1)
```

然后：

```python
preds4 = repeat_batch(preds1, 4)
batch4 = repeat_batch(batch1, 4)
loss4 = runner._compute_losses(preds4, batch4)
```

断言：

```python
torch.testing.assert_close(
    loss1["hand_contact"],
    loss4["hand_contact"],
)
```

这才是真正的 regression test。
