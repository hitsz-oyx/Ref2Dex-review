按你这个目标，我建议**不要追求“所有东西都 GPU 化”**，而是按收益排序：

[
\boxed{\text{CPU 只负责 IO + 取 frame/obj 点；几何监督计算尽量放 GPU}}
]

当前最该改的是下面这套。

## 1. 把 contact supervision 整体从 Dataset 移到 GPU

现在 `__getitem__` 里每个 frame 都在 CPU 做：

```text
clean cdist(512, 1538)
→ contact bin
→ 每个 object point 逐个采样
→ random target
→ contact target
→ hand target
```

当前代码确实在 dataset 内完成 contact sampling 和 edge target construction。 而 contact sampler 又做了一次 `torch.cdist(...double())`，之后 Python loop 遍历有效 object points。

### Dataset 改成只返回

```python
{
    "points",
    "normals",
    "gt_points",
    "gt_normals",
    "point_valid_mask",
    "runtime_obj_valid_mask",

    "selected_obj_idx",
    "selected_obj_point_id",
    "selected_obj_min_dist",

    "random_edge_idx",
    "random_edge_valid_mask",

    "hand_min_dist",

    "contact_seed",
}
```

删掉 Dataset 中：

```python
sample_contact_supervision_edges(...)

_compute_edge_contact_target(... random ...)
_compute_edge_contact_target(... contact ...)

contact_target_from_distance(hand_min_dist, ...)
```

也就是不再返回：

```python
random_edge_contact_target
contact_edge_idx
contact_edge_valid_mask
contact_edge_contact_target
hand_contact_target
```

这些全部到 GPU 后生成。

你已经返回 `gt_points`，所以根本不需要增加 clean geometry 数据传输。

## 2. 在 `runner.prepare_batch()` 后生成 supervision

当前 BaseRunner 流程正好是：

```python
for batch in loader:
    batch = self.prepare_batch(batch)
    metrics = self.train_step(batch)
```

而默认 `prepare_batch` 会：

```python
move_to_device(batch, self.device)
```

所以在 `CorrespondencePTV3V2Runner` 里 override：

```python
def prepare_batch(self, batch):
    contact_seed = batch.pop("contact_seed")

    batch = super().prepare_batch(batch)

    with torch.no_grad():
        self._build_supervision_gpu(
            batch,
            contact_seed=contact_seed,
        )

    return batch
```

注意 `contact_seed` 可以先保留 CPU，因为生成器初始化需要 Python seed；不要先搬 GPU 再 `.item()`，否则又发生 GPU sync。

`move_to_device` 当前已经用了：

```python
value.to(device, non_blocking=True)
```

而 DataLoader 默认 `pin_memory=True`，你的 loader helper 也确实读取这个配置。

所以 CPU→GPU 数据传输这部分框架已经处理得比较合理。

## 3. GPU contact sampler 要 chunked vectorize

不要把现在的代码简单搬 GPU：

```python
for obj_idx in valid_obj:
    ...
```

那样会产生大量 GPU kernel launch 和同步。

应该按 chunk 做。

假设：

[
B\times512\times1538
]

直接完整保存 distance matrix，在 batch 128 时：

[
128\times512\times1538
\approx100.8M
]

FP32 就约 403 MB。

再加 random score 和 mask，很容易爆显存。

所以做：

```python
obj_chunk_size = 64
```

流程：

```python
for start in range(0, num_obj, obj_chunk_size):
    end = min(start + obj_chunk_size, num_obj)

    dist = torch.cdist(
        gt_obj[:, start:end],
        gt_hand,
    )
```

此时：

[
D\in\mathbb R^{B\times64\times1538}
]

然后：

```python
target = (1.0 - dist / contact_radius).clamp_(0.0, 1.0)
```

构造五个 mask：

```python
weak = (target > eps) & (target <= 0.25)
medium = (target > 0.25) & (target <= 0.50)
strong = (target > 0.50) & (target <= 0.75)
very_strong = (target > 0.75)
hard_neg = (
    (dist >= neg_min)
    & (dist < neg_max)
    & (target <= 0)
)
```

然后只生成**一份 random score**：

```python
score = torch.rand_like(dist)
```

对每个 bin：

```python
masked_score = score.masked_fill(~bin_mask, float("inf"))

values, idx = torch.topk(
    masked_score,
    k=quota,
    dim=-1,
    largest=False,
)

valid = torch.isfinite(values)
idx = idx.masked_fill(~valid, -1)
```

因为每个 candidate 获得 iid continuous random key，再取最小 (K) 个，所以仍然对应 uniform without replacement。

四个 positive bin + 一个 hard negative bin拼起来：

```python
contact_edge_idx = torch.cat(
    [weak_idx, medium_idx, strong_idx, very_idx, hard_idx],
    dim=-1,
)

contact_edge_valid_mask = torch.cat(
    [weak_valid, medium_valid, strong_valid, very_valid, hard_valid],
    dim=-1,
)
```

这就把：

```python
for obj_idx in 512
```

彻底去掉。

## 4. contact target 不要再重新算距离

这是一个很容易浪费计算的地方。

你已经有：

```python
dist
target
```

contact edge 又是直接从这个矩阵中选出来的。

所以直接：

```python
safe_idx = contact_edge_idx.clamp(min=0)

contact_edge_target = torch.gather(
    target,
    dim=-1,
    index=safe_idx,
)

contact_edge_target *= contact_edge_valid_mask.float()
```

不要再：

```text
gather hand points
→ hand - obj
→ norm
→ target
```

当前 dataset 就是在 sampling 后重新算 edge distance。

GPU builder 中完全没必要。

## 5. random128 先不要 GPU 化

这一点我现在给你明确建议：

[
\boxed{\text{random128 暂时留 CPU}}
]

不是因为 Torch 不行，而是因为**从速度角度不值得优先动**。

当前 random128 的工作只是：

```python
512 × randperm(1538)
```

相比：

[
cdist(512,1538)
]

以及 PTv3 forward/backward，它不是主要瓶颈。

如果搬 GPU，用：

```python
rand[B, 512, 1538]
→ topk(128)
```

反而：

* 生成大量 random values
* 占 GPU 显存
* 做大 topk

不保证比 CPU 快。

所以我建议：

```text
CPU:
    random128 edge_idx only

GPU:
    random edge target
    contact sampling
    contact target
    hand target
```

random target 到 GPU 后算：

```python
gt_obj = batch["gt_points"][:, :num_obj]
gt_hand = batch["gt_points"][:, num_obj:]

neighbor_hand = gather_batched_knn_features(
    gt_hand,
    random_edge_idx,
    random_edge_valid_mask,
)

distance = torch.norm(
    neighbor_hand - gt_obj.unsqueeze(2),
    dim=-1,
)

random_target = (
    1.0 - distance / contact_radius
).clamp_(0.0, 1.0)

random_target *= random_edge_valid_mask.float()
```

你刚加的 `gather_batched_knn_features` 正好能用。

所以 Dataset 只产生约：

[
512\times128
]

个整数 index。

非常轻。

# 6. `hand_contact_target` 也放 GPU 算

Stage 3 已经缓存了：

```python
hand_to_obj_min_dist
```

Dataset 只返回：

```python
hand_min_dist
```

GPU 后：

```python
batch["hand_contact_target"] = contact_target_from_distance(
    batch["hand_min_dist"],
    contact_radius=self.cfg.meta.contact_radius,
)
```

这本身计算量不大，但可以把 supervision logic 集中在一个地方。

唯一例外是 legacy Stage 3 没有 `hand_to_obj_min_dist` 时，当前 fallback 会在 Dataset CPU 做 full object-hand `cdist`。

我的建议是：

> **训练正式数据直接要求 Stage 3 必须存在 `hand_to_obj_min_dist`。**

不要在训练热路径做 legacy fallback。

直接：

```python
if "hand_to_obj_min_dist" not in data:
    raise KeyError(
        "Missing hand_to_obj_min_dist; regenerate Stage 3."
    )
```

否则某些旧数据会突然让 worker 变得极慢。

# 7. 立刻把 diagnostics 从每 step 热路径拆出去

这个我认为和 GPU contact sampling 一样重要。

现在每个 train step 都在做：

```python
bool(nonzero_count > 0)
float(tensor.detach().cpu())
torch.quantile(..., 0.95)
torch.quantile(..., 0.99)
```

contact aux 也一样，每步做 `quantile` 和多次 CPU conversion。

这些：

```python
bool(cuda_tensor)
float(cuda_tensor.cpu())
```

都会强制等待 GPU。

你现在 baseline 还是：

```yaml
log_every_steps: 1
```

我建议增加：

```yaml
train:
  log_every_steps: 20
  diagnostic_every_steps: 20
```

然后：

```python
def step(self, model, batch, mode="train"):
    preds = model(batch)

    compute_diagnostics = (
        mode == "eval"
        or self.global_step % self.cfg.train.diagnostic_every_steps == 0
    )

    losses, aux_metrics = self._compute_losses(
        preds,
        batch,
        compute_diagnostics=compute_diagnostics,
    )
```

`_compute_losses` 永远计算：

```text
random QFL
contact aux QFL
total loss
```

只有 diagnostic step 才计算：

```text
zero p95/p99
target strength bin MAE
hardneg p95
hand GT distribution
zero baseline
```

你选 best checkpoint 用的是：

```text
val_clean/cross_edge_random_qfl
```

所以 train diagnostics 不需要每一步精确算。当前配置的 best metric 也是这个。

**eval 保持完整 diagnostics。**

我预计这项改动可能比你纠结 random NumPy/Torch 更明显。

# 8. AMP 先别重新打开 fp16，下一步试 BF16

当前 BaseRunner：

```python
torch.autocast(
    device_type=self.device.type,
    enabled=True,
)
```

没有指定 dtype。

CUDA 下通常就是 FP16 autocast，而你已经出现过 `grad_norm=inf`。

所以不要简单：

```yaml
amp: true
```

我建议后续改成：

```yaml
amp: true
amp_dtype: bfloat16
```

BaseRunner：

```python
amp_dtype = (
    torch.bfloat16
    if self.cfg.train.amp_dtype == "bfloat16"
    else torch.float16
)

autocast_ctx = torch.autocast(
    device_type=self.device.type,
    dtype=amp_dtype,
    enabled=self.cfg.train.amp and self.device.type == "cuda",
)
```

同时：

```text
GPU supervision builder → 强制 float32
QFL / BCE → 强制 float32
PTv3 forward → BF16 autocast
```

你的 QFL 实现本身已经把 logits/target 转成 float32。

所以这条路线比较干净。

BF16 时 GradScaler 可以禁用；当前 scaler 只根据 `amp=True` 开启。 这一块需要改成：

```python
use_grad_scaler = (
    amp
    and amp_dtype == "float16"
    and device.type == "cuda"
)
```

# 我给你的最终修改顺序

**第一优先级：**

```text
dataset CPU contact cdist
        ↓
移除

runner.prepare_batch
        ↓
batch 已到 GPU
        ↓
chunked GPU contact supervision builder
```

**第二优先级：**

```text
random/contact/hand target 全部 GPU 构造
```

random edge index 暂时 CPU。

**第三优先级：**

```text
完整 diagnostics 每20 step算一次
eval仍然全部算
```

特别是去掉每 step 的：

```text
quantile
bool(cuda_tensor)
float(cuda_tensor.cpu())
```

**第四优先级：**

```text
BF16 autocast
PTv3 BF16
supervision/loss FP32
```

---

我不建议你现在继续折腾 `torch.compile`。当前 PTv3 wrapper 本身有 Python list flatten、动态 valid point packing，BaseRunner 虽然支持 `torch.compile`， 但这种结构很可能 graph break；先把**明确的 CPU cdist 和 GPU sync bottleneck**干掉。

一句话：

[
\boxed{
\text{IO/取样索引留 CPU}
\rightarrow
\text{监督几何构造上 GPU}
\rightarrow
\text{减少同步}
\rightarrow
\text{再试 BF16}
}
]

这是我认为对你当前仓库**收益最大、且完全不改变 PTv3/cross-edge 架构**的优化路线。
