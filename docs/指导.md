# 必须修 1：hand head 现在对多卡有风险

你的 model 仍然定义：


并返回 hand prediction。

但是 runner 的 loss 只有：

```python
cross_edge_random
cross_edge_contact_aux
```

hand logits **没有参与 loss**。

你的多卡配置却是：

```yaml

  enable: true
```

这意味着：

```text
hand_contact_head parameters
        ↓

        ↓
no gradient
```

PyTorch DDP 文档明确说明，`find_unused_parameters=True` 会识别包括“forward 使用过但没有进入 loss，因此收不到梯度”的参数；默认值是 `False`。([PyTorch Docs][1])

```python
pred_hand_contact_logits = ...
```

以及：

```python

"pred_hand_contact_prob"
```

你现在明确决定：

> hand contact 不参与训练，只观察 GT distribution。

runner 继续记录：

即可。当前 GT-only metric 设计本身是正确的。

# 必须修 2：target bin 边界现在有 bug

当前 diagnostic：

```python
for lower, upper, name in _TARGET_STRENGTH_BINS:
    bin_mask = target_strength_bin_mask(
        edge_target,
        lower=lower,
        upper=upper,
        upper_inclusive=(upper < 1.0),
    )
```

但 helper 定义是：

```python
if upper_inclusive:
    return (target > lower) & (target <= upper)
else:
    return (target > lower) & (target < upper)
```

于是最后一个 bin：

```text
lower = 0.75
upper = 1.0
upper < 1.0 = False
```

得到：

[
0.75<y<1
]

所以：

[
\boxed{y=1}
]

被所有 bin 漏掉。

直接改成：

```python
bin_mask = target_strength_bin_mask(
    edge_target,
    lower=lower,
    upper=upper,
) & edge_valid_mask
```

因为 helper 默认就是：

[
(lower,upper]
]

于是：

```text
(0,    0.25]
(0.25, 0.50]
(0.50, 0.75]
(0.75, 1.00]
```

四档不重叠，也不漏 `y=1`。

hand GT metrics 里同样有这个问题，也一起改。

# 我还建议：sampler 直接按 target 分 bin

你当前 sampler 是：

```python
very_strong = dist <= 0.25 * r
strong = (dist > 0.25 * r) & (dist <= 0.50 * r)
medium = (dist > 0.50 * r) & (dist <= 0.75 * r)
weak = (dist > 0.75 * r) & (dist < r)
```

这里还有一个非常小的 boundary mismatch。

例如：

[
d=0.5r
]

则：

[
y=0.5
]

sampler 把它放进 `strong`。

但 diagnostic 定义：

[
(0.25,0.5]
]

会把 `y=0.5` 放进 medium。

实际连续数据精确打到边界的概率很低，所以这**不是训练大 bug**。

但既然你的方法名称就是：

> target-strength-aware sampling

我认为最自然的实现应该直接：

```python
target_row = np.clip(
    1.0 - dist_row / r,
    0.0,
    1.0,
)

weak = np.flatnonzero(
    (target_row > 0.00) & (target_row <= 0.25)
)
medium = np.flatnonzero(
    (target_row > 0.25) & (target_row <= 0.50)
)
strong = np.flatnonzero(
    (target_row > 0.50) & (target_row <= 0.75)
)
very_strong = np.flatnonzero(
    (target_row > 0.75) & (target_row <= 1.00)
)
```

这样：

[
\boxed{\text{sampler bins}=\text{diagnostic bins}}
]

逻辑完全统一。

我更推荐这个版本。

# 测试有一个“看起来测了，其实没测”的问题

当前 Test 6 写的是：

> random128 baseline stream is byte-identical before and after v2.1

但实现实际上：

```python
seed_a = stable_frame_seed(...)
seed_b = stable_frame_seed(...)

sample_a = sample_random_supervision_edges(seed=seed_a)
sample_b = sample_random_supervision_edges(seed=seed_b)

assert np.array_equal(sample_a, sample_b)
```

它只证明：

[
\boxed{\text{同一个函数 + 同一个 seed 是确定性的}}
]

没有证明：

[
\text{new implementation}
=========================

\text{old baseline implementation}
]

比如明天有人把 random sampler 改成：

```python
rng.permutation(...)
```

只要 deterministic，这个 test 仍然通过。

### 正确做法

固定一个 baseline golden output。

例如：

```python
edge_idx, edge_valid = sample_random_supervision_edges(...)

digest = hashlib.sha256(
    edge_idx.tobytes() + edge_valid.tobytes()
).hexdigest()

assert digest == "OLD_BASELINE_DIGEST"
```

这个 digest 必须取自：

```text
0b814d3 baseline
```

这样 future regression 才真正能 catch random stream 变化。

这个问题和我上次指出的“hand batch invariance test 实际没测 runner”是同一种测试误区。

# 还有一个小问题：contact bin 槽位并非固定布局

当前：

```python
write_col = 0

for candidates, quota in zip(...):
    ...
    edge_idx[obj_idx, write_col:slot] = chosen
    write_col = slot
```

例如 weak 为空、medium 有 16 条：

```text
当前：
col 0~15 = medium
```

而不是：

```text
col 0~15  = weak invalid
col 16~31 = medium
```

**当前训练没有 bug**，因为 runner 是重新根据 target 判断 bin，不依赖 slot。

但代码和测试注释中多次强调：

```text
bin layout is preserved
first weak, next medium...
```

这不完全成立。

我的建议是直接固定 offset：

```python
offset = 0

for candidates, quota in zip(candidate_bins, quotas_t):
    take_count = min(quota, candidates.size)

    chosen = ...

    edge_idx[
        obj_idx,
        offset : offset + take_count,
    ] = chosen

    edge_valid[
        obj_idx,
        offset : offset + take_count,
    ] = True

    offset += quota
```

注意是：

```python
offset += quota
```

不是：

```python
offset += take_count
```

这样四个 bin 的 slot 永远固定。

不是必须，但**工程语义更干净**。
