# 1. 数据目录目前还没有完全对齐

你的配置期望：

```text
data/processed_data/stage4/
├── data/
└── splits/
```

例如：

```yaml
root: data/processed_data/stage4/data
train_split: data/processed_data/stage4/splits/sequence_split_v1/train.txt
```

但生成脚本实际默认写入：

```text
data/processed_data/stage4/cm_sequence_cache/
data/processed_data/stage4/cm_sequence_cache_arctic/
```

GRAB 和 ARCTIC 仍然是两个单独根目录。

所以当前配置中的：

```text
data/processed_data/stage4/data
```

不一定真实存在。

## 建议直接统一成

```text
data/processed_data/stage4/
├── data/
│   ├── grab/
│   │   ├── s1/
│   │   ├── s2/
│   │   └── ...
│   └── arctic/
│       ├── s01/
│       ├── s02/
│       └── ...
│
└── splits/
    └── sequence_split_v1/
        ├── train.txt
        ├── val.txt
        ├── test.txt
        └── split.json
```

修改两个默认路径：

```python
# process/GRAB/stage4_cm.py
DEFAULT_OUTPUT_ROOT = (
    ROOT
    / "data"
    / "processed_data"
    / "stage4"
    / "data"
    / "grab"
)
```

```python
# process/ARCTIC/stage4_cm.py
DEFAULT_OUTPUT_ROOT = (
    ROOT
    / "data"
    / "processed_data"
    / "stage4"
    / "data"
    / "arctic"

```

之后 `train.txt` 写：

```text
grab/s1/bowl_pass_1/left.npz
grab/s1/bowl_pass_1/right.npz
arctic/s01/box_grab_01/left.npz
```

这样多数据集混合时最省事。

# 2. split 接口已经能用了，但要加重叠检查

现在 base 已经支持：

```yaml
data:
  root: ...
  train_split: ...
  val_split_path: ...
  test_split: ...
```

代码会读取三个文本文件，并检查里面引用的文件是否存在。这部分已经落地，不只是文档。

但目前没有检查：

```text
同一个文件是否同时出现在 train 和 val
同一个 sequence 的 left/right 是否跨集合
```

例如下面这种错误现在可能不会被发现：

```text
train.txt:
grab/s1/bowl_pass_1/left.npz

val.txt:
grab/s1/bowl_pass_1/right.npz
```

文件不重复，但 sequence 已经泄漏。

## 在 `src/base/data.py` 先加文件级检查

```python
def ensure_disjoint_splits(
    train_files: list[Path],
    val_files: list[Path],
    test_files: list[Path],
) -> None:
    train_set = {path.resolve() for path in train_files}
    val_set = {path.resolve() for path in val_files}
    test_set = {path.resolve() for path in test_files}

    overlaps = {
        "train_val": train_set & val_set,
        "train_test": train_set & test_set,
        "val_test": val_set & test_set,
    }

    invalid = {
        key: values
        for key, values in overlaps.items()
        if values
    }

    if invalid:
        details = {
            key: [str(path) for path in sorted(values)[:5]]
            for key, values in invalid.items()
        }
        raise ValueError(
            f"Data splits overlap: {details}"
        )
```

读取三个列表后调用：

```python
ensure_disjoint_splits(
    train_files,
    val_files,
    test_files,
)
```

## Cm 再加 sequence 级检查

因为 Cm 的 sequence 就是文件的父目录：

```python
def sequence_keys(paths: list[Path]) -> set[Path]:
    return {
        path.resolve().parent
        for path in paths
    }
```

检查：

```python
train_sequences = sequence_keys(train_files)
val_sequences = sequence_keys(val_files)
test_sequences = sequence_keys(test_files)

if train_sequences & val_sequences:
    raise ValueError(
        "Train and validation contain the same sequence."
    )

if train_sequences & test_sequences:
    raise ValueError(
        "Train and test contain the same sequence."
    )

if val_sequences & test_sequences:
    raise ValueError(
        "Validation and test contain the same sequence."
    )
```

这是这次 split 改动最应该补的一项。

# 3. 文档和代码没有对齐

`docs/指导.md` 里目前写的是：

```yaml
data:
  root: processed_data/stage3/...
  split_json_path: .../split.json
```

训练代码现在以 `split_json_path` 为唯一 split 入口；JSON 指向三个实际文件列表：

```yaml
data:
  root: data/processed_data/stage4/data
  split_json_path: .../split.json
```

另外文档目录树的缩进也乱了。

建议文档直接改成：

```yaml
data:
  root: data/processed_data/stage4/data
  split_json_path: data/processed_data/stage4/splits/sequence_split_v1/split.json

  train_path: ""
  val_path: null
  test_path: null
  val_split: 0.0
```

`split.json` 是训练配置唯一引用的划分描述：

```text
train_split / val_split / test_split：分别指向三个 TXT 文件
其余字段：记录划分方法和统计信息
```

训练代码不再接受 YAML 中与 `split_json_path` 并存的三个直接路径，避免有两套来源。

`sequence_hard_gate_train_val_test_short.yaml` 中出现了两次：


# 6. 输出目录命名现在过于简单

当前输出统一成：

```text
outputs/<task>/<task>_<timestamp>/
```

例如：

```text
outputs/Cm/Cm_20260804_174500/
```

这虽然整齐，但看目录时无法知道它是：

```text
hard gate
no gate
slot 4
slot 16
ARCTIC
GRAB
```

`description` 只写进 metadata，人工浏览不方便。

建议改为：

```text
outputs/<task>/<config_name>_<timestamp>/
```

例如：

```text
outputs/cm/
├── cm_hard_gate_train_val_test_short_20260804_174500/
├── cm_slot_sweep_no_gate_k4_20260804_180100/
└── cm_slot_sweep_no_gate_k8_20260804_181000/
```

代码改成：

```python
task_slug = self._task_slug().lower()

experiment_slug = self._slugify(
    str(getattr(self.cfg, "name", task_slug))
).lower()

run_name = (
    f"{experiment_slug}_"
    f"{self._shared_timestamp()}"
)

output_dir = (
    Path("outputs")
    / task_slug
    / run_name
)
```

同时建议 `_task_slug()` 统一小写，否则现在目录名是 `Cm`，旧实验经常是 `cm_...`，恢复 checkpoint 时可能受到大小写影响。

# 7. `config.json` 仍然保存得过早

现在 `_setup_train()` 还是先：

```python
save_config(self.cfg, ...)
```

之后才：

```python
make_dataloaders(...)
configure_data(...)
```

所以任务在 `configure_data()` 中根据数据修改的字段，可能不会反映到根目录的 `config.json`。

建议顺序改成：

```python
self.output_dir.mkdir(...)

dataloader_bundle = self.make_dataloaders(...)
...
self.configure_data(...)

self.total_steps = ...
self.metadata.update(...)

if self.is_primary:
    save_config(
        self.cfg,
        self.output_dir / "config.json",
    )
    self._write_metadata()
```

这项之前提过，目前还没有落实。

# 8. checkpoint 按 step 保存仍然会覆盖

当前 checkpoint 文件名只有 epoch：

```python
epoch_000001.pt
```

即使保存函数已经拿到了 `step`，文件名仍然只使用 epoch。

你的配置中有：

```yaml
save_every_steps: 1000
```

如果一个 epoch 内在 step 1000、2000、3000 保存三次，会反复覆盖：

```text
epoch_000001.pt
```

建议改成：

```text
step_000001000_epoch_000001.pt
step_000002000_epoch_000001.pt
```

这也是应该尽快修的实际问题。

# 9. eval 仍然会自动优先跑 test

当前逻辑仍然是：

```python
metrics = (
    self.evaluate_test_all()
    if self._resolve_test_loaders()
    else self.evaluate_all()
)
```

只要 test loader 存在，eval 就直接跑 test。

建议明确使用：

```bash
python ... --split val
python ... --split test
```

而不是自动判断。

训练过程中还是只跑 val，这部分没有问题；主要是单独执行 eval 时容易误用 test。

## 建议修改顺序

现在先做这 7 项：

```text
1. 统一 Stage 4 实际输出到 data/stage4/data/<dataset>/
2. 修 docs/指导.md，删除 split_json_path
3. 删除 YAML 重复的 val_split
4. 增加 split 文件和 sequence 重叠检查
5. 把 no-gate 改成严格单变量消融
6. checkpoint 文件名加入 step
7. Stage 4 生成 manifest.csv
```

然后再处理：

```text
8. config.json 延后保存
9. 输出目录加入实验配置名
10. eval 显式选择 val/test
```

当前改动已经把整体目录方向整理对了，主要剩下的是**把代码、配置、文档和实际生成路径彻底对齐**。
