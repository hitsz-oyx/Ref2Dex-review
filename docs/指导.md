# Ref2Dex Correspondence Task 分层组件化重构实施文档

请基于当前本地 Ref2Dex 仓库，对：

```text
src/task/correspondence_ptv3
```

进行一次 Task 内部组件化重构。

本次重构的核心目标不是增加新算法，而是建立以下四层职责：

```text
Layer 1: Base Infrastructure
Layer 2: Task Kernel
Layer 3: Task Experiment Components
Layer 4: Experiment Recipe
```

定义如下：

```text
Base Infrastructure
    跨所有 task 通用的训练基础设施

Task Kernel
    correspondence 问题固定的数据语义、sample contract 和流程骨架

Task Experiment Components
    可替换的研究算法，例如 sampler / supervision / model

Experiment Recipe
    YAML 对组件和超参数的组合
```

最终目标是停止继续增加：

```text
if mode == ...
if contact_mode == ...
if logit_sampling_mode == ...
```

到 Dataset、Runner、Model 主流程中。

允许 selector/factory 中存在集中式分支。

禁止为了完全消灭 `if` 引入复杂 registry、dependency injection framework 或 plugin system。


```python

```

属于 Base。


```text

```

例如：

```python

```

这种类型修正可以做。

## Layer 2：Task Kernel

Task Kernel 表达：

> correspondence 这个问题固定是什么，以及一个 sample 如何经过稳定流程构造。


Task Kernel 可以知道：


但不应该固定：

```text

PTv3 concat
future PTv3 pairgeo
```

这些属于 Layer 3。

YAML 表示实验方案。

```text

```


```yaml

  name: ptv3_concat

    name: soft

```

如果当前 Config loader 对嵌套 YAML object 支持不完善：

```text

```

在 task 内实现轻量 config normalization。

允许 YAML nested dict 被 task-local resolver 转为 typed component config。

## 5.2 EdgeSample

## 9.2 SoftContactSupervision

新增：

```text
supervision/soft.py
```

负责：

```text
output_dim = 1
sigmoid decode
raw logit compatibility export
soft object excess BCE
soft edge per-object excess BCE
entropy floor
```

训练定义：

```text
raw BCE = BCEWithLogits(logits, target)
oracle BCE = Bernoulli entropy target floor
excess BCE = raw BCE - oracle BCE.detach()
```

Object：

```text
raw 和 oracle 使用相同 valid mask
相同 masked mean
```

Cross edge：

```text
raw map
oracle map

二者独立经过相同 per-object reducer

每个 object 内按 edge_weight 平均
有效 object 等权平均
```

返回：

```python
ContactLossResult(
    loss=excess_bce,
    metrics={
        "raw_bce": raw_bce.detach(),
        "oracle_bce": oracle_bce.detach(),
        "excess_bce": excess_bce.detach(),
    },
)
```

不要 clamp excess BCE。

保持 graph-connected zero。

# 十二、Runner 变为 Task Orchestrator

`runner.py` 保持：

```python
CorrespondencePTV3Runner
```

Runner 的固定职责：

```text
构造 task components
调用 model
构造动态 edge target
调用 supervision loss
计算 task metrics
组合 weighted loss
返回 RunnerOutput
```

建议在 `__init__` 或 setup 中：

```python
self.contact_supervision = build_contact_supervision(
    resolve_contact_supervision_config(cfg.meta)
)
```

`build_model()`：

```python
return build_correspondence_model(
    model_cfg=self.cfg.model,
    meta_cfg=self.cfg.meta,
)
```

Runner `_compute_losses()` 的结构应接近：

```python
obj_result = self.contact_supervision.compute_object_loss(
    logits=preds["pred_obj_contact_logits"],
    target_probability=target_contact_prob,
    valid_mask=obj_valid,
)

edge_result = self.contact_supervision.compute_edge_loss(
    logits=preds["pred_cross_contact_logits"],
    target_probability=edge_contact_prob,
    edge_weight=input_edge_weight,
    obj_valid_mask=obj_valid_bool,
)

losses = {
    "obj_contact": (
        loss_obj_contact_weight
        * obj_result.loss
    ),
    "cross_edge_contact": (
        loss_cross_edge_weight
        * edge_result.loss
    ),
    ...
}
```

metric：

```python
aux_metrics = {
    **prefix_metrics("obj_contact", obj_result.metrics),
    **prefix_metrics("cross_edge", edge_result.metrics),
    ...
}
```

例如 soft 自动得到：

```text
obj_contact_raw_bce
obj_contact_oracle_bce
obj_contact_excess_bce

cross_edge_raw_bce
cross_edge_oracle_bce
cross_edge_excess_bce
```

Runner 不再知道 excess BCE 的计算公式。

Runner 不再知道 bin CE 的 target encoding。

Runner 只知道：

```text
contact supervision component 提供 loss
```
