# Ref2Dex V1.2 治理纠偏与可提交验证计划

> 状态：final；影响等级：L3（governance）；approval：user-approved；approved_at：2026-09-18 20:00 +0800。
>
> 本计划完整读取 [V1.2 指导](../指导/V1.2.md)，并以用户于 2026-09-18 的确认作为两个范围决定：恢复
> `modification_version`；从 `oyx` 创建干净治理分支，不改写既有 `ai/governance/phase1`。

## 1. 目标与已确认决定

本次修复 V1.1 治理提交的可追溯和验证边界，使本机 PASS 与远端提交内容一致，并恢复单一
`modification_version` 版本合同。

- `docs/current_versions.yaml` 恢复根与 Task 的 `modification_version` 指针；根当前版本为 `V1.2`。
  `research_version`、`governance_version` 和 `work_version` 不再作为当前版本指针或新记录的必填身份。
- 保留 `git_commit` 与 `run_id` 作为实现/运行追溯字段，但 Activity 改为记录 `base_commit` 和可选
  `related_commits`，不强制记录自身所在提交的不可预知 SHA。
- 继续使用同数值指导谱系 `V<n>.md`、`V<n><letter>.md`：读取完整谱系，跨文件明确冲突以后字母为准；
  同一文件冲突仍须用户确认、修订指导和定稿计划。
- 新分支命名为 `ai/governance/V1.2-verify-hardening`，基于干净 `oyx`，只含治理提交。现有
  `ai/governance/phase1` 和其中混入的 CmResidual 历史不改写、不 force-push。

## 2. 实施范围

### 2.1 纯治理分支与文档可提交性

- 使用独立、干净 worktree 从 `oyx` 建立 V1.2 治理分支；只 cherry-pick 或重建治理文件，不携带 CmResidual
  的四个提交、当前工作树未提交的 Task 文件或实验产物。
- 将当前根 `V1.1.md`、`V1.1a.md`、`V1.2.md` 指导作为 Git 跟踪文件纳入治理分支，确保计划、README 和
  Activity 的链接在远端可解析。
- 对已变更的 Git 文档，本地 Markdown 目标若是仓库内 Markdown 文档，必须已被 Git 跟踪或位于暂存区；仅本机
  未跟踪文件不能使 verify 通过。运行产物链接仍按其实际生成状态和既有规则处理，不强制纳入 Git。

### 2.2 verify 与 CI 合同

- `python3 tools/verify.py --changed` 在非 `oyx` 本地分支选择 `merge-base(oyx, HEAD)...HEAD` 加上 staged
  路径；在 `oyx` 本身只检查 staged 路径。它不读取无关的 unstaged/untracked Task 变更。
- 删除误导性的 `--all` 选项；全量回归将来使用单独、明确命名的入口，不能把受 `pytest.ini` 限制的根 pytest
  冒充全量验证。
- 增加治理测试，覆盖 Git-tracked Markdown 目标、分支差异选择、`oyx` 的 staged-only 行为、补充指导基线及
  `--all` 不再存在。
- 保持 CI 以 PR 的 `VERIFY_BASE...HEAD` 调用唯一 `--changed` 入口。首次推送干净治理分支后创建 Draft PR，
  让 CI 实际运行；PR 创建失败或 CI 不可访问须如实报告，不以本地 PASS 替代。

### 2.3 版本、Activity 和入口纠偏

- 更新 AGENTS、两个 Skill、版本政策、目录规范、根 README、项目总览与 checklist，使它们只要求
  `modification_version`、`base_commit`/`related_commits`、目录化 Activity/experiment 和新 branch 命名。
- 将 `ai_task_checklist.md` 收缩为 deprecated/navigation 页面，只链接 AGENTS、两个 Skill、版本政策、目录规范和
  verify；不再重复工作流规则。
- 修正 V1.1 governance Activity：用 `base_commit: ebefee4…` 和 `related_commits: 4871eed…` 取代不准确的
  `git_commit`。为 V1.2 完成结果创建独立根 Activity。

## 3. 保护边界

- 不修改 Task 研究方法、模型、数据、observation、action、reward、GT、坐标、单位、split、cache/schema、指标、
  checkpoint 解释、训练/评估逻辑或科学结论。
- 不修改或提交当前工作树中的 CmResidual、ObjectInteractionCm、ObjectInteractionCmv2、IsaacGym、Task 计划、
  日志和未跟踪文件。
- 不重写 `ai/governance/phase1`、不 force-push、不删除其远端分支；不自动合并到 `oyx`。
- 不提交 outputs、cache、checkpoint、原始数据或大型日志。

## 4. 验证、交接与回滚

1. 执行 governance 测试、Python 编译、Markdown/YAML 审计、`git diff --check` 和 `python3 tools/verify.py --changed`。
2. 在 Draft PR 中核对 CI 的同一 verify 入口；仅在成功或明确失败后记录真实状态。
3. 写 V1.2 根 Activity，记录 base_commit、related_commits、branch、审批、验证与回滚。
4. 提交并推送仅含治理路径的分支；回滚通过该分支/PR 的单独提交完成，既有 V1.1 分支和 Task 工作树不受影响。

## 5. 审批请求

确认后将创建上述干净 V1.2 治理分支与独立 worktree，实施、测试、推送并创建 Draft PR。不会合并到 `oyx`，也不会
覆盖当前工作树中的任何用户改动。
