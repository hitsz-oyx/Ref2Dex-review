# V1.2h 治理计划：定稿前原地修订，定稿后追加后缀 plan

状态：`FINAL`（用户已确认实施）

work version：`V1.2h`

影响等级：`L3`（计划命名与治理合同）

## 决策

未定稿计划仍是协商中的工作文件，允许在同一文件内原地修订。计划一旦标记为 `FINAL`，其可执行合同
必须保留；后续改变该合同的修改以同基线字母后缀 plan 追加，不能覆盖定稿文件。

由 `指导/V<n><letter>.md` 触发的定稿计划变更沿用同一字母。没有对应指导时，使用该 plan 谱系中下一个
未使用的小写字母。

## 范围与保持项

### 拟议变更

1. 在 AGENTS 和 change-control Skill 明确草案/定稿 plan 的不同修改规则。
2. 添加治理测试，验证两处合同均可被发现。
3. 更新根 work_version、计划和 Activity。

### 保持不变

- 指导补充仍不自动创建 plan，也不要求一一对应。
- 同一指导文件内冲突仍须先向用户确认并写入计划草案。
- 定稿后仅澄清意图、未改变实施合同的补充不创建后缀 plan。
- 不修改 Task、研究语义、数据、cache、checkpoint、outputs 或现有历史计划。

## 风险、验证与回滚

| 风险 | 缓解与验证 |
| --- | --- |
| 草案被误当作不可修改 | 明确非 `FINAL` plan 可原地修订，并以治理测试保护。 |
| 定稿合同被覆盖 | 明确 `FINAL` 后必须使用字母后缀 plan，并测试两处规范。 |
| 指导与 plan 后缀混淆 | 有触发指导时沿用其字母；否则使用下一个未使用的 plan 字母。 |
| 回滚 | 反转独立 V1.2h 提交即可恢复原有表述，不影响研究产物。 |

## 验收标准

1. AGENTS 与 change-control Skill 都区分非 `FINAL` 原地修订和 `FINAL` 后缀追加。
2. 治理测试和 `python tools/verify.py --changed` 通过。
3. 未修改用户的 CmResidual 分支、未跟踪 plan 或任何研究产物。

## 实施授权

用户明确授权直接实施此 L3 规范修订。
