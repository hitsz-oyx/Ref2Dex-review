# V1.2b 治理计划：拆分目录与长任务 Skill

状态：`FINAL`（用户已确认实施）

work version：`V1.2b`
影响等级：`L3`（仓库治理、AGENTS、Skill 与机器验证边界）

## 背景与决策

`V1.2a` 已将仓库治理迁移为以 `work_version`、Activity 和 Skill 为中心的
合同，但其中仍有两个职责混合点：目录与产物放在 change-control Skill 的
reference 中，长时运行的操作约定混在实验工作流中。同时，
`audit_diff.py` 把 Activity 与 Git diff 的逐路径对应关系当作机器门禁，维护
成本和误报风险高于其收益。

本计划是已执行 `V1.2a` 后的补充方案，按既定后缀规则命名为 `V1.2b`。它不
需要与指导文件一一对应；确认后将作为独立的治理工作单元，并把
`docs/current_versions.yaml` 的治理 work version 前移至 `V1.2b`。

## 目标与保持项

### 目标

1. 新建独立的 `directory-and-artifacts` Skill。其名称不含项目名；它专门规定
   目录职责、代码/数据/cache/输出/检查点的放置边界、产物命名与可追溯入口。
2. 新建独立的 `long-running-tasks` Skill。其名称不含项目名；它专门规定长任务
   的启动、状态观察、等待、停止、恢复、检查点和运行状态记录。
3. 保留 `research-experiment-workflow`，但将其收敛为实验设计、变量冻结、证据、
   experiment card 与科学结论的合同；长任务的操作细节改由
   `long-running-tasks` 承担。
4. 移除 `.agents/skills/research-change-control/scripts/audit_diff.py` 及其专属
   reference 和测试；不以另一个逐文件对应脚本替代。
5. 更新根 `AGENTS.md`、相关 Skill 交叉链接和仓库导航，使四个 Skill 的触发条件
   与职责边界清楚可见。

### 保持不变

- `research-change-control` 仍负责影响等级、审批、最小差异、用户改动保护和
  实施后的定向验证，不承担目录规则或长任务轮询细节。
- `research-experiment-workflow` 仍负责科学假设、实验设计、run manifest、
  experiment card 与结论边界，不因工程 smoke 推导科学结论。
- `tools/verify.py --changed` 继续作为统一机器验证入口；它继续覆盖适合机器
  判断的语法、链接、版本合同和 hermetic 测试，不声称自动证明 Activity 与所有
  变更路径逐一对应。
- Activity 的必要字段、人工 diff 审阅和 Git 提交范围审查继续保留；只是取消
  `audit_diff.py` 的自动逐路径门禁。
- 研究语义、Task 实现、数据、cache、checkpoint、outputs、历史日志和用户的
  未暂存删除 `docs/plan/V1.2.15.md` 均不在本计划修改范围内。

| 范围 | 拟议变更 |

| `.agents/skills/long-running-tasks/` | 新建完整 Skill，规定运行前条件、启动信息、受控等待/监控、停止条件、恢复、运行状态和 Activity/experiment card 的记录责任。 |

| `.agents/skills/research-experiment-workflow/` | 删除或转链长任务操作细节；保留实验方法与证据合同，并在需要运行时链接 `long-running-tasks`。 |

| `scripts/audit_diff.py`、`references/audit-contract.md`、`tests/test_audit_diff.py` | 删除；相应的文档链接、验证命令和 CI 引用一并清除。 |
| `docs/current_versions.yaml`、`docs/activities/` | 获确认并实施后，版本指针更新为 `V1.2b`，新增一份 V1.2b Activity 记录实际 diff、审批、验证和回滚入口；不改写 V1.2a 的历史 Activity。 |

## 实施顺序与门禁

1. 在当前治理分支上按已确认的本计划实施；V1.2a 的已暂存实现与 V1.2b 变更作为同一
   未提交治理交付物审阅，但保留各自 Activity 的历史边界。
2. 创建两个独立 Skill，并通过 Skill 创建规范的快速校验；先完成所有入口与
   交叉链接，再删除旧的目录 reference 和 audit 工具。
3. 更新 `AGENTS.md`、Skill 与导航索引，逐项确认：目录规则只由
   `directory-and-artifacts` 所有，长任务操作只由 `long-running-tasks` 所有，
   实验结论只由 `research-experiment-workflow` 所有。
4. 清除 audit 工具、其测试和所有引用，确认 `tools/verify.py` 不依赖该脚本。
5. 更新版本指针，写新的 V1.2b Activity；仅暂存本计划和本次治理文件，明确排除
   用户删除的 `docs/plan/V1.2.15.md`。

## 风险、验证与回滚

| 项目 | 方案 |
| --- | --- |
| 职责遗漏或双重归属 | 审查四份 `SKILL.md` 与根 AGENTS 的触发词、所有权和交叉链接；对每一条目录、运行、科学结论规则只保留一个主所有者。 |
| 删除 audit 脚本后失去审计能力 | 保留 `git diff --check`、显式暂存范围审查、Activity 必填字段审查和 `verify.py --changed`；交接时明确机器验证不覆盖逐路径 Activity 对照。 |
| Skill 格式或导航损坏 | 对四份 Skill 运行 quick validation，执行 Markdown 链接审计和 `tools/verify.py --changed`。 |
| 测试回归 | 运行治理测试与 run-manifest 兼容测试；删除 audit 专属测试后，确认没有残余导入或 CI 调用。 |
| 回滚 | 此次治理变更独立提交；如职责拆分不可用，反转该提交即可恢复 V1.2a 的 Skill 与工具布局，不触及研究代码、数据或历史记录。 |

## 验收标准

1. 仓库中存在且可独立发现四个 Skill：`research-change-control`、
   `research-experiment-workflow`、`directory-and-artifacts` 和
   `long-running-tasks`。
2. 新目录与长任务 Skill 名称均不含 `ref2dex`；根 AGENTS 与导航明确其触发条件。
3. `research-experiment-workflow` 不再作为长任务轮询/停止/恢复的主规范；科学结论
   与运行状态仍分开记录。
4. `audit_diff.py`、其专属 reference/测试及全部调用已移除，且 `verify.py --changed`
   仍可独立通过。
5. 新增 V1.2b Activity、版本指针和提交范围符合本计划；用户的 `V1.2.15.md`
   删除不被纳入提交。
