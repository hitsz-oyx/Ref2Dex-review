# V1.2c 治理计划：目录例外的先询问、追溯与规范确认

状态：`FINAL`（用户已确认实施）

work version：`V1.2c`

影响等级：`L3`（AGENTS、目录与产物 Skill 的公共治理合同）

## 决策

当代码、运行或文档需要使用 `directory-and-artifacts` 合同以外的位置，而现有合同无法
明确决定位置时，AI 不得自行选择、创建、移动或写入该位置；必须先向用户说明候选位置和
影响，并等待选择。

若 AI 已在未确认的位置先行创建、移动或写入内容，无论该行为何时被发现，必须在发现后的
下一次回复中优先、明确汇报，不得继续扩展该例外或把它混在普通交接中。报告至少给出：
精确路径、内容/规模、发生原因、与现有合同的偏离、可能影响、当前 Git/忽略状态，以及
保留、迁移或删除的选项。随后必须询问用户：本次例外是否应提升为
`directory-and-artifacts` 的通用规范；未经确认，不得把个案静默写成长期规则。

“先斩后奏”的及时汇报不构成追认，也不免除原本所需的审批或用户位置选择。

## 目标与保持项

### 目标

1. 在根 `AGENTS.md` 固化目录例外的先询问与发现后即时汇报门槛。
2. 在 `directory-and-artifacts` 中作为目录合同的唯一细则所有者，补充候选位置、用户确认、
   例外报告和“是否提升为规范”的流程。
3. 在 `research-change-control` 中加入路由：遇到未决目录例外时，停止该路径上的写操作，
   转用目录 Skill 并请求用户决定。
4. 为 V1.2c 添加 Activity、更新根 `work_version`，并以治理测试和统一验证入口验证链接与
   当前合同。

### 保持不变

- 已有目录表、outputs 根目录只读、数据/cache/checkpoint 不提交、用户改动保护和研究
  invariant 不改变。
- 已明确符合 `directory-and-artifacts` 的正常路径无需逐次再次询问。
- 该规则不授权 AI 在未确认位置预创建空目录、临时文件、cache 或产物；必须先获得用户的
  位置决定。
- 不回填或改写历史 outputs、cache、Activity、实验卡和日志；历史事实只在需要时报告。

## 风险、验证与回滚

| 风险 | 缓解与验证 |
| --- | --- |
| 正常路径被误判为例外，增加无意义提问 | 明确“仅在现有目录合同不能决定位置时”触发；对目录表中的已知路径不重复确认。 |
| 事后汇报变成对先行写入的默许 | 明确报告不构成追认；先暂停扩大影响，再由用户选择保留、迁移或删除。 |
| 个案被过度固化 | 每次例外报告都单独询问是否提升；只有用户确认才修改 Skill 合同。 |
| 文档合同漂移 | 运行 Skill quick validation、治理测试、Markdown 链接检查与 `conda run -n graspenv python tools/verify.py --changed`。 |
| 回滚 | 本次为独立治理提交；反转该提交即可恢复 V1.2b 目录合同，不改变任何运行产物或研究代码。 |

## 验收标准

1. 当目录位置未由当前合同决定时，AGENTS 和目录 Skill 均明确要求先请求用户位置决定。
2. 已发现的未授权目录例外必须优先报告其路径、内容/规模、原因、影响、Git 状态和处理选项，
   并在同次报告中询问是否将其写入规范。
3. 既有合规路径继续按原目录表运行，不产生额外确认步骤。
4. 根 `work_version`、V1.2c Activity、Skill 校验、治理测试与统一机器验证均通过。
