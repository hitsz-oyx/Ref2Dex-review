# V1.2d 治理计划：work_version 迁移门禁排除运行产物

状态：`FINAL`（用户已确认实施）

work version：`V1.2d`

影响等级：`L3`（治理测试、版本指针与公共验证边界）

## 决策

`test_work_version_migration` 的职责是检查受版本控制的活动 Task 源码与配置是否仍写入
旧 `modification_version`。它不应读取本机的历史运行产物；这些内容位于
`src/task/**/research/**/output/**`，按 `directory-and-artifacts` 合同不可提交、不可回写，
可以保留历史字段。

测试改为只枚举 Git 跟踪的 `src/task` 文件，并跳过任何 `output` 路径组成部分。它不迁移、
删除或修改现有 outputs，也不放宽对活动源码、YAML/JSON/TOML 配置的 work_version 门禁。

## 范围、风险与回滚

- 修改 `tests/governance/test_work_version_migration.py` 的枚举范围；新增 V1.2d plan、
  Activity、索引和根 work_version 指针。
- 风险是错误排除真正的活动源文件。缓解方式是仅跳过名称为 `output` 的路径组成部分，并继续
  遍历 Git 跟踪的其余 Task 文件；治理测试将运行于包含本机历史 outputs 的主工作树。
- 不修改 AGENTS、Skill、Task 实现、数据、cache、checkpoint 或 outputs；不重写历史 manifest。
- 回滚为反转本次独立提交，即恢复 V1.2c 的扫描逻辑；不会影响任何运行产物。

## 验收与验证

1. 在主工作树已有历史 `research/**/output/**` 的条件下，迁移门禁不再把其中旧字段报为源码违规。
2. Git 跟踪的非 output Task 源码和配置仍不得含 `modification_version`。
3. 使用 Conda `graspenv` 运行治理/manifest 测试及
   `VERIFY_BASE=origin/oyx python tools/verify.py --changed`。
4. V1.2d Activity、版本指针和提交范围通过 `git diff --check` 审阅。
