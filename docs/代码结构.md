# Ref2Dex 代码结构

## 主数据流

```text
GRAB / ARCTIC raw data
  -> 数据集目录内解析和 Stage 2 生成
  -> 公共 Stage 2 sequence-hand pkl
  -> 公共 Stage 3 sequence-hand npz
  -> epoch 级 512 物体点采样和随机增强
  -> correspondence_ptv3
```

不生成或读取独立 Stage 1 中间数据。

## 数据处理职责

`process/GRAB/raw.py` 和 `process/ARCTIC/raw.py` 只负责数据集特定逻辑：

- 读取原始文件；
- 统一米制单位和坐标定义；
- 重建 MANO 手部几何；
- 固定采样 4096 个物体表面点；
- 构造供公共 Stage 2 writer 使用的内存字段。

`process/GRAB/optimize.py` 和 `process/ARCTIC/optimize.py` 是用户入口。它们将
左右手拆成独立样本，并调用 `process/common/stage2.py`：

- 按 5cm hand-object 最近距离过滤帧；
- 生成公共字段和质量诊断；
- 写入 `processed_data/generated/stage2/<variant>/`。

`process/stage3/prepare_corr_static.py` 不包含数据集分支。它负责：

- 将世界坐标转换到 hand-root frame（可选 object frame）；
- 保留 4096 个物体点；
- 计算 5cm object candidate mask 与 hand-to-full-object 最短距离；
- 输出仅供 correspondence_ptv3_v2 使用的最小 Stage 3 v2 schema；
- 默认写入 `processed_data/generated/stage3/<variant>_v2/`。

当前训练集加载器 `src/task/correspondence_ptv3_v2/dataset.py` 负责运行时逻辑：

- 用 frame 和 epoch 生成确定性随机种子；
- 从候选池采样 512 个物体点；
- 候选不足时 padding；
- 对输入物体施加共享 SE(3) pose perturbation，手和 GT 均保持 clean；
- 构造 random128、contact-aux 与 dense hand heatmap 三条监督流。

## 模型代码

```text
src/task/correspondence_ptv3/
├── config.py
├── dataset.py
├── sampling.py
├── model.py
├── runner.py
├── train.py
├── eval.py
└── README.md
```

`model.py` 定义 PTV3 backbone、object-hand cross interaction 和当前单一
canonical correspondence head。`runner.py` 计算 loss 和指标；
`src/base/checkpoint.py` 管理原子 checkpoint。

## 可视化

- `render/stage2_visualize.py`：检查公共 Stage 2 几何、帧过滤和坐标系。
- `render/stage3_visualize.py`：显示 4096 点池、5cm 候选、实际采样 512 点、
  clean/noisy hand 以及 clean/input KNN。
- `tools/stage3_npz_to_ply.py`：将 Stage 3 帧导出为标准 binary PLY。

Open3D 使用：

```bash
export DISPLAY=localhost:10.0
```

具体数据字段以 [架构.md](./架构.md) 为准，处理命令见
[`process/README.md`](../process/README.md)。
