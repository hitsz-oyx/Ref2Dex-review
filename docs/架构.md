# Ref2Dex 静态 Correspondence 整体流程

## 1. 总体流向

```text
原始数据集
-> Stage 2: 各数据集独立的 opti / hand preparation 脚本
-> Stage 2 公共格式:
   processed_data/generated/stage2/<dataset_variant>/<subject>/<seq>_<side>.pkl
-> Stage 3:
   processed_data/generated/stage3/<dataset_variant>/<subject>/<seq>_<side>.npz
-> 训练时按 epoch 从物体点池重采样 512 点
-> noisy-hand runtime 邻域 / label / mask 在 dataloader 中生成
-> correspondence_ptv3
```

不再生成独立的 Stage 1 中间数据集。

每类数据集直接从原始数据读取，由自己的 opti 脚本完成：

```text
原始字段解析
-> 坐标和单位统一
-> 物体表面固定采样
-> 左右手拆分
-> MANO 重建或可选优化
-> 输出统一的 Stage 2 schema
```

当前训练版本约定：

```text
1. Stage 2 / Stage 3 文件单位：single_sequence_single_hand
2. 训练样本单位：single_frame_single_hand
3. GRAB 当前使用 init-only hand，不执行接触优化
4. Stage 2 保存完整 4096 个物体表面点
5. Stage 2 直接滤除整只手到物体最近距离大于 5cm 的帧
6. Stage 3 保存完整物体点池，不提前固定训练使用的 512 点
7. Stage 3 的 clean object-hand KNN 落盘，用于监督和可视化
8. 每个 epoch 从 5cm 候选池确定性随机采样 512 个物体点
9. 训练输入特征全部基于 runtime input geometry 计算；当前扰动策略为 clean object + noisy hand
10. 训练监督：clean object + clean hand
11. cross 方向：object -> hand
12. runtime context 邻域：object->hand，4cm 内最多 32 个；当前默认只保留为可选 cross-attn / 调试开关
13. runtime logit 邻域：按 clean GT 统计 2.5cm 内近点手点，并从 >2.5cm 的手点里随机采样等量远点；近点/远点都在各自候选池内随机抽取；总长上限 64，不足直接 padding
14. obj_contact 对所有采样 object 点计算，不要求 runtime context 邻域非空
15. 默认不使用 cano head，不使用 hand/object 双 stem，不开启 cross-attn
16. 监督实现上保留 `obj_contact` 和 `cross_edge_contact` 两个 10-bin loss；当前 baseline 只开启 `cross_edge_contact`
17. AUPRC / rank@k / decoded BCE 等只作为观察指标，不参与梯度反传
18. train/val 留空切分时按原始 sequence 分组，同一条轨迹的 left/right 不允许同时出现在 train 和 val
19. 验证默认同时保留 `val_clean` 和 `val_perturbed` 两套 loader；后者只固定手部扰动，不改变 GT 几何和 GT logit 邻居集合
```

## 2. Stage 2：数据集独立的 opti / hand preparation

### 2.1 路径

```text
raw dataset
-> process/<DATASET>/optimize.py
-> processed_data/generated/stage2/<dataset_variant>/<subject>/<seq>_<side>.pkl
```

不同数据集使用独立脚本，例如：

```text
GRAB   -> process/GRAB/optimize.py
ARCTIC -> process/ARCTIC/optimize.py
```

脚本实现可以不同，但必须输出相同的 Stage 2 公共字段。

### 2.2 作用

```text
1. 直接读取原始数据集
2. 统一长度单位为 meter
3. 统一坐标和法向定义
4. 把左右手拆成独立样本
5. 在原始物体 mesh 上固定采样 4096 个表面点
6. 重建 MANO hand，或按数据集需要执行优化
7. 计算每帧整只手到物体的最近距离，直接滤除距离大于 5cm 的帧
8. 输出完整物体点和 clean hand
9. 保存数据来源、处理模式和质量诊断
```

GRAB 当前配置：

```python
processing_mode = "init_only"
```

`init_only` 表示直接使用原始 GRAB MANO 重建结果，不执行 contact / repulsion
优化。Stage 2 仍保留为数据集适配层，负责左右手拆分和公共 schema 输出。

### 2.3 物体 4096 点采样约定

```text
1. 在每个物体的原始 mesh 表面做均匀面积采样
2. 每个物体只生成一套固定的 4096 个 sample
3. 同一物体的所有序列和所有帧共享 sample identity
4. 刚体物体只变换 sample 坐标和法向
5. 铰接物体按固定 sample identity 随 mesh 变形
6. obj_point_id 表示这套预采样点的稳定 id，不等价于 mesh vertex id
```

采样必须使用稳定 seed，并在 Stage 2 meta/config 中保存 seed 和采样策略。

### 2.4 Stage 2 公共字段

```python
stage2_seq = {
    # ------------------------------------------------------------
    # 1. 来源和处理模式
    # ------------------------------------------------------------
    "schema_name": str,                  # "ref2dex_opti"
    "schema_version": str,
    "source_raw_file": str,              # 相对 raw dataset root 的路径
    "processing_mode": str,              # "init_only" 或具体优化方法
    "dataset_name": str,
    "seq_id": str,                       # "{subject_id}/{seq_name}"
    "subject_id": str,
    "seq_name": str,
    "object_name": str,
    "side": str,                         # "left" 或 "right"

    # ------------------------------------------------------------
    # 2. 帧索引
    # ------------------------------------------------------------
    "raw_frame_id": Int[T_stage2],       # 原始数据集帧号
    "stage2_frame_idx": Int[T_stage2],   # Stage 2 文件内部帧号

    # ------------------------------------------------------------
    # 3. 完整物体点，世界坐标
    # ------------------------------------------------------------
    "obj_points_world": Float[T_stage2, 4096, 3],
    "obj_normals_world": Float[T_stage2, 4096, 3],
    "obj_point_id": Int[4096],           # 固定表面 sample id，通常为 0..4095
    "obj_root_pose": Float[T_stage2, 4, 4],  # object root -> world

    # ------------------------------------------------------------
    # 4. 当前单手 clean geometry，世界坐标
    # ------------------------------------------------------------
    "hand_points_world": Float[T_stage2, 1538, 3],   # MANO face centers
    "hand_normals_world": Float[T_stage2, 1538, 3],
    "hand_point_id": Int[1538],                      # 固定 MANO face id

    # ------------------------------------------------------------
    # 5. 可选手部 metadata（当前 bin-contact 基线不消费）
    # ------------------------------------------------------------
    "hand_cano_points": Float[1538, 3],  # optional
    "hand_finger_id": Int[1538],         # optional
    "hand_region_id": Int[1538],         # optional

    # ------------------------------------------------------------
    # 6. 帧筛选诊断
    # ------------------------------------------------------------
    "frame_min_hand_obj_dist": Float[T_stage2],  # meter，所有保存帧均 <= 0.05

    # ------------------------------------------------------------
    # 7. 质量诊断
    # ------------------------------------------------------------
    "penetration_depth": Float[T_stage2], # meter；允许使用近似指标，但需在 config 注明
    "processing_success": Bool[T_stage2],
    "processing_message": List[str],

    # ------------------------------------------------------------
    # 8. 可复现配置
    # ------------------------------------------------------------
    "config": Dict,                       # MANO、采样、优化及阈值配置
}
```

Stage 2 在写文件前已经完成 5cm 帧筛选，因此不再保存 `hand_valid`。这里的
`frame_min_hand_obj_dist` 是每帧一个标量；Stage 3 的
`obj_to_hand_min_dist` 是每个物体点一个标量，两者不可混用。

`hand_cano_normals` 不保存。当前默认的 bin-contact 基线不消费
`hand_cano_points / hand_finger_id / hand_region_id`；如果保留这些字段，它们只作为
兼容或分析用 metadata，而不是主训练路径的必需输入。

如果某个数据集执行了真实优化，可以额外保存：

```python
optional_optimization_fields = {
    "init_hand_points_world": Float[T_stage2, 1538, 3],
    "init_hand_verts_world": Float[T_stage2, 778, 3],
    "hand_verts_world": Float[T_stage2, 778, 3],
    "init_jt_rms": Float[T_stage2],
    "final_jt_rms": Float[T_stage2],
    "init_vert_rms": Float[T_stage2],
    "final_vert_rms": Float[T_stage2],
    "final_loss": Float[T_stage2],
}
```

这些是优化审计字段，不是 Stage 3 的必需输入。

### 2.5 Stage 2 不保存的字段

```text
1. 不保存 object-frame 几何；Stage 3 用 obj_root_pose 统一转换
2. 不保存 object crop；Stage 2 始终保留完整 4096 点
3. 不保存 obj->hand 1NN / KNN；Stage 3 统一计算
4. 不保存 hand->obj NN
5. 不保存训练 contact label
6. 不保存训练期随机采样的 512 点
```

## 3. Stage 3：静态 Correspondence 点池

### 3.1 路径

```text
processed_data/generated/stage2/<dataset_variant>/<subject>/<seq>_<side>.pkl
-> process/stage3/prepare_corr_static.py
-> processed_data/generated/stage3/<dataset_variant>/<subject>/<seq>_<side>.npz
```

### 3.2 作用

```text
1. 读取 Stage 2 已经通过 5cm 整帧筛选的数据
2. 把完整 object 和 clean hand 转换到 object frame
3. 保留完整 4096 个 object points
4. 计算每个 object point 到 clean hand 的最小距离
5. 生成 5cm object candidate mask
6. 为 5cm candidate points 计算并保存 clean obj->hand top-K GT 邻居
7. 为按 epoch 重采样和可视化提供确定的 clean 数据
```

Stage 3 不提前选择最终训练使用的 512 个 object points。

### 3.3 点数和阈值

```python
N_obj_pool = 4096
N_obj_train = 512
N_hand = 1538
K_gt = 32
K_ctx = 32
K_logit = 64
ctx_radius = 0.04
logit_near_radius = 0.025          # 近点阈值：clean GT 手在物体点 2.5cm 内的边进入近点池
logit_far_min_radius = 0.025       # 远点阈值：>2.5cm 的边进入远点池
N_runtime_total = N_obj_train + N_hand  # 2050

obj_candidate_threshold = 0.05          # meter
contact_d_pos = 0.005
contact_d_neg = 0.03
contact_gamma = 1.0
```

5cm candidate 定义：

```python
obj_to_hand_min_dist[i] = min_j ||obj_point[i] - clean_hand_point[j]||
obj_candidate_mask_5cm[i] = obj_to_hand_min_dist[i] <= 0.05
```

`3cm < distance <= 5cm` 的点保留在候选池中，但 contact soft label 为 0，
因此自然形成接触区域周围的低概率点，不再做人为 near/context 均衡采样。

Stage 3 的 clean GT 邻居表仍按 top-K 保存：

```python
gt_obj_to_hand_knn_idx[i] =
    topk_clean_hand_indices(
        query=obj_point[i],
        key=clean_hand_points,
        k=K_gt,
    )
```

runtime 邻域在 dataloader 中动态生成，并拆成两套：

```python
ctx_hand_idx(i) =
    topk_within_radius(
        query=input_obj_point[i],
        key=noisy_hand_points,
        radius=ctx_radius,
        k=K_ctx,
    )

far_logit_hand_idx(i) =
    random_choice(
        {j | ||clean_obj_point[i] - clean_hand_points[j]|| > logit_far_min_radius},
        k=len(near_logit_hand_idx(i)),
    )

near_logit_hand_idx(i) =
    random_choice(
        {j | ||clean_obj_point[i] - clean_hand_points[j]|| <= logit_near_radius},
        k=min(K_logit // 2, all_near_count(i)),
    )
```

`near_logit_hand_idx` 与 `far_logit_hand_idx` 拼接后不足 `K_logit=64` 时直接 padding。

PyTorch 后统一转为 `torch.long`。

不落盘完整 KNN distance。可视化或检查时根据：

```python

hand_points
gt_obj_to_hand_knn_idx
```

重新计算选中边的距离。只单独保存用于候选筛选和 contact label 的
`obj_to_hand_min_dist`。

### 3.6 Stage 3 数据检查

每个 Stage 3 文件至少检查：

```text
1. 所有坐标和法向均为 finite
2. obj_point_id 在同一物体上稳定
3. obj_candidate_mask_5cm 与 obj_to_hand_min_dist <= 0.05 完全一致
4. candidate 行的 gt_obj_to_hand_knn_idx[..., 0] 对应真实最近 clean hand point
5. KNN index 范围为 -1 或 [0, 1537]
6. KNN 按距离非递减排序
7. T_world_from_obj 能把 object-frame 几何还原到 Stage 2 world frame
```

## 4. 训练时按 epoch 重采样

### 4.1 epoch seed

每个训练样本的 object 采样 seed：

```text
seed = stable_hash(
    base_seed,
    seq_id,
    side,
    raw_frame_id,
    epoch,
)
```

不能只使用 `raw_frame_id + epoch`，因为不同 subject / sequence / side 可能有
相同帧号。

必须使用稳定哈希，例如 BLAKE2；不能直接使用受
`PYTHONHASHSEED` 影响的 Python `hash()`。

训练集每轮开始前：

```python
train_dataset.set_epoch(epoch)
```

验证集固定：

```python
val_clean_dataset.set_epoch(0)
val_perturbed_dataset.set_epoch(0)
```

两套验证集都不随训练 epoch 改变采样点。`val_clean` 不做手部扰动；
`val_perturbed` 对 input hand 使用固定 seed 的 deterministic perturb，但 GT geometry、
GT logit 邻居索引和 GT label 定义保持 clean。

Stage 3 的单个 sequence npz 包含较大的 KNN 数组。训练默认先随机打乱 sequence
顺序，再在单个 sequence 内打乱帧顺序，以避免全局随机帧顺序导致每个 sample
都重新解包另一个 npz。若确实需要全局 `RandomSampler`，可设置：

```python
data.sequence_locality_shuffle = False
```

### 4.2 512 点选择

对一帧：

```python
candidate_idx = nonzero(obj_candidate_mask_5cm)
```

如果候选点不少于 512：

```python
selected_obj_idx = random_choice(
    candidate_idx,
    size=512,
    replace=False,
    seed=frame_epoch_seed,
)
runtime_obj_valid_mask = ones(512)
```

如果候选点少于 512：

```python
selected_obj_idx[:num_candidates] = deterministic_shuffle(candidate_idx)
selected_obj_idx[num_candidates:] = -1
runtime_obj_valid_mask[:num_candidates] = True
runtime_obj_valid_mask[num_candidates:] = False
```

padding 约定：

```text
1. padding 坐标和法向填 0
2. padding point id 填 -1
3. padding clean KNN index 填 -1
4. 所有 object-level / edge-level loss 必须乘 runtime_obj_valid_mask
5. 不使用有放回采样，不复制真实点
```

### 4.3 runtime 几何

先从 Stage 3 完整点池中 gather clean object：

```python
safe_selected_obj_idx = selected_obj_idx.clamp(min=0)

clean_obj_points = obj_points[safe_selected_obj_idx]       # [512, 3]
clean_obj_normals = obj_normals[safe_selected_obj_idx]     # [512, 3]
clean_gt_knn_idx = gt_obj_to_hand_knn_idx[safe_selected_obj_idx]  # [512, K]
clean_obj_min_dist = obj_to_hand_min_dist[safe_selected_obj_idx]  # [512]

clean_obj_points[~runtime_obj_valid_mask] = 0
clean_obj_normals[~runtime_obj_valid_mask] = 0
clean_gt_knn_idx[~runtime_obj_valid_mask] = -1
clean_obj_min_dist[~runtime_obj_valid_mask] = 0
```

再保留 clean GT，并只对 input hand 加噪：

```python
gt_obj_points = clean_obj_points
gt_obj_normals = clean_obj_normals
gt_hand_points = hand_points
gt_hand_normals = hand_normals

input_obj_points = clean_obj_points
input_obj_normals = clean_obj_normals
input_hand_points, input_hand_normals = perturb(hand_points, hand_normals)
```

最后拼接模型输入：

```python
points = concat([input_obj_points, input_hand_points], dim=0)  # [2050, 3]
normals = concat([input_obj_normals, input_hand_normals], dim=0)

gt_points = concat([gt_obj_points, gt_hand_points], dim=0)
gt_normals = concat([gt_obj_normals, gt_hand_normals], dim=0)
```

### 4.4 runtime noisy-hand 邻域

模型候选边拆成 context / logit 两套：

```text
context query = selected input object points
context key   = noisy input hand points
ctx   = radius <= 4cm，再做 K_ctx=32 padding

logit query/label geometry = clean object points + clean hand points
logit near pool  = distance <= 2.5cm
logit far pool   = distance > 2.5cm
logit sampling   = 近点/远点候选内部都随机抽样；近点最多 32 个，远点按近点数配平，
                  总长上限 K_logit=64
model features  = 对上述 hand point id，从 noisy input hand token 中 gather
```

```python
input_obj_to_hand_ctx_idx:
    Int[B, 512, K_ctx]

input_obj_to_hand_ctx_valid_mask:
    Bool[B, 512, K_ctx]

input_obj_to_hand_logit_idx:
    Int[B, 512, K_logit]

input_obj_to_hand_logit_valid_mask:
    Bool[B, 512, K_logit]

input_obj_to_hand_logit_loss_weight:
    Float[B, 512, K_logit]   # 当前默认 valid edge 全 1.0
```

context hand 的规则：

```python
ctx_candidates =
    {j | ||input_obj_points[i] - noisy_hand_points[j]|| <= ctx_radius}
```

如果 `ctx_candidates` 超过 `K_ctx`，保留最近的 `K_ctx` 个；否则 padding。

runtime logit 近点池规则：

```python
near_candidates =
    {j | ||clean_obj_points[i] - clean_hand_points[j]|| <= logit_near_radius}
```

如果 `near_candidates` 超过 `K_logit // 2 = 32`，在近点池内部随机采样 32 个；
否则全部保留。

runtime logit 远点池规则：

```python
far_candidates =
    {j | ||clean_obj_points[i] - clean_hand_points[j]|| > logit_far_min_radius}
```

从 `far_candidates` 中随机采样 `min(num_near, K_logit - num_near)` 个；
不足则只保留已有远点，不强补。

最终：

```python
input_obj_to_hand_logit_idx[i] =
    concat([
        near_logit_hand_idx[i],
        far_logit_hand_idx[i],
    ], dim=0)

input_obj_to_hand_logit_loss_weight[i] =
    ones_like(valid_logit_slots)
```

padding object point 的所有邻域 index 填 `-1`，valid mask 填 `False`。

clean GT 邻居表、runtime context 邻域、runtime logit 邻域三者含义不同：

```text
gt_obj_to_hand_knn_idx:
    clean geometry 的 GT correspondence，来自 Stage 3

    noisy geometry 的局部上下文邻域；当前默认只作为可选 cross-attn / 调试输入

    noisy geometry 的 edge supervision 邻域，用于 pred_cross_contact_bin
```

注意：

```text

2. 这类点仍参与 obj_contact 等 object-level supervision
3. 当前默认关闭 cross-attn；若之后开启，这类点不会得到 ctx update
4. cross-edge loss 仍只在 valid runtime logit edges 上生效
```

## 5. 模型

当前任务的目标仍然是训练 hand-object 交互后的 object dense token，但默认路径改为
更直接的 bin-contact 基线：

```text
1. 输入特征全部由 runtime noisy geometry 计算
2. 不使用 cano head
3. 不使用 hand/object 双 stem
4. cross-attn 默认关闭，只保留 config 开关
5. 训练只反传两个 10-bin contact loss
```

### 5.1 输入特征

对任一点 `p`，记它的法向为 `n`，点类型为 `type ∈ {object, hand}`。在当前
runtime 输入几何上定义：

```python
opp_nn(p)   = nearest point of the opposite cloud
u_nn(p)     = normalize(opp_nn(p) - p)
u_cent(p)   = normalize(centroid(opposite_cloud) - p)

point_feat(p) = [
    p_xyz,                       # 3
    one_hot(type),               # 2
    n,                           # 3
    ||opp_nn(p) - p||,           # 1
    dot(u_nn(p), n),             # 1
    dot(u_cent(p), n),           # 1
]                                # 11D
```

`opposite_cloud` 的定义：

```text
object point -> noisy input hand
hand point   -> selected input object points
```

也就是说，所有 hand-related 几何特征都基于 noisy hand 计算，而不是 clean GT hand。
当前扰动策略仍是“object 保持 clean，hand 加噪”，但特征定义本身是 runtime-input
导向的，之后如果要扩展到 noisy object，也不需要改标签语义。

### 5.2 Unified PTv3 backbone

```python
coord = concat([input_obj_points, noisy_hand_points], dim=1)
feat = concat([obj_point_feat, hand_point_feat], dim=1)
point_valid_mask = concat([
    runtime_obj_valid_mask,
    ones(B, 1538),
], dim=1)

tokens = PTv3(coord, feat, point_valid_mask)

z_obj = tokens[:, :512]             # [B, 512, token_dim]
z_hand = tokens[:, 512:]            # [B, 1538, token_dim]
```

这里不再区分 `obj_stem / hand_stem`。如果实现上需要把 11D 输入对齐到固定 channel，
最多允许一个共享输入投影层，但它不应重新变成 hand/object 两套 stem。

### 5.3 Optional object-hand cross attention

当前默认：

```python
use_cross_attn = False
obj_dense_tokens = z_obj
hand_dense_tokens = z_hand
```

如果之后开启该开关，只允许使用 `input_obj_to_hand_ctx_idx` 这套局部 noisy 邻域来
更新 object token；它是可选增强，不是当前基线路径。

```python
obj_dense_tokens =
    cross_attn_update(
        z_obj,
        z_hand,
        input_obj_to_hand_ctx_idx,
        input_obj_to_hand_ctx_valid_mask,
    )
```

### 5.4 输出 heads

#### Object contact 10-bin head

```python
pred_obj_contact_bin = contact_head(obj_dense_tokens)
# [B, 512, 10]
```

#### Cross-edge contact 10-bin head

对 `input_obj_to_hand_logit_idx` 指定的 runtime logit edges：

```python
edge_shared_ik = edge_backbone([
    obj_dense_tokens[i],
    z_hand[j],
])

pred_cross_contact_bin_ik = cross_edge_head(edge_shared_ik)
# [B, 512, K_logit, 10]
```

当前默认不把 raw edge distance / `edge_geo` 直接喂给预测 head，避免 head 直接读取
几何 shortcut。几何关系主要通过第 5.1 节的点特征和 backbone token 来表达。

slot 排列约定仍保持：

```text
1. pred_cross_contact_bin[..., :32] 优先写入近点随机采样槽位
2. pred_cross_contact_bin[..., 32:64] 顺序写入远点随机采样槽位
3. 若近点或远点数量不足，剩余槽位直接 padding
4. 这个排列只服务实现与调试，不应被当成有语义的 rank embedding
```

### 5.5 从 bin logits 解码回标量概率

训练监督是 10-bin classification，但评估、排序和可视化仍需要 `[0, 1]` 的标量概率。

当前默认的解码方式：

```python
bin_center[c] = (c + 0.5) / 10

pred_contact_prob =
    sum_c softmax(pred_contact_bin_logits)[c] * bin_center[c]
```

这比直接取 argmax 更平滑，更适合做 AUPRC、rank@k 和连续着色。

如果需要严格复现 ContactOpt 的 `class_to_val` 风格，也可以切换为：

```python
pred_contact_prob = (argmax_c pred_contact_bin_logits[c] + 0.5) / 10
```

但当前默认建议使用 softmax 期望值解码。

### 5.6 模型输出

```python
model_output = {
    "obj_dense_tokens": Float[B, 512, token_dim],
    "hand_dense_tokens": Float[B, 1538, token_dim],
    "ptv3_obj_tokens": Float[B, 512, token_dim],

    "pred_obj_contact_bin": Float[B, 512, 10],
    "pred_cross_contact_bin": Float[B, 512, K_logit, 10],

    "pred_obj_contact_prob": Float[B, 512],            # decoded for metrics / vis
    "pred_cross_contact_prob": Float[B, 512, K_logit], # decoded for metrics / vis

    "obj_to_hand_attn": Float[B, 512, K_ctx],          # only if use_cross_attn=True
}
```

## 6. 训练监督和 Loss

### 6.1 先生成连续 contact probability

先用当前的 distance -> probability 映射生成连续 supervision，然后再离散成 10 个
概率 bin。这里分 bin 的对象是 contact probability，不是距离本身。

#### Object contact probability

```python
obj_contact_prob = soft_contact_label(
    selected_obj_min_dist,
    d_pos=0.005,
    d_neg=0.03,
    gamma=1.0,
)
```

padding 点标签填 0，并由 `runtime_obj_valid_mask` 屏蔽。

只要一个 object 点被采样为 runtime 有效点，就计算它的 `obj_contact_prob`。这与它
在当前 noisy-hand runtime 邻域中是否存在 valid hand neighbor 无关。

#### Dynamic cross-edge contact probability

cross-edge target 不按 clean KNN rank 对齐，而是使用 noisy runtime logit
邻域的实际 hand index，到 clean hand geometry 中取对应点：

```python
edge_hand_idx = input_obj_to_hand_logit_idx
clean_edge_hand_points = gather(gt_hand_points, edge_hand_idx)

edge_dist = ||clean_edge_hand_points - gt_obj_points||
edge_contact_prob = soft_contact_label(
    edge_dist,
    d_pos=0.005,
    d_neg=0.03,
    gamma=1.0,
)
```

这保证：

```text
候选邻域来自 noisy hand
监督距离来自 clean hand
```

### 6.2 Contact probability -> 10 bins

参考 ContactOpt 的做法，使用 10 个概率 bin：

```python
num_contact_bins = 10

contact_bin =
    clamp(
        floor(contact_prob * num_contact_bins),
        min=0,
        max=num_contact_bins - 1,
    )
```

也就是：

```text
[0.0, 0.1) -> bin 0
[0.1, 0.2) -> bin 1
...
[0.9, 1.0] -> bin 9
```

如果训练集统计显示类别极不均衡，可以像 ContactOpt 一样给交叉熵加入
`bin_weights`，但这只是 loss 的内部加权，不改变标签定义。

### 6.3 Object contact bin loss

```python
loss_obj_contact =
    sum(
        CE(pred_obj_contact_bin[i], obj_contact_bin[i])
        * runtime_obj_valid_mask[i]
    )
    / sum(runtime_obj_valid_mask)
```

实现上可以直接用 `CrossEntropyLoss` 作用在 logits 上，也可以先
`log_softmax` 再用 `NLLLoss`；两者语义等价。

注意：某个 object 点即使当前没有任何 valid runtime hand neighbor，它仍然参与
`loss_obj_contact`。

### 6.4 Cross-edge contact bin loss

```python
edge_valid_mask =
    input_obj_to_hand_logit_valid_mask
    & runtime_obj_valid_mask.unsqueeze(-1)

loss_cross_edge_contact =
    sum(
        CE(pred_cross_contact_bin[i, s], edge_contact_bin[i, s])
        * edge_valid_mask[i, s]
        * input_obj_to_hand_logit_loss_weight[i, s]
    )
    / sum(edge_valid_mask * input_obj_to_hand_logit_loss_weight)
```

`edge_valid_mask` 只控制 edge-level supervision 的有效边，不反向限制
`loss_obj_contact` 的计算范围。当前 balanced logit 采样下，`input_obj_to_hand_logit_loss_weight`
默认对所有 valid edge 取 1。

### 6.5 当前默认总 Loss

当前默认只反传这两个损失：

```python
loss =
    loss_obj_contact_weight * loss_obj_contact
  + loss_cross_edge_weight * loss_cross_edge_contact
```

当前基线建议：

```python
loss_obj_contact_weight = 0.0
loss_cross_edge_weight = 1.0
loss_cano_weight = 0.0
loss_cross_edge_rankk_weight = 0.0
loss_finger_weight = 0.0
loss_region_weight = 0.0
```

当前 baseline 中，`obj_contact` 权重置 0；`cross_edge` 继续走
`soft_contact_label -> 10-bin CE`，并直接复用 ContactOpt 风格的
`contact_bin_weights`。

也就是说，cano / finger / region / rank-k 这些分支即使代码里还保留开关，默认都只
作为关闭态，不参与当前 baseline 的梯度反传。

### 6.6 观察指标（不反传）

观测指标统一基于第 5.5 节解码得到的标量概率来算。

#### Object contact AUPRC

AUPRC 仍然保留，但它需要一个二值 GT 定义，所以这里单独使用
`pr_label_threshold`，不与训练用的 10-bin label 混在一起：

```python
pr_label_threshold = 0.5

obj_contact_binary =
    runtime_obj_valid_mask
    & (obj_contact_prob > pr_label_threshold)

obj_contact_auprc =
    AUPRC(
        pred_obj_contact_prob[runtime_obj_valid_mask],
        obj_contact_binary[runtime_obj_valid_mask],
    )
```

#### Cross-edge contact AUPRC

```python
edge_contact_binary =
    edge_valid_mask
    & (edge_contact_prob > pr_label_threshold)

cross_edge_auprc =
    AUPRC(
        pred_cross_contact_prob[edge_valid_mask],
        edge_contact_binary[edge_valid_mask],
    )
```

当前实现会跳过“该样本没有任何正 edge”的 frame，不再把这类 frame 按 AUPRC=0 计入 batch 均值。

#### Cross-edge rank@k

rank@k 继续采用无阈值版本，直接比较“预测 top-k”与“GT probability top-k”：

```python
gt_topk_i =
    topk(
        edge_contact_prob[i, valid_idx],
        k,
    )

pred_topk_i =
    topk(
        pred_cross_contact_prob[i, valid_idx],
        k,
    )
```

当前记录：

```python
cross_edge_rank1
cross_edge_rank4
cross_edge_rank8
```

定义为 top-k hit rate：

```python
cross_edge_rankk =
    mean_i 1[pred_topk_i ∩ gt_topk_i != empty]
```

如需和历史实验对齐，也可以继续记录：

```python
obj_contact_oracle_bce
cross_edge_oracle_bce
obj_contact_excess_bce
cross_edge_excess_bce
```

但这些都只是诊断项，不参与训练目标。


warmup 占比。

## 8. 评估可视化

### 8.1 可视化模式与按键开关

visualizer 提供两种显示模式，通过按键切换：

| 按键 | 功能 |
|------|------|
| `G` | 切换 GT / Eval 显示模式 |
| `C` | object contact 概率热力图 ↔ cross-edge contact 可视化 |
| `←` / `→` | 逐帧切换 |
| `,` / `.` | 切换当前选中的物体点 |
| `R` | 重置视角 |

### 8.2 Object contact 概率热力图

对每个物体点，按 `pred_obj_contact_bin` 解码得到的标量概率着色 [0, 1]：

```text
蓝色 (0.0) = 无接触
白色 (0.5) = 不确定
红色 (1.0) = 确定接触
```

**GT 模式**：显示 GT soft contact probability 热力图。

**Eval 模式**：显示解码后的 pred 概率热力图。

### 8.3 Cross-edge contact 概率可视化

选中一个物体点，显示该点对应的 hand-side 概率分布。

**GT 模式**：对 clean hand 的所有点，按该手点到选中物体点的距离经过
`soft_contact_label(d_pos, d_neg, gamma)` 后得到的 GT 概率着色。

**Eval 模式**：对 noisy hand 的所有点，复用当前 cross-edge head 做
`selected object point × all hand points` 的 dense 推理，并按
`pred_cross_contact_bin` 解码后的概率着色。

当前实现用键盘切换选中的物体点，不强依赖鼠标点选交互。
