# Ref2Dex 目录规范

## 一、先按产物性质归类

| 内容 | 规范位置 | 是否提交 |
| --- | --- | --- |
| 共享运行时、Contract、Runner、Manifest | `src/base/` | 是 |
| Task 模型、Dataset、Task 工具 | `src/task/<Task>/` | 是 |
| 独立研究实验 | `src/task/<Task>/research/<experiment>/` | 定义文件是，产物否 |
| 原始数据 | `data/raw_data/` 或外部 `dataset/<name>/data/` | 否 |
| 派生 cache、split、统计 | `data/processed_data/` | 否 |
| 预训练模型、MANO、SMPL-X、URDF | `src/task/<Task>/assets/` | 外部文件忽略；描述说明可保留 README |
| 训练、评估、正式 benchmark | `outputs/<task>/<run_id>/` | 否 |
| 研究诊断、可视化、小型分析 | `research/<experiment>/output/<run_id>/` | 否 |
| 科学结论与活动时间线 | 当前作用域 `docs/logs/` | 是 |

## 二、研究目录固定格式

```text
src/task/<Task>/research/<experiment>/
├── README.md
├── experiment.yaml
├── run.py 或其他实验脚本
└── output/<run_id>/
    ├── run_manifest.json
    └── 生成的图、表、NPZ、日志
```

`research/` 根目录不放散脚本，不放结果文件，不放 checkpoint。实验目录名使用稳定的
`lower_snake_case`，日期和 checkpoint 名字属于 `run_id`。

### 重要实验标记

需要长期保留、用于论文或作为主对照的实验，在其 `experiment.yaml` 增加可选元数据：

```yaml
importance: primary       # primary / reference / exploratory
pinned: true
tags: [paper, baseline]
```

`pinned` 只表示导航优先级，不代表结果成立；最终科学结论仍写入 `experiment_log.md`，并在
对应 `activity_log.md` 中链接所有关键 `run_id`、summary 和证据。不要用文件名加 `final`、
`best` 代替这个标记。

## 三、三种运行目录

- `outputs/<task>/<run_id>/`：BaseRunner 训练、评估和带 checkpoint 的正式运行；
- `research/<experiment>/output/<run_id>/`：只读诊断、可视化和局部 benchmark；
- `data/processed_data/<producer>/<schema>/<version>/`：可复用数据和 cache。

根级 `output/` 是历史兼容目录，只读、不新增。`results/`、`result/` 不再创建；需要长期保留
的结果解释写入 `experiment_log.md`。运行启动、停止、完成和失败等活动摘要写入 `activity_log.md`。

## 四、数据代码与数据文件

- `src/task/<Task>/dataset/`：运行时读取器、schema 和 Dataset 实现；
- `src/task/<Task>/tools/data/`：该 Task 的 cache 构建、split、校准和统计命令；
- 根 `tools/`：跨 Task 的通用工具和仓库维护命令；
- `dataset/<name>/`：外部数据集代码和官方布局；
- 实际生成的文件统一落到 `data/processed_data/`，不能写回代码目录。

## 五、Task 版本线

每个 Task 按 `Vn/Vn.m/Vn.m.k` 组织：`Vn` 由用户确认，`Vn.m` 必须有最终版
`docs/plan/Vn.m.md`，`Vn.m.k` 用于并行实验、实现和状态细分。Task 内只保留代码、配置、研究文档和实验索引：

```text
src/task/<Task>/
├── assets/                    # 该 Task 的外部资产入口（实际内容被忽略）
└── docs/
    ├── guidance/Vn.m.md     # 用户维护；历史中文路径可兼容保留
    ├── plan/Vn.m.md          # 计划边界
    └── architecture/Vn.m.md # 用户指令下冻结的架构快照
```

数据和 cache 不放入 Task 目录，训练/评估配置直接声明其外部路径，不新增 Task 内路径索引。
Task 专属外部资产放在被忽略的 `src/task/<Task>/assets/`；迁移期间允许保留指向旧位置的兼容软链接，
但新配置必须使用 Task-local canonical 路径。根 `assets/` 不再承载新资产。

## 六、Manifest 职责

| 文件 | 位置 | 职责 |
| --- | --- | --- |
| `experiment.yaml` | `research/<experiment>/` | 实验目的、入口、指导/plan 和默认产物位置 |
| `manifest.json` | cache 根目录 | 数据来源、schema、split、坐标系、采样和统计 |
| `asset_manifest.json` | `src/task/<Task>/assets/` 或资产归档 | 外部模型/资产来源、版本和校验信息 |
| `config.json` | 每个运行目录 | 解析后的参数快照，面向用户查看“这次运行想做什么” |
| `run_manifest.json` | 每个运行目录 | 一次运行的代码、配置、输入、checkpoint、seed、`modification_version` 和输出 |
| `summary.json` | 每个 train/eval 运行目录 | 用户可读的终态、最终指标、`run_status` 和关键产物入口 |
| `metrics.jsonl` | 训练运行目录 | 逐 step/epoch 曲线，面向机器读取和绘图 |

这些文件不可互相替代。`metadata.json`、`config.json` 和 `split.json` 可以作为子快照，但不能
替代对应的顶层 manifest。`activity_log.md` 通过 Markdown 链接连接 plan、实验记录、变更文件和运行产物。
Task 配置不再声明 `components` 或 `component_registry`；模型、
Runner 和 Dataset 由 Task 自身的 Python 配置直接选择。

## 七、活动与产物导航

activity 和 AI 最终回复中的本地导航同时满足两层要求：链接显示文本写仓库根目录相对路径；仓库内
Markdown 的目标按当前文档所在目录书写，聊天回复的 target 使用客户端支持的本地绝对文件路径。例如 Task 日志可写
`[output/research/example.summary.json](../../../../../output/research/example.summary.json)`。不要把
`../../..` 作为显示给用户的路径；仓库文档中不要保存依赖某台机器的绝对路径。

每类事件至少提供以下关键入口：

| 事件 | 必须导航的现有目标 |
| --- | --- |
| train / eval / benchmark | 运行目录、`config.json`、`run_manifest.json`、终态 `summary.json`、最佳或最近 checkpoint（产生时） |
| research 诊断 / 可视化 | output run 目录、`run_manifest.json`、`summary.json`、支撑摘要结论的关键图、表或数据文件 |
| data / cache 生成 | 数据目录、`manifest.json`、关键统计或验证报告 |
| code / config / documentation 修改 | plan（适用时）、activity 和实际修改文件 |

批量帧、分片、逐 step 文件不逐个链接，由运行目录和 manifest 索引。`STARTED` / `RUNNING` 时尚未生成
的目标可在同一行标记 `PENDING`；终态 activity 只能保留可解析的本地链接。交接时运行
`audit_diff.py --check-links` 检查最新活动条目；历史日志不因启用新规则而批量回填。

## 八、子任务递归规则

子任务继承根项目总览、`AGENTS.md` 和父 Task 的指导，不重复创建项目总览。只有子任务具有独立
研究问题、实现边界或可单独复现的运行时，才建立 `docs/README.md` 和相应日志；没有实际事件或
事实的日志不创建空文件。子任务的 `activity_log.md` 需要链接父 Task 的活动、experiment 或 run，
使用户可以从根入口逐级跳转到局部证据。
